# Dot으로 연결하는 웹 Pro 작업

갱신: 2026-11-19. **설정안과 인계 파일 준비 완료 / 사용자 Dot 연결 시험은 미실시.**

향후 연구 작업은 [운영 규칙](RESEARCH_WORKFLOW.md)과 [미래 연구 브리프](product/RESEARCH_BRIEF.md)를 사용한다. 브리프를 저장한 것만으로 제품 연구를 시작하지 않는다. 아래 두 작업은 연결 시험이다. 새 연구는 별도 과제로 배정하고, Dot은 정상 진행 중 추가 메시지를 반복하지 않는다.

목적은 웹 ChatGPT Pro를 중심으로 탐색기의 공통 개발 기반을 운영하고, 사용자 PC를 꺼도 클라우드 작업이 이어지도록 하는 것이다. 세션 교체는 정상 절차로 삼는다. GitHub에 저장된 작업 상태를 새 세션이 읽으면 되므로 대화 하나를 끝없이 유지할 필요가 없다.

## 역할

| 구성 | 맡길 일 |
| --- | --- |
| 웹 ChatGPT Pro | 깊은 조사·설계·어려운 판단·독립 검토. 필요한 파일 편집도 수행 |
| Dot | 작업 배정, 완료 확인, 정체 확인, 세션 교체와 다음 작업 연결 |
| Dot의 OpenAI 클라우드 컴퓨터 | Git 동기화, 짧은 상태 추출, diff·검사 결과 읽기, 필요한 작은 검사 |
| Codex Cloud, GPT-6.2 Sol Max | 실행·디버깅·반복 수정이 필요한 작업 묶음 |
| GitHub / Actions | 코드·근거·인계·완료 증거 보존 / 커밋 검사 |

Dot은 작업자가 정상 진행 중이면 개입하지 않는다. 저장소 전체와 긴 대화를 매번 읽거나, 매 도구 호출을 감독할 필요가 없다. Render 서버, 새 DB, 상주 프레임워크는 이 연결의 선행조건이 아니다.

## 시작할 때 읽을 것

1. `laadkke-arch/agentflow-open`의 `chore/workspace-foundation` 최신 커밋.
2. `AGENTS.md`, `STATE.md`, 이 파일, [진행 상태](automation/dot-control.json).
3. 현재 작업의 목표·완료 조건과 해당 `HANDOFF.md`만 추가로 읽는다.

진행 상태 파일은 Dot이 읽고 갱신하는 작업표다. 파일 자체가 스케줄러나 native Goal을 생성하지는 않는다. 현재 `activation.state`는 `prepared_not_activated`다.

Dot 컴퓨터는 필요할 때 저장소를 가져와 다음 정도의 짧은 명령을 실행한다. 체크아웃은 재생성할 수 있는 작업 사본이며, 인계의 기준은 GitHub에 저장된 커밋이다.

`git show origin/...`는 원격에서 가져온 파일을 읽고, `workbench context`는 현재 checkout을 읽는다. context 실행 전 `git rev-parse HEAD`가 이번 작업의 `source_commit`과 일치하는지 확인한다. 기존 작업 사본에 미저장 변경이 있으면 덮어쓰지 않는다.

```sh
git fetch --prune origin
git show origin/chore/workspace-foundation:docs/automation/dot-control.json
python -m workbench context reference-audit --query discovery
```

전체 검사는 실제 코드 변경과 검증 필요가 있을 때만 실행한다. 매 상태 확인 때 `cloud_check.py` 전체를 반복 실행하지 않는다. Actions가 이미 같은 소스 커밋을 검사했다면 그 결과를 재사용한다. PR 검사에서는 PR head와 실제 merge checkout SHA를 함께 확인한다.

## 연결 확인

연결 점검은 다음 세 가지를 실제 도구와 실행 결과로 구별한다.

| 항목 | 확인할 결과 | 현재 상태 |
| --- | --- | --- |
| Dot 컴퓨터 | 클라우드 작업공간에서 저장소의 최신 SHA·파일을 읽은 결과 | 사용자 Dot에서 미실시 |
| Dot → Codex Cloud | 생성·조회·재개 가능한 실제 작업과 실행 증거 | 사용자 계정에서 미실시 |
| Dot → 웹 Pro 세션 | 요청한 웹 Pro 모델의 작업자를 만들고, 새 세션에 GitHub 인계를 전달한 결과 | 지원 도구·모델 선택과 실제 실행 모두 미확인 |

Codex 작업을 시작할 수 있다는 사실만으로 일반 웹 Pro 대화 생성까지 확인했다고 쓰지 않는다. native 연결에서 웹 Pro 작업자 제어가 제공되면 그 경로를 사용한다. 제공되지 않으면 해당 연결만 `BLOCKED`로 기록하고 GitHub 인계 준비를 보존한다. Codex 작업으로 대체한 시험은 Codex 경로의 결과로만 기록한다.

Dot 컴퓨터에서 CoS와 로그인한 브라우저를 운영하는 대안은 별도 시험 후보다. 클라우드 컴퓨터의 존재만으로 브라우저 로그인·확장 연결·상시 실행이 확인된 것은 아니다. [11월 조사](research/dot-continuation-2026-11-19.md)에 현재 코드와 실사용 범위를 정리했다.

## 한 작업을 연결하는 순서

1. **읽기:** 최신 진행 상태와 기존 작업자를 먼저 찾는다. 조회가 늦거나 응답이 불명확하면 같은 작업을 즉시 다시 만들지 않는다.
2. **배정 기록:** 작업 ID, 시도 번호, 담당 종류, 작업 브랜치, 시작 SHA를 먼저 저장한다. 진행 상태는 Dot 한 곳에서 갱신한다. GitHub 쓰기 시 읽었던 head를 조건으로 갱신하고, 충돌하면 최신 상태부터 다시 읽는다.
3. **위임:** 목표, 완료 조건, 허용 경로, 정확한 시작 커밋, 읽을 파일, 다음 인계 위치를 전달한다. 실제 선택 모델과 실행 위치는 실행 결과로 확인한다.
4. **진행:** 정상 작업에는 계속하기 메시지를 반복하지 않는다. 완료·실패·사용자 판단 요청 때 확인한다. 장시간 응답이 없으면 저장된 진행 증거와 작업 상태를 먼저 조회한다.
5. **교체:** 기존 작업의 변경·결론·다음 행동을 커밋하고 원격에서 읽히는지 확인한다. 기존 작업자가 더 이상 같은 파일에 쓰지 않는지 확인한 뒤 새 세션이 해당 커밋과 handoff를 읽게 한다. 미저장 변경이 있는 기존 작업공간은 보존하고 복구부터 한다.
6. **완료:** 대화 종료 대신 작업의 완료 조건, 결과 커밋, 필요한 검사와 검토를 확인한다. 다음 독립 과제를 시작한다. 미통합 변경에 의존하는 작업은 정확한 의존 커밋과 통합 상태를 명시한다.

현재 [인수인계 양식](collaboration/HANDOFF_TEMPLATE.md)을 그대로 사용한다. 채팅 원문 전체를 복사할 필요는 없다. 작업 ID·현재 결론·근거·저장 커밋·검사 범위·다음 첫 행동이면 다음 작업자가 다시 시작할 수 있다. 공개 저장소에는 인증정보나 비공개 대화 원문·주소를 넣지 않고, 실제 서비스의 비공개 작업 ID는 Dot의 비공개 작업 기록에 보존한다. 저장소에는 조회에 쓸 고유 작업 ID와 공개 가능한 참조를 남긴다.

초기 운영값은 **동시 작업 1개, 자동 수정 최대 2회**다. 이는 서비스 한도가 아니라 과도한 개입과 중복 실행을 줄이기 위한 시작값이다. 인증·실행 여부 불명·같은 실패 반복은 원인과 재개 지점을 기록한다. 기존 승인 범위에서 해결되는 일은 다시 허락을 묻지 않는다.

## 처음 실행할 두 작업

이번 두 작업은 연결과 세션 교체만 확인한다. 제품 전체 구현으로 확대하지 않는다. 브랜치와 허용 출력 경로는 진행표의 값을 그대로 사용한다. **두 작업 모두 각자 최신 통합 브랜치에서 시작한다.** 두 번째 브랜치를 첫 번째의 미통합 결과 위에서 만들지 않는다. 첫 인계는 정확한 결과 커밋에서 읽고 별도 의존 SHA로 고정한다.

작업 표시 ID와 CLI용 소문자 `manifest_id`를 구분한다. Dot 컴퓨터 등 실제 checkout에서 각 작업의 계약 manifest를 만들며 진행 상태 파일과 혼동하지 않는다. 첫 작업의 명령은 다음과 같다.

```sh
python -m workbench.session start af-dot-001 \
  --allow docs/workstreams/dot-trial/AF-DOT-001/ \
  --output docs/tasks/af-dot-001.json --fetch
```

두 번째는 `af-dot-002`, 자신의 허용 경로·manifest 경로를 사용하고, `--dependency`에 `work/dot-trial-af-dot-001=첫_결과의_실제_40자리_SHA`를 전달한다. 설명용 문자열을 실제 커밋으로 바꾼다. 새 세션이 변경을 저장하기 전에 manifest를 준비한다. 인계 전에는 해당 manifest를 `workbench.session check ... --fetch`로 확인한다.

### AF-DOT-001 — 첫 웹 Pro 작업

- 최신 통합 SHA에서 [실제 조사 표본](research/discovery-case-2026-11-19.json)을 읽는다.
- 4개 후보의 역할과 미확인 제약을 기존 근거로 확인한다. 자료를 처음부터 재검색하지 않는다.
- `HANDOFF.md`에 현재 목적, 판단, 미확인 사항, 읽은 소스 SHA, 다음 작업을 저장한다.
- 다음 작업은 “이 인계만 받아 기존 reference-audit discovery 검사를 실제 실행하고, 검사로 확인되지 않는 사실을 구분하라”로 정한다.
- 완료 조건: 실제 웹 Pro 작업자·모델 확인, 원격에 읽히는 결과 커밋, 구체적인 다음 행동.

### AF-DOT-002 — 새 웹 Pro 세션으로 인계

- 첫 작업과 다른 실제 웹 Pro 세션을 만든다. 이전 채팅 원문을 전달하지 않고 저장소·작업 ID·인계 커밋만 전달한다.
- 첫 작업의 `HANDOFF.md`와 참조 파일로 목적·남은 일을 복원한다.
- `python -m workbench run reference-audit discovery`를 Dot의 클라우드 컴퓨터 또는 Codex Cloud에 맡겨 실행한다. 웹 Pro에 직접 실행 도구가 있다면 그 클라우드 작업공간도 가능하다.
- 새 웹 Pro 작업자가 결과를 검토하고 출처 연결 검사와 사실 검증의 차이를 기록한다. 검사 대상 코드 SHA, 입력 해시, 종료 코드와 결과 경로를 남긴다.
- `.workbench/runs/`는 Git에서 제외된다. 필요한 receipt와 짧은 stdout/stderr를 자신의 허용 출력 폴더에 보존해 커밋하고, 원격에서 읽히는 결과 커밋·경로를 인계한다. 임시 작업공간 경로만 남기지 않는다.
- 완료 조건: 두 번째 실제 웹 Pro 세션, GitHub만을 통한 내용 복구, 실제 검사 결과, 다음 작업을 담은 결과 커밋. 두 개의 Codex 세션으로 실행했다면 웹 Pro 교체 시험은 미실시로 남긴다.

기존 전체 검사 반복이나 의도적 장애 주입은 이 연결 시험에 필요하지 않다. Dot은 두 작업 결과를 확인한 뒤 종료한다. 결과는 `docs/sessions/`에 간단히 기록하고 `dot-control.json`의 실제 상태만 갱신한다.

사용자 PC가 꺼진 뒤에도 다음 작업이 시작되는 확인은 별도 관측이다. 사용자가 알려준 종료 시각 이후 두 번째 작업의 생성·실행·커밋 시각을 대조하면 된다. 사용자 기기에 접속해 전원을 끄거나, 오프라인 상태를 관측한 것처럼 쓰지 않는다. 작업·검사·GitHub 접근을 모두 클라우드로 지정해 두면 사용자 PC에 실행을 의존하지 않는다.

## 지속 진행 설정

두 작업이 연결되면 같은 절차로 명시된 대기 작업을 이어 간다. 우선 완료 알림이나 native 후속 실행을 사용하고, 누락 복구용 예약 확인은 필요한 경우에만 추가한다. 예약 확인은 상태가 변하지 않았으면 바로 끝낸다. 항상 저장소와 기존 작업자를 먼저 확인해 중복 실행을 막는다.

실제 Goal·스케줄은 생성 뒤 객체 ID, 활성 상태, 다음 실행 시각 또는 완료 이벤트 연결을 다시 읽어 확인한다. 프롬프트에 “계속해”라고 적은 것과 구분한다. 이 저장소에는 아직 그러한 객체나 실행 호스트가 연결되지 않았다. Dot 컴퓨터에서 무한 셸 루프를 띄우는 것을 클라우드 스케줄 설정으로 대신하지 않는다.

```text

반복 구현·디버깅은 Codex Cloud GPT-6.2 Sol Max에 맡겨.
너의 OpenAI 클라우드 컴퓨터는 GitHub 상태·diff·검사 결과 확인에 써.

GitHub laadkke-arch/agentflow-open의 chore/workspace-foundation 최신 SHA와
AGENTS.md, STATE.md, docs/DOT_AUTOMATION.md,
docs/automation/dot-control.json을 읽어.

네가 실제 사용할 수 있는 작업자 생성·재개 도구와 모델 선택을 확인한 다음
문서에 정한 AF-DOT-001, AF-DOT-002 두 작업을 순서대로 진행해.
정상 진행 중인 작업에는 반복해서 개입하지 말고, 저장된 커밋·완료 조건을
확인한 뒤 새 세션에 GitHub handoff를 읽혀서 이어 줘.
실행 중인 작업을 먼저 조회하고 중복 생성하지 마.
완료 조건과 허용 경로를 지키고, 실제 연결·미연결을 구분해 기록해.
두 작업을 끝내면 결과를 남겨. 사용자 PC에서 실행하는 단계는 넣지 마.
```
