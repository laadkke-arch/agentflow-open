## 2. 선택 가능한 보강 검색(최대2군)

연도2019–2025, venue ICSE 또는 CHI, 저자 공개 artifact 또는 공식 논문에서 공개자료를 확인한 별도 연구군만 적격이다. 사람이 소프트웨어를 작성/수정하는 과제를 수행하며 과제시간과 결과 품질을 모두 측정해야 한다. 추천 정확도만, 설문만, 읽기/선호만, 자동 벤치마크만, 다른 venue, 기존 여섯 군은 제외한다. 공개자료에 실제 배정·시간·점수의 행이 없어도 artifact 공개 사실이 확인되면 후보에는 남기되 raw-join 적격성은 별도 판정한다.

검색은 `"API example" "user study" ICSE CHI 2019 2025 artifact`와 `"code search" "user study" ICSE CHI 2019 2025 artifact` 두 기본 질의로 시작한다. 각 질의 처음 반환된 최대30개 고유 결과를 탐색 frame으로 기록한다(엔진이 적게 반환하면 실제 수만). 공식 venue/저자 자료를 연 뒤 DOI·제목으로 중복 제거한다. 적격 후보를 최초 발행일 오름차순, 날짜 동률/미상은 정규화 제목 사전순으로 정렬하고 앞선 최대2군을 선택한다. 결과효과나 raw 조인 성공 여부에 따라 바꾸지 않는다. 논문에 인용된 관련자료는 고정8군의 artifact 탐색에는 쓰되 보강 선정 frame을 사후 확장하지 않는다. 검색은 전수 문헌조사가 아니며 네이티브 학회 전수 정렬을 재현했다고 말하지 않는다.

## 3. 직접 열람의 층과 고유성

목표24개=고정8군 원논문8 + 저자가 별도로 발행한 부록/연구자료/복제패키지6 + 독립 발행된 과제지/채점기준/도구구현6 + 원 측정·비교방법 또는 추가 공개자료4. 동일 논문의 author/publisher판, 같은 패키지 안 여러 CSV·그림·파일, 한 저장소의 파일별 판독은 한 저작으로 묶는다. 하나의 독립 저작은 한 배당에만 산입한다. 논문 본문 appendix는 별도 발행 부록이 아니다. 도구 repository 전체와 그 내부 과제 파일을 두 배당에 중복 산입하지 않는다. 이름만 있는 project page/검색결과/실패 열람은 배당0. 저자가 별도 발행하고 독립 내용이 있는 자료인지 URL·판·발행 단위로 판정한다.

원문을 읽었는지(`direct_read`), 해당 질문을 실제로 답하는지, 고유 최소수에 들어가는지는 별도 열이다. 실패는 `access_failed`, 검색은 `discovery_only`, 고정 입력은 `background_dependency`로 남기며 최소수에서 뺀다. 증거가 부족하면 적격 자료수를 늘리기 위해 같은 파일을 쪼개지 않고 층별 부족을 그대로 인계한다.

## 4. 관측과 키 계약

기본 키는 `(study, experiment/cohort, pseudonymous_participant, task/trial, condition, period/order)`이다. 참가자별 배정표, 이벤트, 제출물, 점수/루브릭의 각 자연키·관계·기수를 먼저 확인한다. 행 대장마다 원행수, 대상행수, 유일키수, 중복키수, null키수, join 전/후 행수, unmatched-left/right와 제외 이유를 기록한다. 같은 참가자라는 사실만으로 서로 다른 과제의 임의 짝을 만들지 않는다. 독립 배정군은 그룹 수준 대비만 허용한다. 교차설계는 참가자와 task/period를 보존하고 순서/훈련/학습효과를 표시한다.

원자료가 없거나 파일을 열지 못하면 실제 join을 실행했다고 쓰지 않는다. 미계산 수는 `미확인`이며, 관측하여 해당 행이 없는 경우만 `관측 0`이다. 조건부 분모0의 비율은 `해당 없음`이다. 원참가자 가명/행은 재배포하지 않고 자체 예시 ID와 원 URL·파일·열·행 범위를 안내한다. 최소 두 군에서 실제 참가자 대장 파일/키를 찾는 데까지 경로를 추적한다. 공개라고 추정한 URL을 성공 자료로 기록하지 않는다.

## 5. 종점과 허용 비교

시간은 선택/첫 유용 후보, 열람, 첫 붙여넣기, 즉시 제출까지 총 경과시간, 활성 작업시간, 첫 채택 이후 후속 재작업시간으로 나눈다. 각 원점·종점·단위·중단·대기·훈련 포함 여부·상한/검열을 보존한다. 이벤트 간 wall-clock 차이를 활동/사람 노동시간으로 부르지 않는다. NCQ 선택과 총시간, Blueprint 첫 paste와 final, CodeMend 부분시간을 각각 다른 행으로 둔다.

품질은 원 척도 점수, 기능 검사 통과, 잘못된 답, 미제출, timeout, 후속 수정으로 나눈다. 품질 동등성은 사전 margin과 해당 신뢰구간 또는 동일 명세를 전원이 충족한 명시적 제한과 함께만 주장한다. 비유의 차이와 집단 합격 수만으로 동등성을 인정하지 않는다. 성공자 시간은 조건부 추정치로 표시하고 전체 배정자 효과와 분리한다.

공개 행이 있으면 (a) 원 배정군별 배정/관측/제출/성공/timeout 수, (b) 동일 종점의 시간분포, (c) 원 점수분포, (d) 제한시간 안 올바른 완료 수/전체 배정시행을 계산한다. 기술통계는 관측 정의가 일치할 때만 산출한다. 독립군 평균차는 E−C, 짝 비교는 실제 매칭된 동일 endpoint의 E−C를 기록한다. median(E)−median(C)는 paired median difference가 아니다. paired CI는 참가자 단위 재표집, 교차설계는 참가자 cluster와 task/period를 보존할 자료가 있어야 한다. 독립군 비율차는 군별 전체 배정분모를 사용하며 small-n exact/Wilson 구간 등 선택을 기록한다. 집계만으로 correlation/paired SD를 만들거나 실패자 시간을0·임의 상한으로 대치하지 않는다. 가능한 집계 산술은 `author_aggregate_arithmetic` 표시와 식/분모/빠진 항을 남긴다. 기존034 숫자 재계산을 새 핵심 성과로 삼지 않는다.

## 6. 감도·반례·귀속

실패 포함/성공자만, 부분/전체시간, 초보/숙련, 훈련 포함/제외, 같은 링크/다른 후보를 구분한다. 실제 분리 가능한 필드가 없으면 미확인으로 둔다. 검색성공 뒤 검사실패, 더 오래 걸린 정답, 읽었으나 미채택을 우선 찾는다. 원문 사례가 없으면 살핀 필드와 최소 추가 event/score를 적는다. 링크와 이유 외에 corpus/ranking/UI/editor/실행지원/허용자료가 달라지면 도구 묶음 비교다. 같은 링크에 설명만 붙인 효과로 환원하지 않는다. 참가자 스스로 선택한 노출은 배정 개입과 구별한다.

설계 유추와 학습 예제의 과제·독창성/정답·후검사·지연 전이를 별도로 판단한다. 추적 기간·첫채택 baseline·실제 재수정/노동이 없으면 재작업 절감은 미확인이다. 분야대조가 소프트웨어에서의 크기/인과를 대신하지 않는다.
