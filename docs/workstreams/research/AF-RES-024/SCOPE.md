## 분기와 모집단

- T0는 2021-12-31 23:59:59 UTC다. 분기별 기준은 각 분기 마지막 날 같은 시각이다. 공식 배포일이 기준 이내인 정식 버전 중 숫자 `(major, minor, patch)` 최대를 택한다. Node의 Current와 LTS가 함께 있으면 같은 규칙을 쓴다. 프리릴리스와 보안 백포트 때문에 가장 최근에 게시된 구계열은 별도 취급한다. 관측 창은 2022Q1–2025Q4다.
- T0는 CPython 3.10.1과 Node.js 17.3.0이다. 공식 태그의 소스 커밋은 각각 `2cd268a3a9340346dd86b66db2e9b428b3f878fc`, `e5873d786249d9b6aa1d8c422f856036c2c53e5e`다. CPython 색인 원본은 `Doc/library/index.rst`, Node는 `doc/api/index.md`다. Node 호스트 또는 고정 Git 판본이 둘 다 납품 불가일 때만 대체 계열로 Django를 쓰며 같은 시점의 공식 안정판과 [공식 버전 문서](https://github.com/django/django)를 사용한다.
- T0 색인에서 실제 연결된 표준 라이브러리/API 장과 하위 색인을 읽는다. CPython의 공개 module 및 최상위 함수·클래스·data 선언, Node의 공개 API 메서드·클래스·속성·CLI 플래그를 추출한다. 식별자 시작이 밑줄인 내부용 이름과 이름 없는 서술 절을 제외한다. Node의 최상위 안내, C++ 관리 절, 폐기 상태 색인은 선택 프레임 밖이고 출처나 상태 관측에는 사용할 수 있다. 코드에서 현행 인기, 사건 또는 미래 상태를 읽을 필드가 없다.
- 상위 기능당 한 이유를 뽑는다. CPython은 모듈의 첫 이름 부분, Node는 API 문서 장을 상위 기능으로 잡고 CommonJS·ESM·module·packages는 한 그룹으로 합친다. T0 본문에 분명한 폐기 표식이 하나라도 추출된 상위 기능은 폐기층에 배치하고 그 그룹에서는 표식이 있는 후보만 추첨한다. 일반층은 문서 실험 여부를 함께 보존한다. 각 계열에서 폐기층 최대 8개, 나머지를 일반층으로 합계 32개씩 뽑는다. 일반층이 모자라면 남은 폐기층에서 충원한다.
- 시드는 `AF-RES-024|2021-12-31|v1`이다. 안정적인 그룹 순서와 그룹 내부 후보 순서는 같은 시드와 서로 다른 단계 문자열의 SHA-256 오름차순으로 정한다. 전체 추출 ID, 대상 여부, 표식, 조건부·결합 포함 확률과 제외를 남긴다. 표식 그룹 내 표식 없는 후보의 포함 확률은 0이다. 선택한 64개를 같은 규칙으로 보존하고 당시 본문에 지지되지 않는 문구는 초기 오류 또는 판정 유보에 둔다. 선택 교체는 하지 않는다.
- 이유는 공개 표준 Linux x86-64 빌드에서 현재 최신 안정판으로 업그레이드할 때 같은 이름과 사용 조건으로 할 수 있는 좁은 작업이다. T0 문서가 지시한 플랫폼·빌드·준비 조건은 이유마다 붙인다. 동일 공개 진입점으로 관측 가능한 결과가 유지되면 구현·문서 이동을 허용한다. 별도 패키지 설치·호출부 변경이나 플래그 교체는 원래 이유의 유지로 세지 않는다. T0판에 고정해 계속 쓰는 경우와 지원 중인 옛 계열을 쓰는 경우는 비교 사례로 둔다. 서비스 가격·약관·폐쇄 운영은 범위 밖이다.

## 분기별 접근과 확인 규칙

1. 당시 관측은 공개일을 확인한 분기판의 정확한 Git 태그와 커밋으로 제한한다. 원격 공개일·태그 작성일·커밋일을 별도 필드에 남긴다. 현재 API 응답은 버전과 실제 오늘 접근에만 사용한다. 릴리스 날짜의 현재 인덱스는 분기 시점에 필터링한 설치판을 재구성하는 입력이다. 이후판의 텍스트, 현재 main과 사건 주소를 관측 입력으로 사용하지 않는다.
2. 출발 문서와 색인 및 릴리스 링크의 관계를 T0에서 고정한다. CPython은 태그의 공식 라이브러리 색인·다운로드 페이지의 공식 Changelog 링크·태그 소스의 변경 기록, Node는 API 색인에서 연결된 공식 저장소의 Releases와 태그의 CHANGELOG.md를 따라간다. 후속 원문은 당시 태그의 색인에 실제로 나타난 링크나 소스 문서에서 직접 연결된 링크로 한정한다. 발견의 출발·후속 경로를 방문 원장에 남긴다.
3. 문서 원문 주소는 HTTP raw의 커밋·경로로, Git 메타데이터는 게시된 같은 태그의 blob 없는 얕은 fetch와 `ls-tree`로 복구한다. 직접 API 디렉터리 경로는 T0 시험에서 CONNECT 403이었다. 본문 유무는 HTTP와 Git 트리를 구별한다. 미수신과 경로 삭제를 혼동하지 않고, 태그의 트리 fetch에 실패한 분기의 S도 실패로 기록한다.
4. N은 재검토하지 않는다. D와 S는 같은 분기, 같은 이유와 원문 풀에서 정책당 20개의 서로 다른 문서/작업상 네트워크 단위를 상한으로 쓴다. 민감도는 10과 40이다. 각 계열의 공식 API 색인과 릴리스 길잡이를 먼저 예약하고 중복 경로는 분기 내 한 번 청구한다. S는 양 계열의 Git 태그 트리 조회를 각각 1개 네트워크 단위로 추가 청구하고 Git 협상 내부 HTTP 요청과 실제 pack 크기는 비용 비교에 따로 둔다. API 색인에서 이어지는 원문은 방문한 문서에서 발견한 경우 큐에 넣고 같은 상한의 남은 자리를 쓴다.
5. D는 계열을 교대로 배치하고 마지막 성공 방문이 가장 오래된 이유부터 본다. 처음에는 시드 기반 순서다. S는 같은 색인·계열 교대를 쓰고 마지막 성공 방문 당시의 blob과 비교한다. 불일치·경로 부재는 강한 신호, T0 또는 이미 읽은 폐기 표식과 프로젝트 안정판 변경은 약한 신호다. 강한 신호 우선, 같은 점수는 마지막 성공 방문이 오래된 순이다. 기본 임계값은 2점(경로 부재·blob 변화에 2점, 기지 경고와 버전 변경에 각 1점)이다. 임계값 1·3으로 재생한다. 판독 불가와 실패 응답은 다음 분기 재시도 가능 상태로 보존하고 실패 차감/대체 규칙을 민감도로 둔다. 부분 수신은 본문 확인이 아니다.
6. 운영 판독은 바뀐 절과 방문한 날짜의 명료한 공식 설명만으로 지원, 폐기 경고, 의미 변경 보고, 근거 부족을 가른다. 경로 부재만 보이면 탐색 신호이며 변경 확정은 아니다. 독립 채점은 별도 단계에서 릴리스 변경 기록과 동시대 매뉴얼 또는 태그의 구현·공식 테스트를 교차 대조한다. 같은 제작자의 서로 다른 판정 경로로 표시한다. O에서만 사건 주소를 정답이 주어진 상한으로 사용한다.
7. 기본 단위는 이유×분기다. 윈도 종료에 구분 가능한 붕괴/유지/검열의 분모, 탐지 후 유지하는 정책의 상태 혼동표, 신규 보고의 정확도, 사건군·이유의 최초 확인과 지연을 각각 계산한다. 첫 공지·실제 배포·분기 말 발견일을 따로 기록한다. 선행 시점과 유지 신호를 세고 불명 양극단 민감도를 보고한다. 독립 추론 단위는 두 프로젝트와 정책 결정 사건군이다. 같은 사건군의 이유 수를 독립 표본으로 계산하지 않는다.
8. 전체 연구용 원문 수집 비용과 정책 큐가 요청하는 비용을 구별한다. 동일한 고정 원격 입력의 최초/캐시 재사용 두 번에서 HTTP 응답 본문 바이트, Git pack 바이트, 로컬 읽기, 요청 중복, 성공/실패/재시도, 벽시간을 기록한다. 304는 실제 HTTP 코드일 때만 쓰고 사람 판독 시간은 미확인이다. 링크 발견·태그/공개일·정답 복원에 무상으로 제공된 준비를 별도 비용으로 둔다.
9. 이 기준과 T0 표본을 순서대로 커밋하고 GitHub에서 확인한 뒤 미래판을 열어 관측을 구축한다. 그 사이 공식 T0 릴리스 페이지의 사후 경고 문구는 활용하지 않는다.
