## 목적·차단 순서

두 분야의 원리를 이미 제공받았다는 조건에서 수신 설계의 서로 가능한 A/B 조작과 정상·경계 출력을 사전에 적고, 공개된 후속 결정·코드·시험과 대조한다. 역사적 영감·첫 독서·채택 인과·자유 웹 회수율·실제 사용자 노동 절감은 측정하지 않는다. 원리의 존재와 적용 가능성, 출력 예측, 유지보수자 선택, 실행 관측을 별도 열로 둔다.

1. 현재 최초 게시 본문과 2019–2024 목록을 읽는다. GitHub 응답의 state, labels, closed_at, comments, timeline 및 PR metadata는 모델 출력 전에 제거한다. API가 받은 필드는 사람/모델이 읽은 필드와 구분한다.
2. 표본과 판정 규칙을 묶음1로 커밋한다.
3. 당시 API와 제공 원문만으로 6요구/12후보의 예측을 작성하고 묶음2를 원격에 커밋·확인한다.
4. root가 봉인 SHA를 전달한 뒤에만 모든 작업자가 해당 요구의 댓글·타임라인·해결 PR·diff·후속 시험·릴리스를 연다. 첫 후속 열람 UTC를 기록한다.
5. 판독 뒤 규칙을 바꿔야 하면 사전 원본과 분모를 보존하고 변경 원인·영향 행을 따로 적는다.

현재 최초 게시 본문은 이슈 생성 당시의 immutable 판과 같다고 보장하지 않는다. `updated_at`은 댓글/metadata 갱신도 반영하므로 본문 편집의 증거로 쓰지 않는다. 본문에 사후 편집 표지·해결 체크리스트가 있으면 실제 노출로 기록한다. 사전학습의 무노출은 보장할 수 없다.

## Q2–Q4 조작·대응·봉인

요구 원문의 조건과 연구자가 보충한 판별 입력을 명확히 분리한다. A/B는 같은 상위 목적의 서로 다른 조작이되 원문 조건을 위반하는 근접 사례는 그 위반 자체를 표시한다. 당시에 공개 API로 가능한 조작인지와 현대 적용 진단인지 구분한다. 수신 매뉴얼은 제공 타 분야 원전으로 세지 않는다.

후보마다 제공 분야의 주 사용자·조작 대상·목표, 정확한 조항, 변수 대응, 유지할 불변조건, 실패 예상, 정상·경계 입력의 A/B 출력을 적는다. 원문에 없는 구현 알고리즘은 연구자 제안이다. 다른 분야라는 명칭만으로 타당성을 부여하지 않는다. 동일/반대/판별불가 예측을 사전에 분류한다. 단위 교환 및 비용 제약 제거를 최소 한 번 검사한다.

## Q5–Q7 판정

- 지지: 봉인한 조작·입력·목적과 일치하는 후속 원문에서 예상 출력을 확인. 증거 등급을 결정 발언(D), 명세(S), 정적 코드(C), 시험 코드(T), 공개 실제 실행/재시험(R)로 병기한다. T를 R로 높이지 않는다.
- 충돌: 같은 조작·입력·목적에서 반대 출력 또는 필수 불변조건 위반이 확인된다.
- 판별불가: 두 후보가 같은 관측을 예측하거나, 후속 기록이 선택한 세부 출력의 차이를 시험하지 않는다.
- 미확인: 해당 입력·출력·판 또는 후속 원문이 없거나 접근에 실패한다. 닫힘 상태만으로 지원이나 구현 완료를 판정하지 않는다.
- 최초 요구에 이미 나온 해법·당시 API 문서의 조작·연구자 보충 선택·후속 채택을 각각 분리한다. 제3의 해법이 채택되면 A/B 둘 중 하나로 강제하지 않는다.
- 판별 성공 분모: 사전 두 예측이 갈리고 같은 입력의 후속 증거가 있는 요구 수. 분자: 유일 지지 사례; 양쪽 기각·판정불가도 함께 보존. 동률 예측 적중은 판별 성공에서 제외한다.
- 전체 6자리와 명시적 결말 노출 제외(현재 A02 제외 5자리)를 함께 계산한다. 최초판 엄격 확인 사례만의 감도에서는 분모0이면 '해당 없음'이다.
- 시각 설계자·데이터 독자·음향 편집자·유지보수자의 보존 대상 차이를 비교한다. 공간 위치/가독성, 프레임/표본, 양쪽 적중, API 제약 사례가 없으면 빈칸을 유지한다.

## 원문 산입

최소 24개의 고유 직접 열람 1차 저작: 요구6, 제공8(공간>=3·시간>=3), 별도 후속6, 독립 비교4. 동일 이슈 댓글·동일 매뉴얼 절·판·미러·번역·재방문은 추가 산입하지 않는다. 요구 이슈 댓글은 후속 근거로 사용할 수 있으나 같은 이슈를 후속 배당에 재산입하지 않는다. 검색 요약·접근 실패는 원장에는 쓰되 산입하지 않는다. 날짜 불명/후발판은 역사 가용성 미확인/현대 진단이다.

원문 전문을 재배포하지 않고 URL·정확 위치·짧은 인용·해시와 연구자 요약을 남긴다. 후속 원문 6개를 확보하지 못하면 다른 사례로 대체하지 않고 수량 미충족을 공개한다.

## 예상 반례

1. 프레임을 포함하는 Out-point 규칙을 오디오의 반열린 표본 구간에 그대로 옮기면 한 단위 길이가 달라진다.
2. 지도의 라벨을 옮기거나 생략하면 가독성은 좋아져도 데이터 값/대상과의 정확한 대응을 깨뜨릴 수 있다.
3. 색상 선택을 그대로 보존하는 원리와 명암을 강제하는 원리는 동일 색상 입력에서 갈릴 수 있지만, 유지보수자는 아예 사용자 색상 기능을 지원하지 않을 수 있다.
4. 두 원리가 모두 구간 값을 그대로 읽으라고 해도 전용/범용 API 선택은 가르지 못한다.
5. 주파수 선택과 시간 선택의 경계 규칙은 변환 영역이 달라 동일 불변조건을 보장하지 않는다.
