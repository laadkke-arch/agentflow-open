# 데이터 읽는 방법

## 행과 분모

- `A-Hnn` / `A-Cnn`: 소비자의 과거 공개 용도에 붙인 한 참조. 단위는 패키지 카탈로그 편집이 아니다. 같은 상류 사건을 두 소비자가 겪으면 참조 2개/사건 1개다.
- `B-Hnn` / `B-Cnn`: 미리 정한 공식 변경 원장으로 시작한 역추적 **시도**. 소비자 확보 실패도 남긴다. A와 겹치면 연결만 하고 A 분모·발견률에 더하지 않는다.
- `X-BIB01` / `X-LIB01`: 타 분야의 적용 조건 대조. 소프트웨어 A/B 분모에서 제외한다.
- `source_id`: 실제 열어 읽은 원문 또는 접근 실패의 관측 ID. 자료 ID 수, URL 수, 고유 원문 최소수, 고정판 수, 독립 사건 수는 서로 다르다.

| 파일 | 읽을 값 |
| --- | --- |
| frame.csv | 사전 후보순서, 실제 시도한 날짜 앵커, 선정/탈락, B 원장과 A 중복 |
| references.jsonl | 과거 원문 그대로의 참조·소비자 고정판·목적·호출 위치; 연구자가 만든 catalog URL은 명시적으로 구별 |
| upstream.csv | 이름/판/출력 관계, 제안·소스·merge·배포 날짜, 전후 원문, 실제 시행 미확인 |
| chains.csv | T0→Tu→To→Tc→Tr와 각 URL; 창 말·이후 첫 수정·끊긴 위치·다음 불변판 |
| verdicts.csv | 동일 용도 유지/부적합/보류, 고의 보존 근거, 반대 설명, L1/L2/L3 기록의 답 가능 범위 |
| intervals.csv | 날짜의 의미·정밀도·양 끝 근거; 계산 가능한 지연만 숫자로 기록 |
| sources.json | 원문별 직접 판독 위치·시각·확인·한계·생산 계보·산입 이유 |
| collectors/ | 생태계별 원장과 실패·재현 경로. 원문 전체의 미러 저장소가 아니다. |
| evidence/ | 표집 봉인·원격 커밋 확인·집계·수용 조건·실제 검사 영수증 |

## '미확인', 0, 해당 없음, 검열

`미확인`은 그 주장을 판정할 자료가 부족하다는 뜻이다. `관측 실패`는 특정 접근/검색 경로가 답을 주지 못했다는 기록이며 원문이나 사건이 존재하지 않는다는 뜻이 아니다. `0`은 명시한 검색 범위·관측 분모에서 실제로 세어 0개라는 뜻이다. `해당 없음`은 무사건처럼 지연의 시작 사건이 없어 해당 변수가 정의되지 않는 경우다. CSV 날짜의 빈 칸은 동반 status/reason으로 해석하며 임의의 0일로 변환하지 않는다.

우측 검열은 시행과 관측 종료가 확인되지만 그 사이 수정이 관측되지 않은 참조에만 쓴다. Tu 자체가 없으면 `INDETERMINATE`다. 최초 관측 전에 이미 변경된 경우만 좌측 검열이다. 판/플랫폼·명령·용도가 다른 두 날짜는 계산하지 않는다. 배포 없는 소스 수정은 `commit_only`이며 실패라고 할 수 없다.

## 증거 경계

버전 관리된 파일과 diff는 그 파일이 공개한 설정/문구를 보여 준다. 패키지 설치와 호출 성공, 그 커밋의 사용자 배포, 실제 피해를 자동으로 증명하지 않는다. 릴리스 자산/공지와 CI도 해당 플랫폼·입력·판에만 적용한다. 이번 연구자가 실행한 파일 정합 검사는 외부 소프트웨어 실행과 다르다.

한 commit의 같은 내용을 API·raw·GitHub 화면으로 다시 본 것은 원문 하나다. 동일 판의 목적을 확인하기 위해 다른 파일을 읽으면 URL/파일 재열람 비용에는 기록하되 고유 원문 최소수에서는 중복 제외한다. 독립 consumer 프로젝트라도 상류 metadata를 자동 복사한 결과는 독립 사실 검증으로 승격하지 않는다.

L1/L2/L3는 이번 자료를 가렸을 때 **어떤 질문에 필요한 필드가 남는지**의 자기점검이다. 독립 사용자 실험·성공률 비교가 아니며, 사람의 읽기시간과 운영 저장비용은 측정하지 않았다.
