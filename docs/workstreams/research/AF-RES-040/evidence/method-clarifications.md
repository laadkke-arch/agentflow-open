# 원문 경계·표시 예산·자연 후보 해석 기록

기록 시점: 2026-11-22 18:46 UTC. 후보 풀 원격 봉인 `b406236564be8dc6435912912ba67e5d16c98102` 뒤, 비교 보기·손실 집계 생성 전이다. 원 요구·후보 순서·풀의 URL을 수정하지 않는다.

## 1. 줄 앵커는 원문 접근 제한이 아니다

SCOPE §4의 ‘대표가 가리키는 원문만 판독’은 **열린 고정 문서 전체**를 뜻한다. 추가 클릭 0은 스크롤·같은 문서 읽기를 금지하는 뜻으로 정의하지 않았다. 따라서 같은 Git 파일의 서로 다른 `#L...` 링크가 후보로 있어도, 하나를 열면 같은 고정 문서의 다른 후보 절도 읽을 수 있다. `document_group`으로 이 접근 가능 범위를 계산한다. 다른 문서에 대한 링크는 새 클릭이므로 자동 포함하지 않는다. 실제 사용자의 스크롤·읽기 시간은 미관측이다.

카드에서 보이는 명명 부품과 열린 문서의 근거 범위는 다르다. 이 때문에 `hidden_card_components`와 `hidden_required_atoms`는 별개다. 카드에서 사라졌지만 같은 원문으로 읽을 수 있는 근거를 실제 근거 손실이라고 세지 않는다. 같은 문서 반복 슬롯과 같은 기능·판·근거 역할의 중복 슬롯도 별도로 센다. 같은 문서에 다른 기능이 있는 경우 전자는 늘 수 있지만 후자가 자동으로 늘지는 않는다.

## 2. 근거쌍의 최소 단위

같은 파일 안의 두 절을 두 원문이라고 세지 않는다. `atom_support_sets`는 필요한 후보 절들의 조합이지만, 상호 보완 **원문쌍**은 고정 문서 ID 집합으로 중복 제거한 뒤 센다. 하나의 원문 전체로 조건을 입증하면 두 번째 문서 클릭이 필요하다고 계산하지 않는다. 소비자 원문에 요구한 실제 오류 해결·배포 포함·실행 결과가 근거에 없으면 완전 적격 경로는 없다.

## 3. 표시 설명의 통제 범위

모든 카드에 설명 최대 80 유니코드 글자와 직링크 1개의 같은 용량을 준다. 같은 후보의 설명은 팔 사이에 동일하다. 실제 설명의 문자수는 기록하고 공백으로 늘리지 않는다. 따라서 ‘같은 설명 길이’는 **동일 상한과 동일 후보 텍스트**로 구현했고, 서로 다른 대표들 간 실제 문자수를 완전히 같게 만든 실험은 아니다. 의미 없는 패딩으로 이 차이를 숨기지 않는다. 글자수 자체의 사용자 효과를 추정하지 않는다.

## 4. 자연 링크와 재현 가능한 근거 링크

구버전 웹 경로가 열리지 않거나 공식 문서의 실제 명명 항목을 고정판으로 식별할 때, Git 태그 파일 URL과 줄 앵커를 사용했다. 특히 S 경로의 24개 주소는 원래 HTML 목차 href를 그대로 수집한 것이 아니라 **공식 버전 파일의 명명 항목에 근거해 구성한 직링크**다. `url_construction`과 발견 원장·절을 남겼다. G 경로도 원래 `discovered_href`와 고정 소스 파일의 주소를 함께 남겼다. 따라서 이를 자연 웹 검색의 원 순위·링크 분포라고 일반화할 수 없다.

원래 raw href와 일치하는 6개 자연 링크만으로 비교하라는 강한 해석의 수용 조건은 미충족으로 남긴다. 원래 기록을 나중에 바꾸거나 constructed anchor를 ‘관측한 HTML href’라고 부르지 않는다. 다음 최소 조사는 배포된 버전 매뉴얼의 실제 href 6개를 순서대로 저장하는 새 표본이다. 이번 고정 풀의 문서 수준 비교는 그 한계 아래 유효하다.

S1에서 builder 목차 뒤 configuration 명명 항목으로 진행한 단계1 해석과 G 경로의 초기 HFA 직접 열람은 각 조사 노트의 이탈 기록을 함께 읽는다. 동일 입력을 세 팔에 제공한 사실과 표집·발견 절차의 완전 사전 준수는 서로 다른 수용 조건이다.
