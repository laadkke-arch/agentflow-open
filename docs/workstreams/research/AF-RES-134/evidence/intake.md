# 모집 확인 영수증

- A/B의 HTTP 인수와 출발 시각은 [forum-http.jsonl](forum-http.jsonl)에 있다. /t/6001.json과 /search.json?q=가중치의 상태는 각각 **프록시 CONNECT 403**, 원본 HTTP·콘텐츠 타입·JSON topic/post·검색 배열은 미확인이다. 다른 A/B 요청도 같은 실패였다. DNS 오류, origin HTML 오류, 접근 서비스 제한 및 삭제를 관측한 행은 0이다.
- 같은 64개 topic의 정상 HTML 주소와 네 공개 검색 HTML을 한 번씩 비교했다. 웹 도구는 A 6027의 text/html, 첫 글 번호 1만 반환했다. 광고 내용이므로 불적격이다. 나머지 A 63과 B 4는 웹 도구 접근 불가다. 원본 서버 상태나 삭제로 옮겨 적지 않았다. [HTML 영수증](forum-html.jsonl)
- GitHub 공식 공개 HTML 검색의 hydrated payload에서 번호·UTC를 먼저 파일로 고정했다. G1 공식 목록의 `pageInfo.totalCount`는 22, 끝은 #48이다. GitHub 연결 도구의 별도 `sort=created&order=asc` 검색은 같은 22 ID 순서를 반환했고 날짜 필드가 null이라 공식 목록으로 시각을 대조했다. G2 두 검색의 코드·정확 문자열·페이지별 응답·최종 위치는 [G2 어떻게](g2-how-search.jsonl)와 [G2 싶습니다](g2-want-search.jsonl)에 있다. G2 결과의 후행 읽기 순서는 어떻게→싶습니다로 고정했다.
- 68개 반환 슬롯의 공개 이슈 페이지에서 이슈 ID와 날짜를 다시 대조했다. HTML에 포함된 답글/타임라인을 파서에서 판독 입력으로 내보내지 않았다. 첨부 이미지 중 G1 #39와 #43의 원저자 이미지 URL은 각각 HTTP 403이고 웹 도구도 접근 불가였다. #39는 본문에 두 reduction이 있어 채택했고 수식은 미확인이다. #43은 계산 객체/출력을 특정하지 못해 유보했다. #30 본문도 torchvision 버전 추측과 스크린샷만으로 목표 조작을 특정하지 못했다. [첫 게시물의 해시와 편집 필드](github-openings.jsonl)
- G2 어떻게에서 확보한 24슬롯과 G2 싶습니다에서 확보한 22슬롯은 현재 검색 노출이다. 같은 GitHub 이슈 2회와 동일 FAQ 재게시 3회를 앞선 소스로 연결했다. 비슷한 2019/2020 행사 규정은 차이를 남겼다. 한국어 작성 여부는 첫 본문에서 판정했고 작성자 신원은 공개 노드 ID의 해시로만 대조했다. 학습/설치 일반, 번역, 타인 Slack 글 인용, 템플릿 주석의 물음은 대조용 제외 사례다.
- 채택 원문은 6건/6저자다. G1 두 reduction, G2의 말뭉치 라벨 구성, 5클래스 적재 계약, HDF5 배치 실행, loss 합성이다. 첨부·PDF·링크 내 텍스트는 점수 입력에 넣지 않았다. 첫 본문을 NFC로 정규화하되 원래 CR·LF를 보존했다. 전체 Markdown을 커밋하지 않았다. 여섯 원문과 구절의 해시는 투영 시에 일치했다.
