# 보정·반례 및 전이 (④)
- 발행자: O01–O04는 기준을 정의하는 자료, 시험표와 정확도·범위 통계는 서로 다른 보증. 국가 격자 정의와 기존 triangulation 관측값 불일치가 가능하다. 개발자는 데이터 파일과 DB/런타임을 함께 버전·해시·경로로 묶어야 하고, 소비자는 수평 좌표가 맞아도 높이 기준이 맞는지 separately 확인해야 한다.
- E02/E03은 강한 반례: 로그가 실제 vertical file open 성공 및 최종 ballpark vertical/OSTN15 horizontal selection을 구분. 49.92226393730° < bbox south 49.93° (원문은 west라고 표현, 좌표상 남쪽 경계); St Marys EPSG5749를 선택하면 맞았다는 보고지만 정정 수치는 없다. 이전 ③의 E02 source row에 이 정정을 남겼다. TP01은 본토 ODN 시험점으로 세지 않는다. 사용자 보고를 현재 모든 PROJ 배포 상태로 일반화 금지.
- 9367→27700은 철도 전용 grid와 OSTN15 둘 모두의 후보가 있는 사례. 원제보자의 실제 선택이 없으므로 약 87m 불일치를 grid 누락 단일 원인으로 단정하지 않는다. CAD 기준 검증·축/단위/CRS 설정·동일 입력·실효 판 경쟁 설명. E,N 단위와 geographic axis 순서 다름. 3번째 인자가 0이라고 높이 기준 변환된 것이 아니다. 네트워크 사용·사전 다운로드·미설치 세 환경의 동일 사건 결과는 없음.
- 축/단위: P07 always_xy 옵션은 지리 lon,lat; 공식 OS test 표 lat,lon. 같은 tuple을 두 설정에서 재사용하면 의미 달라짐; 실제 E1 axis 오류 사례는 확인되지 않음. degree, radians, E/N metre, foot 및 epoch를 별도 요구 키로. P08/T01은 수직 보정 없는 fallback/2D z pass-through 문서 예시. 로그/경고가 없다고 보정 성공으로 간주 금지. E03에서는 debug log가 존재하므로 "경고 없었다"는 주장 미확인.
- 데이터 선택의 대가: OS full raw pack 13MB·NTv2 ZIP28MB·GTX2MB 및 20km lite 70KB는 배포 설명의 용량, 현재 CDN TIFF 크기는 미확인. 전체 데이터 설치보다 제한된 영역의 격자 선택은 저장량 감소 가능하나 AOI·데이터 계보·파일 변경 관리 필요. 네트워크 스트리밍은 연결·cache 의존; 오프라인은 파일을 사전에 가져와 접근권한/DB mapping/실제 operation 확인. OS native Grid InQuest II는 지역 구분 내장 대안, 새 라이브러리 구성과 비교 실행 안 함.
- 교정: C01 제조자 Beamex의 설명·MC6 예시는 계기 범위마다 uncertainty, reference chain 및 calibration 시점; 실제 MC6 예시 수치 미확인. C02 교정업체 예시(0–200psi, 40psi nominal, 40.01psi)에서 허용 폭과 ±1.2psi expanded uncertainty 별개. C03 15000psig에서 as-found14900 실패, as-left15000 통과: 조정 전/후 영수증 구분. 계기/serial/판/범위/환경/불확도/규칙/시점과 다음 영향대상을 보존하는 원리를 좌표 데이터의 source/datum/area/epoch/file revision/operation/input/output에 전이. 교정 주기나 압력 공차 자체는 전이하지 않는다. 제조자 예시의 숫자 확인 부족은 C02/C03으로 범위를 보완하되 제조자 발급 동일 성적서로 대체하지 않음.
- 조석: C05 San Francisco 9414290, C06 Providence 8454000 모두 1983–2001 19년이지만 MLLW 기준 MHHW 1.780 vs 1.476m, NAVD88 −0.018 vs +0.754m, MSL0.951 vs 0.686m. 동일 epoch와 같은 datum label이어도 다른 관측소 offset 사용 금지. C04 짧은 관측은 동시 control station 비교 필요; station datum은 고정 기준 유지, benchmark 관계/갱신 판을 확인. C07 갱신 진행 확인, 현재 새 epoch 적용은 미확인. UK의 datum 수치와 NOAA 수치를 결합하는 것은 불가. 다만 지역·시점·기준 관계와 승계 근거를 링크에 포함할 원리는 전이 가능.
- 답변 최소 단위 후보: 라이브러리 링크만 / 라이브러리+데이터+공식 확인점 / 보류 질문+대체 경로. 단순 기능 소개에는 첫째, 실제 오프라인 정밀 변환에는 둘째, 지역/수직 기준/축 모호하면 셋째. 낮은 정밀도를 허용하는 경우 공식 근사 대안으로 돌릴 수 있으나 정확도 미상 ballpark를 동일한 대안으로 취급하지 않음. 제품 최종 DB/API/검색순위 결정 아님.

## ④b 재검토
- 이전 ③의 임시 점 분류를 X14–X17로 수정: TP01 flag2, TP02/TP03 flag1, TP21 flag3. TP01~TP40 순서에서 TP02~TP20 flag1, 다음 TP21 flag3. 선택된 4개 ID의 원행 두 재게재본 일치, 원본 ZIP 바이트와 지역 경계는 여전히 인증하지 못함. T03/T04/T05의 구현 테스트 허용차는 OS 공인 허용차 아님. X05 표와 X16에 TP11·TP24·TP29 높이 1mm, TP31/32 E/N 값 차이가 있어 재게재본을 곧 공식 원전으로 부르지 않음. P10이 직접 연결한 X18은 중국 CRS 축·식별의 실제 제보로 Q5 반증 참고만, UK 변환·좌표 출력 없어 고정 사건 분모 제외. 원래 E1에서 축 순서가 원인인지는 여전히 미확인.

- ⑤에서 O04의 PDF index4 스크린샷 및 L463–473 공식 flag key를 추가 재확인했다. 1=본토 Newlyn, 2=Scilly St Marys, 3=IoM Douglas02, 15=offshore, 16=outside. 따라서 ④b의 datum mapping 추정을 공식 규칙으로 강화하되, 원자료 점행 자체의 공식 ZIP provenance는 여전히 미확인. flag1은 본토 datum 범위이며 2km 연안 buffer 가능하므로 엄밀한 내륙 여부는 원자료 지리 설명 확인 필요. X05와 X16/17 차이를 native-vs-NTv2라고 확정하던 ③ 설명은 철회: X16/17 native형 전체 CSV도 TP31/32에서 NTv2 mirror E/N과 일치.
