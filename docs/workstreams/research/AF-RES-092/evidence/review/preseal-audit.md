# AF-RES-092 사후 답 미노출 검토: P2 완결과 같은 예산의 해석

## 판정과 수정 제안

**수정이 필요하다. 사전 봉인 행을 바꾸지 말고, `고정 Pandoc 경로의 조건부 문서 완결`과 `원 Quarto 처리사슬의 완결 미확인`을 별도 열로 적어야 한다.** 사전 `P2 A=완결/B=완결`은 구체적이고 유망한 매크로 경로를 발견했다는 관측으로 보존할 수 있다. 그러나 이를 원 질문자가 제시한 Quarto 경로 전체에 필요한 연결 근거까지 모두 확인했다는 뜻으로 읽으면 과장이다. 원 Quarto가 만든 실제 `.tex`의 명령·템플릿과 고정 Pandoc 참조판의 코드가 같다는 연결은 두 후보 행 모두 스스로 `unconfirmed`에 남겨 두었다.

이 검토는 기존 계약·후보·검색 로그와 이미 읽은 고정 Pandoc 세 파일만 사용했다. 원 질문/답/댓글/채택, 다른 Quarto 파일, booktabs 문서, 외부 자료를 새로 열지 않았다. 별도 조사자의 근거 검토지만 사전 판단을 본 뒤의 감사이며 독립 맹검 검색·평가자 일치도 자료가 아니다. 인접판 메타데이터 조사와 기능판정 검토도 구별한다.

고정 코드에서 명령 이름이 확인되므로 booktabs PDF 실패만으로 이 경로를 전면 반박할 수 없다. 반대로 booktabs 동작을 읽지 못했으므로 폭 변수 설정 같은 다른 해법을 문서 근거 없이 반환해서도 안 된다. `완결`과 `모든 테이블에서 항상 안전`은 다르다. 선택적 폭 인수를 받는 다른 호출, 다중 표 중 하나만 변경, 다른 template가 뒤에서 다시 정의하는 경우는 현재 경로의 조건이다.

**최소 관측:** P2의 공개 R0 입력을 명시한 참조 Quarto 1.4.553로 `.tex`까지 생성하거나, 그 판의 template/writer 연결 코드를 확인한다. 반환할 두 재정의 앞에 booktabs가 로드되고, 해당 표가 인수 없는 top/bottom 매크로를 호출하며, 재정의가 그 뒤에 다시 덮이지 않는지를 확인한다. 이 세 조건이 맞으면 엄격한 연결 판정을 문서적 완결로 올릴 수 있다. 실제 PDF에 선이 남거나 undefined-control-sequence/선택적 인수 누출이 나오면 제안 경로를 반박/수정한다. 이 최소 관측은 이번 감사에서 실행하지 않았다.

### 검색2 파서 실패

로그는 Unicode separator를 Python `splitlines`가 줄 경계로 다룬 JSON 파싱 실패를 기록한다. 같은 질의를 다시 실행하지 않고 그 1회 예산을 소비시킨 처리는 사후 유리한 재시도를 막는다. 하지만 이를 성공 검색과 동일한 증거 노출로 취급하면 A/B 능력 비교가 왜곡된다. P2-B는 검색 예산2/2 소비, **성공 노출 검색1/2**다. `검색23성공+1실패`라는 전체 집계만으로 이 영향이 사라지지 않는다.

**수정:** 실패행은 그대로 보존하고 P2 대응쌍에 `retrieval_fault=true` 또는 동등한 비교제한 주석을 추가한다. 주 관측 6쌍에는 남기되, 성공 검색만 비교하는 보조 분모에서는 P2를 구분한다. 파서 복구 후 같은 고정 입력을 재실행하더라도 원 12경로의 과거 노출로 대체하지 않고 별도 사후 민감도 실험으로 둔다.

**최소 관측:** 저장된 같은 코퍼스와 같은 regex를 고친 파서로 한 번 실행하여 정상 결과가 어느 파일·절을 상위40에 노출하는지 확인한다. 결과가 여전히 전부 Pandoc이면 인접 검색 노출0의 원인은 순위 규칙임이 더 강해진다. 인접 문서가 나타나 다른 반환을 만들면 실패 결손이 결론에 영향을 준 것이다. 이 감사는 재실행하지 않았다.

### PDF 실패와 네 번의 성공 열람

SCOPE는 `최대4개의 서로 다른 원파일을 열 수 있다`고 하고 실제 본문 열람을 open 이벤트로 센다. 본문이 전혀 오지 않은 PDF 실패를 직접자료·성공 열람으로 세지 않는 것은 그 정의와 양립한다. 따라서 현재 기록만으로 숨긴 성공열람 초과라고 단정하지 않는다. 다만 user의 `같은 열람 예산`을 접근 시도 상한으로 읽으면 B는5회이다. 이 정의 차이를 완결 비율의 숨은 자유도로 두지 않아야 한다.

B 이벤트 순서는 실패PDF → MANUAL → Table.hs → Quarto schema → default.latex다. 접근 시도4회 상한을 사전 적용했다면 마지막 default.latex를 읽지 못했을 것이다. 이 자료가 제공하는 패키지 로드·header 순서 근거를 그 보조 분석에 사용하면 안 된다. 이미 A에서 읽은 template 기억도 B의 접근 예산을 대신할 수 없다.

**수정:** P2-B를 `성공4 + 실패1 = 시도5`로 필수 표2에서 표시한다. 성공본문 상한과 요청시도 상한의 두 해석을 모두 남긴다. 예산 위반을 사후 소급 선언하거나 실패비용을 없애는 방식은 피한다.

**최소 관측:** 추후 프로토콜에서 실패 요청의 비용, 재열람, 자료 하나의 단위와 경로명 탐색을 사전에 정의한다. 동일 질문에 성공본문4/시도4 두 예산을 별도 배정하면 실패가 많은 인접 범위의 실제 비용을 확인할 수 있다.

## 3. 소스 집합과 순위가 만드는 해석 제한

A와 B는 공통 Pandoc 판을 공유하고 B만 Quarto/booktabs를 허용한다. 그러나 검색결과는 repository 순서가 파일 우선순위보다 먼저 적용되고 주 도구가 항상 앞이다. 이미 A에서40행 이상 나온 P2 질의1에서는 B의 추가 자료가 아무리 적합해도 노출될 수 없다. **허용 소스 집합이 넓어졌다는 것과 실제 후보 노출이 넓어졌다는 것은 다르다.**

노출 상한의 단위도 서로 다른 자료가 아니라 match 행이다. P2 검색1의40행에는 동일한 명령을 반복하는 여러 test/command 파일과 같은 파일의 여러 행이 들어간다. 이것은 봉인한 정렬 규칙을 일관되게 적용한 결과이므로 사후 편향 조작이라고 볼 근거는 없다. 다만 이 정렬 정책의 결과를 일반 검색기의 인접 단계 발견 능력으로 외삽할 수 없다.

Quarto schema를 두 번의 경로명 목록 탐색 후 직접 고른 것은 로그에 투명하게 남아 있다. 이는 유효한 탐색 행동이지만 결과는 `regex 검색 + 경로 탐색 + 조사자의 도구 지식`의 결합이다. 상위40 목록에서 발견된 인접 후보라고 쓰면 안 된다. P2는 A→B 순서이며 B는 A의 구체적 매크로 해법을 기억한 상태에서 wrapper 전달만 확인했다. 이 한 쌍으로 B가 A만큼 쉽게 독립 발견한다고 주장하지 않는다.

**수정:** 결론을 `이 고정 코퍼스·노출 순위·같은 조사자의 교차 순서에서는 추가 완결을 관측하지 않았다`로 한정한다. `인접 범위 확대 자체가 무익하다` 또는 `추가 자료를 동등하게 탐색했지만 이점이 없다`는 표현은 지지되지 않는다. 직접 경로 탐색의 사용·비용도 표2/방법에 남긴다.

**최소 관측:** 질의·판·4원자료·최종2링크를 유지하되, 자료집별 할당 노출 또는 파일 단위 중복 제거처럼 다른 사전 순위를 별도 실험한다. 이를 원 12경로와 합치지 않는다. B에서 인접 자료가 실제 노출·선택되어 제약 충족이 달라지면 현재0증분을 순위정책 의존 결과로 재해석한다.
