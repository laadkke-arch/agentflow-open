# AF-RES-092 원자료·분모·후속 관측 독립 검산

## 판정

요청받은 집계에서 산술 오류나 중복 산입은 찾지 못했다. 원장 104행 중 최소량에 산입된 자료는 40개이며, 저작/사건 계보를 합친 그룹은 29개다. 계획 표본 6질문, 실행 12경로, 계획 대응쌍 6개와 엄격 비교 가능 5개를 구분하면 집계가 맞는다. 최초 봉인의 양쪽 완결 3/6과 원 Quarto 연결을 보수적으로 재평가한 2/6도 각각 별도 시점의 판정으로 일치한다.

수정이 필요한 것은 숫자보다 보고 문구와 표 표시다. `29개 독립 실험`, `실제 실행 8건`, `원 질문자 성공률 0%`, `과거 채택 5건`, `모든 역사적 댓글이 30일 이내`라는 표현은 현재 증거보다 강하다. 또한 사후 보고서 J1 행에 이스케이프하지 않은 파이프가 있어 Markdown 표 열이 깨진다. 기존 파일은 수정하지 않았다.

이 검산은 저장된 원장·CSV·실제 열람 로그·API 영수증의 교차 대조다. 외부 40개 자료를 이번 검산에서 새로 열었다거나 공개 API가 숨김·삭제 자료까지 완전하게 보존한다고 주장하지 않는다. 새로운 외부 검색, 재실행, 커밋은 하지 않았다.

## 1. 원자료 40개와 저작/사건 그룹 29개

검산 입력은 `sources.jsonl`, `frame.csv`, `searches.jsonl`, `candidates.csv`, `outcomes.csv` 및 `evidence/outcomes/`의 보고서와 네 영수증이다.

|구분|최소량 산입 자료 수|계보를 합친 저작/사건 그룹 수|분류 확인|
|---|---:|---:|---|
|새 질문 R0|6|6|`new_r0`, 지정된 질문 ID 여섯 개와 일치|
|매뉴얼·공식 코드|14|10|`manual_code`; jq 구현 두 파일, Pandoc 문서 세 파일, Pandoc LaTeX 구현 두 파일은 각각 같은 그룹|
|상류 동작 근거|8|4|기존 경로의 시험 파일 2개와 사후 상류 자료 `UP-01`–`UP-06` 6개; jq 시험 모음, Pandoc 시험 모음, 이슈 7343, 이슈 7369로 묶임|
|오디오|6|5|규격 1, 구현/문서 3, 릴리스 1, 실제 실패 1; opusfile 구현·문서는 같은 그룹|
|전자책|6|4|규격 2, 구현/문서 3, 실제 사례 1; EPUB 규범 문서 2개와 Readium 문서 2개는 각각 같은 그룹|
|합계|40|29|`count_minimum=true`와 `counted_direct=true`의 원소 집합이 동일|

104행에서 `source_id` 중복은 없었다. 산입된 40행에서 fragment를 제거하고 GitHub 화면/원파일 주소를 같은 파일 주소로 정규화한 뒤에도 동일 파일 URL의 중복 산입은 없었다. 지문 문자열의 중복 산입도 없었다. 다만 서로 다른 파일의 고유성은 서로 다른 사건이나 독립 실험을 뜻하지 않으므로, 40과 29를 함께 보고하는 현재 구조가 필요하다.

29는 통계적 독립성을 보증하는 수가 아니다. 예를 들어 KOReader 구현 변경 `EB05`와 실패 사례 `EB06`은 코드 저작과 사용자 사건으로 분리할 수 있지만 서로 인과적으로 관련된다. 따라서 `중복을 보수적으로 묶은 29개 저작/사건 그룹`이라고 쓰고, 그 수를 표본 수·독립 시행 수·승률 분모로 쓰지 않아야 한다. 같은 두 항목을 하나의 수정 계보로 더 합치는 민감도에서는 28그룹이 되지만 주 비교의 분모나 40개 자료의 파일 단위 집계는 변하지 않는다.

상류 동작 근거 8개에는 시험 입력·기대 출력 6개와 공개 문제/관측 기록 2개가 포함된다. 이것을 연구자가 성공적으로 실행한 8건 또는 8개 독립 실패 사건으로 부르면 안 된다. 코드·기대 출력 열람, 원 사용 기록, 연구자 실행은 서로 다른 근거 수준이다.

### 실제 독해 표시와 제외 처리

산입된 40행 모두 URL, 열람 시각, 직접 확인 내용, 재열람 경로, 지문 또는 판별 값을 가진다. 경로에서 연 매뉴얼·코드 14개와 상류 시험 2개는 `searches.jsonl`의 실제 `open` 기록과 대조할 수 있다. 원장만으로 외부 내용의 진실성을 새로 재검증한 것은 아니지만, 최소량에 검색 요약이나 접근 실패를 섞었다는 정황은 발견하지 못했다.

독해 상태를 나타내는 필드는 통일되어 있지 않다. 산입 40행 중 `direct_read=true`가 12행, `directly_opened=true`가 6행이며, 나머지는 `views`·열람 시각·관측 내용과 산입 표시로 독해를 기록한다. 반대로 `POST-J1`–`POST-P3` 및 `POST-PD-EXAMPLE-LISTS`는 `directly_opened=true`이면서 최소량 산입은 false다. 이는 이미 센 사건이나 같은 저작의 재확인이므로 맞는 처리다. `counted_direct=false`를 `읽지 않음`으로 바꾸어 해석하면 오류가 난다. 후속 자동 검산에서는 `본문을 실제 읽었는가`와 `최소량에 새로 산입하는가`를 별도 필드로 통일하면 좋다.

접근 실패 12행, 메타데이터 전용 자료, 불완전 독해, 중복 판/같은 저작의 보조 자료, 교정용 26행 등은 최소량에서 빠져 있다. 교정 세 사례나 사후 답·댓글이 새 질문 R0 또는 독립 사건을 늘리지 않는 것도 맞다. 산입 40행 중 발행 시각 공석은 `AUD-04`, `UP-01`–`UP-04` 5행이다. 판·경로·지문이 있어 재확인은 가능하지만, 이를 발행 시각까지 확정된 40개로 표현해서는 안 된다.

## 2. 모집·경로·비교 분모

`frame.csv`는 jq 원순번 3·4·6과 Pandoc 원순번 3·5·6의 지정 여섯 ID만 포함한다. `candidates.csv`는 사례별 A/B가 정확히 한 번씩 있는 12행이다. 독립 두 번째 제약 `C2`는 J2와 P2에서 비어 있고 나머지 네 행에만 있다. 빈칸을 실패로 세거나 추가 제약으로 채우지 않았다.

|사례|최초 봉인 A/B|사후 보수 A/B|엄격 비교 포함|해석|
|---|---|---|---|---|
|J1|완결 / 완결|완결 / 완결|예|양쪽 완결|
|J2|부분 / 부분|부분 / 부분|예|어느 쪽도 완결하지 못함|
|J3|완결 / 완결|완결 / 완결|예|양쪽 완결|
|P1|부분 / 부분|부분 / 부분|예|어느 쪽도 완결하지 못함|
|P2|완결 / 완결|부분 / 부분|아니오|원 Quarto 연결의 공백과 경로 B 실행 결함을 별도로 보존|

세 집계는 용도가 다르며 모두 남겨야 한다.

- 최초 봉인 전체 6쌍: A만 0, B만 0, 양쪽 완결 3, 어느 쪽도 완결하지 못함 3.
- 사후 보수 판정 전체 6쌍: A만 0, B만 0, 양쪽 완결 2, 어느 쪽도 완결하지 못함 4.
- 엄격 비교의 계획 6쌍: A만 0, B만 0, 양쪽 완결 2, 어느 쪽도 완결하지 못함 3, 비교 불가 1(P2). 비교 가능한 분모는 5쌍이다.

따라서 `B만 추가 완결 0/5`는 엄격 비교 가능한 다섯 쌍의 관측 요약으로 계산할 수 있다. 이것으로 인접 단계 탐색의 보편적 효과가 0이라고 추정할 수는 없다. 동일 조사자의 교차 순서, 작은 목적 표집, 검색 순위와 실패 처리가 남아 있기 때문이다. P2를 제외했다는 사실을 숨긴 채 전체 표본이 5였다고 쓰면 안 된다.

## 3. 예산·실패·검색 순위

`searches.jsonl` 79행은 검색 24, 성공 원문 열람 33, 종료 12, 경로 탐색 9, 열람 실패 1로 구성된다. 여섯 사례 모두 A→B/B→A 교차 순서가 지정대로 기록되어 있다. 각 경로 검색은 명목상 2회이며, 성공 본문 열람은 다음과 같다.

|사례|A 성공 열람|B 성공 열람|추가 실패|
|---|---:|---:|---|
|J1|2|2|없음|
|J2|2|2|없음|
|J3|2|2|없음|
|P1|3|4|없음|
|P2|4|4|B 검색 2의 파서 실패, booktabs PDF 접근 실패 1회|
|P3|2|4|없음|
|합계|15|18|성공 원자료 열람 합계 33|

상한은 24검색·48성공 원문 열람이지만, P2-B 검색 2는 결과 노출 전에 실패했다. 결과를 노출한 검색은 23회이며, 이 중 P2-B 검색 1은 booktabs 고정 코퍼스 공석으로 부분 코퍼스만 검색했다. 따라서 `정상 검색 23회`라고 묶으면 안 된다. P2-B는 성공 원자료 4개와 실패 접근 1개로 총 접근 시도 5회다. `성공 본문 열람만 4회`라는 사전 운영 정의에서는 상한을 지켰지만, 사용자가 기대할 수 있는 `접근 시도도 4회`라는 더 엄격한 비용 정의에서는 벗어났다. 두 정의와 비용을 같이 공개하는 보수적 비교 불가 처리가 적절하다.

P2의 결함은 단순히 시간 비용만 다른 것이 아니다. B의 두 번째 질의가 실패했고, 첫 질의 노출 상위 40개는 A와 같은 Pandoc 자료였다. 추가된 저장소가 허용 집합에 존재해도 실제 앞 순위 노출이 달라지지 않을 수 있다. Quarto schema는 후속 경로 탐색에서 골랐다. 따라서 이 사례로 `인접 문서를 검색할 기회가 같은 강도로 제공됐다`고 쓰면 안 된다. 자세한 사전 판단·순위 검산은 [preseal-audit.md](preseal-audit.md)에 보존되어 있다.

이 순위 한계는 P2만의 문제가 아니다. B 전체 12개 정규식 질의의 실제 노출 항목을 저장소별로 다시 세면 인접 저장소 항목은 0개다. B에서 읽은 인접 원문 6개는 P1의 rmarkdown·fontspec·Eisvogel, P2의 Quarto, P3의 CSL·Better BibTeX이며 경로명 탐색 9회 뒤 직접 선택했다. 따라서 관측된 B는 `정규식 검색 결과가 인접 답을 끌어올린 경로`라기보다 `인접 저장소를 열 수 있게 허용하고 파일 경로 탐색으로 보충한 경로`다. 경로 탐색 비용을 9회로 공개한 점은 강점이지만, 이를 검색 예산 밖의 무비용·자동 선택처럼 취급하면 안 된다. 이번 0/5로 인접 검색의 잠재 회수율이나 순위 개선 효과까지 부정할 수 없는 가장 큰 이유 중 하나다.

## 4. 최초 답·현재 채택·30일 창

`api-receipts.json`은 봉인 SHA `a04fbb20ca1a415235f69a1018a93e07e7adc926` 이후의 질문 6, 답 7, 질문 댓글 3, 답 댓글 4, 답 개정 11을 기록한다. 다섯 API 응답은 모두 HTTP 200이며 `has_more=false`다. 최초 답 영수증 7개 모두 개정 번호 1의 시각이 해당 답 생성 시각과 같다. 이 범위에서는 최초 보존 답 본문을 읽었다는 표시가 일치한다.

`답 7개`는 여섯 질문에 달린 일곱 답의 최초 보존 판이다. 일곱 질문이나 일곱 독립 사용자 사건이 아니다. J1에 답이 두 개 있다. 현재 채택 5는 2026-11-23 API 확인 시점의 표지이며 과거 채택 시각은 전부 미확인이다.

R0 시각과 영수증 생성 시각을 다시 비교하면 공개 답 7개와 공개 댓글 7개는 모두 30일 이내다. 공개 API에서 30일 이후 답·댓글은 0개다. 다만 삭제·숨김·비공개 기록까지 `없음`으로 확정한 것은 아니다. J2의 2024-07-03 질문 편집은 별도 사건이며, 30일 이후의 새 답·실행 결과로 세지 않는다.

댓글 작성자 표시를 따르면 원 질문자 댓글은 3개이고 질문으로는 J1·P3 두 개다. J1의 감사와 보조 예 실패를 성공으로 세지 않는 현재 `outcomes.csv` 처리는 타당하다. P3는 [질문자 댓글](https://stackoverflow.com/questions/78358965#comment138159258_78358965)의 “Tarleb's answer below has fixed the problem”이라는 보고로 해결 보고 1사례를 지지한다. 그러나 원 명령·정확 사용판·해결 후 출력이 없어 완비 실행 검증으로 올릴 수 없다. J3의 답변자 출력도 원 질문자의 실행 출력과 구분되어 있다.

`정확판과 출력이 함께 확인된 질문자 사례 0/6`은 증거 확보율이다. 검증 가능한 원 질문자 실행만을 분모로 삼은 실행 성공률은 분모 0이므로 **산출 불가**다. 실제 사용자 성공률을 0%라고 쓰는 것은 현재 자료의 결론이 아니다.
