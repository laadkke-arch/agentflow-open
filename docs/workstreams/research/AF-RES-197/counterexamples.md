## 반례
- 같은 체크 수, 다른 ID: [T05](https://github.com/TanStack/table/issues/4555), [T06](https://github.com/TanStack/table/issues/4555#issuecomment-1325742392), [X11](https://github.com/TanStack/table/discussions/3619), [C16 L199-201](https://github.com/TanStack/table/blob/v8.5.15/packages/table-core/src/core/table.ts#L199-L201). 연구자 가상 p1=[a,b], p2=[c,d]에서 index0 선택 후 p2로 이동하면 c가 체크될 수 있다. 둘 다 count=1이라 count만 비교하면 틀린다. stable ID a이면 p2 객체 모델에는 a가 없다.
- ID state는 남으나 객체는 현재면: [T01/T02](https://github.com/TanStack/table/discussions/4873), [C06 L191-208](https://github.com/TanStack/table/blob/v8.5.15/packages/table-core/src/features/RowSelection.ts#L191-L208). 반대로 전 행이 적재된 클라이언트 [D05](https://github.com/TanStack/table/blob/v8.8.4/examples/react/row-selection/src/main.tsx)는 page 이동해도 core 모델이 전체라 같은 문제가 필연은 아니다. [D07](https://github.com/TanStack/table/discussions/2155) 2023-06-06 소비자 객체 cache는 이미 적재된 객체 유지 가능, 신규/변경 데이터는 여전히 조회 필요. false key/undefined 및 stale 객체 경계.
- 이미 명시된 현재면: [M03](https://github.com/mui/mui-x/issues/2672), [D04](https://github.com/mui/mui-x/pull/2781); 다른 면에는 손대지 않는 UI 요구. 불필요한 전체 ID 조회/되묻기는 오히려 요구와 불일치. [D06](https://github.com/TanStack/table/discussions/3619) consumer page handler 예. UI-only 요청에 한정; 서버 일괄 edit가 추가되면 별도 수신 계약.
- 전체에서 제외: [T08](https://github.com/TanStack/table/issues/4781) select all 후 1행 제외하는 실제 동작 보고(미로드 포함 의도, 구현은 미충족); [C15](https://mui.com/x/react-data-grid/row-selection/#controlled-row-selection), [C17 L717-737](https://github.com/mui/mui-x/blob/v8.0.0/packages/x-data-grid/src/hooks/features/rowSelection/useGridRowSelection.ts#L717-L737) 새 판의 exclude 조건. UI 모델에서 전체의 서버 분모를 유추하지 않음. 가상 F0={a,b,c}, exclude={b}, 신규 d 도착. snapshot 결과 {a,c}, live {a,c,d}; 둘 다 적절할 수 있으며 계약이 달라야 한다.
## QGIS 별도 집합
- [G01](https://docs.qgis.org/3.44/en/docs/user_manual/working_with_vector/attribute_table.html) 표시 필터와 layer/provider query subset이 다름. 표시되지 않는 선택 feature가 있더라도 layer에 속한다면 selected-only export 후보; source subset 밖 행은 선택 후보에 없는 것. Map extent 제한이 추가되면 출력 범위도 별도 확인.
- [G06](https://docs.qgis.org/3.44/en/docs/user_manual/introduction/general_tools.html) regions.shp에서 TYPE_2=Borough 선택, 복사해 새 레이어에 저장하는 절; [G03](https://docs.qgis.org/3.44/en/docs/user_manual/processing_algs/qgis/vectorselection.html) 새 선택/추가/제거/교집합과 extract output 분리. [G02](https://docs.qgis.org/3.44/en/docs/user_manual/managing_data_source/create_layers.html), [G04](https://docs.qgis.org/3.44/en/docs/user_manual/processing_algs/qgis/vectorgeneral.html) selected-only flag/알고리즘 및 empty output. QGIS에서 원자료 ID가 출력까지 보존되는지는 별도 검증(새 provider ID 재할당 가능).
- [G05](https://docs.qgis.org/3.44/en/docs/training_manual/vector_analysis/basic_analysis.html) roads subset filter 후 Save Features As (선택 피처만 저장과 다른 예), roads_34S 출력 설명. 실제 feature ID나 output file을 확보/실행하지 않았으므로 정확한 수는 미확인.
- GIS 원리: 표시 D, layer universe U, 선택 I, 출력 O와 extent E를 따로 둔다. 데이터그리드에서 D⊂U일 때 선택에 필요한 scope와 실제 처리 집합을 분리하는 비유. 공간 query나 레이어 ID가 서버 페이지 API와 동일하다는 주장 아님.
