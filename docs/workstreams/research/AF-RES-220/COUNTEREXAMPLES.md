# 반례·정정 — 원순위 관측 이후 별도 보조 조사

이 파일은 검색 도착 예산(원 1위/자기 제외 첫 이슈의 본문·응답, 각 직접 링크 최대 1개) 밖에서 확인한 자료를 분리한다. 보조 자료를 첫 도착 답으로 소급하지 않는다. source_id는 sources.jsonl 참조.

## 1. 같은 숫자열, 반대 목표
- O01은 01,12를 정수 1,12로 자동 해석하고 싶다는 요청이다. 보존 단서로 바꿔 읽으면 정반대다. C01의 후속 망설임과 C04의 명시 타입 수용은 처음의 자동 탐지 요구를 완화하지만, 사전 동결 목적은 바꾸지 않는다.
- C12 #5782는 09001→9001 손실 때문에 VARCHAR를 원했다. C13 PR5850의 strict integer/double leading-zero 거부와 회귀 기대값 09001 VARCHAR, 명시 cast 09001/00009001→9001이 서로 다른 목적에 대한 선택임을 보여 준다. #11411을 #5782의 duplicate로 배제하지 않는 이유다. C14는 사용자 dev 판 성공 보고이나 정확한 판/입력 없음.
- P02에서 주 FIPS 01/02/12, P03에서 2자리 코드, P01 NYT에서 fips 필드; 발행자의 코드폭을 보존할 때는 문자 혹은 폭을 별도 계약으로 둔다. 정수 집계만 필요한 경우에는 명시 cast가 맞다. C11은 15자리 ID를 BIGINT로 바꾸는 소비자 선택을 보고했으나 OOM 해결은 아니었다. 코드폭을 아는 경우 정수+표시 규칙이 가능하더라도 임의 가변 길이나 접두어에서 복원 불가.
- P04의 5778→0005778, D000126; P05의 patent_id varchar(20)와 patent_date date/num_claims int(11)는 한 파일 안에도 서로 다른 역할이 있음을 보인다. P05는 2025년 보관본, 2024-12-31 데이터 기준이고 신고 파일 동일성 불명.

## 2. 인용, 표본, 판과 해법
- M01 RFC4180 §2는 쉼표·줄바꿈·인용부호의 구조적 escaping을 정의할 뿐 모든 quoted field의 문자열 타입을 보장하지 않는다. TSV는 그 자체가 RFC의 쉼표 형식이 아니다. M02 현행 문서도 인용 숫자를 여전히 추론한다. 전부 숫자처럼 생긴 quoted ID를 full scan해도 BIGINT 가능; 유형 명시는 다른 해법이다. O03에서 표본보다 뒤의 접두어 D1000263가 드러나는 경우에만 -1이 후보가 된다. C07의 LIMIT100 통과와 CTAS 실패는 부분 읽기와 전체 검증의 차이다. C08은 첫 비수치 2,156,093행이라고 했으나 O03 안정판 8,123,649행 D1000263 및 nightly 인용 오류 2,156,093행과 충돌한다. 행을 합치지 않는다. C15 quote-relax PR은 인용 오류와 관련되지만 타입 보장 근거는 아니다.
- O02는 dateformat을 주었는데 DATE가 아니라 VARCHAR; 명시 DATE/strptime은 작성자 자체 출력으로 작동. C06은 v1.0.1-dev4803에서 같은 시험 성공이라 보고하지만 C16 버전 커밋 자체는 pipeline cardinality 변경이다. 실제 CSV fix commit과 정식 릴리스는 미확인. M04의 현재 format 설명을 과거 판의 해결 근거로 쓰면 안 된다.
- O04의 2047/2048은 헤더 외 데이터 행수다. M06의 2048 chunk 및 20480 표본은 원인 가설이지 원래 버그의 코드 위치나 패치 증거가 아니다. C09 재현 확인에 그쳤다. C17은 2025년의 천 단위 쉼표+소수점 점 예(100,000.00)로 타입을 명시해도 실패했다고 보고한다. 이슈 #12856의 소수 쉼표만 해결한다 해도 천 단위 제거 문제와 동일하지 않다. M03의 현행 thousands 옵션도 역사판에 소급하지 않는다.
- M05: 값의 수학적 동일성·표현 동일성·정밀도는 별개의 계약이다. 데이터 발행자와 분석 소비자, 추론 구현자의 최적점이 다르다.

## 3. 검색자의 반례
- #12856 B의 자기 원문 1위는 정확한 재현 증거를 제공하나 고치는 조작을 제공하지 않는다. 이 점수 1은 부분 관련성에만 해당. 정확한 해결 여부만 세면 원·제외 모두 4쌍 동률(모두 0). 원래 점수 1도 조작을 요구할 경우 U로 남기는 민감도: 원 포함 동률3·판정불가1.
- #11583 B는 자기 rank 5→2지만 첫 답은 DATE가 아닌 ID 문자열 보존 사례로 이동했다. 외부 첫 링크 2개 모두 0이어도 방향이 서로 다른 오답이다. 자기 포함 검색은 학습용 정답 회수와 새로운 발견을 혼동시킨다.
- 4개 only-self 응답에서 제외 후 공집합은 관측된 결과 없음이다. 제공자 전체에서 적합 사례가 없다는 주장이나 검색 실패/결측으로 재분류하지 않는다. 5개 제한, 단일 repo, AND-like 어휘 제약, 업데이트된 인덱스·본문과 날짜 제한 때문에 일반화 불가. 모든 반환 score=1은 ranking tie/알고리즘의 설명이 아니다.
- #11411 A에 이미 ignore leading zeros라는 목적 표현이 있다. #12856 A number field는 넓은 일반어다. A/B가 동일 토큰 하나 차이여도 목적 정보의 증가량이 균일하지 않다. 표본과 발표자 ID 노출, 비가림 판독, 사전 의도 동결과 사후 외부 판독을 별도 기록했다.

## 4. 원장 정정
초기 원장 O/G/M01/P01의 checked_utc를 첫 검색 시작 시각으로 일괄 적었던 것은 실제 개별 열람 시각으로 볼 수 없어 확인 가능한 시간창으로 낮췄다. P01의 카운티 코드 5자리 단정도 읽은 README 절만으로 강제 계약을 주장할 수 없어 fips 필드 존재로 낮췄다. 원래 커밋 07ab630 및 274a469에서 변경 전 값을 보존한다. P05는 PDF 본문 추출을 읽었으나 요청한 페이지 이미지 확인 실패, P06은 동일 저작 메타데이터로 비산입; F01/F02 실패. P05를 보수적으로 비산입해도 하한 충족. 검색 원응답 8개는 자료 수에서 제외.
