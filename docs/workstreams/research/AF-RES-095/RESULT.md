## 판과 처리 단계

1. **직접 관측.** 배포 tar.gz 118,537,400바이트의 SHA가 공급자 파일과 일치했다. 번들 경로 `bin/tools/x86_64/pandoc`의 3.1.11을 execve에서 확인했다. 독립 참조 Pandoc도 버전 이름은 같다. 실제 바이너리 SHA는 `9c91e481cfaac807e20fcb72dadad1e531a9e3f8233d10ade7405bf90d76fd5e`다. 표본은 Debian 13.6 x86_64, XeTeX 0.999996, LaTeX2e 2024-11-01 PL2, 설치 패키지 TeX Live 2024.20250309 계열이다. XeTeX는 자체 버전에 `TeX Live 2025/dev/Debian`을 표시한다. [공식 배포](https://github.com/quarto-dev/quarto-cli/releases/tag/v1.4.553) · [환경 지문](environment.json)
2. **직접 관측.** Quarto는 Qmd를 staged Markdown과 metadata로 넘겼다. defaults의 `from`은 번들 `qmd-reader.lua`, `to`는 `latex`, writer 출력은 `document.tex`였다. main.lua 필터 실행이 진단에 있고 임시 template.patched와 13 부분의 해시는 배포 파일과 일치한다. 번들 reader를 같은 staged 입력에 JSON sink로 별도 호출했을 때 원 표의 TableHead 행은 0, 첫 TableBody 행은 Name/Number였다. 대조 첫 행은 실제 헤더였다. 필터 직후 전체 AST는 미확인이며 생성 tex가 두 구조를 반영했다. [실제 defaults](evidence/matrix/D-O-1/pandoc-defaults.yml) · [원 reader](evidence/matrix/D-O-1/reader.json) · [Pandoc pipe table](https://github.com/jgm/pandoc/blob/c3038dcd54152c4e18e49db31676b79ee7cc29b2/MANUAL.txt#L4545-L4585)
3. **직접 관측.** writer는 대상과 대조의 longtable에 `\toprule\noalign{}` 및 `\bottomrule\noalign{}`를 남겼다. 대조의 실헤더 뒤만 `\midrule\noalign{}`가 있었다. 패키지는 tex L55, 본문 시작 L140, 공통 재정의 L143–144로 생성됐다. `.fls`에서 xelatex.fmt 및 booktabs.sty 경로를 읽었고 `.log`가 booktabs v1.61803398을 확인한다. [D-T-1 생성 tex](evidence/matrix/D-T-1/document.tex#L143) · [실제 로드 순서](evidence/matrix/D-T-1/document.fls) · [패키지 정의](https://texdoc.org/serve/booktabs/0#page=11)
4. **기전 해석.** booktabs는 본래 선택 폭과 전후 간격을 다룬다. Z의 빈 정의는 뒤의 `\noalign{}`를 빈 alignment 간격으로 남긴다. T의 두 필수 인수는 `\noalign` 제어열과 `{}` 그룹을 각각 받는다. P-TRACE-T에서 4회 이 토큰을 기록했다. 두 경우 모두 첫 표의 첫 셀 위치가 229.608에서 226.020pt로 올라갔다. 대조 헤더 구분선도 341.353에서 331.663pt로 올라갔고 두께 0.4982pt는 같았다. 값과 행 순서는 동일했다. [LaTeX 인수 정의](https://github.com/latex3/latex2e/blob/08926fa6af2c978cbd19f14597252877619f6338/base/ltdefns.dtx#L260-L275) · [P-TRACE-T 로그](evidence/probes/P-TRACE-T/document.tex-log.txt#L813) · [D-O-1](evidence/matrix/D-O-1/) · [D-T-1](evidence/matrix/D-T-1/)
5. **측정 방법.** PDF word 좌표로 각 제목 다음의 2열과 표 영역을 찾았다. 검은 수평 벡터는 좌표, 폭, 셀 영역과 겹치는 길이를 검사했다. 별도 Poppler 288 DPI에서 회색조 값 128 미만이 가로 90% 이상 연속되는 줄을 밴드로 세고 벡터 중심과 0.75pt 이내 일치가 필요했다. 교정에서 지정 폭·좌표의 한 줄과 밑줄·페이지 긴 선의 오탐 여부를 확인했다. [교정과 음성 구역](evidence/calibration/README.md) · [벡터 사양](https://github.com/pymupdf/PyMuPDF/blob/1.26.6/docs/page.rst#L1550-L1627) · [Poppler 설명서](https://manpages.debian.org/trixie/poppler-utils/pdftoppm.1.en.html)

## 반례와 한 표의 해법

- **직접 관측.** P-LOCAL-Z·P-LOCAL-T에서 `\begingroup`과 `\endgroup`로 첫 longtable만 감쌌다. 첫 표 0/0/0, 뒤 표 1/1/1, 셀 전부 보존이었다. P-HEADER-T와 P-INCLUDE-T는 두 표 모두에 적용됐다. preamble의 두 형식은 booktabs 뒤 같은 위치에 정의를 넣었다. [Qmd 예](fixtures/probes/local-T.qmd) · [프로브 실측](evidence/probes/README.md)
- **직접 관측.** P-TABULAR-Z는 정상 호출 다음의 Stable을 남겼고 P-TABULAR-T는 able로 잘랐다. 선택 폭을 넣으면 Z와 T 둘 다 폭 토큰 일부를 셀에 출력했다. 비어 있지 않은 `\noalign{\vskip 8bp}`는 Z에 남아 T와 행 간격 차이 8.000pt를 냈다. P-BARE-BOTTOM-T에는 다음 `\end{tabular}`가 있어 TeX 종료 1과 PDF 없음이었다. 같은 파일의 O/Z는 둘 다 PDF와 종료 0이었다. [원 tabular 입력](fixtures/probes/tabular.tex) · [raw 반례 결과](evidence/probes/README.md)
- **설계 제안.** 탐색기 카드에는 생성 단계와 현재 정의를 가르는 질문, 적용 대상 범위, 성공 때도 움직이는 위치, 가장 작은 반례를 같은 실행 ID와 붙인다. 해당 PDF 연구판에서 두 후보를 함께 반환한다. raw tabular나 다른 템플릿이 들어오면 실제 다음 토큰을 판단할 절과 입력을 연결한다. [카드](cards.md)

## 다른 출력 분야

- **CSS 관측.** 두 HTML 표에서 공통 타입 선택자는 상·하 실측 밴드를 (2,2)→(0,0)으로 바꿨다. 한 표 클래스 선택자는 (0,2)였다. 셀 자체의 solid 후보를 추가하면 `none`은 선을 남기고 `hidden`은 억제했다. 고정 WPT와 기대 화면의 Chromium 픽셀 차이는 0이었다. 공통 변수는 규칙 선택 후 그리는 대상 집합이다. CSS의 겹치는 요소 edge 후보의 충돌 우선순위는 TeX 두 인수의 토큰 소비로 전이할 수 없다. [CSS 실측](evidence/cross/css.json) · [W3C 경계 충돌](https://www.w3.org/TR/2016/WD-CSS22-20160412/tables.html#border-conflict-resolution) · [WPT 기대값](https://github.com/web-platform-tests/wpt/blob/0ba12e737fd832416b9a29dae9f200b311147517/css/css-tables/border-conflict-resolution-ref.html)
- **Calc 관측.** 같은 Page Style의 Grid 켬/끔은 두 시트의 PDF 격자 path를 (5,5)/(0,0)으로 바꿨다. 서로 다른 스타일은 (5,0)이었고 첫 범위만 직접 붉은 테두리를 줄 때 첫 시트 고유 상·하단 2선과 둘째 0선을 얻었다. 값과 행 순서는 전부 유지됐다. 공통 변수는 그리는 시트가 참조하는 설정 범위다. Calc에는 화면 격자·인쇄 격자·셀 테두리가 별 상태로 존재하며, 이 구별은 현재 macro 정의의 수명과 대응하지 않는다. 26.2 고정 회귀는 원 ODS 셀 테두리 모델, 보조 PDF 실행판은 26.8 개발판이다. [Calc 실측](evidence/cross/calc.json) · [Page Style 도움말](https://help.libreoffice.org/latest/en-US/text/scalc/01/05070500.html) · [셀 원 회귀](https://github.com/LibreOffice/core/blob/afbbd0df0edb6d40b450b0337ac646b0913a760c/sc/qa/unit/subsequent_filters_test.cxx#L958-L1011)
