# 인수와 실행 계약

GitHub의 배정 브랜치 최초 확인값은 `f72073277e6be643302a33f204d70baeb2c749a4`였으며 AF-RES-095 브랜치가 없었다. 진행표의 AF-RES-095 의존 ID는 AF-RES-092이고 AF-RES-092의 `result_commit`은 `e0d7ecda64bab2bd5d5779a9fb2a18d39a83bcdf`였다. [배정 시점 진행표](https://github.com/laadkke-arch/agentflow-open/blob/f72073277e6be643302a33f204d70baeb2c749a4/docs/automation/dot-control.json)

- GitHub AF-RES-092 원격 헤드가 이미 `e742bc665efde0d3883ec4d0f5479e03e914fcbf`였고 지정 인계는 그 조상이다. 지정 [인계](https://github.com/laadkke-arch/agentflow-open/blob/e0d7ecda64bab2bd5d5779a9fb2a18d39a83bcdf/docs/workstreams/research/AF-RES-092/HANDOFF.md)와 후속 [인계의 변경](https://github.com/laadkke-arch/agentflow-open/compare/e0d7ecda64bab2bd5d5779a9fb2a18d39a83bcdf...e742bc665efde0d3883ec4d0f5479e03e914fcbf)을 구분한다. 다음 실행 입력 디렉터리는 `707216d8…`에서 원격 헤드까지 바이트 변경이 없었다. 지정 인계·결과·증거 파일을 이번 실험에 사용했다.
- 요청한 `python -B -m workbench.session start af-res-095 --allow docs/workstreams/research/AF-RES-095/ --dependency work/research-af-res-092=e0d7ecda64bab2bd5d5779a9fb2a18d39a83bcdf --output docs/workstreams/research/AF-RES-095/manifest.json --fetch`는 종료 2, `{"status":"invalid","error":"dependency changed: work/research-af-res-092"}`였다. 도구는 조상 포함 관계와 별도로 현재 헤드와 정확한 일치를 요구한다. [해당 구현](https://github.com/laadkke-arch/agentflow-open/blob/f72073277e6be643302a33f204d70baeb2c749a4/workbench/session.py#L131-L166)
- 지정 SHA로만 구성한 별도 로컬 checkout에서 같은 도구를 `--fetch` 없이 실행해 종료 0으로 [manifest](../../manifest.json)를 생성했다. 현행 원격을 읽은 본 작업 checkout의 원격 추적 ref와 진행표에는 이 대체 생성의 변경을 적용하지 않았다. manifest의 `freshness_at_start`는 `local_only`이며 원격으로 재검증할 때의 오류와 구별한다.
