# AF-RES-116 — 사전 범위 v1

## 목표·경계

같은 매뉴얼 출발점에서 A(요청+URL), B(이미 아는 보존조건의 재진술), C(새 목차 단서)를 받아 3개봉 안에 필요한 동작과 보존조건의 근거·예외를 찾는 과정을 분리 관측한다. 도달 가능성, 실제 선택, 노출된 근거로 뒷받침되는 판단은 별도 지표다. 현재 소프트웨어 실행값·사람의 시간 절약·원 작성자 채택은 추정하지 않는다.

자기 브랜치 `work/research-af-res-116`, 허용 경로 `docs/workstreams/research/AF-RES-116/`만 사용한다. 통합판·main·dot-control.json은 수정하지 않는다. 원시 자료도 허용 경로 안에 둔다. AF-RES-112는 읽기 전용 운영 선행이며 Godot/LilyPond/ZIP 결원을 채우지 않는다.

## 모집 — 원문·답 읽기 전 고정

- 저장소: `jgm/pandoc`, `ImageMagick/ImageMagick`.
- 생성시각: 2023-01-01T00:00:00Z 이상, 2026-01-01T00:00:00Z 미만. PR 제외, 공개 이슈만.
- 원문은 최초 게시물의 현재 공개 body 스냅샷이다. 제목은 식별용이며 검색 포함 여부는 body에서 판단한다. 편집 이력이 있으면 최초 시점의 원문을 복원했다는 주장을 하지 않는다.
- Pandoc body에 대소문자 무시한 독립 단어 `table` 또는 `image`, ImageMagick body에 `profile` 또는 `alpha`가 있는 이슈를 모집한다. 정규식은 `\b(table|image)\b`, `\b(profile|alpha)\b`이다. 복수형만 있는 본문은 제외한다. GitHub 검색은 후보 열거용이며 로컬 원문 검사를 다시 한다.
- 각 단어 별 GitHub 공개 검색을 생성 UTC 오름차순으로 받아 합친 뒤, 번호로 중복 제거하고 `(created_at, number)`로 정렬한다. 첫 50개를 분야별 frame으로 고정한다. 검색 페이지의 마지막 시각이 최종 50번째보다 뒤에 있음을 확인한다. 50개를 보장할 수 없으면 미완성 frame으로 남기고 임의 대체하지 않는다.
- 적격: 원문에 (1) 입력을 출력/표현/상태로 바꾸려는 구체적 조작과 (2) 그 과정에서 유지하거나 복원하려는 관찰 가능한 성질이 함께 있다. 구현 버그도 포함한다. 단순 설치·충돌·속도·기능 목록만 있고 보존 성질이 없는 것은 제외한다.
- 첫 적격 3건씩을 자연 표본 P1–P3 / I1–I3으로 고정한다. 정상·반대 입력은 원문에 있는 것을 우선 기록하고, 없으면 미제공으로 표시한다. 이후 구성한 반대 입력은 자연 자료로 소급하지 않는다.
- 모집 중 댓글·성공 해법·공식 문서 본문은 열지 않는다. 원문 안에 해법이 이미 있으면 노출을 기록하며 제거하지 않는다. 선정은 문서 난이도와 무관하다.
- 문서 기준일: 2025-12-31T23:59:59Z. 명시 버전이 있으면 해당 공식 tag/문서판을 사용한다. 없으면 기준일 이전 최신 안정 공식판의 원 소스·문서 commit을 고정한다. 판 불명·문서판 불일치는 유지한다.
- 공통 시작 URL: Pandoc `https://pandoc.org/MANUAL.html`, ImageMagick `https://imagemagick.org/script/command-line-processing.php`. 실제 수신은 고정판의 로컬 문서 뷰어다. 원 작성자가 건넨 URL은 별도 기록하며 이 가공 시작점을 실제 원저자의 인계라고 부르지 않는다.

## 순서와 가림

1. 이 모집·판정·뷰 규칙과 계약을 원격 봉인한다.
2. 100행 frame 및 최초 적격 6건의 원문·요청·입력 출처를 원격 봉인한다.
3. 문구 제작자는 원문에서 만든 공통 요청과 고정판 시작 목차만 읽고 B/C를 작성한다. B/C는 사건별 같은 50–100 유니코드 문자 수; UTF-8 바이트는 따로 측정한다. C의 새 단서는 실제 표지 하나이며 정답값·깊은 URL·검증 표시는 없다. 작성과 노출을 기록하고 정답을 본 뒤 유리하게 바꾸지 않는다.
4. 꾸러미를 먼저 봉인한다. 그 뒤 기준 판독자가 문서 본문·원 규격·시험을 읽고 gold/도달성/교정 사례를 별도 봉인한다. 제작자와 기준 역할이 같으면 같은 작업자의 시간상 분리라고 쓴다.
5. 자연 6건에 순서 ABC, ACB, BAC, BCA, CAB, CBA를 각각 P1,P2,P3,I1,I2,I3에 배정한다. 각 꾸러미에 새로운 AI 문맥을 제공한다. 포크 이력 없음, 해당 공통 요청/한 줄만 전송, 금지 파일을 읽지 않는 절차적 가림을 사용한다. 공유 파일시스템은 OS 격리가 아니다. 실제 제공 모델·문맥·노출을 기록한다. 독립 문맥을 얻지 못하면 동일인 재판독/위치 재생으로 표시하고 새 독자 선택은 미관측이다.
6. 수신 노출·답을 원격 봉인하고 A/B/C 식별을 가린 평가 입력으로 판정한다. 평가자가 이미 gold/힌트를 보았으면 그 노출을 명시한다.

## 문서면과 행동 예산

- 같은 문서판은 A/B/C 모두 같은 추출·페이지네이션·링크 목록을 사용한다. 최대 3개봉, 개봉당 전체 표시(내비게이션+본문+표시 식별자) 1,500 유니코드 문자. URL은 메뉴의 실제 주소 대신 짧은 선택 ID로 보일 수 있으며 매핑은 원장에 보존한다.
- 첫 문서 페이지도 1회. 다음 구간/이미 보인 링크/앵커 선택도 각 1회. 재열람도 1회다. 뒤로 가기도 개봉으로 센다. 이미 노출된 선택지는 후속 단계에서 선택 가능하다. 전체 문서 검색·숨긴 URL 추측·외부 검색·수신 중 다른 파일 읽기는 금지한다.
- 실제 문서 순서를 유지한다. 목차는 실제 HTML 목차 또는 고정 매뉴얼의 원래 절 제목 순서를 따른다. 연관성 순으로 재정렬하거나 답 근처만 발췌하지 않는다. 본문 끝에서만 다음 구간 선택을 제공한다. 제목 점프는 원문에 존재하는 목차·앵커로만 허용한다.
- 내비게이션/본문 각각의 문자·바이트와 합계, 원문 offset, URL·fragment·판, SHA-256, 표시 선택지와 선택 이유, 이전 단계까지 확인했다고 한 두 조건·예외, 실제 UTC와 측정 wall duration을 기록한다. 작성/판독의 사람 능동시간은 계측하지 못하면 null이다.
- 시작 페이지 생성 방식과 캐시·allowlist는 원 요청 봉인 후 문서를 받으면서 기계적으로 고정한다. 문서 형식 변환은 원문 매핑 및 변환 한계를 기록하고 브라우저 실사용으로 부르지 않는다.

## 도달 가능성·판정

각 사건 gold에는 조작 O와 보존 P 및 필요한 예외 E의 최소 근거 구간을 각각 둔다. 적어도 한 실제 3개봉 경로에서 O/P와 판단을 바꾸는 E를 읽으면 reachable. 고정 뷰어의 3단계 허용 행동을 완전 열거하고 어느 경로도 충분하지 않을 때만 unreachable. 문서판·자료·열거가 부족하면 unknown. 미모집과 구분한다. 원 소프트웨어에서 불가능함과 문서 예산에서 불가능함도 다르다.

단계 평가는 누적 실제 노출에서 인용 위치를 확인한다. full_supported(조작·보존·필수 예외의 충분한 근거), justified_hold(근거 부족을 정확히 보류), partial_reconstruction(일부 조건만 복원), label_only(라벨만 맞고 근거 없음), dangerous_certainty(필수조건을 확인하지 않고 확정), unsupported_or_wrong로 분리한다. 부분 답과 합당한 보류는 함께 태깅할 수 있다. 정확한 절 도착은 충분한 답과 별도다.

한 HTML의 여러 앵커·같은 회귀 코드/PR·미러·반복 개봉은 고유 저작을 늘리지 않는다. 목표 배당은 자연 요청 6, 정의/공식 예제/구현 8, 별도 회귀/문서변경/반대 입력 6, 조립/기록관 4다. 선별용 원문 수와 배당용 24를 별도 대사한다.

교정 사례는 자연 사건을 바꾸지 않고 별도 층으로 사전 봉인한다. 하나는 실제 세 번 이내 양조건 근거 도달, 하나는 비슷한 표지의 절이 예외를 놓치는 경로다. 조립/보수와 기록관은 보조 원리 비교이며 자연 성공 분모에 넣지 않는다.

## 산출물·완료

필수 원장과 표를 재생성 가능한 코드로 연결한다. 18꾸러미/54자리의 관측·조기종료·미모집·실패를 합산한다. 각각 A↔B/B↔C/A↔C 18쌍을 내며 reachable/unreachable/unknown을 섞지 않는다. 실제 관측 없는 효과·시간절약은 null이다. 결손이 남으면 PARTIAL; 긍정 결과는 완료 조건이 아니다. 결과판 커밋→원격 재열람→고정판 검사→검사 영수증→마지막 HANDOFF 단독 커밋 순서를 따른다.
