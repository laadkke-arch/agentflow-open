# AF-RES-116 결과 검토 영수증

**검토 완료: 정정된 보고서는 검토 범위에서 PARTIAL 결과로 수용 가능하다.** 수치나 원 의미 판정을 바꿔야 하는 반증은 이번 집중 검토에서 발견하지 않았다. 대신 해석 범위 5곳과 근거 링크 2곳을 지적했고, 통합 담당이 수정한 내용을 실제 파일에서 다시 확인했다. 이는 54단계 전체의 새 가림 판정이나 향후 결과 SHA에 대한 최종 인수 검사를 대신하지 않는다.

- 검토자: `/root/source_protocol_audit`
- 첫 로컬 시각 체크포인트: `2026-11-24T05:42:36Z` — 첫 읽기 호출 뒤 측정했으므로 정확한 업무 시작 시각은 아니다.
- 완료 시각: `2026-11-24T05:54:46.617208+00:00`
- 당시 HEAD: `1167bb29101c40d4c7fe4bcc58bbd1e2d746670f`. 보고서 출력은 아직 작업 트리 상태였다.
- 새로 쓴 파일: 이 문서와 [result-review.json](result-review.json)뿐이다. 커밋·새 웹 열람은 하지 않았다. 앞선 `evidence/audit/` 원자료 감사는 수정하지 않았다.

## 역할과 실제 노출

앞선 원자료 감사의 읽기 제한이 끝난 뒤 부모가 AF-RES-116 전체 읽기와 별도 결과 검토를 명시적으로 허용했다. **이 후속 검토자는 이제 조건 A/B/C, 한 줄, 기준 자료, 수신 답, 가림 판정과 통합 해석을 아는 비가림 검토자다.** 원자료 감사 때와 같은 AI 문맥이며 부모의 지시와 정정 메시지를 이어 받았다. 새 가림 평가자 또는 별도 문맥 격리가 입증된 독립 실험으로 소개하면 안 된다.

직접 읽은 범위는 결과·해석·자체 점검·재현 문서, 아래 경계 사례의 원답·실제 노출·기준·판정, 교정 및 타 분야 주장의 원장이다. 전체 54단계·18꾸러미는 구조와 수치 검산을 위해 프로그램으로 대조했고, 모든 답을 독립적으로 다시 채점한 것은 아니다. 별도 읽기 전용 보조 문맥 `/root/source_protocol_audit/numeric_result_check`가 원장 연결·비용·분모·쌍 비교·순서·링크를 재계산하여 `2026-11-24T05:44:40Z`에 보고했다. 그 계산 검토 역시 가림 의미 평가가 아니다. 정확한 검토 파일 SHA-256은 JSON 영수증에 남겼다.

### I2의 앞 106자와 끝 60자

고정 corpus의 `i7114_command-line-options[12856:13022]`가 선언한 Extract target이다. 세 조건의 마지막 실제 뷰는 `[11612:12962]`이며, target과 겹치는 구간은 `[12856:12962]`, 정확히 **106/166자**이다. 빠진 60자는 다음과 같다.

> cy, so as to generate a grayscale mask of the image's shape.

세 답 모두 추출 설명의 보인 앞부분과 `Set`이 비활성 채널을 opaque로 초기화하는 조건을 이용해 제한적 부분 답을 쓰면서 원 TIFF와 보존 여부는 보류한다. 그러므로 부분+보류+문서 예외를 함께 기록한 판정을 바꿀 반증을 찾지 못했다. 이 `Set` 예외는 원 `demo.tif` 실패의 실행 반례가 아니다. 원 파일의 unspecified meta 선언·비상수 plane이라는 사실은 기준 판독자가 확보했으며, 수신자가 보았다고 소급할 수 없다.

`r13`의 답 수정 시도는 [원 이벤트](../readers/r13/events.jsonl) 8행에서 `2026-11-24T05:19:08.367107+00:00`에 거절되었다. 원 2단계 답은 유지되고 다음 단계의 오류 인정도 남아 있다. 이 제어 이벤트는 추가 열람이 아니다.

새 사후 위치 진단은 builder와 별개로 누적 doc·offset 문자 집합에서 재계산했다. 같은 선언 fragment 범위는 **8/18**(P1 A/B, P2 A/B/C, I2 A/B/C), target 일부 겹침은 **3/18**(I2 A/B/C), 원 전구간 기준은 **0/18**이다. 새 값은 위치 설명이며 성공 종점의 사후 변경이 아니다.

### 교정의 예외와 같은 화면으로 가는 별칭

[교정 명세](../calibration/preregistered-cases.json)의 인용을 고정 corpus의 실제 offset에 대조했다. K1의 3개 구간과 K2의 2개 구간은 모두 원문과 정확히 일치했다. K1 증인 `open → n3l3 → n3l5`는 standalone과 UTF-8/지역 인코딩·header 예외의 3구간을 덮는다. K2 증인 `open → n3l10`은 heading 이동과 문서 첫 heading의 metadata-title 예외 2구간을 덮는다. 근접 오답 `open → n3l19 → next`는 같은 Reader options 표지의 다른 fragment로 가며 두 필수 구간 모두 덮지 않는다. 표시량도 각각 4,249자/4,335B, 2,826자/2,886B, 4,250자/4,336B로 원면에서 재계산했다.

이 교정들은 기준 읽기 뒤 구성한 문서 경로 증인이다. 새 독자의 선택, Pandoc 변환 성공, 자연 A/B/C의 성공이 아니다. D0도 사후 시작 면 진단이며 자연 및 사전 두 교정 분모에서 빠져 있다.

I1·I2는 서로 다른 링크 ID가 같은 doc·offset으로 가는 경우가 있다. 실제 `display_text` 순서를 비교하면 각각 세 조건의 3면 노출은 같다. I1 B↔C/A↔C와 I2 A↔B/B↔C의 행동 문자열 차이는 문서 노출 차이가 아니다. [pairs.csv](../pairs.csv)가 이 둘을 분리하는 것을 확인했다. P1/P3의 C 경로 차이는 실제 표시 차이지만, 사건·조건당 한 문맥의 관측만으로 한 줄의 일반 인과효과나 사람 시간 절약을 주장할 수 없다.

## 남는 PARTIAL과 검토 한계

P3의 정확한 원 command·engine·template·package 환경, I3의 동일 원 JP2와 필요한 band 해석은 여전히 없다. 최초 remote ref-update 원응답에 의한 독립 업로드 시각 증거도 없다. 보고서는 모집·수신·배당을 수행한 범위와 이 원 사건 복원의 결손을 분리하고 PARTIAL을 유지한다. 0개의 긍정 결과 자체를 실패나 미완료 이유로 삼지 않는다.

이 검토에서 역사 바이너리를 실행하거나 원 사건을 다시 재현하지 않았고, 새 독자를 모집하거나 54단계를 모두 새로 판정하거나 전체 graph를 다시 열거하지 않았다. 부모가 결과 commit 뒤 수행할 필수 공통 검사·전수 재생·최종 인수 영수증은 별도다. 이 문서의 판단은 JSON에 기록한 작업 트리 파일 지문에 적용되며, 이후 수정이나 새 SHA의 검사를 미리 PASS로 인정하지 않는다.
