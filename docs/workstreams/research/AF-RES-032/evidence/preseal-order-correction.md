# A 원격 봉인 전 표집 순서 정정

정정시각: 2026-11-22T07:17Z. 사유는 root의 SCOPE 작성 오류다. 사용자 Q1은 날짜→배포처→매뉴얼 경로 순을 요구했는데 초안은 프로젝트 우선으로 기재했다. 현재 A 목적지·후속판 열람은0이고 A 전체 원격 봉인은 아직 안 했다. 따라서 미래 결과에 따른 교체가 아니다.

## 적용

- 경로R 후보10프로젝트(DBI,curl,data.table,httr,jsonlite,knitr,rmarkdown,xml2,readr,dplyr)의 각 최초2020판(없는 프로젝트는2021→2024)을 원장에서 모두 목록화한다. 후보를 날짜→원장URL→HTMLmember순으로 정렬해 첫6적격문서를 선택한다. 한프로젝트 최대2는 유지한다.
- 이전 프로젝트순 provisional R6은 별도 위치에 그대로 보존하고 최종표본 최소수·A/B분모에 산입하지 않는다. 각 원문을 읽었다는 사실은 시도 이력으로 남긴다.
- 경로D의 Python/PostgreSQL/SQLite는 각2의 사전 strata이고 전체6이므로 date순 정렬은 구성원을 바꾸지 않는다. 분석용 frame은 SQLite2020-01-22→PostgreSQL2020-02-13→Python2020-02-24 순이다. 실제 병렬다운로드 시각은 이 정렬과 다르며 access receipt를 숨기지 않는다.
- 이후 원격 봉인될 references.jsonl의12개만 A다. 이 정정문서는 SCOPE 원문과 함께 보존한다. 최초수집순과 요구한 표집순을 같았던 것으로 보고하지 않는다.
