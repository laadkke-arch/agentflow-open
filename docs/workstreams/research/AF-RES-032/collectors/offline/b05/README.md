이 수집자는 B05를 맡기 전에 A-D04를 이미 읽었다. 검색에서 PostgreSQL이 다시 나왔어도 독립적인 발견 또는 검증으로 부르지 않는다. A의 사건키는 RFC 서비스별 이관, B의 사건키는 전체 tools 전환이라는 서로 다른 해상도다. 같은 소비자·RFC4180 목적·전환 프로젝트로 보수적으로 중복 처리하되, 개별 시행 단계와 날짜가 같다는 것은 미확인으로 남긴다. 봉인 B 목록의 `prior_exposure_note:null`을 덮어쓰지 않고 이 후속 정정에서 수집자 노출을 명시한다.

## 검색과 원문 판독

세 질의를 한 번의 검색 요청에 묶었다. 반환값이 각 hit를 개별 query에 귀속하지 않으므로 쿼리별 hit 수를 만들어 내지 않았다. 검색에서 나온 [PostgreSQL commit 알림](https://www.postgresql.org/message-id/E1ruWhw-001Rrq-GW%40gemulon.postgresql.org)을 직접 열었지만, 본문은 **REL_15_STABLE**이다. 이것을 A의12branch commit이나12.19출판 날짜로 사용하지 않았다. `cases.json`의12계열 전후 바이트는 `followup/`의 실제 archive 근거를 명시적으로 재사용한다.

추가로 [2022-09-14 IETF LLC board minutes](https://www.ietf.org/media/documents/2022-09-14-llc-board-minutes.pdf)의6페이지, Tools/RPC/RSOC/RSE를 직접 읽었다. 문서는 tools 서비스 폐지와 redirect 설정 완료를 보고한다. 공지의 예정 표현보다 나은 완료 관측이지만, RFC4180 개별 URI의 실제 전환 순간이나 PDF 최초 업로드 시각은 아니다. 전체 전환 완료와 개별 URL 변경의 시계를 구별했다.

`followup/`에서 이미 확인한 마지막 옛판은12.18, 최초 새판은 해당12계열의12.19다. 옛 tools 주소의 현재 RFC 본문도 요구한 CSV 규칙을 제공한다. 주소 수정 사슬과 독자 실패 사슬을 합치지 않는다.2026-10-29에 추가된 IETF 블로그 문장은2022당시 시행 근거에 넣지 않았다.

다음 첫 자료는 `/html/rfc4180`를 명시한 날짜 있는 IETF 배포 설정/운영 영수증이다. 새 독립 소비자 탐색은 이번3질의 상한을 늘리지 않고 다음 별도 조사에서 해야 한다. 공개판 접근 가능성에서 실제 독자의 열람/실패를 추정하지 않았다.
