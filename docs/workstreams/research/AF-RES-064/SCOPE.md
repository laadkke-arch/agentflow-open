## 목적지 선택

1. A는 상위 슬롯의 게시 목적지에서 첫 문서 본문 시작이다. 저장소/디렉터리 목적지는 같은 ref에서 제공하는 README로 투영한다. 게시 주소에 자체 앵커가 있었다면 그 위치를 우선한다. 제목과 경로 구조는 GitHub 파일 순서가 아니라 공급자가 게시한 문서의 첫 페이지, 그 페이지 순서의 내부 문서 링크, 원표기의 위치를 포함하는 목차/공개 API 인덱스 순으로 읽는다. 게시 메뉴나 API 인덱스가 연결하지 않는 저장소 파일은 B의 임의 대체 후보로 쓰지 않는다.
2. B 후보는 060에서 일치한 **F1 공급자 표기**를 해당 060 표기 출현의 앵커/문서 행과 연결한다. 선택에 전달하는 값은 표제·공개 심볼·링크 라벨/경로·행 위치 및 원표기 위치다. NFKC → casefold → 양끝 공백 제거 → 문자/숫자/언더스코어/달러 이외의 구분문자는 공백으로 합친다. 심볼은 수신자/namespace가 명시된 경우 마지막 심볼 또는 문서가 공개한 별칭을 비교한다. 첫 적격은 동일 문서의 원표기 연관 위치나 거기서 명시적으로 연결된 같은 판 문서의 표제/공개 API다. 제목/심볼과 정규화 완전 일치, 원표기 자체를 링크한 주제 페이지의 첫 제목, 원표기가 속한 가장 가까운 **기능명 제목** 또는 표기 위치에 실제로 나타나는 공개 호출의 소스 행 permalink를 허용한다. 출현 범위에서 관계를 밝힐 수 없는 관련 기능 단어, README 일반 Features/Library Features/Introduction/Usage 포괄 제목, 검색 결과 본문·시험 기대·판정은 B 선정 입력에서 제외한다. 연결되지 않은 동의어, 결괏값·정답을 근거로 한 이동을 선택하지 않는다.
3. 동일 티어의 후보는 해당 공급자 게시 문서 순서 → 소스 행순이다. 같은 문자열이 제목과 목차에 반복되면 실제 제목에 한 번만 매핑한다. 다중 적격, 끊긴 링크/앵커, 번역/다른 판, 동명 오역/비구현, 도착 변화 없음을 각각 남긴다. 같은 repo의 URL도 SHA 검산과 ref 대응이 필요하다. 브랜치형 웹사이트 경로는 빌드/소스 매핑을 보일 때만 같은 ref의 소스로 해석한다. 매핑이 없으면 A 또는 판 미확인 상태를 보존한다. GitHub의 해시 제목은 중복 접미사와 실제 DOM ID를 확인한다. 섹션 ID를 입증 못 하면 GitHub의 고정 소스 행 링크를 명시적으로 구분해 쓴다.
4. P는 B 첫 위치(없으면 A 시작 이후의 첫 적격 표제 또는 B 후보가 탈락한 A 위치) 다음의 같은 레벨 표제를 먼저 쓴다. 없으면 직전 같은 레벨 표제, 그래도 없으면 다음 실제 표제를 쓴다. B와 첫 위치가 같아지는 후보는 빼며 후보 자체가 없으면 빈칸이다. 하위 대안이 필요할 때는 문서 순서의 첫 다른 실제 표제다. B가 공개 호출 permalink인 경우 같은 문서에서 호출 뒤 첫 실제 표제, 없으면 앞 첫 표제를 쓴다.
5. A/B/P의 둘째 행동은 첫 창에서 **전체 라벨이 보이는** 첫 같은 판 내부 예제/시험 링크다. title 또는 경로 요소에 정규화된 `example/examples/test/tests/spec/specs`가 있어야 하며, 파일명 구분·접두사도 같은 방식으로 분리한다. 인라인 코드의 URL·일반 설치·API 설명·GitHub Actions 상태·외부 상호운용 저장소는 제외한다. 실제 URL이 문서/코드 파일 또는 실재하는 예제/시험 표제를 가리켜야 한다. 선택한 첫 링크가 실패하면 다른 링크로 대체하지 않는다. 자체 위치로 되돌아가는 링크는 제외한다. 문서 진행 중 분기는 최대 하나다.

## 독자 창과 판정

같은 Markdown/reStructuredText 본문 렌더링 투영을 사용한다. 탐색기에는 구조 메타데이터만 출력한다. 렌더러가 읽는 raw 응답 바이트와 판정자가 받는 창을 비용상 구분한다. CSS·스크롤 높이·토큰화 모델 대신 텍스트 투영의 결정적 제한을 사용한다. 제목·보이는 앵커 라벨·문장·코드·JSON·수식은 같은 규칙의 연속 텍스트다. 링크 목적지 URL은 라벨로 표시된 경우만 텍스트로 계수하며 클릭 식별자/행 permalink는 창의 메타데이터다. Markdown 구문·이미지 픽셀·사이트 전역 nav는 렌더 텍스트에 포함하지 않는다. 화면 정규화의 차이는 재현 한계로 남긴다.

Unicode `\w+` 하나 또는 개별 비공백 문장부호 하나를 예산상의 단어 하나로 센다. 단어 정의는 특히 압축 JSON과 코드 구분자를 누락시키지 않는다. 시작점부터 문서 끝 혹은 500번째 단어까지 연속 창을 낸다. 긴 무공백 식별자는 1단어가 될 수 있으므로 바이트/줄/최대 토큰 바이트를 같이 집계한다. SHA-256은 표시 UTF-8 바이트의 것이다. [경계시험](evidence/boundary-check.json)의 499/500/501/611와 JSON·코드·수식·최대 토큰 시험을 목적지를 선택하기 전에 실행했다. 혼합식 fixture의 손계수 18을 실제 규칙 17로 바로잡고 다시 통과했다. 060의 611단어 두 경로와 preview 경계 불명 한 경로는 과거치 81/84의 일부로 유지한다.

판정자는 각 A/B의 같은 구현판에서 실제로 받은 최대 두 창에 대한 C1/C2 인용 행, 환경 상태, 반박/미확인을 판정한다. 이름 전이는 일반 속성 제약과 data type/값을 가르는 근거가 있을 때 작은 이름 치환만 허용한다. 환경, API, draft, 입력 구조, 상수 집합은 이름 전이에 포함하지 않는다. 원문 단어 그대로의 채점도 보존한다. 하나의 조건만 지지되면 부분, 같은 경로에서 두 조건과 환경이 모두 지지되면 완결, 명시 동작이나 명시 환경이 요구를 위반하면 반박 또는 환경 제한을 그 범위에서 표시한다. 도착지의 불일치와 기능 자체의 불가능성을 구분한다. 초과나 불명 경로는 엄격 분석의 분모에서 표시하되 기본 비교표에 남긴다.

작업 주체는 단일 Codex Cloud 연구자다. 검증식·구조 추출·창 표시는 자동화하고 의미 판정은 직접 독해한다. 배정문과 060 인계에서 이미 Ajv의 이름 전이 및 060 전체 판정 요약을 보았으며 일부 행이 고정 결과의 필수 열람에서 보였다. 독립 블라인드 판정이나 인간 사용성 실험이라고 부르지 않는다. 선정기의 입력에서 과거 판정·시험 내용과 새 출력은 제거한다. [실행 판정표](fixtures/expectations.md)는 문서 판정의 원격 봉인 뒤 실행한다.
