# Python 요구 동결 — 목적지·목록 미열람

작성 단계: ①. pypa/packaging-problems의 2022–2024 공개 issue를 생성 UTC, 동률 번호 오름차순으로 모집했다. 검색 결과 230건, incomplete_results=false; 첫 40건은 #563~#609이며 이전 저장소에서 옮겨온 #1020을 생성일 기준 28위에 유지한다. 직접 issue REST URL 40개를 열었다. 댓글 API, 후보 공식 목록, 공급자 목적지는 열지 않았다. 검색은 모집 경로이고 직접 응답과 내용 동일성을 확인하는 데만 사용했다.

## 모집 판단

- 두 독립 조건은 서로 별도로 성공·실패할 수 있는 기능/설정 결과다. OS·Python·pip 버전의 나열만으로 두 조건을 만들지 않는다.
- 부품 선택은 새 도구만이 아니라 빌드 백엔드·배포 설정의 선택도 포함한다. 계정·네트워크 장애, 일반 앱 실행, 단일 메타데이터 값의 허용 목록 문의만 있는 글은 제외한다.
- #563은 한 라이선스 분류 값의 허용 문제라 부품/배포 설정 조합 선택과 두 독립 기능 조건이 부족하다. 이 경계가 바뀌면 첫 자연 요구가 바뀐다는 감도를 남긴다.
- #574의 setup.py 부재는 보고된 입력 상태다. 'setup.py를 추가하면 안 된다'를 요구자의 명시적 금지로 승격하지 않는다.
- 40개 모든 본문은 최초로 접근 가능한 현재 REST 본문이다. 원게시 당시 판은 복원하지 못했다. created_at은 생성일이고 updated_at은 본문 수정일만을 뜻하지 않는다. 이후 댓글 내용은 보지 않았다. 선택 두 본문에는 별도 첨부가 없다. 두 번째 선택 앞의 #573 스크린샷은 직접 열었고 환경과 같은 설치 실패만 추가되어 탈락을 유지했다. 그 이후 탈락 글의 첨부는 열지 않아 첨부만에 숨어 있을 추가 조건은 미확인이다.

## 보강층 요구 연결에 사용할 사전 모집집합

새 요구를 목록을 본 뒤 만들지 않는다. frame.csv에서 eligible_later인 #575,#576,#577,#583,#588,#1020,#605,#609는 자연층에 넣지 않는다. 보강 절과 맞는 요구를 찾을 때는 P-N1,P-N2를 먼저, 이후 모집 순서로 검토한다. 최종 필수조건의 추가 상세화는 해당 원문을 읽어 목적지 열람 전에 별도로 동결해야 한다. 주제만 비슷한 요구는 연결하지 않는다. 공통 요구 재사용 시 issue 번호를 공통 ID로 기록한다.

SCOPE.md와의 정합: 도구 일반명 setuptools/wheel/build/twine, 템플릿의 튜토리얼 제목은 매칭 명사에서 제외했다. 본문 코드가 가진 명시 입력 파일·필드와 목적 기능만 남겼다. `editable`은 해석 설명에 쓰지만 원문 명사 목록에 새로 추가하지 않으며, 발행자가 `pip install -e`의 공식 별칭으로 명시할 때에만 별칭 단계에서 사용할 수 있다.
