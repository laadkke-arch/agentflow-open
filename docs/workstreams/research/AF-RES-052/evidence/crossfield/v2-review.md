# 단계② v2 방법론 검토

검토 대상: `ea4fa69f841dca2c470b62c3fdf1ee4d9029712e`의 root `SCOPE.md`, `CORRECTIONS.md`, `slots.csv`, `pools.csv`, `groups.csv`, 단계② 봉인 기록, 두 분야의 v2 모집·진단 파일. 별도 문맥 판독자의 문서 검토이며 후보 동작의 정답 검증이나 실행 시험은 아니다. 소프트웨어 공급자 목적지는 열지 않았다. root·도메인 파일은 수정하지 않았다.

## 판정

**본표 8자리/24행과 진단 표본의 분리가 일관된다.** C01–C04의 정정 이력은 이전 사전 규칙·잠정 배열을 보존하고, 목록을 본 뒤 목적지 정답을 보기 전에 기능 절 정의를 고쳤다는 사실을 밝힌다. 이로써 이전 `critique.md`에서 지적한 소유 범주 혼입, README 선노출 은폐, 문서역할 추정의 주요 문제를 보수적으로 처리했다.

현재 단계에서 가능한 결론은 표본·키·가시성에 관한 것이다. 사용자 요구를 충족하는 독립 구현 수나 두 번 열람의 실효성을 확인했다고 결론 낼 단계는 아니다.

## P-S1의 기회와 독립 구현을 혼동하지 않기

원풀은 순서대로 bandersnatch Docs, Issues, GitHub, PyPI, AWS S3다. 앞4개는 같은 upstream이고, 다섯 번째는 별도 저장소 제품이다.

| 방식/감도 | 보이는 원순번 | 숨은 형제/잘린 후보 | 해석 |
| --- | --- | --- | --- |
| A3 | 1,2,3 | 4,5는 슬롯 밖 | 정확 URL은 다섯이지만 앞3은 같은 upstream |
| B3 | 1,5 | 2,3,4는 r1의 형제 | r5 URL이 앞으로 옴. 그룹은 둘뿐이라 세 번째 대표를 만들지 않음 |
| C3 | 1,2,3 | 4,5는 슬롯 밖 | 제품판·문서역할 미상 때문에 각 멤버 singleton |
| A4/C4 | 1,2,3,4 | 5는 여전히 슬롯 밖 | 새 대표 r4는 bandersnatch의 PyPI 주소. 새 독립 upstream이 아님 |
| B4 | 1,5 | 기존과 동일 | 추가 자리가 있어도 새 그룹이 없음 |
| C 제품판 미상만 완화 | 1,2,3 | 역할 미상은 그대로 | 나머지 미상값까지 동시에 합쳐야 한다면 다른 실험이다 |

상류·부품·공개 용도는 알려져 있다. 따라서 'C의5필드가 모두 미상'이라는 표현은 틀리다. 정확한 표현은 **5필드를 모두 알아야 하는 키가 제품판과 문서역할의 결측 때문에 성립하지 않는다**다.

AWS S3는 원문 라벨과 도입에서 파일 제공의 기반으로 읽힌다. 그 URL의 가시성 승격이 빌드 백엔드의 대체나 package mirroring 요구의 완결을 자동으로 의미하지 않는다. 사전 적격 요구 중 mirroring 목적과 맞는 것이 없으므로, 직접완결·두 동작 완결·A대비 유용 구현 증감은 **미확인**이다. 이를 관측 실패0으로 바꾸지 않는 것이 중요하다.

## 진단 배열

- `D-P1`은 예전 PyPA Projects 부모 범위의6출현이다. build:index는 exact URL 결측으로 남아 있다. 이6번째 미확인을 주풀 P-S1의5개 URL에 섞으면 안 된다.
- `D-M1`은 Official6을 보존한다. B에서 mdast r6가 앞으로 오더라도 명세 링크의 승격이다. 정답 검토 뒤에도 실행 구현과 별도 단위로 세어야 한다.
- D-M1-r1의 remark README 선노출은 root diagnostic pool/group 두 곳에 기록됐다. 본표의 모든 목적지 비노출이라고 주장하려면 진단을 제외한 범위임을 명시해야 한다. 전체 조사 차원에서는 선노출 예외가 남는다.
- 진단6행은 본표24행에 포함되지 않는다. 진단 요구 공유 ID M-N1도 새로운 자연 요구 하나로 세지 않는다.

## 자료 수의 중복 방지

최종 `sources.jsonl` 통합과 수용 원장은 아직 이 검토에 포함되지 않았다. 개별 파일에 배당 문자열이 있다고24개가 충족되는 것은 아니다.

1. remark 라우팅 README는 나중에 후보 도착으로 다시 읽어도 같은 저작1개다. source ID가 달라지더라도 URL의 정규화·repo/path·work ID로 연결해야 한다. 같은 원문을 목록 배당과 공급자 배당에 각각 한 개씩 중복 산입하지 않는다.
2. 목록·규칙4개는, 실제 직접 기록이 있다면 PyPA key_projects, PyPA contribute, awesome-remark, remark plugin 등록/명명 규칙처럼 독립 저작을 선택할 수 있다. fragment, README의 다른 구간, 별도 browser/API 표현은 새 저작이 아니다.
3. 녹음 X01/X01M 및 X02/X02M은 HTML/XML 각각 같은 저작이다. crossfield 최소 배당은 이미 X01–X04의4개에만 주었다. 교차 분야의 Inter 발행기록은 소프트웨어 후보 시험4개의 부족분을 메우는 자료로 바꾸지 않는다.
4. 릴리스·시험은 별도 발행/행동 자료여야 하며, 시험 파일을 읽은 것과 실행 성공을 분리한다. 접근 실패나 검색 snippet도 직접 원문수에서 제외한다.

## 남는 한계와 결과 작성 기준

기능 절의 v2 정의는 소유 범주를 제거하는 목적에는 적절하다. 다만 모든 named-project 절의 목적 문구가 완전히 같은 세밀함은 아니다. 'historical packaging system'처럼 넓은 설명과 mirroring처럼 구체적인 처리의 범위를 동일하다고 일반화하지 않는다. 이 차이는 첫 선택 bandersnatch의 순위에는 영향을 주지 않지만, 첫20이라는 관찰 범위를 설명할 때 기능 분류가 연구자의 조작적 정의라는 사실을 남겨야 한다.

자연층 기회는0/4 요구의 관측값이다. 보강층은 '예정4자리 중 메타데이터 풀1개 확보,3자리 미충원'과 '그1풀의 목적 미연결'을 별도 수치로 쓰는 것이 정확하다. 목적 연결 분모0의 완결 성공률은 **해당 없음**이며0%가 아니다. 실제 사용자의 채택 수는 이 설계조사에서 측정하지 않았다.

**이 단계의 검토 종료:** 더 정답을 보지 않아도 고칠 수 있는 중대한 배열·분모 오류는 발견하지 않았다. 이후 evidence/paths/RESULT에서는 source dedup, 실제 도착과 저장소 대체 구분, 현재판·역사판, 한 시행에서 함께 읽은 조건만 합치는지를 추가 확인해야 한다.
