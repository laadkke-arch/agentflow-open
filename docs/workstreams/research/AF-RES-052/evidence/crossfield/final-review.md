## 보고한 오류와 해소

첫 초안의 acceptance AC02는 frame.csv 선택 조건을 `record_type=issue_screen`이라고 적었다. 실제 열 이름은 `record_kind`이고 해당 값의 행은80개다. 부모에게 먼저 알렸으며, 부모가 생성 스크립트와 acceptance를 재생성한 뒤 `record_kind=issue_screen`으로 바뀐 것을 다시 읽어 확인했다. 요구 선정·분모·결론은 바뀌지 않았다.

후속 문장 정정도 확인했다. RESULT L57의 D-P1 설명은 이제 **49행은 시작 URL이 알려진 경로이며, 그 안에도 정확 fragment·접근 실패·부분 창 결측이 남는다**고 명시한다. 이는 instantiated와 성공한 도착을 더 정확히 구분한 정정이다. 결과191행, 두 필수 표8/24행, 수치·결론은 그대로이며 아래 RESULT 해시는 이 정정 후 내용으로 갱신했다.

## 최종 출판 시 남겨야 할 경계

- 원5 AWS URL 승격, 원6 mdast URL 승격, C1 노출 증가, 완결 구현 증가를 같은 단위로 합치지 않는다. 이번 주표본의 완결 효용은 미확인이고 진단의 완결 차이는 관측0이다.
- 엄격 C의 실제 충돌이 없어서 C=A인 결과를 안전성 검증으로 부르지 않는다. 제품판만 완화하는 감도에서 다른 결측·부품 차이가 남았다는 설명도 유지한다.
- 최종 HANDOFF는 실제 고정 SHA 재열람과 session check를 기록한 뒤 마지막 단독 커밋으로 만들어야 한다. 이번 초안 검토에서 AC15를 satisfied로 올리지 않았다.
