## 자연층 모집과 요구

각 저장소 `pypa/packaging-problems`, `remarkjs/remark`에서 2022-01-01T00:00:00Z 이상 2025-01-01T00:00:00Z 미만 생성된 공개 issue를 모은다. PR은 제외한다. created_at UTC 오름차순, 동률 issue number 오름차순으로 첫40개를 모집한다. 이관된 이슈도 공개 기록의 생성 시각을 유지한다. 검색은 모집용이며 선정된 본문은 issue API/공식 페이지에서 직접 읽는다. 첫40개 모두 선정/탈락 이유를 기록하고 그 이후로 대체하지 않는다.

적격은 (a) 작성자가 원하는 결과가 있고, (b) 독립 판정 가능한 명시 필수조건이 둘 이상 있으며, (c) 패키징 구성요소 또는 Markdown 변환 구성요소/설정을 선택해야 그 목적을 확인할 수 있는 요청이다. 기존 구성요소의 버그/설정 질문도 대체 부품·설정 선택이 목적 달성에 실제 관련되면 포함하되 명시적인 비교구매 요청과 구별한다. 단순 버전/OS의 나열을 둘째 기능 조건으로 만들어 적격시키지 않는다. 질문 자체에 이미 구현을 정했을 때 그 구현의 대체 허용은 연구자 가정이다.

첫 적격2개씩 P-N1/P-N2/M-N1/M-N2를 고른다. 최초 본문 복원이 안 되면 `최초 가용 현재본문; 생성판 미확인`이다. updated_at은 이슈 전체 수정 시각으로 본문 수정 증거가 아니다. 후속 댓글·해결·close 상태는 선정에 쓰지 않는다. 첨부 링크는 목적 재현에 필요한 것만 읽으며 접근 실패를 기록한다. 현재 본문에서 확인한 명시 요구, 환경, 선호, 판독자 선택 규칙을 분리한다. 요구별 근접 오답과 허용 조합 기준은 목적지 전에 고정한다.

## 목록 선택과 순서

Python은 `pypa/packaging.python.org`의 공식 index/source 라우팅에서 안내하는 도구/프로젝트 선택 목록을 쓴다. Markdown은 `remarkjs/remark` README가 직접 가리키는 플러그인 목록을 쓴다. 목록 파일을 고른 이유·발행자가 선언한 적용 범위·정렬/기여 규칙을 기록한다. 저장소 metadata/index는 출발점 확인이고 공급자 목적지 관측이 아니다. 여러 공식 목록이 있으면 index/README의 원순서 첫 명시적 도구/플러그인 목록을 주목록으로 하고 나머지는 범위/작성 규칙 배당에만 둔다. 후보 수가 많거나 중복이 생긴다는 이유로 주목록을 바꾸지 않는다.

주목록의 고정 commit/blob과 원본 파일 행번호를 사용한다. 제목의 TOC 복사본은 중복 기능 절로 세지 않는다. 기능 절은 본문의 제목이 시작하는 범위이며 같은 수준 이상 제목 직전까지다. 목록이 단일 평면 목록이면 그 발행자가 붙인 하나의 기능 절로 취급하고 패키지마다 새 기능 절을 발명하지 않는다. include/선언형 데이터가 있으면 해당 고정판에서 작성자가 정한 순서만 확장한다. 원문이 없는 순서는 미확인이다.

자연 매칭은 질문자의 목적/재현/기대 결과 문구에서 미리 기록한 기능 명사만 사용한다. 입력 template/support 문구·도구 일반명으로 기능어를 추가하지 않는다. 대소문자·공백만 정규화한 같은 철자의 전체 단어/명사구를 목록 제목에 매칭한다. 후보명 안의 우연한 부분문자열은 불허한다. 완전한 제목 일치 → 제목 안의 명사구 일치 → 발행자가 명시한 별칭 순서로, 같은 수준 동률은 편집 순서다. 매치가 없으면 빈 풀이다. 상위 절로 이동하거나 전체 링크 앞6개로 fallback하지 않는다. 별칭은 목록판에 실제 적힌 경우만 인정한다.

매치 절의 첫 여섯 실제 정보 링크를 원순서로 보존한다. 링크 텍스트·원 href·resolve한 정확 URL(쿼리/fragment 유지)·원문 행·전역 순번·절 내 순번을 기록한다. 순수 TOC/제목 permalink·badge·계정/기여/공유/라이선스 UI는 후보에서 제외하고 제거 이유를 기록한다. 같은 URL 반복도 원풀 행으로 보존한다. 여섯 전에 소진되면 소진이며, 읽지 못하면 결측이다. 사이트 순위/당시 HTML로 해석하지 않는다. 목록판 시각이 요구 뒤면 현재 재탐색이다.

## 보강층 모집

주목록의 첫20 기능 절(20개 미만이면 소진까지)을 순서대로 스캔한다. 첫 슬롯 P-S1/M-S1은 정확 URL >=4이고 표시상 동일 상류 반복이 앞3자리 중 한 그룹을 합쳐 뒤의 별개 URL을 올릴 수 있는 첫 절이다. 두 번째 P-S2/M-S2는 같은 조건에서 C의 다섯 필드가 모두 알려져 실제 충돌하는 첫 절이며 첫 슬롯의 절은 재사용하지 않는다. 모든 검사 절과 탈락 코드/URL 수/B·C 기회를 남긴다. 정원 미달은 빈 자리로 남기며 기능 절 범위·버전 정의를 완화해 채우지 않는다.

목적 연결은 목록 열람 전에 적은 동일 분야 첫40 요구 프레임 중 적격 요구만 허용한다. 목록판/목적지에서 새로운 요구를 만들지 않는다. 여러 요구가 맞으면 최초 생성 적격 요구를 쓰며 요구·절 재사용은 공통ID로 적는다. 대응 목적이 없으면 메타데이터 기회만 기록하고 정답/완결 판정은 미확인이다. 보강은 자연층을 대체하지 않는다.

## 표시와 세 그룹

A는 정확 resolve URL이다. B는 발행자가 귀속한 상류 프로젝트/제품이며 동일 GitHub 조직이라는 이유만으로 다른 프로젝트를 합치지 않는다. C는 상류·명명 부품·공개 용도·제품판·문서 역할 다섯 값 모두 명시되고 같은 경우만 묶는다. 역할은 overview/capability/reference/configuration/example/migration/test/release 중 목록 라벨/URL로 직접 지지되는 값이다. 목적지에서 읽은 의미로 키를 보완하지 않는다. `latest`/`stable`과 목록 파일 SHA는 제품판이 아니다. 한 필드라도 모르면 C는 원멤버 단독이다. B 상류 미상도 단독이다.

모든 방식에서 원순서의 첫 그룹부터 세 자리, 그룹의 첫 멤버를 대표로 한다. 원문 명칭·설명(있는 그대로)과 길이·URL은 고정하고 방식만 바꾼다. 숨은 형제와 뒤로 잘린 그룹을 구별한다. 그룹 관련 링크 목록에는 원멤버를 원순서대로 둔다. 목적지를 열기 전 pools/groups에서 이 배열을 복원할 수 있어야 한다.

## 도착 범위와 두 동작

목록은 이미 보이며 증거 조건을 충족한 것으로 세지 않는다. URL을 한 번 열면 1동작이다. 보이는 다른 대표도 각각1동작이다. 형제 목록 열기→멤버 열기는2동작이다. 대표→도착 범위 안의 첫 두 실제 정보 href 중 하나는2동작이다. 원순서/첫대표/다른대표의 모든 순서쌍 및 모든 보이는 그룹 형제를 포함한 경로를 기록한다. 연구자가 도착의 셋째 이후 링크를 찾아 읽었어도 2동작 적격에 소급하지 않는다.

판독 창은 fragment가 있으면 실제 도착 절에서 다음 동급 이상 제목 직전(최대800 whitespace 단어), fragment가 없으면 본문 첫 제목 뒤800단어다. 원자료가 더 짧으면 끝까지다. 없어진 fragment/접근 실패는 정확 도착 실패다. GitHub Markdown/reST는 원본 제목/링크 순서로 읽으며 브라우저 렌더 또는 실행을 했다고 주장하지 않는다. 원 URL이 외부 HTML이면 해당 원주소를 먼저 열고, 저장소 소스 대체는 별도 획득이며 사용자에게 같은 도착이라고 세지 않는다. 첫 두 href는 본문 정보 링크만, badge/전역탐색/자기정확URL/계정/편집·기여·저작권 UI는 제외한다. 의미 정답을 보고 적격 링크를 고르지 않는다.

정답 근거는 각 구현/허용조합의 같은 판·방향에서 모든 필수조건을 확인해야 한다. 공식 문서 D1, 코드/시험 읽기 D2, 실제 실행 D3를 구분한다. 시험 파일을 읽은 것은 실행이 아니다. 원풀 전체에서 확인한 구현 ID, 대표 한 번의 직접 완결 ID, 개별 <=2동작 시행의 완결ID 합집합, 한 시행 최대, 원풀 밖 우연 도착을 각각 센다. 서로 다른 시행의 부분조건을 합쳐 완결을 만들지 않는다. 제품판이 결측이면 명시한 역사 버전 지원은 미확인으로 남긴다.

## 반례·감도·자료 수

반례는 (1)4~6위 독립 구현 승격 (2)대표 하나가 이미 두 구현 설명 (3)판 미상으로 C=A (4)보완 예제 숨김 (5)뒤쪽 병합으로 첫3동일 (6)URL4개라도 독립 구현은 적거나 목적 불일치이다. 없었던 양성은 만들지 않고 조사 범위/뒤집을 최소 조건을 남긴다. 고정3자리와 추가4자리, C의 판미상을 동일 sentinel로 취급하는 완화 감도를 원분석 뒤 별도로 계산한다. 그 외 C 필드는 그대로 유지한다.

자료는 sources.jsonl에서 저작 ID로 중복 제거한다. 목표 배당은 요구4, 독립 공식목록/판/작성규칙4, 공급자문서8, 별도릴리스/행동시험4, 녹음·서체의 개별발행/식별4이다. 동일 저작의 fragment/미러/탭/여러판은 최소수에 중복 산입하지 않는다. 최소24 충족과 실제 표본 완결은 다른 조건이다. 빈 풀 때문에 후보 관측이 없으면 그 결손을 남기고, 공식 목록의 첫8 고유 공급자 정보문서를 맥락·반례 확인용으로 따로 읽을 수 있으나 그것을 자연/보강 적중으로 넣지 않는다. 릴리스/시험은 이 맥락 후보의 발행판에서 읽고 배당 분모를 명시한다.

원문 전체는 Git에 재배포하지 않는다. 공개 URL·직접확인UTC·SHA/본문해시·절/행·자체요약·한계·지지/반증/미확인·계보를 보존한다. 로컬 캐시는 재독용이며 제출 근거의 대용이 아니다. 검색 결과는 탐색 경로로만, 실패는 직접 원문수에서 제외한다. 녹음과 서체의 비교는 소프트웨어 적중에 합산하지 않는다. 무관한 추가 실험·설치·유료API·연락·배포는 필요하지 않다.

결측은 **미확인**, 직접 관측한 빈 집합은 **관측 0**, 조건부 분모0의 비율은 **해당 없음**이다. 사람의 실제 이해·채택은 측정하지 않는다. 최종 상태는 수용 원장이 정하며 파일 존재/검사 성공만으로 의미적 완료를 주장하지 않는다.
