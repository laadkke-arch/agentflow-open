# B 목적표집: 발견 진술과 선택 결과 재대조

## 범위와 실제 분모

고유 선택은 **B01–B09의 9건**이다. GitHub 토론·PR 경로 8건과 당사자 회고 경로 1건이며 프로젝트당 1건이다. A의 Backstage/Kibana·Flink·Rust RFC 선택과 같은 사건은 없고, AF-RES-017의 40행·7기원 경로와도 중복되지 않는다. B는 발견 진술을 찾는 목적표집이므로 발생률의 분모로 쓰지 않는다. 아래 숫자는 선택된 기록의 구성이다.

- 원 의도·당시 대안·인지·후속 시행이 연결된 주 연결 집계는 2건: B05, B08. B05는 **알려진 대안 재평가**이며, 이 연결 자체를 정보 발견의 인과효과로 보지 않는다.
- 직접 미인지와 그 때문에 고치겠다는 진술, 후속 코드가 함께 있는 엄격 변경 1건: **B08의 JSON 출력 경계 부분 채택**.
- B09의 공개 gist는 Git 이력으로 날짜까지 고정했다(`dated_example_chain=true`). 그러나 자리표시자와 수정 때 추가된 오타가 있는 **교육용 예제**이므로 실제 시행 연결은 `connected_chain=false`다. 주 연결 수에 더하지 않는다.
- 자체 구현/예제 유지 3건 B01·B02·B09를 확보했지만, 각각 후발 기능·요구 불일치·교육용 예제라는 서로 다른 조건이다. 이를 “그때 쓸 수 있던 대안을 늦게 알고도 생산 자체 구현을 유지한 엄격 사례 3건”으로 표시하지 않는다.
- 결과 구성은 유지 3, 기본/제안 백엔드 대체 2, 부분 채택 1, 시험 후 철회 1, 변경 미확인 2다. 6개 엄격 사례라는 보강 목표에는 못 미친다.
- 원장에는 직접 판독·탐색·차단을 합쳐 58자료가 있으며 고유 원문 최소수 산입은 40건이다: 당시 결정/제안 11, 별도 후속 11, 공식 판/조건 17, 기타 고정 코드 1. 이는 40개의 독립 사건이라는 뜻이 아니다. 같은 선택의 PR·댓글·릴리스는 `lineage`로 묶었다. 부모 작업의 전체 원문 집계와 합칠 때 URL·판·계보를 다시 대조한다.

표집 후보 원장은 257개의 고유 검색 결과 주소를 보존한다. 그중 9선택을 채택했고, 별도 2사건 원문(mbmd·DeSmuME)은 읽은 뒤 제외했다. Stripe 회고 1건은 원문 접근에 실패했다. 기존017 Pendo 1건은 중복 배제했다. 나머지는 제목/요약 단계 후보이며 **244건을 원문 판독 후 부적격이라고 주장하지 않는다**. A처럼 연속 적격 모집을 했다는 뜻도 아니다. `sampling.csv`의 B 순번은 질의 묶음 후보 원장의 순번이다. 질의 간 독립 순위나 최초 비공개 필요의 시간 순서가 아니다.

## Q2–Q4: 날짜·가용성·인지의 대상이 바꾸는 판정

“처음 코딩한 시각”과 “처음 공개된 산출물”은 같지 않다. B01의 2018-03-22·05-14는 Git 작성 시각이고, B07의 4월25일 시작 커밋은 공개 PR의 4월29일보다 앞선다. 이 실행은 그 커밋들이 작성 즉시 공개됐다고 확인하지 않았다. B08은 코드 표제3월2일과 게시3월3일을 분리했다. B09는 2021년 원 토론이 시작된 날짜를 2023년 다른 참여자의 선택일로 쓰지 않았다. 각 필드의 `precision`에 이 차이를 남겼다.

B09의 웹 revision 주소는 열리지 않았지만, 공개 Git 전송으로 3개 개정을 직접 읽었다([gist Git 원장](https://gist.github.com/5847e7fb93f51a140ff358d45bb1e761.git); B-058, `b09-git-audit.json`). 초기 `cfe44f4`는 2023-02-05T03:53:29Z에 후크와 연결 URL 자리표시자를 담는다. `9f824c5`는 2월9일03:07:14Z에 세션 생성 한 행을 바꾸며 `enginer` 오타를 넣었다. `6a24929`는03:11:41Z에 공식 격리 설정 링크 주석만 4행 추가했다. 이 때문에 “후기에 그렇게 말했으나 실제 예제는 바꾸지 않았는가”라는 의문은 좁혀졌지만, 성공한 운영 실행을 확인한 것은 아니다. Git 작성 시각을 서버 최초 게시 시각으로 단정하지도 않는다.

GitHub의 현재 이슈·PR 본문과 생성 시각만으로 최초 초안의 모든 문구를 복원했다고 보지 않았다. 가능한 곳은 날짜가 찍힌 댓글과 고정 코드·patch를 대조했고, 초기 본문 수정 이력이나 비공개 구상이 없는 곳은 그 한계를 유지했다. B09는 개정 diff를 확보한 예이며 B08은 작성자가 따로 게시한 날짜별 두 코드 판을 대조한 예다.


B02는 첫 결론을 실제로 반박한 사례다. [5월12일 답글](https://github.com/jsocol/pystatsd/issues/127#issuecomment-491563765)만 보면 이미 있던 도구로 작업을 줄인 듯하다. 그러나 [5월22일 후속 PR 본문](https://github.com/jsocol/pystatsd/pull/128)은 외부 도구가 필요한 datagram 구성에 맞지 않음을 설명한다. [발견 전 코드](https://github.com/jsocol/pystatsd/blob/1c90b9fdf322680e2625da659abc2aa5d79b5bff/statsd/client/stream.py)의 `UnixSocketStatsClient.connect`가 SOCK_STREAM임을 제공자 자료로 확인했다. 이 경우 먼저 소개할 링크에는 “Unix socket 지원”이라는 이름만 아니라 전송 형식이 필요했다.

B01과 B06의 제공자 자료도 반례다. [OBD9141 #12](https://github.com/iwanders/OBD9141/pull/12)와 [Go Cloud의 Azure 추가](https://github.com/google/go-cloud/commit/38a09e97496915ea40567701513208c505685202)는 원 구현 시작 뒤 필요한 기능이 나왔다. 현재 검색에서 보이는 라이브러리를 원 선택일로 이동시킬 수 없다. 두 원 프로젝트의 최초 공개일, 필요한 기능 추가일, 안정판 배포일, 해당 팀에서 승인한 날짜를 모두 한 값으로 합치지 않았다. 안정판·팀 승인일이 없는 곳은 그대로 남겼다.

B05의 댓글에는 명시적인 미인지 표현이 있지만 대상이 잘못 제기된 **라이선스 위험**이다. [최초 제안](https://github.com/MultiQC/MultiQC/issues/1789)은 이미 Plotly를 선두 대안으로 명명한다. [곧 이어진 정정](https://github.com/MultiQC/MultiQC/issues/1789#issuecomment-1296609726)과 [과거 MIT 파일](https://github.com/plotly/plotly.py/blob/v4.0.0/LICENSE.txt)을 함께 보지 않으면 대안 미인지를 과대계수하게 된다. B06도 새 기여자의 이전 PR 미인지와 외부 go-cloud 인지를 분리했다. B04에서는 요청자의 인지 진술을 결정자에게 옮기지 않았다.

## Q5: 유지·채택·철회는 서로 다른 제약을 드러낸다

B08과 B09는 같은 Python 환경의 작은 선택이지만 결과가 다르다. B08의 목표는 Path 자료구조를 유지하면서 JSON으로 출력하는 것이고, 기존 인코더 확장은 그 경계를 바꿀 수 있었다. 후속 코드의 `cls=PathEncoder` 호출이 계획을 뒷받침한다. B09는 내장 격리 설정을 알게 됐어도 직접 연결 후크를 보여 주는 **예제의 교육 목적**이 남았다. 따라서 예제 보존을 비합리적인 중복이나 조기 링크 실패라고 단정할 수 없다. 두 사례 모두 같은 작성자의 설명과 산출물을 연결했으며 독립 연구자가 운영 현장에서 재현한 것은 아니다.

B01·B02·B09의 유지 3건은 강도가 같다거나 제품의 대상 팀을 대표하지 않는다. B01은 원 시점 가용성이 끊겼고, B02는 필요한 기능 호환성이 끊겼으며, B09는 고정 revision 날짜를 회복했지만 생산 운영으로의 연결이 끊겼다. 이 차이 자체가 “발견했으면 재구현 비용이 줄었을 것”이라는 일반화를 제한한다.

B07은 실제 도입과 실제 철회 patch를 각각 열었다. [도입 커밋](https://github.com/transloadit/uppy/commit/e4253e063ffb8d3df7d6c532018d4664f883f640)이 의존성과 DOM 속성을 넣고, [철회 커밋](https://github.com/transloadit/uppy/commit/bbbc77ba3b6f039b668eeed48798e3dbb5947f55)이 의존성을 제거하고 자체 trapFocus를 복원한다. [제공자2.1.0 README](https://github.com/WICG/inert/blob/v2.1.0/README.md)의 추가 폴리필·트리 탐색 경고는 팀의 사유와 연결된다. 이것은 더 일찍 알았더라도 버전·브라우저 조건이 선택을 막았을 가능성을 보여 주며, 실제 조기 소개 효과를 측정한 실험은 아니다.

B05는 새 백엔드를 채택한 뒤에도 [v1.20](https://github.com/MultiQC/MultiQC/releases/tag/v1.20)에서 예전 출력 코드를 임시 템플릿으로 남겼다. [v1.21](https://github.com/MultiQC/MultiQC/releases/tag/v1.21)의 버전 고정·Kaleido 우회는 도입 뒤 통합 부담이 있음을 보여 준다. 버린 코드, 보존된 코드, 새 통합 작업을 전부 한 “재작성 낭비”로 합산할 수 없다.

## Q6: 비용 원장의 해석

`costs.csv`에는 12행을 두었고 9개 사건 모두 수량 또는 미확인 행을 갖는다. 합계는 계산하지 않는다.

## Q7: 다른 분야 구조로 과대해석하지 않은 부분

이 B 표본은 외부 구현·표준 라이브러리 확장·같은 생태계 도구의 재사용 비교다. Python 코드가 문서의 확장 지점을 사용하거나 Uppy가 DOM의 상호작용 차단을 적용한 것을 다른 분야의 지식 전이로 세지 않는다. B07에는 “배경 DOM을 비활성화→포커스 대상을 제한”하는 실제 코드 관계가 보이지만 웹 접근성이라는 같은 분야다. B08 후속 코드 L12–15는 설치돼 있으면 simplejson을 json 별칭으로 가져온다. [simplejson3.17.0의 cls/JSONEncoder 문서](https://github.com/simplejson/simplejson/blob/v3.17.0/simplejson/__init__.py)와 [2019-11-17 배포 기록](https://github.com/simplejson/simplejson/blob/v3.17.0/CHANGES.txt)도 확인했다(B-056~057). 실제 실행 경로는 미확인이며, 양성은 **기존 JSONEncoder 호환 확장점의 부분 재사용**이다. 공식 simplejson 문서는 가능한 경우 default/for_json을 더 권장하므로 관찰한 선택이 최적이었다는 주장도 하지 않는다.

## 반례 탐색 경로와 미발견

`search-log.json`의 BS04–BS09는 세 결과 방향마다 세 문구를 GitHub 토론과 회고 두 계열에 적용한 **18개 실제 질의**다. 예를 들면 후기 유지에는 “did not know/keep/implementation”, “was not aware/still/library”, “discovered/homegrown/kept”; 소개 후 무변경에는 “thanks for pointing/not use/library”, “was not aware/won’t/dependency”, “did not know/closing/library”; 철회에는 “revert/library/performance”, “replaced/back to/dependency”, “switched/rolled back/library”를 사용했다. 정확한 사이트 필터·나머지 질의는 원장에 보존했다.

이 격자에서 모든 방향×계열에 적격 사건을 찾은 것은 아니다. 회고 검색은 일반 롤백 가이드·가상 팀 예시·원 선택일이 검증되지 않은 글을 함께 반환했다. GitHub 검색도 “몰랐다”의 대상이 문법/기능 차이인 후보가 많았다. 반례 B07은 긍정 표현을 겨냥한 BS12 결과의 실제 후속을 읽다가 확인했고, B09는 BS06에서 찾았다. B01·B02는 처음 후보를 고를 때의 긍정적 결말을 후속/과거판 대조로 제한한 사례다.

직접 읽은 mbmd의 wmbusmeters 언급은 ORNO 선택과의 기능 적합성이 연결되지 않아 제외했다(B-033). DeSmuME의 표현은 ES3 함수 조건을 몰랐다는 말이어서 제외했다(B-034). Stripe 글은 원문 접근 실패로 보류했다(B-035). 일반 검색에서 기존017 Pendo가 재등장했으나 새 표본에 재산입하지 않았다.

## 남은 최소 입력과 인계 판단

전체 B 묶음은 파일 원장·상반 기록·시점/비용 분리를 검토할 수 있는 상태다. 엄격6사례 및 생산 자체 구현의 엄격 후기 유지3사례라는 보강 목표는 충족했다고 주장하지 않는다. 다음 최소 입력은 각 `minimum_next_record`에 적었다. 우선순위는 B03의 실제 config commit, B09의 실제 운영 구성/성공한 실행 기록, B01의 발견 직후 코드 비교다. 추가 검색이 같은 수의 감사 답글만 늘리는 경우에는 사례 수보다 끊긴 연결을 먼저 보완해야 한다.

이 폴더의 파일은 부모 에이전트가 묶음 커밋하고 고정 SHA에서 다시 읽는다. 하위 에이전트는 branch/commit/push를 변경하지 않았다.
