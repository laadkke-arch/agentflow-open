# AF-RES-100 — 모집·비교 사전 범위

## 질문과 판정의 대상

부분 설계/목적에 대해 돌려줄 주 도구 링크 네 자리(A)와 주 도구 두 자리+직접 인접 도구 두 자리(B)를 비교한다. 같은 후보 파일을 통째로 접근할 수 있는 F와 최초 질의 일치 주변 최대 1,200자만 받는 S로 복제한다. 대상은 **제시된 공개 자료에 원 요구를 지지할 충분한 근거가 있는지**다. 문서상의 구성 가능성, 다른 사람이 실제 실행했다는 보고, 원 질문자의 전체 환경 성공은 분리한다.

시작 통합판은 `01177554d0fbd33a914ea9c982c348d442d1358d`, 계획판은 `fcde6becc49120c5be91adf43fb5b4aa42e71d48`다. 두 통합판의 차이는 중앙 dot-control.json뿐이며 수정하지 않는다. 연구 입력은 096 결과 `1d399f630930d2763459e16509c5224b0cded9a0`, 인계/운영 의존은 `fce8d0ded93fe1f13f2c4978ed273c1ceef32934`다. 실제 start 명령은 exit0이며 manifest.json과 evidence/start-receipt.json에 남는다.

## 모집·원 요구

현재 Stack Overflow jq/pandoc 태그에서 2025-07-01~12-31 UTC 생성 오름차순, 동률 숫자 ID순으로 태그당 최대60개를 확인한다. 기존68 ID는 제외한다. 각 태그의 실제 입력/관측 또는 원하는 출력과 직접 인접 자원이 있는 첫3개, 주 도구 안에서 끝나는 첫 대조1개를 택한다. 해결하기 쉬운 질문으로 바꾸지 않는다. H2 목록은 jq24·Pandoc15, 선정 순번은 jq1/2/4/6·Pandoc1/2/3/4로 모두 채워져 Q1 보충은 하지 않았다. jq는 최초본문7개까지 읽고 그 이후17개는 metadata-only, Pandoc은15개 최초본문을 읽었다. 모집 목록39행과 직접 본문22건을 구분한다.

최초 revision은 공식 Stack Exchange API의 revision1 body이며 생성시각과 일치함을 확인했다. 일반 질문페이지/답/댓글/점수/채택은 사전판정이 원격 봉인될 때까지 열지 않는다. view-source 주소는403이고 web.open은 DisabledError였지만 API의 정확 GUID body 열람은 성공했다. 실패 응답은 자료수에 넣지 않는다.

jq 첫 목록 수집 때24개 current title이 노출된 이탈을 보존한다. 선정4 중3개는 R0 제목과 같고 J4만 앞의 jq가 빠졌다. 답의 내용은 보이지 않았으나 완전한 맹검 모집이라고 하지 않는다. 패킷 독자는 current title/다른 경로/답을 받지 않는다. Pandoc P1은 현재태그에만 Pandoc이 있고 최초본문·태그에는 없다. 다른 사건 재게시 및 동일 원 입력 여부는 원문 링크/자술만 추적하며 독립 사용자·실제 사건8건을 주장하지 않는다.

원 요구, 사용자판, 결손, 조건별 원 revision의 문자·바이트 위치, 주 해석·엄격 민감도·이를 가를 관측은 protocol.json의 cases에 고정한다. J1은 디버깅 다음 단계, J2는 결손을 TRUE로 발명하지 않는 변환, J3는 Bash 변수 전달, J4는 원 요구/샘플의 VolName을 주 기준으로 삼는다. P1의 helper 허용 여부, P2의 실제 import 보존, P3의 기존 script/template/컨테이너 연결, P4의 YAML 콜론 보존을 별도로 규정한다. 제공되지 않은 원값·파일을 연구자 예시로 채우지 않는다.

## 판·질의·파일 순위

주 도구는096과 동일한 jq1.7.1/Pandoc3.6 및 정확한 공식 파일범위다. 사용자 실제판은 별도다. 새 인접은 본문에서 직접 입출력 경계에 붙는 첫 명명 도구/자원으로 정한다. jq: sed, Windows Terminal, AWS CLI. Pandoc: knitr, CeTZ, 공식 Pandoc Docker image. P3에서 우선 제안한 Eisvogel은 결과/해결문서 열람 전에 원문 실행경계 대조로 정정했고 이전 제안을 보존했다.

각 두 질의는 최초본문 어휘로만 만든다. NFKC→casefold 후 `[a-z0-9_]+`의 distinct token 교집합으로 점수화한다. 두 질의 점수를 합산하지 않고 토큰 합집합으로 재점수화한다. 점수 내림차순, repo/path 대소문자 구분 오름차순이다. 파일명 보너스·동의어·길이보정은 없다. 점수0은 전체순위에 남되 노출하지 않는다. 경계 B는 main 상위2+adjacent 상위2이며 대조 B=A다. 빈자리를 다른 파일로 메우지 않는다.

공식 원 archive는 corpus-plan.json의 범위만 캐시에 확보하고 파일바이트/hash 목록을 만든다. 코퍼스 구축 비용은 경로의 네 접근과 별도로 기록한다. 구축/인덱싱은 문서 독해로 세지 않는다. 외부 원문 전체는 커밋하지 않으며 재열람주소·지문·짧은 근거·원 위치로 재현한다.

## P3 안정판 결손의 처리

공식 pandoc/dockerfiles는 GitHub release/tag가 없다. DockerHub의 안정 이미지3.7.0.0-ubuntu는 OCI revision label로7f10864aea88fc746c727f12a61a24cdc0eb93d5와 연결했지만, 질문 전에3.7.0.2용 source를 준비한 commit도 존재한다. 현재 tag last_updated는 최초출시시각이 아니므로 당시 최신 안정판은 확정하지 못했다. 구판을 최신판으로 부르거나 rolling main을 대신 쓰지 않는다. **P3-B의 인접 두 자리는 F/S 모두 공석으로 과금하고, P3의 두 A/B쌍은 엄격 승패 분모에서 제외한다.** 남은 주 도구 두 파일의 조건 지지는 기록한다. 확인한 구판 image-source는 사후 보조 설명에만 사용할 수 있다. 8요청/32패킷/16비교 자리는 유지하며 예상 엄격 분모는14, 판 결손은2다.

## 두 읽기 단위와 독립 문맥

F는 등록된 네 파일 내부에서 절 이동이 가능하다. S는 같은 네 파일의 최초 raw token 일치200자 전부터 연속 최대1200 Unicode codepoint이며 끝에서 멈춘다. raw 일치가 복원되지 않으면0부터, 빈파일은 공석이다. 전체 source SHA256, 계산한 Git blob SHA, UTF8 byte 구간과 codepoint 구간, 노출구간 hash를 보존한다. S는 추가 이동/검색/재독을 허용하지 않는다. 빈자리와 실패도 접근1로 과금한다. F 파일내 검색/이동은 별도로 기록하고 새 외부접근으로 세지 않는다.

각 packet은 opaque ID를 가진다. 네 새 에이전트 문맥에 Latin square로 배정하여 같은 질문의 네 조건이 서로 보이지 않게 한다. 독자는 question별 한 packet만 읽고, 각 조건을8질문 전체에서 두 번씩 받는다. 슬롯별4자리 모두 시도한다. 독자는 source URL·정확 표시 구간 외 지식을 근거로 쓰지 않는다. 동일 문맥의 다른 질문에서 같은 파일을 본 적은 기록한다. 이는 서로 다른 사람의 시험이 아니고 공유 파일시스템의 OS 격리도 아니다. helper interface와 운영지시로 접근을 제한한다.

F에서 접근 가능한 총량과 실제 표시한 양을 구분한다. read helper의 기본은F첫1200자이며 필요한 절로 이동한다. S는 등록구간 전체를 한 번만 표시한다. 실제 표시 문자수(반복 포함), 중복을 합친 고유문자수, 절 이동수, 인용구간은 원장으로 계산한다. 도구출력 잘림이 생기면 그 구간을 실제 독해로 주장하지 않는다. F/S의 사람 시간·독해 노력 동등성을 가정하지 않는다.

## 채점·봉인·공개 후속

조건마다 supported/refuted/partial/unknown을 기록하고 모든 필수조건을 패킷 안 근거가 지지할 때만 complete다. 초기 독자 판단과 별도 원문 구간 대조의 근거가용성 판단을 함께 보존한다. 수정은 이전값·시각·근거를 남기고 답 공개 전에 원격 커밋한다. 다른 경로에서 얻은 생각은 해당 패킷에 실제 지지가 없으면 완결로 옮기지 않는다. 판·접근·외부근거 위반은 영향 행을 격리하고 엄격 비교가능 분모를 따로 보고한다.

① 모집/요구/판/질의/순위/두 예산 → ②32패킷/사전 판단/인용 위치와변경 이력 → ③공개 답/수정/현재채택/30일내질문자행동·대체설명/밀려난 원문/다른 분야 → ④원장 재계산/필수3표/자가검산 순으로 커밋하고 즉시 작업브랜치에서 읽히도록 한다. 공개 후속의 실제 동일판·동일입력·동일출력·실행자 역할을 구별한다. 채택·감사 댓글을 실행 성공으로 승격하지 않는다.

## 반례·정지·완료

B만/A만/양쪽/둘다미완결/비교불가를 F/S와 경계6·대조2로 나눈다. 단독완결0의 분모0 승률은 산출불가다. 같은 승패라도 상류 시험·실패경고가 빠지는 경우, 주 도구가 외부 의존까지 설명하는 경우를 찾는다. 다른 분야는096의예제와 다른 GDAL warp vertical shift 및Sphinx inheritance diagram 고정문서/원시험을 사용하고 새 검색 적중에 넣지 않는다.

표본공석·자료부재·안정판 미확정은 성공/패배로 바꾸지 않는다. 가능한 가용성·밀려난 구간·반례는 끝낸다. 결과판에서 자체 재계산·task check --fetch·공통 cloud_check를 실제 수행하고 대상SHA·exit·범위·skip을 기록한다. GitHub 결과판의필수표/원장/재현절차를 재열람한 뒤HANDOFF만 마지막단독커밋으로 작성한다. 원천결과·중앙진행표·다른작업경로는변경하지 않는다.

## 원장 보관·복원

반복된 전체 코퍼스/순위 metadata는 `.jsonl.gz`로 무손실 압축하고 논리 JSONL SHA256을 evidence/compressed-ledgers.json에 기록한다. `python -B docs/workstreams/research/AF-RES-100/hydrate_ledgers.py`로 정확 바이트를 복원한 뒤 재계산한다. packets.jsonl·judgments.jsonl·sources.jsonl은 사람이 직접 읽을 수 있는 원장으로 둔다. 외부 본문은 캐시에만 있고 Git에 싣지 않는다.
