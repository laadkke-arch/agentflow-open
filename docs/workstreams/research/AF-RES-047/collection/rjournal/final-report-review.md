## 숫자 외에 직접 읽은 위험 주장

### RJ03 — 후보 대조를 진본 사용판으로 올리지 않음

RESULT15,34–36,104–105행을 대조했다. R4.2.0/4.2.1의 Iris 멤버가 같은 바이트이고 Df2가 같아도 U/R/V는 미확인이다. UCI 두 변형은 날짜가 확정된 다음판 관계라고 부르지 않는다. 보조 SumSq 차이는 primary Df를 교체하거나 하나의 실제 R판을 확정하는 데 쓰지 않았다.

125행은 미래 R release와 CPM 시간 역전을 실제 “그 파일을 읽지 않은 실행”의 배타적 음성 영수증으로 승격하지 않는다. 고정URL·동일bytes·실제미사용이라는 강한 조건은 미확보로 남긴다.

### RUN01 — 서로 다른 preprocess와 원 test를 합치지 않음

RESULT19,46–48,94,107행을 읽었다. v1/v1.1의 prediction·test log가 동일하다는 사실과 preprocess ID/날짜가 달라졌다는 사실을 함께 기록한다. 후대 preprocess가 원 test보다 늦으므로 같은 실행의 연속 단계로 합치지 않는다.

로그의 table hash를 전체 HDF5 파일의 byte hash라고 하지 않았다. 확인된 local 입력 연결만 R_local로 세며, external U/R과 진본 필드 V는 미확인이다. 소비 archive의 두 판을 CAMELYON 발행자의 다음판 쌍으로 바꾸지도 않았다.

### RUN02 — 사용 선언·prefix 일치·전 파일 동일성을 분리함

RESULT20,49–51,94,108행을 읽었다. 완전한 source URL과 local input hash/size는 구체적 U 선언을 지지한다. 그러나 publisher와 local gzip의 크기·압축표현이 다르고, 확인한 decoded 범위는 첫20개 record다. 이를 전체 decoded 동등성이나 독립 CHROM 결과 검증으로 올리지 않는다.

다른 GitHub export UUID와 Zenodo archive UUID를 합치지 않는다. 원 FASTQ에 VCF CHROM 필드가 없고 첫 gVCF 블록 DP0가 판별력을 주지 않는 한계도 유지한다. Output hash 일치는 같은 저자 기록의 내부 일관성이라고 설명한다.

### 보조 확인 — RJ02와 N-E02

RJ02의16/16은 현재 publisher filename 객체 도달이며 원 소비 tar bytes·run 영수증은 아니다.0/386은 명시적으로 저자 기록 재독이다. U는1998 선택16개 filename/version으로 한정하고 V0을 유지한다.

N-E02는 RUC 원문을 보존본으로 복원했지만 캡처 날짜·FSL1.3 schema·실제1994–2016 훈련 export를 구별한다. 자체 출력 DOI235를 외부 입력판으로 넣지 않았다. 발행자 원문 배당을 채운 사실이 P/U/R/V 성공으로 바뀌지 않는다.

## 남아 있으나 숨기지 않은 미충족

엄격 진본 사용판·원 실행·고정 필드의 독립 양성은0이다. 완전 사전 고정된 최초6+2의 확정, 정확 primary값/행키 두 사례, 실제 미사용 음성례, 순수 metadata 변경의 전후 payload 불변, 전체8사례의 실제 사용판→다음판 값 쌍에는 여전히 빈자리가 있다. 보고서 첫부분과 마지막3행이 이를 숨기지 않는다.

따라서 이번 static 검토에서 새로 수정해야 할 실질 보고 오류는 발견하지 않았다. 최종 HANDOFF와 결과 commit SHA로 다시 여는 절차는 이 검토 뒤 root가 수행할 작업이다.
