## Q1. 배정과 개입

**Newton.** 논문 Table3의 참가자 12명과 저자 패키지의 12개 `exp...` 폴더가 대응한다. 각 폴더명에는 조건·자료집·순서가 들어 있고 두 조건의 notebook이 있다. 대조는 자유로운 온라인 자료 탐색, Newton은 API 문서 링크·문서 패널·코드 생성·자동완성·체크리스트·사람이 응답하는 Wizard-of-Oz 도움을 묶었다. 같은 후보에 설명만 추가한 효과가 아니다. 48명은 모집 설문 응답 분모이고 실제 배정 분모는 12명이다. 연구 개발 중의 sandbox 10개는 배정 참가자로 더하지 않았다. (`SW-N-P`, `SW-N-D`)

**DesignPatternDoc.** 두 군 모두 Java 코드와 GoF 참조 카드를 받지만 플러그인에는 패턴 자동 인식·제안·hover·실시간 편집이 있고 대조는 PDF와 draw.io를 이용한다. 문서 표현뿐 아니라 발견·편집·도표 생성 작업량도 다르다. T22와 T32가 코드 수정·요구사항 확장을 요구함을 과제지에서 확인해 S02의 설계·구현 범위 불확실성은 해소했다. (`SW-D-P`, `SW-D-T`)

**Casdoc.** 논문은 전원이 같은 조건이라고 명시한다. 코드 예제 아래에 펼친 문단과 코드에 붙은 대화형 주석을 동시에 제공했다. 대부분의 설명 내용은 같지만 자동 생성 API 참조 주석은 펼친 문단에 없다는 예외도 있다. 연구자가 두 조건에 배정한 비교로 읽으면 안 된다. (`SW-C-P`)

## Q2. 시계와 품질의 원 정의

Newton의 과제 시계는 도구 훈련 뒤 시작하는 25분 작업 상자다. 별도 전체 세션 상한은 70분이고, 공개 스크립트는 못 끝내도 괜찮으며 참가자의 성과를 평가하는 목적이 아니라고 안내한다. 저자의 결과 표에는 완료/실패가 있지만, 최종 성공을 판정한 체크리스트·자동 검사·독립 채점 기록은 찾지 못했다. Wizard 스크립트는 모델 학습, 테스트 데이터 예측, 선택적인 precision/recall/F1 출력 경로를 제시한다. 특정 점수를 합격으로 규정하지 않는다. 이것만으로 새 정확도 문턱을 만들 수 없다. (`SW-N-P`, `SW-N-T`, `SW-N-W`)

Newton의 `goal` 또는 그래프의 `Success`는 마지막 검사 결과가 아니다. 분석 코드에서 이것은 예측 코드를 사용자에게 제시하는 Newton reply의 유형이다. 그래프의 `Submission`도 채팅 폼에 값을 넣은 사건이다. 두 레이블을 과제 최종 제출·검사 통과로 재사용하면 종점이 바뀐다. (`SW-N-A`)

DesignPatternDoc은 관찰자가 스톱워치로 하위 과제를 재고, 참가자가 답을 제출할 때 코드와 문서가 맞는지 확인하는 절차를 기술한다. 그러나 절차의 `Tasks (45 min)`와 과제지의 약 40–50분은 강제 종료 지침으로 확인되지 않았다. 실제 대조군 시간 합 중 4/10행이 2,700초를 넘고 최댓값은 3,290초다. 이는 일정상 시간 예산을 개인의 기한 내 통과 수로 바꾸지 말아야 하는 직접 반례다. 검사 절차가 있다는 사실도 보존된 q=21 집계와 같지 않다. (`SW-D-P`, `SW-D-D`)

Casdoc은 40분 뒤의 선택 연장과 조사자의 도움을 포함한다. 논문은 여덟 과제 전부를 완료할 것으로 기대하지 않았다고 명시한다. 따라서 여덟 과제 전체를 새 합격선으로 정하거나 연장 후 성과를 40분 성과에 넣지 않는다. 원래 과제 성공과 다음 과제로의 이동이라는 구조적 제약은 있지만 `instr-N`은 일반적으로 지시문 읽기의 시작을 나타낸다는 코딩 지침 때문에 모든 지시문 사건을 검사 통과로 바꿀 수 없다. (`SW-C-P`, `SW-C-D`; 사건 수는 root 감사)

## Q3. 실제 연결과 실패 위치

`audit_software.py`를 실행했고 `audit-execution.json`에 명령·시각·종료 코드 0·출력을 남겼다. 연구자의 도구나 모델을 실행한 것이 아니라 공개 패키지를 읽어 키·합계·열 정의를 감사했다.

Newton은 공개 `Participant` 열이 있는 네 설문 파일 모두 12행·12고유 ID이며 중복과 예상 ID 미연결은 0이다. 조건별 설문 24행과 notebook 24개는 파생된 사람×조건 원장 24행에 연결된다. Newton 로그는 12파일·588사건이고 사건 ID 중복 및 timestamp 공란은 0이다. 반면 대조 조건 로그는 제공되지 않았다. 588행을 사람 수준으로 집계하면 12행이 되지만 **이벤트의 처음과 마지막 시각 차이는 33–68분**이며 일부 시각 역전도 있다. 이것을 25분 과제 소요시간으로 쓸 수 없다. 서버가 중단된 한 로그는 저자가 영상에서 복원했다고 설명한다. (`SW-N-D`, `SW-N-R`, `SW-N-A`)

DesignPatternDoc의 `data.csv`는 세미콜론으로 구분한 21행·28열이다. 집단은 0=대조 10명, 1=플러그인 11명이고 빈 셀은 없다. 그러나 참가자 ID가 없어 응답 CSV의 타임스탬프나 정렬 위치를 키로 대신하지 않았다. 논문은 참가자가 만든 코드와 도표를 분석 뒤 보존하지 못한 것을 명시한다. 따라서 배정표를 왼쪽에 두고 최종 검사를 연결하는 작업은 재개 자료 없이는 불가능하다. (`SW-D-P`, `SW-D-D`)

Casdoc의 122개 검색 조각 ID 연결은 실제 성공한 연결이다. 그것은 검색 행과 탐색 패턴 행의 결합이며 사람×과제×배정조건×최종 품질 결합이 아니다. 동일한 `join` 성공이라는 말 아래 두 분모를 섞으면 안 된다. (`SW-C-D`; `../root/casdoc-audit.json`)

## Q4. 공동 성공 범위

세 사례의 1차 종점은 서로 다른 이유로 정의 또는 자료가 모자라며 `bounds.json`의 1차 행은 L/U를 `null`로 둔다. q나 hard deadline 자체가 원래 정의되지 않았을 때 단지 `[0,N]`을 써서 실험이 그 공동종점의 넓은 범위를 측정한 것처럼 보이게 하지 않는다. 추가 품질 기준이나 시간 문턱이 주어진 뒤의 가정적 범위와 원래 연구 종점의 식별을 구별한다.

Newton의 저자 완료 집계는 별도 보조 행으로 보존한다. 그 종점에서는 6/12와 4/12, 차이 1/6이 명시적 집계의 산술 결과다. 논문은 25분 time-box를 명시하고 연장은 언급하지 않으므로 저자가 표시한 시간 내 완료 집계로는 허용한다. 다만 이 완료는 단순 제출이 아닌 과제 성공이라는 레이블이며, 저장된 실패 notebook을 제출로 세는지와 최종 제출의 정의는 따로 공개하지 않았다. strict t=null은 이 차이를 보존한다. 독립 채점자 부재를 새 필수요건으로 삼는 것은 아니다. 원 연구자가 적용한 기능 합격 기준이 확인되면 저자 집계만으로도 재판정할 수 있다. DesignPatternDoc에서 정확한 q가 있다고 가정하거나 계획상 45분을 실제 deadline으로 지정해 극단표를 만드는 계산은 미실시다. Casdoc의 형식별 N은 배정 분모가 아니므로 형식별 성공률 대비 자체가 없다.

## Q5. 부호와 불확실성

Newton의 **저자 완료라는 보조 종점** 차이는 +1/6이다. 같은 사람의 대조·개입 과제가 서로 다른 자료집이며 순서 효과가 남을 수 있으므로 이를 개인별 인과효과로 부르지 않는다. 표본 불확실성의 신뢰구간이나 배정검정은 이 조사에서 계산하지 않았다. 1차 정확 완료 종점의 식별 불가와 작은 표본의 표본 불확실성은 다른 문제다.

DesignPatternDoc에서 직접 재계산한 평균 시간은 대조 2,529.1초, 플러그인 1,178.0초다. 차이는 −1,351.1초다. 그러나 구현 단계 T22만 보면 475.3초 대 483.909초로 플러그인이 약 8.609초 더 걸린다. 이 작은 차이를 효과 입증으로 읽지 않으며 저자가 도구의 해당 단계 지원 부재를 인정했다는 해석과 함께 보존한다. 시간 합은 하위 과제의 합으로 21/21행에서 검산되었고 도구 훈련 2분은 포함하지 않는다. (`SW-D-P`, `SW-D-D`)

## Q6. 반례와 다른 읽기

1. **참고·문서화 단계는 빨라져도 제한시간 내 정확 완료는 별도다.** DesignPatternDoc은 자동 인식·문서화 단계의 시간과 구현 단계 T22의 방향이 다르며 강제 deadline은 확인되지 않는다.
2. **성공자를 뽑은 시간은 전체 배정군의 성공률이 아니다.** Newton의 완료자 6명만 대상으로 로그 시간을 비교하면 미완료자 6명과 대조 조건 미완료자 8명이 빠진다. 현재 로그 시계는 과제 시간으로도 검증되지 않았다.
3. **코드·점수표가 참가자 대장은 아니다.** Newton의 457노드/796연결 그래프는 대화 코딩이다. Casdoc의 122검색 조각은 13명이다. Kruse의 50프롬프트 행은 25명×2함수다.

Kruse의 원논문과 패키지는 선정 후 범위 밖 진단으로 직접 읽었다. 연구는 25/25명에게 두 문서 생성 도구를 비교하고 문서 품질 평점과 True/False 이해 문항을 수집한다. 생성한 문서가 더 높은 평점을 받더라도 일부 이해 문항의 정답 수는 오히려 줄어든다. 구현 과제가 없고 원래 binary 최종 품질 통과선이 없으므로 빈 S04를 채우지 않았다. (`SW-K-P`, `SW-K-D`)

## 재현과 자체 점검

손 계산 1: Newton 저자 완료의 두 조건 표는 두 조건 모두4, Newton만2, 대조만0, 둘 다 미완료6이다. 합계는12이고 Newton 완료4+2=6, 대조 완료4+0=4, 차이는6/12−4/12=1/6이다. 이 표의 축은 **두 조건의 완료 상태**이며 시간×품질 2×2표가 아니다.

손 계산 2: DesignPatternDoc 대조 평균 하위 시간은585.8+325.5+211.8+475.3+468.5+462.2=2529.1초다. 플러그인 값은117.2727+55.5455+114.9091+483.9091+243.0909+163.2727=1178.0초다. T22의 개입−대조는483.9091−475.3=8.6091초여서 전체 시간 차이와 부호가 다르다. 마지막 소수 차이는 표시 반올림 때문이다.

원자료 내려받기는 `fulltext-downloads.json`의 네 ZIP URL을 이용하며 `schema-audit.json`에 입력 SHA256을 고정했다. `python -B audit_software.py --cache cache --output schema-audit.json`은 Python 표준 라이브러리만 사용하고 개인별 값을 출력하지 않는다. 로컬 복사본은 참고용 cache에만 두고 커밋 대상은 URL·해시·원장·집계·재현 코드다. 동작 중인 Newton/IntelliJ 도구 재실행이나 새로운 참가자 검사, 분실 코드의 기능 재검사는 미실시다.

자체 검토 주체는 `/root/software_frame`이다. root는 Casdoc 같은 ZIP의 키·행 수를 별도로 감사했지만 논문 전체를 독립적으로 다시 채점한 검토로 기록하지 않는다. 최소수는 고유 원연구4편과 별도 저자 패키지4개, 합8저작이다. 이 가운데 Kruse 원연구는 범위 밖 진단이다. 패키지 안 과제지·README·CSV·도구 ZIP을 다시 세어 독립 개입 자료 배당을 채우지 않았다.

검색에는 native API 실패·정렬 해석 문제와 좁은 OSF 제목/설명 검색이 있었다. 최종 canonical frame은 Zenodo29·OSF3 메타데이터이고 원래 논문일/DOI로 선택을 고정했다. 그 이전의 진단 검색 노출을 숨기지 않는다. 전체 분야의 가장 이른30개 또는 공개율 추정이라고 부르지 않으며, 진단용 웹 질의 모두의 초 단위 시각·파라미터가 보존된 것도 아니다. 이 결손은 `search-log.json`과 `frame.json`에 남겼다.
