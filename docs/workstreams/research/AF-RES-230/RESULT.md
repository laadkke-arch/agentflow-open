## 비용·설계 대안과 관점
- 녹음을 다시 맞출 믹서: 각 파일 track isolation, source/project 공통 시간 원점·길이/offset, 채널·rate 일관성, 필요한 processing 보존이 성공 조건. trim off만으로 같은 end 보장 안 됨. 프로젝트 저장(AUP3)과 audio stem 공유도 다름.
- 곡별 배포 편집자: 곡 경계(region/point), 듣는 mix, pre-label/곡 사이 공백, filename/metadata 정확성, 압축 형식이 성공 조건. stem처럼 앞 공백이 길면 실패.
- UI 유지자: scope에 대한 정확한 선택/disabled 사유, 기본값과 저장값 구분, selectedOnly의 실제 전달, preview count·range·channel·name collision·tag 표시, 같은 결과의 버전별 시험이 성공 조건. 3.4.2의 top label/PCM mix 문서 불일치와 3.5.0 채널 정책 변경은 별도 안내가 필요.
- 후보 설계(실증 아님): 내부 필드를 unit(track/clip/label/project selection), boundary source(top label/manual span), content selection(track IDs/mute/solo), start basis(project origin/clip/region), end basis, channels, file naming, tags, version/evidence로 구별한다. 요청에서 명확한 필드를 그대로 채우고 첫 링크를 바꾸는 미지 축 하나만 질문. 같은 링크의 설정 차이는 두 옵션값과 결과 예시를 제공. 단위-원점이 함께 모호하면 질문 후보 두 개 중 사용자가 선택해야 하는 손실이 큰 쪽을 우선하되, 지명 자료에서 이 우선순위의 적중 검증은 불가.
