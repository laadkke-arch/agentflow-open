# 재생 입력과 파일 접근

기준 판독을 원격 커밋으로 재열람한 후 첫 비교를 실행했다. 두 실행 모두 새 디렉터리에 동일한 request 및 보인 레코드 JSONL, 후보 절, 비교기만 복사했다. 비교기 첫 단계에 Python 파일 열기 감사 훅을 설치해 두 입력과 두 출력 이름 이외의 읽기·쓰기를 거절했다. 정답표, 후보 선택 규칙의 요청 주석, 원본·변형 파일, 완결되지 않은 보기의 정규화 ID는 비교기의 읽기 창에 없다. [재생 지문](evidence/replays.json) · [실행](runs.jsonl)

봉인된 후보 `candidates.json`의 URL과 수를 유지했다. `candidate-conditions.json`은 M60의 opening에 없는 ‘frame’이라는 연구자 추정을 A에 전달하지 않도록 원글의 ‘expected order’를 두 후보가 공유하는 의도로 풀었다. C++ 후보가 이미 19로 끝나고 XML에는 10이 들어 있다는 차이는 공식 원문의 별도 사실로 기록했다. 모든 방식에 같은 참고 날짜와 절을 제공했다. 원 규칙과 gold는 별도 보존됐다. [봉인](evidence/gold-seal.json) · [공통 후보 절](candidate-conditions.json)

기계 판독기는 네 종류의 좁은 문구 패턴을 처리한다. 의미 해석기가 알려지지 않은 다른 요청에 일반화되는지는 미확인이다. B/C에서 시드 후보가 복수면 더 연결이 풍부한 후보를 임의로 고르지 않는다. direct ID와 역저장 대조 없이 문맥이 닮은 후보를 지지하지 않는다. 기록된 application effect는 각 행에서 `unknown`이다.
