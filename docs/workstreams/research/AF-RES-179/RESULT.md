## Q1 — 목적과 실제 호출
J = 한 인수 JSON_VALID를 TEXT 입력에 적용: 예시 SELECT json_valid('{"a":2}'), json_valid('broken') → INTEGER 1,0 (문서 기대값). SQL NULL 입력은 별도 기록하며 역사 버전의 NULL 처리까지 현재 문서에서 소급하지 않는다. Django 3.1.4 C1: JSONField 저장형 TEXT와 CHECK (JSON_VALID("%(column)s") OR "%(column)s" IS NULL); NULL 허용 여부는 필드마다 다름. C2 실제 feature check는 SELECT JSON('{"a": "b"}')의 예외 여부로 J 계열만 검토하고, C3 필드 check는 supports_json_field 참조. C4 LS v1.0.0 서버는 _apply_database_migrations에서 migrate 호출, C5 모델 Task.data/meta 등이 JSONField. 제보 D2의 traceback도 migrate → create_model → cursor.execute로 이어진다. 다만 C4 태그 line 54/235와 설치 wheel의 line57/238가 달라 wheel 동일성 미검증; 정확 테이블과 실제 SQL은 모른다. J는 단순 문법 검증이지 임의 JSON shape 검증이나 앱 전체 성공이 아니다.
A = SELECT '{"a":2}' ->> '$.a', typeof('{"a":2}' ->> '$.a') → (2,'integer'); SELECT '{"a":"x"}' ->> '$.a' → SQL TEXT x; missing path/JSON null → SQL NULL. B = SELECT typeof(jsonb('{"a":2}')), json(jsonb('{"a":2}')) → ('blob','{"a":2}') 기대 (문서/제안, 미실행). SQLite JSONB opaque internal BLOB, 별도 SQL type이 아니고 PostgreSQL wire format 아님. Python 기본 변환 TEXT→str, INTEGER→int, BLOB→bytes, NULL→None (P18). JSONB bytes를 실제로 받는 경우까지 테스트; X10 typeof 출력만 BLOB 근거. JSON_VALID, ->>, jsonb()를 동일 열에서 판정하지 않는다.

## Q7 — when to ask, combining links
First ask one missing thing by user intent: no specified action → J vs A vs B? Known action but CLI only → same Python connection exact operation and value. Known J positive → say limited to that predicate and observed time. Need B → ask BLOB type and roundtrip on target connection; D12 B type does not ensure jsonb_each or all future operations. If exact action succeeded but value is NULL/empty, ask known path/input with expected typed result, not version upgrade. If task really is Django storage, reproduce same migration not isolated SQL alone. Separate upstream capability link, package link, observation link and its exact conditional sentence.
 
## 경쟁 설명과 조합 비용
Publisher sees API/option/version; package producer sees ABI/compile/link/distribution; app user sees actual process and query result. Version-only A candidate cheap but false positives (X8 CLI, X10 version name); flag-only B better before 3.38 but OMIT_JSON and connection-level load matter, and lack of ENABLE_JSON1 after 3.38 is expected; exact probe C costs one user run, guards against false negative old opt-in and false positive wrong process; full application D also tests input semantics and migrations but heavier. Designs as alternatives: two-link candidate plus caveat, typed receipt with minimal identity, or on-demand check for operation. Never imply the check is already performed by the explorer. No product DB/collector/final search schema selected.
