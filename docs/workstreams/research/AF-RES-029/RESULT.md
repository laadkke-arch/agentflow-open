## 이 비교가 지지하는 선택

**상태는 REVIEW_READY_WITH_GAPS다.** 원 반환의 최대 3 URL 기준 부분 완결은 공통 출발점 2/12, A 4/12, B 3/12다. 두 경로 공통 성공은 Q01·Q09 두 사건, A만 성공은 Q04·Q10 두 사건, B만 성공은 Q11 한 사건이며 양쪽 미지지는 7/12다. 전체 설계는 C/A/B 모두 0/12다. '지지'는 동결한 필수 술어 전체에 대한 문서 근거이고, '미확인'이나 빈 반환은 그 부품이 세상에 없다는 판단이 아니다.

이 자료에서 다음 열람의 목적은 **호출할 부품과 필요한 절을 연결하는 것**이다. 출발 제공자에 그 부품이 없거나 탐색 가능한 링크가 없을 때 A가 유효했다. Q04는 명세 PDF에서 실제 버퍼를 쓰는 API로, Q10은 표준·SciPy 설명에서 NumPy의 실제 생산자/소비자 문서로 옮겨 부분 요구를 완결했다. B의 Q11 이득은 새 제품 발견이 아니라, 이미 읽힌 StringDType의 인용을 배열·스칼라 계약까지 연결한 것이다. 따라서 이 12건은 남은 예산을 항상 A 또는 항상 B에 주는 일반 규칙을 확립하지 않는다.

공통 출발점 대비 추가 부분 성공은 A 2/12, B 1/12다. **새 대상인 성공은 양 경로 모두 Q01의 JavaScript 하나이고 이미 공통 출발점에 있었다.** 공통 이후에 새 대상 성공이 늘었다고 볼 사건은 0/12다. 명시된 제품군의 새 부품으로 분류된 반환은 있지만 그 범주의 부분 완결은 0/12다. 같은 제품명/용도와 실제 사람의 사전 지식은 별도 값이다.

상위 1 URL에서는 Q04의 버퍼 연결과 Q10의 생산자 export 근거가 빠져 A가 2/12로 내려간다. Q11의 strings HTML만으로 정확한 Python 스칼라와 N-D 사용까지 충분한지에 대해 최초 판독은 넓게 해석했고, 별도 공개 재검은 PDF를 요구했다. 원 판독 해석은 C2/A2/B3, 엄격 재검은 C2/A2/B2다. 이 차이는 [R01](judging/reconciliation.jsonl)과 [재검](audits/positive-crosscheck.md)에 남겼고, 최대 3 URL 판정은 바뀌지 않았다. **1 URL에서 B가 반드시 우세하다는 결론은 성립하지 않는다.**

## 공통 출발과 공정성의 범위

질문별 봉인 중립 질의 1개를 같은 도구(system2_search_query), 영어, 같은 현재 조사일, 무 recency/domain 제한으로 실행했다. 제공 순서 앞 10개를 기록하고 적격 원문을 앞에서 최대 2번 열었다. 이는 역사적 검색 순위나 인증된 전체 검색엔진 순위가 아니다. 스니펫은 경로 찾기에만 쓰고 원문 근거 수에는 넣지 않았다. Q02에는 적격 공통 출발점이 없었고 Q04에는 첫 실패, Q07에는 메타데이터 응답이 있었다. 이를 삭제하지 않아 전체 분모는 12, 읽을 수 있는 공식 공통 본문 하위분모는 11이다.

공통 출발만으로 반환 부분이 지지된 사건은 Q01·Q09다. Q11 공통에서는 필요한 본문이 열렸지만 반환 절이 누락돼 열람 기준으로만 추가 성공한다. 여러 공통 시작이 같은 제공자의 미러/판 두 개여서 서로 다른 제공자 둘을 확보한 설계가 아니다. Q10 공통 검색에는 NumPy interoperability가 3위에 있었지만 앞의 적격 두 원문 뒤에 있어 공통으로 열지 않았다. 그 뒤 B는 SciPy와 Array API 경계에 남았다. 이것은 제공자 내부 탐색의 조건부 약점이며 공개 웹 전체의 부품 부재가 아니다.

A의 두 질의와 B의 목차→API/타입→공식 예제 규칙은 상대 결과 열람 전에 고정됐다. 홀수는 A, 짝수는 B가 먼저 완료됐고 원 시각으로 점검했다. 기록상 상대 경로의 결과 입력 유입은 0건이다. 그러나 24실행 중 23개가 여러 질문 문맥을 공유했고 21개는 같은 작업자가 완료한 앞 질문 기억이 있었다. 양 경로가 모두 질문별 새 문맥인 쌍은 0개다. 가림 판독자는 세 분리 문맥의 **같은 모델**이며 사람 0명이다. 공통 응답 라벨, 중복 URL과 익숙한 API로 경로를 추정할 가능성도 기록했다.

표집 상태/후발 복원 노출을 제외하면 Go 4건만 남아 C1/A2/B1이다. 관련 제안까지 포함한 모든 상태/후속 노출을 엄격 제외하면 분모 0, 해당 없음이다. 기록된 상대 경로 노출만 제외하는 기준은 12건을 남기지만 내부 기억 독립성을 증명하지 않는다. 각 정의와 사건/행 근거는 [노출 감사](audits/resume-exposure-overlap.json)에 있다.

## 직접 읽은 자료와 판정 주체

요구 최소수에 산입한 고유 원문은 **49개 그룹 = 새 최초 전문 12 + 실제 A/B 인용에 연결된 적격 공급자 문서 32 + 타 분야 원문 5**다. 요구 28개(12+12+4)를 충족한다. 박물관과 제조사 보조 사례는 2개이며 설계 사건 12의 분모에 더하지 않는다. 원문을 열었어도 실패/줄번호 화면/색인만인 응답은 최소수에서 제외했다. 첫 121개 출처 행의 669,531바이트 해시는 보존했고 13개 보강 출처를 덧붙였다. 출처행 134, 시도행 661은 고유 원문 수가 아니다.

## 서로 다른 관점과 사후 반례

설계자에게 중요한 것은 이번에 호출할 동작과 남는 접합이다. Q02의 의미 정규화, Q08의 잘못된 그래프 거절처럼 핵심 기능을 어댑터가 전부 만들어야 하면 유용한 단서여도 부분 완결로 올리지 않았다. 공급자 관점에서는 지원판·장치·변경 가능한 버퍼·명시 configuration이 계약의 일부다. 검색자 관점에서는 요청 수와 실질 본문이 다르며, 판독자 관점에서는 이미 열었던 같은 문서에서도 반환 절 선택이 성공을 바꾼다.

[반증 원장](supplementary/CHALLENGES.md)은 분야명을 지운 입력→출력→상태 관계로 추출/패딩, 감지/회복, 정수/공유 버퍼, 경로 그래프/거절, dtype/값 독립, CPU 배열/공유 저장소, 문자열/엄격 검증을 다시 맞췄다. 같은 list, recover, resolve, result_type, array, NPY_TARGET_VERSION이라는 이름만으로 다른 주체·다른 출력·다른 판을 받아들이지 않았다. 사후 반례는 경로 반환 수나 성공 분자에 추가하지 않았다.

박물관 사례에서는 [Met의 API 운영 문서](https://metmuseum.github.io/)가 유효 objectID 목록과 total을 제공한다. 식별자 열거가 목적이면 목록에서 끝나며, 모든 개별 작품을 여는 비용은 목적을 더 충족하지 않는다. 반대로 [Quail and Millet 객체 기록](https://www.metmuseum.org/art/collection/search/45734)은 Kiyohara Yukinobu, 17세기 후반, 비단 두루마리의 재료·118.4×47.6cm 치수를 제공한다. 제목이나 accessionNumber만으로 그 실물 정보를 대신하지 못한다. 운영 문서는 accessionNumber가 항상 고유하지 않다고 경고하지만, 이 작업은 같은 번호를 공유하는 다른 실물 두 개를 실제 비교한 것으로 쓰지 않는다.

제조사 사례의 [1591XX 카탈로그](https://www.hammfg.com/electronics/small-case/plastic/1591xx)는 표준 brass-insert/M3와 economy self-tapping, flange 변형을 구별한다. 검은 economy 부품 번호 목록만 필요하면 표로 충분하다. 조립에서는 같은 크기 계열이라는 이름이 결합면·나사를 보장하지 않는다. [1591XXASBK 개별 항목](https://www.hammfg.com/part/1591XXASBK)은 99×51×20mm와 M3 교체 나사를 적지만, 카탈로그의 명목 101×51×25mm 및 [실제 도면](https://www.hammfg.com/files/parts/pdf/1591XXASBK.pdf)의 100.90×51.40mm, 높이 25.00mm, #4×1/2 self-tapping 표기와 맞지 않았다. 도면의 PCB 94×44.50mm와 내부 높이 21.00mm도 별도 경계다. 따라서 **개별 페이지까지 내려갔다는 사실 자체가 정답 보증은 아니다.** 어느 자료가 오래됐는지·실제 부품이 무엇인지는 미확인이며 제조사 개정 도면이 다음 첫 자료다. 이 비유로 A/B 적합률을 높이지 않았다.

재현은 저장소 루트에서 다음 명령을 쓴다. 원 입력을 다시 검색하거나 다시 표집하지 않고 저장된 원장과 판독을 재결합한다.

GitHub 원격 재독은 별도 영수증이다. 미실시 공급자 환경 시험은 [pending-checks](supplementary/pending-checks.md)의 명령·입력·사유를 따른다. 원 자료 보존/재현 통과는 표집 무노출이나 사람 판독의 충족을 뜻하지 않는다. 공통 색인 반영 제안은 “제품명” 아래에 **호출자/입력/출력·필수 술어·지원판·정확한 API/타입/예제 절·남는 접합·원문 열람과 반환 완결의 별도 상태**를 기록하는 것이다. Q04/Q10처럼 제공자 경계를 바꿔야 하는 경우와 Q11처럼 같은 제공자에서 인용을 완결할 경우를 구별할 근거가 된다. 이 브랜치는 공통 색인이나 dot-control.json을 수정하지 않았다.
