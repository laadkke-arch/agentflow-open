# AF-RES-029 — reading rules fixed before route results are inspected

This document operationalizes the already committed SCOPE and predicates. It does not add a predicate, remove an inconvenient requirement or modify a query. It is written while the isolated route selectors execute, before the coordinator inspects their results.

## Unit, evidence and verdict

The independent unit is one of the twelve design events. A route has at most three candidate uses and three document URLs. Several sections of one document, several candidates for one event and repeated editions do not increase the event denominator.

For each mandatory predicate use `supported`, `conflict`, or `unverified`. `Supported` requires a directly read supplier statement, official test or implementation that entails the frozen predicate in its documented environment. `Conflict` requires positive contradictory evidence, including a different output/actor or incompatible environment. Missing information is `unverified`, not a universal absence claim. A missing result is an observed retrieval failure, not proof that no component exists.

Score two evidence surfaces separately:

- **Opened evidence:** all substantive original text actually delivered within that route's allowed calls, plus its stored common originals. The source's reported total line count is not a claim that those lines were delivered.
- **Returned citation:** only the original URL and exact section supplied in the sealed return. Later rereads and uncited sections cannot improve this score. When a section label is too vague to locate necessary evidence, keep a citation-completeness gap.

Each candidate use must meet every partial mandatory predicate to count as a partial completion; every whole mandatory predicate is needed for whole completion. If any required predicate conflicts, the use conflicts; otherwise an unmet predicate yields unverified. Do not sum unrelated tools' predicate fragments into a fictional working component. Multiple returned URLs can support one coherent component or an explicitly documented composition. The caller may select configuration, supply an offset or wire an interface; implementing the core required behavior is not residual integration.

The primary event success is at least one supported candidate use on the **returned-citation** surface. Separate opened-evidence success exposes citation loss. Unknowns remain in the full denominator and are never silently converted to support. Documented interface support is not a runtime execution result.

## Versions, identity and novelty

Record each observed version/commit and compatibility boundary. Do not combine incompatible editions to manufacture a single supported use. Unpinned current or development manuals establish only the observed contract. They do not prove original availability, authors' ignorance, past rankings or saved labor.

Novelty compares the selected first text's explicit named family/component and intended use with the return: `new_target`, `new_component_in_named_family`, `same_named_use`, or `unverified`. A spelling change or later realization of an already proposed operation is not automatically a new use. Actual human prior knowledge remains unverified. Prior-025 overlap is audited only after routes are sealed and is never supplied to selectors; overlapping candidates do not count as new samples in that sensitivity analysis.

## Masking and independence

Create shuffled opaque packets after all twenty-four route returns are sealed. Include frozen question predicates and candidate names/intended uses/citations, plus sanitized delivered body excerpts. Remove route, rank, selector assessment, selection rationale, later choices, path names and source IDs that encode a route. Keep the route/rank key in a separate sealed file. A common-only packet is included without its label. Readers must not read the key, route directories, search snippets, later proposal drafts or each other's judgments.

Fresh readers are separate contexts of the same model, not independent humans. They can infer familiar APIs or infer a likely route from a packet's content; record such inferences if made. The coordinator has seen common evidence and collects final outputs, so coordinator reconciliation is a separate exposed reread. Preserve initial masked verdicts and any append-only correction with reasons.

## Required sensitivities

- Report the full twelve-event denominator and the subset with an actually readable official common source. Empty routes and both-failure ties remain visible.
- Report ledger, original whole/partial request boundary, partial/whole support, new target/named family/same use, and known common provider versus external provider.
- For top-one-URL analysis, take the first distinct document URL in original candidate/citation order. Rescore using only that URL's returned sections. Do not choose the best URL after seeing outcomes.
- Report exposure-inclusive results; then strict exclusion of events with recorded sampling/current-outcome exposure, and separately route-cross-exposure exclusion. If a conditional denominator is zero, label it not applicable.
- Count navigation operations, body-open attempts, substantive original-body responses, fetch failures and unusable metadata responses separately. Record actual HTTP/token instrumentation as unmeasured where unavailable; local saved UTF-8 size is not network transfer volume.
- Cross-field cases, same-name distractors, supplementary official decisions and source rereads occur after the route seal and cannot add route wins.

## Falsification priority

Try to overturn apparent positives with the frozen counterexample inputs and remaining-adapter rule. Try to overturn apparent negatives by checking whether an exact supporting section was opened but omitted, or whether the opposite route retrieved a valid external component. Neither a recognizable product name nor a useful clue is sufficient on its own. Preserve unresolved cases with reason, last checked location and one next source capable of changing the answer.
