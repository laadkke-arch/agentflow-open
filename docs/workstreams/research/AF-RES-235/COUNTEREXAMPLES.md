# ④ 반례·정정
## 1. 처음 추정에 대한 수정: 2.2 제거 결정은 2.0/2.1 노트보다 앞선 별도 경로
G10 PR2797 2022-11-16 제안, 11-22 G09 결의, 11-23 병합, G11 2023-01-05 CfC, G12 1-12 합의(25 +1/3 objections), W03 10-05 REC. G13 11-30 이슈는 교육, 테스트 도구와 다중판 전환 부담을 제기, 2023-01-13 CfC 사유로 닫힘. G01 2023-04-04 회의에서 2.0/2.1 노트 결의와 2.2 재검토 여부가 논의되었으나 기존 제거 방침 유지. G02는 4/18 생성/7/17 병합 원 diff 확인으로 초안·정오표 항목일·발행일 구분 확정. 최초 외부 공개 초안의 날짜판은 F08, 12/13 회의 직접 접근 F09 실패. 계획의 단일 시점 가설을 세분화.

## 2. P1/P2: URL alive ≠ requirement alive
W01/W02 옛 본문 고유 ID 등 잔존; W06/W09은 본문과 충족간주 노트 공존. W03/W08은 번호/제거 표시만. 따라서 동일한 번호, 동일한 검색 키워드, 본문 문장 존재로 현재 실패를 판정하면 잘못된다. 2.0 정오표는 editorial #13(규범 원문 제거 아님), 2.1도 editorial. HTML/XML 한정; 다른 마크업을 자동으로 충족이라 판정하지 않는다. author nonconformance ≠ WCAG 4.1.1 failure. old audit의 당시 실제 판단 타당성은 당시 기준+실제 결함+감사 결과 필요, 옛 보고서 전체를 사실로 인증하지 않는다.

## 3. P4: 도구 규칙 사라짐 가설 반례
A07 제목/PR 설명의 remove 표현보다 A04/A05 파일의 enabled=false 우선; A24/A25 명시 실행용 시험 기대 여전히 존재. A06의 태그 wcag412+reviewOnFail=true와 A23 expected incomplete는 동일 rule ID에 실패 분류까지 바뀐 구체적 반례. A18 4.8 도움말 L113 여전히 F77/4.1.1 링크(현행 안내에서 옛 자원 존재), G06 F77 obsolete이지만 L27–29 관계 문제 여전히 설명. A19 실제 공개 사용자 보고 v4.10.1 withTags에서 규칙 누락; contributor는 obsolete 태그/비권장 안내. 이것은 도구 사용자의 특정 환경 보고일 뿐 자체 실행 증거 아님.
- 합성 입력 C1: <p id=x>A</p><p id=x>B</p> (다른 참조 없음). 역사적 원문 ID 조건에 걸릴 수 있지만 현행 HTML 4.1.1 충족 간주/2.2 제거. 4.1.2 실패를 자동 생성할 근거 없음.
- C2: <span id=n>다른 제목</span><span id=n>실제 제목</span><button aria-labelledby=n>열기</button>. 관계 모호성/이름 불일치가 있으면 4.1.2 검토, 표 관계라면 1.3.1 가능. 실제 접근성 이름이 올바를 수도 있어 자동 failure 아님; A06/A23 review 의미와 합치. 이 둘은 실행하지 않은 제안 입력. 
- C3: <img src=x>는 이미지의 목적·예외를 조사해야 하고 1.1.1 존속. image-alt 태그 A26/27 유지; 도구 통과만으로 텍스트의 동등 목적 보증 불가.
- 1.1.1 control: W01의 Controls→Guideline 4.1과 W04 #2의 SC4.1.2 정정 차이는 요구 전체 폐지/완전 바이트 불변이라는 두 가설 모두 반증. P3 핵심 존속만 지지.

## 4. P5: RFC 연결 강도와 역조회
R01/R02 update는 둘 다 보관. R03→R04/R06와 R05/R07/R08 분할 때문에 단일 latest URL을 후계로 간주하지 않는다. R10 verified EID499은 Abstract 목록 정정이지 RFC2119 폐지 아님. 단순 related, reported 또는 held를 verified와 합치면 잘못. R09 공식 정책은 원문 파일과 informative rendering 분리. 
## 5. 보존 비용과 반증 조건
모든 오래된 link에 자동 warning을 붙이면 1.1.1 안정 사례의 비용과 경고 피로가 증가; 내용/참조만 바뀐 경우 diff 유형과 중요도 제한. 병기는 세부 scope·출처·판별 날짜 필드가 더 필요하나 audit provenance 복구 가능. 완전 교체는 현행 전용 카드에서만 (원래 citation 보존, 사용자 목적 확정, 후계 절+scope 검증). 시간/저장 byte 실측 아님. 조건: 실제 DOM target 불일치, 해당 CfC 또는 erratum 상반된 원문, 고정판 실행에서 rule 태그/분류 다름, HTML/XML 밖 마크업에서 적용 근거 확인 시 관련 주장 재검토.
