## Q1~Q7 답과 적용 조건

**Q1 — 동일 문장인지 먼저 검사.** [B1A](https://github.com/mdn/browser-compat-data/blob/a630801ac9352a2a84c926e841b22d2c7476f824/css/properties/align-content.json)의 parent Chrome29(21 prefix)와 flex_context21, grid57, block123은 다른 술어/조건이다. Firefox는 flex28, grid52, block125. [C1A](https://github.com/Fyrd/caniuse/blob/e3d9f5f611976ae05c15b0a2e1f450f5e4e53ba6/features-json/flexbox.json)의 Firefox22–27 a #3는 align-content 포함 기능 묶음 결손이고 28 y로 바뀐다. 이 넓은 단계에서는 일관성이 있지만 center 결과의 합의는 아니다. [R03](https://github.com/Fyrd/caniuse/blob/main/CONTRIBUTING.md), [R04](https://caniuse.com/ciu/about)에서 y/a/n, prefix x, flag d, unknown u, note # 분리. y라도 사양 모든 하위 기능 완전 지원을 보증하지 않는 운영 정의다. 고정 후보 CIU와 BCD의 2024/25 자료 모두 해당 값의 동일 의미와 당시 화면을 확인해야 합의에 포함한다. 속성/값/구문/적용 조건/used value·실제 렌더/엔진 제품/기본 활성/OS를 따로 기록.

**Q2 — 누가 작성했는가.** [R01](https://github.com/mdn/browser-compat-data/blob/a630801ac9352a2a84c926e841b22d2c7476f824/README.md)와 [R02](https://github.com/Fyrd/caniuse)에 BCD를 쓰는 프로젝트에 MDN과 CIU가 명시된다. [R03](https://github.com/Fyrd/caniuse/blob/main/CONTRIBUTING.md)의 CIU native DB→export, PR 승인→DB 경로도 존재한다. 따라서 전부 BCD 복사라고 보는 경쟁 설명도 부당하다. [P1](https://github.com/mdn/browser-compat-data/pull/26792)→[B8B](https://github.com/mdn/browser-compat-data/blob/03681469611e3281cb0f5a2ccd0756326a0f5ed3/css/properties/font-kerning.json)는 PR이 특정 값 데이터를 추가한 연결; [D02](https://caniuse.com/mdn-css_properties_font-kerning_normal)는 mdn namespace 및 값이 같지만 정확 importer 증거가 없어 부분적 추론. CIU native row의 최초 셀별 작성·정정 commit과 MDN의 당시 표 렌더 경로는 추적 끊김. 일반 공유 공급은 문서로 확인하되 cell-specific 독립성은 별도로 유보.

**Q3 — 최초 증거와 실행 구별.** P1/P2는 collector 보고 및 추정에 기반한 저작; raw run ID 미확보. [R05](https://github.com/openwebdocs/mdn-bcd-collector)의 collector는 생성된 feature detection test를 설명하며, 코드의 기대값이 렌더 성공이라는 뜻은 아니다. [P5](https://github.com/mdn/browser-compat-data/pull/22702)의 네 브라우저 시험은 당사자 보고(정확 값/OS/결과 파일 미상). [E08](https://bugzilla.mozilla.org/show_bug.cgi?id=1684236)의 WPT sync와 릴리스 논의는 시험 파일/동작 이력과 배포 보고이지 실행 pass 영수증이 아니다. [X05](https://wpt.fyi/results/css/css-align)에서 판독 가능한 실행행 0; 실제 실행 0으로 취급하지 않는다. 기술 도메인 원자료는 배포·이슈·PR 문구까지 도달했으나 같은 대상 판의 관측값까지 도달한 사례 없음. Codex 후속은 정확 빌드와 fixture 기준으로 전달한다.

**Q4 — 다수 표시와 독립 계보.** [E07](https://hacks.mozilla.org/2010/11/firefox-4-font-feature-support/)은 BCD font-feature-settings 주석과 CIU native font-feature #1이 직접 가리키는 같은 옛 구문 출전(L09/L10). 각 사이트의 다른 부분이 별도 시험일 가능성은 남긴다. 두 JSON은 별개 데이터 저작, 같은 문장을 지지하는 해당 주석은 하나의 명시된 출전; 그 기사에서 모든 지원판이 왔다고 추정 금지. [E05](https://developer.mozilla.org/en-US/docs/Mozilla/Firefox/Releases/125), E08/E09은 Gecko 출시 보고와 구현 이슈 연결로 각각 링크를 줄 이유가 있어도 독립 실측 세 번으로 세면 안 된다. P5의 시험과 Chrome 공식 발표가 별개 관측이라는 가설도 가능하나 실행 artifact/주체 연결이 없으므로 unknown. 데이터 생성 경로, 특정 셀의 편집 경로, 실제 관측 경로를 서로 다른 연결로 보존(provenance.csv 28행). 원천 불명은 B가 0이 아니라 확인된 수=0, 실제 수 unknown.

**Q5 — 정정과 시간 차.** B6A→B6B는 serif 1/1 하위값 추가; P2는 Chrome15+ 일부 실패 및 Firefox5–49 crash, 처음 표준판에서 통과하면 상위 지원 시작판으로 추정했다고 설명한다. B8A→B8B는 normal33/32 추가(P1). 두 변화는 2025 신규 기능 배포가 아니라 데이터 상세화/소급 기입이다. N6/N8의 대상 131/133을 재선택하지 않음. B1의 normal(P3), B3의 default(P4), B5의 font width 이름(P11)은 다른 값/편집 변화. CIU 넓은 네 기능의 후보판 131/133 y 값은 유지; exact 동등 셀의 전파 시차는 추정 금지. B3의 flex 36 vs note52는 서로 다른 절차를 표현했을 가능성도 있으므로 독립 관측 반박이 아닌 내부 미정합. B7의 parent48/34 vs normal16/15(P8)는 prefixed detection vs unprefixed property 차이일 수 있음. 이 역시 동일 술어라는 전제가 없으면 충돌 판정 안 함. E11은 font-family의 option 예외로 단순 y→모든 요소 사용 가능이라는 추론을 반박하나 같은 FF133 serif 일반 요소의 동등 주장 반례는 아님. 엄격한 독립 실측 하나가 동등 다수 표기를 뒤집은 사건과 양의 독립 합의 사건: 미확보. 추적 최초 결측과 필요한 최소 증거를 claims/observations/advice에 기록.

**Q6 — 다른 분야.** T01/T02: BLS Employment Situation Table A-1의 2026-10 SA 7,068천명/170,683천명 = 4.1410%, 한 자리 4.1%, FRED UNRATE 같은 시리즈/발행기관과 월간 SA 정의(별개 페이지의 별개 숫자 아님). 독립 측정망 예는 다른 sampling frame/동일 대상의 별도 조사 필요; 비계절조정이나 다른 분모는 동일 주장 아님. **Q7 — 원문을 반환하는 설계 대안.** A는 발견용으로 유용하나 점수나 독립성으로 변환하지 않음. B는 특정 주장마다 공통 supply/citation/test lineage를 연결하여 복제 링크를 묶고 미상은 숨기지 않음. C는 사용자에게 중요한 판·조건·값·실측에 한해서 최종 추천의 강도를 정함. 하나의 원전(P1)은 *데이터가 왜 바뀌었는가*에 충분하되 렌더는 보류. 세 복제(BCD/MDN/CIU BCD row) 가능성은 하나의 공급 원리로 설명 가능하지만 당시 세 페이지 동등성과 exact import는 미검증이므로 사례를 완결된 세 복제로 주장하지 않음. 한 강한 원천에 별도 원천을 보강하려면 무엇이 추가 검증됐는지 말해야 한다. 사용자에게는 예: "2025년 BCD에 font-kerning normal Chrome33/Firefox32로 추가되었고 PR은 collector를 출전으로 밝힙니다. 사용 폰트에서 실제 커닝을 확인하세요." 필요한 경우 [PR](https://github.com/mdn/browser-compat-data/pull/26792)을 대표, [표시](https://caniuse.com/mdn-css_properties_font-kerning_normal)를 읽기용. 데이터 저장 구조 확정 아님. 독립 관측이 기술 결론을 실제 바꾼 사례가 없으므로 C 우월성/빈도는 미검증.
