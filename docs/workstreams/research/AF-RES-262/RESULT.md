## 대안과 적용/철회 조건
A. relevance-first 탐색 후보 우선순위: 원점수·원행/분포·출처·평정 범위를 표시, 1점도 아이디어 단서로 보존. 적합성 gate를 통과했다고 표시하지 않는다. 사용자의 요청이 단순 원래 query의 관련 탐색이면 유용; hard constraint가 있으면 단독 사용 철회. 원코드 접근/버전 증거 없을 때 평가와 내용 판독 U 분리.
B. 조건 ledger + 검증 gate: 원 관련성 축 별도, 추가 조건별 Y/N/U/NA·근거 위치·범위·판/실행 상태 저장. hard condition에 N/NA면 그 목적의 direct solution 배제; U면 원인/최소 확인 표시. 강점: J1/J2 반례 설명. 비용: 함수·하위 호출 및 조건 확인, 실행환경별 비용; 새 조건이 필요 없는 질문에서는 이 비용을 선택적으로 쓰고, 요구가 semantic JSON roundtrip이면 문자 조건 재평가.
C. pooled expansion + 사람 행동 추적: 외부 함수 unjudged는 독립 표본/정해진 예산에서 판정 후보로 보강하되 0으로 대체 금지. 사전에 query/candidate selection·평정자 독립성 고정; 249에서 제안한 실제 사용자·artifact chain/검수/시간 없이는 도입·절감 추론 철회. 신규 search rank run이나 CSN 모델 훈련은 이번 범위 밖.
결합 가능: A의 graded relevance를 후보 탐색, B의 조건 gate를 사용 목적, C를 새 후보/효과 검증에 각각 사용. 단일 weighted score로 합치면 unknown을 점수로 만들 위험. 실측 비용 없음; 공개 원자료 28개와 별도 정적 판독(9개 본표)만 확인. 적합성 검증 실패한 고정 소스는 링크 회수 우선, 독립 검증과 actual test는 Codex 인계.
