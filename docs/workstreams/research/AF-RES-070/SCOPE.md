## 2. 모집 순서 — 댓글을 열기 전에 고정

각 큐의 검색식은 `repo:OWNER/REPO is:issue in:title,body TERM created:2021-01-01..2024-12-31`, 정렬은 `created`/`asc`. 큐 내부 동시각은 issue number 오름차순이다. 첫 용어부터 번갈아 한 항목씩 꺼낸다. 중복이면 그 방문도 기록하고 같은 차례에서 해당 큐의 다음 미방문 항목을 꺼낸 뒤 상대 큐로 간다. 한 큐가 소진되면 다른 큐에서 이어간다. API 반환 순서와 정렬 후 순서를 모두 보존한다. 검색은 현재 색인에 대한 모집이며 당시 삭제된 이슈의 전수 복원이 아니다.

초기 8개 전부의 최초 글을 읽고, 그 글만으로 일부 동작과 원하는 결과를 식별할 수 있는 순서상 첫 3개를 잠정 슬롯으로 고른다. 봇 공지, 단순 충돌/크래시 재현만 있고 설계 목적이 없는 글, 요청 부분/목적 부재는 사유와 함께 남긴다. 버그 보고라는 이유만으로 일괄 제외하지 않는다. 댓글 수·해결 여부·후속 내용은 선정 입력에서 가린다. 순서·본문을 읽은 적격 여부와 시간순 주 분석 적격 여부를 별도 열에 둔다.

작성 당시 body가 복구된 적격 사례가 3개보다 적으면 해당 저장소의 다음 8개(순위 9–16)를 같은 규칙으로 연다. 그래도 부족하면 공석을 남긴다. 주 표본을 채우려고 17위 이후에서 임의로 고르지 않는다. 미응답·정보 추가 무효 대조가 부족하면 같은 큐의 다음 미열람 8개만 진단층으로 조사한다(주 표본 대체 금지). 선정과 진단에서 이미 읽은 이슈는 중복 계상하지 않는다.

## 3. 최초판과 가림

최초 본문 원문은 분석 작업 사본의 `private/`에 순서·바이트를 보존하고 SHA-256과 위치를 공개한다. 공개 산출물에는 짧은 최소 발췌와 분석 요약만 남긴다. 검색 결과·REST 최초 body만 수집하고 댓글 endpoint는 A 커밋 전 호출하지 않는다. HTML을 확인해야 할 경우 parser는 최초 issue 객체의 편집 메타데이터/최초 본문만 노출하고 댓글 노드는 분석자에게 출력하지 않는다. 네트워크에서 수신했으나 판독하지 않은 댓글과 실제 판독을 구분한다.

`updated_at`은 댓글/라벨 등으로도 바뀔 수 있으므로 body 편집 증거로 단독 사용하지 않는다. 최초 body의 `lastEditedAt`·`edited` 표시·공개 수정 이력을 확인한다. 무편집 직접 증거가 있으면 현재 body를 최초판으로 승인한다. 편집된 경우 공개 편집 이력/당시 원공개 보관판으로 작성 시 body를 복구한다. 복구하지 못하면 시간순 주 분석에서 제외하고 진단층에만 남긴다. 수정 여부 자체가 미확인이면 최초판 확인도 미확인이다. 편집본의 추가 조건을 A 최초 정보라고 부르지 않는다.

사전에 읽은 댓글/후속값이 생기면 해당 분석자는 그 행의 사전판독자로 집계하지 않는다. 공개 body 자체에 다른 시점의 후속 내용이 들어 있으면 편집 복구 문제로 기록한다. 팀원별 판독 범위와 A 봉인 시각을 적고, 서로 다른 저장소를 맡아 댓글 정보의 사전 전파를 막는다.

## 4. A 사전 봉인

댓글 판독 전에 각 행에 다음을 기록하고 커밋한다.

1. cutoff-A, 최초 글 URL·작성 UTC·body hash·원문 위치, 원 작성자가 지목한 부분·목적·금지조건·실행 설정.
2. 실제로 가능한 해석 두 개와 같은 도구 안의 작업 후보 두 개. 억지 양분을 만들지 않고 해석이 하나면 그 이유를 적는다.
3. 목적 / 인접 단계 / 금지조건 / 실행 설정 중 **한 필드**, 그 필드에서 두 선택을 가르는 **한 값**의 형태. 복수 정보 묶음은 금지한다.
4. 질문 한 문장 또는 질문 생략, A에 이미 값이 있는지, 각 값에 대한 사전 권고와 바뀔 조건.
5. 당시 이용 가능한 고정 태그/SHA와 판별 문서·코드·테스트 절. 후보당 최대 2개 문서, 문서당 지정 절 1개. 동일 문서를 두 후보가 공유해도 노출 장부는 별도로 연결한다.
6. A의 후보 ID·판·절 목록·예산·봉인 커밋 SHA를 `PINS.csv`와 `COMMITS.csv`로 연결한다. 자기 커밋 SHA는 다음 커밋의 원장에 기록한다.

도구 사용판이 본문에 없으면 당시에 존재한 공개판을 조건부 분석판으로 고정한다. 그 판이 작성자의 실제 설치판이라는 주장은 하지 않는다. 판을 정할 근거 자체가 없으면 판정불가로 유지한다. 좁은 절을 넘어 읽은 경우 노출량과 사후 보강을 남기고 예산 준수 주 분석에서 제외한다.

## 5. B 공개와 독립 판정

A 봉인 커밋을 원격에서 확인한 뒤에만 댓글을 시간순(동시는 ID순)으로 읽는다. 선택한 필드에 답하는 **최초의 같은 작성자·같은 목적 발언**만 B에 한 값으로 넣는다. 원문에 없는 추정은 금지한다. 작성자가 다른 목적을 채택했다면 별도 사건이다. 타인이 추정한 값은 B에 넣지 않고 별도 열에 둔다.

발화 유형은 자발 공개 / 특정 질문 응답 / 다른 질문 응답 / 해당 값 무응답(조회 종료 UTC까지) / 작성자 변경으로 나눈다. B에 값이 없으면 `data_absent`. A에 이미 있는 값은 새 정보로 세지 않는다. A와 B의 후보·도구판·판별 절·예산은 동일하다. B를 보고 새 후보나 새 절을 도입하면 사후 보강층이다.

작성자 의도는 작성자 원문으로, 도구 동작은 해당 판 공식 문서·코드·원시험으로 판정한다. B 값의 문장 자체를 그 권고가 맞았다는 독립 증거로 재사용하지 않는다. 작성자의 별도 이후 댓글·PR·원시험이 없으면 행동 변화·실사용 성공은 미확인이다. 과거 스레드의 사후 정보는 가치 가능성을 보여줄 뿐, 탐색기가 먼저 물었어도 답을 받거나 비용이 정당했음을 입증하지 않는다.

연구자가 설정 하나만 반대로 둔 비교는 `counterfactual`, 작성자가 실제 두 조건을 시험한 직접 원기록은 `observed_pair`, 후속값만 있는 경우는 `retrospective_value`로 구별한다. A의 두 가설은 관측 설정 쌍으로 세지 않는다.

## 6. 결과·분모 규칙

- 모든 12슬롯과 탈락/공석을 표시한다. 본문만 있고 댓글이 없는 글도 모집·무응답 원장에 남는다.
- 정보로 **권고가 달라짐**, 독립 기준으로 **권고가 개선됨**, **작성자가 행동을 바꿈**, **실사용 성공**은 네 개의 별도 결과다.
- 개선: 같은 후보·독립 기준 아래 A의 부적합 선택에서 B의 적합 선택으로 바뀜. A가 조건부/판정불가이고 B가 좁혀지면 `resolved_uncertainty`로 따로 적고 엄격 개선과 섞지 않는다.
- 동일/악화 역시 독립 기준이 있어야 판정한다. B 없음 또는 독립 기준 없음은 `unobservable`이며 개선 0/오답으로 치환하지 않는다.
- 질문 오탐: 질문 제안이 있었고 A에 답이 이미 있었거나, 두 값에서 같은 권고가 됨을 독립 판별 절로 확인함. 분모는 질문 제안 중 독립 판정 가능한 건수. **무응답만으로는 분모 진입 불가**.
- 새 정보를 보고 옳던 A를 틀린 B로 바꾼 경우를 악화로 보존한다. 검증된 악화 0과 악화 미측정을 구별한다.
- 표 3의 분모는 행 슬롯 수이며 `개선+동일+악화+관측 불가=분모`. 불확실성 해소는 별도 세부 열에 두며 엄격 개선에 넣지 않는다. 반사실 비교는 표본 밖 별도 수다.
- 실제 B를 가진 사례와 미응답, 정보 추가 무효를 각각 최대 3쌍씩 비교한다. 동일 저장소 → 동일 동작 → 생성시각 거리 → 이슈 번호 순으로 매칭한다. 실제 양쪽 사례가 없으면 짝 미충족이지 효과 0이 아니다.
- 빈 분모=`N/A`, 실제 관측 0=`observed_zero`, 실행/사람 효과 미측정=`not_measured`, 자료 미확인=`unknown`을 분리한다.

## 8. 검토·종료

RESULT는 지정된 세 표를 먼저 둔다. 뒤에 실제 짝, Q1–Q8, 분야 간 보존 대상/실패 기준, 반례 경로, 마지막에 정확히 3개 약점과 판단을 바꿀 자료를 적는다. 입력 폼이나 질문 정책을 채택하지 않는다.

검산은 CSV 열 수·고유키·조인·합계·계보중복·직접독해·판별절·B 한 필드·A 봉인 이전/댓글 노출 이후 순서를 검사한다. 별도 검토자는 연구자 자체 검토와 구분한다. 실제 명령/cwd/대상SHA/종료코드/누락을 VALIDATION.md에 남긴다. 코드 변경 없는 과제에서 저장소 전체 시험을 불필요하게 반복하지 않는다.

결과 커밋의 GitHub 파일을 다시 읽고 해시·표·원장 수를 대조한 다음 HANDOFF.md만 마지막 단독 커밋한다. 목표 미충족은 `PARTIAL`. 부족한 최초판·B·독립 기준을 성공 수로 채우지 않고 다음 공개 원자료·명령을 특정한다.
