# AF-RES-070 독립 판정 검토

## 검토 결론

**권고 후보를 좁힌 관측 1건과 엄격한 정확성 개선의 판정 가능 분모 0을 구별한 통합 판정은 타당하다.** `RG-1840`의 B는 A의 두 조건부 후보 중 하나를 좁힌다. 틀렸던 A가 옳은 B로 바뀐 사례는 아니다. `RG-1808`과 `jq-2349`의 값은 A에 이미 있던 조건의 재확인이다. 나머지 21행의 자료 없음·모호함·해당 없음은 동일 또는 개선 0으로 바꾸면 안 된다. 원행은 `CASES.json`의 해당 `issue_id`, `VIEWS.csv`의 `-A/-B`, `OUTCOMES.csv`의 `OUT-{issue_id}`에 연결된다.

검토자는 rclone 원자료를 담당했던 조사자이며 통합 원장 작성자와는 다르다. 따라서 이 검토는 통합과 다른 저장소의 판정에 대한 별도 검토이고, rclone 판독 전체에 대한 새로운 외부 맹검은 아니다. 새 댓글·새 문서로 A/B 근거를 보강하지 않았다. 이미 저장된 원자료 사본에서 선택 절과 댓글을 다시 확인했고 봉인된 A 파일을 수정하지 않았다. 검토 대상 파일별 SHA-256, 실제 검산 결과와 수정 사항은 `evidence/adjudication-audit.json`에 고정한다. 최종 원격 결과 커밋 재열람은 ROOT의 별도 검증 대상이다.

| 판정 항목 | 수 | 허용되는 해석 | 허용되지 않는 해석 |
|---|---:|---|---|
| 분석 사례 | 주 12 + 진단 12 | 각 층의 봉인 사례 수 | 24개의 독립적인 질문 실험 |
| 질문 제안 / 생략 | 8 / 16 | 연구자가 사전에 고른 한 필드에 대한 판단 | 작성자가 실제로 받은 연구자 질문 수 |
| 새 B 값 | 1 | `RG-1840`의 제외 원인 보고 | 질문의 인과효과 1건 |
| 중복 B 값 | 2 | `RG-1808`, `jq-2349`의 같은 조건 재확인 | 새 정보로 인한 엄격 동일 효과 2건 |
| 엄격 정확성 효과 | 판정 가능 분모 0; 비율 N/A | 독립적으로 개선·동일·악화를 판정할 완전한 행이 없음 | 개선율 0%, 효과가 없다는 결론 |
| 질문 오탐 | 0/2 | 두 값이 코드상 서로 다른 분기를 가르는 기술적 판정 | 질문 비용의 정당화, 모집단 오탐률, 엄격 예산 통제 결과 |

## 분모와 결과 열

봉인된 SCOPE §6에 따라 표 3의 분모는 슬롯 수다. 각 집단의 `개선 + 동일 + 악화 + 관측 불가 = 슬롯 수`를 유지하면 0/0/0/N은 **분류된 행의 수**로 적합하다. 다만 각 행의 `strict_accuracy_change`는 `unobservable`이고 효과 추정의 분모는 별도로 0, 비율은 N/A여야 한다. `same_direction` 두 행을 이 표의 엄격 동일 열에 넣으면 독립 기준이 없는 방향 재확인을 정확성 관측으로 바꾸게 된다. 연구자의 설정 반전과 작성자의 실제 설정 비교 역시 슬롯 합계에 넣지 않는다. 기준은 [봉인 SCOPE §6](https://github.com/laadkke-arch/agentflow-open/blob/41fa88918ab89617deb220fd491ad06ca1d29b5f/docs/workstreams/research/AF-RES-070/SCOPE.md#6-결과분모-규칙)이다.

`unnecessary`는 **선택한 필드를 다시 묻지 않아도 된다는 판단**이다. 그 이슈에 어떤 질문도 필요하지 않다는 전역 판정이 아니다. 실제로 질문을 생략한 16행을 제안 질문의 오탐 분자에 넣을 수 없다. “무조건 한 번 묻기” 정책이 중복 질문을 만들 가능성은 설명할 수 있지만, 이 연구에서 실행한 정책의 오탐 관측으로 보고할 수 없다.

## 오탐 분모의 두 행을 원자료와 대조

### RG-1840 — 신규 값은 원인을 좁히지만 실사용 성공을 독립 검증하지 않는다

`RG1840-C1`은 hidden 제외 해제, `RG1840-C2`는 해당 ignore 규칙 조정이다. 고정판의 [RG-D2: app.rs L1425–1444](https://github.com/BurntSushi/ripgrep/blob/7cb211378a2ac6d421c5f6f3f71411937af23136/crates/core/app.rs#L1425-L1444)는 hidden 옵션을, [RG-D3: walk.rs L448–480](https://github.com/BurntSushi/ripgrep/blob/7cb211378a2ac6d421c5f6f3f71411937af23136/crates/ignore/src/walk.rs#L448-L480)는 ignore 일치와 hidden 판정의 순서를 설명한다. ignore 제외에서 이미 멈춘 경로를 hidden 옵션 하나로 되살린다고 권고할 근거는 없다. 따라서 봉인한 두 값에 따른 행동 분기는 독립 코드로 구별된다.

작성자 numeric ID `20991`의 [댓글 811886363](https://github.com/BurntSushi/ripgrep/issues/1840#issuecomment-811886363)은 maintainer의 진단 요청 뒤 실제 원인을 부모 ignore 규칙으로 보고한다. 통합 B에는 `exclusion_reason=ignore_rule` 한 값만 들어간다. 같은 댓글의 symlink 설명과 실행 성공 보고를 추가 입력 또는 독립 성공 증거로 재사용하지 않은 처리가 맞다. 다른 조건도 동시에 파일을 제외할 가능성과 전체 목표의 달성은 이 두 절만으로 확정할 수 없다. 따라서 `conditional_pair_to_C2`는 허용되지만 엄격 개선이나 독립 실사용 성공은 미확인이다.

### pandoc-7013 — 다른 질문에 답했어도 봉인한 필드의 B는 없다

선택 필드는 생성된 상대 리소스 후보의 fetch 성공/오류다. [PAN-D03: EPUB.hs L1049–1054](https://github.com/jgm/pandoc/blob/dcbd8d326cce4960e0d736e25e7d00f9057a1fc2/src/Text/Pandoc/Writers/EPUB.hs#L1049-L1054)는 성공 시 다음 이름을 탐색하고 오류 시 현재 이름을 반환한다. [PAN-D04: PandocMonad.hs L355–413](https://github.com/jgm/pandoc/blob/dcbd8d326cce4960e0d736e25e7d00f9057a1fc2/src/Text/Pandoc/Class/PandocMonad.hs#L355-L413)는 원격 입력 URL을 기준으로 상대 참조를 읽는 경로와 로컬 경로를 구별한다. 이 범위에서 성공/오류 값은 같은 제어흐름을 뜻하지 않으므로 조건 판별 가능성을 기술할 수 있다.

하지만 원래 서버의 응답은 관측되지 않았다. 작성자 numeric ID `33672`의 [757339567](https://github.com/jgm/pandoc/issues/7013#issuecomment-757339567)은 입력 URL이 이미 최초 글에 있었다는 응답이고, [757355329](https://github.com/jgm/pandoc/issues/7013#issuecomment-757355329)와 [757374825](https://github.com/jgm/pandoc/issues/7013#issuecomment-757374825)는 회귀 버전과 bisect 결과다. 이들은 선택한 fetch 결과의 값이 아니다. [757552532](https://github.com/jgm/pandoc/issues/7013#issuecomment-757552532)의 감사도 후보 적용 성공 시험이 아니다. B 부재를 유지한 판정이 맞다. 이 행이 오탐 분모에 들어가는 이유는 무응답 자체가 아니라 고정 코드의 조건 판별 가능성이다.

두 행을 합친 0/2는 **예산 이탈을 포함한 기술층의 조건 판정**으로만 제시해야 한다. `질문 필요`라는 제목을 쓰더라도 실제 질문 비용까지 정당화된 필요성이 아니라 후보를 가르는 누락 필드라는 뜻을 밝혀야 한다. 새 사용자에게 그 질문을 먼저 보냈을 때 같은 값을 얻을 확률·비용은 측정하지 않았다.

## 시간순과 노출의 한계

`RG-1808`의 [댓글 791894916](https://github.com/BurntSushi/ripgrep/issues/1808#issuecomment-791894916)은 생성 뒤 수정되었고 최초 댓글 문구는 복구하지 못했다. 따라서 생성 UTC는 현재 보이는 값의 최초 발화시각이 아니다. 이 값은 **현재 편집본에서 확인한 중복 조건**으로만 기술해야 한다. A의 원래 금지조건과 같은 방향이라는 설명은 가능하지만, 정확한 최초 B 사건의 복구 또는 엄격한 시간순 효과 관측은 아니다. `jq-2349`의 [919371061](https://github.com/jqlang/jq/issues/2349#issuecomment-919371061)도 A에 있던 목적의 재확인이며, 별개 [919685736](https://github.com/jqlang/jq/issues/2349#issuecomment-919685736)은 원출력이 없는 작성자 성공 보고로 남겨야 한다.

원시 `preread`의 Boolean 뜻은 저장소별로 다르다. rclone의 false를 다른 저장소의 false와 같은 이유로 일괄 제외하거나 true로 일괄 승인해서는 안 된다. 원래 노출 사유, 최초 본문 복구, 봉인 시점, 실제 읽은 절을 함께 해석해야 한다. `RCL-4914`는 후대 문서 링크 노출을 반영해 재구성층으로 분류해야 한다.

또한 봉인 패킷의 후보당 2문서·문서당 1절 제한과 실제 판독 노출은 다르다. RG-D2는 여러 app.rs 절을 읽었다고 기록하고, RG-D3는 지정 구간 밖 navigation 열람을 기록한다. PAN-D03도 실제 판독 범위 1027–1054가 봉인 판별 범위 1049–1054보다 넓다. SCOPE §4에 따라 패킷이 형식적으로 유효해도 이런 행은 실제 예산 준수층에서 빼야 한다. 통합 `clean_packet`은 초기 문맥 가림과 지정 절 실제 열람 준수를 모두 충족한다는 제한된 뜻으로 사용하며, 조사자의 전체 사전 지식이 통제되었다고 주장할 수 없다. 원행과 한계는 각 `SOURCES.jsonl`의 해당 source ID 및 `streams/*/pre.json`의 노출 열에 남아 있다.

## 기계 검산과 수정 추적

별도 읽기 전용 Python 판독으로 CSV 헤더/행 열 수, 기본키 중복, case·source·event 조인, 24사례의 A/B 한 쌍, B 3건의 numeric 작성자·UTC, 고정 SHA URL, 후보별 문서/절 제한, 슬롯과 분모 합계를 확인했다. 대상 프로그램 실행이나 새 사용자 실험은 하지 않았다. 모든 통과/보류 항목의 스냅샷은 `evidence/adjudication-audit.json`에 있다.

검토에서 발견한 통합 수정은 unknown 문자열을 `field_in_A=true`로 읽던 두 행, 실제 예산 이탈 누락, rclone 후대 링크 노출, 원사건 접근시각과 A 판독 완료시각 혼동, archive 줄 위치 누락, counterfactual의 문서 ID가 후속 사건 ID 열에 들어간 문제다. 이들은 원자료 결론을 새로운 효과로 바꾸는 수정이 아니라 정규화와 추적성의 수정이다. `COMMITS.csv`의 봉인과 결과 커밋 연결, 결과 SHA로 GitHub 파일을 재열람하는 절차, 마지막 HANDOFF 단독 커밋은 ROOT가 이어서 확인해야 한다.

## 인계 판단

자료 수량 충족과 분석 효과 관측 충족은 별개다. 공개 자료의 사후 값은 어떤 한 필드가 후보를 가를 수 있는지를 보여주지만, 이번 판정 가능 효과 분모로는 질문 정책의 효용·비용이나 정확성 개선율을 추정할 수 없다. 그러므로 결과는 PARTIAL로 인계하고, 누락한 필드 값·당시 실행판·독립 출력·동일 동작의 대조 짝 중 어떤 원자료가 확보되면 판정이 바뀌는지 명시하는 것이 적합하다.
