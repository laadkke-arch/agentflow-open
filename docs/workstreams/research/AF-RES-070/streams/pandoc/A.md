# Pandoc A 봉인 원장

원 모집 첫 세 자리는 #7003·#7013·#7006이다. 초기 8건 모두 GH Archive의 `IssuesEvent/opened`에서 작성 당시 본문을 복구했다. 두 자리의 선노출 때문에 대체 사례를 고르지 않았다. #7003은 변경된 제목과 댓글 첫 구절 두 개가 메타데이터 탐색 중 노출되었고, #7006은 현재 제목 및 후대의 correct/wrong 강조 문장을 먼저 읽었다. 이 둘은 `reconstructed_exposed`, #7013만 `main_blinded`다. 실제 열린 수정이력과 같은 시점 최초본문 복구는 다르며, 현재 body를 최초판으로 간주하지 않았다.

| 자리 | 사례·원문 최소 발췌 | 필드 | 질문 결정 | 근거·한계 |
|---|---|---|---|---|
| 1 | #7003 · outputs two listings | 보존 대상 | 생략 | 리스팅 보존 목적이 이미 있다. --listings만 바꿔 RST 입력 해석을 고친다는 근거 없음. reader 경계의 전체 해결은 미확인. |
| 2 | #7013 · convert a web page to EPUB from a specified URL | 없는 생성 상대 리소스의 fetch 성공/오류 | 한 가지 묻기 | EPUB getMediaNextNewName은 성공시 다음 번호로 재귀, 오류시 이름 반환. 원문은 요청 시도만 기록하므로 실제 응답값 미확인. |
| 3 | #7006 · minus the trailing text, fails | 각주 이미지 뒤 블록 유무 | 생략 | OP가 양 조건과 출력을 이미 비교했다. 고정 2.11.3.2 코드의 backlink와 단독 이미지 조건은 해당 경계를 설명하나 실제 설치판은 미확인. |

모든 후보·고정판·후보별 두 문서/한 절 예산은 `pre.json`에 있다. 같은 코드 파일의 서로 다른 절을 두 후보가 각각 사용하는 경우 후보별로 표시하며, B에서 교체하지 않는다. 코드 탐색 중 본 module-index 및 비선정 JATS 절은 `sources-pre.jsonl`에 별도 보존하고 현재 주 후보의 예산에 새 근거로 끼워 넣지 않는다.

## 직접 읽은 반례와 보존 대상

초기 큐 #7039는 image 파일을 디스크에 추출했다는 사실과 RST 출력에 그 참조가 남는 조건을 분리한다. #7003은 파일 실행의 결과보다 코드 리스팅 텍스트의 보존을 요청한다. #7057은 파일이 열리는 것과 문서 내용이 표시되는 것이 서로 다른 성공 기준임을 보여준다. 이 세 사례는 아직 댓글을 읽지 않은 최초글 보고다. 다른 분야의 파일 보존과 비교할 때 `내용 바이트`, `출력 참조`, `같은 경로`, `렌더링된 의미`를 바꾸어 말하지 않아야 한다.
