# jq 후속 판독과 반례

## 같은 목적을 다시 말해도 권고가 바뀌지 않음

jq #2349의 최초 예시는 anidb_id가 없는 항목을 출력에 남겼다. A에서 이를 보존 금지조건으로 읽어 질문 생략, 결측키 항목 분리 방향을 봉인했다. 같은 작성자의 [후속 목적 재진술](https://github.com/jqlang/jq/issues/2349#issuecomment-919371061)은 이 값을 재확인한다. B는 한 필드만 더하지만 새 정보가 아니며 같은 후보 C2가 남는다. [다른 날의 별개 댓글](https://github.com/jqlang/jq/issues/2349#issuecomment-919685736)에는 작동한 것 같다는 적용 보고가 있다. 원출력·정확한 설치판은 없다. 이 보고를 사용자 추가 질문의 효과로 귀속하지 않는다.

## OP 값이 없는 두 사례

#2259의 현재 댓글1개는2026 유지보수자 수정 보고, #2267의 댓글1개는2023 타인 수정 보고다. 두 행 모두 OP의 선택필드 후속값은 관측되지 않았다. 따라서 B 자료없음이지 개선0이나 잘못된 권고가 아니다. 이 둘은 동일 jq이지만2349의 JSON키병합과 다른 동작이라 유효한 동일동작 효과대조짝으로 강제하지 않는다.

## 편집·시점

#2349의 필터 제안 댓글919406413은18:24:49 생성/18:30:35 수정이다.18:26:41의 OP 의도댓글이 인용한 이전 필터와 수정된 제안을 구분한다. B값으로 쓴17:39:12의 OP 댓글은 created=updated이며 별개 최종 적용댓글도 같았다. 전체 원시출력은 공개되지 않아 프로그램의 완전 성공을 판정할 수 없다.
