## 정답, 교란, 읽기 계측

A는 대상 **경로**를 실행이 열었는지, K는 대상 데이터 **키·필드**의 값에 실행 코드가 접근했는지, R은 사전에 지정한 한 필드 변경이 **보고값**을 바꾸는지, I는 후보 파일의 전체 바이트가 지명한 발행판의 멤버와 일치하는지다. 물음은 각 run에서 후보 경로, 키·필드, 대상 발행 객체와 변경 하나를 지목한다. 보고값에 대한 R은 지정한 변경에서의 국소 감도다. 원산식에 들어간 K 값과 R을 분리하고, 별도 내용 사용은 같은 해시의 어느 경로에서든 지목 필드가 산식 입력에 들어갔는지로 기록한다. 선택 자체를 결정하는 조건값은 포함하며, 열린 파일에서 읽어 버린 값은 제외한다. I는 특정 실행의 취득 경로나 발행판의 유일성을 증명하지 않는다.

| 조건 | 후보 경로 / 정답 단위 | 사전 지정한 선택 교란 / 비선택 교란 |
| --- | --- | --- |
| C1 원본 | S는 main CSV의 선택일 BX 값. T는 main trips의 방향 0 활성 trip 중 첫 ID의 direction_id. | S 선택 BX +100, T 선택 direction_id 0→1. S 비선택 QN 값을 +1, T 비선택 trip_headsign에 표식 추가. |
| C2 복사 | main과 바이트가 같은 extra 경로를 보이게 두고 열지 않는다. 키·필드는 C1과 같다. | extra에서만 C1과 동일한 선택/비선택 필드 변형을 각각 수행한다. main을 그대로 둔다. |
| C3 헤더 | probe 경로에서 CSV 헤더 한 줄만 읽는다. 준비 단계에서 S QN +2, T 첫 대상 trip의 trip_headsign에 별도 표식을 넣어 probe를 만든다. 키·필드 물음은 C1과 같다. | probe에서만 C1의 선택/비선택 변형을 각각 수행한다. 헤더와 main은 동일하다. |
| C4 경계 | S main의 BX 값은 합에 들어간다. T는 같은 노선·서비스일의 방향 1 활성 trip 중 첫 ID의 trip_id를 방향 검사 전 읽고 집계 밖에 둔다. | S 선택 BX +1, 그 증가가 보고 경계를 넘을 때만 -1. T 선택 trip_id를 고유 접미사가 붙은 ID로 교체. 비선택은 S QN +1, T 해당 반대방향 trip_headsign 표식. |

각 행의 두 교란은 각각 원 파일에서 독립 생성하며 하나의 논리 셀만 바꾼다. 섞어서 실행하지 않는다. C1의 변화와 C2/C3/C4의 불변을 예상한다. S-C4 원합 변화도 예측한다. 각 첫 실행/깨끗한 재실행은 다른 작업 디렉터리·새 Python 프로세스로 실행한다. 매 주 실행의 두 교란을 별도 ID로 연결한다(32개). Q6은 추가로 S 한 필드 결측, T 방향 1과 서비스일 변경을 각각 한 번 수행한다. 날짜 변경은 달력에서 먼저 발견되는, 주 날짜 이후 처음으로 활성 서비스 ID 집합이 달라지는 날을 택한다. 순서 비교용으로 주 날짜의 다음 같은 서비스 패턴 날짜도 확인한다.

단계는 준비(복제·해시·입력 allowlist), 분석 자식(열기·헤더·키 조회·필터·산식·결과), 감사(별도 검산 및 교란 결과)다. 자식만 실행 계보 대상이다. 헤더만 읽기의 I/O는 버퍼 없는 한 바이트씩 첫 개행까지로 한정하며 읽기 수를 OS 추적으로 검증한다. 파싱 위해 파일 전체를 읽는 일과 값 필드를 명시적으로 조회하는 일은 구분한다. 새 자식에서 로컬 allowlist만 변환에 사용하고, 경로와 호출을 `strace -yy`로 별도 대조한다. 운영 캐시·이전 프로세스 선행 읽기·C 라이브러리의 mmap/네이티브 I/O·외부 원 실행은 별도 범위다. 불완전한 원장의 부재는 미확인이다.

봉인된 `truth.csv`는 16개 구조 정답과 짝별 변화 예측을 담는다. 공식 원표를 변환 코드와 다른 도구로 읽고, 값·라인·손계산 및 정확한 키·날짜를 고정 입력 커밋에 남긴 다음 관측을 연다. 시험 계측기는 별도 OS 추적, 값 정답은 별도 판독과 손계산을 비교한다. 발행판의 원표는 두 시점에서 동일 진단일만 비교하고, 교통 ZIP 경로에는 같은 작업을 실제 과거판이 있을 때 적용한다. 새 설정과 편집 사본은 연구자 통제로 표시한다.

## 공개 순서와 고정 판정

평가 단위는 각 run × 기록 방식 × 네 사실이다. 고정 질문 없이 URL만 보고 생기는 혼동을 피하기 위해 대상 경로·키·변경·발행 객체는 질문으로 이미 제시된다. 답은 아래의 자료만 순차 공개한 뒤 기계적으로 판정하며 실제 판독자 모집이나 무작위 시험은 없다.

| 구성 | 새로 공개하는 최상위 필드 | 고정 주 규칙 |
| --- | --- | --- |
| P0 | address, purpose | A·K·R·I 모두 미확인. 목적·URL에는 관측이 없다. |
| P1 | edition, distribution_sha256, publisher_file_sha256, candidate_sha256 | 발행판 anchor와 멤버가 고정되고 전체 해시가 있으면 I의 일치·불일치 판정. A·K·R은 미확인. |
| P2 | run_id, coverage, visible_paths, opens, key_reads, transform, output | P1의 I를 유지한다. 범위가 닫혀 있고 해당 경로·키 로그가 있으면 확인, 완전한 범위에서 부재하면 반증. R은 정확히 그 경로·키가 산식에 들어갔는지와 기록된 변환·원값에 질문의 국소 변경을 대입한다. 포괄범위·규칙·값이 하나라도 없으면 미확인이다. 짝 실행의 관측값이나 truth.csv는 이 구성에 노출하지 않는다. |

주 점수는 확인/반증/미확인을 독립 정답과 대조해 거짓 양성, 거짓 음성, 보류, 일치를 센다. 정답 미확인은 별도 수로 두고 분모에서 뺀다. 한 가지 추가 스트레스 시험을 같은 자료에 적용한다. P0 지름길은 URL+목적이 있으면 네 사실을 모두 확인으로, P1 지름길은 I를 네 사실에 복사, P2는 주 규칙을 유지한다. 실제 사람의 오판율이 아니라 두 추론 규칙의 행별 반례다. 추가 필드 수는 최상위 JSON 키 수 차이이며 바이트는 키 정렬·공백 없는 UTF-8 JSON(+개행 없음)의 전체/증분을 별도로 센다. CSV, 서명·색인·네트워크·추적 저장비는 이 단위와 다르다.
