## 1. 고정 질문과 연구 단위

Q1 템플릿에서 입력과 대안이 분리되는가, 언제 도입됐는가. Q2 네 계열 이상에서 역사적 결정 30개 이상을 재현 가능한 절차로 선정할 수 있는가. Q3 각 대안/선행 항목의 역할·취급·리뷰 추가는 무엇인가. Q4 먼 분야 원리가 실제로 얼마나 인용되는가. Q5 범용 LLM+웹+공개 코드 검색의 문서 항목 회수. Q6 목록/패턴만 사용한 회수. Q7 독립 문서 항목과 후보의 대조 및 정답 밖 효용. Q8 AF-RES-009의 충분성 가설 및 추가 가치 기각 조건에 대한 제한된 함의.

단위는 **한 역사적 제안의 결정 전 목적 문맥 × 후보 링크 × 제안된 사용 방식**이다. 정답은 저자/리뷰어가 실제 기록한 유한한 항목 집합이다. 적중률은 이 집합에 대한 회수율이며 세상 전체의 recall 또는 실제 설계 성공률이 아니다. 저자와 독립된 원문이 정답의 출처이며, 항목 분절·역할·일치·L/E/H/T는 연구자 코딩이다.

## 2. 계열과 포함·제외

주계열: Rust RFC, Python PEP, Swift Evolution, Kubernetes KEP. 보충 후보: Go proposal, TC39 proposal, IETF draft, 공개 ADR. 주계열에서 최소수 미달이 확인될 때만 SAMPLING의 순서로 보충하며 조용히 대체하지 않는다.

포함: 공개 원문 직접 열람; 고정 SHA 또는 명확한 판; 수락/거절/병합의 날짜를 공식 결정 기록 또는 Git commit/PR metadata로 확인; prior art/alternatives/rejected ideas/rationale의 명시적 비교 대상 3개 이상. 단순 참고문헌 전체를 gold로 만들지 않는다. 대안 절의 자체 설계도 독립 비교 항목이면 포함하되 원문 anchor를 항목 URL로 두고 외부 실체가 아님을 표시한다.

제외: 빈 템플릿, 결론만 있고 3개 미만 비교항목, 결정일 불명, 최신 문맥을 과거에 투사해야 하는 사례, 접근 실패, 비공개, 합성 문제, 이 연구의 다른 새 작업 결과. 초안의 병합을 언어 기능의 수락으로 표기하지 않는다. 결정 날짜의 의미를 decision_event에 명시한다.

5개 이상의 대체/철회/재설계 사례는 의도적 층이다. 제안 전체의 supersession과 명시적인 일부 결정 reversal은 구별하고 후속 문서의 정확한 변경 범위를 기록한다. 단지 더 새 제안이 있다는 이유로 superseded로 세지 않는다.

## 3. 접두부와 누설 방지

- 가능하면 최초 공개 draft 또는 수락 전 마지막 revision의 Summary/Abstract/Introduction/Motivation/Problem/Goals/Non-Goals만 사용한다. 최종판만 접근되면 최초판과 해당 절이 같음을 비교해야 한다. 불가능하면 제외한다.
- 연구자가 해당 절을 한국어 또는 영어로 요약한다. 원문 전문·사용자명·프로필을 저장하지 않으며 출처당 직접 인용은 25단어 이하. 필수 제약과 당시 이미 존재한 상황만 보존한다.
- 제안 번호·제목·저자·최종 해법·대안의 이름·후속 채택/대체 정보·정답으로 가는 링크는 접두부에서 제거한다. 문제의 생태계 이름과 필요한 시점은 보존한다. 제거가 필수 조건을 훼손하면 해당 부분은 별도 leakage_note로 기록하고 적중 민감도를 나눈다.
- 모든 접두부를 별도 묶음으로 먼저 커밋·push한다. 이후에만 gold 파일을 커밋한다. git merge-base --is-ancestor와 commit log로 순서를 확인한다.
- A 실행자는 fork_turns=none인 **새 문맥**으로 접두부와 BASELINE_RULES만 읽는다. 사례 원문·CASES·sampling 결과·sources·다른 baseline 결과를 읽지 않는다. 파일 시스템 강제 격리 또는 사전학습 기억 배제라고 주장하지 않는다.
- B도 별도 새 문맥으로 실행한다. A 실행자 재사용을 피한다. 불가능하면 오염된 기준선으로 명시한다. 사람 번역을 내부 모델이 대신한 차이를 보고한다.
- 해당 제안 자체, 동일 저장소의 문서, 동일 제안 번호를 인용한 페이지는 후보에서 제외한다. 검색 snippet에 노출된 경우도 exposure로 기록한다. 후보 제거와 실행자의 노출은 다른 사건이다.
- 결정 이후 자료는 post_decision=true로 표시하고 역사적으로 유효한 적중과 별도 집계한다. live 문서의 과거 존재를 증명 못 하면 date_unknown이며 엄격 역사 적중에 넣지 않는다. 현재판 검색 성공의 별도 수는 보존한다.
- 모델 사전학습에 포함된 유명 제안의 정답은 통제하지 못한다. 결과를 완전 blind 또는 실제 과거 검색 재현으로 부르지 않는다.

## 4. 기준선 실행 예산과 저장

B: AF-RES-009 (a)(f)의 awesome/AlternativeTo/OpenAlternative/SaaSHub, microservices.io/EIP/Azure/AWS patterns/Thoughtworks 목록을 허용. 목록에 연결된 원문은 검증만 가능하며 새 후보 발굴은 목록 경로가 있어야 한다. 사례당 <=25페이지 또는 <=20분; 후보 <=15. 적어도20사례, 가능하면30사례. B의 도구 번역자가 내부 모델임을 표기한다.

원 응답은 baseline 실행자가 생성한 문장을 raw_response에 그대로 보존한다. 검색 질의는 문자열·순서·UTC, open은 URL·UTC·결과·본문 확인 범위를 남긴다. 외부 원문 전체/검색결과 전문은 저장하지 않는다. 제약 때문에 후보가0인 실행도 실제 query/open 로그가 있어야 한다.

## 5. 정답 역할·항목·일치 규칙

역할 6개: 같은 목적 완성품 / 재사용 부품 / 같은 분야의 다른 설계 / 다른 언어·생태계 / 다른 분야 원리 / 표준·논문. 경계는 boundary_note에 이유와 대체 역할을 남긴다. 우선 분류는 문서가 가져오는 기능에 따른다. 같은 언어 문제의 다른 언어 문법은 **다른 언어·생태계**이며 먼 분야로 세지 않는다. 표준/논문은 발행 형식만으로 정하지 않고 인용된 역할이 명확한 경우 기능 역할을 우선한다. 이 규칙으로 논문의 메커니즘이 먼 분야이면 다른 분야 원리로 분류할 수 있다.

먼 분야의 보수적 경계: 비소프트웨어 원리, 또는 언어 설계↔분산 운영처럼 목적·객체·실패모드가 다른 소프트웨어 영역의 관계를 명시적으로 옮긴 경우. 단순 어원·비유는 term_only로 별도이며 결정에 대한 작동 근거와 합치지 않는다.

gold는 이름이 독립 비교 대상인 것을 하나씩 분절한다. 같은 문서의 같은 대상 반복은 한 항목, 서로 다른 설계 변형은 실제 별도 비교일 때만 별개. 같은 항목을 이름만 바꾼 후보는 공식 alias, 동일 repo+subsystem, DOI/표준 ID, 동일 명시 메커니즘으로 매칭한다. 프로젝트 이름만 같고 필요한 구성요소가 다르면 불일치. 일반 원리명만 같으면 불일치. 사례의 자체 대안은 후보가 제시한 구체 구조와 핵심 조건이 같을 때 structural_match로 기록하고 external_entity_hit와 분리한다. 매칭 사유·양쪽 구절 위치를 남긴다.

후속 더 나은 후보는 원래 gold에 소급 추가하지 않는다. 정답원 밖 유용 후보로 판정하고 확대 pool 민감도만 별도 보고한다. 같은 후보가 gold 여러 항목을 충족하면 명시된 복수 구조의 독립 근거가 있을 때만 각각 인정한다. 거절된 대안의 적중도 회수 적중이며 직접 적합 판정과 다르다.

## 6. AF-RES-004 판정축과 라벨 — 그대로 적용

L = ok / broken / missing.
E = supported / contradicted / unknown.
H = 각 접두부 필수조건별 pass / fail / unknown / not_in_scope.
T = not_needed / mapped / analogy_only / unknown.

우선순위: SURFACE_OR_CONSTRAINT_MISMATCH (결정적 알려진 위반) → INSUFFICIENT (결정적인 미확인) → CONDITIONAL_TRANSFER (좁은 대응·필요 연결·실패조건) → DIRECT_DOCUMENTED (명시 구성의 모든 필수조건에 긍정 근거). H_assessment_scope = proposed_configuration 또는 reference_design; runtime_observation=not_performed. 축을 합산하거나 unknown을0으로 바꾸지 않는다.

유용한 정답 밖 후보: 원문 링크가 열리고(L ok), 주장 지지(E supported), 필수 H에 fail/결정적 unknown이 없고, 해당 사용 방식이 DIRECT_DOCUMENTED 또는 구체 대응을 갖춘 CONDITIONAL_TRANSFER인 행. 단순 비슷함·소개 페이지·원문 미열람은 유용 수에 넣지 않는다. '더 나음'은 원문의 핵심 제약을 더 잘 만족한다는 대조가 있을 때만 쓴다.

깨진 링크는 명시적404/410 또는 확실한 다른 대상. timeout/403/도구차단은 inaccessible_unknown으로 분리; 가짜라고 단정하지 않는다. 근접 오답은 후보가 주목적에 가까우나 접두부의 특정 필수 제약을 위반한 경우. 참고 범위를 처음부터 좁힌 후보에 전체 제품 제약을 임의 적용하지 않는다.

## 7. 보고와 기각 경계

결과는 지정된 표1·2·3으로 시작한다. 사례/역할별 gold 분모, 상위<=15 후보, 미확인 확인방법을 표시한다. 역사 유효 적중, 사후 적중, 날짜 미확인, 동일저장소 누설을 분리한다. 불충분 gold의 선택편향을 해석에서 드러낸다.

AF-RES-009의 A/B 기각 조건은 **새 절차와 동등 이상**을 요구한다. 이번에는 새 절차가 없으므로 기준선 절대 회수 관측만으로 H1의 추가 가치 또는 제품 필요성을 기각/입증하지 않는다. Q4 빈도는 선정된 공개문서의 gold 항목 분포이며 실제 설계자 전체의 수요/효과가 아니다. H2 유지 가치는 측정하지 않는다.

반례 탐색: 빈 prior art, gold 밖 유용/우월 후보, 뒤집힌 이유를 사전 문맥으로 찾는가, 잘못된 링크, 실질 원리/장식 비유. 각 검색과 읽은 근거를 보존한다.

## 한계

이 계획은 공개자료의 과거 결정을 현재 검색으로 관측한다. 시간여행 검색·기억 제거·사람 효용·정답 완전성은 보장하지 않는다. 이 한계를 없애려고 기준을 사후 완화하지 않는다.
