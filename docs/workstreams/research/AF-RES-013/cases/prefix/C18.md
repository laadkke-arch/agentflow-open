# Design context — C18

Decision cutoff (UTC date): 2014-06-04

A Rust program sometimes handles data that cannot be interpreted as Unicode as a whole but still contains readable ASCII portions. Different portions of an HTTP message may use different encodings; a PDF can mix ASCII, UTF-16 strings, and raw binary data. Existing text and character values represent Unicode, which is not the right interpretation for all of this input.

Find language or library designs that let programmers express readable byte values and byte sequences in this situation. Preserve raw byte meaning rather than assuming the entire value is valid Unicode. Consider both individual bytes and sequences.
