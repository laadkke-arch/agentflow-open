# 결정 전 문제 문맥 — C30

Decision cutoff (UTC date): 2016-02-23

## 시점과 환경

2016년 초의 Swift 문자열 API 문제다. 직렬화, 파일 형식, 네트워크 메시지, 암호 관련 처리에서 문자열과 바이트 표현을 오가는 작업이 필요하다.

## 해결할 문제

당시 공개 API로 효율적이고 안전하게 버퍼에서 문자열을 만드는 길이 제한적이다. 빠른 경로는 특정 인코딩과 끝 표시 문자를 요구하므로, 길이가 따로 주어진 버퍼나 다른 종료 조건을 쓰는 형식에서는 복사하거나 매우 느린 반복 추가를 해야 한다. 문자열 안에 끝 표시와 같은 문자가 들어가는 경우도 처리하기 어렵다. 이미 알고 있는 길이를 다시 계산하는 낭비도 있다.

## 반드시 고려할 조건

바이트 또는 코드 단위 버퍼에서 문자열을 만들 때 성능과 Unicode 안전성을 함께 고려한다. 길이를 이미 아는 입력, 다른 종료 방식, 내부에 널 문자가 있는 데이터라는 문맥을 다룬다. 문제 해결을 위해 불필요한 전체 버퍼 복사나 느린 원소별 처리를 당연시하지 않는다.
