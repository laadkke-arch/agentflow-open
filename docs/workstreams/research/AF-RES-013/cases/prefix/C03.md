# Design problem input — C03

Cutoff date: 2019-04-16

## Context and purpose

Kubernetes developers use small immutable application images containing only their build output. These images lack shell and system tools needed to inspect a running workload. Operations staff may not be the application authors and need to attach a known debugging environment at troubleshooting time. The design question concerns API and node-agent support for that debugging experience, rather than implementing the end-user command.

## Required boundaries

- Inspect the namespaces and filesystems of individual running containers.
- Obtain debugging tools at troubleshooting time, without requiring prior pod/image configuration.
- Respect admission control and audit logging and make the debugging activity visible through the API.
- Support container runtimes through CRI, with reduced capabilities permitted.
- Do not require administrative access to the node or inherently modify the running application image.
- Make the complete debugging container specification inspectable by admission control.
