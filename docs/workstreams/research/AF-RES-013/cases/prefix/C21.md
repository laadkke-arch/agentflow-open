# Design context — C21

Decision cutoff (UTC date): 2014-07-30

Rust has accumulated multiple closure use cases and needs a coherent model. Programmers need control over inlining and dispatch, both borrowing and ownership-based capture of surrounding variables, and different ways of accessing a closure's environment: consuming it, reading it, or mutating it. Some closures escape their creating stack frame; many others only read or update local variables while that frame is active.

Find prior designs that cover these use cases without forcing every closure into a single capture or environment-access mode. Preserve both by-reference and by-value use cases and user control over optimization. Syntax, default capture mode, and the representation of callable values remain open design choices.
