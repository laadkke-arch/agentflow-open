# Design problem input — C06

Cutoff date: 2018-01-24

## Context and purpose

Containers in a Kubernetes pod share several namespaces, but process-namespace sharing was not defined when the original runtime lacked support. Some existing container images now depend on being PID 1. The design should allow process visibility and signalling within a pod, while retaining the behavior expected by existing images and making sharing configurable for each pod.

## Required boundaries

- Keep backwards compatibility for existing images that depend on PID 1 behavior.
- Configure process-namespace sharing at pod scope.
- Multiple separate shared PID groups per pod and per-container sharing configuration are out of scope.
- A general-purpose container init system is out of scope.

Find public existing approaches and references that can help this design. Explain the useful part and its conditions.
