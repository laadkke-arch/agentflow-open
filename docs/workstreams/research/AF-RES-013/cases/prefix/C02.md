# Design problem input — C02

Cutoff date: 2023-02-07

## Context and purpose

Kubernetes workloads may need a privileged identity inside a container, but an escape should not give the same privilege on the host. The design seeks to map workload user and group IDs to different host IDs, improve pod-to-host isolation, and use nonoverlapping mappings between pods where feasible. Capabilities granted inside a pod should not grant equivalent host capabilities. The broader goal is incremental hardening against runtime and kernel vulnerabilities.

## Required boundaries

- A privileged identity inside the workload must correspond to an unprivileged identity on the host.
- Consider both user and group identities and pod-scoped capabilities.
- Running the kubelet or container runtime itself without privilege is outside this decision.

Find public existing approaches and references that can help this design. Explain the useful part and its conditions.
