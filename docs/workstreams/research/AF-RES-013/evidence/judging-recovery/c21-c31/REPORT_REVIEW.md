# RESULT 최종 연구해석 검토 — 내부 별도 검토

주요 인과·제품 우위·수요·전수 회수의 과대주장은 발견하지 못했다. 수치와 구조를 재계산했고 **날짜 분류 일관성 1건**, **분류 축 이름 1건**의 수정을 권고했다. root는 두 제안을 수용했다. 이 기록은 정정 전 snapshot에 대한 검토이며, 수정된 파일의 최종 해시·표 재생성·원격 본문 대조는 root QA가 확인한다.

판정자는 GPT-6 Astra Pro의 **내부 별도 검토**다. 사람·다른 모델의 검토가 아니다. 새 검색이나 기준선 재실행을 하지 않았으며, 이 폴더의 REPORT_REVIEW 두 파일만 작성했다.

## 1. 발견사항과 조치

### RR2131-F01 — C08 A1의 날짜 필드와 역사 적격성

C08 A1은 주 문서의1999년 표지·grammar를 확인해 `date_status=pre_decision`을 보존했다. 그러나 상세 semantics는 날짜를 확정하지 못한 Haskell1.3 mirror로 확인하여 `nongold_historical_useful=false`로 처리했다. 따라서 현재 `pre_decision ∩ nongold_useful`을 단순 계산하면84행인 반면, 더 엄격한 전체 근거 기준의 역사 유용 수는83행이다. 집계 스크립트의 산술 오류가 아니라 **하나의 날짜 필드에 서로 다른 확인 단위가 남은 문제**다.

C25 A1 등에서 프로젝트 존재와 실제 주장에 해당하는 본문의 시점을 구별한 것처럼, C08 A1도 원 pre 값을 `original_date_status`에 남기고 최종 `date_status=unknown`으로 일관화할 것을 권고했다. root는 별도 정정 커밋·집계·결과표 재생성을 수용했다. 예상 변화는 A의 날짜 분포104/22/78→103/22/79, C08 표의 날짜unknown0→1이다. A 역사gold16, 날짜무관23, 정답밖 유용170, 역사 유용83 및 B의 값은 그대로다.

근거: `JUDGMENTS.json` C08/A/1의 `date_assessment_note`, `transfer_mapping`, `remaining_check`; 같은 파일 C25/A/1의 원 주장·판 날짜 분리.

### RR2131-F02 — 외부 실체와 재사용 부품의 축 이름

Q8의 ‘부품 외부 대상의 A 역사 적중8/30’은 역할의 재사용 부품17과 종류의 외부 실체30을 혼동하게 할 수 있다. 수치8/30은 맞으며 **‘외부 실체의 A 역사 적중8/30’**으로 한정하면 된다. root는 해당 문구와 AF009의 기각방향 문구를 수정했다고 통보했다. §3.1의 역할/종류는 별개 축이라는 설명은 유지해야 한다.

## 4. 재계산 기록과 한계

정정 전 snapshot의 수치는 A 후보204·역사gold16·날짜무관23·nongold178·유용170·역사유용83, B138·5·14·120·109·30이다. label은 DIRECT3·CONDITIONAL318·INSUFFICIENT21/342다. scoped-out 조건을 가진 행78, 모든 조건을 scope 밖으로 둔 행0, 교차검토36행을 확인했다. 표1 수치 불일치는0이다. 정확 해시·검토 필드·발견사항의 root 처리 상태는 `REPORT_REVIEW.json`에 남겼다.

이번 검토는 전342개 외부 원문의 새로운 전수 열람이 아니다. 보존기록·현재 결과·기존 직접 열람과 원 고정 AF004/AF009 기준을 대조한 보고 검토다. D4 적용·사용자 반응·통계 유의성·최종 원격 동일성을 새로 검증하지 않았다. root가 날짜1행을 정정한 뒤 달라지는 날짜 집계와 본문 연결 SHA를 마지막으로 확인해야 한다.
