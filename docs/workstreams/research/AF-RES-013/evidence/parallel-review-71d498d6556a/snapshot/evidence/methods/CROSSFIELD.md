# 독립된 인용 정답원으로 검색을 평가할 때의 비교

작성 범위: AF-RES-013의 사례 외 방법론 조사. 내부 별도 검토자가 공개 원문을 읽고 종합했다. 아래의 논문 실험은 원저자의 실험이며 이번 작업에서 재실행한 결과가 아니다. 설계 사례의 정답, 실제 기준선 적중 수, 다른 분야 인용 비율을 이 파일에서 산출하지 않는다.

## 1. 답과 가장 중요한 구분

**저자·리뷰어·심사관이 남긴 인용은 작업자와 독립된 관측 정답이지만, 유용한 선행 사례 전체의 목록은 아니다.** 따라서 AF-RES-013이 직접 측정하는 것은 ‘해당 문서에 기록된 항목을 다시 찾는 정도’다. 기록되지 않은 후보의 유용성, 실제 사용자의 판단 개선, 인용한 문서가 모델 답변의 원인이었는지는 각각 추가 증거가 필요한 별도 질문이다. 이는 불완전 판정의 문제([M01](https://tsapps.nist.gov/publication/get_pdf.cfm?pub_id=150469)), 테스트 컬렉션과 사용자 효용의 구분([M03](https://informationr.net/ir/18-2/paper582.html)), 인용의 지지와 모델의 실제 의존성 구분([M14](https://staff.fnwi.uva.nl/m.derijke/wp-content/papercite-data/pdf/wallat-2025-correctness.pdf))을 이 과제에 적용한 연구자 해석이다.

반대로 ‘정답이 불완전하므로 평가할 수 없다’는 결론도 과도하다. NTCIR-4는 심사관 인용에 수작업 검색과 시스템 풀을 더해 판정 범위를 넓혔고, 풀링 깊이를 다룬 별도 연구는 시험한 조건에서 예상했던 모든 편향이 나타나지는 않았다고 보고했다. 필요한 조치는 관측 정답에 대한 점수와 정답원 밖 후보의 판정을 분리하고, 특정 누락이 실제로 어떤 결론을 바꾸는지 확인하는 것이다. [M07](https://research.nii.ac.jp/ntcir/workshop/OnlineProceedings4/PATENT/NTCIR4-OV-PATENT-FujiiA.pdf), [M16](https://codalism.com/research/papers/wmz10_evia.pdf)

### 2.1 인용 정답의 불완전성에 대한 증거의 크기

CLEF-IP의 주최 측은 인용 기반 평가와 별도의 전문가 평가를 비교했다. 후자는 전문가 7명이 주제 12개에 대해 상위 20개 결과를 평가한 범위이며, 자동 인용 평가의 전체 주제 묶음과 전문가가 선택한 소수 주제의 수동 평가 사이에서 시스템 순위 관계가 달라졌다. 비교에서 주제 범위도 달라지므로 정답 보완만의 인과 효과로 읽으면 안 된다. 같은 논문은 자동 추출 인용34건 중13건을 전문가가 비관련으로 판단했다는 직접 불일치도 보고한다. 이 관측은 인용 정답과 추가 판정이 언제나 같은 결론을 내지 않는다는 실증 사례다. **12개 특허 주제의 차이가 31개 설계 사례에서 어느 크기로 재현될지는 여기서 알 수 없다.** [M05](https://ceur-ws.org/Vol-1175/CLEF2009wn-CLEFIP-RodaEt2009.pdf)

NTCIR-4 본 실험의 34개 주제는 심사관 인용뿐 아니라 전문가 검색과 111개 제출 run 가운데30개 run의 풀을 사용했다. 추가69개 주제는 인용 기반으로 구성했으며, 그중 중복/컬렉션 밖 인용2개를 빼고 최종101개 주제를 평가했다. 따라서 ‘독립 정답’이라는 이름만 같아도 판정 범위와 재현성은 다르며, 추가 후보 판정 여부를 기록해야 한다. [M07](https://research.nii.ac.jp/ntcir/workshop/OnlineProceedings4/PATENT/NTCIR4-OV-PATENT-FujiiA.pdf)

학술 종합 검토가 조사한 지역 인용 추천 접근 중 15/17은 실제 인용을 다시 맞히는 평가에 의존했다. 이 빈도는 해당 검토의 대상 접근에만 적용되며, 논문 인용 전체나 소프트웨어 설계 문서의 비율이 아니다. [M12](https://link.springer.com/article/10.1007/s00799-020-00288-2)

AF-RES-013에서 ‘정답원이 불완전하다’는 증거의 크기는 실제로 열린 정답원 밖 후보 중 **기존 L/E/H 판정을 통과한 수 / 별도로 판정한 정답원 밖 후보 수**, 그리고 그 후보가 나온 **사례 수 / 실행한 사례 수**로 보고하는 것이 적절하다. 더 좋은 후보인지 여부는 단순 누락과 다른 주장이다. 위 문헌은 그런 검사를 해야 할 이유를 제공하며, 이번 실험에서 발견한 후보 수를 대신하지 않는다.

|---|---|---|---|

이 표는 M03·M06·M07·M12에서 확인한 평가 목적의 차이를 연구자 판단으로 대응시킨 것이다. 설계자나 리뷰어를 새로 인터뷰했다는 뜻은 아니다.

## 4. 프로토콜에 적용할 사항: 기존 판정을 바꾸지 않는다

### 4.1 적중과 유용성, 채택과 거절

항목 일치 여부는 문서 저자가 무엇을 고려했는지 재현하는 척도다. **거절된 대안을 정확히 찾은 것도 항목 적중일 수 있다.** 그러나 그 대안을 해당 제약에서 사용할 수 있다고 추천하면 별도의 제약 위반 문제가 된다. 같은 후보에 대해 항목 ID 일치와 AF-RES-004의 L/E/H/T 및 라벨을 별도 필드로 남겨야 이 둘이 섞이지 않는다. 정답원 밖 후보도 이 기존 판정으로 평가하되 정답 적중 분자에는 넣지 않는다.

M01의 bpref, M04의 풀 편향 보정, 특허의 A/B 관련성 등은 기존 축을 대체할 새 채점 규칙으로 제안하지 않는다. 여기서는 **현재 점수의 해석 범위를 좁히는 근거**로 사용한다. [M01](https://tsapps.nist.gov/publication/get_pdf.cfm?pub_id=150469), [M04](https://codalism.com/research/papers/wp09_sigir_pp.pdf)

### 4.2 시간과 누설의 구분

실행자는 다음을 구분해야 한다. (1) 정답·대안 절이 접두부에 직접 남음, (2) 같은 문서 또는 같은 제안 번호를 참조하는 페이지가 결과에 나타남, (3) 결정 후 작성·수정된 자료가 후보를 뒷받침함, (4) 모델이 과거 학습에서 내용을 기억했을 가능성. 앞의 세 가지는 파일·페이지 기록으로 일부 검사할 수 있지만, 네 번째는 새 하위 에이전트를 만들었다는 사실만으로 해결되지 않는다. M02의 시간·특성·표본 의존성 구분과 M06의 최종 명세서 문제에 근거한 적용이다. [M02](https://arxiv.org/pdf/2207.07048), [M06](https://ceur-ws.org/Vol-1175/CLEF2009wn-CLEFIP-LopezEt2009.pdf)

현재 열리는 설명 페이지와 아이디어의 최초 공개 시점도 분리해야 한다. 아이디어가 오래되었더라도 이번 실행에서 그 사실을 확인하지 못했다면 자동으로 역사적 적중으로 올리지 않는다. 이미 결정 전 존재한 아이디어를 현재 페이지로 확인한 것인지, 당시에는 없던 후보인지, 날짜를 확인하지 못한 것인지 기록해야 한다. 이는 역사 재현의 엄격한 증명과 현재 웹에서의 검색 성능이 서로 다른 질문이기 때문이다.

### 4.3 점수·반복성의 적용 한계

판정하지 않은 후보를 전부 무용한 것으로 간주하면 혁신적인 검색 결과를 과소평가할 수 있다. 그렇다고 미판정 문서를 지우는 방식도 항상 공정하지 않다. 공통 주제를 추가 판정하는 보정은 그 판정이 실제로 있을 때만 가능하다. [M04](https://codalism.com/research/papers/wp09_sigir_pp.pdf)

실행이 확률적인 경우 사례 간 편차와 같은 사례의 반복 편차가 다르다. M15는 비결정적 검색 시스템에서 한 번의 인스턴스 비교가 다른 실행에서 달라질 수 있음을 보였다. 이 연구의 단회 LLM 실행은 예산 내 관측으로 해석해야 하며 모델·검색 서비스 일반 성능에 대한 분산 추정으로 쓰지 않는다. [M15](https://codalism.com/research/papers/jwsdc14_sigir.pdf)

M16은 풀링 깊이뿐 아니라 평가 깊이가 결과에 영향을 주며, 조사한 조건에서는 일부 예상한 편향이 나타나지 않았다고 보고했다. 이는 모든 인용 정답을 무효로 취급하는 주장에 대한 반례다. 동시에 그 실험은 희소한 설계 문서 인용의 공정성을 직접 보장하지 않는다. [M16](https://codalism.com/research/papers/wmz10_evia.pdf)

### 4.4 생성형 검색에서 링크 확인 이상의 검사

CiteEval은 인용문 하나의 함의 여부뿐 아니라 검색된 전체 문맥, 질문·답변, 불필요하거나 오해를 부르는 인용 등을 평가한다. 링크가 존재하고 관련 문구가 있다고 해서 답변이 충분히 입증되지는 않는다. [M13](https://aclanthology.org/2025.acl-long.1574.pdf)

M14는 답을 지지하는 인용의 정확성과 모델이 그 인용에 실제로 의존했는지를 구별했다. 이 결과를 AF-RES-013에 적용하면, 원문 확인은 후보 이유의 근거를 검사할 수 있지만 모델의 내부 인과 경로를 증명할 수 없다. 이 문헌의 특정 모델 오류율을 이번 기준선의 오류율로 전용하지 않는다. [M14](https://staff.fnwi.uva.nl/m.derijke/wp-content/papercite-data/pdf/wallat-2025-correctness.pdf)

## 6. 자료 수와 조사 범위

원문 본문을 확인한 사례 외 자료는 **16개: 논문·종합 논문 14개, 공식 과제·컬렉션 설명 2개**다. 출처 사이트는 10개이며 단일 사이트 최다 3개다. 방법론 자료는 M01–M04·M15–M16의 6개, 다른 분야 원문은 특허 M05–M08·법률 M09–M10·학술 M11–M12, 새 생성형 인용 평가 논문은 M13–M14다. 자료 종류가 겹치는 경우에도 문서 자체는 한 번만 센다.

`sources.json`에는 실제 연 URL, 본문을 확인한 절, 판, 확인 내용과 한계가 있다. `excluded`의 접근 실패·차단·목록·메타데이터 자료는 위 16개에 포함하지 않는다. M02는 2022년 arXiv v1이며 접근하지 못한 2023년 출판판의 수치를 섞지 않았다. `SEARCH_LOG.json`에는 20개 검색 질의와 후속 열람 연결을 남겼다.

## 7. 한계

- 이 파일은 한 내부 별도 검토자의 원문 조사와 방법론 적용이다. 사람 평가나 다른 모델 평가로 표현하지 않는다.
- 원저자의 실험을 재실행하지 않았다. 모두 D1 자료이며 이번 기준선의 D3-run 또는 D4 증거가 아니다.
- 다른 분야의 인용 편향이 설계 문서에도 있을 수 있다는 대응은 연구자 해석이다. 같은 크기·방향의 편향을 관측했다고 주장하지 않는다.
- 확인한 문헌만으로 실제 설계자의 타 분야 인용 빈도, 기준선 A/B의 충분성, 정답원 밖 후보가 실제 결정을 개선한 정도를 계산할 수 없다.
- 출처 기록 시각은 명시된 짧은 본문 열람 묶음의 완료 시각이며 요청마다 자동 계측한 시각이 아니다. 그 정밀도를 넘는 실행 속도 비교에 사용하지 않는다.
