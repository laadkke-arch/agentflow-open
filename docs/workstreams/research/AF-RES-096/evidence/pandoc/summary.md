# Pandoc 층 사전 경로 판정 요약

작성 기준: 공개 답·댓글·채택 표지는 아직 열지 않았다. 신규 R0와 노출 범위는 ① 원격 커밋 `abf2bc2ac9303cb96e6109eba107684e5f858a42`에서 고정됐다. 아래 판정은 원 사용자 환경의 실행 성공이 아니라 고정 비교판 문서와 구현에 근거한 요구 충족 판정이다. P3/P4의 구체 변환안은 연구자가 합성했으며 아직 실행하지 않았다.

P1의 ‘반박’은 원 시도의 명시된 연결이 끊긴다는 뜻이며, 가능한 모든 해결책이 없다는 주장이 아니다. P4의 기존 named-filter 연결도 깨져 있지만, 최종 반환한 별도 구체안이 같은 요구를 문서적으로 충족하므로 최종 경로 판정은 완결이다. 최종 반환 및 조건별 근거의 원 행은 각 `evidence/routes/P*-*/judgment.json`이다.

Pandoc 모집은 H1 원 모집 31/31건의 생성 메타데이터와 earliest-body 리비전 메타데이터를 확보했고, 본문을 순차 확인해 첫 네 건에서 경계 3건과 주 도구 대조 1건을 채웠다. 실제 읽은 R0는 10건이며 외부 하한에는 선택 R0 4건만 산입한다. H2 확장은 없었다. jq 층 및 선행 088/092 제외 목록과 선택 ID 중복은 없다. 자세한 모집 분모와 원순번은 `frame.csv` 및 `report.md`다.

## 실제 비용과 기록 검산

각 경로는 검색 2회 뒤 노출 파일 네 개를 순서대로 모두 열었다. 8경로의 본문 접근은 **32/32회**, 실패 0회, 재시도 0회, 초과 접근 0회, 미노출 파일 이용 0건이다. 반환 링크는 경로당 최대 두 개이며, 최종 조건 근거와 반환 절 모두 해당 경로에서 이미 연 파일과 별도 section 로그 안에 있다. B의 인접 두 자리는 3쌍 모두 차 있었으므로 인접 본문 열람은 6/6자리다. 대조 P2는 양쪽 같은 네 파일이다. 사전 구축 원문 다운로드 비용은 이 32회와 별도다.

`route-audit.json`은 원 exposure/access/judgment 행에서 파일 순서, 과금, 성공 여부, 반환 상한, 미개봉 근거, 반환 절의 실제 로그 포함, 마지막 접근보다 이른 완료 시각을 다시 검사한 결과다. 총 위반은 0이며 P3/P4 최종 메타데이터 보완 시각은 `2026-11-23T18:25:06.526715+00:00`이다. 문서 판정을 검산한 것이므로 실행 결과의 참·거짓을 검증한 기록으로 읽으면 안 된다.

고유 공식 파일 16개를 실제 열었다. `sources-note.jsonl`은 파일별 주소·고정판·접근 UTC·해시·읽은 절·직접 확인 내용·한계를 기록한다. 그중 하한에 보수적으로 적합하다고 표시한 자료는 주 도구 매뉴얼/구현 5개, 인접 매뉴얼/구현 4개, 상류 원 시험 2개로 **11개**다. 나머지 5개는 잘못된 출력 형식이나 질문과 다른 문서 경로 등으로 실제 슬롯을 소모했으나 필수 자료량에는 보태지 않았다. 같은 프로젝트·판의 여러 파일과 여러 경로의 반복 열람은 독립 성공 사건 여러 건으로 계산하지 않는다.

## 초기 판정 보존과 최종 공통 검토

| 요청·경로 | 초기 판정 | 최종 판정 | 같은 요구 안에서 닫은 연결 |
|---|---|---|---|
|P3-A|부분|완결|R 청크 결과를 -V 옵션으로 건네는 시점이 빈 후보 대신, 원 R 대입에 raw 형식 표지를 추가한다. 원 생산·평가 단계가 유지된다.|
|P3-B|부분|완결|A와 같은 raw 형식 표지다. B에서 본 PDF 전용 처리나 다른 경로의 구현을 근거로 쓰지 않는다.|
|P4-B|반박|완결|기존 CodeBlock 필터의 입력 불일치와 별개로, 이미 노출된 주 도구 RawBlock 예제에 원 preamble을 공급한다.|
|P4-A|부분|완결|원 libraries/global tikzset를 공식 예제의 별도 컴파일 문서에 보존하고 SVG 파일 전달까지 명시한다.|

수정 전 여덟 판정은 `pre-review/`에 원바이트와 해시로 보존했고, 수정 이유·시각은 `evaluation-review.json`에 남겼다. 새 외부 파일, 새 검색, 추가 본문 시도, 새로운 명시조건, 공개 정답은 추가하지 않았다. 구체안과 근거 절은 `documentary-syntheses.md`, P4 Lua 합성안은 `p4-raw-tikz.lua`다. 본문에서 주어진 한 입력을 넘어 임의의 Markdown delimiter/YAML 문자열이나 임의의 TikZ 문서까지 성공을 일반화하지 않는다.

한 연구자가 양쪽을 읽었다. 최초 경로 순서는 P1 A→B, P2 B→A, P3 A→B, P4 B→A였고 각 초기 판정을 다음 경로 전에 작성했다. **최종 P3/P4 검토는 여덟 경로를 모두 본 후에 진행되어 교차 기억이 있었다.** 최종안에 쓰는 절은 각 경로에서 별도로 재열람·기록했고 반대 경로에만 노출된 파일을 근거로 들이지 않았지만, 이것만으로 기억 오염을 제거하지는 못한다. 이 결과는 독립적으로 가려진 두 연구자의 최초 발견률 비교가 아니며 최종 공통 검토가 실제 발견 순서의 차이를 지울 수 있다. 최초 판정과 최종 판정을 함께 보고해야 한다.

## 관점별 반환과 되물을 것

- 질문자에게: P1은 upstream 역할 부여와 downstream 속성 손실 두 링크가 실패 위치를 설명한다. P2는 [공식 custom styles 절](https://github.com/jgm/pandoc/blob/8a72b8449ddccd84fcdffc1a09ae18c4baaca32a/MANUAL.txt) 하나와 ‘reference.docx의 VE는 paragraph style인가 character style인가?’라는 질문이 먼저다. P3는 같은 매뉴얼의 YAML/raw-format/template 절을 이어 읽고 구체 wrapper를 적용한다. P4는 [공식 Lua TikZ 예제](https://github.com/jgm/pandoc/blob/8a72b8449ddccd84fcdffc1a09ae18c4baaca32a/doc/lua-filters.md)와 매뉴얼의 raw_tex/embed-resources 설명 두 링크로 반환한다.
- 도구 유지관리자에게: P1은 Asciidoctor role emission 시험과 Pandoc reader의 속성 소거를 분리해 재현한다. P2는 style.xml의 실제 유형과 이름이 있어야 원인을 좁힐 수 있다. P3/P4는 고정판에서 합성안을 실행한 뒤 사용자판 차이를 비교한다.
- 검색 결과 편집자에게: 인접 자리 배정은 P1의 경계 진단을 늘렸지만 이 표본에서는 B만 완결을 만들지 못했다. P2의 Powerpoint 구현과 P3의 MediaWiki fixture가 높은 어휘 점수만으로 자리를 소비한 사실을 보존해야 한다. 특정 결과를 보고 토큰이나 후보를 고쳐서 이 사전 승패를 다시 계산하지 않는다.

## 이후 최소 실행 — 아직 미실시

P1은 정확한 원 reference.docx 및 role/name 매핑을 받아 AsciiDoc→DocBook→Pandoc native→DOCX의 속성을 비교한다. P2는 원 파일의 `word/styles.xml`에서 VE의 `w:type`, `w:name`, `w:styleId`와 생성 파일의 중복을 확인한다. 원 파일이 없으므로 두 검사는 현재 미실시다.

P3는 원 Rmd/template과 2.11.2, 3.1.11, 비교판 3.6을 각각 준비하고 원본·raw wrapper 적용본을 렌더링한다. 실제 knitr 중간 Markdown의 signature scalar와 최종 HTML table 안의 의도하지 않은 br 수를 비교한다. 사용자 전체 환경과 정확한 중간 파일이 없어 현재 미실시이며, 일반 동적 문자열까지 검증됐다고 주장하지 않는다.

P4는 R0의 완전한 `example.tex`와 여기 합성 필터를 입력으로 삼는다. 명령은 `documentary-syntheses.md`에 고정했다. 먼저 `pandoc --from=latex+raw_tex --to=native example.tex`로 실제 RawBlock 경계를 확인하고, 그다음 본 변환을 실행해 원 네 상태·라벨·화살표와 SVG 내장 여부를 대조한다. `pdflatex`, `pdf2svg`, 원 TeX 라이브러리 설치를 성공으로 가정하지 않는다. 실제 실행 전에 이 문서적 완결을 원 작성자의 성공으로 바꿔 쓰면 안 된다.
