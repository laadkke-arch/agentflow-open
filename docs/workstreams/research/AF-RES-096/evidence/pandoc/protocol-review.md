# 사전 protocol 검토 · Pandoc 담당

확인: 2026-11-23 UTC. 읽은 파일은 `protocol.json`, `corpus-plan.json`, `SCOPE.md`이며, 기존 모집 단계에서 직접 읽었던 R0 기억과 대조했다. corpus 본문·검색 결과·답·댓글은 열지 않았다. 이 검토는 사전규칙 검토이며 사후 정답 또는 경로 평가가 아니다.

## 조정 권고

1. **P4 인접 구현 경로의 범위 누락 가능성 — 봉인 전 metadata 확인 필요.** R0가 지명한 파일은 `pandoc-ext/diagram`의 `_extensions/diagram/diagram.lua`이다. 현재 DG include는 `README.md`, 루트 `diagram.lua`, `test/*`, `tests/*`뿐이다. 고정 SHA `023b31752cb5b63cd8bab828b268fa60ebd16d0c`에서 구현도 그 하위 경로에 있다면, 실제 요청이 직접 지명한 구현을 후보 범위에서 제외하게 된다. 고정 tree의 **경로 metadata만** 확인하고, 필요하면 `_extensions/diagram/*.lua` 및 호출 설정 파일 경로를 사전 목록에 추가한다. 현재 검토에서는 해당 tree나 본문을 열지 않았으므로 실제 누락 여부는 미확인이다. 후보 범위 변경은 봉인 전 원래값/시각/이유를 기록한다.
2. **Pandoc `test/writer*.html` 제외 근거를 고정할 것.** 원 시험/기대출력을 후보로 포함한다고 했으나 이 패턴만 제외하는 이유가 plan에 없다. 문서 미러와 실제 기대출력은 같지 않다. 전체 writer fixture가 의도적으로 빠지면 주 도구 네 자리와 B가 보존하는 두 자리의 비교에 영향을 줄 수 있다. metadata 차원에서 중복자료라면 무엇의 중복인지 적고, 그렇지 않으면 다른 텍스트 기대출력과 동일 포함 원칙을 적용하는 편이 재현 가능하다. 이는 파일 내용을 읽고 발견한 결론이 아니라 사전범위 일관성 지적이다.
3. **정규화 매치와 원문 발췌 offset 연결의 예외 규칙을 추가할 것.** 점수는 NFKC/casefold 토큰이고 발췌 anchor는 원문 case-insensitive boundary이다. NFKC에서만 동일해지는 문자나 casefold 길이 변환은 점수가 양수인데 원문 anchor를 못 찾을 수 있다. normalized-to-original offset mapping을 쓰거나, anchor 미발견 시 0 offset+명시 경고처럼 결정적인 규칙을 사전에 고정한다. 의미 있는 파일만 유리하게 고치는 사후 수동 탐색은 금지한다.

## 현재 판단

규칙은 사용자 Q1–Q5와 대체로 일치한다. 가장 먼저 확인할 것은 **R0가 직접 지명한 DG 구현 경로가 corpus include에 실제 포함되는지**다. 그 확인 전에는 P4의 인접 원문 노출 정책이 완비됐다고 볼 수 없다. 이 검토의 지적만으로 어느 경로의 성공/실패도 예측값에서 관측값으로 승격하지 않는다.
