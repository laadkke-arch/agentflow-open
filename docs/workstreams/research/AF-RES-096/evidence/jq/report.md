## 같은 질문을 유지하기 위한 고정 사항

`selected.json`은 입력·기대 출력·명시 조건·원문 짧은 인용·사용자판 미확인·두 질의 토큰 후보·긍정/손실 예상·A/B 순서를 가진다. J1·J3은 A→B, J2·J4는 B→A다. jq 비교판은 루트가 지정한 1.7.1이며, 인접 비교판·실제 검색 파일 목록은 루트의 protocol 봉인에서 고정한다. 아직 도구 매뉴얼·소스·실험 순위는 열지 않았다.

- J1의 JSON은 일부만 제시됐고 두 번 적힌 명령이 동일한데 서로 다른 실패 출력이 붙는다. 이 자료로 원 명령 실행 성공을 확인했다고 쓸 수 없다.
- J2는 원문 기대 출력에 start/end 숫자가 있지만 입력 예시에 offset 필드가 없다. 제목·작곡자에 해당하는 primary/secondary의 매핑과 접미사도 예시 사이에 다르다. 이 값을 추정해 완결로 올리지 않는다.
- J3의 조건 중 'jq 안에서'를 B에 유리하게 지우지 않는다. 원 OverpassQL 질의가 없어 생산 구조를 정확히 재현했다고 말할 수 없다.
- J4의 원문은 일관된 JSON을 제공하지 않는다. 중첩 괄호와 빈 값 모두 명시 조건이며, grep의 행 선택을 값 내부 괄호 추출로 오인하지 않는다.
