# AF-RES-096 사용자 요구 대조 검토

검토 기준: 사용자 전체 지시, ②봉인 `d03ca37daf0c43688c68bc39417d84a9b84803e9`, 모집·경로·사후·Q7 원장 및 독립 감사 기록. 통합 RESULT/SELF_CHECK/cards의 생성 완료를 기다리거나 내용을 선행 승인한 검토가 아니다. 코드를 실행하거나 봉인 파일을 수정하지 않았다. 검토자 `jq_recruit`는 jq 모집·평가에 참여했으므로 자기 기여분까지 맹검 독립 재판정했다고 주장하지 않는다.

## 1. 모집·열람·자료·사건의 분모를 섞지 않는다

**확인:** jq 메타 모집45 + pandoc 메타 모집31 = **76건**. 최초 보존 revision은 두 층 모두 확보했지만 연구자가 실제 읽은 R0는 jq45 + pandoc10 = **55건**이다. Pandoc 11–31은 retrieval/metadata만 있고 사람 역할의 연구자 본문 열람은 없다. 모집 슬롯은 양 태그의 첫 3경계+첫1대조로 **8/8 충족**, 서로 다른 질문 사건8, 경계6/대조2이며 H2 확장은0이다. 현재 태그 기준 모집과 grace-period 이전 최초 입력 미확인도 유지해야 한다.

**과장 위험:** “76개 본문을 모두 직접 읽고 선정했다”, “새 요청에서 경계가 나타날 확률은6/8”, “55개 무작위표본의 비율”은 성립하지 않는다. 3+1 정원 선발이고 정원 뒤 열람도 태그별로 비대칭이다. 모집틀76, 직접R0열람55, 선정8을 각각 표시하고 경계 빈도 추정으로 바꾸지 않는다. 별도로 자료 감사의 “하한 산입 corpus파일에 대한 실제 접근55회”는 우연히 같은 숫자인 **다른 분모**이다.

**자료 하한:** `source-count-audit.md`/`evidence/source-counts.json`은 고유1차자료46 = R0 8 + 주 매뉴얼/구현10 + 인접 매뉴얼/구현10 + 별개 원시험4 + Sphinx7 + GDAL/PROJ7을 보고한다. 현재 원장 기준 24자료 하한은 채워져 있다. 원시험4는 jq·Asciidoctor **두 저작 계보의 네 파일**이며 네 독립 실행/성공 사건이 아니다. Q7·사후 답·댓글·반복절·자체 실행으로 신규 질문 사건8을 늘리지 않는다.

## 2. 관측하지 못한 A만 손실과 인접성의 종류를 정확히 쓴다

**확인:** 사전 경계6쌍은 A만0/B만0/양쪽4/어느쪽도아님2이며 대조2쌍은 양쪽1/어느쪽도아님1이다. B의 경계 인접원문은 노출6/6·열람6/6·반환3/6, 완결 변경0/6이다. 불일치쌍0이므로 그 안의 승률은 **산출 불가**다. `displacement-audit.md`는 밀려난 A 3·4위 **12/12자리**를 살펴 A만 완결 **0/6**을 보고한다.

**필수 반례 탐색의 남은 결손:** 사용자가 요청한 “필수 주 도구 파일이 밀려나 A만 성공한 실제 사례”는 **찾지 못했다**. 탐색12자리와 미관측0/6을 정직하게 쓰면 된다. 이것을 “넓혀도 손실이 없다”로 일반화하거나 사후 사례를 끼워 넣어 충족시키면 안 된다. J4-B는 A가 반환한 Oniguruma 없는 build의 실패 경고를 잃었지만 이는 **설명·반대조건의 손실**이며 관측된 완결 패배는 아니다.

**인접 도구 필요와 인접 원문 필요도 구별:** P4의 외부 TeX/PDF/SVG 호출, Q7의 dot/grid 경계는 외부 연산·자원이 필요한 목표를 보여 준다. 같은 요구를 주 도구 매뉴얼에서 찾을 수 있었다면 그것만으로 B의 인접자료 슬롯이 필수였다는 증거는 아니다. J3/P3의 채택 답이 같은 주 도구 안의 다른 절을 사용한 사실과 J2의 긍정댓글·offset 결손 불일치를 함께 드러내야 한다.

**비교 가능성 표현:** 16경로·32검색·64본문 시도·초과0이라는 기술적 회계 통과와 독립·맹검 효과 추정은 다르다. 동일 연구자의 기억노출, Pandoc 후반의 늦은 판정 보완/절 재열람, 큰 매뉴얼이 양쪽 상위 두 자리에 남는 구조를 최종 결과에서 감추지 않는다. 동일 파일시도 수는 동일 bytes·시간·추론 노동을 뜻하지 않는다. J4/P3의 “문서 기반 구체 합성”을 “완성 해법 snippet을 검색으로 발견”으로 서술하지 않는다.

## 3. Q7 교정과 실행·계약 완료의 경계를 남긴다

**Q7:** 원문·설정·상류 기대값을 대조한 교정 자료14개/목표5개/프로젝트3계보이다. 신규 모집0·A/B경로0·발견능력 분모0이므로 새 질문에서 같은 자료를 찾는 성능으로 외삽할 수 없다. Sphinx 시험의 dot 부재 skip, 실제 그림과 텍스트 fallback의 차이, GDAL의 PROJ 라이브러리 의존과 추가 grid 필요의 차이, `only-best`를 풀어 얻은 대체 좌표를 원 조건 성공으로 세지 않는 구분은 잘 남아 있다. Graphviz판·PROJ-data판/격자해시·고정판 원시험 실제 실행은 **미확인/미실시**이며 제시된 후속 명령은 실행결과가 아니다.

**사후 실행:** J4 원 요구 범위8/8 성공과 범위밖 JSON-quoting 기대의 실제실패1건을 분리한다. J1의 잘린 원 입력 실패와 연구자의 최소 닫힘 수리 성공도 분리한다. P3는 R/knitr 전체 실행이 아닌 합성 중간 Markdown의 Pandoc 단계 검증이다. P4는 실제 변환 exit83/내부 pdflatex exit1이고 그림 생성·HTML 내장·라벨 보존은 아직 미확인이다. 이 상태에서 “8질문 모두 실제 성공을 검증”이라고 쓰면 틀린다. 공개 질문자의 정확 실행증거는 jq0/4+pandoc0/4=0/8이다.

**계약:** `manifest.json`은 `BLOCKED_DEPENDENCY_DRIFT` 실패 영수증이며 정상 계약 도구 산출물이 아니다. 지정 의존 `e0d7ec…`와 실제 원격끝 `e742bc…` 불일치로 start는 exit2였다. `SCOPE.md`의 시작 SHA와 고정 의존을 유지하고, 체크를 통과시키려고 schema/의존/ref를 바꾸지 않는다. 연구 자료 하한 충족과 계약 완료를 분리하고, 최종 상태·HANDOFF에 계약 결손/미확인 실행을 명시해야 한다. 결과 SHA에서 지정 `workbench.session check ... --fetch`와 공통 검사의 **실제 명령·대상 SHA·종료값**을 기록할 일은 아직 최종 발행 단계의 확인사항이다.

**마지막 인계에서 확인할 미완료 발행 항목:** RESULT의 필수 세 표와 분모 선배치, SELF_CHECK의 Q1–Q7 각각 반증 탐색·한계·다음 최소 관측, 요청별 카드 최대두링크·되물을 한 가지, RESULT 마지막 절의 약점 **정확히3건**, ③/④ 각 원격 커밋 SHA·GitHub 재열람, 마지막 HANDOFF 단독 커밋. 이 검토 시 생성 중인 파일을 미리 PASS로 표시하지 않는다. 중앙 진행표/다른 경로 변경 없이 담당자에게 인계한다.
