# AF-RES-034 · 미시행 후속 비교 설계

**설계 제안이며 실제 참여자·관측 결과가 아니다.** 이 작업에서는 모집, 연락, 새 사용자 시험을 실행하지 않았다. 아래의 시간 예산·판별 경계는 제품 판단을 위한 제안값이다. 선행 연구에서 확인된 제품 효과나 합의된 사업 기준으로 읽지 않는다.

## 1. 판별할 주장과 채택한 설계

제품 가설은 “새 설계가 굳기 전에 목적·근거·적용 한계가 붙은 선례 링크를 받으면, 같은 품질을 유지하면서 최초 작업과 다음 수정에 드는 **사람 노동의 합계**가 줄어든다”이다. 검색시간만 줄이는 가설, 정답을 빨리 찾는 가설, 장기 재작업을 줄이는 가설을 별도로 기록한다.

**두 군 무작위 병렬 비교**를 선택한다. 같은 사람이 두 도구를 쓰는 균형 교차는 CodeMend·Unakite처럼 짧은 서로 다른 과제를 비교할 때 효율적이지만, 여기서는 선례·실패 원인·수정 요구를 한 번 알면 다른 조건에서 잊을 수 없다. NCQ의 기본 도구 선행 순서도 학습과 처치를 분리하지 못한다. 병렬 설계의 추가 모집 비용을 받아들여 기억 전이를 막는다. 사람마다 한 과제군을 배정하고 다른 난도 과제군을 균형 배치한다. 협업 팀이 자료를 공유하는 시험으로 바꾸면 무작위화·분석 단위를 팀으로 바꾸고 사람 수로 팀 수를 부풀리지 않는다.

| 항목 | 사전 고정 내용 | 근거와 한계 |
| --- | --- | --- |

제공 카드의 실제 출력(문구·순서·URL·버전·스크린샷)과 링크가 가리킨 당시 원문 해시를 보존한다. 카드가 과제를 직접 해결하는 코드 전체를 포함하면 별도 완성 솔루션 조건으로 분리하며 위의 B에 섞지 않는다. 같은 페이지를 열어도 읽었다고 단정하지 않고 화면 노출·클릭·명시적 인용·코드/설계 채택 증거를 분리한다.

## 2. 시간·품질·중단 처리

**일차 판정은 시간과 품질의 공동 기준**이다. 모든 배정 인원을 분모로 한 제한 예산 안의 최종 통과율/중대 오류율을 먼저 보고하고, 최초+수정 단계의 사람 노동 분포를 함께 보고한다. 빠르지만 기능·보안·요구 적합성이 나빠진 결과를 성공으로 판정하지 않는다. “통계적으로 다르지 않음”을 동일 품질로 쓰지 않는다.

제안하는 최소 사업 차이는 전체 사람 노동 10분, 품질 비열등 경계는 통과율 −5%p, 중대 보안/데이터 손실 결함은 허용하지 않는 것이다. 이는 **미합의 가정**이다. 실제 제품 책임자가 사전 확정해야 하고 관측 결과를 본 뒤 넓히면 안 된다. 소규모 시험의 넓은 신뢰구간은 효과 없음이 아니라 판별 불충분이다.

- 시간 시작은 공통 훈련을 마치고 과제 본문을 처음 여는 순간이다. 카드 읽기·원문 확인·구현·디버깅·사람이 결과를 기다리며 감시하는 시간을 포함한다. 중간 휴식, 시스템 장애, 다른 업무는 원 로그에서 별도 사건으로 남긴다.
- 실행 경과시간을 사람 노동으로 대체하지 않는다. 화면/IDE 이벤트에 관찰자 태그를 붙여 `read / search / design / code / test-inspect / discuss / active-wait / idle`를 상호 배타적으로 분류한다. CPU 시간, 빌드 시간, 커밋 간격, 수정 줄 수는 별도 보조지표다.
- 최초 종료는 참여자의 채택 선언과 그 시점의 제출 SHA다. 정답을 확인한 마지막 테스트 통과 시점은 별도 필드다. 더 빨리 멈춘 실패도 종료로 기록하되 성공시간으로 넣지 않는다.
- 최종 품질은 조건을 모르는 두 채점자와 동일 테스트가 평가한다. 기능, 안정성/보안, 요구 적합성, 변경 용이성의 항목별 원점수와 합의 전 불일치를 보존한다. 참신성은 제품 과제에서 필요한 경우의 보조척도이며 기능 품질과 합치지 않는다.
- 90/60분 상한의 미완료, 중도 철회, 시스템 장애, 로그 손실을 각각 분류한다. 완료자만의 평균은 명시적으로 이차 기술통계다. 배정 후 제외를 숨기지 않고 모든 배정 결과를 먼저 공개한다.
- 제한 예산 내 성공까지 시간은 성공 사건과 사전 고정 상한 도달에 따른 행정적 검열을 구분해 분석한다. 조기 포기·확정 실패·철회·장애는 별도 사건 또는 결측 사유이며 비정보성 검열을 자동 가정하지 않는다. 전원 분모의 제한시간 성공확률, 실제 소비 노동, 실패 상태를 함께 보고하고 분석법과 민감도 분석을 사전 고정한다. 실패자의 실제 소비 노동은 관측값으로 남기되 “성공까지 시간”에 0 또는 상한값을 임의 대입하지 않는다. 결측 결과의 최선/최악 경계도 함께 제시한다.

개별 사람을 분석 단위로 하며 여러 테스트/클릭/수정이 사람 수를 늘리지 않는다. 층화 배정을 반영한 회귀/무작위화 기반 추정과 사람 단위 bootstrap을 사용할 수 있다. 품질 우선 판정·시간 차이·사전 지식 상호작용의 순서를 사전등록하고 다중 비교 범위를 명시한다.

## 3. 재작업 관측 시작점

`t0`는 **첫 설계 채택 선언과 제출 SHA의 고정 시점**이다. `t1`은 7일 뒤 독립 품질 재검 결과를 양군에 같은 방식으로 전달하는 시점이다. 그 사이의 실제 작업 여부는 별도 기록하며 자료 공유를 막을 수 없었다면 노출 경로를 남긴다. 양군 모두 원래 요구사항을 다시 보는 동일 수정 세션을 갖는다.

첫 제출 전에 한 탐색·되돌리기·타이핑은 초기 노동이다. `t0` 이후 기존 결정을 취소하거나 바꾸고, 이미 만든 작업 일부를 버리거나 다시 만드는 행위만 재작업 후보로 코딩한다. 단순한 추가 기능·새 요구사항·형식 정리·반복 실험은 별도 코드다. 새 요구사항을 일부러 늦게 넣어 생긴 일은 선례의 조기 발견으로 예방할 수 있었던 재작업으로 계산하지 않는다.

| 재작업 사건 필드 | 기록 예 | 판정 원칙 |
| --- | --- | --- |
| 기존 결정·증거 | decision_id, 최초 SHA, 선택 이유, 이미 투입한 작업 | t0 전에 실제 채택했는지 확인 |
| 재검 계기 | 이미 있던 요구 위반, 선례의 제약, 새로운 요구, 외부 장애 | 원인 분류를 처치 효과 추정과 분리 |
| 되돌린 내용 | 선택 대안 변경, API/구조 교체, 폐기 부분 | 단순 편집 수를 재작업 횟수로 쓰지 않음 |
| 노동 구간 | 시작/끝 UTC, 실제 활동 초, 중단 사유 | 버린 초기 노동과 이후 수정 노동을 각각 보존하고 중복 합산하지 않음 |
| 후속 품질 | 같은 테스트 통과 여부·독립 점수·미완료 | 수정이 줄었지만 결함을 그대로 두면 이득 아님 |
| 누가 부담했나 | 최초 설계자, 동료 검토자, 자료 제공자, 운영자 | 읽는 사람의 이득만 팀 전체 이득으로 환산하지 않음 |

`t0`에 설계를 채택하지 못한 사람의 재작업은 **해당 없음/아직 시작되지 않음**이지 0분 성공이 아니다. `t0` 채택자만의 재작업 평균은 처치 후 선택에 조건부이므로 인과 일차 지표로 삼지 않는다. 모든 배정자의 최종 품질과 전체 소비 노동을 공동으로 비교하고, 채택자 이차 결과에는 두 군의 선택 분모를 나란히 제시한다. “아꼈을 것” 자기보고는 별도 의견 칸이며 시간값에 더하지 않는다.

## 4. 표본과 판별력

당장 정할 수 있는 것은 두 군·두 시점·동일 품질 기준의 구조다. 선행 연구의 초/분 효과를 이 과제의 표준편차로 전용해 확정 표본 수를 만드는 것은 타당하지 않다. 준비 단계에서는 예를 들어 60명(30/군)의 탐색 비교를 계획할 수 있으나 이는 확정적 비열등성 검증 표본이라는 뜻이 아니다. 가능하면 처치 정보가 가려진 파일럿의 사람 단위 분산·통과율로 사전 확정 표본을 다시 계산한다. 파일럿에서 유리한 결과가 나왔다는 이유로 종료하지 않는다.

단순 독립군 시간 비교의 계획 근사는 `n_per_arm ≈ 2*(z_.975+z_.80)^2*SD^2/delta^2`이다. 가령 **가정** SD20분, delta10분이면 약63명/군이며, 탈락·층화·시간분포·품질 비열등성은 별도로 더 검토해야 한다. 이 63은 실제 관측 입력이 아니다. 품질 5%p 비열등성은 기초 통과율과 중대 오류 빈도에 따라 훨씬 큰 표본을 요구할 수 있으므로, 시간 표본 수만으로 공동 판별력을 약속하지 않는다.

판정은 다음처럼 고정한다. 품질 기준을 충족하고 시간 차이의 불확실성 범위가 실질적 이득을 지지하면 다음 범위 시험으로 진행한다. 품질 손상이 보이면 카드 선정/검증을 바꾼다. 시간과 품질 모두 불확실하면 표본·과제 다양성을 보완한다. 품질을 지키며 효과가 작다는 좁은 추정이 나오면 이 과제군에서는 가치가 제한적이라고 판단한다.

| rework | participant_id, decision_id, old_sha, new_sha, trigger_code, changed_decision, discarded_work_evidence, repair_active_seconds, reviewer_seconds | t0 이후 되돌림과 노동 |
| provider_cost | source_bundle_id, prepare_seconds, verify_seconds, maintenance_seconds, consumers_n | 자료 제공·유지 비용을 포함한 팀 관점 |

설계자는 실제 문제 적합성과 수정 부담을, 자료 제공자는 출처 선택·버전 점검 시간을, 독립 채점자는 오류와 누락을, 비용을 부담하는 팀은 이 세 노동의 합계를 본다. 예를 들어 자료 준비 비용을 여러 소비자에게 분산하는 경제성 산식은 `준비·유지 노동 + 소비자별 실제 노동 합계`다. 모든 사람이 같은 카드를 재사용한다고 가정해 비용을 자동으로 0으로 만들지 않는다.
