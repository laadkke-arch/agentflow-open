## ① 모집 규칙 — 다음 판 본문을 열기 전에 고정

1. 프로젝트는 Matplotlib, CPython, ggplot2 세 개다. 공식 릴리스 목록에서 공개일이 2023-01-01–2025-12-31인 안정 `x.y.0` 중 날짜가 가장 이른 판을 고른다. prerelease/dev/RC는 제외한다. 그 동일 `x.y` 계열에서 그 뒤 처음 공개한 안정 패치판을 비교한다. 태그의 author date와 릴리스 공개일을 혼동하지 않는다.
2. Matplotlib은 공식 gallery, CPython은 공식 배포 문서의 tutorial/howto/library/reference/c-api/extending 등 예제·튜토리얼·참조 본문, ggplot2는 공식 reference/pkgdown을 모집틀로 삼는다. 릴리스 소스만 있고 생성 HTML이 없으면 HTML을 직접 생성하여 대체하지 않는다.
3. 이전 판의 상대 HTML 경로를 대소문자를 보존한 사전순으로 정렬한다. 인덱스·테마·로고·공통 내비게이션·다운로드 버튼 아이콘은 제외한다. 예제/설명 주 본문에 이름 있는 로컬 이미지·데이터의 명시적 URI가 있는 첫 두 서로 다른 페이지를 택한다. 설명 그림과 실행 결과 그림은 모두 포함하되 종류를 기록한다. 경로의 존재만 확인한 후순위 후보는 ‘본문 미열람’으로 구별한다. 적격 여부 확인을 위해 읽은 선행 제외 페이지는 기록한다.
4. 각 페이지의 첫 적격 자원 URI를 주 대상으로 고정한다. `img`의 `src`, `srcset`, `picture/source`, 명시적인 데이터 다운로드를 문서 순서로 확인한다. 자동 다운로드용 `.py`/`.ipynb` 코드 링크 자체는 이미지·데이터로 세지 않는다. 코드가 실행될 때만 생기는 가상의 경로는 제외한다. 내장 data URI만 있고 이름 있는 로컬 자원이 없으면 주 모집에서 제외하되 보조 반례로 남긴다.
5. 이전 판을 공식 배포 HTML, 공식 다운로드 아카이브, 또는 발행자의 Git 트리에서 찾은 경로를 기록한다. 두 페이지를 못 구하면 해당 자리를 결원으로 보존하며 다른 프로젝트로 채우지 않는다.
6. 공식 릴리스 목록의 제목·공개일은 비교 판을 고르는 데 사용할 수 있다. 다음 판의 예제 본문·파일 내용·생성 기록은 ② 커밋 뒤에만 읽는다. 각 조사자의 노출은 시점·내용·영향과 함께 기록한다.

## ② 낮은 비용 예측 — 목록만 사용

- 먼저 옛 절 URI, 논리 자원, 사용 목적, 옛 파일의 절 기준 상대 URI와 배포 루트 기준 정규화 경로를 봉인한다.
- 새 판의 트리 또는 공식 아카이브 멤버 **이름 목록만** 읽는다. API가 자동 제공한 blob SHA/길이는 판정에 사용하지 않는다. 아카이브 전송 시 새 본문 바이트를 함께 받더라도 봉인 전에는 압축 해제·읽기·파싱하지 않는다. 이 취급을 노출 로그에 명시한다.
- 옛 배포 루트 상대 경로가 새 목록에 정확히 한 번 있으면 `사용 예측 YES`; 전체 목록에서 없으면 `사용 예측 NO`. 목록을 완전히 확보하지 못하면 `UNKNOWN`.
- 정확 경로가 없고 같은 basename 후보가 다른 경로에 있거나, 같은 정규화 경로가 중복되면 `HOLD`(이름 이동/모호). basename 일치만으로 긍정하지 않는다. 정확 경로가 유일하면 다른 디렉터리의 같은 basename은 부차 후보로 기록하되 그 URI의 존재 예측은 유지한다.
- 이 예측의 표적은 ‘동일한 다음 판 절이 고정 논리 자원을 실제 사용함’이다. 배포 포함, 바이트 동일성, 새 생성 여부는 예측 표적이 아니다. 경로가 없어도 이름이 바뀐 자원을 실제 참조하면 놓친 연결로 센다.
- 6개 자리는 늘 유지한다. 결원/노출은 분모 6에서 삭제하지 않으며 사후 판정 가능 분모를 별도로 표시한다.

## ③ 사후 판정의 세 축

| 축 | YES의 필요한 근거 | NO/유보의 경계 |
|---|---|---|
| P · 해당 판에 배포/포함 | 정확 판의 공식 ZIP/트리와 실제 멤버·payload 연결 | 불완전 목록·접근 실패는 UNKNOWN. 다른 판 URL 성공으로 메우지 않는다. |
| U · 정확 절에서 사용 | 해당 판 생성 본문의 구체 속성/링크를 base URI에 따라 해석하고 실제 payload 연결 | NO는 조사한 절 경계와 `src/srcset/source/href/data URI/inline SVG/script` 탐색 범위를 명시한 경우만. 네트워크 실패는 UNKNOWN. |
| G · 이번 빌드가 이 바이트 생성 | 특정 실행/발행 기록이 입력·실행·산출물 지문을 직접 연결 | 같은 이름/TITLE/mtime/SHA/태그/배포 커밋만으로 YES를 만들지 않는다. 기존 파일을 복사하는 규칙은 생성 provenance와 구별한다. 증거가 없으면 UNKNOWN. |

정적 참조+일치 payload는 U까지만 지지할 수 있다. HTTP가 반환한 MIME과 파일 signature/내장 manifest MIME도 각각 기록한다. 정적 HTML/JS 조사와 실제 브라우저 요청·실행을 구분한다. 최초 URL, 리다이렉트, 최종 URL, 바이트 수, SHA-256과 절/속성의 짧은 발췌를 남긴다.

## ④ 비교·자료 수·비용

- 6쌍/12자리를 유지한다. YES/NO 예측과 U를 비교하여 참·오귀속·놓친 연결을 세고 HOLD/UNKNOWN/결원·노출을 별도 공개한다. 모집 표본에서의 결과를 전체 문서 생태계 정확도로 일반화하지 않는다.
- Q5의 다섯 반례 유형은 주 사례에 없으면 공식 자료의 보조 사례로 찾되 6쌍 분모에 넣지 않는다. 094의 두 SVG는 한 교정 사건이며 신규 사례 수에 넣지 않는다. 094의 24경로, Moby-Dick, IIIF 0009는 재사용 성과로 세지 않는다.
- 직접 읽은 외부 1차 자료 하한은 25. 실제 예제 본문 10, 원 이미지/데이터 6, 발행·빌드·목록 5, EPUB 규격+패키지 2, 데이터 식별 규칙+실제 버전 레코드 2 이상을 독립 검산한다. 동일 저작·동일 바이트는 판/anchor/raw/blob URL이 달라도 1건이다. 목록 한 번을 그 안의 수천 멤버 수로 늘리지 않는다. 실패·검색 미리보기·읽지 않은 링크는 제외한다.
- 내려받은 원문 전체는 재현 가능한 임시 캐시에 두고 커밋에는 원주소·지문·짧은 속성/메타데이터 발췌를 남긴다. 원자료를 읽은 것과 기계가 경로 목록만 수집한 것을 구분한다.
- 요청/문서/내부 ZIP 파일의 수는 실제 영수증으로 계산한다. 사람 클릭 시간·장애 지속시간은 추정하지 않는다.
- 작성자 자기검토와 별도 에이전트의 실제 교차검토를 구분한다. 사람 검토를 수행했다고 부르지 않는다.
