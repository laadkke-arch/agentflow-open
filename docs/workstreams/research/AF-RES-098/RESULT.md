## 주 예측의 성패와 확인 가능 분모

**목록만으로 봉인한 6개 사용 예측은 모두 참이었다.** 확인 가능한 분모는 6/6이며 참 6, 오귀속 0, 놓친 연결 0, 유보 0, 결원 0이다. 그러나 예측과 실제 모두 양성인 표본이다. 실제 음성 분모가 0이므로 특이도나 삭제·이름 변경에 대한 탐지 성능은 계산할 수 없다. “성공률 100%이므로 파일 존재만으로 충분하다”는 결론은 지지하지 않는다. [봉인한 예측](predictions.csv), [사후 12행](lineage.csv), [집계](evidence/counts.json)를 서로 대응시켰다.

## Q3. 본문에서 실제 바이트까지

`lineage.csv`는 소스 URL·SHA → 생성 HTML URL·SHA → 정확 절·literal URI·base URI → payload URL·MIME·길이·SHA → 발행 기록·생성 기록의 빈칸을 12행에 유지한다. 각 HTML에는 대상 해석을 바꾸는 base 요소가 없었다. 상대 주소는 해당 본문의 최종 URL을 기준으로 해석했다. 주 이미지 12개는 모두 HTTP 200이며 원 MIME `image/png`, PNG signature가 일치했고 해당 요청에서 리다이렉트는 없었다. PY ZIP의 docs.python.org→www.python.org 이동은 별도 영수증에 남겼다. raw GitHub HTML은 전송 MIME이 text/plain인 HTML 소스이고, 브라우저에 렌더된 과거 사이트와 같다고 표시하지 않는다. [MP audit](evidence/matplotlib/audit.json), [PY audit](evidence/cpython/audit.json), [GG audit](evidence/ggplot2/audit.json).

MP는 두 판·두 절에서 src와 2.0x srcset을 모두 따라 8개 PNG를 받았다. 1x 4개가 주 12자리의 일부이고 2x 4개는 동일 사례의 변형이며 분모를 늘리지 않는다. picture/source·figcaption·다운로드 링크·inline/data URI·JS를 절 범위에서 조사했고 실제 브라우저의 DPR 선택 요청은 보지 않았다. MP1과 MP2는 각각 마지막/시작 정적 장면으로, 특히 pause/resume 본문과 소스는 정적 문서로 클릭 동작을 입증할 수 없음을 드러낸다. 배포 .py 두 개는 해당 source tag의 파일과 같은 바이트였다.

GG는 Examples의 첫 이미지를 고정했고 전체 절에는 각각 5개·18개 이미지가 있었다. 선택 절에서 base/srcset/picture/source/figcaption/script/inline SVG/data URI는 없었다. 4개 payload는 실제 1400×866이고 HTML 표시 크기는 700×433이다. ## Q4. 발행 귀속과 생성 귀속의 경계

MP의 고정 발행 커밋은 버전 디렉터리와 생성 HTML·PNG를 묶는다. 그러나 [3.7.1 release guide](https://github.com/matplotlib/matplotlib/blob/b3bd929cf07ea35479fded8f739126ccc39edd6d/doc/devel/release_guide.rst)의 문서 배포 절 L347–400은 tagged library와 ver-doc 브랜치를 조합해 문서를 만들고 rsync·commit/push하는 절차를 설명한다. 따라서 source release tag 하나가 정확 문서 입력 전체가 되지 않는다. [doc/conf.py](https://github.com/matplotlib/matplotlib/blob/b3bd929cf07ea35479fded8f739126ccc39edd6d/doc/conf.py) L178–202의 gallery·2x·animation 설정은 생성 규칙이며 실행 영수증이 아니다. sphinx-gallery의 최소 버전 조건도 당시 정확 환경을 고정하지 않는다.

[검사한 Sphinx-Gallery 0.11.1 코드](https://github.com/sphinx-gallery/sphinx-gallery/blob/v0.11.1/sphinx_gallery/gen_rst.py) L989–1007에는 MD5가 같고 run_stale_examples가 꺼져 있으면 이전 결과를 쓰는 경로가 있다. 이는 가능한 캐시 메커니즘이다. 선택한 MP 발행에서 실제 이 버전·옵션·캐시가 쓰였다고 판정하지 않았다. release guide의 정리·재빌드 지침과 캐시 가능성을 나란히 보존했다.

PY는 [tagged rst](https://github.com/python/cpython/blob/2305ca51448552542b2414186252123a8dc87db7/Doc/howto/logging.rst) L420의 정적 image 지시, [Sphinx 4.5.0 HTML builder](https://github.com/sphinx-doc/sphinx/blob/v4.5.0/sphinx/builders/html/__init__.py) L719–729의 파일 복사, [Doc/Makefile](https://github.com/python/cpython/blob/2305ca51448552542b2414186252123a8dc87db7/Doc/Makefile) L169–179의 ZIP 포장 경로를 연결했다. `.buildinfo`의 설정·태그 해시와 HTML footer 시각은 이미지 생성 지문이 아니다. [당시 이전의 docsbuild-scripts](https://github.com/python/docsbuild-scripts/blob/f0a570aec824c7d775ea9d345a89d1b10d0f11b2/build_docs.py)에는 문서 변경 없을 때 생략, full/partial rsync의 삭제 차이가 있으나 실제 release 호출 상태는 미확인이다.

GG는 발행 commit 메시지의 source SHA, HTML의 릴리스 판, pkgdown.yml을 교차 확인했다. 옛 판은 pkgdown 2.0.7/pandoc 2.19.2, 새 판은 2.0.9/3.1.11이었다. [관련 규칙·실제 정적 재사용](evidence/ggplot2/stage3.md), [배포 action의 clean 정의](https://github.com/JamesIves/github-pages-deploy-action/blob/v4.4.1/README.md).

조회한 source/deploy Actions 결과의 0건이나 HTTP 403은 과거 job이 존재하지 않았다는 증거가 아니다. 보존 기간·API 접근 범위·발행 경로가 달라질 수 있다. 0건 결과와 실패는 최소 자료 수에서 제외했다. 세 프로젝트 모두 **특정 실행의 입력·환경·산출물 지문을 연결하는 기록을 확보하지 못했다**는 범위로 G를 남긴다.

## Q7. 재사용 가능한 판단 단위와 반환 비용

색인 제안은 **`요청 목적 + 고정판 + 정확 절 + 참조 관계 + payload 지문 + P/U/G 근거 수준`을 한 판단 단위로 보존하고 필요한 링크만 펼치는 것**이다. 예제를 실행하려면 본문과 코드가 우선이고, 역사적 이미지 인용은 고정 본문과 당시 이미지가 필요하다. 발행자가 생성 이력을 묻는 경우에만 job·manifest·환경을 추가하되 없으면 생성 미확인을 그대로 보인다. 파일을 쓸 수 있다는 양성과 생성판이 밝혀졌다는 양성을 하나로 합치지 않는다.

같은 PY1 사건에서도 흐름을 이해할 독자는 본문, PNG를 재사용할 개발자는 본문→PNG, 생성 귀속을 따지는 발행자는 여기에 입력·복사·생성 기록을 요구한다. 세 주소를 늘 반환하면 본문만 읽거나 EPUB 하나만 받으면 되는 요청에 과잉이다. 반대로 PNG 주소만 반환하면 판·절·용도를 잃고, concept DOI 하나만 반환하면 특정 분석 버전을 잃는다. 반환 표는 이 차이를 링크와 관측 범위로 표현한다.

비용은 열린 자료 수로 기록했고 사람 클릭 수·소요 시간·장애 지속시간은 추정하지 않았다. 사전 목록 봉인에는 MP 3·GG 3·PY 1, 총 7개 논리적 접근이 필요했고 기록된 응답 전송은 14,522,038B였다. PY의 멤버 이름만 읽어도 ZIP 12,749,453B를 전송받았으므로 “싸다”는 판단은 열람 정보의 범위에 한정되며 네트워크 바이트가 작았다는 뜻은 아니다. 주 대상으로 확정한 URL은 본문 12+1x PNG 12=24개이고 MP srcset 4개를 추가해 **28개 본문/이미지 주소**를 확인했다. PY는 여기에 공식 ZIP 2개를 받았고 내부 고유 멤버는 옛 판 520(515 HTML 자동 스캔+선정 PNG 2+rst 2+.buildinfo 1), 새 판 7이었다. 이 520은 직접 자세히 읽은 외부 저작 520개라는 뜻이 아니다. EPUB 비교는 패키지 2개를 받았고 목적별 최소 경로는 패키지 1+내부 4멤버다. 릴리스 목록·트리·태그·규칙·이력·반례·실패 재시도는 프로젝트별 영수증에서 별도로 확인할 수 있다. 28은 총 HTTP 요청 횟수가 아니라 주 검증 주소의 수다.
