## 결과

**최종 산입 102건 / 원장 164행**이며 `counts.json`과 일치한다. 실제 예제 본문 18, payload 17, 발행·빌드·목록 48, EPUB 규격·패키지 3, 과학 데이터 규칙·레코드 6으로 최소 요구를 충족한다. 1,335개 모집 경로를 직접 읽은 1,335개 자료로 늘리지 않았다.

이 검토의 ggplot2 부분은 해당 작성자의 **자기검토**다. Matplotlib·CPython·타 분야 원장과 수치·영수증 대조는 별도 에이전트의 **AI 교차 검토**다. 사람 독립 검토는 아니다. 모든 외부 사실을 다시 브라우징한 검토나 생성 job 검증으로 해석하지 않는다.

## 초기 104건에서 고친 점

초기 기계 대조는 164행 중 104개 counted, raw 응답 SHA/URL 중복 0을 확인했다. 그러나 이 방식은 **다른 HTML wrapper 안에 같은 저작 본문이 든 중복**을 잡지 못한다. 이후 cross-domain 검토자가 MP2의 두 판 article이 동일한 10,598B라고 찾았다. MP1도 저작 예제가 같고 바뀐 article 부분은 실행시간 7.524→10.212였다. root는 두 새 본문 `MP1-NEW-HTML`, `MP2-NEW-HTML`을 보수적으로 제외했다. 최종치는 **102 / 본문18**이며 초기 104 / 본문20을 최종 수치로 사용하면 안 된다.

보수적으로 합친 **주 여섯 예제의 저작 본문은 8개**다. 이 값과 전체 실제 예제 본문 18개를 구분해야 한다. 18에는 이전판 모집 과정에서 실제 읽은 다른 예제 본문과 보조 홈페이지 예제가 포함된다. 이들이 주 여섯 쌍의 결과 분모를 늘리지는 않는다. 원 그림 최소 수에서도 주 고정 src의 고유 payload 10개, 추가 srcset 4개, 보조 3개를 합해 17개이며 사례 수는 여전히 여섯 쌍이다.

## 필드와 중복 점검

- 필수 의미 필드(`id`, Q, case, 원URL, UTC, 발행자·계보, 판·위치, 관측, claim, 한계, 산입·중복 근거) 공란 0행, source ID 중복 0개다.
- 최종 counted 항목 사이에서 추가 raw 응답 SHA-256 중복은 0묶음이다. 이는 내용 단위 중복 검토의 대체가 아니다.
- GG의 세 mutable API 목록은 고정 URL을 지어내지 않고 `fixed_url:null`을 유지한다. root가 `fixed_url_status`와 limitations에 이유를 보완했다. 실제 원URL·UTC·응답 지문은 있다.
- CP `PY-S010`은 새 ZIP의 **목록 지문**을 보존했으며, 봉인 당시 전체 payload 지문을 확인한 것으로 쓰지 않았다.

- GG의 동일 source·workflow, 정적 PNG 네 경로, 빈 Actions 결과는 이미 보수적으로 제외돼 있다. 타 분야에서도 같은 EPUB 내부 파일과 raw mirror, DOI landing/API mirror를 별도 저작 수로 늘리지 않았다.
