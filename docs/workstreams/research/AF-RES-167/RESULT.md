## Q1–Q7
**Q1 요구.** M08은 구매 PDF의 orchestral instrumentation 편집이 목적이므로 단순 화면 성공으로 부족하다. M07의 원 요구는 두 성부 rest 배치를 수동으로 고치지 않는 것, I09는 최초 wall-mounted 형상 누락 뒤 parametric guardrail 필요를 추가했다. I16은 viewer 표시가 아니라 NEOM_Operations_Class, NEOM_BOQ_Cost_Code, NEOM_Target_LOD 등 추출이다. 요구 종류를 최초/댓글 추가 시점으로 분리하며 결과는 properties.csv에 둔다. (M07 M08 I09 I16).

**Q2 지원 범위.** MusicXML4는 W3C Community Group 최종 규격이지 W3C Recommendation이 아니다(S01). measure-repeat는 실제 반복 음표와 기호를 별도 표현(S01r). clef-octave-change와 transpose/octave-change는 서로 다른 기능(S01c/S01o). Dorico/Finale/MS 구현 문서 D02/D03/D07은 가져오기 설정·파트 생성·사운드 재할당 등 절차이지 과거판 값 보존 시험 아님. IFC4 Reference View 1.2(S02)는 단방향 참조 목적; DTV 표기만으로 native 창 편집 보증하지 못한다(I17). Revit2024 exporter(D04)에는 MVD, 사용자 pset, 매핑/공간 선택; Archicad24(D05/D06)에는 Object/Morph fallback, 분류/필터/merge 시 새 GlobalId와 External IFC ID. 인증은 방향·MVD·판을 따로 확인(S03/C03), 구문/스키마/규범 검사(S04)는 특정 프로젝트 요구를 전부 검사하지 않는다. 실제 개별 인증 scorecard/당시판별 양쪽 절은 결측.

**Q3 조인.** 강한 입력은 I04 고정 blob(원파일 직접, 수신판 결측); I10 고정 ZIP과 댓글의 #5889·#5915 및 두 버전 이름(압축 내부 미열람); M15 본문 전체 XML(첨부 일치 해시 미확인). 동일 첨부 이름과 보고자 연결은 그보다 약하다. I09의 railing_wmr.ifc/rebar1/2를 최초 railing.ifc.txt와 합치지 않는다. I18 private 원파일은 제외한다. 원파일 접근 거절/렌더러 추출 불가를 X01–X04에 기록했다. 깃허브 이슈 URL은 고유 식별이나 본문 수정 가능; 공개 지문 없는 행은 낮은 조인 강도.

**Q4 처음 갈라진 곳.** M06 이조 -1/-1은 본문 직접 판독, 중복 이조라는 유지보수자의 판정은 보고이고 원 생산자도 모른다. M15의 입력 wedge/시간축은 직접 인라인 판독, crash와 start segment 설명은 보고다. I04 STEP의 #45, #46, #115, #120, #128을 직접 읽어 단위 0.3048과 precision 0.0001을 확인했지만 0.006ft nail width는 당사자 해석, 결과는 보고. I10은 삼각형 닫힘과 2 vertex 결과 보고, reversed orientation 진단; 직접 재변환 없음. I02 구 HasPorts 질의 오류와 I15 30k import object limit 해결은 제품의 데이터 소실로 일반화할 수 없다는 반례. M11 화면 root 누락이나 편집 중 G가 남았다는 보고도 같다. I18은 mandatory representation 및 IfcSystem/Site 문제 제보(전체 private). 첫 결측을 발신/수신/표시/설정/미확인으로 낮춰 분류한다.

**Q5 방향.** M08 같은 파일의 MS와 VSM, I04 BB와 BIMcollab, I16 같은 모델 exporter22.1/22.6 비교는 자연 대조 후보 보고이나 두 소비판·파일·값을 모두 잇지 못했다. I19 containment 추가, I04 precision 수정, M05 edited XML은 수정 조건 대조이며 동일 원파일 대조 아님. M05 Finale 자체 재수입과 MuseScore 단방향은 왕복 교환 아님. I12 BB 2차 export에서 False 누락 보고는 최초 소비자 재수입과 원값이 결측. 자가 5건(M03/09/14/17/18), 독립 구현 공개 명명 보고 11건, 실제 서로 다른 조직의 공동 교환 시험 확인 0건(보고층 조직 및 참가 판 미확인); strict natural pair 0 확인/적격 모집 분모 미확정. 한 방향만 원하는 참조용 RV와 원 native edit 복귀가 필요한 경우를 다른 목적에 둔다. 별도 교정층 C01(GeoBIM 2019, 2021 논문 §4.4 표7, IfcDerivedUnit/Element 7/16 reexport 누락, 일부 entity counts 동일도 값 동등성 아님), C04(2021 구조해석 §4–5.3, 50kN/m+25kN, RFEM→SAP2000 성공과 역방향 loads loss, 자체 시험 성공) 독립 시험 저작 2개; C02 LilyPond2.24 42a/45a 등 한 구현 자가 시험 1저작. C03은 시험 규칙이지 성적 아님. 모두 자연층 외. 자연층으로 빈 칸 채우지 않음.

**Q6 인접 분야.** A01(Todd Millennium→Koha, PDF text 228–252)은 item status 미export로 별도 stock report 및 manual correction, 표본 수백; bibliographic MARC와 holdings/item sidecar를 구분. A02(IAEA migration, PDF text 77–108)은 template→MARC 대응, 610/650 구별 불가, first test load 이후 >5000 IDs와 로컬/OPAC suppression mapping. 두 기관 마이그레이션 저작은 직접 읽었지만 두 표준 MARC 구현 간 동일 레코드의 태그별 손실 시험 두 건으로는 부족하며 A02는 특히 원천 template다. 원면 screenshot A01 404/A02 403으로 텍스트 판독만; 보충 원면 필요. A03 Smithsonian/LOC 2021 pp24–27 fig2–4는 SHA 일치에도 손상 복사본을 인수할 수 있고 750+ 후속 처리 중 4 transcode 오류 보고; staging RAID 복구. A04 BFI 2022 vendor V210 MOV→FFV1 MKV, MediaConch policy와 frameMD5 및 로그를 대조, stream copy/segmentation 처리. 동일 비율로 통합하지 않는다. 송신 규격·실제 인수검사·예외의 분리 원리를 MusicXML의 raw note 및 화면/편집, IFC 속성과 형상/ID로 옮기되 AV hash/frames는 의미 보존 전체를 보장하지 않는다. MARC 기관 보고 2, AV 2; 정확한 MARC-to-MARC 태그별 두 사건은 미완료.

**Q7.** 사양 소개는 존재 가능한 구조만 알려준다. L01–L07(links.csv)처럼 (1) 요구와 속성에 해당하는 규약 절, (2) 양 구현·방향·판/설정 절, (3) 특정 파일/속성의 관측 원문을 분리 반환한다. 한 절만 충분한 경우는 사양 표현력 또는 공급자의 특정 기능 선언을 묻고 실제 상호운용을 요구하지 않을 때. 둘째 구현이 미정이면 '이 판의 두 구현에서 관측' 문구를 금지하고 시험 입력을 반환. ## 조건이 다른 대안·동시 적용
- 참조/검토에는 RV, 화면/형상과 좌표·단위 검사; native 편집에는 공급자 내부 객체 변환 절/속성 매핑 및 별도 회귀 테스트를 추가. DTV 문자열 자체를 합격으로 사용하지 않음.
- 악보 가독성만이면 layout 설정/표시 판독; 재기보·재생/편집이면 voice/lyric/measure-repeat/note 및 악기 ID 비교. 원본 XML과 정규화 결과를 각각 보관하고 의도치 않은 double transpose와 정규화 부작용을 검사.
- 기능 링크 단독, 사양+양쪽 절, 파일별 교환 증거 패킷을 비용별로 반환. 정확판·프로필·속성·방향이 고정되지 않으면 증거를 보강하거나 제한된 조건부 문장만 사용.
