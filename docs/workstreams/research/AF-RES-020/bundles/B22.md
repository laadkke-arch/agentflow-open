# B22 — 색인의 내용 상태와 인수 상태 분리

## 식별·질문

- 브리프: assembly. 상태: 편집 제안 / 공통 색인 미적용.
- 결정: 읽고 쓸 수 있는 결과와 요청의 완료 판정을 어떻게 별도로 전달할 것인가?
- 입력: AF-RES-009 `7f627a81…`, AF-RES-013 `eb569f07…`, AF-RES-016 `3b43c41a…`; 운영 규칙과 현재 색인 `7b4334e5…`.

## 짧은 핵심

`DONE`, `REVIEW_READY`, 채택, 효용 검증은 서로 다른 상태다. 원 인계 상태를 보존하고, 정규화 상태·미충족 조건·사용 가능한 범위를 나란히 둔다. 편집 담당은 결과를 통합하지 않아도 고정 SHA 링크로 안내할 수 있다. 공통 색인 갱신이 최종 제품 설계 선택을 뜻하지 않는다.

## 대안·기발한 조합

원 상태 문자열을 그대로 보여 주는 안은 손실이 적지만 비교하기 어렵다. 표준 세 상태만 남기는 안은 쉽지만 과거 의미를 지운다. **H:** `original_handoff_state`와 `normalized_handoff_state`를 함께 기록하고 정규화 이유와 미충족 조건 ID를 연결한다. 진행 담당은 REVIEW_READY이며 수용 조건이 모두 true인 경우에만 DONE 검토가 가능하다. 이는 자동 DONE을 지시하는 규칙이 아니다.

## 반례·한계

013의 사이트 상한은 이번 brief에서 사례와 방법 문헌을 분리하며 명료해졌지만, 그 사실로 과거 HANDOFF의 BLOCKED를 고쳐 쓰면 안 된다. 인수 담당이 새 규칙을 적용했는지의 기록은 별개다. 016의 다른 문헌을 많이 읽었다는 사실로 지정 2편의 미열람을 true로 바꾸면 안 된다.

## 관계

B18은 실행·관측 범위, B20은 선택·폐기 이유, B15는 013 표본 범위, B12는 016 분류 근거를 제공한다. B22의 인수 상태는 이들의 내용상 결론을 일괄 승인·기각하지 않는다.
