# B02 — 부분 입력에서 필요한 문맥만 추가하기

## 식별·질문

- 브리프 질문: input. 상태: **조건부 검토**. 확인일: 2026-11-21 UTC.
- 판단할 질문: 전체 구조가 없을 때 어디까지 답하고 언제 추가 문맥을 요구할 것인가?
- 입력은 아래 고정 SHA 원 결과다. 결정을 바꾸어도 인접 묶음의 결론을 자동 변경하지 않는다.

## 짧은 핵심

원리 탐색과 환경 적합 판정을 나눈다. 없는 정보는 미상으로 두고 답을 바꾸는 판정에만 질문을 붙인다. 주변 입출력·공유 경계가 중요한 경우에도 전체 설계를 입장 조건으로 강제할 근거는 없다.

## 대안·기발한 조합

부분 질문을 그대로 탐색하는 안, 직접 입출력만 추가하는 안, 두 해석을 조건부 병기하는 안을 비교한다. H: B01의 원문 보존을 공통으로 두고, 질문이 바꾸는 판정을 한 문장으로 못 적으면 필수 질문으로 승격하지 않는다.

## 반례·한계

공유 상태·수신 주체를 발명해야 답할 수 있으면 연동 적합성은 멈춘다. 반대로 인터페이스 아이디어에 무관한 전체 서버 구성을 요구하면 과도한 문맥 수집이다. 001에서 질문은 실제 사용자에게 보내지 않았으므로 “질문을 줄였다”는 효과는 미확인이다.

## 관계

B01이 의미 보존의 전제다. B11의 실제 부분 질문 관측과 함께 쓰고 B23의 질의 원문/요약 차이에 연결한다. B07의 사용 범위에 따라 필요한 문맥이 달라지므로 독립된 고정 필수 필드 수로 만들면 숨은 의존을 잃는다.

## 검토

AF-RES-020 내부 별도 검토(같은 모델 계열, GPT-6 Astra Pro)가 원 결과와 하위 근거를 대조했다. 원 연구의 작성자·정답 구성자와 이번 대조자를 구별한다. 각 주장 판정은 `CLAIM_CHECK.json`의 `C-B02-*`로 추적한다. 사람 검토나 외부 모델 재현성 검증은 아니다.

## 다음 확인

부분 원문 2개를 골라 직접 경계만 있는 입력과 숨은 공유 상태를 추가한 입력에서 후보 판정이 바뀌는지 비교한다. I5 같은 입출력 문맥의 충분성은 후속 실제 질문 자료로 판단한다. 첫날에는 미입력·모름·미정·무제약·상충을 서로 바꾸지 않는다.
