# B09 — 범위와 기존 도구 조합

## 식별·질문

- **브리프 질문:** scope. **선택 단위:** 자체 자료집을 만들기 전에 기존 LLM·코드 검색·목록·원문 확인을 조합한 제품 범위를 비교군으로 삼을지.
- **상태:** 비교 기준으로 채택 가능. 기존 도구의 문서상 능력과 목표 문제의 실측 효용을 분리한다.

## 짧은 핵심

입력 구조를 받고 구현 부품을 찾아 설명하며 출처로 되돌아가는 기능의 일부는 이미 존재한다. 009가 분류한 **7범주 35시스템**의 문서 비교에서 넓은 목적 자체를 신규성으로 주장할 수 없다. 자체 자료집 없이도 기존 조합에 질문·검증 기록만 보존하는 시작 구성이 성립한다. 다만 문서상 기능 존재는 같은 예산에서의 정확도·설계 유용성을 입증하지 않는다.

## 대안·기발한 조합

이 묶음은 B05·B06의 저장 구조를 모두 보류해도 채택할 수 있다. H: 후보 검색은 기존 서비스에 맡기고 질문 원문·검색 입력·응답 시점·판정 근거 위치를 작은 검증 장부로 보존한다. 반복 질문이나 노후화 비용이 실제로 드러날 때 B05 또는 B06을 추가한다. 데이터 집합의 소유가 제품 차별성의 필수 조건이라는 가정도 보류한다.

## 반례·한계

기능 표의 빈칸은 문서에서 확인하지 못했다는 뜻이며 시장의 부재가 아니다. 특정 클라우드 점검 능력이 모든 OSS·다른 분야 원리 탐색을 해결한다는 뜻도 아니다. grep.app의 공식 MCP 예시는 부분 문제에서 코드·행 근거를 연결하므로 ‘기존 도구는 목록만 준다’는 주장을 반박하지만, 자체 연구 문제의 성공률은 제공하지 않는다. 2026-11-20 문서 창 밖의 현재 기능·가격은 이번에 재조사하지 않았다.

## 관계
