# B03 — 발견 경로와 기능 보장을 분리하기

## 식별·질문

- 브리프 질문: retrieval. 상태: **조건부 검토**. 확인일: 2026-11-21 UTC.
- 판단할 질문: 완성품·부품·원리를 어떤 검색 경로로 비교할 것인가?
- 입력은 아래 고정 SHA 원 결과다. 결정을 바꾸어도 인접 묶음의 결론을 자동 변경하지 않는다.

## 짧은 핵심

세 경로는 후보를 찾는 방법이며 적합성의 등급이 아니다. 목적 검색에서 나온 제품도 실패 조건을 확인하고, 부품을 찾았다고 완성된 사용 경험을 얻었다고 판정하지 않는다. 경로의 순서나 비중은 고정하지 않는다.

## 대안·기발한 조합

전체 경험이 목적이면 제품군, 필요한 부분이 정해졌으면 동작·실패 조건, 같은 분야 해법의 한계가 반복되면 관계 추상화에서 시작할 수 있다. H: 각 결과에 발견 경로와 실제 책임 범위를 남기는 얇은 검증층은 자체 자료집 없이도 쓸 수 있다.

## 반례·한계

명칭이 같은 reflow 저장소, OCR 부품을 완성 앱으로 읽는 해석, 개인용 예제의 팀 제품 승격이 오탐이다. 검색 반환 창 밖에서 나중에 찾은 후보를 전체 색인 누락으로 세면 안 된다. 순위·recall·실행 우위는 이 두 사례에서 측정하지 않았다.

## 관계

B09의 기존 도구 조합에 함께 쓴다. B07의 사용 단위 판정과 B08의 전이 계약이 검색 후 판단에 선행한다. B13·B14의 검색 지표와 직접 경쟁하는 성능안이 아니며, 특정 검색기 우위를 이 묶음으로 결정하지 않는다.

## 검토

AF-RES-020 내부 별도 검토(같은 모델 계열, GPT-6 Astra Pro)가 원 결과와 하위 근거를 대조했다. 원 연구의 작성자·정답 구성자와 이번 대조자를 구별한다. 각 주장 판정은 `CLAIM_CHECK.json`의 `C-B03-*`로 추적한다. 사람 검토나 외부 모델 재현성 검증은 아니다.
