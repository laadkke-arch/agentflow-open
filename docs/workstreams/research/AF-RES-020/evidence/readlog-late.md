# 내부 읽기 기록 B — AF-RES-011~016

## 범위

지정 고정판의 필수 원 결과19파일과 추가 증거27파일, 합계46파일을 직접 열었다. git show로 읽은 경로·SHA·SHA256·시각·행수는 audit-numeric-late.json의 read_objects에 있다. 자료별 확인 내용과 한계는 sources-late.json의 아래 ID로 연결된다. 외부 원문 재조사와017~019 열람은 하지 않았다.

읽기와 판단: GPT-6 Astra Pro, 같은 모델 계열 내부 별도 검토. 기존 결과의 판정자를 새로운 사람 검토 또는 독립 다른 모델로 바꾸지 않았다. 이번 산술 검증은 기존 결과의 재집계이며 원 검색 실험 재실행이 아니다.

## 재계산과 반증 시도

- 표집 시드·핵심/수치/반례 규칙은 SCOPE.md를 따른다. 각11묶음의3주장, 총33개를 고르고29개에 두 번째 원 증거 파일을 열었다. 최종 선택은 수치·분모·관측 창·판정 주체를 보존한 표현이다.
- 012와014의 N 평균이 슬롯 비율로 읽히는지 반증했다. 각각85→163/216질의·조건,17→11/183질의·조건으로 재집계해 평균과 슬롯 분모를 분리했다.
- 013의 동일한146이라는 숫자가 같은 집합인지 교차표를 만들었다. 교집합142, 각축만4개여서 동일 분모로 합치면 안 됐다.
- 015의 현재무너짐14/195, 후발5/83, 정확답날짜2/77을 원자이유에서 다시 세고 사건 중복·방향 차이를 확인했다.
- 016의 실제코딩 JSON 두 개를 조인했다. 011 S2 comparison0/120 대14/120은 실질재현성 차이이며, S3 contribution198/198 복사는 독립 재검사로 세지 않았다.
- 014의 알려진 반례 두 개를 열었다. GGL의 유효필수충돌과 Word의 극성오독을 같은 오류로 취급하지 않았다. 인라인한계 역시 Librarika11→1과Guacamole10→24를 함께 확인했다.
- 011 CASES의 원문질문·답내용은 새 해석에 쓰지 않았다. 구조집계 탐색 중 outcome dict 전체를 Counter로 출력해 일부 기존 요약필드가 도구출력에 부수노출된 일이 있어 audit-late.md와 수치감사 한계에 남겼다. 그 텍스트를 파일에 복사하거나 개별사례를 새로 코딩하지 않았다.

## 재개 명령

저장소 루트에서 다음 명령은 owned_path의 감사파일만 다시 쓴다. 외부서비스 호출·이전연구 검색재실행은 없다.

```bash
python docs/workstreams/research/AF-RES-020/evidence/audit-late.py
```

입력은 evidence/fixed-inputs.json의 지정 SHA와 원 결과들이다. 결과를 다시 서식화하려면 build-late.py 뒤 audit-late.py를 실행한다. 생성기의 claim 수동문장은 검토후 변경해야 하며 수치통과가 문장진위 자동판정은 아니다.
