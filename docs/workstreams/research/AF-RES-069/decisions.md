# AF-RES-069 · 판단과 선택의 변화

**상태: PARTIAL.** 아래는 연구자의 선택 원장이다. 원 개발자에게 채택을 요청하거나 제품을 수정하지 않았다. 원실험은 `de1727aada52835ebcde4ff1c92c3940db215476`, 입력은 `03d1e436cfa7dc209b57b19508ef4b2e75942824`에 고정되어 있다. 새로움은 명시 사전 노출 이후 처음 읽은 문서·구체 기능에 한정한다.

## D01 · 세 요구의 전향적 선정, 최초판과 관측판 분리

`F1-01/P1`, `F2-04/P2`, `F3-03/P3`를 관측층에 넣었다. 최초 본문 수정 이력을 확인하지 못했으므로 엄격층에는 아무 문제도 넣지 않았다. 이는 0건의 엄격층 성공이라는 관측이 아니라 **엄격층 분모가 없음**이다. 예비 Godot/KiCad 프레임은 세 관측 자리가 채워져 사용하지 않았다.

Inkscape의 첫 적격 판단은 검색 전에 바로잡았다. 문구가 제안되었다는 이유만으로 구현 선택까지 닫혔다고 볼 수 없고, P2의 두 entity 표현과도 같은 기준을 적용해야 했다. 그 과정에 읽은 F3-04는 여분 노출·선별 독해로 남겨 최소수에는 실제 읽은 한 원저작으로 세되 표본으로 교체하지 않았다. 근거는 `evidence/selection-review.json`, `frame.csv`의 원행, `problems.jsonl`이다.

## D02 · P1: 완료 표식이라는 일반 발상을 새 발견으로 세지 않음

사전 선택은 저장부의 완료 구분을 최소 수정하고 재기동 경계를 검사한다는 연구자 가정이었다. A의 공식 매뉴얼은 전환 의도와 CLI·설정층을 제공했지만 구체 영속 표현을 결정해 주지 않았다. B의 첫 다섯 NARA 문서는 보존·처분 규칙이어서 상태 전환 구현과 대응하지 않았다. 검색만으로 선택을 바꾸지 못한 이유를 그대로 둔다.

`A-P1-S03`에서 얻은 enable/disable/lock/unlock은 시험 부품이다. disable 후 무조건 unlock하는 후보는 기존 lock=True 하나로 C1을 깨므로 채택하지 않는다. `B-P1-S01` FAQ15의 완전 복사는 내용 일치이며, 프로그램의 새 항목과 구판 항목을 구분하는 완료 상태가 아니다. 기록의 보존을 올바르게 해도 새 항목을 잘못 잠글 수 있다.

사후 `PS-P1-COMMENTS`에서는 작성자가 이미 완료 표식과 항목별 False 기록을 비교했음을 확인했다. `PS-P1-PR19648`의 setdefault 패치는 더 직접적인 동종 대안이지만 봉인 A 적중은 아니다. PR의 기존 True 보존 코드와 작성자 테스트 보고를 관찰했을 뿐 독립 실행하지 않았다. 고정 head의 회귀 명령과 추가 경계 입력은 `evidence/resume-checks.md`에 있다.

## D03 · P2: entity 모양보다 leaf의 식별·명령·결과 연결을 먼저 확인

독립 Chime 장치 또는 Doorbell 아래 entity는 최초 노출 대안이므로 새 발상이 아니다. A의 `A-P2-S02`가 지목한 기존 Chime volume/action을 먼저 재사용 검토하는 것이 직접적이다. 제조사 문서 `A-P2-S03/S05`는 Mini와 Hub/Pro 연결 절차, Chime의 별도 Sound 조작을 구분한다. 하지만 해당 연결에서 외부 API가 같은 Chime을 발견하고 쓰는지는 미확인이다.

B의 `B-P2-S01/S03/S04`는 각각 역할 분리, ID·능력·native 제어 연결, 질문/답/명령 구분이라는 조건부 원리를 제공한다. 연구자의 다음 시험을 **같은 leaf ID, 요청값, 응답 의미, 실제 상태의 출처**를 나누어 기록하는 방향으로 구체화했다. UI에 leaf가 나타나는 것과 실제 leaf가 움직이는 것은 다른 검사다. 부모 endpoint의 응답이어도 정확한 leaf 결과를 보증한다면 유효할 수 있으므로 위치만으로 배제하지 않는다.

최소 기각 입력은 Chime C의 값2에서0을 요청했는데 Hub가 정확한 `(C,0)`을 echo하고 C는2에 남는 경우다. getter가 요청 캐시0만 반환해도 실제 결과는 여전히 미확인이다. 이는 관측한 장치 고장이 아닌 논리적 반례다. 반대로 실제 결과를 보증하는 setter 계약이 있으면 별도 GET을 무조건 추가할 필요는 없다.

`B-P2-S02`의 leaf는 결정 트리의 결과이므로 물리 장치 연결로 이전하지 않는다. `B-P2-S05`는 동기화 유지 중 역할 변경을 허용하므로 기존 pairing 유지의 근거로 쓰지 않는다. 단어가 겹쳐도 조작과 변수가 다르면 부적합이다.

## D04 · P3: 실제 수정 지점의 가치와 완성 해법 판정을 분리

A가 읽은 소스는 TreeView에서 머리글을 숨기고 세 데이터 바인딩을 이미 갖는다. 따라서 target revision을 확인한 뒤 **기존 표시·제목을 국소 수정**하는 후보가 생겼다. 이를 곧바로 해결 성공으로 세지는 않는다. 읽은 Doxygen/1.4-6과 보고된 e1e8684의 동일성이 확인되지 않았기 때문이다. GTK ColumnViewColumn은 다른 위젯이고 데이터 셀의 ellipsize는 머리글 동작을 보장하지 않는다.

B의 `B-P3-S01/S05`는 짧음만 최적화하지 말고 의미, 가로 폭, 추가 높이를 함께 보라는 조건부 UI 지침을 제공한다. 긴 제목·명확한 약칭·두 줄 제목의 비교 입력은 구체화했지만 수치 폭과 초보자 관측이 없어 하나로 선택하지 않았다. 표시만 켠 뒤 Children이라는 제목이 남으면 C1, 두 줄의 아래 줄이 잘리면 C2가 실패할 수 있다. 역사적 ADD/FIND/HELP 명령메뉴 `B-P3-S04`는 데이터 열 제목의 부품으로 쓰지 않는다.

사후 별도 문맥 판독에서 Tarkan의 초기 ‘원리 지지’ 두 칸과 ‘대상 성공 미확인’ 두 칸의 의미 차이를 확인했다. 원래 점수는 유지하고 `evidence/review-reconciliation.json`에8조건의 대조와2라벨 차이를 기록했다. 서로 다른 판독 범위이므로 일치율·신뢰도 수치로 일반화하지 않는다.

## D05 · 비용 상한의 동일성과 실제 비용의 차이를 보존

각 문제·갈래의3질의·15자리·5최초접근은 지켰다. 동일문서 추가 접근10회를 포함하면 A25/B33이다. 따라서 “같은 비용”의 효과 비교로 수용하지 않는다. 추가 접근을 숨기거나 B 비용을 A와 맞추기 위해 삭제하지 않았다. 실패3건도 접근 비용에 남겼다. 관측된 효과와 지출한 연산의 단위는 `evidence/costs.jsonl`에 있다. 금액·토큰·시간 절감은 미측정이다.

## D06 · 사후 원 개발자 맥락은 검색 성과에 소급하지 않음

P1은 작성자가 이전에 같은 일반 대안을 검토했고 PR도 이미 있었다. P2는 원 신고자가 기준일 전에 장치를 반품했다. open이라는 표지와 실제 개발 선택·채택 기회가 일치하지 않는 반례다. 관리자의 재페어링 제안은 성공 미확인이며 동결 C1 밖이다. P3 댓글은 접근 불가로 미확인이다. 이를 표본을 몰래 교체할 이유로 쓰지 않고 모집의 제한으로 남겼다.

원 개발자의 선행 지식 전체, 실제 채택, 선택 변화는 측정하지 않았다. 읽은 댓글에서 특정 논문이 나오지 않았다고 원 개발자가 몰랐다고 결론내리지 않는다. 원문은 `PS-*` source와 `evidence/postseal-discussion-metadata.json`, `evidence/postseal-pr19648-metadata.json`에 연결되어 있다.

## D07 · 항공의 실제 절차는 사후 보조 비교

`AUX-FAA-01/02`의 수신·의도·지시 확인·실제 상태 구분은 P2의 증거 의미를 점검하는 데 쓴다. 항공 readback을 소프트웨어 상태 getter라고 번역하지 않는다. 정확한 native 제어가 있으면 동종 HA 기능이 더 직접적이고, API가 없으면 FAA 원리가 빠진 기능을 대신하지 못한다. root가 나중에 고른 분야이므로 B 적중0, 원실험 비용 산입0이며 별도3연산을 남겼다.
