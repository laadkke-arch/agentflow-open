# AF-RES-069 봉인 입력 독립 검토

## 판정과 검토 범위

입력 파일 사이의 불일치는 발견하지 못했다. 세 문제의 두 필수 조건은 B의 관계 표현에서도 대체로 보존된다. B에 프로젝트명, 이슈 식별자, 미리 고른 타 분야, 유명 해법 또는 특정 후보 이름을 넣은 흔적은 발견하지 못했다. 다만 P2의 관측 주체가 축약되는 위험과 P3의 한 질의에 추가된 지속 노출 조건은 결과 해석에 남겨야 한다. 원질의를 수정하거나 재검색할 이유로 사용하지 않는다.

- 봉인 커밋: `03d1e436cfa7dc209b57b19508ef4b2e75942824`.
- 이번 검토에서 읽은 파일: `problems.jsonl`, `queries.jsonl`, `arms/A/input.json`, `arms/B/input.json` 네 개만.
- 검토자: `/root/protocol_audit`, 같은 모델의 별도 문맥. 독립 사람 판독이 아니다.
- 검토자는 앞선 모집 판독에서 지정 문제의 제목·본문과 root의 잠정 적격 판단을 보았다. 따라서 문제 선정 판단에 대한 완전 가림은 아니다. A/B 검색 결과, 반환 후보, 원문 열람 결과는 읽지 않았다.
- 이번 검토는 입력 번역과 파일 일관성에 한정한다. 실제 검색 순서, 검색자가 실제 읽은 범위, 검색 도구의 반환 수, 후보의 적합성은 검증하지 않았다.

## 별도로 남길 입력 이상과 주의점

### IA-01 · P2의 관측 주체 축약

`P2-B-Q1`은 `root discovers intermediate device`라고 묻는다. 앞서 읽은 문제 본문에서 기기를 발견하고 진단 파일을 내는 주체는 Home Assistant 연동이며, Hub는 그 연동이 접속하는 중간 구조의 한 기기다. 원문은 진단의 빈 `Chimes` 값을 보고하지만 Hub 자체의 원시 API 응답을 직접 제시하지 않는다.

고정 원장의 경계 입력에도 이미 `root 진단`이라는 축약이 있으므로 전적으로 B만의 새 오류는 아니다. 다만 B 질의는 root 자체가 발견을 수행하는 것으로 읽히기 쉬워 관측자와 제어 대상을 합칠 위험이 있다. 해당 후보가 나오더라도 외부 연동, Hub, Doorbell, Chime의 대응을 분리해 확인해야 한다. 단순히 일반 계층에서 말단을 열거한다는 사실만으로 P2-C1/C2를 충족했다고 판정하면 안 된다. 현재 단계에서는 **잠재 의미 손실**이며 실제 후보의 실패를 관측한 것은 아니다.

### IA-02 · P3-B-Q3의 추가된 지속 노출 표현

`P3-B-Q3`의 `persistent labels`는 고정된 공통 조건에 명시되지 않은 지속 노출의 강도를 더한다. 원문은 열 제목을 요청하고 작은 공간을 언급하지만 여러 노출 방식 중 지속 노출만 허용한다고 별도로 정하지 않았다.

이 표현은 특정 제품·외부 분야·유명 해법의 유입은 아니다. 그러나 질의 한 개의 검색 방향을 좁히는 추가 표현이다. 그대로 실행 결과를 보존하고, 최종 판독에서는 A와 B 모두 봉인된 P3-C1/C2로 판단한다. B 후보에만 지속 노출을 별도 통과 조건으로 추가하지 않는다.

### IA-03 · P3 경계 입력의 연구자 가설 표시가 arm에서 약해짐

원장의 `boundary_span`은 구체 폭과 모호성 시험을 연구자 가설로 표시한다. 두 arm의 경계 입력에는 긴 제목이 넘치는 상황과 짧은 이름이 모호할 가능성이 남지만 이 가설 표시 자체는 전달되지 않았다. 두 입력 모두 원문에 수치 폭이 없다는 제한은 보존한다.

따라서 실제 위젯에서 overflow나 이해 실패를 이미 관측했다고 쓰면 안 된다. 검색 문서에 작은 공간 대응 기법이 있어도 대상의 실제 폭, 글꼴, 언어, 초보 사용자의 이해를 검사한 것으로 셀 수 없다. 이는 두 arm에 공통된 **가설 표시의 약화**이며 B만 조건을 완화한 증거는 아니다.

### IA-04 · A의 특정 위젯 질의는 검증된 현행 구현과 구분

`P3-A-Q2`는 `GTK4 ColumnView`와 `ellipsize minimum width`를 직접 지정한다. 이는 A의 평상시 기술 탐색에 해당하며 B에 이름이 유입된 것은 아니다. 다만 고정 입력만으로 실제 Undo History 구현이 그 위젯을 사용한다고 확인할 수는 없다. `prior_exposure`도 정확한 GTK4 제목 동작과 치수를 읽지 않았다고 기록한다.

따라서 이 질의는 후보 기술에 대한 사전 가설로 취급한다. 질의에 들어갔다는 이유로 실제 사용 기술이 확인되었거나 실행 뒤 처음 발견한 이름이라고 보고하지 않는다. 원질의의 수정이나 검색 결과에 따른 사전 노출 원장 재작성은 하지 않는다.

## 최종 판독에 넘길 경계

B 검색자에게 원장의 `prior_exposure`와 `not_new`가 전달되지 않은 것은 가림을 위한 정보 분리다. 그 자체는 파일 불일치가 아니다. 대신 신규성 최종 판독은 공통 원장으로 해야 한다. P1의 일반 완료 표식, P2의 독립 기기/부모 속성 표현, P3의 열 제목과 짧은 명칭이라는 일반 발상을 새로 얻은 대안으로 다시 세지 않는다.

본 검토만으로 가림 실행의 성공, 검색 적중, 조건 충족 또는 대안의 우열은 확정하지 않는다. 다음 결과 원장에서는 IA-01~IA-04가 실제 판정을 바꾸었는지를 따로 연결하고, 판별되지 않은 부분은 미확인으로 남긴다. 고정 입력 네 파일은 변경하지 않았다.
