# 실행 세부 계약 — 반환 판독 전 기록

- 문제·질의 봉인: `03d1e436cfa7dc209b57b19508ef4b2e75942824`.
- A와 B는 같은 모델의 `fork_turns=none` 별도 에이전트 문맥이다. A는 `arms/A/input.json`, B는 프로젝트명과 원이슈 URL을 제거한 `arms/B/input.json`만 받았다. 공유 파일시스템은 기술적 접근 차단이 아니며 읽지 않도록 지시한 가림이다. 독립 사람 판독은 없다.
- root는 모집/질의 작성자이자 통합 판독자다. protocol_audit은 별도 문맥이지만 선정 당시 root 잠정 판단을 전달받았다. 선정 검토를 완전 가림 검토라 부르지 않는다.
- 실행 단계는 A-P1과 B-P2를 먼저 진행, 그 두 갈래의 작업 완료 후 B-P1과 A-P2, 이후 A-P3→B-P3. 문제 간 동시 실행은 허용하며 한 문제 안의 선후는 홀짝으로 유지한다.
- 각 질의는 `system2_search_query` 한 번. 각 반환 목록의 첫 다섯 원순위를 보존하고 Q1→Q2→Q3 순서로 최초 노출 원문을 고른다. 질의 수정/질의 추가/다른 엔진 재검색 없음.
- 원문 열기는 갈래별 최초 서로 다른 URL 최대 5회 접근 시도로 운영한다. 실패도 한 시도로 소비하며 성공한 다섯 문서를 채우려고 새 URL을 추가하지 않는다. 동일 원문의 find/line 확인은 별도 접근 비용이며 새로운 원문 수에 추가하지 않는다. URL이 달라도 같은 저작/매뉴얼/issue-PR 계보는 독립 독해 수에서 합친다.
- 이 엄격한 5회 접근 운영은 접근 실패에 따른 결손을 드러내기 위한 선택이다. ‘5개 성공 독해를 보장한 검색’으로 보고하지 않는다.
- 검색엔진의 실제 결과 페이지 URL이 도구에서 제공되지 않으면 정확한 tool payload와 tool_query 식별자를 기록한다. Google/Bing HTML 검색 URL을 가짜 실행 URL로 쓰지 않는다.
- root의 tracker 권위 확인은 trial 밖 방법 조사다. A/B에 결과를 전달하지 않고 적중·분모·최소20에서 제외한다.

## 판정 층

1. **반환 자리:** 3질의×5자리×6갈래 = 90 계획 자리. 빈 자리와 중복을 유지한다.
2. **문서 독해:** 실제 본문을 연 원문과 읽지 못한 자리/접근 실패를 분리한다. snippet만으로 적격 처리하지 않는다.
3. **조건별 판독:** 원문이 조건을 지지/위반/판별 불가인지 각각 기록한다. 일반 이름·비슷한 그림·포괄 목적만으로 구조 대응을 승인하지 않는다.
4. **직접 부품:** 현재 대상 환경에서 두 조건을 지지하는 직접 문서가 있어야 하며 실제 실행 미실시는 별도다. 동일 기능명만으로 직접 사용 가능하다고 하지 않는다.
5. **이전 원리:** 원 분야 조작·변수·목적과 대상 관계의 구체 대응, 적용 전제, 최소 기각 반례가 있어야 한다. 대상 프로토콜/저장 형식/실제 폭 등이 미확인이면 조건부 대안으로 남기고 직접 적격 부품과 합치지 않는다.
6. **짝 분모:** 양 갈래를 실행한 관측층 문제와 최초판을 확인한 엄격층 문제를 분리한다. 적격 관측 0과 미확인/미측정은 별개다. 실제 채택·시간 절감·전체 웹 재현율은 조사하지 않는다.
7. **새로움:** 동결된 명시 노출 원장 이후 새로 읽은 문서/구체 기능만을 뜻한다. 일반적인 완료 표식, 부모-자식 표현, 열 제목/축약 발상은 이미 노출되었으며 새 원리 발견으로 셈하지 않는다.

최종 판정 전 root는 원문과 근거 절을 다시 확인한다. 다시 읽은 같은 저작을 추가 독해 한 건으로 세지 않는다. 모든 사후 보조 원문과 댓글/연결 PR 열람은 검색·초기 채점 봉인 후 시행하고 검색 적중으로 소급하지 않는다.
