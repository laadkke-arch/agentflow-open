## Q2–Q4 · 사슬의 단위

- PR이 주 단위, 첫 적격 선례 URL이 사건 단위다. review ID·inline comment ID·commit SHA·source work ID는 각각 다른 자료 단위다.
- baseline: 최초 요구, 작성자, 기존 선택/후보, 테스트 입력·기대값, 원 base/head, 최초 또는 링크 이전 구현, 정확 파일·hunk를 기록한다. author date, committer date, GitHub submitted_at/created_at, 최초 공개 관측 가능한 하한을 각각 기록한다. git 시각만으로 공개 시각을 만들지 않는다.
- exposure: `posted_only`, `author_read_explicit`, `already_known_explicit`, `first_discovery_explicit`, `unknown`. 단순 감사·승인·수정 완료는 해당 자료를 읽었다는 직접 증거와 구별한다. 최초 미인지에는 당사자 표현이 필요하다.
- change: 동일 작성자/타인/미확인, 동일 요구/다른 요구/설명만/변경 없음/미확인을 구별한다. 링크 이후 첫 관련 patch와 테스트의 입력·기대값을 직접 대조한다. commit 작성자와 PR author의 식별이 불명하면 같은 작성자로 승격하지 않는다.
- 엄격 사슬: 링크 전 구체 선택과 역사적 판 → 첫 적격 링크 → 그 자료와 변경을 연결하는 작성자의 명시 발언 → 같은 작성자의 같은 목적 실제 diff → 그 변경에 대응한 시험 또는 merge/배포 근거. 각 고리를 따로 기록하고 한 고리라도 미확인이면 부분 사슬이다. 최초 발견은 엄격 사슬의 별도 더 좁은 하위집합이다. 엄격 관측도 무작위 인과효과로 해석하지 않는다.
- 이전 동일 수정 요청, 기존 실패 시험, CI 실패, 먼저 작성된 commit, 참고문헌 후첨, 링크를 읽고 유지, 유지보수자 대리 구현을 적극 탐색한다.

## Q5 · 관측창·노동·감도

- 주 관측창: PR created_at부터 `min(최초 종결 시각, created_at+90일)`까지. 재오픈 이력이 있으면 최초 종결과 최종 종결을 구별한다. API가 현재 closed_at만 주고 최초 종결 timeline을 복원 못하면 경계 미확인으로 표시한다. 링크·무응답·미병합 모두 같은 규칙.
- 후기 revert/회귀는 별도 tail 기록이며 주 분모에 소급 삽입하지 않는다. 감도는 30일, 60일, 90일 창과 최초 종결/재오픈 후 종결 선택을 계산한다. 창 끝에 걸리는 링크/변경은 날짜와 함께 표시한다.
- 사람 작업 로그(시작·중지·범위·행위자), 본인 명시 소요시간, timestamp elapsed를 분리한다. 수정 commit 수·실제 파일 수·기능 변경·CI 대기·주말을 사람시간으로 환산하지 않는다. 주말도 실제 비작업이라는 관측이 없으면 가능 교란일 뿐이다.
- 절감량은 동등 품질/동일 요구/비교 설계가 있는 사람 시간 쌍에서만 계산한다. 없는 시간/품질 반사실은 미확인. 시간0분으로 코딩하지 않는다.

- 예상: 공개 diff 변화는 노동시간보다 더 잘 남을 수 있다. 반대 예상: 링크가 없어도 수정되고 링크가 있어도 원 설계를 유지할 수 있다. 링크 게시/수정/절감은 각각 다른 주장이다. 양성 수를 맞추기 위해 선정 규칙을 바꾸지 않는다.
