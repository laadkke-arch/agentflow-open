- 각 최초 revision을 읽어 편집할 대상, 관측 가능한 원하는 결과, 구체적으로 수행한 조작이 모두 있는지 판정한다. QGIS는 데이터 처리·편집에 관한 요청을 대상으로 한다. 설치·충돌만의 질문, 기능명만 언급하고 수행 조작이 없는 글은 제외한다. 최초판 태그와 현재 태그를 별도 기록하며 현재 태그로 검색되었다는 한계를 유지한다.

- 초기 판독용 API 필터 `7W-GLRnw_MC-oFjiXW2Yp.*Kixtw9X1Cp_B-Jb`는 점수·채택·답변 수를 제외한다. revision 응답을 기계적으로 최초판에 투영한 뒤에만 판독자에게 출력한다. 전체 응답을 받은 것과 사람이/모델이 후속 내용을 읽은 것을 구분한다.

## 2. 초기 지식과 동일 조작

코딩 단위는 `(객체/레이어, 노드/처리기, 입력 상태/단위, 주요 매개변수, 관측 결과, 판)`이다. `N`=이름 언급, `T`=누르거나 적용해 봄, `O`=같은 입력의 효과를 관측한 명시 기록이다. 조작의 기능적 동일성과 작성자의 인지는 독립 축이다. 도구명이 같다는 이유로 같은 조작으로 처리하지 않는다. 이름이 달라도 동일 입력·변환·결과의 지지가 있으면 겹침을 기록한다. 입력/매개변수/판이 빠지면 완전 동일은 미확인이다. 이미 아는 하위 단위는 전체 제안 사전인지가 아니다. 같은 사건에서 알려진 부분과 새로 배운 부분이 다르면 양쪽 대상을 따로 저장한다. 전체 제안에 대한 명시 사전인지/명시 신규인지 또는 그 동일 조작의 제안 전 실제 수행을 연결할 수 있는 경우만 해당 판정 분모에 넣으며 충돌·부분지식·대상불명은 미확인 분모로 분리한다. 새 조작을 배워 실행했다는 결합 판정에는 같은 주체·조작·제안 이후·180일 안 실행 보고가 모두 필요하다.

## 3. 첫 제안 고정

초기 8자리와 보조 검색 규칙을 커밋·푸시하고 원격 SHA를 확인한 다음에만 타인의 제안을 연다. 최초 글 이후 30일 안의 타인 답과 질문 댓글을 `(creation_date,공개 숫자 ID,원문 순서)`로 정렬한다. 입력에 적용할 연산/단계를 지목한 첫 제안 1개만 선택한다. 한 제안의 두 방법은 첫 방법이 주 단위다. 명확화 질문만으로는 제안으로 세지 않는다. 답변은 가능하면 최초 revision에서 당시 존재한 내용을 복원한다. 현재 편집본만 읽히면 당시 제안 여부를 미확인으로 둔다.

작성자 댓글·자기 답·제안 후 편집은 제안 봉인 전 출력하지 않는다. 초기 수정도 첫 제안 시각보다 앞인 작성자 수정만 별도로 추가하며 봉인한 최초판을 덮어쓰지 않는다. 제안 URL/UTC/첫 방법/당시 링크/달라지는 단 한 부분을 먼저 기록한다. 제안 없음과 동작 미확인도 1자리로 보존한다.

답 생성 뒤 수정에서 조작이 처음 나타나면 그 revision 시각을 조작의 최초 공개 시각으로 사용하고 답 생성시각으로 소급하지 않는다. 시간순 주표의 첫 제안 선정은 원래 기준을 유지한다. 보조 진술이 가리키는 제안이 스레드의 첫 제안과 다르면 두 제안을 구분하고 인지 진술을 무관한 첫 제안에 옮기지 않는다.

## 4. 명시 인지 진술 보조 모집 — 검색 사전과 경계

시간순 8자리와 별개의 목적 표본이다. 대상은 두 사이트의 2024년 공개 답·댓글이며 GN 또는 QGIS 처리 질문과 연결된 작성자 자신의 진술이어야 한다. 최초 질문의 공개 `user_id`와 발언자의 `user_id`를 대조하고 삭제/익명/이름만 같은 사람은 미확인으로 둔다. 첫 제안 및 그 진술의 구체적인 지시 대상을 함께 고정한다.

고정 사전은 Unicode NFKC, 소문자화, 곡선 아포스트로피를 ASCII `'`로 바꾼 뒤 단어 경계를 적용한다. 사전인지 계열은 `already tried`, `already knew`, `already know`, `had already tried`, `have already tried`, `i tried that`, `i knew that`; 신규 계열은 `didn't know`, `did not know`, `wasn't aware`, `was not aware`, `never knew`, `was unaware`다. 단순 키워드 적중은 자격이 아니다. 질문 작성자가 특정 제안의 조작에 대해 말해야 한다. 감사·채택·투표는 인지 진술이 아니다.

검색 범위는 공개 API로 열람 가능한 시간순 모집 프레임의 요청과 그 공개 답(2024년 생성)·요청/답 댓글(2024년 생성), 그리고 공개 검색엔진의 고정 질의 결과다. 엔진은 search_service의 system1_search_query, 1질의당1회 응답(response_length=long), 추가 페이지 없음으로 고정한다. HOST는 순서대로 `blender.stackexchange.com`, `gis.stackexchange.com`이고 각 사이트에서 `site:HOST "PHRASE" "2024"`를 실행한다. PHRASE 순서는 `already tried`, `already knew`, `already know`, `i tried that`, `i knew that`, `didn't know`, `did not know`, `wasn't aware`, `was not aware`, `never knew`, `was unaware`다. `had already tried`와 `have already tried`는 이미 `already tried` 질의/정규화에 포함된다. 곡선/ASCII 아포스트로피는 API본문의 정규화에서는 명시 대응하고 엔진이 같은 검색으로 정규화하는지는 미확인으로 남긴다. 검색엔진은 1회 응답에서 실제 반환된 결과를 모두 기록한다. 각 질의별 응답 경계·검색 시각·순위·실제 열람 여부를 보존한다. 22질의와 API프레임의 페이지를 모두 소진하거나 실패를 기록한 시점에 후보 풀을 닫고, API와 엔진 후보를 합친 뒤 `(발언 생성시각,발언의 숫자 ID,원문 순서)`로 정렬하여 사이트×계열별 최초 적격 1자리, 총4자리를 선택한다. 실패로 핵심 범위가 미완료면 탐색완료 결원으로 부르지 않는다. 동일 사건과 시간순8자리 사건은 건너뛴 사유를 남긴다.

이 프레임은 2024년 전체 댓글 전수 검색이 아니다. 삭제된 댓글·검색 비색인·공개 API 밖의 자료를 복원하지 않으며 전 세계 최초 진술이라고 주장하지 않는다. 검색가능 범위 내 첫 적격이라는 한정과 실제 조회 수를 결과에 쓴다. 이 보조 모집에서 사전인지/신규 인지의 발생률을 계산하지 않는다. 사전을 나중에 넓히면 주표를 바꾸지 않고 별도 탐색으로만 남긴다.

두 계열에 같은 사건이 걸리면 사이트 안 모든 적격 발언을 함께 `(시각,숫자ID,원문순서)`로 정렬하여 먼저 나온 발언의 계열에 사건을 배정한다. 이미 채워진 계열의 사건은 다른 계열에 재사용하지 않고, 한 사건이 두 계열의 슬롯을 채우지 않는다. 아직 빈 계열은 다음 독립 사건으로 진행한다. 동시각·동일 발언 안 두 계열이면 원문에서 먼저 나타나는 적격 진술의 계열을 우선한다. 후보 풀을 닫기 전에 최종4자리를 확정하지 않는다.

## 5. 후속·공식 동작·반례

제안/보조4자리 고정과 원격 확인 뒤 제안 시점부터 180일 이내의 작성자 댓글·수정·자기 답과 직접 연결된 공개 입력/출력을 읽는다. 말(D1), 구현 관찰(D2), 독립 실행(D3)을 섞지 않는다. 같은 사건의 수정과 댓글은 한 에피소드다. 제안보다 먼저 결과가 있었는지, 다른 사람이 실행했는지, 입력·판이 같은지 반대로 점검한다. 감사·채택·침묵은 그대로 기록한다.

Blender와 QGIS 각각 판이 특정된 공식 문서/구현4개, 서로 다른 상류 시험/입출력 예제2개를 읽는다. Calc와 Audacity 각각 공식 설명1개와 별개 원 예제1개 이상을 읽는다. 최초 요청8개를 포함해 고유1차자료 최소24개다. 같은 문서의 앵커·미러·같은 사건의 후속·실패 응답을 추가 고유자료로 세지 않는다. 원 사용자가 제시한 판/제안 당시 이용 가능 판/이번에 읽은 문서판을 나눈다. 공식 동작을 원 사용자 실행 결과로 승격하지 않는다.
