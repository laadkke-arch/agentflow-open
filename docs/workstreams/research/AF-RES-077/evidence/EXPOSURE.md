# 노출과 역할 기록

## 고정된 순서

- 모집판: `b3fee8986841c3dbda82a4a3093d2316c915e9c5`.
- 공통 배경·입력 9자리·원문 보기 6개: `9518c3dccbd21cda72cec715afe47eebd4dba543`.
- A 선택·예상: `7c1df93b11e06ca8b7f44ac5b7ff996879aebd09`.
- B 선택·예상: `7bc2d1f84c04b47711d72e7c110b8f927d97f4ad`.

각 A/B 판독자는 새 `fork_turns=none` 문맥에서 같은 대상의 common 파일과 해당 보기 파일만 읽었다고 기록했다. 6건 모두 추가 원문 열람은 0이다. 공통 파일의 해시가 같고, 입력과 대상판을 바꾸지 않았다. SC-A는 두 파일의 해시를 읽은 내용/제공 해시로 재구성했으며 root가 실제 파일 SHA256과 대조해 일치를 확인했다. 나머지 판독자는 읽는 시점에 직접 해시를 계산했다.

## 독립 효과로 해석하지 않는 이유

root는 모집·원문 선정·발췌·최종 비교를 맡았고 처음부터 사용자 지시의 경쟁 구현 예시와 제공 외부 원전의 이름을 알았다. 모집 담당 3명에게는 프로젝트별 모집 임무를 줬으며 전체 경쟁 예시를 전달하지 않았다. A/B 판독자는 root나 모집 담당과 다른 새 문맥이지만 같은 모델 계열이다. 사전학습에서 원전을 접했는지는 6건 모두 측정할 수 없다. 사람의 독립 표본, 무작위 배정, 인과 효과나 원 개발자의 시간 절감으로 읽어서는 안 된다.

root는 자료 수집 중 웹 검색 결과에서 Sigil 0.9.18 수정, 1.4.0 중복 ID, 1.4.3 fragment 회귀 및 Shotcut 26.1 관련 짧은 결과 요약을 B 봉인 전에 보았다. 원문 결말과 패치는 당시 열지 않았고, 이미 봉인된 입력·발췌를 변경하거나 판독자에게 요약을 전달하지 않았다. 그래도 root까지 완전한 결말 맹검이었다고 주장하지 않는다. 사후 공개 원문 검산은 B 원격 봉인 뒤 시작했다.

B 역할 지시에는 공여 원리가 역연산/복구를 뒷받침하지 못하면 기각하라는 문구를 명시했다. A/B 역할 지시 전체가 바이트 단위로 동일했다는 증거는 남기지 않았다. 동일한 common·질문·입력과 원문 예산을 공유한 기술 대조로 한정한다. source-only 효과를 분리할 통제는 부족하다.

각 보기 1저작·최대2절·2,000 Unicode 문자 상한, 추가 열람0이라는 예산은 같았다. 실제 원문 문자수는 SC 1410/1517, MS 949/1571, SG 1234/1824로 같지 않다. common·URL·메타데이터도 실제 노출이므로 VIEWS/COSTS에 별도 기록한다. 현대판을 과거 개발자의 당시 접근 자료로 간주하지 않는다.

결과의 단위는 3개 보조 사례의 봉인된 첫 선택이다. 이후 root 재판독과 사후 조사자는 원시험 검산자이며 새로운 독립 판독 표본이 아니다. 동일인이 검색과 재검토를 수행한 범위는 SELF_CHECK에 명시한다.
