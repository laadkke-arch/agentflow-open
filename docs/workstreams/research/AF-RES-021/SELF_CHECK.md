## 검사와 검증 범위

- [검증 기록](evidence/verification.json)에 정확한 SHA, 종료 코드와 입력 검사를 연결했다. 새 캐시에서 38개 원본을 확인한 뒤 카드·기본 로그의 바이트를 일치시켰다. 네 실행의 전체 로그 또는 SHA 및 1,560 CSV 행을 재생했다. 표 첫 4개와 끝의 정확히 3개 데이터 행을 스크립트로 확인했다. [재생](replay.py) · [검증](evidence/verify.py)
- 출처는 산입 46개다. 공개 원 질문 12, 공급자 고유 원문 26, 타 분야 원문 8이다. 같은 사건의 답, 버전 중복, 초록, 실패 주소, 후보 제외, 릴리스 시각만 본 메타데이터는 분리했다. 문서 해시와 고정 파일 내 근거 행 범위는 검사했다. CMake 심층 reply URL의 Web 도구 접근 실패 때문에 직접 읽은 스레드 주소와 게시 번호를 함께 둔다. [출처 원장](sources.json)
- 공통 `cloud_check`는 결과 커밋 `4b384be7dafb6bee975f532b0a17f9b5769d74ff`에서 종료 0이다. 그 실행의 전역 manifest 발견은 `no_active_sessions`였다. 이 경로의 개별 `workbench.session check ... --fetch`를 따로 실행해 통과했다. 판독 자체의 독립 검토나 사람 판독은 미실시다.
- 최종 상태는 `REVIEW_READY_WITH_GAPS`다. 상세 편집 이력, 판독기에 주어진 원 질문 범위, 더 엄격한 근접 표본 수와 실제 세부 모델 표기가 남았다. 성공률 값을 수용의 필수 통과 기준으로 사용하지 않았다. [수용 근거](evidence/acceptance-evidence.json)
