## 표집과 관측 창

- 2019-01-01~2024-12-31 UTC에 게시된 pytest, CMake, HTTPX 공개 지원 질문을 목적 표집한다. 질문 최초 시각으로 정렬하고 프로젝트당 3개 이상, 전체 선택·특정 기능 각각 4개 이상을 확보한다. 전체 선택은 배포·생성·클라이언트 수명 같은 완결된 접근이나 작업 경로의 선택이다. 부분은 옵션·동작·API 적용 같은 단일 기능이다.
- 공식 프로젝트 포럼·이슈·토론에서 요구가 읽히고 당시 유효한 판을 고정할 수 있으며 실사용 대안 또는 시도와 당시 판 문서가 있는 사례를 먼저 본다. 버전 미기재는 게시 시점의 명시적인 비교판을 택하고 실제 실행 버전의 미확인을 남긴다. 마지막 공개 수정과 최초 답을 비교한다. 최초 문장이 확인되지 않으면 그 상태를 표시하며 원판 복구 성공으로 산입하지 않는다. 포럼에서 확인한 수락·자기 성공 보고·거절과 일반 조언을 구별한다. 2025년 이후 답을 역사 판정에 보태지 않는다.
- 질문·초안에는 게시 원문 주소와 소량의 원문 표현, 필수·선호·불필요/금지·범위 축을 기록한다. 각 후보는 실제 제안·시험·진지하게 제시된 대안이 출발점이다. 비교 가능한 공식 대안을 추가할 때 사례 원장에 기원을 표시하고 자연 근접 오답 수에서 제외한다. 한 후보를 서로 다른 적용 조건에 쓰면 별행이다. 질문과 후보의 단위 수는 각각 그대로 보존한다.
- 언급 없음·근거 범위 부족은 보류. 근접 오답은 실제 스레드의 제안/시도를 공식 판에서 검토해 명시 필수 조건 하나의 충돌을 확인한 행이다. 여러 필수 조건에 실패하거나 핵심 나머지 조건을 확인할 수 없는 행은 수에 넣지 않는다. 새 위치·버전 오류 주입은 진단에만 사용한다. 013·011·017 표본과 018의 산출물은 이 표집에 쓰지 않는다.

## 동결된 처치와 판독

- 공통 항목은 동일 질문 발췌와 제약, 후보 ID, 제안 사용과 짧은 설명 문장, 같은 고정판의 문서 URL 하나다. A는 URL, P는 같은 URL에 절 위치 후보 목록, M은 P와 동일한 목록에 후보 사용 및 요구 ID와 위치 간 간선을 부가한다. 링크 토큰을 포함해 카드당 256개 이하의 공통 규칙 토큰을 허용한다. 빈 예산을 채우는 문장은 추가하지 않는다. P/M은 매 후보의 공통 직렬화, 위치 집합 및 순서를 비교하고 해시로 남긴다.
- 문서 원시 바이트 SHA-256을 고정한다. Markdown 제목, RST 제목/밑줄, Python AST의 모듈·클래스·함수/메서드 경계에서 나눈 뒤, 긴 절은 시작부터 같은 32 물리행 단위로 분할한다. 빈 조각은 제외한다. 고정 행 범위를 위치 ID로 사용한다. 공통 색인은 제목·문서 이름·행·URL이다. 판독 단계는 본문을 색인에서 찾을 수 없으며 읽은 절만 절 파일에서 취득한다.
- 시드 `210922`. 질문은 게시 UTC 순서, 후보는 질문 안에서 시드·ID의 SHA-256으로 한 번 섞어 공통 사용. 공통 정규화는 소문자, 식별자·옵션·숫자 보존, 단순 영문 복수형 제거. 제목 어휘 점수는 후보 식별자 3, 요구 원어/공개 설명 2, 질문 원문의 기타 어휘 1. 동률은 시드·질문·후보·절 ID 해시 순서다. A는 URL 문서에 속하는 공통 색인에서, P는 위치 목록에서, M은 같은 목록에서 필수 조건 및 제안 사용에 연결된 위치를 우선한 후 같은 점수 및 동률 규칙으로 선택한다. M에서 필수 연결 우선, 그 다음 제안 사용 연결, 그 다음 미연결 순이다.
- 최대 네 절을 실제 읽어 순서와 제외 사유를 보존하며, 1·2·4절은 한 로그의 접두사로 채점한다. 절 읽기 실패도 시도 예산과 분모에 남긴다. 읽은 본문의 단락/문장에 후보 이름 또는 절 제목과 요구 표현이 함께 성립하고 공통 긍정·부정 술어나 예시 호출이 나타나는지를 확인한다. 명시 충돌 하나는 충돌, 모든 필수 조건에서 지지 단서가 있을 때 지지, 나머지는 보류. `not required`류는 조건 부재와 허용의 혼동을 피하도록 별도 보존한다. 동일 후보가 여러 조건을 만족하려면 각 필수 조건을 실제 읽은 절에서 확인한다. 블라인드 규칙이 내린 결론을 원문 판정으로 간주하지 않는다.
- 공식 키는 당시 판에 대한 지지·충돌·보류와 허용 근거 위치 집합을 사람이 감독하지 않는 연구 편집 단계에서 작성한다. 역사 키는 해당 요청자의 수락·성공·거절 기록과 위치 및 거기에 대응하는 공식판의 허용 위치를 함께 기록한다. 역사 답 자체는 판독기 문서에 없다. 역사 지지 근거 회수는 수락된 **사용**의 공식판 근거를 읽고 지지 판정했는지를 의미한다. 역사·공식이 모두 보류여도 분모를 유지한다. 필수 근거가 여럿이면 한 허용 집합의 전체가 도달해야 한다. 재생의 지지 단서 절과 집합의 교집합을 확인한다.
- 지지 근거 회수, 근접 오답의 지지 판정, 실제 지지에 충돌 판정, 보류 및 키 근거 미도달을 각 분모로 비교한다. 회수 성공당 열람은 **실패·보류를 포함한 총 열린 절 / 성공 수**다. 0 성공은 정의하지 않는다. 조립 비용은 열람 페이지·연결·수정 횟수 및 측정된 도구 시간, 판독 비용은 열린 절·오류·검열이다. 사람 시간은 관측하지 않는다.
- 사전 판정 기준은 동일 예산의 공식 지지 근거 회수 M−P 증가 및 근접 오승인 비증가다. 공식과 역사의 방향이 다르거나 질문별로 이득이 편중되면 유보한다. P−A만 증가하면 링크 위치 효과까지만 인정한다. 자연 근접 또는 지지 분모가 각각 12 미만이면 그 효과값은 탐색적이다. 비용 상쇄는 추가 작성량을 관측한 단위로만 평가한다. 사람·검색 전체·H2로 확대하지 않는다.
- 민감도에서는 P/M 순서만 시드로 바꾼 재생, M 간선 제거, 같은 문서에서 존재하는 다른 위치로 M 간선을 옮긴 별도 재생을 수행한다. 진단은 주실행과 다른 파일 및 행 태그를 갖는다. 편집자가 내용을 아는 위험과 판독기의 기계적 우선을 기록하며 평가 결과를 본 뒤 규칙을 조정하지 않는다.

## 입력 분리와 이력

1. 원문 탐색과 질문 확정. 질문·사용 문장과 후보 선택에 역사 답이 필요한 경우 편집자가 읽고 그 영향을 기록한다. 카드 생성에는 `cases.jsonl`, `evidence/card-plan.jsonl`, 공통 문서 색인만 허용한다.
2. 카드·질문·문서 원장과 별도 `keys.jsonl`을 묶음 단위로 동결한다. 판독 프로세스에 `cases.jsonl`의 공개 필드 투영, `packets.jsonl`, 공통 색인과 고정 절 파일만 전달한다. 원 답, 출처 원장에 든 판정, 키는 전달하지 않는다. 판독 스테이징에 실제 복사한 파일명·SHA-256 및 판독 로그 해시를 기록한다.
3. 4절 판독 로그가 묶음마다 저장된 뒤에만 채점기가 `keys.jsonl`과 로그를 읽는다. 입력 공개 시각, 명령, 버전 및 실패/수정의 경위를 보존한다. 동일 연구 에이전트가 편집과 검증을 담당할 때 사람 맹검이나 독립 검토로 취급하지 않는다.

## 판독 후 관측 범위

공통 카드 URL은 행당 하나다. 여러 페이지가 필요한 키 묶음은 근거 접근이 구조상 불가하더라도 분모에 남겼다. 규칙 판독과 편집자·사람 판독의 효과를 분리했다. 편집자는 제안 사용을 만들기 위해 답과 문서를 읽었다. 실제 판독 프로세스는 키가 물리적으로 들어 있지 않은 임시 디렉터리에서 `python -I`로 실행했다. 이 실행에 운영체제 권한 경계를 따로 만들지는 않았다.

공개 질문은 게시 시각으로 정렬했고 실제 검색·다운로드 순서는 검색 결과와 전송 배치 순서를 따랐다. 상세 편집 이력 확인과 필수 조건의 원 저자 의도는 별개의 확인 항목이다. 작업의 모델 표시 이름을 실행 환경에서 확인할 수 없어 계열만 적었다.
