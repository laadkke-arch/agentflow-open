# Cargo 후보의 가린 교차 판독

**33개 후보 키, 37개 인용 묶음, 필수 술어 156개를 판독했다. 모든 필수 조건을 원 열람 묶음과 반환 인용만으로 확인한 묶음은 각각 0/37이다.** 이는 유용한 부분 선례가 없다는 판정이 아니다. 상위 3개 선택, G/R 경로, 순위와 연결되지 않은 판독이며 경로의 승패는 여기서 계산하지 않는다.

## 입력과 독립성

허용 입력은 `blind/cargo.jsonl`, 그 패킷이 지정한 Q05–Q08 최초 설계 전문, 패킷에 인용된 원문이다. 입력 SHA-256은 `857659268178a06680bc4054756879abc9ec220ff04a5139c4dc60a063b9e062`다. 최초 전문 네 개를 전부 읽었다. Cargo 검색 로그·원 반환·후속 결정·정답 대응표·다른 판독자의 결과·도서관/제조 보조 원문은 열지 않았다.

가림은 경로와 순위에 적용되었다. 패킷의 `required_bundle` 기존 판정 및 관측 한계는 보였으므로 기존 판정까지 가린 실험으로 부르지 않는다. 이 작업은 **같은 표시 모델의 별도 에이전트 판독**이며 사람의 독립 검증이 아니다. 첫 큰 출력이 잘린 이력과 가림 재점검 중의 중지는 `mask-exposure.json`에 남겼다. 부모가 Cargo 패킷의 경로 문자열 누수는 없다고 확인한 후 해시를 재확인하고 재개했다.

## 결과를 읽는 법

`reviews.jsonl`의 각 후보에는 사용 경계, 공급자 관측, 연구자가 제안한 사용, 반례와 한계가 분리되어 있다. 각 인용 묶음은 별도로 판독했다. 다른 묶음의 문서나 실패 후 나중에 확보한 자료를 전달하지 않았다. 열린 적 없는 Bazel 7.3.0 묶음은 빈 묶음으로 유지했다.

- `status`: 현재 확인한 해당 술어의 supported / conflict / unknown 판정.
- `support_in_original_opened`: 패킷의 원 열람 위치에 필요한 근거가 있는가.
- `support_in_original_citations`: 원 반환의 URL과 절만으로 해당 조건을 확인할 수 있는가.
- `opened_complete`, `cited_complete`: 위 불리언이 모든 필수 술어에서 참인가.
- `audit_opened_complete`: 추가 감사 판독을 포함해 모든 필수 조건이 확인되었는가.

추가 감사 원문의 ID는 별도 `fresh_audit_source_ids`로 기록했다. 추가 절이 원 반환의 누락을 소급 보완하지 않는다. 원 반환에 채택되지 않은 후보를 이번 판독 때문에 반환 성공으로 승격하지 않는다. 그 선택 여부는 가려져 있어 추정하지 않았다.

판독 집계는 supported 술어 31, conflict 12, unknown 113이다. 묶음 단위로 conflict 8, unknown 29이며 모든 조건이 충족된 묶음은 없다. 유용한 일부 근거는 보존되지만, 같은 단어·목적이나 부분 기능의 존재만으로 결합 조건 전체를 통과시키지 않았다. unknown은 기능 부재의 단정이 아니다.

## 직접 재확인한 핵심 경계

1. **사용자 매핑의 우선순위.** BUILD_PATH_PREFIX_MAP은 생산자가 오른쪽에 새 값을 덧붙이고 오른쪽 매핑을 우선한다. 기존 사용자 값 뒤에 자동 값이 붙는 반례가 성립한다. 초안 지위 자체를 탈락 이유로 삼지 않았다. `RVC-003`, [생산자·소비자 규칙](https://reproducible-builds.org/specs/build-path-prefix-map/).
2. **명시한 이름과 평범한 검색의 차이.** webpack에서 정의되지 않은 alias는 node_modules로 해석될 수 있다. 이 동작은 요구된 필수 base 오류와 다르다. `RVC-002`, [resolve.alias 표](https://webpack.js.org/configuration/resolve/).
3. **한 번 처리함과 출력 재입력 금지의 차이.** trace 변환 모델은 생성한 target을 뒤의 match 문맥으로 사용할 수 있다. 중복 match 실행 방지만으로 출력의 재사용이 배제되지 않는다. `RVC-008`, [§2.5.1](https://link.springer.com/article/10.1007/s10270-020-00791-9).

인증에서는 최초 설계의 모든 리다이렉트 대상에 대한 토큰 제거를 유지했다. cross-host 조사만으로 이 조건을 인정하지 않았다. Bun의 HTTP 토큰 사례는 사용자가 보고한 반례이며 재현·공급자 확인으로 승격하지 않았다. 코드의 prefix-list 우선순위는 실제 드라이버가 그 순서로 옵션을 넣는다는 증거와 구분했다.

## 감사 비용과 원문 수

원문 URL 10개를 직접 다시 열었다. 도구 open 요청은 14회이며 이 중 네 번은 같은 논문의 추가 절 열람이다. 실패·재시도와 새 검색은 각각 0회다. 요청별 실제 시간과 응답 해시는 `receipts/`에 있다. 요청 벽시간 합은 6.873초이며 병렬 실행이 포함되어 전체 경과시간 또는 인시로 해석할 수 없다. 토큰·청구 비용·절감 인시는 관측되지 않았다.

`sources.json`의 RVC-001–010은 모두 이미 집계된 원문 계보의 재열람이므로 고유 외부 원문 최소수에는 더하지 않는다. 고정되지 않은 최신 문서, 사용자의 문제 보고, 아직 실행하지 않은 반례는 각각 구분했다. 현재판의 판독을 과거 이용 가능성으로 소급하지 않았다.

## 재집계

저장소 루트에서 실행한다.

```sh
python docs/workstreams/research/AF-RES-025/reviews/cargo-by-jupyter/validate.py
```

판정은 `reviews.jsonl`의 수동 판독으로 고정한다. 이 명령은 키·조건 분모, 근거 위치의 원 패킷 일치, 불리언 집계, 영수증·출처 스키마를 확인하고 `review-summary.json`을 재집계한다. 판단 자체나 실제 프로그램 동작을 자동 검증하지 않는다.
