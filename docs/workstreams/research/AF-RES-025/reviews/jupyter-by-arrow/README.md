# Jupyter 후보의 가린 교차 판독

판독자: `arrow_agent_same_model`. 다른 검색 stream을 맡았던 동일 모델의 별도 에이전트 판독이며, 사람에 의한 독립 검증이 아니다. 판독일은 2026-11-22 UTC다.

## 고정 입력과 결과

입력은 `blind/jupyter.jsonl`의 35개 키, 거기에 지정된 Q09–Q12 최초 설계 전문, 패킷이 인용한 원문으로 한정했다. 입력 SHA256은 `60d0dcfafa3297f8e572aa5fc41617e302df3130b58412b105d61e948e6bc524`다. 최초 가림 커밋은 `a2231c43c1dac665e5dd296869a600181153c712`이며, 다른 stream의 추가 가림 커밋 `64f2db1004d5e40842a6f347a835964bcb8503ef`에서도 Jupyter 입력의 바이트는 같다는 root 통지를 받았다. 이 판독은 원격 확인 작업을 대신하지 않는다.

`reviews.jsonl`에는 35개 후보, 37개 인용 패키지, 101개 필수 조건 판독이 있다. 패키지별 조건은 원래 인용 묶음 안에서 평가했다. 이 범위에서 전체 조건이 뒷받침되는 것은 현재 ipykernel 수신 어댑터 1개다. 이는 검색 경로의 승패나 당시 이용 가능성 판정이 아니다.

| 질문 | 후보 키 | 인용 패키지 | 전체 supported | hold | near_miss |
| --- | ---: | ---: | ---: | ---: | ---: |
| Q09 | 8 | 10 | 0 | 8 | 2 |
| Q10 | 9 | 9 | 0 | 9 | 0 |
| Q11 | 10 | 10 | 1 | 5 | 4 |
| Q12 | 8 | 8 | 0 | 5 | 3 |
| 합계 | 35 | 37 | 1 | 27 | 9 |

조건 단위로는 supported 25개, unknown 66개, conflict 10개다. 패키지에 담긴 URL은 최대 2개이므로 이 입력에는 별도의 3 URL 제한으로 잘리는 패키지가 없다. 같은 키의 패키지가 여러 개인 경우 합치지 않고 각각 판독했다.

## 판정 필드의 뜻

`predicate_reviews.status`의 supported는 해당 후보가 제안한 사용 경계에서 필수 술어를 지지하는 근거가 원 패키지에 있다는 뜻이다. unknown은 누락·미확인이고, conflict는 제안된 사용을 깨뜨리는 명시된 경계 또는 논리적 반례가 있다는 뜻이다. 결함이 없다는 확률이나 실제 제품 적합성의 절대 점수로 해석하지 않는다.

`support_in_original_opened`와 `support_in_original_citations`는 각각 그 조건을 원 열람 묶음과 원 반환 인용으로 확인할 수 있는지 나타낸다. `opened_complete`와 `cited_complete`는 모든 필수 조건이 각각 충족되는 경우만 true다. 근거 묶음의 항목이 목록에 포함되었는지만 따지는 별도 필드가 `bundle_open_coverage_complete`와 `bundle_citation_coverage_complete`다. 이 입력의 37개 패키지는 목록 포함 기준으로 모두 완전하지만, 그 사실이 조건의 충족을 뜻하지는 않는다.

각 true의 `source_ids`, `urls`, `sections`, `original_evidence_locations`는 패킷의 원래 값을 그대로 쓴다. 감사 원문 `RVJ-*`는 그 배열에 끼워 넣지 않았다. 새로 확인한 위치가 원 인용 밖이면 그 위치로 원 인용의 결함을 고치지 않는다. `fresh_success_source_ids`로 어떤 패키지를 직접 재확인했는지 구별한다. 특히 Google Pub/Sub의 두 패키지 중 재열람한 것은 subscription-overview 쪽이며, 다른 개요 패키지를 합쳐 보강하지 않았다.

패킷에는 원래 top 3 반환 여부를 드러내는 필드가 없다. 따라서 이 판독은 어떤 opened-only 후보도 반환 적중으로 승격하지 않는다. root가 봉인된 반환 매핑에 연결해야만 실제 반환 분자를 계산할 수 있다. 원 G/R 경로, 순위, 당시 return 여부를 이 파일에서 추정하지 않았다.

## 중요한 판독 경계

**ipykernel (`B-4f391993bf95`).** 현재 `execute_request`는 같은 메시지의 코드와 root metadata를 분리하고 지원하는 `do_execute`에 `cell_meta`를 전달한다. 제안한 root-metadata client와 하위클래스 경계에서는 세 조건을 모두 충족한다. 반면 최초 설계 예시처럼 `content.metadata`에만 넣으면 현재 코드가 그 값을 읽지 않는다. 파일 metadata의 자동 전송, 모든 kernel 지원, 2021 당시 태그까지 인정한 판정은 아니다. 최초 문서는 Jupyter를 명시하지만 ipykernel 이름은 명시하지 않으므로 새 부품과 새 제품을 세는 단위도 구별해야 한다. 근거: 패킷 `S-32e7dea464dc`, 감사 `RVJ-006`.

**포트 설계 선례.** Node의 bind→주소 조회→IPC 회신, RFC7605의 bind→파일/IPC 전달, SOCKS의 BIND 회신 및 PCP의 확보→회신→게시 관계는 일부 조건을 뒷받침한다. 구현이나 Jupyter adapter가 없다는 이유만으로 설계 선례를 배제하지 않았다. 그러나 다중 커널·채널 식별과 후속 클라이언트 재사용은 여전히 전체 질문의 별도 조건이다. RFC7605 패킷의 ‘§6’ 표제는 실제로 §7.1이다. 함께 적힌 p9–10/L500–555로 해당 위치를 찾을 수 있어 P1/P2의 근거를 무효화하지 않았다. 근거: `B-a130cf2b54b3`, `B-b086270464d1`, `B-8dab70c937e3`, `B-e4a22ebb5c04`; 감사 `RVJ-003`–`RVJ-005`.

**구독 준비.** WebSub의 callback challenge는 202보다 강한 관측이지만, subscriber가 echo를 보낸 순간 hub의 검증·상태 변경이 완료됐다는 관측까지 제공하지 않는다. SAS의 READY는 입력 발행을 기다리게 하는 선례지만 ACK 연결의 관측 및 1입력:1출력 보장을 셀 실행의 가변 출력에 그대로 옮길 수 없다. publisher라는 단어만 보고 주체 불일치를 단정하지 않았다. OGC의 비규범 표지는 탈락 사유로 삼지 않았으며, 등록·매칭 barrier와 실제 통지 경로의 준비가 같은지 보류했다. OGC PDF의 독립 재확보는 실패했다. 근거: `B-e148d3383916`, `B-eb88c394616d`, `B-06b02d84d2b9`; 감사 `RVJ-001`, `RVJ-002`, `RVJ-010`.

**매개변수 실행기.** NVIDIA는 사용자 입력과 template 실행 연결이 가깝지만 선택 뒤 새 kernel.json과 Launcher 항목을 생성하므로 명세 증가를 피한다는 조건과 충돌한다. CTX와 Cosmo Tech는 template·실행값 분리와 args/env 적용을 제공하지만 사용자에게 입력을 요청하고 선언된 허용값으로 검증하는 전체 입력 경계의 인용이 부족하다. JSON Schema 자체는 최초부터 명시된 입력 부품이다. 근거: `B-836354c77778`, `B-28640fb5042b`, `B-f0752e922f0e`, `B-8add6c6d3c45`; 감사 `RVJ-007`–`RVJ-009`.

## 직접 재열람과 비용

추가 검색 질의는 0회다. 원문 감사는 웹 open 18회와 동일 URL HTTP GET 1회, 합계 19회다. 13개 원 URL을 시도해 12개 URL의 본문을 직접 읽었다. CTX의 두 문서는 같은 제품·메커니즘 계보로 기록한다. 모두 기존 후보 원문의 재열람이므로 외부 최소 원문 수에 추가 가산하지 않는다. 자료별 날짜·판·읽은 위치·관측·한계·계보는 `sources.json`에 있다.

실패 3회는 모두 같은 OGC PDF URL이다. 첫 웹 요청은 403, HTTP GET은 200이지만 PDF가 아닌 repository HTML, 마지막 웹 요청은 읽을 행이 없는 HTML이었다. `requests` 모듈 부재는 네트워크 요청 전 준비 실패이고, 한 번의 캐시 저장 명령 길이 초과는 원문 요청 재실행 없이 개별 저장으로 복구했다. 이러한 로컬 실패를 원문 열람 성공으로 세지 않았다.

각 요청의 관측 시간 합은 17,539 ms다. 독립 요청을 병렬 실행했으므로 이것을 전체 조사 벽시간으로 합산하지 않는다. 최초 감사 요청 시작은 05:34:27.833 UTC, 마지막 완료는 05:39:23.922 UTC이며, 그 구간 전체를 작업 시간이나 인시 절감으로 환산하지 않는다. 토큰·인시는 제공되거나 관측되지 않았다. 원 요청, 시각, 해시와 실패는 `receipts/`에 있고, 긴 응답 캐시는 `.gitignore`로 원격 산출물에서 제외한다.

## 가림과 독립성의 한계

Jupyter의 raw return/search log, 경로 매핑, 다른 판독자의 결과, 후속 결정 및 도서관·제조 보조 사례는 열지 않았다. 실제 G/R 문자열이나 원 순위는 인지하지 못했다. 그러나 패킷 `proposed_uses`의 ‘반례’, ‘보류’, ‘혼동’ 같은 표현은 앞선 연구자의 해석을 암시한다. 또한 직접 재열람하지 않은 후보는 패킷의 공급자 관측에 의존한다. 따라서 완전히 새로운 원문만으로 진행한 이중 맹검이나 사람의 독립 검증으로 부르지 않는다.

root가 추가 예시로 제시한 Solace/PubSub+는 35개 패킷에 없었고 이후 잘못된 예시라고 정정했다. 이를 검색하거나 새 후보로 만들지 않았다. 일부 페이지의 인접 절에서 보인 Node BoundSocket, NVIDIA Kernel Starter 및 Datalayer의 다른 backend 이름은 원 후보·원 인용에 추가하지 않았다. `receipts/mask-exposure.json`에 이 노출을 남겼다.

각 행의 counterexample은 그 판독을 깨뜨릴 수 있는 연구자의 논리적 사례다. 재현 프로그램을 실행하거나 실제 장애를 관측했다는 뜻이 아니다. 현재 main 문서와 현재 문서판의 관측으로 최초 설계일의 출시 가능성을 소급하지 않았으며, 당사자가 최초 문서에 적지 않았다는 이유로 몰랐다고 추론하지 않는다.

## 재집계

저장소 루트에서 다음 명령은 네트워크 없이 같은 가린 입력과 수작업 판독 내용을 다시 조합한다.

```bash
python docs/workstreams/research/AF-RES-025/reviews/jupyter-by-arrow/build_sources.py
python docs/workstreams/research/AF-RES-025/reviews/jupyter-by-arrow/build_reviews.py
```

`build_reviews.py`는 입력 해시, 35개 키, 조건 수 및 원 인용 위치의 포함을 검사한다. 반환 경로·순위·원래 선택 여부의 join은 의도적으로 수행하지 않는다. 다음 행동은 root가 이 판독을 봉인된 매핑과 연결하고, 자기 판독과의 불일치 및 당시판 확인을 별도 단계에서 다루는 것이다.

## 추가 익명 관계 점검

위 Jupyter 판독을 저장·검산한 뒤 root가 별도로 승인한 `relation-check/cargo-anonymous.json`의 REL-01–03만 읽었다. 입력 SHA256은 `234c9943541951f6ad67bdbd73aaaf58e1c928db4e6440f81bea049999b765e6`다. 원 출처, 분야, 검색 경로를 추정하거나 원 Cargo 결과를 읽지 않았고 추가 검색도 하지 않았다.

`relation-check.json`은 상태에 따른 적격성·갱신, trace와 규칙별 일회 적용, 합집합의 보존·멱등성이 각각 어디까지 대응하는지와 그로부터 따라오지 않는 실행 정책을 기록한다. REL-03은 정확히 a·b·c 세 기호로 나중 버전 억제 및 출력 재입력 금지가 대수 법칙에서 나오지 않는 반례를 제시한다. 이 논리 점검은 실제 원 시스템의 실패 관측이나 원 검색 적중의 변경이 아니다.
