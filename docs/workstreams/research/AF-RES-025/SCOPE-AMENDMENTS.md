### 전문 보존과 노출

메일 본문은 공개 아카이브라는 이유로 대량 재게시하지 않았다. 원 Message-ID·raw URL·SHA256·`restore_inputs.py`를 커밋하고, 동일 전문을 다시 받아 4/4 해시 일치를 확인했다. 전문 읽기 캐시는 Git에서 제외했다. 다른 8개 초안은 MIT/BSD 라이선스와 원 출처를 함께 보존한다. 재복구가 막히면 해시를 바꾸지 않고 해당 입력을 미확인으로 둔다.

각 G/R 작성자는 동일한 최초 초안 전문을 읽고 질의를 만들었다. 후보 검색 결과에서 새 후보명이나 후대 답을 가져와 질의를 고치지 않았다. 공유 모델의 사전 지식과 원장 상태·일부 후속 노출은 각 stream의 exposures 원장에 보존한다. 이를 제거한 맹검이라고 주장하지 않는다.

검색 설정은 영어·`system1_search_query`·공개 웹·`response_length=long`이다. 도구가 제공한 순위를 기록하며 검색엔진의 절대 순위라고 단정하지 않는다. 질의당 최초 10개 이하만 선택 대상으로 삼고, 10개 미만이면 제공 부족을 표시한다. 토큰·과금·인시는 도구가 제공하지 않으면 추정하지 않는다.

## 2026-11-22 05:14:22 UTC — Q08 적격성 정정

최초 전체 봉인 영수증은 `evidence/input-lock-v1.json`, 현재 질문별 입력은 `input-lock.json`, 정정 전후 메타데이터·질의는 `input-amendment-Q08.json`에 있다. 원래 RFC3143 자료는 CG-I04로 보존하되 최소수에서 제외했고, RFC3146은 CG-I05로 구별했다. 정정 커밋 `3bf7dc476cad2776d7d3c85846220711ad0854c8`의 원격 파일 재독을 05:15:27 UTC에 확인한 뒤 Q08 검색을 승인했다.

## 2026-11-22 05:20 UTC — 반환 링크 단위 점검

최초 SCOPE는 반환 예산을 ‘후보 3개’로 구현했으나 사용자 원문은 ‘최종 링크 최대 3개’다. 일부 경로의 후보 3개에는 서로 다른 근거 URL이 4~5개 붙었다. 이 차이를 숨기거나 처음부터 3개 URL 제한을 지킨 것으로 소급하지 않는다.

모든 경로는 기존의 동일한 검색·열람 규칙으로 끝까지 기록한다. stream별 원본 `returns.jsonl`도 보존한다. 최종 반환 예산을 엄격하게 해석한 별도 결과는 다음 공통 규칙으로 만든다.

1. 경로별 원래 순위 1→3, 각 슬롯의 기존 인용 순서대로 처음 3개 고유 원문 URL만 남긴다. 절 fragment만 제거해 같은 원문 URL인지 판단한다.
2. 같은 URL의 다른 절은 해당 링크의 절 표시로 보존한다. 새 URL·후보·인용은 추가하지 않고 순위를 바꾸지 않는다.
3. 인용이 하나도 남지 않는 슬롯은 링크 예산 때문에 생긴 빈 슬롯으로 표시한다. 원래 후보 키와 탈락 이유는 별도 필드에 남긴다.
4. 제한 때문에 필요한 근거가 사라진 후보는 완전 인용 성공으로 세지 않는다.

가린 판독에는 경로·순위를 숨긴 원래 인용 묶음과 제한 후 묶음을 같은 후보 키로 제공한다. 최종 보고는 3개 URL 제한 결과와 후보 3개 원본 결과를 분리한다. 이를 처음부터 동일한 반환 단위로 사전등록한 시험이라고 부르지 않는다. 수용 배열에는 이 불일치와 재개 입력을 남긴다. 이 정정은 질의·열람 예산·원래 검색 순위·신규성 기준을 바꾸지 않는다.
