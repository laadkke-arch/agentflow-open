# Arrow 최초안 표집

사전등록의 Arrow 공개 제안/메일 원장을 공식 월별 mbox로 읽었다. 2021-01~04의 전체 메시지 중 Re: 또는 In-Reply-To가 있는 회신은 본문을 읽지 않고 제목/날짜 심사에서 분리했다. 비회신 헤더를 UTC 시각·Message-ID순으로 정렬하고 전체2/부분2 상한을2021-02-07에 채웠다. 뒤 달 헤더는 held_after_cap이며 결과에 따라 교체하지 않는다.

메일 API topics.lua는404, 새 HTML목록은JS shell이었다. source.lua와 공식 mod_mbox는 성공했으므로 실패를 부풀려 Git대체원장을 주장하지 않는다. 병행해서 살펴본 Git PR 제목 RFC/proposal/design/specification의 메타데이터는 보존하되 선택 표본으로 사용하지 않았다. 그 PR들의 결과·diff는 열지 않았다(첫커밋 메타데이터와 파일명만 확인;12196의 최초commit메시지는설계본문을포함해보였다).

Q01은64비트오프셋 출력 선택이라는 새로운 reader동작요청이다. Q02는개별배열 value를공통trait으로이동하자는새API경계제안이며, 단순한기존사용법질문으로분류하지않았다. 반환타입/널의미는미기재이므로추가요구로만들지않는다. Q03은기존ORCwriter전체가아닌테스트보조두함수의새전체설계다. Q04는타입안전배열전체재설계다. 각최초메일전문을G/R의동일입력으로고정한다.

Q04에연결된README의최초reachablecommit67bb67a의본문은제목과목적3행뿐이다. 이를후대상세README로덮어쓰지않고보조자료로보존한다. 메일당시branchhead의상세README전체는미확인이다. 따라서원질문은고정메일의전체설계제안에한정하며모든설계코드의최초공개판을복구했다고주장하지않는다.

원문최소수는선택된메일4건이다. 동일메일의mbox/raw/HTML주소는중복. 월별mbox는원문수별도산입하지않는다. Jan21MATLAB의첨부누락,Jan7정책문서,Jan10오류교정,Feb1동일사건후속,Feb2원초안미복구를탈락원장에보존한다. 검색결과/후속노출은exposures.json에따로있으며검색적중으로소급하지않는다.

## 입력 복구와 저작물 보존

메일 전문의 재배포 허가를 공개아카이브만으로 추정하지 않는다. 전문은 cache/inputs/ 아래의 제외된 읽기 캐시에만 있으며, 원격에는 원본 Message-ID·raw 주소·본문 SHA256·복구코드 restore_inputs.py와 짧은 판독만 저장한다. G/R 양 경로는 같은 해시의 전문을 실제 읽었다. `python docs/workstreams/research/AF-RES-025/streams/arrow/restore_inputs.py`로 원문을 다시 받아 MIME plain-text 본문을 복구하고 해시가 다르면 실패한다. 아래 차수에서 질의문을 바꾸려면 별도 변경기록이 필요하다.

메타데이터에서 상한 뒤 원제안 몇 건의 본문도 심사 도중 읽혔다. AR-X06~AR-X13에 남기며 검색후보나 최소수에 산입하지 않는다. 첫4선택은 고정했고 이 후보기능들을 질의에 추가하지 않는다.
