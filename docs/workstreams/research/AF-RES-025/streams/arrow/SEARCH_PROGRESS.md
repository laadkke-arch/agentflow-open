# Arrow 검색 진행 · 4질문 완료

- Q01 G→R, Q02 R→G, Q03 G→R, Q04 R→G 순서를 실제 UTC로 검산했다. 이전 경로 반환 고정 뒤 다음 경로 검색이 시작되었다.
- 8경로 × 3질의 = 24 실제 질의, 제공 결과215개, 각 질의 최초10 이내206개, 최초 원문 시도40회, 같은 URL 재시도2회, 반환24슬롯(빈슬롯3).
- Q03 G random.h/random.cc는 첫 시도와 같은 URL 재시도 모두403. R은 봉인 질의에서 나온 Debian random.h를 열었지만 G의 근거를 소급 보강하지 않았다.
- 후보 원문 관측 원장36행 중 고유 직접 원문34건. random.cc 접근 실패와 AI 생성 SQL demo 글은 최소수 밖이다. 최초 설계4건은 별도 sources.json에 있다.
- 현재/당시 주 지표의 검증 신규 후보는 양쪽0이다. 이는 검색 가능한 모든 대안이 없다는 결론이 아니다. 첫 적격5원문 선택과 제한된 인용에서 전체 필수 조건을 증명하지 못했다는 실행 결과다.
- 마지막 관측 ID: Q04-G-o5. 8개 route-records의 completed_utc가 원 반환 고정 시각이다. 원 반환의 순위·인용·판정은 추가 자료로 변경하지 않는다.
- 다음 첫 행동: root가 이4질문 묶음을 커밋하고 원격 확인한 뒤, 다른 stream의 가린 독립 판독을 배정한다. 아직 후속 결정 본문 또는 도서관/제조 보조 사례를 열지 않는다.

## 남은 판독 한계

1. G/R 공유 모델·문맥과 latest 문서의 판 드리프트를 제거하지 못했다. 특히 arrow_array의 R59.0.0/G60.1.0 관측은 source version_observations에 남았다.
2. Q03/Q04에서 후속 구현 또는 원 프로젝트의 나중 README 제목·스니펫이 노출되어 감도 분석에서 질문 전체 제외가 필요하다. 해당 본문은 열지 않았다.
3. root 사전규칙의 ‘3후보+각 근거 묶음’은 사용자 ‘최종3링크’보다 넓을 수 있다. 원 반환을 보존하고 root의 별도3URL 제한 판독/감도 분석에 넘긴다.

## 재집계

소유 stream 경로에서 `python record_route.py`, `python logtools.py`, `python check_search.py` 순서로 실행한다. 입력 복구는 README의 restore_inputs.py 명령을 따른다. raw 응답은 cache/에만 있으며 커밋에서 제외한다. receipts/에는 원 요청, UTC, 제공순위/주소, 응답 해시, 실제 콜 시간과 오류를 보존한다. 콜 시간 합계는 겹칠 수 있어 벽시간이나 인시로 바꾸지 않는다.
