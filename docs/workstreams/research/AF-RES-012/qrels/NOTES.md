# 실행 전 판정

판정 단위는 질의 × 대상 × 요청 역할이다. 전체 질의는 정해진 부품으로 적용 가능한 필수 조건을 충족하는 경우에도 2를 허용한다. 부분 질의는 빠진 조건을 되살려 감점하지 않는다. “이번에”, “그 폴더”처럼 원문을 가리킬 때에는 같은 문제의 지시 대상을 판정자가 식별했다. 검색에는 발췌 텍스트만 들어간다. 가령 K01.2에서 브로커 금지를 지키는 아무 로컬 소프트웨어가 정답이 되지 않는다. 수집기 송신 대기라는 목표의 일부여야 한다.

2는 해당 역할의 필수 조건에 맞는 문서화된 경로, 1은 조건부 부품·전이·실패 경계의 유용한 참고, N은 근접한데 구체 조건이 어긋나는 대상이다. 운영 실측 없이 문서 기반 적합성을 판정했다. 접근 보류나 근거 부족만으로 N을 부여하지 않았다. 명시 0과 미판정 쌍을 구별한다. 후자는 주요 후보 및 반례 중심의 초기 판정에 포함되지 않았고 사후 풀링 대상이다. 선행 원장이 판정한 자료와 겹치는 새 부품도 순위 산출 전에 일부만 판정했다.

| 선행 입력 | 투영 방법 |
| --- | --- |
| AF-RES-001 K01–K06 | 사례 인용을 `transfer`로 옮기되 인용 자체를 적합으로 취급하지 않는다. 예를 들어 K02의 Paperless-ngx 설정·코드는 오히려 N의 근거다. K05는 두 필수 조건이 양립하지 않아 2를 두지 않았다. |
| AF-RES-002 P1/P2 | 조건부 검토, 부분 부품, 전이 참고는 1로 옮겼다. P1의 Jiandu 공개 소스 평가 중단은 0, P2의 Anytype/CryptPad 보류와 원문 미열람 오탐 기록은 별도 대상·근거가 없으므로 채점에서 빠진다. P2의 자체 운영은 선호 조건이다. |
| AF-RES-004 R01, R02, R06, R08, R10, R14, R15 | DIRECT_DOCUMENTED → 2. 재사용 조건은 R행의 구성에 고정된다. P01 R02는 `y-indexeddb` 항목에 Y.Doc와 network provider의 조합을 판정하고, `yjs` 단독은 1이다. P03 R10은 `asyncio-queue`에 고정 worker를 함께 둔 행이다. |
| AF-RES-004 R11, R12, R17 | CONDITIONAL_TRANSFER → 1. R17은 manifest 부분 질의 P04.2에서 직접 원리로 2다. |
| AF-RES-004 R03, R04, R07, R13, R16 | SURFACE_OR_CONSTRAINT_MISMATCH → N. 명시 구성에 한정된다. 예를 들어 R16의 rsync 단일 mirror를 전체 rsync 구성으로 일반화하지 않는다. |
| AF-RES-004 R05, R09, R18 | R05의 INSUFFICIENT는 저장 어댑터가 없는 core가 제공하는 부분 유용성만 1로 옮겼다. R09의 미지정 큐 구성은 R06과 동일 대상이어서 최초 전체 판정에서 구성 조건을 함께 보존했다. R18은 P02-V1의 변경 전제에 붙은 N이며 이 고정 질의의 P02에는 전파하지 않는다. |

`origin=new`는 이번에 발췌 범위 또는 다른 원장을 대조한 판정이다. `reference`는 파일의 표, 사례행 또는 출처 ID를 가리킨다. K05의 로컬 앱이라는 1급 참고를 문서상 불가능한 원격 요구의 해법처럼 읽지 않는다. 저장, 재시도, 충돌 추출, 앱에서의 표시 및 운영의 경계는 근거가 지지하는 부분에서만 인정했다.
