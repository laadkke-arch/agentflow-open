# 분석 구현 기록

이 파일은 실행 시작 후 분석 코드를 구현하며 정한 자료 처리의 설명이다. 사전 기준은 `SCOPE.md`와 첫 실행 전 커밋의 규칙 파일이며, 이 파일로 H1 임계값·질문·정답·검색 예산을 변경하지 않는다.

## 입력 무결성

`verify_inputs.py`는 동결 커밋 blob, 현재 HEAD blob, 실제 작업 파일을 대조한다. Git의 텍스트 정규화 때문에 `gold/answers.tsv` 작업 파일만 CRLF이고 커밋은 LF였다. LF로 정규화하면 동결 SHA256과 같다. 이 차이를 원장에 표시하고 다른 내용 차이는 실패로 처리한다. 실행 이후 질문/정답 재생성 명령은 쓰기 전에 중단하도록 보호했다. 질문 하나의 최초판을 읽고 해시를 검사하는 `questions/generate.py --emit`은 그대로 동작한다.

## 열람과 시간

실행자의 실제 로그와 보수적으로 선언한 예산 수를 고치지 않는다. 일부 실행은 find 또는 같은 문서 재열람도 새 문서처럼 과금했다. 따라서 다음 값을 함께 낸다.

- 선언한 검색/열람 예산: 실행자가 기록한 값이며 상한 준수 감사에 사용한다.
- 정규화한 열람 비용: 성공한 고유 URL(조각 식별자 제외) 한 번 + 실패한 열람 시도 각각. 명시한 find는 같은 문서 재열람으로 별도 집계한다.
- 전체 벽시계: 시작부터 최종 종료. 부모가 검사 후보를 보내기까지 대기한 시간도 포함한다.
- 기록된 활동 구간: 시작→발견 동결과 검사 시작→검사 종료를 합산한다. 계산 장치의 순수 연산 시간이나 사람 검토 시간이 아니다.

날짜가 `pre_decision_version_live_text_unknown`처럼 판의 날짜와 현재 본문 불확실성을 함께 표현하면 원문을 보존한다. `post_decision=true`는 사후로, 정확히 `pre_decision`인 항목만 사전으로, 나머지는 미확인으로 처리한다. 알 수 없는 시점을 과거 근거로 바꾸지 않는다.

## 조건을 가린 출력 변환

발견 후보는 이름·URL·30단어 이하 이유로 변환한다. 검사 후보는 두 조건에 주어진 공통 입력의 이름·URL을 사용한다. 일부 실행의 검사 응답에 URL 필드가 빠졌다는 이유로 한 조건만 주소가 없는 형식으로 평가자에게 보이지 않게 한다. 판단 이유는 실제 해당 실행의 이유를 보존한다. 변환에 정답 등급이나 예상 판단을 넣지 않는다.

30단어 초과는 자동 앞부분 절단을 최종 출력으로 채택하지 않는다. 조건을 가린 편집자가 핵심 부정·범위·미확인을 보존해 줄이고, 손실이 불가피하면 변환 원장에 적는다. 원 응답은 수정하지 않는다.

## 동일 실체와 서로 다른 정답 출처

`map_candidates.py`는 출력 후보와 동결 정답의 실체 일치만 판단할 입력을 만든다. 정확한 이름/URL은 제안이며, 범주·공급자만 같은 후보는 일치시키지 않는다. 수동 판단은 이유·검토자와 함께 기록한다. 외부 목록에 없는 후보는 미판정이며 자동으로 무관0이 되지 않는다.

내부 관련성 판정에서 후보 풀은 A/P의 **발견 출력**의 합집합이다. 심은 검사 후보를 이 검색 풀에 넣어 recall 분모를 늘리지 않는다. 동일 실체에 상이한 행 판정이 있으면 원 행을 남기고 민감도를 따로 본다. 실제 채택2는 외부 기록만 제공하므로 내부 평가가 채택 사실을 독립 재판정한 것처럼 쓰지 않는다.

## 구간과 결측

대응 부트스트랩의 재표집 단위는 질문이다. 같은 질문에서 나온 모든 주장과 두 조건이 함께 이동한다. 비율은 각 재표본의 분자/분모를 다시 합산하며, 질문별 recall의 macro 평균과 주장별 오류의 합산 비율을 혼동하지 않는다. 분모0인 반복은 정의되지 않은 값으로 별도 집계한다. 작은 층의 점추정/구간은 그 층에 대한 확정적 우열 근거가 아니다.

부트스트랩은 Python `Random(18018)`의 질문 인덱스를 캐시하고 NumPy로 합계/평균/중앙값을 계산한다. 스칼라 참조 계산과의 허용 오차는 1e-12다. 일정한 효과의 구간이 부동소수점에서 1±2e-16으로 나타날 수 있으므로 출력 동등성 검사를 정확한 비트 일치로 하지 않는다. H1 임계값 판정 자체는 정수 분자·분모의 `Fraction`을 사용한다. C3의 동일 오류율을 반올림 차이로 개선이라고 세지 않는다.

첫 관련 후보 순위의 주 분석은 모든 질문에서 미적중을 11로 두며, 실제 정답 실체가 있는 질문만의 값과 적중 질문만의 값도 보조로 낸다. 적중 질문만의 조건별 기술 중앙값은 서로 다른 질문 집합일 수 있어 대응 효과 추정과 구분한다.

## 실제 열람 상태어 정규화 보정

완료 실행49개 시점에서 `success`/`successful`을 `opened`와 같은 성공 관측으로 읽고, `successful_find`/`no_matching_text`를 재열람으로 읽도록 분석기를 보정했다. 메뉴·이동 안내만 관측한 경우는 비용을 소비하나 D1 본문 근거로 올리지 않는다. 빈 본문·읽을 수 없는 응답은 실패 열람 시도로 남긴다. 원 로그·선언 예산·동결 해시·지표 임계값은 수정하지 않았다. 변경 전후의 실제 로그 집계는 `status-normalization-audit.json`에 있으며, 기존 감사의 상태어별 오분류를 숨기지 않는다. 최종 결과에는 정규화한 실제 비용과 실행자가 보수적으로 선언한 비용을 함께 보고한다.

## 코호트와 실제 질문 날짜의 중첩

완료 실행51개 시점에서 동결 메타데이터 날짜 범위를 다시 확인했다. 01133개 중 T019,T049,T054,T058의4개도2026-06-01 이후다. 따라서 사전16층의011/new를 달력상 과거/최근과 동일시하지 않는다. 주분석과 표본은 유지하고, 날짜 경계 이전29개/이후24개 및 최근0114개 제외49개의 탐색 민감도를 추가한다. 이는 실행 후에 확인한 표본 해석 보조이며 사전 등록 분석으로 부르지 않는다. 모델 지식 시점이나 학습 오염 여부를 이 분할로 확인했다고 쓰지 않는다.

C1에는 관측된 A 거절률에서 가능한 최대 개선폭 `1-A`도 기술한다. 이는 기준선의 천장 효과를 설명하는 계산이며20%p 사전 임계값을 낮추지 않는다.

## 검사 후보의 정답 자체에 대한 반증

T023-P의 검사에서 ‘새 계정 생성 불필요’와 ‘인증 불필요’가 다르다는 범위 문제가 제기됐다. 이 관측을 이유로 동결 gold/checks나 주분모26개를 고치지 않는다. 별도 조건가림 이유 감사는 처음부터 `frozen_violation_supported`를 기록하도록 준비했으므로, 모든26개에 동일하게 적용한다. 두 조건의 가려진 이유 행에서 모두 위반이 지지된 검사만의 보조 거절률을 추가하고, 미지지·불명·상호불일치를 별도로 공개한다. 이 보조 분석은 실행을 본 뒤 추가한 탐색 민감도이며 주H1 판정을 대체하지 않는다. 서로 동의하는 내부 판정을 사람 검증이나 완전한 정답으로 부르지 않는다.

## 실제 출력 인용의 주소 복원

완료 실행65개 시점에5개 원 응답이 URL 문자열 대신 도구 인용 식별자를 함께 사용함을 확인했다. 원 응답에 실제로 인쇄된44개 참조 중7개는 보존된 source_ref 로그에 주소가 있었고,37개는 해당 참조를 root가 정상 열람 도구로 다시 열어 반환 헤더의 주소만 확인했다. 원장은 evidence/citation-resolution.json이며 이 열람은 D3-fetch 메타데이터 관측이다. 새 방법 문헌이나 사실 검증 본문으로 세지 않는다.

모든 실행에 동일한 citation_audit.py를 적용한다. 원 응답에 없는 문서 로그를 새 인용으로 붙이지 않는다. 주장 추출자는 실제 출력 링크와 이 주소 대응만 받으며 원 실행·조건·정답·새 사실은 받지 않는다. 주소가 끝내 확인되지 않은 인용은 별도 남긴다. URL 미제공 주장, 인용 표시 자체도 없는 주장, 미해결 인용이 있는 주장을 구분해 원래 존재한 인용을 누락으로 잘못 세지 않는다. 원 응답·예산·판정 기준·후보는 수정하지 않았다.

## 재개 시 부모 관측 시간

AF-RES-018#2는71–74의 미커밋 배정 기록을 보존하며 새 실행을 시작했다. 해당 행의 부모 관측 시간은 과거 배정시각이 아닌 `resumed_at_utc`부터 센다. 실행자 자체의 시작·발견 동결·검사 구간은 새 원응답에 기록된 실제 시각을 그대로 쓴다. 재개 사이 세션 공백을 한 조건의 검색 비용으로 잘못 더하지 않으며, 이전 bookkeeping은 attempt_history에서 확인할 수 있다.

## 재개 실행의 후보 수 필드 보정

P/N016은 반환1개와 조사 후 제외4개를 합쳐 candidate_count=5로, P/T030은 반환3개와 검사3개를 합쳐 최종 candidate_count=6으로 기록했다. 부모 감사가 예산 필드의 정의 차이를 발견해 실행자에게 계산 필드만 바로잡도록 요청했다. 각각 반환1개와3개로 고치고 원래 조사/검사 수와 해석을 별도 필드·원장에 보존했다. N016은 부모 동결·검사 주입 전, T030은 검사 종료 뒤 최종 합계 필드만 보정했다. raw_response와 후보 해시는 불변이며 내용·선택·판정 이유를 피드백하지 않았다. evidence/schema-corrections.json과 동결 영수증에서 확인할 수 있다. 이후 배정에는 후보 수 필드가 반환 후보 수임을 명시했다. 추가로 P/T048의 조사4개(반환3·제외1)를 반환 수3으로 고치는 같은 종류의 사전 주입 보정이 있었다. 이 세 건은 답변·판정 변경이 아니라 계산 필드의 의미를 통일한 기록이며, 별도 원장에 원래 값과 검증 해시를 보존했다.

## 재개 시 미해결 인용

완료78개 시점에 원 응답에 실제로 표시된 추가 인용17개의 URL을 정상 열람 도구의 반환 헤더로 복원했다. P/T036의 이전 세션 참조5개는 같은 도구가 reference does not exist로 반환해 미해결로 남겼다. 원장은 evidence/citation-resolution-resume.json과 전체 citation-resolution.json이다. 주소를 문맥으로 추정해 채우거나 열람 로그를 새 인용으로 연결하지 않았다. 미해결 참조, URL 부재, 참조 표시 자체 부재는 서로 다른 변수다. 이 메타데이터 조회는 실험자의 검색 예산이나 방법 문헌 본문 수에 넣지 않는다.

## 원문 입력 관측의 기록 수준

완료78개 시점의 형식 감사는 A/T017,T026,T030의 원 응답 JSON에서 동결 SHA256 문자열 자체를 찾지 못했다. T017은 해시 일치와HTTP200을 명시했고, T026은 허용된 원문 출력 명령으로 읽었다고 기록했다. 문자열 부재만으로 원문 접근 실패를 만들지 않는다. 실제 호출 근거가 부족한 항목은 원문 실행의 완전한 계측으로 주장하지 않고 별도 provenance 확인 대상으로 남긴다. T030 실행자는 이후 읽기 전용 확인에서 원래 호출의HTTP200·실제UTC·SHA256 검증 결과를 보존 문맥으로 보고했다. 동결 메타데이터와 해시가 일치하며 analysis/input-access-audit.json에 보충 기록했다. 원 실행 JSON은 수정하지 않았다.

## 반례 선택에서 실행자와 평가자의 미확인 구별

완료98개 시점, 최종 판정·주장 검증 전 코드 검토에서 반례 CE1이 내부 별도 평가자의 INSUFFICIENT만 선택함을 확인했다. P 실행자가 실제로 붙인 INSUFFICIENT와 평가자의 불충분 판단을 별도 필드로 보존하고 둘 중 하나 또는 실제 제외가 있는 외부 관련 후보를 모두 열거하도록 보강했다. 누락된 실행자 라벨을 추론하지 않으며 이 형식별 라벨 수를 공정한 A/P 미확인 빈도 비교로 사용하지 않는다. Q7의 공통 비교는 양쪽 원 응답에서 같은 규칙으로 추출한 명시적 불확실성 원장을 쓴다. H1 기준, 실제 제외 정의, 동결 정답과 출력은 바뀌지 않았다.

## 한계

이 구현 기록은 관측된 파일 형식 문제를 투명하게 처리하기 위한 것이다. 생성 당시의 모델 문맥을 OS 수준에서 격리하거나 도구의 모든 내부 토큰·비용을 계측한 기록은 아니다. 원문/요약과 과거/현재 문서의 차이는 별도 분석으로 보존한다.
