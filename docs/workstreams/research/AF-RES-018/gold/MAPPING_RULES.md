# 정답·검사 입력의 범위 — 실행 전

`RULES.md`는 고정014 원문을 그대로 복사했다. `answers.tsv`/`answers.json`은 고정014 실제 답과 새 질문의 실제 답, 보조 질문의 확인된 외부 기록이다. 작업자가 현재 좋다고 생각한 제품을 외부 등급1/2로 보충하지 않는다. 검사 후보의 작업자 구성 N/0은 `checks.json`에 별도로 있으며 외부 사용 기록으로 부르지 않는다.

## 실체 일치

정답 일치는 같은 질문 안에서 제품·구성요소의 동일 실체인지로 판정한다. 명확한 이름 별칭이나 동일 공식 URL/저장소를 연결할 수 있지만, 같은 범주·같은 공급자·비슷한 이름만으로 일치시키지 않는다. 여러 답이 같은 실체를 반복하면 recall 분모는 한 번이다. 같은 실체의 등급이 충돌하면 외부 채택2, 반박 없는1, 범위가 맞는N의 출처·시점을 함께 검토하고 원 행을 보존한다. 합성 제품 조합은 원 답이 제안한 단위와 구성요소를 구별한다.

실행 후 실제 출력의 이름을 정답 이름에 연결한 변환 원장을 남긴다. 자동 정규화는 대소문자·공백·일반적인 구두점 차이만 처리하며, 모호한 합성·버전·별칭은 근거를 적은 작업자 매핑으로 남긴다. 매핑자는 채택을 새로 판정하거나 답 밖 후보를 자동으로 무관이라고 부르지 않는다. 미판정 후보는 known-gold recall에서는 적중하지 않지만 블라인드 관련성 판정에서 새로 유용할 수 있다.

## 역사 N과 현재 N

과거 외부 반박 기록은 삭제하지 않는다. 다만 최초 질문판의 요구가 다르거나 현재 제품판이 달라졌으면 현재 엄격N 거절 분모에서 제외한다. LEDA 현재 라이선스, QtiPlot의 미확인 라이선스 범위, SXR05 최초판에 없는 후속 조건이 그 예다. Lambda는 표준 함수와 Managed Instances를, GitHub Pages는 github.io 호스팅과 Enterprise Server를 구별한다. 범위가 다른 출력에 이름만 보고 N을 붙이지 않는다.

주 분석의 심은 N 올바른 거절률은 `eligible_current_strict_N_denominator=true`인 검사만 쓴다. 단순히 제외했을 뿐 아니라 실제 핵심 위반 이유를 맞혔는지 조건을 가린 별도 이유 감사로 확인한다. 거절 자체의 비율과 이유까지 맞은 비율을 별도로 제시한다. 역사적 N 전체를 사용한 결과는 보조 민감도이며 현재 사실의 정답으로 대신하지 않는다.

## 결측 역할

필수조건이 없거나 공식 문서로 명시적 위반을 확인하지 못한 슬롯은 이름이 있는 보조 후보로 채우되 N·양성 거절 분모에서 제외한다. 따라서 53질문×3후보의 실제 판단 입력을 갖추었다는 사실과 53질문 모두에 양성/N/무관 세 역할이 완비되었다는 사실을 구별한다. 후자는 충족하지 못했다. 정답/필수조건 없는 곳에 라벨을 만들어 요구 수를 채우지 않는다.

SX01·SX08은 실제 답이 반박되어 양성1/2를 확보하지 못했다. T054는 특정 제품 정답이 아니라 실제 답의 모델 평가 절차를 보존했으며 독립 제품 URL이 없다. 해당 절차를 임의의 모델명이나 원 스레드 URL로 바꾸어 실행자에게 넘기지 않는다. T054는 제품 실체 recall 분모에서 제외하고 절차형 양성 거절의 포함/제외 민감도를 함께 보고한다.

## 채택과 필수조건의 불일치

새 질문의 Pentaho, Caddy, sshguard, Qwen3.8-27B Q4 사례는 최초 조건·정식 판·이후 변경·출시 시점과 채택 기록을 구별한다. 등급2를 지우지 않으며, 이들을 제외한 민감도에서 순서가 바뀌는지 확인한다. 기존 T007의 curl/JMeter처럼 등급1은 모든 필수조건 준수의 인증이 아니다. 관련 후보의 거절을 계산한 뒤 전부 잘못된 제품 판단이라고 해석하지 않는다.

## 한계

정답과 검사 구성은 작업자가 외부 기록·공식 문서에 규칙을 적용한 것이다. 실제 답 기록과 내부 별도 블라인드 판정은 서로 다른 자료원이며, 전자의 불완전성을 후자의 합의만으로 없앨 수 없다. 새 조건에 맞춘 임의 정답을 뒤에 추가해 주 지표를 개선하지 않는다.
