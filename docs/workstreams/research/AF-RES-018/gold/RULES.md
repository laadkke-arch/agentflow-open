# 실제 답과 판정 출처

## 실제 답 기반

| 등급 | 배정 규칙 |
| --- | --- |
| 2 | 011의 공식 채택 매핑으로 특정한 답 또는 질문자가 선택·식별·실제 사용했다고 명시한 후보. 예정·시험 의향·감사는 2가 아니다. 여러 대안을 담은 답의 채택은 답 전체가 후보일 때만 답 단위 2이며, 채택 문구가 지목한 제품·방법에만 2를 전파한다. |
| 1 | 011의 실질 추천에 제시됐고 해당 후보 수준의 반박이 기록되지 않은 것. top_voted는 판정 근거 종류로 기록해도 독립 승급 근거가 아니다. |
| N | 011의 엄격 근접 오답 중 main이고 `count_as_near_miss=true`인 일치 후보. 보완 사례는 이 61개에서 제외한다. |
| 0 | 질문자의 명시 거절 또는 같은 후보에 대한 코드북으로 구별된 실질 반박(엄격 N 외), 그리고 해당 질문의 실제 답에서 미확인된 다른 스레드·방해 후보의 평가 기본값. 명시 거절과 미판정은 저장소에서 구별한다. |

- 011의 answer ID, 승인 ID, N 증거 ID, 출처 포인터 및 후보→URL 대응을 남긴다. 이름은 NFKC, casefold, 구두점 정리 후 정확히 일치시킨다. URL 없는 답, 복수 제안, 원리와 제품의 혼합은 문서가 동일 대상을 대표한다는 근거가 있을 때만 코드로 연결하고 별칭·분해를 명시한다. 후보를 표시하기 어려우면 URL/답 ID와 이유를 별도 장부에 남긴다. 링크 목록에만 있는 명칭은 답변에서 추천됨을 011의 기록으로 확인할 수 있을 때만 1이다. 단순 비교 대상·이미 불만이 있던 기존 제품·예시·후속 질문자를 자동으로 관련에 넣지 않는다.
- 충돌 시 N을 먼저 보존하고 특정 후보에 대한 명시 사용과 실제 반박의 공존은 주석으로 남긴다. 채택된 혼합 답 안의 거절된 옵션을 통째로 2로 바꾸지 않는다. 링크가 사라지거나 당시 기능을 확인하지 못해도 실제 답 판정은 원본대로 장부에 남기며 코퍼스 내/외를 분리한다. 011의 후보 역할과 질문 라벨 자체는 다시 코딩하지 않는다.

## 풀링과 내부 별도

- 비교 전체 방법의 질의별 상위 10개 합집합에서 이미 답 기반으로 판정된 행을 빼고, 방법·순위·답 매핑을 가린 상태로 채점한다. 1은 같은 작업·역할을 직접 지원하거나 구체적으로 설치·결합할 수 있고 필수 조건 위반 근거가 없을 때 준다. 가까운 목적에 명시 위반이 있으면 N, 그 외 0이다. 작업자와 내부 별도는 실제 채택 사실을 생성할 수 없으므로 2를 추가하지 않는다. 조건 확인에 필요한 근거를 못 얻으면 U로 남기고, 묵시적 0과 구별된 미판정으로 센다.
- 내부 별도의 질의 10개는 61개 ID를 정렬해 Python `random.Random(14014).sample(ids, 10)`으로 먼저 고정한다. 그 질의의 동일 미판정 풀을 새 문맥에서 다시 판단한다. 검토 입력에는 원래 요구의 비식별 요약/조건, 후보명·설명·출처만 포함한다. 두 별도 판정표는 같은 고정 답 기반 표 위에서 각각 평가한다. 10개 동질 집합의 nDCG@10과 방법 순서를 비교하고 내부 별도에 판정 누락이 있으면 규모를 공개한다.
