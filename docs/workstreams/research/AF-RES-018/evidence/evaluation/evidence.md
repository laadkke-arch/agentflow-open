# AF-RES-018 평가 방법 근거: 구조의 효과와 판정 편향

작성: 2026-11-21 UTC. 작업자: 내부 별도 연구 작업자, 부모와 같은 모델 계열. 이 문서는 P/A의 관측 결과가 아니라 사전 설계와 해석에 쓰는 문헌 대조다. 직접 읽은 15편의 실제 URL·읽은 절·시각·확인 내용·한계는 [sources.json](sources.json)에, 검색 문자열 및 실패는 [SEARCH_LOG.json](SEARCH_LOG.json)에 둔다. 논문 전문과 커뮤니티 사용자 본문은 저장하지 않았다.

## 2. 비교를 망칠 수 있는 여섯 가지 가정

### 2.1 같은 상한은 같은 실제 지출이 아니다

검색 12회·열람 20개라는 공통 상한 아래에서 P가 검증에 문서를 쓰면 탐색에 쓸 문서가 줄어든다. 따라서 그 비용 배분까지 포함한 절차 전체의 효과를 비교한다. 이것은 연구 설계의 논리적 함의다. 실제 검색 수·열람 수·시간을 따로 기록하고, 두 조건이 상한 이내라는 이유만으로 같은 비용을 썼다고 쓰지 않는다. 시간 차이를 사람 검토 시간으로 해석하지 않는다.

### 2.2 정답 밖은 무관과 같지 않다

EV05는 어느 질문을 기준으로 답의 관련성을 판정하는지조차 인터페이스에 의해 흐려질 수 있음을 보인다. EV06의 최고 득표 답은 여러 유효 답 중 하나다. EV09의 불완전 판정 문제와 함께 보면, 외부 답 일치율과 새 후보의 블라인드 유용성 판정은 다른 지표로 남겨야 한다.

권장 기록은 후보별 외부 등급 2/1/N/0, 외부 기록에 후보가 없다는 표시, 내부 별도 판정 라벨을 분리하는 것이다. 내부 판정이 좋다는 이유로 사전 동결한 외부 정답을 사후 확장하지 않는다. 이 원칙은 질문자 채택을 재는 Q3와 읽는 사람에게 새 후보가 도움이 되는지를 재는 Q5의 차이를 유지한다.

### 2.3 블라인드와 새 문맥이 모든 편향을 없애지는 않는다

EV01·EV03은 위치 효과가 모델·과제·품질 차이에 따라 달라짐을 보인다. EV02의 자기 선호 실험 때문에 같은 계열 모델의 별도 문맥은 독립적인 사람 평가와 동등하다고 부를 수 없다. 후보 순서를 고정 시드로 섞고 조건명을 가리되, 같은 질문·같은 후보가 A/P 양쪽에서 나왔을 때 라벨이 달라지는지 별도로 점검한다.

공통 후보의 다른 설명이 실제 정보를 다르게 담았다면 라벨 차이를 곧바로 편향으로 단정하지 않는다. 후보 URL·버전·근거 범위를 맞춘 뒤 차이를 확인한다. 정규화 후에도 같은 후보가 어느 쪽 문장으로 제시되었는지에 따라 달라지면 조건 스타일의 잔여 효과라는 가능성을 남긴다.

### 2.4 30단어 정규화도 정보 손실을 만들 수 있다

EV04의 길이 보정은 통계적 조정이며 문장 절단과 다르다. 가격의 무료 범위, 오프라인의 최초 설치 조건, 자체 호스팅의 특정 에디션을 지우면 짧게 만들면서 정답을 바꾸게 된다. 원 응답, 30단어 변환본, 삭제된 범위 표현을 연결한 변환 로그가 필요하다. 정규화 담당자는 새 사실을 덧붙이거나 후보의 순서를 교정하지 않는다.

판정 대상은 정규화본으로 고정하되 주장 정확성 감사는 원 응답의 사실 주장으로 해야 한다. 그렇지 않으면 긴 출력이 더 많은 검증 대상 사실을 제시했다는 위험이 정규화 과정에서 사라져 버린다.

### 2.5 인용 있음, 열람함, 주장 참은 다른 사실이다

EV07은 출처가 문장을 지지하는지와 세계에서 참인지를 분리한다. EV12에서는 출처의 침묵과 모순이 모두 미지지가 될 수 있다. EV13은 소비 URL과 표시 인용 URL의 차이를 측정했으며 인용 정확성은 직접 검증하지 않았다. 따라서 URL 유효성, 실제 열람 로그, 인용 연결, 현재 공식 문서와의 일치, 확인 불가를 따로 기록한다.

거짓/(참+거짓)와 확인 불가/전체 추출 주장을 함께 보고하면 확인 불가를 늘려 오류율을 낮춘 것처럼 보이는 경우를 드러낼 수 있다. 조건당 75개 이상 추출할 때 복수 주장을 한 문장에 묶은 채로 세지 말고, 가격·플랫폼·라이선스·오프라인·자체 호스팅·기능의 최소 사실 단위로 고정한다. 동일 후보의 여러 주장은 독립 질문처럼 취급하지 않는다.

### 2.6 작은 층의 유의하지 않은 차이는 동등성 증거가 아니다

EV10은 평가 통계량과 검정 통계량을 맞추라고 강조한다. EV15는 한 검정을 기준 정답처럼 둔 평가에 반례를 제시한다. EV11의 검정력 관점을 적용하면, 50개 질문을 출처·전체/부분·I5·must로 나눈 셀은 표본이 희박할 수 있다.

질문을 단위로 A/P 쌍을 함께 재표집한다. 주장150개를 질문150개로 해석하지 않는다. 각 셀의 질문 수, paired 차이, 신뢰구간을 표기하고 n=0은 계산하지 않으며 n이 극히 작은 셀은 탐색 결과로 표시한다. recall 비열등 기준 충족은 사전에 정한 절차로만 판정한다.

## 3. 구조에 유리한 설명과 그 반례

| 가설·관점 | 지지할 수 있는 경로 | 반례·조건 | 이번 작업에서 볼 관측 |
|---|---|---|---|
| 질문자: 필수 조건을 드러내면 채택에 가까워진다 | 실제 필요를 평가 항목에 연결 | EV05의 원 질문/관련 질문 혼동처럼 잘못된 분해는 판정 자체를 바꿈 | 원문 위치, 부정 극성, 관련 후보 과잉 거절 |
| 답변자: 명시적 출처가 검증을 쉽게 한다 | 주장과 근거의 연결 | EV12·EV13처럼 접근 가능한 URL도 지지·정확성을 보장하지 않음 | 주장 참·거짓·확인 불가, 무근거 주장 |
| 목록 독자: 세분화가 검토를 줄인다 | 조건별 대조가 빠를 가능성 | EV07의 문장별 판정은 200요약에서 평균 258.1초 대 원 절차 203.7초, 전문가50건 대조 품질 유의차 없음 | 단어 수·미확인 수·첫 관련 순위; 실제 사람 시간은 미측정 |
| 검색 평가 연구자: 정답 일치가 성능이다 | 채택·사용 기록과 직접 연결 | EV06·EV09의 복수 유효 답·미판정 문제 | 외부 정답 순서와 블라인드 순서 유지 여부 |
| LLM 판정 연구자: 별도 판정자가 객관화한다 | 조건 가림·무작위화 | EV01–04의 위치·길이·자기 선호가 남을 수 있음 | 공통 후보 라벨 차이와 정규화 손실 기록 |

EV07의 반례는 구조가 항상 시간 절약을 낳는다는 주장에 직접 반한다. 그러나 추천 문제에서의 실패를 증명하지는 않는다. 채택 답을 P가 과잉 거절하는 경우, 새 질문에서 A가 우세한 경우, must 없는 전체 질문에서 비용만 늘어나는 경우는 이 문헌으로 대신할 수 없고 실제 P/A 실행 결과에서 찾아야 한다.

## 4. LLM 판정에 관한 반대 방향 근거

EV08은 자동 판정이 자체 편향을 기준으로 삼을 수 있음을 경고한다. 반대 방향의 EV14는 실제 검색자가 필요를 느끼던 상황에서 만든 외부 선호 자료를 기준으로 모델·프롬프트를 선택한 Bing 사례다. 긍정 결과의 조건은 실제 사용자 기준, 대규모 표본, 프롬프트 선택, 지속 감사다.

두 문헌은 내부 판정을 쓸지 말지의 단일 명령을 주지 않는다. 이번 실험은 사용자 요구대로 외부 답 기록과 내부 별도 판정을 함께 제시하고, 두 출처에서 A/P 순서가 유지되는지를 결과로 삼는다. 다른 모델을 실제로 선택하지 않은 상태에서 이 조합을 다른 모델 검증이나 사람 검증이라고 부르지 않는다.

## 5. 자료 신규성 확인

새 인용 문헌 EV12·EV13은 고정 AF-RES-009(7f627a81199f06da7f7b15f979e7fef25dd17602) 및 AF-RES-013(eb569f07a3a34ffacf114384ae9b06ad062f5396)의 sources.json URL·제목과 대조했다. 새 Q&A 문헌 EV05·EV06은 AF-RES-014(42dc266dfd096bcc3c71f951fe0d9176f2eb9fd9)와 대조했다. 정확한 URL뿐 아니라 문헌 제목·식별자 별칭도 확인한 결과를 [novelty-check.json](novelty-check.json)에 둔다. EV09는 기존 문헌 재사용임을 명시하며 새 Q&A 문헌 최소 수에 넣지 않는다.

## 6. 한계

이 묶음은 P/A 실행 자료를 생성하지 않았고 H1을 판정하지 않는다. 질문자·답변자·독자 관점의 대응은 논문에서 AF-RES-018로 옮기는 연구자 해석(H)이다. 직접 읽은 절은 출처별로 기록했으며 논문 전체를 모두 읽었다고 주장하지 않는다. SourceCheckup은 v1만 계상하고 후속 출판본의 표본·모델 수를 섞지 않는다. 실제 모델 지식 시점은 이 작업자가 확인할 수 없어 미확인이다. 논문 초록만 확보하거나 CAPTCHA·MIME 오류가 난 자료는 최소 개수에 넣지 않았다.
