# 공통 실행 전달 규칙 — 결과를 보기 전

각 실행자는 새 문맥(`fork_turns=none`)의 내부 하위 에이전트다. 부모는 배정한 질문 JSON과 A 또는 P 규칙 파일의 위치, 기록할 파일 위치만 전달한다. 원판의 재현 명령은 질문 JSON에 포함한다. 다른 질문·정답·코딩 metadata·과거 실행·비교 결론을 읽지 않도록 지시한다. 모든 실행 모델 표기는 실제 세션의 `GPT-6 Astra Pro`이고 다른 모델의 검증이라고 부르지 않는다.

두 조건의 `raw_response`와 후보 이유는 영어로 기록한다. 한국어 요약 입력은 그대로 읽는다. 이 공통 언어 규칙은 한국어 띄어쓰기 차이가 단어 수 차이로 오인되는 것을 줄이기 위한 실행 표준화이며, P의 출력 길이를 A와 같게 만들지는 않는다. 단어 수는 공백 분리 수이며 모델 토큰 수나 인간 읽기 시간이 아니다. 최종 연구 보고서는 한국어다.

실행 순서는 SCOPE대로 seed=18018로 질문쌍 순서를 섞고 각 질문 안의 A/P 순서도 무작위화해 고정한다. 세 개 슬롯에 이 순서로 시작하며, 네트워크·도구의 비동기 완료 순서는 시작 순서와 다를 수 있다. 시작·종료 시각을 각 실행에서 실제 UTC로 기록한다. 검색/열람 시간뿐 아니라 모델 응답과 공유 실행기의 지연도 벽시계 시간에 포함될 수 있다.

## 두 단계와 누설 통제

1. 실행자는 자발적 검색 결과와 원 응답, 후보 순위, 실제 질의/열람 기록을 `runs/<조건>/<qid>.json`에 저장하고 discovery 완료를 알린다. 검사 후보는 아직 제공하지 않는다.
2. 부모가 `analysis/runner_audit.py --freeze <조건> <qid>`를 실행해 원 응답·후보·질의·문서 로그의 해시를 남긴다. 발견한 기록 형식 오류는 검사 후보를 보여 주기 전에 고친다.
3. 부모가 같은 질문의 검사 후보 이름·URL·범위 세 개만 같은 무작위 순서로 전달한다. 정답 등급, positive/N/무관 역할, 근거 설명은 전달하지 않는다. A는 자유 판단, P는 규칙4–5단계를 따른다.
4. 같은 실행자가 남은 12질의/20문서 한도에서 검사하고 `checks`와 추가 로그·최종 종료 시각을 덧붙인다. 원 응답·후보 순위를 고치지 않는다. 부모는 해시와 로그 접두부 동일성을 감사한다.

검사 후보를 본 뒤 생성한 문장은 자발적 추천 답에 합치지 않는다. 검사 단계 시간은 따로 기록해 모델의 실제 판단 시간과 부모 대기 시간을 구분한다. 사용자 지표의 총 벽시계와 능동 단계 시간(발견 + 검사)을 함께 보고한다.

## 외부 접근·예산

원판의 질문만 해시 확인하여 받는 입력 단계는 검색 예산 밖이다. 후보 검색의 정확한 질의 문자열마다 1회, 열린 문서와 실패한 열람 시도마다 1개를 센다. 동일 문서의 find/재표시를 새 문서로 세지 않되 기록 근거는 남긴다. 익명 코드 검색 시도는 질의와 페이지 예산 양쪽에 포함하고, 차단이면 같은 예산 안의 웹 색인 코드 검색으로 대체했다고 표시한다. 원 스레드·사본·스레드를 인용한 페이지는 제외하며 우연한 snippet 노출도 기록한다.

## 한계

독립 문맥은 모델 사전학습 기억을 지우지 않는다. 공통 원판/요약·공통 모델·공통 도구를 맞춘 비교이며 모델 간 일반화나 사람 검토 시간은 측정하지 않는다. 실행 슬롯의 공유 지연이 벽시계에 영향을 줄 수 있다.
