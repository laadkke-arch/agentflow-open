# AF-RES-018 — 실행 전 분석 계획 v1.0

## 1. 질문과 고정 입력

H1: 목적·부분·제약과 후보의 대응을 기록하는 절차 P가 같은 검색·열람 **상한**의 범용 LLM 검색 A보다 채택 답 회수, 위반 거절, 주장 정확성, 검토 부담 대리 지표에서 나은가. A/P 실험은 아직 시작하지 않았다. source_commit과 일곱 고정 입력은 INPUT_LOCK.json에 있다. 지식 시점은 세션에 노출되지 않아 미확인이다. 최신 질문이라는 이유만으로 학습 오염이 없다고 주장하지 않는다.

모든 새 산출물은 이 owned_path 아래에 쓴다. 원문 본문 전체·사용자명·프로필을 저장하지 않는다. 기존 011 코딩과 014 검색 수치, 013 설계문서 실험, L/E/H/T 및 분류 정의는 다시 연구하지 않는다. 기존 설계문서 사례는 새 표본에 넣지 않는다.

## 2. 조건과 예산

- A: RULES_A.md는 AF-RES-013 고정 SHA의 BASELINE_RULES.md **바이트 동일 복사**. 원 규칙의 B 절은 실행하지 않는다. 원본 15후보 상한은 이번 사용자의 명시 상한 10으로 좁힌다. 나머지 검색·공개 코드 검색 시도·대안 탐색·누설/시점 기록 규칙은 유지한다.
- P: PROCEDURE.md의 입력 분해 → 검색 → 형태/기여 기록 → 제외 조건 대조 → L/E/H/T → 출력.
- 두 조건 모두 검색 질의 <=12, 문서 열람 시도 <=20, 최종 후보 <=10. 실패한 검색/열람도 자원 사용에 센다. 한 도구 호출 안의 여러 검색문은 각각 1질의다. find/추가 구간 읽기는 같은 문서이면 새 문서 수로 더하지 않되 호출 로그에 남긴다. 고정 질문 입력을 가져오는 읽기는 검색 예산 밖의 동일 입력 준비다.
- 검사 후보를 받기 전 자발적 검색 결과·순위를 동결한다. 같은 새 문맥에서 이어서 검사 3개를 판단하며 남은 12/20 예산 안에서 검증한다. 양쪽 모두 검사 단계 예산을 남길 수 있다. 검사 후보는 먼저 보여주지 않는다. 검사 이후 본래 상위 목록을 고치지 않는다.
- 같은 상한은 실제 검색/열람/시간의 동등함이 아니다. 실제 사용량·실패·시간을 모두 보고한다. 도구 접근 실패를 다른 조건에 유리한 무료 추가예산으로 상쇄하지 않는다.

## 3. 표본과 질문 판

011 본표본에서 30개(whole15/part15)를 고정시드18018로 고른다. 엄격 N을 가진 본표본8개를 강제 포함한다. 엄격 N의 보완 스레드 SX01/SX08/SXR05도 추가해 총33개를 목표로 한다(11개 관련 스레드 전부). 기존 whole/part/I5/must 코딩은 그대로 사용하며 보완3개만 원자료에 따라 기록한다. 접근 성공 여부로 선정 질문을 사후 교체하지 않는다.

2026-06-01~2026-11-21 새 추천질문20개 이상을 SR SE/HN/Reddit/GitHub Discussions 중3플랫폼 이상에서 확보한다. 한 플랫폼 <=50%, 답2개 이상 또는 질문자 반응이 필요하다. 표집은 검색으로 접근 가능한 목적표본이다. 011에 이미 있는 동일 URL/ID는 새 질문에서 제외한다. 질문 날짜·답 수·반응·포함/제외 이유를 남긴다.

질문 시점의 원판을 웹 작업공간의 정상 열람 경로로 다시 시도한다. 최초판을 확인한 경우에만 original; 현재 판만 읽거나 역사 판을 확보하지 못하면 summary라고 표시하고 011 question_summary를 그대로 사용한다. 원문 전체는 메모리에서 읽고 hash/단어수/원판 URL/위치와 비식별 요약만 저장한다. A/P가 동일한 원문을 받을 수 없는 경우 요약으로 동결하고 원문 확보 성공과 실제 원문 실행을 별개로 센다. 생성 스크립트는 원문을 파일로 쓰지 않고 hash를 검증한 뒤 실행 입력으로만 출력할 수 있다.

## 4. gold와 심은 검사

014 RULES.md의 2/1/N/0을 그대로 복사한다. 공식 채택·실사용2는 조건 충족을 보장하지 않는다. 반박 없는 실제 추천1도 완전한 외부 정답이 아니다. 미등재0과 명시 거절0을 분리한다. 014가 제외한 보완3개의 grade는 해당 011 보완 관측으로 같은 규칙을 적용한다. 새 gold는 실행 전에 작업자가 원자료를 읽고 만든다.

각 질문에 관련2/1 하나, 엄격N 하나, 이름/범주만 비슷한 무관0 하나를 사전 고정한다. 011 N이 없으면 공식 문서의 명시 위반을 확인한 작업자 구성만 N으로 인정한다. 특정 버전·배포·설정에 한정된 위반은 그대로 제한한다. 필수 조건이 전혀 없거나 근거가 없으면 새 조건을 발명하지 않는다. 그때는 N 구성 불가를 기록하고 가능한 범주 오답0을 별도 검사로 남긴다. 이를 엄격N 성공 분모에 섞지 않으며 이 사용자 요구의 미충족 여부도 공개한다. 기능목표 자체 위반을 쓸 때는 추가 must가 아니라 원문 목적의 어느 요구인지 연결한다.

검사 입력에는 후보명·공식 URL·필요하면 판/설정만 주고 grade/선정 이유/골드/다른 출력은 숨긴다. 후보 순서는 질문별 고정시드로 섞어 A/P에 동일 순서를 준다. 유지+확인필요는 유지이며 거절로 세지 않는다. 관련 후보를 확인필요로 둔 수는 거절률과 별도 보고한다.

## 5. 새 문맥·무작위 순서·누설 제외

각 질문×조건은 fork_turns=none인 새 내부 하위 에이전트 하나다. 허용 문맥은 해당 질문 파일과 해당 규칙 파일뿐이다(공통 실행 지침은 규칙에 포함). root가 읽은 gold·선행연구·다른 실행은 전달하지 않는다. 파일 접근은 지시로 제한하며 OS 강제 격리라고 부르지 않는다. 일반 모델 지식은 제거할 수 없다.

전체 질문쌍 순서와 쌍 안 A/P 순서를 random.Random(18018)로 동결한다. 병렬 실행은 그 dispatch 순서에서 사용 가능한 슬롯으로 시작하고 실제 시작·완료 시각을 기록한다. 도구 지연 때문에 완료순서가 다를 수 있다. 기본 동일 모델계열/표시 GPT-6 Astra Pro. 다른 모델을 실제 선택한 판정이 있을 때만 정확한 표시와 함께 별도 분석한다.

원 질문 스레드, 사본, 그 질문을 인용하는 페이지는 검색 근거에서 제외한다. 검색문에 제목 전체·질문ID·채택답 힌트를 넣지 않는다. 스니펫 노출도 exposures에 남긴다. 후보가 우연히 질문에 이미 등장하더라도 금지페이지 열람과 모델기억을 혼동하지 않는다. 질문 이후 발행/판은 post_decision=true. 날짜 없는 live 페이지는 unknown이며 과거 존재로 소급하지 않는다. 현재 웹 결과 전체와 날짜 검증 pre_decision만의 역사 하위결과를 함께 보고한다.

## 6. 정규화와 블라인드 판정

정규화 형식은 후보 이름, URL, <=30 whitespace words 이유다. 동일 변환을 양쪽에 적용하고 원문→정규화 변환기록을 남긴다. 조건명/축/점수/랭크/장문 표를 숨기며 명시 부정·버전·조건·미확인을 자르지 않는다. 30단어를 넘으면 기계적 앞부분 절단 대신 의미보존 축약을 변환기록에 표시한다. 평가자는 조건 표시 없는 고정시드 혼합순서와 질문만 본다.

외부 실제 답 gold와 새 내부 별도 블라인드 판정, 두 출처를 보고한다. 내부 평가자는 실제 채택2를 만들 수 없으며 관련1/엄격N/0/U와004 라벨·must별 위반을 남긴다. 같은 후보의 A/P 중복은 별도 행으로 보존해 조건 추정·표현 편향을 감사한다. 원 판정을 사후 합의값으로 덮어쓰지 않는다. 조건 대응key는 판정 후 공개한다.

## 7. 지표·주장 검증·구간

주요 결과는 현재 웹 관측 창(실제 실행 UTC)의 질문별 대응 비교다.

- 등급2 적중@10: grade2가 하나 이상 회수된 질문 / grade2 gold가 있는 질문. 보조로 고유 grade2 후보 회수/전체2도 낸다.
- 등급>=1 recall@10: 질문별 회수한 고유 관련gold / 질문별 관련gold의 macro 평균. 전체 회수/전체gold micro도 보조 보고한다. alias는 사전 금표준 기준으로 매칭하며 사후 일치는 근거·기록을 남긴다.
- 첫 관련 순위: 1..10, 없으면11로 처리한 전체 질문 중앙값; 실제 적중질문만 중앙값도 별도. N/상위10: 실제 반환 후보 분모와 최대10*n 분모 모두.
- 심은 N 올바른 거절률: 제외와 질문의 실제 핵심 위반 이유가 모두 맞은 엄격N 검사 / 판정 가능한 엄격N 검사. 단순 제외율도 별도. 관련 잘못 거절: 관련검사 제외 / 관련검사전체. 무관0 거절은 따로.
- 출력단어수, 확인필요 명시 항목수, URL 없는 사실주장수, 검색·열람수·벽시계시간은 **사람 검토 시간의 대리 지표**다. 사람시간을 측정했다고 쓰지 않는다.
- 사실주장을 원 응답에서 원자적 단위로 추출하고 condition별>=75개를 seed18018로 표집한다. 가격/라이선스/오프라인/자가호스팅/플랫폼/기능을 포함한다. 가능하면 질문별 최소1개 후 잔여 무작위; 부족하면 모든 사실주장을 판정한다. 확인할 수 없는 사실을 추가로 만들어 수를 채우지 않는다.
- 현재 공식 문서로 참/거짓/확인불가. 현재 판정 시각과 증거 URL 필수, 011은 현재기준으로 표시한다. 주오류율 거짓/(참+거짓), 확인불가/전체와 보수 상하한 [거짓/전체,(거짓+확인불가)/전체]를 함께 보고한다. 오류유형: 오래된정보/다른제품혼동/버전·요금제범위누락/근거없는일반화.
- 95% 구간은 질문을 단위로 A/P 대응 cluster bootstrap10,000회(seed18018) percentile. 주장도 질문cluster를 재표집한다. 층 n<5는 구간을 확정효과로 해석하지 않고 관측수와 폭을 보인다. 빈층은0을 성능으로 표시하지 않고 미확인. 표본선정 불확실성·동일모델반복 변동은 포함하지 않는다.

층은 011/new × whole/part × I5 present/not_present × must present/absent의16칸. 원문/요약, 011main/supplementary, N 외부관측/작업자구성, 날짜known/unknown 및 gold/내부별도 판정은 보조 민감도다. 새질문 층에서 A우위, must없는whole에서 비용만증가, P과잉거절, 동일후보 판정불일치, 타분야 무효과의5반례를 실제 탐색한다.

## 8. H1 사전 기준

| 기준 | 사전 임계값 | 해석 |
|---|---|---|
| C1 | P의 올바른 엄격N 거절률 - A >=0.20 | 알려진 나쁜 후보 변별력의 실질 향상 |
| C2 | P의 macro recall@10 - A >=-0.05 | 실제 답 회수를 크게 잃지 않는 비열등성 점추정 기준 |
| C3 | P의 확인가능 주장 오류율 < A | 정확도 개선. 둘다0이면 이 기준 미충족 |
| C4 보조 | 관련후보 잘못거절률 P-A <=0.05 | 과잉거절 위험 |

C1–C3 모두 충족이면 이 설정에서 H1의 좁은 절차 효과 지지, 모두 미충족이면 **이 설정에서 H1 불지지**, 일부만이면 혼합결과다. 표본/확인가능 분모가 없으면 불충족이 아니라 판단불가. 구간이 임계값을 가로지르면 충족 점추정과 불확실성을 함께 표기한다. 외부gold와 내부별도에서 조건순서가 바뀌면 강한 지지를 보류한다. 검토부담 감소는 대리 지표가 엇갈릴 수 있어 별도 단정하지 않는다. 비용 증가, 주장의 미확인 비율 및 조건별 실제 사용예산을 항상 병기한다. 제품/별도UI 가치·H2 유지가치·사용자효용은 이 실험으로 확정하지 않는다.

## 한계

목적표본·같은모델계열·현재웹·불완전gold·하위층 작은분모와 원문복원 실패가 예상되는 제한이다. 관측 뒤 기준이나 실패정의를 바꿔 H1을 살리지 않는다. 필수자료가 차단되면 구체 사유·입력·재개명령을 남기고 BLOCKED 또는 REVIEW_READY_WITH_GAPS로 인계한다.
