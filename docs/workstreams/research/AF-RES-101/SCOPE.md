## Q2 최초 이력의 단위

`initial.csv`는 최초 본문 위치별 입력 상태, 도구/명시된 판, 호출·옵션, 출력/오류, 허용할 변경, 필수 출력, 확인되지 않은 값을 담는다. 지식·시도 코드는 `mention_only`, `attempted`, `failure_reported`, `third_party_suggestion`, `not_stated`로 구분한다. 질문에 코드가 있어도 실행했다고 단정할 수 없는 예시/희망 구문이면 그렇게 표시한다. 도구 태그 하나만으로 실제 사용을 입증하지 않는다. `failure_reported`는 당시 작성자의 보고이며 연구자가 실제 실행을 관측했다는 뜻이 아니다.

최초판 이후 수정·자기 답·추천 후 발언은 최초 이력에 소급하지 않는다. 뒤의 증거가 최초 해석을 반박하면 최초판 판단은 보존하고 별도의 현재판 대조에만 쓴다. 최초 자료와 후보 선정 규칙을 첫 원격 커밋에서 봉인한다.

## Q3 후보 수집·원순서

각 요청의 생성 시각부터 30×86400초까지(양 끝 포함) 공개된 질문자 외 작성자의 답변과 댓글에서 구체적인 조작을 채택한다. 모든 공개 답/댓글의 순회 완전성을 먼저 확인한다. 답 본문은 공개 revision으로 30일 안에 존재했는지 확인하고 창 밖 수정으로 추가된 조작은 제외한다. 댓글에는 수정 이력이 제공되지 않는 한 현재 보이는 본문의 과거 동일성을 보증하지 않는다. 이 한계를 후보별로 표시한다.

정렬 키는 조작이 처음 공개된 시각 → 숫자 게시물/댓글 ID → 본문 출현 위치다. 하나의 파이프라인은 하나의 조작 후보다. 별도 인수 선택이나 별도 처리 단계가 독립적으로 제안되면 다른 후보로 둔다. 같은 조작을 단순 인용/반복한 것은 합쳐서 원주소를 모두 보존한다. 구체적 조작 없는 도구 이름·감사·일반 논의는 후보가 아니다. 최초 3개를 고정하며, 없으면 명시적 빈 자리다. 새로운 외부 검색 후보로 채우지 않는다.

원래 제안에 실제 붙은 URL/절, 링크 없는 명령, 연구자가 나중에 연결한 공식 URL/절은 독립 열이다. 연구자가 찾은 절을 당시 받은 링크로 쓰지 않는다. 작성자 반응·채택 상태는 두 번째 봉인 전 모델에 노출하지 않는다. API의 불필요한 필드·인용된 사후 사실 등 노출이 생기면 원 payload와 모델 실제 노출 범위를 기록하며 완전 맹검이라고 부르지 않는다.

## Q4 두 필터와 반환

두 방식은 **동일한 세 후보, 동일한 순서**에서 각각 앞의 두 생존 후보만 반환한다. 빈 자리는 유지한다.

| 방식 | 제외 조건 | 미확인일 때 |
| --- | --- | --- |
| A 제품 단위 | 최초 본문에서 질문자가 실제로 써 본 제품과 후보의 제품이 같음. 제품명 별칭은 동일 제품이라는 근거가 있을 때만 정규화. | 실제 사용 또는 제품 동일성이 미확인이면 유지. |
| B 조작 단위 | 최초 본문으로 이미 시도한 조작과 후보의 입력 상태, 효과를 바꾸는 인수, 처리 단계까지 같다고 입증됨. | 필요한 값이 하나라도 비면 유지하고 `동일성 미확인`. 이름·주소 일치만으로 제외하지 않음. |

후보마다 제품 동일성, 조작 동일성, 각 근거 위치, A/B 제외 사유·반환 위치·원순위에서 이동한 수, 반환 설명, 판정 UTC를 저장한다. 호출의 명시적 차이는 기록하되 효과를 바꾸는지는 후속 공식 근거에서 따로 검토한다. 별칭·같은 주소 다른 절·다른 주소 같은 호출·새 이름의 기존 helper에 대한 확인 여부를 개별 표시한다. 공식 근거·작성자 후속을 읽은 후에는 봉인된 필터 출력을 수정하지 않고 오류/민감도 행으로 남긴다.

## Q5 동작 근거와 Q6 후속의 분리

공식 문서·구현·원 시험은 고정 릴리스/40자리 커밋에서 읽는다. ImageMagick·Typst 각 3개 이상, 합계 8개 고유 문서/구현과 원 동작 시험 또는 입력·예상 출력 묶음 4개를 확보한다. 같은 문서의 여러 절·미러·재인용은 하나다. 연구판·원 질문의 명시판·판 미기재를 분리한다. 원 필수 출력과 변경 불가 조건을 각각 `지지/반박/미확인`으로 판정하며 공식 함수가 존재한다는 사실만으로 원 목적 전체가 충족됐다고 하지 않는다.

90일 창은 최초 질문 시각부터 90×86400초까지(양 끝 포함)다. 질문자 후속 댓글·수정·자기 답 및 명시된 공개 결과/패치만 시간순으로 코딩한다. `already_knew_before_proposal`, `explicit_new_awareness`, `execution_report`, `input_version_output_linked_execution`, `rejection`, `old_method_retained`, `no_observed_response`, `unknown`을 독립 표시한다. 현재 채택만 있거나 감사만 있으면 신규 인지는 미확인이다. 삭제 댓글·수정 전 댓글·외부 비공개 실행은 확인되지 않는다.

주 비교의 분모는 후보 단위이며 아래 자격은 서로 대체하지 않는다.

| 지표 | 비교 가능한 후보의 필요 근거 | 분자 |
| --- | --- | --- |
| 재추천 제거 | 같은 조작을 이미 알았거나 시도했다는 후보별 독립 근거. 공식 유효성은 별도 열. | 그 중 해당 필터가 제외한 수. |
| 다른 유효 조작 손실 | 최초 시도와 효과상 다른 조작임이 확인되고, 필수 출력·변경 불가 조건 충족을 직접 근거가 지지함. | 그 중 해당 필터가 제외한 수. |

## 자료·커밋·검사

`sources.jsonl`은 ID, Q/사건, 직접 연 원본/고정 URL, UTC, 저자·발행자/계보, 버전·절/행·지문, 실제 관측, 주장과의 관계, 한계, 고유수 산입/중복 이유를 가진다. 실패 응답은 별도 기록한다. 외부 원문은 필요한 짧은 근거·위치·해시로 남기고 대용량 임시 수신은 이 작업 폴더의 무시된 `.cache/`에서만 처리한다. 커밋 증거에는 다운로드 영수증과 재현 절차가 있어야 한다. 현재 유효한 공개 읽기 범위만 사용하고 삭제/비공개 자료 접근을 시도하지 않는다.

① 모집/최초 이력/규칙, ② 후보/A·B/후속 전 봉인, ③ 공식 동작/후속/반례, ④ 결과/분모/재현/자기검토를 각각 커밋·푸시한다. 변경 파일·봉인 UTC·원격 SHA를 다음 묶음의 영수증에 기록한다. 마지막 결과 SHA에서 요청한 개별 `session check --fetch`와 공통 `cloud_check --fetch-contract --require-clean`을 실제 실행한다. 공통 검사에서 직접 검증한 세션 수를 읽고 0이면 개별 검사를 대체했다고 쓰지 않는다. 정확한 결과 SHA를 GitHub에서 다시 읽은 뒤에만 HANDOFF를 마지막 단독 커밋으로 작성한다. 이후 HANDOFF를 앞 검사에 포함됐다고 하지 않는다.

자기 검토, 다른 분담자의 실제 대조 검토, 사람의 독립 검토를 구별한다. 필수 표 8/24/8자리와 고유 24개 하한, 창·결손·분모·반대 증거를 검산한다. 핵심 비교가 확보되지 않으면 정확한 결손과 함께 PARTIAL로 인계한다.
