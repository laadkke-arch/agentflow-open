## 경쟁 설명 및 관점 비교

- 제안자: 지식 부족일 수도 있지만 N1/E2/N2는 기존 검사 인지. N2는 구성 가능성만 새로 인지; N3는 formatter 미사용 요구, E3는 소스 가독성과 새 direct From 발견. 같은 기술을 알더라도 다른 목적 때문에 요청 유지.
- 유지자/리뷰어: N1 구현을 확장하는 것이 자연스럽지만 R02는 분리 및 오탐 위험을 지적. B2는 rustc 이동·기존 사용자의 deny warnings 호환성, 발견성 문제와 문서 중복 비용을 같이 고려(B07). PR 구현·종료는 타인의 작업이며 원제안자의 실행이 아니다.
- 실제 규칙 사용자: U01 capacity 보존, U02 서로 다른 attribute 혼용. 같은 제안이 어떤 환경에는 적합하고 다른 환경에는 오탐/비용. 결과를 코드로 바꾸지 않고 기대값/진술로만 기록.
- 표목 심사자: 같은 의미/범위는 기존 heading과 UF, 다른 범위는 새로운 record 또는 재제안 근거. 사용자가 어떤 기록을 실제 카탈로그에 적용했는지 별도. 2021 승인 list 날짜 역전은 인과 문구를 약화한다.

## 대안 조합·조건·비용

1. 링크 후보를 검색 결과 라벨/최신판만으로 제시하지 말고 release 태그, 기본 수준, 정확 입력과 반례, 사용 설정/설치판을 함께 묶는다. 예: rustc unused_qualifications + 기존 absolute paths 길이 정책은 서로 보완, 같은 것으로 병합하지 않음.
2. 조건부인 경우 사용자가 이미 가진 lint/formatter/도구판과 원하는 before/after를 먼저 확인한다. 동일한 code shape·변환 의미·후속 사용을 대조해 남은 요구를 보존한다. 추후 구현의 PR 링크는 당대 재사용 링크가 아님을 표시.
3. 탐색기 UI 가설: 기존 그대로 / 조건부 / 새 구현 여지의 병렬 옵션; 각 항목은 증거 위치·유효 버전·오탐 가능 입력·사용자 제약·실제 적용 여부와 함께. 비용은 검색/설정/유지보수·경고 노이즈·호환성·새 규칙 구현 범주의 정성 비교만. 시간을 수치화하려면 같은 작업 목표의 baseline, 대안 노출 시점, 실제 설정/패치 전후, 작업 기록이 필요. 이번 작업은 고정 fixture 실행도, 소요시간 관측도 하지 않음.
4. 자연 모집과 보강의 분모를 결코 합치지 않는다. 현재 ledger 포함 플래그 합 41(6 proposal, 4 dated response/patch, 23 historical, 2 consumer, 6 LC), 총 94행(접근 실패·제외·보조 포함); response는 동일 PR 작성자/리뷰어 관련 3개와 N3 원작성자 1개, 유지자 권한 및 고유 사건 수와 구분. 날짜 누락 때문에 직접 댓글 상당수 불산입. 6개 자연 및 2개 보강은 제안 issue 사건 단위; B1 경계. U01/U02는 소비자 대조 2사건, LC는 여러 표목·문서 별도 lineage. 자료량은 인과 관측 부족을 보상하지 않음.
