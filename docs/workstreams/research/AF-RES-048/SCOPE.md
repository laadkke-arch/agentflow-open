## 자연층 후보 결정

1. `https://pandoc.org/MANUAL.html`과 `https://vega.github.io/vega-lite/docs/`의 원 발행 HTTP 본문을 얻는다. 요청/최종 URL, 상태, 수집 UTC, content-type·charset, 본문 바이트 길이·SHA256, 문서판과 HTML의 계보를 기록한다. 전송 인코딩을 해제하고 charset 디코딩하기 전의 응답 본문이 해시 입력이다. 원 URL 실패 시 공식 저장소나 공식 배포판의 실제 발행 HTML만 별도 획득으로 허용한다. 스크립트 실행 뒤 DOM·Markdown·새로 렌더한 HTML은 진단에만 쓴다. 판을 아는 공식 URL이라도 이전 바이트와 동일하다고 가정하지 않는다.
2. 044의 최대 세 토큰과 최장 정확 일치, 원순서 동률, 범주 첫 여섯 규칙을 복제한다. [고정 P discovery plan][pplan]에서 최초 의미 문장과 일치하는 토큰만 사용한다. P1 `task lists`(구 `checkbox`, `characters`는 최초 문장 밖), P2 `images`, `LaTeX`, `alternative`, P3 `PDF`, `HTML`(구 `PDF engines`는 제목의 표현), P4 `DITA`, `DocBook`(구 `output`은 최초 문장 밖). V3 새 규칙은 최초 문장 `Vega supports word cloud.`의 기능 명사구 `word cloud`만 사용한다. `Vega`는 제품명이고 `supports`는 동사다. `text`, `wordcloud`, 임의 유의어를 추가하지 않는다.
3. 대소문자 무시, 공백 축약 후 토큰 전체가 일치하는 가장 긴 목차 라벨의 원순서 첫 결과를 선택한다. 문장부호 옆의 단어는 허용하고 더 긴 식별자의 일부는 제외한다. 목차는 공식 기능 TOC(`#TOC`, `.toc`, `.toctree-wrapper`, 문서 내 TOC 표시 영역 순)를 사용한다. Pandoc에서 매치가 중첩됐다면 바로 상위 기능 li부터, 최상위라면 해당 li부터 센다. Vega-Lite는 매치된 기능 li의 subtree를 사용한다. 그 제목의 실제 href를 포함하고 자식과 반복을 HTML 순서대로 첫 여섯까지 고른다. 상위 기능이 없는 경우 매치된 범주를 고정한다. 범주가 외부 공식 문서 페이지로만 이어지고 범주 내 문서 링크가 없으면 실제 href의 페이지 하나까지만 확인한다. 임의로 URL을 수정하지 않는다.
4. 목차가 없거나 매치되지 않으면 본문에서 같은 토큰 순위를 적용해 제목을 찾는다. h2/h3의 바로 상위 기능 제목을 선택하고 더 깊은 제목은 그 제목을 포함하는 가장 가까운 h2/h3 아래에서 센다. 본문 매치도 없으면 문서 본문(`main`, `article`, 문서 역할 영역, `body` 순)의 첫 여섯 실제 href를 얻는다. 전역 nav·footer·공유·계정·편집 UI·제목 permalink는 제외한다. 기능 TOC는 제외 표시된 전역 nav에 있더라도 기능 목차로 선언된 경우 읽는다. 상위 범주를 확정한 경우 그 범주에서 일찍 소진하면 빈칸을 남긴다. 전체 raw HTML a 순번과 범주 순번, 원 속성, DOM 해석 href, 정확 resolve URL, fragment, repeat 또는 소진 여부를 기록한다.

## 보강층의 표시 정보 순회

시작 목차는 Matplotlib [Users guide](https://matplotlib.org/stable/users/index.html), Python Packaging User Guide [영어 목차](https://packaging.python.org/en/latest/)다. Matplotlib은 사용 안내 영역에서 `Using Matplotlib`, `Tutorials`, `How-to`, `Explanations`, `Users guide` 제목과 아래 목차, Packaging은 `Tutorials`, `Guides`, `Discussions` 제목과 아래 목차를 범위로 삼는다. 우선 범위가 문서에 없으면 그 공식 페이지의 기능 목차 첫 링크부터 시작한다. 외부·관리 메뉴·순수 동일 페이지 fragment·API 색인·검색·내용 목록 UI를 시작 페이지의 문서 표집에서 제외한다. 목차에 실제 있는 같은 발행자 문서의 첫 20 링크를 DOM 순으로 내보낸다. 중복 등장 순번과 실제 href를 보존하고 재방문은 표집 정원에 다시 넣지 않는다. 20개 미만이면 실제 소진 수와 빠진 순번을 기록한다.

각 문서에서 목차/제목에 표시된 기능 안내 h2~h4(동급 또는 상위 제목 전까지)를 원순서로 방문한다. 문서 전체의 목적을 뜻하는 h1의 도입 범위도 첫 기능 범위로 포함한다. 그 범위의 첫 여섯 연속된 실제 정보 문서 href가 원풀이다. 전역 템플릿·제목 permalink는 후보에서 뺀다. 같은 구현의 뜻이 드러날 만한 URL·title·TOC 라벨·발행 메타데이터만 판독하며, 타깃 본문의 prose, 코드·예제·표는 그 단계 화면에서 가린다. 후보 본문을 다운로드하더라도 선정용 출력에 나타내지 않는다. 동일 href 반복은 유지하고 그 자체로 distinct-URL 병합 자격을 주지 않는다. 정원 전 적격 문서를 문서당 최초 적격 절 하나씩 원순서로 최대 두 개 선정한다. 모든 검사한 문서·절의 원순번과 탈락 코드, 키 위치를 기록한다. 정원 후 발견하는 키는 추가 표본으로 쓰지 않는다. 문서에 명시된 사용 목적과 필요 조건은 그룹 봉인 뒤 출발 원 안내의 조항을 열어 확인하고 요구 원장에 적는다. 목적·필수조건 없는 일치가 드러나면 근거 미확인으로 남긴다. 기준을 고쳐 다시 선정하지 않는다.

표시 키는 상류 구현, 명명 부품, 공개 용도, 판, 문서 역할 순이다. 상류는 발행자가 귀속시킨 프로젝트/제품이다. 문서나 절의 라벨에 API·포맷·방향 이름이 표시되면 그 범위를 유지한다. 동일 이름의 표시용 퍼머링크와 문서 루트는 그 이름을 공유할 수 있다. 기능 절의 부제만 다르고 독립 부품 이름이 없는 경우 목적을 문서 제목의 기능명으로 유지한다. 일반 제품명이나 표현이 유사하다는 것만으로 같은 용도로 입력하지 않는다. 문서 역할은 overview/capability/reference/configuration/example/migration/test/release 중 공식 breadcrumb·URL·제목이 지지하는 값이다. 같은 장의 분리 fragment라도 역할·이름·방향이 표시상 다르면 별도 키다. 일반 기능명이 불분명하면 미확인이다. 판은 명시한 번호·버전 선택 표시·고정 발행판만 인정한다. `stable`, `latest` 호칭만 확인된 경우 미확인이다. 릴리스 판이 같은 사이트 문서에 실제 나타나면 절에도 그 판을 적용한다. 하나라도 미확인인 C 행은 고유 슬롯 단독이다. A는 resolve URL(쿼리·fragment 보존), B는 발행 자료상 상류(미확인은 슬롯 단독)다.

## 화면, 경로와 판정

모든 방식에서 세 대표는 그룹 첫 출현순·첫 멤버를 띄운다. 카드 `원문 보기`(5자)와 빈 설명을 고정하고, 각 카드의 `관련 링크`(5자)에서 그룹 전체 원멤버를 원순서로 열거한다. 한 멤버 그룹의 목록도 실제 경로에 넣는다. 비어 있는 칸은 행으로 남긴다. 키·세 그룹·대표·모든 href와 경로는 답안 채점 전에 먼저 봉인한다. 후보를 열 때 접근 오류는 다음 슬롯으로 대체하지 않는다.

판독 창은 [044 §5][old]의 경계를 복제한다. fragment가 있으면 실제 element에서 동급 이상 다음 heading 직전까지의 절, 없으면 main/article/body의 첫 h1 뒤 최초 800 whitespace 단어다. heading 밖 anchor/definition은 도착 element부터 인접 동급 이상 제목까지 관찰하며 정확한 절 이름을 따로 남긴다. 페이지에 실제 800단어 이하일 때는 끝까지, 문서 내 링크 단어 위치가 경계를 넘으면 제외한다. 아예 fragment가 없어진 HTTP 200은 정확 도착 실패다.

빈 화면 상태의 오름차순 계획에 (1) 표시 대표 열기; (2) 첫 대표 → 다른 표시 대표의 모든 순서쌍; (3) 해당 카드 형제 버튼 → 원멤버; (4) 대표 → 도착 판독 창 내 첫 두 정보 href를 넣는다. href 적격은 의미 정답과 독립이다. 실제 HTTP(S) a 링크, 탐색용 퍼머링크·전역 UI·동일 정확 URL 자기 링크 제외, 같은 페이지 다른 fragment 및 반복은 유지한다. 창의 셋째 이후는 계획 밖으로 기록한다. 첫 도착 실패 시 그 문서에서 둘째 링크 조작은 미실시다. 새 HTTP 관측은 케이스/동작열 기준으로 중복 제거하고 방식 적용 횟수를 별도 센다. 서로 다른 방식에서 같은 유효 경로의 도착 재사용은 관측 1회다. 실제 클릭 가능한 저장 입력 재생의 절·판은 라이브 HTTP와 별도 ID를 사용한다. 도착 전 목록 자체에는 atom이 없다. 경로별 URL·부모 raw href·출발/도착 해시·실행 조작 수·절·실패를 연결한다.

원풀의 적격 대안은 독립 구현/허용 조합·같은 판·같은 방향에 대한 필수 atom 전체를 원풀 도착 창의 합집합이 지지할 때만 ID를 부여한다. 근거 없는 대안은 0으로 세기 전 풀/응답/창의 관측 가능 범위를 확인한다. 각 direct는 개별 대표 한 도착에서 완전한 ID의 합집합이다. 두 동작 도달은 한 시행에서 확인된 완전 ID의 합집합, 한 시행 최대는 그중 가장 큰 동시 확인 수다. 같은 구현·판이라도 다른 시행의 부분조건을 합치지 않는다. 풀 밖 새 대안은 원풀 분모 밖 진단이다. 원풀 부재, 잘못 합친 키, 세 자리 잘림, 도착 실패, 경로 예산 밖을 필요 시 중첩 사유로 표시한다. 미관측 값은 null/미확인이고 적격 실제 0 분모의 조건부 비율은 해당 없음이다.

## 반례·재현·봉인

예상 반례는 첫 대표가 여러 대안을 이미 설명하는 경우, 다섯 표시 필드가 같아도 입력/출력 방향의 계약이 다른 경우, 판이 없어 단독인 경우, 병합이 네 번째 다른 구현을 띄우는 경우, 세 번째 이후만 병합해 세 대표가 그대로인 경우다. 한 저작의 다른 판을 국립도서관 레코드와 규칙, 같은 정차명에 다른 승강장/방향을 발행기관 GTFS와 시간표에서 확인한다. 한 대표가 충분할 질문과 원멤버가 필요한 질문을 둘 다 찾는다. 사람의 이해·채택·작업 시간은 이 도달 관측으로 추정하지 않는다.

저장 입력은 허용되는 원응답 fixture 또는 바이트 동일성 검증이 가능한 공개 고정 자산을 우선한다. 증명되지 않은 경우 공개용으로 최소 파서 입력(원 href·heading·anchor·판·판독 창 위치·바이트 해시)을 저장하고 원응답 영구 재검증과 구분한다. HTML 파서·버전 미표기 감도는 고정 규칙 분석 뒤 별도 부록이다. 새로운 HTTP 수집과 저장 입력 재생에 서로 다른 실행 ID를 부여한다. 5 최초 요구·4 공식 목적 안내·7 공급자 문서/기능 저작·4 릴리스/시험/호환성 저작·4 분야 원자료를 각각 직접 열어 읽되 고유 1차 원문은 한 배당에 한 번 센다.
