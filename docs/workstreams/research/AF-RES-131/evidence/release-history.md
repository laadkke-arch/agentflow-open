# 안정판 경계와 배포 계보

`releases.csv`의 같은 행에서 패키지 시각과 태그 시각을 따로 읽는다. 64/64 tarball에서 npm SHA-512·SHA-1, package version, Translate SHA-256을 확인했다. 완전히 같은 배포 모듈은 16개 SHA, 대응 Git 소스는 15개 blob이다. 각 그룹의 constructor와 hit callback의 줄을 읽고, 소스에서 class branch와 tarball의 ES5 prototype branch를 대조했다. npm 태그 소스와 완전히 같은 35개, 빌드가 달라지는 27개, 태그가 없고 기록된 gitHead로 연결된 2개다. 6.x의 27개는 생성자/prototype과 import·sourcemap이 다른 배포 코드다. 양 옵션과 condition의 존재를 대응해 64/64가 같은 판정을 냈다. ## 공개 순서와 반증

양 옵션의 경계는 semver와 publish UTC 정렬 모두 6.6.1 → 6.7.0이다. 6.6.1의 태그 시각 2021-07-15 09:14:51 UTC, npm 09:15:55.869 UTC의 차는 64.869초다. 6.7.0의 태그 2021-09-09 17:33:02 UTC와 npm 17:33:58.060 UTC의 차는 56.060초다. 구형 15/64, 신형 49/64, 미판독·부재·사이 안정판 각 0이다. stable의 두 옵션에 각각 64/64 판독, 64/64 대응 소스 비교 가능, 뒤집힘 0/63 인접쌍이다. 여기서 뒤집힘은 신형에서 구형으로의 복귀를 센다. 제외된 두 개발판 중 `6.6.2-dev.1629476146484`는 병합 전 구형, `6.6.2-dev.1629628221039`는 병합 뒤 신형이며 후자는 6.7.0의 Translate tarball 모듈과 SHA가 같다. 두 개발판 모두 npm gitHead가 없어 정확한 개발 소스 커밋은 미확인이다. [공개군 비교](release-rules.json) · [개발판 두 건](lineage-probes.json)

10.7.1의 npm gitHead는 `034b63ccbdcd4c2d29411949c86543b251582599`이고 10.8.0 태그의 조상이다. npm에는 10.7.1이 먼저 12:12:54.303 UTC, 10.8.0이 14:08:26.693 UTC, 10.7.2가 18:56:39.243 UTC에 올라왔다. 10.7.1·10.7.2에는 같은 번호의 Git 태그가 없다. 유지보수자가 10.7.2를 10.7.0의 태그에서 다시 냈다고 확인했다. 실제 10.7.2에서 1,095개 tarball 파일 중 package.json만 달랐다. 10.7.1은 10.7.0 대비 268개 파일의 합집합 차이가 있고 10.8.0은 같은 수만큼 다르다. 네 판의 Translate는 같은 SHA다. 이 경우 배포·계보 역전과 일부 앱의 빌드 변화는 실제며 Translate 옵션 계약은 그대로였다. 조사한 안정판에서 구형으로 돌아가는 유지보수 백포트는 관측되지 않았다.
