# Pillow 사전 판정의 해석 한계

이 주석은 A/B 원본을 고치지 않는다. 2026-11-23 사전 봉인 준비 중 root 검토를 반영했다. 아직 후속 회신·수정·회귀시험을 열지 않았다.

## P3의 변화는 세 필드의 순수 효과가 아니다

A의 유보→B의 묶음에는 같은 요청의 목적을 다시 해석한 효과가 섞여 있다. 원 작성자가 새 RGBRGB 순서를 선호한다는 문구는 A를 작성할 때도 제공됐다. A는 8.2 호환 목적을 가능한 조건으로 크게 남겼고, B는 원문에 명시된 8.3 새 순서 선호로 적용 범위를 좁혔다. 추가 필드만으로 정확도가 개선됐다는 인과 주장을 허용하지 않는다. 독립 연구자·무작위 순서·새 사용자 검증도 없다.

P3 B의 next_operation은 완성된 이미지 출력 이후의 새로운 편집·선택이 아니라, 생성된 palette를 image에 부착하는 후보의 실행 단계다. 원문에는 이후 show/getpalette 비교가 있지만 두 후보의 고정 절에서 이 별도 읽기 결과까지 모두 확인하지 않았다. 따라서 P3는 Q3의 엄격한 ‘첫 출력 이후 다음 조작’ 효과를 충족했다고 세지 않는다. 공식 구현상 같은 p를 다루는 입력 경로라는 제한된 지지를 기록한 것이다.

## P1·P2의 빈칸

P1은 요청에 자막·GIF 저장이 있지만 같은 두 후보 절이 전체 저장 결과의 palette·색 보존을 보증하지 않아 next_operation/preserve_value를 null로 남겼다. 후보 두 번째는 convert→expand라는 조합이며 완결 GIF 자막 구현 두 개가 아니다. 두 링크가 서로 완성된 대체품이라는 결론은 미확인이다.

P2의 사용자는 RGBA 모드라는 첫 결과를 이미 명시했다. 추가 후속 편집 요구는 원문에 없고 next_operation은 null이다. A만으로도 분리 판단을 할 수 있었으므로 추가 필드가 반드시 필요하다는 근거로 삼지 않는다. 사후 공식 테스트가 있더라도 정확한 원 입력·대상 판·두 호출 결과를 모두 갖추었는지 따로 확인한다.

## 사후 채점의 원칙

같은 공식 후보 코드로 기대값을 다시 추론한 것을 독립 정답으로 세지 않는다. 작성자 후속/유지관리자 회신/회귀시험을 각각 귀속하고, 실제 같은 요청·판에서 두 후보 호출을 대조할 수 있는 자리만 채점한다. 어느 한 후보나 다른 판만 확인되면 유보·미확인과 다음 최소 관측을 남긴다.
