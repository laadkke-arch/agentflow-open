# AF-RES-039 · 실행 전 범위와 채점 규칙

2026-11-22 UTC. 고정 표본 G01–G06/R01–R06, 24짝 48실행. 비교 단위는 같은 참조와 과업의 C1/C2 짝이다. 표집·036의 판독·기준을 재작성하지 않는다. 실제 배정 SHA, 계획 SHA, 실행 환경 및 실제 확인 가능한 모델 범위는 [manifest.json](manifest.json) 참조. 의존 인계는 [036 HANDOFF](https://github.com/laadkke-arch/agentflow-open/blob/5682b0d61a80edc159d4b510d213bbb4c69543be/docs/workstreams/research/AF-RES-036/HANDOFF.md)다.

## 저장물과 가시 범위

- C1은 C1_B_presealed, C2는 C2_BH_with_provenance다. 036 retention-options.jsonl의 UTF-8 행과 끝의 LF를 그대로 파일 하나로 옮긴다. JSON을 다시 직렬화하지 않는다. B·H는 필드의 UTF-8 바이트를 센다. C2 H_spans에 있는 036 작업 폴더 경로는 출처 메타데이터다. 실행기에서 경로를 열지 않는다. C2의 출처 주소는 C2의 실제 처리 정보다.
- 실행기는 저장 파일과 공통 replay.py, 과업 인자만 받는다. 실행 순서·seed와 채점판 파일/행 해시는 inputs.jsonl에 별도 기록한다. B 안의 소비자 문서·주소·판·문맥/목적은 입력이다. N, 036 공유 취득 계획, 판정·사후 대체 URL·정답 해시·이전 실행 URL 및 파일은 미제공이다. 실행기의 stdout·몸체 증거는 실행 이후 감독 프로세스가 수거한다.
- 새 CWD·HOME·캐시 디렉터리, 새 Python 과정, 쿠키·자동 재시도·.curlrc 미사용. 통신에는 같은 관리형 egress의 상속 프록시와 검증 가능한 TLS를 쓴다. 중간 프록시/CDN 캐시는 관측 가능한 헤더만 남긴다. 애플리케이션의 빈 캐시와 인터넷 중간 캐시 상태는 별개다. R01/G05는 먼저 네트워크 없이 파일/필드 경계를 검증한다. 결과는 별도 저장한다.
- Scorecard는 036 references.jsonl, components.jsonl, adjudication.csv의 파일 SHA-256과 해당 참조의 기존 N/H 증거 행 해시로 고정한다. 계획 단계는 본문이나 정답 locator를 조회 실행기 규칙에 넣지 않는다. 같은 조회창에서 새로 확인한 근거로 현재 판정을 사후 검토한다. replay-costs.csv의 값은 48건을 봉인한 후에만 읽고 조인한다.

## 조회 규칙 v1

1. 각 짝은 연속 실행한다. Python random.Random(39036)으로 12 ID × (current, restore)를 섞고 짝 순위 0부터 짝수는 C1 먼저, 홀수는 C2 먼저 실행한다. 입력·알고리즘·버전을 GET 전에 원격 커밋한다.
2. 원 href를 첫 논리 GET으로 연다. 이동 시 Location을 따라가되 기존 fragment의 상속 여부를 보존한다. 두 번째 GET은 같은 발행자와 판 범위에서 선택한다. 평문 연결이 거부되면 같은 주소의 HTTPS가 우선이다. 필요한 절이 부족하면 반환 문서의 링크 중 원 link text/인용 문맥의 표식과 맞는 공개 설명·색인을 우선한다. 링크를 발견하지 못하면 원 주소 구조의 공개 발행자 색인(부모 문서나 버전 색인)으로 한 번만 좁힌다. 목록 조회도 GET을 소비한다.
3. T현재는 섹션 검사 성공 시 원 링크 경로는 유지, 별도 발견 주소는 교체를 반환한다. 다른 판으로 유도되었거나 절·기능·판을 확인할 수 없으면 보류한다. 원 링크의 자동 canonical redirect는 원 링크 경로에 속한다. B가 목적지 판을 명시한 경우 C2의 같은 판 발행 기록은 fallback 후보가 될 수 있다. 저장 H만으로 현재 이용 가능성을 인정하지 않는다. 발행자 표준 색인 자체가 목표인 경우 해당 판과 문서 탐색 진입부, 배포처인 경우 릴리스 파일 링크를 확인한다. 정보 검사는 B의 인용 표식과 절 구조에 기반한 제한된 규칙이며 사후의 사람 기준과 분리한다.
4. T복원은 036에서 사용한 N·H의 발행 근거 발췌를 재표시하는 과업이다. 원 href 및 목적지 절을 먼저 처리하고, N 후보를 확보하면 남은 GET을 이력 발행본이나 색인에 쓸 수 있다. H 주소가 저장되었다면 해당 발행본이 우선한다. C1은 반환 링크의 판 단서나 공개 발행자 버전 색인을 쓴다. H에 여러 발행본/멤버가 있어도 같은 예산을 쓴다. C2는 로컬 H의 해시를 검사하고 본문을 제시하며, 독립 재취득 여부를 별도로 기록한다. 200, 링크/제목, 목록 단서 또는 H 메타데이터만으로 본문을 인증하지 않는다.
5. 전체 예산은 실행당 논리 GET 최대 2, 각 논리 GET의 리다이렉트를 포함해 전송 총 30초다. curl 기본 retry 없이 Location을 수동 추적한다. 루프·잘못된 Location·타임아웃·전송 실패를 보존한다. 성공 응답 본문과 오류/리다이렉트 본문을 분리 기록한다. bytes는 curl이 로컬로 넘긴 (헤더와 transfer framing 제외) body 바이트다. 애플리케이션 HTTP GET 교환, 상태 없는 전송 시도, 프록시 CONNECT를 따로 센다. 엄격 2교환 기준은 실제 순서의 문서 HTTP 교환 최초 2개까지만 증거로 다시 채점한다. 이는 같은 실행의 절단치이며 별도 독립 표본을 추가하지 않는다. 논리 GET 한도는 엄격 기준에도 적용된다.

## 사후 판정과 반례

- 현재의 완전 성공은 같은 조회창에서 확인한 목적/판과 일치하는 확정 행동 및 실행 내 필요 절 확보를 모두 요구한다. 책/릴리스 판을 추정했거나 일부 문구·색인만 얻은 경우 부분, 확보 실패나 근거 부족은 보류를 기록한다. 기준 부재는 미확인으로 분리한다. 보류를 성공률 분자에 넣지 않는다. 036의 행동과 새 기준은 각각 남긴다.
- 복원은 각 N/H에서 정확 발췌 바이트, 공백/직렬화 차이로 같은 내용, 부분, 실패를 순서대로 확인한다. 각 H에는 local-only / 새로 연 발행본 / 본문까지 독립 일치 여부를 별도 표시한다. 본문 근거는 버전에 맞는 발행자 주소·절/멤버와 함께 평가한다. 기본 성공은 N과 H의 모든 고정 발췌가 정확히 복원된 경우다. 내용 등가까지 합친 민감도를 따로 낸다. 전체 응답 해시와 발췌 해시, 저장 카드 해시, 036의 당시 접근 사건과 시각은 각각 다른 조건이다.
- 사전 반례: G05는 올해 절을 여는 비용·행동에서 H가 이득을 주지 않아도 옛 GCC 절을 즉시 표시할 수 있다. G03은 2018 판이 B에 있으므로 특정판의 가치와 C2의 증분을 분리한다. R01은 036 H tarball과 교체 기준 HTML이 서로 다른 위치다. H는 로컬 복원에 유리해도 현재 대체 경로를 찾아주지 않을 수 있다. 반대로 H의 판·경로가 충분하고 원 링크가 무너지면 C2만 현재 성공할 수 있다. HTTP 200과 잘못된 anchor/판, archive 멤버 부재, 동등하나 바이트가 다른 본문, 관리형 egress 차단을 따로 검증한다.
- 원장 최소치는 직접 연 소비자 12, 서로 다른 현재 설명 6, 별개 이력 4, 통계·서지 발행 원문 각 1이다. 같은 작품의 표기·재배포 중복은 추가 개수로 인정하지 않는다. 기준/원장 조회와 48건 이후 재시도/추가 예산은 별도 구간으로 계측한다. 공개 웹 도구가 본문만 돌려주고 전송 계측을 제공하지 않으면 해당 칸은 미확인으로 둔다.
- 판정률은 목표와 예산마다 12짝, 모든 24짝의 양방향 차이 및 부분·보류를 그대로 보고한다. 036 모의는 알려진 locator, 과거 크기, 자원 공유 가정이 같은 단위에서만 비교한다. 저장 증가의 반복 회수 식은 매회 동일 결과·동일 바이트 단위의 절약이 양수인 조건에서만 수치화한다. 노동·돈·원본 접속 시각 증명은 별도 증거가 필요하다.
