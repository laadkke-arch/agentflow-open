### Q2 streamcopy와 경계가 함께 성립하는 조건
FFmpeg input -ss는 앞선 seek point로 이동, transcoding + accurate_seek는 중간 decode/discard, streamcopy 또는 noaccurate_seek에서는 이 구간이 보존될 수 있다. Output -ss는 출력 시각에 맞춰 discard하는 규칙이지만 독립 디코드 가능 첫 프레임·정확 copy 보장은 아니다. -seek_timestamp는 nonzero start time의 절대/상대 해석을 바꾼다. [F01](https://ffmpeg.org/ffmpeg.html) (3.1 L207–235; -ss L968–969; accurate_seek L2631–2637). MKVToolNix --split parts 및 parts-frames는 요청 시각/프레임·필드/블록과 실제 keyframe 경계를 분리하며 시작/끝 모두 다음 keyframe 규칙; 연결하는 부분의 timestamps도 조정된다. 첫 영상 트랙 기준이므로 다른 영상/음성/자막을 같은 경계로 증명하지 못함. [F02](https://mkvtoolnix.download/doc/mkvmerge.html) (2.5 --split L107–134). segment muxer의 기준 stream, delta, keyframe forced transcode, [F04](https://ffmpeg.org/ffmpeg-formats.html) (4.74 segment muxer L4661–4671,4725–4755). B-frame의 decode order와 presentation order가 다르고 RAP가 아닌 I-frame도 있을 수 있어 패킷 K flag나 플레이어 이동만으로 완전 독립성 확인 불가([I04](https://kicherer.org/joomla/index.php/de/blog/42-avcut-frame-accurate-video-cutting-with-only-small-quality-loss) (Basics L12–32; Implementation L39–55), [I02](https://github.com/skeskinen/smartcut/blob/master/README.md) (Usage Basic Commands, Audio Export, Testing, Version History)). 
- 충분한 단순 사례(조건부 규칙): 이미 독립 RAP에 맞춘 start, 호환 가능한 codec/container, end와 동반 track 경계도 허용, 숨겨진 prefix 없음이 요구일 때는 copy. L03 exact branch가 encode 생략. I05 complete GOP 삭제 fixture의 기대값(100 frames)도 사례 설계 참고이지 실행 아님.
