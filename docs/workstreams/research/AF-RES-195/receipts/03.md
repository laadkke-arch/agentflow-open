# 단계 3 · 분절 대조 실행

Codex Cloud, Python 3.12.14, pandas 2.2.3, Git 2.52.0. 저자 함수 `time2seconds`, `per2metrics`, `per2texts` 및 두 상수의 고정 AST를 그대로 실행했다. pandas만 추가로 사용한다. 언어 모델, TER, QE, 전체 전처리 CLI 실행은 범위 밖이다. 입력 파일의 절대시각은 이벤트 ms와 무관하며 결과표에서 제외했다.

```sh
d=docs/workstreams/research/AF-RES-195
python "$d/extract.py" inventory --upstream /workspace/af195-input/divemt --prior-repo . --out "$d"
python "$d/extract.py" measure --upstream /workspace/af195-input/divemt --prior-repo . --out "$d"
git -C /workspace/af195-input/divemt ls-tree --long a3b514c99529f13ffda5d2143fc836d04cc974b3 data/raw/ita.zip data/raw/tur.zip
```

세 실행은 종료 코드 0이다. measure의 stdout/stderr와 결과 지문은 이 폴더에 있다. 관측 행 단위는 완료 .per의 분절이다. 별도 `03-revisions.csv`는 96개 백업/408 분절 상태, `03-pairs.csv`는 32개 같은 원문 조건 삼중쌍을 보존한다. 고정 TSV를 획득한 뒤 measure 명령에 `--hf-main /workspace/af195-input/hf/main.tsv`를 붙이면 원래 행번호, 모드 키 검증, ms, 단어 및 텍스트 해시가 독립 산식 및 저자 파서 옆에 채워진다. 입력은 SHA-256을 검증한다.

단계 2 목록화에서 .pej 파일의 job/폴더·조건은 정상 관측했으나 /job/unit 개수를 조회해 배정 입력의 분절 수를 0으로 기록했다. 첫 measure 시도(프로세스 종료 0, 의미 검증 실패)는 96개 raw 행과 24자리 job이 있었으나 입력 비교 0행이었다. 원 XML을 직접 다시 읽어 .pej의 자식이 `/job/task`, .per는 `/job/unit`임을 확인했다. 원 ID·원문 및 MT hash를 그대로 검증하고 선택 24자리의 계획 task 96개 및 비교 96행으로 바로잡았다. 입력 ZIP·선택 문서·원파일 지문은 동일하다. 따라서 단계 2 파일의 체크섬은 당시 커밋에서 재검산한다.

`03-viewer-five.csv`는 공개 [Dataset Viewer main/train](https://huggingface.co/datasets/GroNLP/divemt) 표시행 94,99,104,107,112에서 E1–E5의 12개 비식별 열만 추출한 투영이다. unit/flores/item/subject ID와 원 이벤트 ms, 단어, 대상 문자수, 각 휴지 건수·ms 및 방문 수를 `segments.csv`와 직접 검산했다. `03-viewer.stdout`은 비교 종료 0의 로그다. 변환 viewer의 정확 입력 SHA를 확인하지 못해 이 수치는 고정 TSV join에 산입하지 않았다.
