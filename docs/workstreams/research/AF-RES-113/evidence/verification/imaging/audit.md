## R6 정정의 범위와 남은 모순

R6 정정은 단순한 선택지 추가가 아니라 초기 규칙 적용 오류의 정정이다. common 4/6에서 5/6으로 늘고, 공석의 원인은 시작 4+링크 5에서 시작 2+링크 7로 바뀐다. 추가 노출은 여전히 3, 공석은 9, 비교쌍은 0이다. 총수가 그대로라는 사실로 초기 오판을 숨기면 안 된다. PREJUDGMENT와 초기 common-review의 옛 R6 설명은 역사적 문서로 유지하되 최종 설명은 R6-v2.json을 참조해야 한다.

복구된 project/notes.md에는 다시 ‘보수적 보류, lab2lch로 볼 수 있음’이라는 이전 문장이 있었다. requests.jsonl에도 초기 target_symbol=null과 불명확 판정이 남아 있다. 이는 모두 같은 최신 판정을 말하는 것으로 읽히면 모순이다. root에 알렸으며 이 감사자가 해당 파일을 고치지는 않았다. 최종 통합은 원판 기록인지 정정된 현재 판단인지 열/문장으로 분명히 해야 한다.

고정 lch2lab 절에는 inline astronaut 왕복만 있고 독립 gallery href는 없다. B 후보는 source, 자기 anchor, See also lab2lch, EasyRGB bare URL, Wikipedia 두 항목이다. source/API 교차참조/일반 배경은 제외할 수 있다. EasyRGB 제외의 근거는 **시작절에 원방법 제안자나 원표준으로 귀속한 문장이 없다는 것**이다. 목적지를 읽지 않았으므로 EasyRGB 저작의 정확성·원작성 여부 자체를 부정하면 안 된다. 새로운 독자가 그곳을 읽고 유용한 값을 찾더라도 그것은 이번 엄격 출전 경로와 별도 탐색이다.

원글 dtype assert는 LF24의 lab.dtype이고 LF27은 lab2와 lab의 수치 비교다. 두 조건을 ‘최종 왕복 출력의 dtype·오차 두 assert’로 합쳐 쓰면 실제 코드를 잘못 요약한다. lch2lab 공통 문서의 shape/channel_axis 조건은 유용하지만 원 s390x 수치 실패의 원인·수리·dtype 보증은 아니다.

## R2의 공석과 첫 3선별은 별개 문제다

#1648은 mir_eval.sonify.pitch_contour라는 이미 알려진 구현을 지목했다. 따라서 ‘관련 구현을 찾지 못한 요청’이라고 기술하면 연구 질문의 출발점도 왜곡된다. 이번 지정 원 프로젝트는 librosa이고, 원글은 그곳에 구현을 두려 하지만 해당 public 목표 함수명을 지정하지 않았다. pyin은 입력 f0를 만드는 upstream 예이고 NumPy cumsum/nancumsum은 구현 연산이므로 임의 대체가 아니다. 이 제한 안에서 API 공석을 남기는 것은 타당하다.

그러나 Q1 적격성과 Q2 대응은 별도다. 명시된 기능이 있으니 Q1의 기능 요건을 통과할 수 있어도, 독립 보존 조건이 있다고 자동 추론할 수 없다. 원글의 NaN 처리, scoop 제거, sr/hop grid는 모두 바꾸거나 추가할 요구일 수 있다. 현재 frame/preserve의 합성 유지 설명을 엄격하게 적용하면 미충족이라는 강한 반대 코딩이 가능하다. 따라서 ‘확정된 첫 3 적격’의 재현 가능성을 제한하는 경계 사례로 남겨야 한다. 후속 댓글에서 원 저자가 mir_eval 쪽 PR로 갔다고 말한 것은 원 선별 때 가려졌고, 이 의문을 사후에 소거하는 근거도 아니다.

생성순 프레임 120, 공식 판정 13, 선택 6, 제외 7, 이후 미선별 107의 산술은 맞는다. 실제 batch 본문은 22개였으므로 ‘quota 뒤를 한 번도 보지 않았다’는 주장은 틀리다. API가 반환한 100행 전체를 읽었다는 주장도 하지 않는다. 양 프로젝트 60번째 경계가 모두 2023년이므로 2023–2024의 시간 분포를 대표하는 표본은 아니다.

## 새로 기각한 R3 입력과 남겨야 할 관측

직접 재독해한 소스는 [librosa 고정 segment.py](https://github.com/librosa/librosa/blob/9caf46a4ecaeb8ea24bb541231065c9f761174ae/librosa/segment.py), 파일 SHA256 `6f5fc0aa99569f0e1d2f1d42d82b12eb49158243f4736d76b6c26408c0f97f5f`이다. LF580–586이 observation 축의 길이 t를 정하고, LF588–593이 width를 검사한다. 이 guard는 LF612 이후 neighbor search보다 앞선다. 따라서 data=[[0,.1,100]], width=1의 첫 실패는 빈 행의 scalar/pairwise 분기가 아니다.

`executed-checks.json`의 CSR [[0,.1,0],[.1,0,0],[0,0,0]], k=1은 별도의 고립 함수 입력이다. scalar 0.1, mean/gmean 빈 이웃 오류, 전부 빈 그래프의 scalar 오류라는 실제 기록을 지울 이유는 없다. 다만 public recurrence_matrix가 그 CSR을 생성했다는 증거는 아니다. local 예외 대역 클래스와 분리 실행이라는 한계도 그대로 둬야 한다.

후속 구성 입력 data=[[0,.1,10,10.1,100]], k=1, width=1, sym=True는 t=5에서 width guard를 통과한다. 상호 가까운 두 쌍과 고립점을 만들 것이라는 기대는 소스 흐름/거리의 예상이며, 이 감사에서는 public API를 실행하지 않았다. mode='affinity' 및 scalar/pairwise bandwidth 옵션, 반환 그래프, singleton과 실제 값/오류를 같은 고정판에서 관측해야 public 구별 입력이 된다. 이를 사전 3점 예측의 성공으로 바꾸거나 최초 B 성과로 세면 안 된다.

## 고유 저작 단위와 반대 방향 근거

project 8개는 LIB-COMMON-STREAM, LIB-COMMON-RECURRENCE, R4-COMMON, R5-COMMON, HOP-R4-A, HOP-R5-A, V-STFT, V-MORPH-GALLERY다. 같은 함수 docstring이나 뒤 구현 재독해는 같은 work_id 계보에 연결해야 한다. 두 A 예제는 3000자 본문 접두사를 직접 읽었으므로 본문 도달 자료지만 전체 완독·방법 전체 독해는 아니다. R6 기능 문서는 추가 검증으로만 남겨 숫자를 늘리지 않은 보수적 처리를 유지한다.

방법 6개는 NET-METHOD-SELF/STFT/SNF와 M-IMG-OTSU/GIL/PYE다. Soille survey를 원방법 제안자 배당에서 제외했고 van Herk 검색 요약도 산입하지 않았다. SNF는 기관본 방법 텍스트를 읽었지만 수식의 PDF 시각 확인 실패를 그대로 남긴다. 같은 논문 DOI·미러·재개봉은 한 저작이다.

외부 4개는 EXT-ACOUST-FARINA2000/2007, EXT-MAP-OGC11/GDAL33이다. 앞의 둘은 같은 연구자 후속, 뒤의 둘은 명세와 구현의 직접 계보다. 저작 4개라는 사실을 독립 실험집단 4개로 표현하면 안 된다. 실제 읽은 반복/실패/metadata를 sources에 남기는 것은 좋지만 그 행수를 고유 저작 배당으로 합치지 않는다. 최종 집계는 evidence/source-census.json에서 확인해야 한다.

반대 증거가 판단을 실제로 제한한 사례는 충분하다. Otsu histogram 수학으로 1D API 허용을 정당화할 수 없고, Gil–Kimmel은 R5의 영상 경계를 제외하며, Pye의 연속 창은 구멍 난 footprint를 보존하지 않는다. Soille의 원점 포함 조건 때문에 중심점 없는 footprint에서 출력이 작아지는 사실 자체도 오류가 아니다. Cornea 뒤 절은 opening에서 잃은 실제 좌표와 대안을 주므로 ‘예제가 예외를 안 준다’는 일반화는 폐기해야 한다. Farina2007은 clock 견고성의 한계를, GDAL RFC33은 올바른 명세 해석과 과거 파일 호환성의 충돌을 보여 준다. 이 자료는 모두 사후 검증이며 원 홉 발견 수를 바꾸지 않는다.

## 봉인 시점·실험 독립성·완료를 막는 조건

초기 A/B는 별도의 새 자동 문맥으로 원글·공통·자기 경로만 읽었다는 범위 영수증이 있다. root는 양쪽 내용과 종합을 봤다. 이 감사자는 사후 영상 원전을 읽었으며 초기 경로 독자가 아니다. 같은 A/B의 R6 v2 재판독은 추가 공통 입력을 본 같은 문맥이고 새 독립 독자 실험이 아니다. 장애 후 같은 packet의 일치 확인·재판독도 새로운 인간 효과 자료가 아니다.

Git metadata에서 노출 봉인 11287 생성은 04:14:07 UTC, A 시작은 04:14:38 UTC다. 커밋 선행은 확인되지만 readback 기록 시각 04:14:54만으로 readback까지 A 시작 전에 끝났다고 증명할 수는 없다. 기록 지연과 사건 시각을 구별해야 한다. 문서판의 fixed commit은 불변 소스를 지정하지만 0.26.x 배포 HTML이나 issue snapshot까지 불변이라는 뜻은 아니다.

다음 조건을 만족하지 않으면 완료라고 쓸 수 없다.

- 원래 6요청·12자리와 결손을 모두 유지하고, 0/6쌍을 비교 효과 0으로 바꾸지 않을 것. 현재 핵심 비교 결손은 PARTIAL 사유다.
- R2 적격성 경계, R6 규칙 적용 정정, R3 무효 후보를 최종 표/원장/재현 절차가 함께 표현할 것.
- R6 동일 독자의 복구 재판독 파일과 재구성의 범위를 실제로 저장할 것. 소실된 결과를 원격에 존재했던 문서로 주장하지 않을 것.
- 고유 24개 배당과 모든 직접 읽기/실패/반복의 계보를 최종 census로 대사할 것. 초기 홉과 사후 검증·외부 분야를 섞지 않을 것.
- 가변 원문의 같은 지문 재취득 가능 여부와 못 복구한 부분을 기록할 것. 집계 재현과 원문 입력 전체 재현을 구분할 것.
- RESULT·원장·재현 절차의 원격 결과 SHA를 고정하고 그 SHA의 파일·대표 원문을 재열람한 뒤 manifest와 적용 공통 검사 결과를 기록할 것. 이 감사가 저장소 수용 검사 통과를 대신하지 않는다.

이 감사에서는 원 프로젝트나 최종 검사 명령을 실행하지 않았다. 실행 영수증과 고정 소스의 제한된 구간을 대조했으며, 현재 저작/선별 계수를 확인한 수준이다. 다른 정식 원장을 수정하지 않고 이 audit과 SELF_CHECK만 재작성했다.
