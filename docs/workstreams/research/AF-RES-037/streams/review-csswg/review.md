# 독립 반증 검토 · CSSWG 담당의 교차 검토

## 권고

**B02 전체 RFC20을 엄격한 타 분야 C3로 올리지 않는다.** 봉인한 SCOPE의 C1 조건은 “수신 원안에 이미 같은 선택이면 반드시 여기 또는 더 낮은 판정”이다. B02 초기 선택은 이미 EPSG 축을 명시하고 기존 longitude/latitude 호환성을 보존하는 방안이다. 다만 좁은 GMLJP2의 기존 코드가 실제 바뀐 사실을 부정해서도 안 된다. 표에는 **전체 RFC20: C1·부분 반영 / 독립 부분 GMLJP2: 저자의 표준 준수 연결과 코드 변경 확인, 규범 연결은 보강됨, 타 분야 분류는 논쟁적**으로 범위를 나누어 적는다. 좁은 부분은 같은 B02 사건 내부이며 사건 분모를 늘리지 않는다.

처음에는 05-047r3 §7.7만으로 origin/offset tuple 순서가 정해지지 않는 점 때문에 C2의 원문 접점 미확인을 권고했다. ROOT-P10의 GML 3.1 원문 §12.4.3.1을 읽은 뒤 이 반론을 수정했다. §9.1.3.1의 DirectPosition/pos, §9.1.4.1의 VectorType, RectifiedGrid의 origin 및 offsetVector schema는 해당 규범을 객체에 연결한다. 따라서 **“당시 축 순서 규칙이 없었다”는 부정 결론도 지지되지 않는다.** DGIWG 2014의 실무상 불명료함은 이 명시 규칙의 부재 증명이 아니다. 마지막으로 EPSG:4326의 당대 특정 축 정의와 저자가 가리킨 출처 판을 연결하면 좁은 기술 준수 사슬의 규범 접점은 더 강해진다. 그러나 이것만으로 봉인한 원안 조건이나 분야 경계가 사라지지는 않는다.

## 표와 수치의 방어선

필수 표1의 B02 행에 좁은 GMLJP2 범위를 명시하되 전체 RFC20 성공으로 읽히지 않게 한다. 필수 표2는 A와 B를 합쳐 하나의 자연 발생 비율로 만들지 않는다. 각 층에서 표집 적격 전체와 역사적 양성 대조 적격을 분리한다. 엄격 사슬 0은 관측된 사슬 수이며 `미확인`의 실제 부재라는 뜻이 아니다. B의 타 분야 인과를 0으로 결론내리더라도 같은 분야의 실제 변경 사슬이나 회고 근거를 삭제하지 않는다.

“당대 가용”은 P(문서 발행), V(당시 공개), A(작성자의 인용), I(당시 검색색인)를 합쳐 한 참값으로 만들지 않아야 한다. ROOT-P10의 발행일/공식 ZIP과 2006 참조는 가용성에 관련되지만, 작성자가 어느 절을 언제 읽었는지와 당대 검색색인은 독립이다. `작성자 인용` 열은 단순 인용과 명시 인과를 구분한다. `실제 반영` 열은 구현 여부와 원문이 원인이었다는 판정을 분리한다.

반증으로 뒤집힌 수는 원래 잠정 판정과 바뀐 판정이 기록된 경우만 센다. 처음부터 C1로 둔 사건의 반례를 찾았다고 자동으로 “뒤집힘1”을 더하지 않는다. 이번 reviewer의 원문 접점 평가 수정은 review 차원의 정정이며, root가 C3를 실제 기록했다가 변경한 적이 없다면 주 결과의 뒤집힌 사건으로 세지 않는다.

## 추가로 이 결론을 바꾸는 최소 자료

B02를 현행 엄격 C3로 올리려면, 봉인한 원안보다 이전에 다른 선택을 유지하던 **동일 저자/같은 목적의 설계 기록**과 정확한 타 분야 원문을 접한 뒤 그 선택을 수정했다는 연결이 필요하다. 기존 코드 diff만으로는 원안 이후 새 선택이라는 조건을 채우지 못한다. 원안보다 이전의 코드 변경도 평가할 별도 해석 기준을 사후 명시하면 기술 준수 사슬의 민감도 양성이 될 수 있으나, 원래 strict 수치로 환산하면 안 된다. 분야 경계는 “지도”라는 명칭 대신 실제 제공 객체·권한의 비소프트웨어 기원과 수신 소프트웨어 연산의 관계로 설명해야 한다.

## 검토 범위와 제한

SCOPE, 사용자 지시, root의 donor/반례 원장, B 초기안 및 원장을 읽었다. 독립적으로 #2131 원문, bef1fa8 commit diff, OGC05-047r3 및 DGIWG104 공개 원문, root가 공식 ZIP에서 받은 GML-3.1.pdf의 관련 절을 확인했다. B 최종 followup 파일은 이 검토 스냅샷에 아직 없었으므로 들어오는 파일의 최종 주장·시험 SHA를 전체 검토했다고 하지 않는다. 직접 확인한 문헌은 기존 sourceID와 중복이며 추가 최소수에 세지 않는다. 다른 스트림은 수정하지 않았고 Git 작업은 하지 않았다.
