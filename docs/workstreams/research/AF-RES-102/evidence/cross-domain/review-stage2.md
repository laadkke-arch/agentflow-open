# Stage 2 독립 AI 검토

**판정: 봉인된 80개 신호에서 A/C층과 12자리를 독립 재계산한 결과가 일치한다. 8개는 실제 예측이고 4개는 공석이다. 새 본문 최초 열람이 원격 봉인 뒤인지의 최종 대조는 다음 고정 결과판까지 유보한다.**

검토 대상은 원격 2단계 커밋 `f1c5d6ff927fd5fbe108565598810ca7e94c5753`, tree `d8f7fd10edf18fb8665c3ca29d4874bb46522cb5`다. 두 프로젝트 작성자·root와 별도인 `/root/cross_domain` AI 에이전트가 수행했다. 사람 검토가 아니며, 자기 작성 Q7은 검토 대상에서 제외했다. 입력 지문·계산 결과·한계는 [review-stage2.json](review-stage2.json)에 있다.

## 독립 재계산

`git show <봉인 SHA>:<경로>`로 동결 자료를 읽었다. `prediction-seal.json`의 **18/18 파일 지문**이 일치했다. 두 옛 frame의 80개 해시를 다시 만들고, 새 배포 경로 목록과 옛 대응 source 경로의 blob을 대조했다. MP의 캐시된 원 tree는 봉인된 HTTP 영수증의 SHA-256과 먼저 대조한 뒤, 옛 source 경로에 해당하는 blob만 계산에 사용했다. 새 asset blob·본문·그림·개별 CI는 열거나 판단 입력으로 쓰지 않았다.

| 프로젝트 | 옛 적격 | 외부 경로 적용 가능 | inline/경로 적용 불가 | 옛 자원 경로 남음 | A 후보 | C 후보(일반층 제외 전 → 후) | 선택·공석 |
|---|---:|---:|---:|---:|---:|---:|---|
| ggplot2 | 40 | 40 | 0 | 40 | 0 | 40 → 38 | G 2 + C 2, A 2공석 |
| Matplotlib | 40 | 28 | 12 | 28 | 0 | 6 → 6 | G 2 + C 2, A 2공석 |

| 자리 | 동결 선택 | 독립 계산 |
|---|---|---|
| GG-G1/G2 | `expansion` / `geom_count` | 일치 |
| GG-A1/A2 | 공석 / 공석 | 일치 |
| GG-C1/C2 | `annotation_custom` / `geom_histogram` | 일치 |
| MP-G1/G2 | `demo_imagegrid_aspect` / `demo_colorbar_with_axes_divider` | 일치 |
| MP-A1/A2 | 공석 / 공석 | 일치 |
| MP-C1/C2 | `demo_axes_hbox_divider` / `inset_locator_demo` | 일치 |

실제 채워진 8자리의 예측은 **YES 8, NO 0, 유보 0**이다. root CSV의 공석 행에는 표시상 `미확인`이 있지만 `vacant=True`가 먼저 적용돼야 한다. **공석 4개를 유보 예측 4개나 관측 음성 4개로 세면 안 된다.** 동결 원장의 옛 resource/source 경로·blob을 바꾼 흔적은 없었고, root 통합 CSV의 사례 대응도 프로젝트 동결 자료와 일치했다.

## 순서와 원격 봉인

| 사건 | UTC | 판독 |
|---|---|---|
| 1단계 원격 검증 | 2026-11-23 22:03:18.088 | root `checkpoints.json` 영수증 |
| 가장 빠른 새 tree 영수증(MP) | 22:03:53.099031 | 1단계 원격 검증 뒤 |
| GG 예측 기록 | 22:04:03.902910 | 새 목록 뒤, 새 본문 전으로 기록 |
| MP 예측 기록 | 22:04:24.934583 | 새 목록 뒤, 새 본문 전으로 기록 |
| 로컬 통합 봉인 파일 | 22:06:29.242235 | 원격 봉인 이전 |
| 2단계 원격 검증 | **22:07:47.803** | 새 본문·payload·개별 CI 접근을 허용하는 실제 경계 |

원격 SHA의 parent/tree는 로컬 Git 객체와 영수증이 일치한다. 검토자는 원격을 다시 조회하지 않았으므로 원격 확인 시각 자체는 root가 남긴 영수증에 근거한다. 그 영수증은 자기 commit 내부에 들어갈 수 없어 다음 묶음의 `checkpoints.json`에 추가된 기록이며, 이 차이를 JSON에 표시했다.

동결 자료에는 새 본문·자원·개별 CI 열람이 0으로 기록돼 있다. 이는 보존된 기록에 대한 확인이며 미기록 행동을 감시했다는 뜻이 아니다. 작성자들의 진행 중 3단계 자료를 읽지 않았으므로, **모든 작업자를 합친 새 본문 최초 접근이 22:07:47.803 뒤인지**는 최종 고정 결과판에서 확인해야 한다. 예측 행의 22:04 시각으로 이 경계를 대신하면 안 된다.

## 보조 탐색의 고정 범위

양쪽 보조 순서는 **각 프로젝트의 같은 첫 40적격에서 주 표본 4개를 뺀 36개 중, 동일 해시순 첫 20개**와 정확히 일치했다. GG는 `geom_hex`부터 `benchplot`까지, MP는 `demo_axis_direction`부터 `demo_axes_grid`까지다. 전체 사이트의 나머지 모든 예제를 대상으로 하는 순서가 아니다.

따라서 A=0은 **GG의 40개 외부 경로와 MP의 28개 외부 경로가 이 두 발행 tree에 남았다**는 관측이다. MP의 inline 12개는 부재 음성이 아니며, 이 결과를 전체 사이트의 삭제·이름 변경·논리 사용 음성 0건으로 확대할 수 없다. 보조 탐색도 같은 제한된 frame 밖의 반례를 배제하지 못한다.

## 해석과 재현에서 남는 주의

GG의 C 원시 후보 40개가 모두 달라진 `man/*.Rd` blob을 갖더라도 논리 예제의 설명 목적이 바뀌었다고 말할 수 없다. MP C6은 발행된 `_downloads/<digest>/…py` source 비교이며, source 경로 변경·부재는 저자 저장소 예제 삭제와 동일하지 않다. 이는 옛 docs revision이 release tag와 다를 수 있다는 stage1의 구분과 함께 유지해야 한다.

MP `stage2.py`의 `C_eligible` 식에는 완전 tree 조건이 직접 들어 있지 않다. **이번 입력은 `truncated=false`가 확인돼 선택 결과에 영향이 없다.** 그러나 불완전한 다른 tree로 재실행하면 source 경로 누락을 변경 증거로 취급할 수 있으므로 재현 절차에서 완전 tree 검사를 먼저 통과시켜야 한다. 동결 코드는 수정하지 않았다.

이 검토는 새 네트워크 요청 없이 수행했다. U/G 결과, 최종 혼동표, 신규 자료 최소량과 진행 중 3단계 결과는 검토하지 않았다.
