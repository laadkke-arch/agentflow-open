## Q1–Q7 판정

**Q1 요구.** 포럼 H02는 평가/학습 예외 없는 수행을 요청(반환 필요는 맥락에서 추론), 원버퍼 공유·변경 전파 언급 없음. H01은 MTEB 호환 오류 해결을 직접 명시. A01은 설계 토론이므로 일반 제보자의 정확 입력/공유 요구 없음; 유지자가 명시 False를 NumPy 버전에 맞추고 내부 필요한 복사를 허용하는 선택을 함. F09는 별도 test_copy가 alias/identity를 기대하는 근거이나 원제보의 요구나 mutation 실측은 아님.

**Q2 입력.** H02 두 stack은 old L197 일반 반환으로 연결(F01). pa.Table column이 ChunkedArray이고 list comprehension 결과가 최종 array 입력인 것은 정적 코드 추론; 실제 pyarrow 타입/값/feature schema/dtype/shape/nulls/판은 미확인. object branch는 별도 C02이며 traceback에 나타나지 않음. Astropy 내부 비교 helper의 array-like/Quantity와 단위 정규화는 F04/F05, 실제 테스트 float arange(10.0) 및 m/s→cm/s는 F09; issue에는 실제 traceback/객체가 없음. 서로 바꿔 끼우지 않는다.

**Q3 계약.** N01–N05: 1.26 array False는 필요시 복사; 1.26 asarray copy kw 없음. 2.0 array True 기본, asarray None 기본. True=복사(객체 원소 깊은 복사 아님), None=필요시 복사, False=필요시 ValueError. NumPy 2 non-NumPy __array__(dtype=None,copy=None)은 copy 의미를 구현해야 하고 1.x는 copy kw 전달 안 함. migration이 asarray 권고한 이유는 종전 array(copy=False)의 성능 최적화 필요가 사라진 것; subclass/ndmin/order 및 단위 계약을 대체하는 일반 등가식은 아님.

**Q4 구현 선택.** F01→F02는 2.0.0b1 gate, 일반/object 반환 2개, upstream Arrow zero_copy_only 유지. F03 기존 시험은 값/dtype. F04→F05는 비교 helper의 4곳 copy-if-needed; F06 shim은 여전히 2.x explicit False 완화. A03 후속 F07→F08은 shim 제거/기본 의미 정렬, 실제 단위 변환/astype 분기는 남음. F09가 q0/q1/q2/q3/q4 base/identity 기대를 보여 주나 동작 실측은 아니다. 새 regression 실행·명시 ValueError assert 직접 확인 미흡.

**Q5 배포.** HF 06-17 제안, 06-19 병합, 06-23 user report, 06-24 예정/임시 downgrade, PyPI 2.20.0 06-13 old, 2.21.0 08-14 new (D01–D04). A 03-06 제안, 03-10 내부 병합; 03-08 후속 제안, 04-04 병합; PyPI 6.0.1 03-26 old shim, 6.1.0 05-04 new (D05–D10). 고정 태그 코드 2/2 대조 확인. 최초 안정판 후보는 위 두 태그이며 전체 pre-release/태그 전수 아님. wheel/sdist 파일 내부·최초 사용자의 설치·동일 입력 성공은 둘 다 미확인. 12월 fasttext 메시지의 다른 package versions는 별도 C08, 동일 호출 재발 증거 아님.

**Q6 타 분야.** NARA/LOC 원본 보존과 접근 파생본의 목적·허용 변환·비용·원본 보존 여부를 분리(X01/X02). Linux/Microsoft shared/private/read-only mapping은 초깃값, 공유, write permission, propagation, persistence를 분리(X03/X04). NumPy에서 이런 속성의 독립 검증을 차용할 수 있으나, 보존 derivative나 OS COW를 NumPy가 구현한다고 주장하지 않는다.

**Q7 가장 짧은 답.** 표 3 및 advice.csv R01–R03. 1.26 strict를 요구하면 호환되는 ndarray/dtype/order 선검사 및 반환 alias 검증 필요; 나중에 shares_memory 확인만으로 그 전에 allocation이 없었다고 증명할 수 없음. 2.0에서도 shares_memory/writeable/mutation은 실제 대상에 대해 확인하고 readonly 또는 단위 변환이 있으면 조건부 거부. 사용자가 의도를 모르고 dtype 입력을 주지 않으면 한 질문 후 분기하거나 명시적으로 조건부 링크 둘을 반환.

## 경쟁 설명과 조건/비용

- **예외 해결 vs 값·단위 보존 vs memory identity:** 같은 오류 메시지로 세 가지를 합치지 않는다. H02 12월 다른 stack 후보와 F09 q4는 첫 결론을 뒤집는 자료. Datasets가 Arrow에서 복사를 피하는 플래그와 최종 list→array의 정책도 독립.
- **기본값만으로 충분한 대안:** asarray default None는 값 목적에 충분할 수 있으나 array/Quantity default True 및 기존 False 시그니처의 변화는 서로 다름. F10의 Astropy 내부 helper를 외부 import하는 대신 D09의 사용자 정의 constant를 참고할 수 있다. 엄격한 제약이 있으면 copy를 명시하고 no-copy 실패를 다룬다.
- **탐색기에서 재사용할 조건:** (입력의 실제 타입·dtype·단위·배포판, 호출에서 허용할 변환, 값/공유/쓰기 전파 중 필수 조건, 호출 전후 정확 위치, 적용 tag와 설치/재시험 여부, 반례) 연결이 있어야 단일 권고를 강하게 말할 수 있다. 링크·한 문장·기각 조건을 반환하되 DB/API/랭킹은 미결정.
