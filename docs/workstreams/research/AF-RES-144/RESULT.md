## Q4 · 배포 결함과 null 정책

`cat`으로 전달된 줄에는 물리 개행을 가를 byte 원본이 없었다. LF 세 개의 공개 형태 복원에서만 .6에서 실패했다. .6의 선두 LF 처리 변경은 3개 byte를 peek한 뒤 LF를 선두 내용으로 취하고 빈 노드 생성을 유도할 수 있다. 이는 길이와 CR→LF 차이를 설명하는 코드 근거이며 관측은 공개 호출의 대조 실행이다. 수정 커밋은 우변이 null이면 좌변을 보존하도록 바꾸었다. 명시 null은 .5도 실패해 .5 핀이 모든 경우를 해결한다는 판단을 뒤집는다. 최상위 null을 직접 건너뛰는 필터는 .6 LF 대조에서 성공했지만 기존 호출을 고치는 .7 링크의 근거는 사용자 선호에 의존하지 않는다. 실제 원 CI의 yaml 문서가 공개되면 자료를 별도로 검증해야 한다. ## Q5 · YAML scalar의 물리 개행과 값

`load_str`은 파일 bytes에서 문자열을 만든다. CRLF를 담은 구성 문자열은 기본·flow·literal 지시 모두 인용 출력에서 원 문자열로 왕복했다. 끝에 LF가 없는 LF는 strip 블록, 끝에 LF가 있는 LF는 clip 블록으로 같은 문자열을 얻었다. CRLF 사본을 LF로 바꾸면 두 종결 형태 모두 잘 보이지만 데이터 코드포인트의 U+000D가 사라진다. 이때 정상화한 사본과 재해석값은 같으며 원본 bytes와는 다르다. -i를 사용한 네 행은 대상 1.yml만 바꿨다. 원 입력 2.yaml에 대한 생산 정책 승낙은 댓글에 없고, 이슈의 표시 파일명 2.yml과 명령 2.yaml 차이 때문에 명령 이름으로 만든 사본에 한정했다.
