## ① 자연 보고층 — 내용 열람 전 순서

기간은 생성시각 `2021-01-01T00:00:00Z <= created_at < 2026-01-01T00:00:00Z`. 저장소는 `pandas-dev/pandas`, `moment/moment-timezone`. PR 제외, open/closed 모두, 중복은 저장소+이슈 번호로 합친다.

1. GitHub issue search에서 여섯 검색(`timezone`, `"time zone"`, `tzdata`, `DST`, `offset`, `daylight`, 각각 `in:title is:issue created:2021-01-01..2025-12-31`)의 합집합을 생성시각·정수 번호 오름차순으로 정렬한다. 검색 응답의 body는 이 단계에서 출력·판독하지 않는다.
2. 제목의 대소문자를 무시하고 `timezone|time[\s_-]+zone|tzdata|\bDST\b|offset|daylight`를 적용한다. GitHub 토큰화가 누락할 수 있으므로 **키워드 없는** `repo:... is:issue created:...` 목록을 같은 순서로 읽어 제목을 대조한다. 100개/페이지, 월별 구간 분할로 한 검색의 1,000개 상한을 피한다. 최초 30번째 적격 제목의 생성시각을 지날 때까지 제목 전수 대조; 최대 12개 월·월당 10페이지. 30개에 못 미치면 이후 월을 2025-12까지 확장한다. 상한 도달·불완전 검색은 프레임 결손으로 남긴다.
3. 공백/하이픈/검색 토큰화 수정은 본문 열람 전에 제목 목록과 수정 이력에 남긴다. 첫 30개 제목을 봉인한 뒤 그 30개 본문을 모두 읽는다. API가 현재 편집본만 주면 최초 본문 복원으로 부르지 않는다. 공개 edits UI/timeline도 시도하고 최초판 미확인을 표시한다.
4. 적격: 작성자가 날짜·오프셋·달력 출력 차이를 묻고 자신의 입력 또는 관측을 하나 이상 게시. feature-only, 일반 문서 요청, 원 입력/관측이 없는 제3자 진술은 제외. 차이가 설명되는 정상 동작도 포함. 예외만 있는 사례는 날짜 계산 결과 차이를 묻는 문맥이 있을 때 포함하며 성공 날짜 출력과 구별.
5. 각 저장소 첫 3개 적격을 `N-P1..3`, `N-M1..3`에 배정한다. 이후의 버전·로그 확보 여부로 교체하지 않는다. 30개 안에서 부족하면 빈자리 유지. 나머지는 모집 원장에 판정을 남기고 반례는 `A-*` 보조 행으로만 쓴다.

## ② 실행물 우선층 — 제목·경로·날짜로 모집

같은 기간, 같은 두 프로젝트를 출발점으로 한다. 자연층의 좋은 이슈를 이 층으로 이동시키지 않는다.

1. 공식 저장소 Actions run 목록의 `created` 기간 질의에서 run ID, 이름, workflow path, event, created_at, head_sha, conclusion만 읽는다. `release|publish|dist|wheel|doc|sphinx|deploy`가 이름 또는 `.github/workflows/` 파일명에 있는 run을 적격 후보로 한다. `release` event도 포함. 상태/성공 여부 필터 없음. 단순 lint·일반 unit test는 제외한다.
2. 월별 날짜 구간(2021-01부터)으로 조회, 각 월 100개/페이지·최대 10페이지. 정렬은 created_at→run ID. 15개 적격을 확보하면 그 월의 동률까지 정렬하고 첫 15개를 고정. 기간 전체 0이면 실제 조회 0이며 과거 실행이 없었다는 뜻은 아니다.
3. Actions가 15개 미만이면 같은 프로젝트의 고정 소스에 링크된 Travis/Azure/Circle/ReadTheDocs 공개 실행 목록을 본다. 처음 확인한 프로젝트 원목록 주소를 기록, run 시작시각→ID, 프로젝트당 최대 30개 목록 페이지, 적격 합계 15개까지. 로그인/보관 만료를 기록하고 우회하지 않는다.
4. 이어서 공식 문서의 cookbook/tutorial/examples/notebook 경로가 직접 링크한 원저자의 `.ipynb`, `.html` 노트북 또는 nbviewer/GitHub/Zenodo 보관물을 조사한다. 공식 출발문서 고정 SHA, 링크 순번, 원저자와 처음 공개한 commit/publication date를 남긴다. 파일명 필터 `(?i)(time|date|pandas|moment|tutorial|cookbook|notebook).*\.(ipynb|html)$`; 이름이 일반적인 경우 공식 링크 제목에 위 단어가 있으면 포함. 서로 다른 파일이어도 동일 저작은 하나. 공식 출발문서 최대 10개, 그곳의 노트북 원목록 최대 30개 링크. 기간 밖은 보조로만 남긴다.
5. 경로별 조사 우선순위는 Actions → 공식 연결 다른 CI → 공식 연결 노트북이다. 원목록이 다른 층을 합한 전역 최초 15개라고 주장하지 않는다. 조사 가능한 후보 전체를 날짜·ID로 정렬해 각 프로젝트 첫 15개를 프레임에 기록하며 경로별 포괄성 결손을 따로 보고한다.
6. 15개 각각에서 job/log/artifact 또는 저장 notebook cell `outputs`를 연다. 날짜 변환의 **실제 출력**이 보존된 첫 두 개를 `E-P1..2`, `E-M1..2`에 배정. stdout, execute_result, stream, display_data와 실행 키를 요구한다. 코드의 assert 기대값, 정적 문서 예시, 사이트 스크린샷, 현재 재현은 제외. 성공/실패 모두 같은 규칙. 출력은 있으나 공급자 불명인 것도 채택.
7. 만료를 다른 성공 사례로 교체하지 않는다. 15개에서 부족하면 4개 표 자리 유지. 이 층은 자연 사용자 비율에 합하지 않는다. 공개 CI 존재, 로그 접근, 날짜 출력, 실제 사용판 귀속을 각각 센다.

## ③ 다른 분야 — 두 저작의 사전 탐색 순서

Dataverse와 Zenodo 원저자 공개 레코드를 각각 출발점으로 삼는다. 검색어는 순서대로 `"replication" "vintage"`, `"real-time" "notebook"`, `"replication" "data" "checksum"`. 공표기간 2021–2025를 우선하고, 부족하면 기간 제한을 해제한 별도 보조 후보로 기록한다.

- 각 저장소 첫 성공한 원 검색에서 최대 30개 metadata 후보를 date→persistent ID로 정렬하고 내용을 열기 전 목록을 저장. 웹 검색은 원목록 접근을 찾는 데만 사용하며 검색 순위를 전역 날짜순이라고 하지 않는다.
- 적격: 저자가 공개한 학술/통계 복제 패키지 또는 실행 노트북이고 관측시점/원 데이터 판 또는 checksum, 실행 파일/셀, 출판 결과 중 하나 이상을 실제 제공. 모든 사슬이 갖춰져야 선정하는 규칙은 아니다.
- 각 저장소 첫 적격 하나씩 `X-D1`, `X-Z1`; 동일 저작이면 다음 독립 저작. 파일 크기 상한은 원 패키지당 100 MB, 원문/README/manifest 우선, 필요한 하위 파일만 조회. 후보 30건/검색어 3개가 상한. 원 검색 불가 시 공식 record를 찾는 웹 검색 결과를 별도 프레임으로 명시하고 전역 첫 적격 주장 보류.
- 저장 파일과 논문의 같은 숫자만으로 실제 입력판을 확인하지 않는다. 실행 키/셀과 데이터 바이트가 연결되지 않으면 빠진 열을 남긴다. BLS/ALFRED의 기존 두 숫자는 다시 찾지 않는다.

## 증거 등급과 같은 실행 규칙

| 코드 | 확인 범위 | 허용하지 않는 확대 |
| --- | --- | --- |
| D | 문서/의존 선언·작성자 버전 주장 | 설치·로드 입증 아님 |
| K | 고정 lock·이미지/배포 파일 | 해당 과거 프로세스 수신/로드 입증 아님 |
| I | 같은 run의 설치 영수증·환경 출력 | 다른 공급자 우선·캐시 가능 |
| L | 같은 run의 공급자 self-report/모듈 경로 | 바이트가 없는 label은 정확한 멤버 지문과 구분 |
| H | 같은 run의 실제 로드 멤버 hash/바이트 | 단일 지역 파일은 전체 자료판의 유일 지문이 아닐 수 있음 |
| O-R | 원저자가 입력과 함께 게시한 관측 출력 | 독립 기계 로그가 아니며 실행시각은 보통 미확인 |
| O-M | 원 run stdout 또는 보존 notebook output | 셀 실행순서·환경 join과 선택적 출력은 별도 검토 |
| E | expected/문서 예시 | 과거 실제 출력 분모 제외 |
| R | 이번 연구자 재현 | 과거 원 실행과 분리; 본 과제에서 신규 변환 재실행은 기본 미실시 |

`그 판으로 실행`은 시대/프로세스/입력/지역/로드 근거/출력이 하나의 실행 키로 결합될 때만 허용한다. label self-report와 hash-bound 사용은 별도 열. issue body의 입력/출력 블록은 보고 단위로 연결할 수 있지만 댓글 환경·유지보수자 재현을 원 작성자 실행에 합하지 않는다. publication UTC와 execution UTC를 분리한다. 원 사용자·댓글 참가자·run 사건·비교 셀 수를 따로 센다.

UTC/현지, epoch s/ms/ns, 양의 동쪽/서쪽 offset, timezone alias, format과 fold/gap를 기록한다. 모호한 입력은 가능한 순간 집합을 적으며 임의 보정하지 않는다. offset 없는 현지 01:30은 하나의 UTC라고 가정하지 않는다.

## 후보판·세 보기·비용

- 후보 범위는 원 보고시각까지 공개된 판. 관련 패키지 공개 라벨/공식 tag 원전을 읽는다. 열거가 불완전하면 `bounded lower-bound candidate set`, 유일판 미확인. 출력이 같다는 것은 동치류를 만들 뿐 실제 사용의 양성 증거가 아니다.
- 전체 자료판 label, 패키지판, 로드 멤버 지문, 단일 관측이 각각 배제하는 후보를 분리. 다른 공급자, 같은 지역의 여러 판, UTC/local 해석 충돌을 반례로 찾는다.
- V0=게시일·버전 표기, V1=+고정 배포/설치/lock, V2=+같은 실행 공급자·입출력. 같은 10자리에 순차 적용. 없는 증거는 가상으로 추가하지 않는다.
- 비용은 실제 추가로 연 원자료 건수와 접근 시도수; 바이트를 실제 수신·측정한 경우만 bytes를 사용한다. 도구의 반환문자수를 HTTP bytes로 바꾸지 않는다. 공통 loader 문서는 공통 비용으로 따로 센다. 10×3=30 보기 셀이 기본; 다른 분야/보조는 별도.
- `미확인`=판정 입력 부족, `관측 0`=정의한 분모에서 센 영, `해당 없음`=분모/적용 자체 없음, `미실시`=하지 않은 검사.
