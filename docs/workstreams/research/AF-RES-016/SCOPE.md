## 3. 코딩과 동결

코드북을 먼저 커밋하고 push한다. 문헌 묶음, 선정 스크립트·표본 순으로 커밋한다. 작업자(root)가 198단위를 직접 읽어 S1/S2/S3를 한 번 코딩한다. 프로그램은 사람이 아닌 작업자가 명시한 코드의 직렬화·검사에만 쓴다. 과거 역할/관련성/기대 답으로 새 코드를 자동 생성하지 않는다.

`coding/coder-a.json`을 커밋·push한 뒤 새 문맥(`fork_turns=none`)의 내부 하위 에이전트를 만든다. 제공 문서는 CODEBOOK.md와 sample/units.json뿐이며 과거 라벨, A, 기대 답, 연구 결론은 제공하지 않는다. B는 같은 모델 계열의 **내부 별도 검토**이며 사람/다른 모델/외부 독립 실험이 아니다. 파일 접근 지시를 통한 문맥 분리이지 OS 접근 격리는 아니다. B 원응답을 별도로 커밋한다.

각 코더의 최초 의미 판정은 수정하지 않는다. JSON 형식 보정이 필요하면 원응답을 보존하고 의미값 불변을 검사한다. 동결 뒤 조정은 adjudication.json에 별도로 남기며 조정 뒤 일치율을 새 신뢰도로 발표하지 않는다. S3의 기여 축은 S2와 같은 변수로 재사용한다. 따라서 S3는 새로운 독립 코딩 조건이나 무작위 교차실험이 아니다.

## 4. 분석 사전 규칙

- 분류안×표본별 exact agreement와 nominal Cohen kappa. S3는 (form, contribution) 쌍의 exact 일치가 주 값이며 두 축별 값도 병기한다. 범주 수와 주변분포가 다른 kappa를 단순한 우승 순위로 읽지 않는다.
- S1/S2/S3의 unknown/mixed도 관측 범주로 포함한다. unknown 일치 제외·mixed 제외 민감도를 추가하되 주 수치를 대체하지 않는다.
- 95% percentile bootstrap 5,000회, seed=2026112016+600. 011은 스레드, 012는 선택 질의, 004는 문제를 cluster로 재표집한다. 004의 4개 cluster와 011의 15개 cluster는 모집단 보장에 부족함을 명시한다. kappa 분모가 0인 반복은 제외 수를 공개한다. raw agreement에도 같은 95% 구간을 보고한다.
- 011 원판 149쌍의 75/149를 먼저 재현하고 새 120쌍과 동일한 부분집합의 옛 수치를 별도로 계산한다. 전체50.34%와 120개 수치 차이를 분류안 효과로 혼동하지 않는다. 같은 cluster 재표집으로 새−옛 차이 구간도 산출한다.
- 불일치 유형: 경계 정의 부족 / 문맥 부족 / 실제 다의성. root가 사후 분류한 진단이며 정답이나 별도 독립 일치 검증이 아니다. 근거와 대안 해석을 함께 남긴다.
- Q7은 최소30개 고유 불일치 단위를 ID 정렬에서 균등하게 분산 선택한다. 역할 A/B 각각에 004 H/T 또는 근접 오답을 적용한다. **라벨만 교체하고 사용 방식·근거를 고정한 결과**와 **역할 해석이 사용 범위를 바꾸는 결과**를 분리한다. 결과 변화의 원인이 단어인지 단위 변경인지 표시한다. 판정은 이 작업자의 문서 기반 조건부 분석이며 실제 사용자 행동/설치 결과가 아니다.
