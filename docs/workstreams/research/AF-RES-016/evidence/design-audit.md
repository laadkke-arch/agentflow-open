## 3. A2 — 012의 무작위 질의 연결과 문맥의 불완전성

### 3.1 수량과 선택 경로

`sample/select.py:81–103`은 먼저 156개 자료에서 60개를 뽑고, 초기 qrels에 그 자료가 있으면 거기서 질의를 고른다. 초기 qrel이 전혀 없는 자료만 전체 36개 질의에서 고른다. 이는 결과 등급으로 긍정 자료만 고르는 절차는 아니다. 초기 qrels가 있는 자료는 모집단에서 63/156이고 선정된 표본에서는 24/60이므로, 자료 추출의 단순 무작위성을 문제 삼을 근거도 없다. 문제는 두 층이 서로 다른 문맥 생성 과정을 거친다는 데 있다.

반증 시도: 초기 qrel 부재 자료가 독립 판정 파일에는 나타날 수 있는지 고정 independent.tsv를 대조했다. 선택된 36개 쌍은 모두 없었다. 무작위 자료 표본 자체가 편향된 긍정 선택이라는 비판은 모집단의 qrel 보유 비중 63/156과 표본 24/60을 대조하여 지지되지 않음을 확인했다. 남는 문제는 자료 선택보다 문맥 연결과 추정 대상이다.

## 4. A3 — S3 contribution을 S2에서 복사할 때 비교의 뜻

`SCOPE.md:43,47` 및 `CODEBOOK.md:39–41`은 S3 contribution을 S2와 같은 변수로 복사한다고 명시한다. 숨긴 설계 변경은 아니다. 다만 다음 수학적 관계는 결과 해석의 제약이다.

각 행 i에서 두 코더의 S2가 같으면 C_i=1, form이 같으면 F_i=1이라고 두면, S3 합동 일치 J_i는 `C_i × F_i`다. 따라서 같은 표본에서 다음이 성립한다.

`agreement(S3 joint) = mean(C_i × F_i) ≤ mean(C_i) = agreement(S2)`

이는 어떤 코더가 더 잘했는지와 무관하게 복사·합동 일치 규칙에서 생긴다. S3 기여축 일치율과 kappa는 S2 값과 정확히 같아야 하며, 달라지면 결과 생성 또는 무결성 문제다. S3의 범주 수·주변분포가 S2와 다르므로 합동 kappa에는 같은 부등식이 일반적으로 적용되지 않는다.

### 최소 보강 분석

- 표 1의 세 안은 그대로 보고하되, S3를 **두 변수의 결합 표현**으로 설명한다. S2와 독립된 세 번째 문제 기여 판단 실험이라고 쓰지 않는다.
- S3 form의 단독 일치, S2=contribution 일치, 합동 일치, 그리고 **S2가 일치한 행 중 form만 불일치한 행 수**를 같이 보고한다. 합동 일치율 하락 중 얼마가 추가 형태 구분의 비용인지를 바로 확인할 수 있다.
- 코더별 모든 행에서 S3.contribution=S2인지를 확인한다. 이번 감사는 coding/를 열지 않았으므로 실제 불변식 충족은 미확인이다. 만약 원응답에 다르면 원응답을 고치지 말고 위반 수를 그대로 보고해야 한다.
- S3가 역할 오해를 줄이는지에 관한 근거는 Q7의 구체 사용 범위·판정 변화와 연결한다. 정확 일치율 하나만으로 두 축 정보를 버릴 근거를 만들지 않는다.
- 독립된 세 번째 코딩 조건의 효과를 묻는 후속 연구는 기여축을 S2와 별도로 판단하게 하고 조건 순서·노출을 통제해야 한다. 그것은 이번 198개 결과의 사후 재명명으로 얻을 수 없다.

사용자는 각 안에서 198개 이상의 이중 코딩을 요구했다. 이 감사는 세 표현의 값이 실제로 모두 작성됐는지 검사하지 않았으며 그 조건을 면제하지 않는다. 동시에 사용자가 명시하지 않은 독립 무작위 교차 실험을 이번 완료의 새 필수 조건으로 만들지도 않는다. **확인할 것은 198개 각 안의 원응답 존재와 코드북 준수이고, 제한할 것은 세 독립 실험이라는 해석이다.**

반증 시도: S3의 낮은 합동 일치가 그 자체로 열등함을 증명하는지 정의에서 직접 검산했다. 부등식 때문에 그 주장은 성립하지 않는다. 반대로 form 단독 일치와 판정 정보가 추가될 수 있으므로 S3가 무의미하다는 주장도 나오지 않는다.

## 5. A4 — 004 R18 변경 조건의 실제 반영

R18은 오류 후보로 적극 확인했으나, **현재 동결 packet에서는 조건 반영이 맞다.** 검증 위치는 `sample/select.py:108–130`, units `/units/7`의 R08 및 `/units/17`의 R18이다.

| 검사 | R08 | R18 | 결과 |
|---|---|---|---|
| given의 handler 전제 | 같은 ID의 결과를 중복 반영하지 않는 영속 멱등 처리가 주어짐 | 그 전제가 변경 H3로 대체되고 영속 멱등 처리가 없다고 명시 | 일관되게 대체됨 |

재현 코드가 base given의 특정 문장을 문자열 치환하므로 향후 다른 입력 판에서 문구가 달라지면 적용 실패 가능성은 있다. 그러나 이번 입력 SHA가 고정되어 있고 실제 출력도 확인했으므로 현재 표본의 결함으로 기록하지 않는다. 현재 최소 행동은 수정이 아니라 이 검증 근거를 보존하는 것이다.

Q7에서 R08/R18을 사용한다면 H 판단 차이는 요구 조건의 변화 때문임을 표시해야 한다. 같은 도구·같은 역할인데 요구 변화로 판정이 달라지는 사례는 유용하지만, 역할 라벨을 바꿨기 때문에 결과가 바뀌었다는 인과 사례는 아니다.

반증 시도: R18에서 변경 H3만 넣고 base given의 멱등 전제를 남긴 모순, 또는 configuration이 R08의 멱등 전제를 재도입한 모순을 찾았다. 현재 packet에서는 둘 다 발견하지 않았다.

```sh
PYTHONDONTWRITEBYTECODE=1 python - <<'PY'
import pathlib, runpy, io, contextlib
base = pathlib.Path('docs/workstreams/research/AF-RES-016')
ns = runpy.run_path(str(base / 'sample/select.py'), run_name='audit_import')
outputs = {}
class MemoryFile:
    def __init__(self, name): self.name = name
    def write_text(self, text):
        if self.name in ('units.json', 'selection.json'):
            outputs[self.name] = text
        return len(text)
class MemoryDir:
    def __truediv__(self, name): return MemoryFile(name)
ns['main'].__globals__['OUT'] = MemoryDir()
with contextlib.redirect_stdout(io.StringIO()) as report:
    ns['main']()
print(report.getvalue().strip())
for name, text in outputs.items():
    print(name, text.encode() == (base / 'sample' / name).read_bytes())
PY
```
