이 연구 묶음의 검산·재독 대기는 없다. 후속조사를 시작한다면 첫 자료는 [R05 최초본문 L98–117](https://github.com/kubernetes/enhancements/blob/6d97b64e59854ec7744d8bc3bfb9fadac29b52fe/keps/sig-network/20200103-mixed-protocol-lb.md#L98-L117)과 [VPL 접수/제공 구분](https://www.vpl.ca/borrowing/interlibrary-loans) L3·L64–106이다. 먼저‘한복합책의요청접수’와‘제공기관의발송재량’을구분하는공개양식/규정및2020년1월이전판이있는지확인한다. 현재판의새해시를옛판의확인으로기록하면안된다. 실제자료신청이나사람에게연락을보낸적은없다.

저장소루트에서아래명령은캐시없이커밋벡터와원장을다시검사하는첫행동이다.

```sh
python -B docs/workstreams/research/AF-RES-033/retrieval.py --check
python -B docs/workstreams/research/AF-RES-033/validate_results.py --require-report --metadata-only
python -B -m workbench.session check docs/workstreams/research/AF-RES-033/manifest.json --fetch
```

원문까지다시검사할때의입력은sources.jsonl/corpus.jsonl의원URL·고정판·본문범위·SHA256, inputs.jsonl의고정Gitblob이다. 로컬캐시가있는현재환경에서는위표의`--require-cache`검사를실제로통과했다. 새환경의캐시없음은실본문재확인이완료됐다는뜻이아니다. 제공전문과공개토론전문은허가되지않은재배포를피해커밋하지않았고,원자료가바뀌었다면차이를기록하고그원판재확인을보류해야한다. 채점벡터의정확재생과원문재획득을구분한다.

현장추가검증의첫입력은[F02 PDF13쪽](https://www.nyc.gov/assets/planning/download/pdf/planning-level/transportation/covid19-transportation/20200421.pdf#page=13)의세날짜에해당하는보존feed/DCP집계코드와[F04 데이터셋](https://www.ons.gov.uk/peoplepopulationandcommunity/populationandmigration/populationestimates/datasets/estimatesofthepopulationforenglandandwales/mid20222023localauthorityboundaires)의v1/v2 MYE3!A9:O365다. 전자는원시실행검증이남아있고,후자의357키·78변경셀은이미검사했으므로필요없이같은집계만반복하지말고전체모형/하류전달이라는다음경계를확인해야한다.
