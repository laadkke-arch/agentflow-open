# 본문 열람 전 보완 001

시점: 최초 수신 본문·질의 작성 이전. 표집 원장과 제공 분야 규칙은 이미 봉인됐지만 수신 본문 열람 권한은 아직 부여하지 않았다. 이 보완은 독립 문맥의 protocol_audit가 발견한 두 문제를 수정한다. 원 규칙 커밋 `cf10073b65a84002a889d37a2436a19b8f43d412` 및 메타데이터 커밋 `1c4706228af21a8183dd3c873d5864f06edbe206`는 보존한다.

## A. 전체/부분이 실제 표본에 포함되도록 사전 규칙 보완

각 저장소에서 날짜순 처음4개 적격 제안을 기본으로 택한다. 이4개가 모두 같은 범위라면 가장 이른3개를 유지하고 이후 날짜순으로 처음 나오는 반대 범위의 적격 제안1개를 채택한다. 밀려난 네 번째 제안도 frame에 `scope_quota` 사유로 보존한다. 이 규칙은 저장소마다 적용하고 검색 성공이나 후속 결과를 보지 않는다. 반대 범위가 전체2020~2024목록에 없으면 부족으로 남긴다.

범위 판독 기준:

- `whole_design`: 새로 도입하는 독립 기능·프로토콜·구성 요소의 입력부터 정상 처리/출력까지를 제안한다. 독립적인 새 계약과 사용 흐름을 본문에서 확인할 수 있어야 한다. 전체 Rust나 Kubernetes 제품을 설계한다는 의미가 아니다.
- `partial_design`: 이미 존재하는 기능·프로토콜·구성 요소의 일부 단계, 제약, 표현, 검증/오류 경계 또는 한 동작을 바꾸는 제안이다. 기존 주변 기능의 계약을 전제로 한다. 새 flag 하나는 부분으로 본다. 기존 인프라에 의존한다는 사실만으로 독립적인 새 기능을 부분으로 낮추지 않는다.
- 경계가 모호하면 본문 근거를 붙여 미확인으로 표시하고 할당 목적의 범위를 임의로 바꾸지 않는다. 전체·부분 각각으로 볼 때의 대체 해석도 기록한다. 최소 한 전체/부분이라는 요구는 이 사전 할당 규칙으로 충족시키려 하며 결과를 본 뒤의 교체는 금지한다.

## B. 첫 생존 커밋과 최초 제출본 구별

독립 검토의 반례: 09시 초안A →10시 완성B →11시 PR생성이라면 현재 PR 커밋 목록 첫A는 제출 당시B가 아니다. 따라서 `가장 오래된 생존 커밋=최초 제출본문`이라고 하지 않는다.

현재 PR 이력에서 생성 시각 이전에 작성된 생존 커밋들을 투영하여 보존하고, topological 순서의 마지막 pre-open 커밋을 `opening_head_candidate`로 둔다. 새 제안 파일은 최초 추가 diff로 확인하고 그 경로의 blob을 opening 후보 SHA에서 다시 확인해 복원한다. 가장 오래된 추가 커밋과 opening 후보를 모두 남기며 다른 파일 버전이면 그 차이를 기록한다. 생성 후의 커밋만 남았거나 경로 복원이 실패하면 표집 제외한다.

이것도 확정된 최초판은 아니다. 강제 푸시·재작성·사라진 커밋·작성 시각의 신뢰 경계가 남는다. REST 사건으로 관측한 force-push와 관측 불가를 구별한다. 저장된 opening head 사건 또는 그 시점의 독립 아카이브가 없으면 `initiality_unproven`을 유지하고 엄격 최초판 민감도에서는 제외한다. 현재 문서에서 좋은 결과가 나왔다고 최초판 확실성을 올리지 않는다.

## C. 복원 입력의 실제 연결 검증

유효한 임의 blob을 읽고 그 해시가 맞는지만 확인하면 커밋·경로가 틀린 URL도 인증할 수 있다. 복원기는 PR메타데이터 검사에서 확인한 커밋·경로·blob tuple에 실제로 연결되는지 확인해야 한다. 새 제안 added 경로와 고정 후보 커밋의 blob을 기록하고, 다른 tuple을 입력하면 거부한다. Git blob SHA1·raw SHA256·canonical-LF SHA256 검사는 그 다음에 한다.

## 바꾸지 않은 것

제공 발행처·후보 정렬·날짜 범위, S/R질의의80토큰 상한·언어·무노출,18문서BM25및200토큰 반환 창,16검색·144대응·양성 여부와 무관한 종료조건은 그대로다. 원 규칙을 사후 결과에 맞춰 수정한 것으로 표시하지 않는다. 실제 보완 원격 SHA와 수신 본문 허용 시각을 seal-log에 추가한다.

## D. 제공 분야 적격성의 경계 확인

수신 본문을 보지 않은 제공 수집자가 SFMTA Blue Book의 공사 중 정류장 이동 절을 확인하고 적격성을 질의했다. 대중교통 일정 변경은 시간표·빈도·운영시간대·노선 운행 구성 또는 운행 중단/변경 절차를 명시해야 한다. 물리적 정류장 위치·공사 간격·안전 허가만 다루고 실제 운행 변경 규칙이 없으면 제외한다. 이 경우 이미 고정한 제목 순서를 계속 읽고, 해당 발행처에 적격 문서가 없을 때만 고정 대체 발행처로 이동한다. 후보 숫자를 채우기 위해 범위를 넓히지 않는다.

## E. 점수에 영향을 주지 않는 검색기 표현·입력 검사 보완

독립 검토의 합성 메타데이터 입력에서 질의 중복·동률·S/R 동일 처리에 문제가 없음을 확인했다. 데이터셋 신원 오류를 조기에 드러내기 위해18고유 후보·분야별6개·8고유수신·저장소별4개 검사를 추가했다. 반환되지 않은 행의 최적 창은 `best_window_id`에만 두고 `returned_window_id`는 실제 상위3양수 반환에만 쓴다. 창의 문자 좌표는 `NFC(source).lower()`의 좌표임을 필드명과 해시로 명시한다. 이는 소문자화 때 길이가 달라지는 문자의 잘못된 원문 절단을 막는다. BM25점수·순위·창 선택 규칙은 바꾸지 않았다. 실제 자료로 검색하기 전에 봉인한다.
