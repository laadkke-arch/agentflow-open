## 입력과 동일성

[inputs.json](replay/inputs.json)의 배열 9개를 모두 사용한다. 각 배열에서 `require('simple-statistics').quantile(a, p)`의 p는 0, 0.25, 0.5, 1, -0.25, 1.25다. 공개 `median(a)`에 같은 배열을 넣는다. `require`가 ESM 진입을 지원하지 않는 경우 공개 bare import를 사용하고 실제 load URL을 기록한다. deep import는 실행에 쓰지 않는다. `direct`는 매 호출마다 새 입력 원 배열을 전달한다. `sorted_copy`는 별개 원 배열을 만든 다음 복제본을 오름차순으로 정렬한다. 유한 수는 수치 순서, NaN은 마지막이며 동률은 공식 Node의 안정 정렬 순서를 유지한다. 정렬한 인수와 남겨 둔 원 배열을 각각 전후 비교한다. 모든 호출은 다른 호출의 변형에서 독립이다.

한 판의 기능·입력·p·전달 방식이 셀 하나다. 값 숫자·NaN·-0·±Infinity·undefined·null·예외·API 부재를 서로 다른 타입으로 직렬화한다. 예외의 이름, 코드, 본문에 차이가 나면 예외 차이로 센다. 스택과 절대 설치 경로는 원자료에는 보존하되 동등성에서 제외한다. 인수와 원 배열의 전후는 Object.is 의미로 판정한다. 값/예외만 같은 판은 변형까지 같은 판과 구분한다. 한 셀 이상 바뀐 인접쌍은 한 번 센다. 모든 셀을 대조해 변화 0이 확인되면 불변이다. 판 또는 셀의 설치·실행·두 경로 합의가 없으면 해당 셀이 미확인이고, 확인된 변화도 없는 불완전 쌍은 미확인이다. 변화 분모가 0이면 검출률을 계산하지 않는다. 미확인 전체를 변화 또는 불변으로 놓은 감도를 계산한다.

Node v24.22.1, npm 11.9.0, Python 3.12, Linux, LANG=C.UTF-8·TZ=UTC를 쓴다. 현재 환경의 npm lockfile v3을 생성해 두 별도 작업·npm 캐시 디렉터리에서 같은 잠금으로 `npm ci --ignore-scripts --no-audit --no-fund`한다. 설치된 판·실제 진입점·직접 의존과 잠금 해시를 확인한다. 당시 실제 사용자 lock은 미확인이다. 두 인접판에 공통 런타임 직접 의존이 있으면 각각의 잠금에서 공통 범위에 속하는 같은 버전을 고르고 대조한다. 후보가 없으면 미확인 이유를 적는다. 공통 의존이 비었으면 양판 각각의 직접 의존 집합을 기록하며 기본 실행을 별도의 맞춤 설치라고 세지 않는다. 직접 의존 밖 간접 해석은 별도 조건이다.

## 출력 열람 전에 정할 정책

A는 항상 실행한다. C·D·E와 비교용 함수/공지 단독 경보는 기능별로 봉인한다. 한 판에서 두 함수 중 하나라도 확인을 요구하면 그 판의 전체 126셀을 한 Node 과정에서 실행한다. 기초 첫 판은 모든 정책이 확인한다. 변화·강제·생략은 별도다. 신호 비교 자체는 두 판의 실제 자료를 읽되, 공지는 각 판의 npm 공개시각에서 잘라 쓴다. 역순 semver 행에서 두 판 모두 이용 가능한 시각은 늦은 쪽 공개시각이다.

- **C.** 판 고정 upstream `src/quantile.js`·`src/median.js`의 해당 대상 이름에 붙은 함수 JSDoc 전체가 고정 공식 기능 절이다. 파일·대상 연결이 먼저다. 같은 문서가 타르에도 있으면 지문을 비교한다. 댓글 경계와 줄 앞의 JSDoc 별표, 독립 버전/생성 배너와 공백을 정규화한다. 본문·URL·예제의 문자, 파라미터, 섹션의 순서를 유지한다. 태그마다 다른 Git 주소와 논리 위치를 분리한다. 이 정규화 지문의 전후가 다르면 확인한다. 둘 중 한 절이 없거나 경로가 이동했거나 자료 판을 해소할 수 없으면 강제한다.
- **D.** C가 요구하거나 tar 기준 Node 공개 파일, 관련 함수의 배포 src 파일(개별 파일이 없는 경우 해당 함수를 찾아낸 번들 파일), 정확한 런타임 직접 의존 묶음의 원 바이트 지문·경로가 달라지면 확인한다. 직접 의존에는 선언 이름·범위·정확한 해석판·integrity를 쓴다. 경로 변경, 구성 파일 누락·미해소와 잠금 미해소는 강제다. 원 바이트 비교는 주석·공백·번들 배너도 경보를 낼 수 있다.
- **E.** 동일 판의 배포 src를 우선하며, 개별 파일이 빠져 있으면 공개 배포 번들의 유일한 명명 함수에 한해 사용한다. ES 구문 파서로 함수 본문과 해당 본문이 직접 호출하는 패키지 내부의 한 단계 위임 함수 본문을 지문화한다. 토큰 종류·리터럴·연산자는 보존하고 주석, 공백, 위치, 배너는 버린다. root와 위임의 지문은 따로 보존한다. 재위치 자체는 경보로 쓰지 않는다. 이름 바인딩은 로컬 선언, 정적 상대 import·require, 또는 단일 번들에 있는 유일 명명 선언까지 해소한다. 검산 가능한 JS 표준 내장 호출·원배열의 내장 메서드와 Error 계열은 런타임을 고정한 외부 항목이다. 동적 callee, 중복 이름, 해소할 수 없는 내부/외부 위임, 파서 실패, 필요한 경로 소실, 고정 src/공개 진입의 관계가 해소되지 않는 경우 강제한다. 직접 위임의 본문은 비교하되 그 안의 추가 호출은 좁은 신호 범위 밖이다. 본문 변화 또는 공지 단어 적중이 있으면 확인한다. 공지는 두 함수 공통이다.
- **공지.** 대소문자 무시 영단어 경계와 고정 별칭 `quantile/quantiles/quantileSorted/quantileRank/quantileRankSorted`, `percentile/percentiles/percentileRank`, `median/medians/medianSorted`, `quartile/quartiles/interquartile/interquartileRange/IQR`, `interpolation/interpolate/interpolated`를 쓴다. GitHub 공식 non-draft 릴리스 본문과 배포 동봉 CHANGELOG의 해당 버전 섹션만 대상이다. tar의 해당 섹션은 공개시각 내용 증거다. 누적 내용에 버전 경계가 없으면 신호를 추측하지 않고 강제한다. GitHub 본문은 공개시각·마지막 편집시각(또는 불변 본문 보관) 모두 해당 npm 시각 이하일 때 사용한다. 오늘 공개된 목록에서 npm 이후에 처음 공개됐다고 확인한 본문은 제외한다. 공개시각은 당시인데 마지막 편집을 확인할 수 없거나 나중에 편집되었다면 당시 본문을 미확인으로 두고 강제한다. 현재 공식 목록을 끝까지 읽고 tar에 해당 CHANGELOG가 없는 경우에는 관찰된 두 표면의 공지 없음으로 분류한다. 삭제된 옛 공지의 부재는 미확인이고, 이 경우도 강제하는 감도를 별도로 낸다. 목록이나 tar 자체를 열 수 없으면 강제한다. 현재 본문의 단어 수·증거 URL과 당시 사용 여부는 다른 필드다. 함수 단독 F와 공지 단독 N은 각각 자기 구성의 강제 조건을 유지한다.
- 출판 후에 발견한 새 단어·위임 규칙은 원래 경보를 덮어쓰지 않고 사후 대안으로 둔다. 기능 절·소스·공지의 정적 판독은 예측에 필요하므로 코드에서 짐작할 수 있는 동작은 생긴다. 배포 함수 실행, 대상 테스트 기대값과 실행 판독 원장은 경보 커밋 뒤에 처음 연다.

## 비용·질의와 반환

같은 셀 묶음을 질의 한 건으로 센다. 질의열은 첫 판 1회, 각 새 공개판에 그 판 1회, 첫·마지막 지원판 교차 6회다. 지원판은 두 기본 설치·공개 실행이 합의한 판이다. semver 최고판을 매 공개마다 질의하는 135 방식을 순위 역전 시 감도로 함께 기록한다. 첫/끝 고정 질의는 마지막 판이 나온 뒤 재생한다. 일괄은 질의시점까지 공개된 모든 판에 정책을 적용한다. 요청 시 방식은 요청된 판의 답부터 찾고, 없으면 발표순으로 과거 발판에서 대상까지 신호를 읽어 하나라도 확인을 요구하면 대상만 실행한다. 발판이 없으면 대상을 실행한다. 실행 실패나 그 뒤의 미검사 경계가 있으면 보류한다. 같은 고정판 응답 캐시는 재사용하고 새 판의 신호를 이미 실측한 판에 소급하지 않는다. 답에 요청판, 마지막 실측판·시각·잠금, 강제/생략 근거와 입력을 함께 보낸다. 결과가 일치하는 이월과 실제 출력이 다른 이월은 나눈다. 마지막 실측판과 링크가 가리키는 판은 별도다.

GitHub 릴리스 메타데이터 취득 공통분은 별도 집계하고 본문 비용의 재생에서는 버전 단위로 모형화한다. 실패한 읽기는 요청 횟수에 넣고 미확인 본문 바이트는 0 수신과 구분한다. 실제 수집·설치·실행 시간, 그 계측을 합친 질의 시뮬레이션 시간, 프로덕션의 알 수 없는 대기 시간/트래픽을 구분한다. 초도와 후속 질의 비용은 CSV에서 분리한다.
