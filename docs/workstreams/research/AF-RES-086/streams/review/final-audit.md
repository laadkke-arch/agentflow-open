## 독립 산식 검산

원장201행을 직접 읽어 `countable_original` 대상126행, 고유 URL·판126쌍, 계보25개를 다시 계산했다. stream별 적격 행은 Python37 + R46 + incidents19 + preservation24 =126이다. 같은 직접 지문을 가진 세 쌍은 P3 현재/보관1.x, R2 현재/생성root, R2 현재/생성leaf다. 이 중복3을 더 세지 않으면 **123자료**다. R1 NEXT/LAST 동일 HTML4개는 이미 적격에서 제외돼 재차 분자를 늘리지 않는다. 정책4계보를 빼면 실제 저작·사건21계보이며 사용자 최소20계보보다 많다. 계보와 API 응답 수를 같은 값으로 읽지 않았다.

비용은 다음과 같이 직접 합산했다.

- 계측 논리 GET: Python58 + R73 + 사건직접6 + 보존35 = **172**.
- 본문 bytes: 1,703,113 + 1,619,294 + 277,631 + 3,777,598 = **7,377,636**.
- 현재 고정9경로의 bytes를 원장 개별 행에서 합산하면 **458,565**다.
- R 사전 입력11개의 영수증을 직접 더하면244,494 bytes이며, 사후62요청은1,374,800 bytes다. Python 사전9요청520,628 bytes와 더하면 사전20요청765,122 bytes다.
- 사후 Python49 + R62 =111요청, 1,182,485 +1,374,800 =2,557,285 bytes다.

별도 GitHub connector46호출, 보존 사전탐색3 GET, 검색도구 전송량·헤더·TLS·redirect 내부 hop·독해시간·금전은 알려진 합계에 섞지 않는다. 비용은 이번 조사 계측이지 일반 독자의 필수 비용 또는 서비스 내부 비용이 아니다.

현재9경로는 200이8개, P1 named가404이며 목표판 내용은 P3 tag·1.x와 R2두파일의4개다. RTD 생성4/4, 별도 게시0/4, Pages success 직접확인0/2를 서로 다른 단위로 둔 표는 타당하다. 원자료량·수치·구조 검산과 역사적 공석을 분리하는 PARTIAL 판정이 유지되어야 한다.
