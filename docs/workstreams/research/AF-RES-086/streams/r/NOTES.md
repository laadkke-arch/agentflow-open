[발행자 이슈 #113](https://github.com/r-lib/archive/issues/113)은 2025-03-20에 작성되고 2025-03-24T12:33:05Z에 갱신된 릴리스 체크리스트다. URL 검사, GitHub 릴리스 작성, 개발 버전 올리기 항목에 완료 표시가 있다. 이는 발행자가 수행했다고 보고한 행위이며 당시 각 URL의 응답·판 지문이나 검사 로그가 아니다. 해당 원문에는 구판 문서 유지 기간이 없다.

## Q4·Q5 — 당시 응답과 지금의 바이트 일치를 분리한 선택

R1 주창의 정확한 root 및 archive_read CDX 검색은 HTTP 200의 빈 배열이었다. 초기 wildcard 주창·보조창 검색은 503이었으며 그 실패를 기록한 뒤 정확한 경로 조회로 보완했다. `available` 지시자에서 찾은 2025-02-27T04:30:36Z root 응답을 실제 열었다. 이 보조창 응답은 1.1.11이며 선택 1.1.12 출시 전의 자료다. 전달된 gzip 4,399 bytes와 해제된 HTML 21,930 bytes의 해시를 분리했다. 따라서 해당 보관본은 옛 root 내용이 실제 남았다는 예이지만 3월 24–26일의 1.1.12 제공 증거가 아니다. leaf의 가까운 보관본은 11월로 보조창 밖이어서 내용 판독에 편입하지 않았다.

R2 주창·보조창 CDX 검색은 빈 배열이었다. 가장 가까운 지시자는 2024-03-16로 보조창 밖이며 내용 확인 점수에 넣지 않았다. 빈 검색은 당시 제공이 없었다는 반증이 아니다.

## 자체 반증과 다음 행동 — 중요한 약점 3건

1. **R1의 inactive를 성공 또는 구판 소실로 읽을 수 없다.** 대상은 deployment `2328795124`의 이전 상태와 run `14035386117`/job `39292155301`이다. 다음 입력은 발행자가 당시 보존한 상태 JSON·공개 로그 또는 동일 ID의 독립 기록이다. 관측할 값은 성공/실패 상태의 UTC, 입력 SHA, 환경 URL이다. 성공 원행이 발견되면 제공자 성공 0/2를 바꿀 수 있으나 독자 경로 0/4는 별도다.
2. **R1 root 보관본은 선택 판 출시 전이고 주창의 두 경로가 비어 있다.** 대상은 `https://archive.r-lib.org/`와 `https://archive.r-lib.org/reference/archive_read.html`, 입력은 2025-03-24T00:00:00Z부터 2025-03-27T00:00:00Z 미만의 보관 응답 또는 날짜가 붙은 발행자 기록이다. 관측할 값은 응답 시각·최종 URL·1.1.12 표식과 파일/절 지문이다. 이것이 생겨야 당시 읽은 판 판정을 바꾼다.
3. **R2 현재 바이트 일치는 2024년 제공 이력을 만들지 않는다.** 대상은 두 대표 경로와 배포 `1283145596`, 입력은 고정 3일 창의 응답·성공 상태·발행 산출물 지시자다. 관측할 값은 2.3.1의 본문 지문과 당시 URL, 게시 UTC다. 이 자료가 생기면 역사 제공 보류를 바꿀 수 있다. 서로 다른 현재 이름/주소가 같은 파일을 준다는 일반론만으로 시간 조건을 제거하지 않는다.
