## Q4. 현장의 최소 정정 기록

GitHub 전달은 옛 주소의 현재 읽기 위치를 가볍게 유지한다. MARC 775는 다른 판을 별도의 설명과 제어 번호로 이어 준다. Crossmark는 중요한 업데이트에 문서와 다른 DOI를 부여해 연결하고 더 작은 수정은 직접 허용한다. ## Q6. 복구의 확인 범위

자연 사건에서 PREDIMED 원 보고와 재출판을 별개로 받았다. C는 옛 DOI와 옛 초록 요지를 보존한 채 현재 읽을 위치로 재출판을 반환했다. 새 인용은 자기 DOI에 그대로 남았다. B도 옛 판을 보존했지만 새 문서를 묻는 추가 조회에 앞 기록의 정정 주체를 붙였다. Open Library에서는 저자 병합을 되돌리는 과정에서 후속 작품 정보가 보존되지 않았다는 보고를 실제로 읽었다. 기존 거래 ID와 개정 diff를 열지 못해 같은 작업의 전후 값을 모두 되감았다고 볼 수 없다. [S12a](https://pubmed.ncbi.nlm.nih.gov/23432189/) · [S12b](https://pubmed.ncbi.nlm.nih.gov/29897866/) · [S08a/b](https://github.com/internetarchive/openlibrary/issues/6371).

구성 오류의 N04/N06은 4개 L/P 오류를 냈고 C의 개별 취소로 4/4 복구했다. A/B는 그 관계를 취소할 표현이 없어 각자 포함한 오답을 유지했다. 중복 받은 동일 내용은 답이 전부 유지됐지만 A의 쓰기가 두 배였다. 역순은 A의 React 옛 주소와 현재 주소 두 판정에 영향이 있었다. N12의 중간 실패 후 세 방식은 행 1개의 미확정 쓰기를 rollback했고 DB 재개 후 정상 답과 최종 행 수가 돌아왔다. 이 대조는 동시 편집, 임의 재전송 순서, 네트워크 장애 시험으로 외삽할 수 없다. F/L/T/A만 묻는 안정 대조는 한 주소의 작은 메모로 32/32 맞았다. 두 주소가 동일한지 근거와 함께 묻는 네 쌍은 모두 소실됐다. 주소를 나눠 저장하면 진짜 React PR 중복이 P에서 오분리였다. ## 경쟁 설명 및 분야 간 적용 조건

- 공개 생산자는 저장소나 대상의 이관을 발표할 수 있다. 외부 인용자는 자기 작업이 쓰는 버전·절·출력을 확인해야 한다. 예를 들면 React 팀은 repo를 이전했고 React 소비자는 CodeSandbox 동작을 별도로 문제 삼았다. 같은 주체나 동일 시점의 주장으로 합성하지 않는다. [S06b](https://react.dev/blog/2026/02/24/the-react-foundation) · [S06d](https://github.com/react/react/issues/36807).
- 판본 관계를 가져오려면 인용자가 Work 대신 Edition을 붙일 수 있어야 한다. 소프트웨어의 일반 소개를 같은 작품으로 묶는 것은 가볍지만, 입출력·기본값·발표 시점 차이를 묻는 순간 tag/commit이 필요하다. 수록 판을 나누지 않고 여러 URL만 늘린 설명은 N09와 N04를 구별할 수 없다. [O03](https://www.loc.gov/marc/bibliographic/bd775.html) · [S09a](https://frankensteinvariorum.github.io/fv-collation/Frankenstein_1818.html) · [S04b](https://raw.githubusercontent.com/docker/compose/1.29.2/compose/service.py).
- 재동정을 가져오려면 같은 실물 또는 계속 식별할 기준이 있고 과거 판단을 별개 참조로 만들 수 있어야 한다. 소프트웨어에서 서로 다른 구현의 오래된 기능에는 박물관 등록번호 같은 물리 불변 기준이 없을 수 있다. 반면 공개 편집자는 잘못 이은 링크를 지목할 수 있다. 관계만 되돌리는 최소 근거의 단위가 서로 다르다. [O04](https://dwc.tdwg.org/terms/#identification) · [S11a](https://link.springer.com/article/10.1186/s12862-017-1076-y) · [O05](https://github.com/internetarchive/openlibrary/pull/6948).

기초 자료는 75행이고 직접 확인 71행 중 고유 원전 49저작을 하한에 산입했다. 역할별로 당사자 변경 12, 고정판 18과 소비자·편집자 인용 5, 비소프트웨어 사건 9, 규약/공개 구현 5다. 접근 실패 4행과 동일 저작의 다른 표시, 보강 근거를 산입하지 않았다. 산입 행에 기록된 발행자 표기는 30개, 같은 생태계와 재간행 통로를 보수적으로 묶은 발행 주체는 23개다. 사건은 별도 12+4이고 60개의 관측/정정 입력은 연구자가 추출한 재생 단위다.
