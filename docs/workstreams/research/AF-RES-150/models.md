# 저장 방식과 조회 의미

입력은 출처에서 읽을 수 있었던 문서 관측과 관계 선언이다. 원문 작성자 발언, 서버 주소 관측, 작업자 해석은 원장에서 구분한다. 비교의 ID는 로컬 실험에서 원문 근거를 연결할 키다. 실제 서비스의 전역 식별자를 대신하지 않는다.

| 방식 | 저장·쓰기의 가정 | 사전 예상 조회와 고장 경계 |
| --- | --- | --- |
| A 주소와 메모 | 원시 주소마다 현재 관측 1행을 갱신한다. 관측 판, 기능 메모, 원문 근거를 한 행에 둘 수 있다. 이미 본 URL의 문서가 바뀌면 마지막 메모를 보존한다. 확인된 전달만 현재 주소로 쓸 수 있다. | 안정된 링크는 F·L·T를 답한다. 별칭을 병합할 근거와 과거 판·정정 주체는 실질적인 수정이 들어오면 손실되기 쉽다. |
| B 공통 키와 고정판 | 공급자가 제시하거나 외부 인용자가 함께 쓰는 공통 키와 문서 관측을 추가한다. 판·원출처를 되짚고 키 안에서 최신 유효 관측을 찾는다. 변경 알림과 주체도 키 단위로 보존한다. | F·T는 판에서 답한다. 결합할 범위가 키와 일치하면 L·A도 답할 수 있다. 판/절보다 넓은 키나 새 키 때문에 L을 오답으로 반환할 수 있다. |
| C 인용과 방향 있는 변경 | 별도 관측 ID에 원래 위치·판·기능을 보존한다. 같은 참조, 읽을 위치의 이동, 부분 계보, 이견, 명시적 취소를 출처·공개 시점·유효 시점과 함께 기록한다. 관계 취소는 그 관계만 비활성화한다. | F·T는 처음 관측, L은 해당 목적의 최신 유효 관계, A는 관련 정정 출처를 읽는다. 이견이나 대체 위치가 확정되지 않은 경우 보류한다. 외부 자료에 관계가 없으면 추론으로 빠진 연결을 채우지 않는다. |

A의 영감은 이관된 위치와 메모, B는 별도 판과 갱신 알림, C는 재동정과 되돌림의 변경 범위다. MARC/Crossmark/Darwin Core/Open Library에서 확인한 방법을 로컬에서 비교할 만큼 단순화했다. 공급자가 실제로 아래 SQLite 형태를 쓴다는 뜻은 아니다. [GitHub 이관 규칙](https://docs.github.com/en/repositories/creating-and-managing-repositories/transferring-a-repository) · [MARC 775](https://www.loc.gov/marc/bibliographic/bd775.html) · [Crossmark](https://www.crossref.org/documentation/crossmark/participating-in-crossmark/) · [Darwin Core](https://dwc.tdwg.org/terms/) · [Open Library #6371](https://github.com/internetarchive/openlibrary/issues/6371).

관측의 유효일은 사건이 적용된 날, 공개일은 원문에서 알 수 있게 된 날, 전달 순서는 로컬 재생 순서다. 기간 밖 행은 배제한다. 나중 정정이 과거에도 적용된다는 사실을 확인하면 사후 감사에만 반영하고 당시 조회에는 전달하지 않는다. 판 관계의 동일성 범위는 작품·실물·저장소·문서 절에 따라 다르므로 파생·후계·다른 판을 양방향 동일성으로 닫지 않는다.

기록 비용은 로컬에서 성공한 행 변경 수, 정정 입력 수와 정정으로 생긴 행 변경 수, 남은 직렬화 값의 UTF-8 바이트, 파일을 닫은 SQLite 파일 바이트다. 실제 노동·네트워크·서비스 규모 비용은 별도 실측 대상이다.

## 실행에서 사용한 세 가지 규칙

- **A**의 키는 문자 그대로의 URL이다. fragment와 query를 보존한다. 같은 URL에 관측이 두 번 오면 최신 메모와 원문 근거가 앞 기록을 덮는다. 검증된 전달의 경우만 기존 메모의 읽을 위치를 갱신한다. 시간 필드가 없어 같은 DB를 과거 시점으로 질의할 때 현재 메모가 보인다.
- **B**의 키는 관측 ID이며 공통 키의 일치는 별칭 판단과 현재판 선택에 쓴다. 최초 F/T와 정정 알림은 보존한다. 읽을 위치는 그룹의 최신 고정판을 선택하며 같은 핀은 최초 주소를 유지한다. 주체와 이견의 공지는 그룹 전체에 보인다. 예를 들어 한 서지 Work의 두 판과 한 GitHub repo의 두 주소가 둘 다 공통 키 아래 들어갈 수 있다.
- **C**의 키는 문서 관측 ID와 선언 ID다. 방향 있는 읽기 경로는 해당 인용의 기능 범위가 일치할 때만 따라간다. 확인된 전달도 경로를 바꿀 수 있다. 두 주소의 좁은 동일성은 명시한 쌍에서만 확인하며 비교할 대상과 범위를 데이터에 기록한다. 이견과 공개 근거 미확인은 결정을 보류한다. 정정 유효일과 공개일이 모두 cutoff에 도달해야 해당 행을 사용한다. 취소는 지목한 선언 ID만 없던 판단으로 처리하므로 다른 인용 행을 다시 쓰지 않는다.

B와 C는 같은 ID에서 내용이 달라지는 입력을 예외 처리하고, 직전과 같은 ID·내용은 행을 추가하지 않는다. A는 같은 URL에 쓰기를 다시 한다. 내부 행은 케이스 ID와 각 방식의 실제 키, 정렬 JSON payload를 저장한다. C의 일부 관계가 연결 결정을 더 잘 보존하는 원인은 목표와 증거 범위를 따로 쓴 데에도 있다. 특정 DB 엔진의 효과를 실험한 것은 아니다.

F/T는 재생 DB에 들어가 있는 원 관측에서 읽는다. L에서 위치 값이 같아도 기대했던 근거가 빠졌으면 근거 소실이다. A에서 `NONE`은 그 저장소에서 확인할 정정 기록이 없다는 반환값이다. `MISSING`은 원자료와 판독이 없음을 그대로 남긴다. `HOLD`와 함께 반환한 증거가 부족하면 정당 보류로 세지 않는다. P는 네 조회와 별도이며, 쌍의 동치 판단이 잘못될 때 오병합·오분리로 센다.

비용의 성공 쓰기는 SQLite `total_changes`의 성공 트랜잭션 차이다. 입력 정정 수와 실제 반영 쓰기를 분리한다. 논리 바이트는 케이스 ID·스토리지 키·JSON의 UTF-8 합계다. 파일 바이트는 전체 DB별 SQLite 페이지를 포함한다. 시나리오별 집계 행 `ALL`과 사례 행을 함께 남긴다.
