### Q2 원 제출 대 표시
EARL [S02](https://www.w3.org/TR/2017/NOTE-EARL10-Schema-20170202/)의 assertion은 subject/test/assertedBy/result/mode/date를 가진 단언. reports README [S06](https://github.com/w3c/json-ld-api/blob/8811ba2a3bcae883ac91efacffb70ef08d84e92f/reports/README.md)에 *.ttl→earl.jsonld→index.html 생성 경로; generator [S07](https://github.com/gkellogg/earl-report/blob/0.9.1/README.md)은 결과를 조인한다. 2025 report는 internal document이며 W3C Recommendation 자체와 문서 지위가 다르다. assertions.csv 60행에 실제 원파일 line range, 렌더 col/outcome, DOAP release 및 일시, raw outcome, 증거 한계를 남김. primary 25 automatic/25 PASS 일치, C 미제출 5. 보강 29 pass/1 fail. EARL automatic은 측정 모드의 자기보고이지 JSON-LD processingMode가 아니다. 원 결과를 그대로 재표시한 것이 새로운 independent vote가 될 수 없다. 단언 블록 정규표현식 매칭은 이 판의 관찰이지 일반 RDF parser 검증은 아님.

## 조건부 대안과 추가 분석
1. 표준 편집자: 원 spec + manifest + EARL을 버전 구분. 편집 변경을 확인할 때 test_id와 fixture digest를 함께 비교. 반대 설명: 동일 ID이므로 동일 술어라는 가설은 H01로 약화되나 main 10에는 미검증.
2. 구현 제출자: raw report는 잘 정리된 결과 교환 단위, 별도 CI artifact/commit/command/runtime로 강화. 독립 저작 여부는 dependency tree+port history+core runtime를 별개로 수집. 구현 언어가 다르다는 사실만으로 독립성 결론 금지. 유지자는 공통 engine ID를 부여하고 run IDs 별도 관리. 배포판을 고르는 독자는 exact version+mode를 필터링하되 실패가 없는 미제출 구현을 합격으로 보지 않는다.
3. 가장 잘 지지되는 설명: 여러 당사자가 같은 test IRI에 개별 단언을 남겼고 generator가 재게재. 반대 설명: 일부 단언도 같은 실행 복사/공통 engine일 수 있다. 서로 다른 assertedBy와 날짜가 완전한 복제 가설을 약화하나 run artifacts 없이 배제 못함. 동일 suite는 비교 조건이지 재게재 표시 아님. 제품 DB·검색 엔진·Studio 선택은 보류. 세 반환 선택은 advice.csv.
4. sources.jsonl 38행, 고유 실질 자료 30(7 suite/spec/gen, 6 reports, 11 implementation, 2 changes, 2 proficiency, 2 environmental source docs). 동일 출전 파생/재열람 8행 제외. 원 자료 수≠독립 실측. 환경 특정 행 0, 엄격 원 실행 0, 결과 PARTIAL. 정확판 fixture/보고 역사 및 실행 증빙 확보 후 Codex에서 조인 검사. 새 실행은 과거 제출의 증거가 아니라 별개의 신규 관측.
