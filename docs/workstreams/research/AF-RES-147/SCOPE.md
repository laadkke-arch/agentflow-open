## 관측·요청·판정

- 같은 엔진·등록 API·URL·입력 순서로 분리된 DB를 운용한다. A는 URL/제목/마지막 상태·값, B는 정확판·셀 키/위치·관측 시각·실패 종류/공급자 이벤트 식별자가 있는 추가 전용 관측, C는 그 관측에 요청판·프로젝트·의미 입력과 보존조건·근거 ID·당시 결과·전임 요청을 연결한다. 최초 등록은 제목/본문을 취득하지 않고 URL만 저장한다. 본문은 작업 DB에 저장하지 않으며 고정 원문을 요청에서 다시 읽어도 된다. A의 주 비교는 URL로 범위가 증명되지 않으면 다시 읽는 신중한 경로다. 같은 URL 최신 저장값을 재사용하는 낙관적 A는 별도 대조다.
- tz 프로젝트 하나는 같은 UTC 순간을 지정 판의 오프셋으로 표시하고, 하나는 문자열을 유지할 수 있는지 검사한다(레바논 공지 기준 기대 표기 EEST, 그 외 가상 요구는 CST). CLDR 프로젝트 하나는 고정 숫자 12.5 또는 1234의 값을 보존하도록 해당 역할의 기호를 넣고, 하나는 입력 구분문자 U+002C를 문자 그대로 보존할 수 있는지 검사한다. 기대 보존조건은 프로젝트 입력이며 원문에 대한 주장으로 취급하지 않는다. 숫자 적합 여부는 이 선택 셀의 표기 생성 계약에 한정한다.
- 순차 및 양끝 질의는 같은 판 전환/URL과 동일 두 프로젝트를 사용한다. 첫 질의 없이 등록 확인, 첫 조회→동일 요청 재시도→두 번째 프로젝트→판 교체→옛 전달(요청 ID만)→현재 조회를 포함한다. 각 판/키의 두 프로젝트에 대해 전달값과 현재 적용, 해당 컷오프에서 원문 관측 가능 및 실제 근거를 분리한다. 같은 값의 새 근거판, 다른 키, 같은 표시의 역할 충돌, 실제 변경을 분리한다. 보류 이유를 실패·키 부재·미지 선호·이력 증빙 부재로 나눈다. 기준 지원과 안전한 재취득을 허용하므로 A/B의 모든 현재 응답이 틀릴 것을 가정하지 않는다. B가 원래 입력과 컷오프를 호출자가 제공한 경우의 재구성도 별도 검증한다.
- 구성 공급자는 실제 원전 판독과 별도 분모다. 일시 불능은 실패 틱 3, 재시도 4, 공급자 회복 5, TTL 만료 6에서 검증한다. TTL은 관측 후 3 가상 틱 미만만 유효하다. 정상 키 부재/고정 진입 불능은 정확판·키에만 유효하고 일시 불능과 구별한다. 캐시 꺼짐은 현재 원문 재취득, 요청 재시도는 일시 실패를 이월하지 않고 성공/확정 음성만 정확 범위에서 재사용, TTL은 일시 실패에만 임시 추가 재사용이다. 미지 선호는 공급자 재시도로 해결되지 않는다. 중복 동일 delivery_id, 늦은 옛 판, 두 전달의 역순, 원문 접근 단절, 같은 값의 이중 출처, 단순 북마크를 따로 검사한다.
- C의 판/위치/입력 키/요청판/관측시각/실패 종류/근거 연결을 한 번에 하나만 가린다. 가린 값을 ID 문자열이나 외부 원장으로 복원하지 않는다. 정착한 질의에 새 필드를 설명하는 사례는 구성으로 분리한다. 가능한 대체 질의와 보수적 보류의 대가를 결과에 포함한다. 출력 재생·현재 적용·이전 시점의 지식은 독립 판정이다. 모델은 실험 입력 구조를 알고 있지만, 조회 프로세스와 SQLite에는 평가자의 `oracle.csv`나 기대 답을 넣지 않는다. 평가자는 판독 결과를 먼저 고정하고 별도 단계에서 답을 대조한다.
