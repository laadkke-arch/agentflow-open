# 실행 프로토콜 v1 — 계획, 실험 미실시

## 1. 목적과 단위
제공 URL에 의한 새 방법 발견과 이미 알던 방법의 상기를 구별 가능한 사건으로 남기되, 내적 지식 상태나 개인별 인과관계를 확정하지 않는다. 무작위 배정으로 식별하는 효과는 '추천 카드의 이른 제공 정책'이다. 모든 사람은 나중에 카드를 받을 수 있고, 1차 창에도 스스로 다른 경로로 발견할 수 있다. 개인×과제 1개 배정이 분석 단위; 추천 후보×동일 산출물 계보 1개가 사건 단위; 이벤트는 그 안의 기록 단위. 시간은 분, 초 원장과 사람별 합. 4 합성 사건은 검정용 자료, 실험 배정 수 0.

## 2. 대상과 배정
향후 별도 동의·연구 심사·비공개 환경에서만 시행. Python 기본 리스트/함수 경험 있는 개발자, 해당 표준 API 지식으로 선별하지 않는다. 모집 목표 24명(효과 검정력 근거 아님), A/B 두 과제. 연구자는 모집 전 참가자 순서표/seed와 배정 생성 코드 해시, 자료 버전/채점 벡터를 봉인한다. 독립 배정 관리자가 task 순서를 A→B 또는 B→A로 12명씩 할당하고 타이밍은 각 순서 층에서 6명 E→L, 6명 L→E. 모집 담당자는 다음 배정 모름. 초기 설계 저장 완료 시 t0에 1기 타이밍을 해제. 2기는 같은 사람 반대 타이밍이므로 추론 가능성, 과제 1의 경험과 질문 효과 기록. 1기만 사전 지정 주분석(24, 각 task×조건 6), 2기는 탐색적(24); 모든 배정 48, 각 task 24, 각 task×조건 12 예정. 모집 중단은 사전 기간/인원 도달/안전 사유, 결과 보고서 확인하여 조기 종료 금지. 탈락자가 다시 들어와도 최초 배정 유지; 순서표 재사용 금지.

|---|---|---|---:|
| S1 | A-E | B-L | 6 |
| S2 | A-L | B-E | 6 |
| S3 | B-E | A-L | 6 |
| S4 | B-L | A-E | 6 |

## 3. 단계별 진행(분)
- 등록: 동의, 연구 ID, Python 일반 경험/환경(방법명 언급 금지), 기록 범위 안내, 브라우저/작업 디렉터리 초기화. 실명·비밀번호·개인 계정은 수집하지 않는다. 참가자 간 교류·검색 세션 공유 금지. 실험자는 합성 자료만 공개; 향후 개인 로그 접근 제한, 동의/삭제 기간을 사전에 고정.
- 0 이전 6분 공통: 요구문/공개 예시만 제공. 외부 검색·AI·자동완성·API 도움말 금지. 자유회상 질문 “이 문제를 어떻게 해결하겠습니까? 이미 써 본 방식, 기억나는 도구, 가능한 다른 방식, 모르는 점을 이름을 몰라도 설명해 주세요.” 선택지/API 단어/문서 보여주지 않음. 구두·문자 답변, 초기 pseudocode/설계/초기 코드(미완성도)와 원본 bytes를 seal. 편집기 snapshot, stable function id, SHA256, time, actor ID, session ID, task ID, phase. 미제출이면 빈/미확인 코드와 사유 기록; 누락자를 임의 탈락시키지 않음.
- t0: 배정 수신 및 기록. E는 지정된 두 카드 제공(적합·같은 역할 부적합), L은 동일 자리 중립 안내. 카드 외형/제공 시각을 제외하면 UI/과제/시간 동일. L의 무노출 비교창은 '실험 카드 미제공'일 뿐 지식 무노출 보장 아님.
- t0≤t<12: 양쪽 공식 문서·공개 웹 검색 동일 허용, 생성형 AI/협력/외부 코딩 도구 금지; 허용 목록과 자동완성 동일. 자력 검색 결과 스니펫, 링크 제공·보임·열기, 문서 실제 구간, 탭 변경, 검색/복사·실행/저장 이력 기록. 자동 추천과 검색 결과를 구별. 비인가 노출/기록 끊김/타인의 추천 표시하되 배정 제외 금지.
- t12 직전: 입력 잠금하고 두 조건 동일 snapshot, 문서/카드 노출 상태 및 현재 선택 이유 중립 질문을 기록한 다음 L에 같은 두 카드, E에는 중립 안내. 링크 순서는 미리 참가자별 무작위화하여 동일 후보 세트, 순서 기록. 잠금 실패/12분 이전 카드 누출은 명시.
- t12≤t≤24: 계속 작업, t24에 공통 최종 freeze. 후보별 사후 자유 설명(왜 바꿨는지, 처음 접한 경로·시각·기억, 다른 추천/검색/실패, 이전에 알고 있었는지); 질문은 새 힌트가 되므로 산출물 동결 뒤 시행. 코드 수정 허용하지 않음. 시간 초과 변경은 후속 재작업으로 별도 version.
- 5분 중립 휴식(교류/문서 금지) 뒤 다음 과제. 1기의 회고 자체가 2기 탐색 전략을 가르칠 수 있음. 선택적 대안으로 1인 1과제 독립 4-cell 무작위, 비용은 증가하지만 전이 감소; 더 엄밀한 본실험 후보.
- 독립 채점: 배정, URL, prior, 활동 시간, 작업자 ID를 숨기고 무작위 artifact alias와 요구문/동결 rubric만 제공. 실행 담당은 동일 Python 3.12.0 고정 및 hidden vectors; 채점자는 첫 제출별 결과와 명세 위반을 평가. 코드 자체가 API/조건을 암시하므로 추론했는지 별도 기록. 두 채점자 독립 판정 후 불일치 제3자 판정; 동일 결과/메서드 외형을 이유로 자동 합의 금지. 운영 인수자는 별도 역할, 수락/거절/보류 및 사유/시간 기록. 원자료의 quality label을 수정하지 않고 후속 artifact 별도.
- 후기: 사전 정한 공통 후속 검수/수정 창(최대 작성자 추가 15분, 검수자 10분/버전, 최대 2라운드, 실제 경과 48h cutoff). 1차 결과는 t12−, t24의 원산출물, 최종 인수는 후기 별도. 2기 종료 전 1기 품질 정답 공개 금지. 검수 후 작성자 변경과 검수자의 직접 변경을 구별; 운영 인수는 rubric 전부 통과, 미해결 요구 없음, 동일 hash의 독립 수락 기록으로 한정. 운영자·채점자 동일 인물이면 역할별 활동 중복 제거 및 명시.

## 4. 원자료 보존 및 조인
event-dictionary.csv를 따르는 append-only JSONL/CSV. 원문 이벤트와 코딩 분리, 정정은 old_event_id를 가리키는 새 이벤트. UTC + monotonic ns, clock sync/오차 기록. event_id 유일; participant×session×assignment×artifact_id 고정. version_hash는 원 bytes SHA256, previous_hash; snapshot + 기능 단위 diff + editor actor. 동일 hash라도 다른 사람 작성 가능하므로 auth provenance, actor-linked editing log 필요. 연결 누락 시 원문은 보존하고 해당 주장만 보류. 브라우저 기록은 viewport/문서 section/visible seconds 기록, 실제 읽음은 텍스트 재진술/행동과 별개; 화면 단순 hover/탭 로드 ≠ 이해. 짧은 링크 텍스트에 이미 방법명이 나타날 수 있으므로 first_content_visible 별도. URL redirect/floating docs는 resolved URL + saved content hash/판. 자동 시각만으로 인과관계 주장 금지.
각 후보는 prior state K=사전 방법 이해/사용 지지, NAME_ONLY, CONCEPT_ONLY, N_CONSISTENT=비인지 진술과 봉인된 설계 및 사후 진술 합치, U=unknown/conflict; prior의 단위 method family / API name / 적합 조건 / 적용 능력 각각 분리. 비인지와 모르는 조건, 기억 못함은 별개. source attribution은 자기 진술+시간선+기능 diff+다른 경로 기록을 함께 판정; 대안 미추적이면 경쟁 설명 미확인. K라도 새 조건 학습은 별도 사건. R=교체 관측 여부, A=독립 인수 여부. 전후가 처음부터 같은 알고리즘이면 사용 유지/재확인. 시도→되돌림은 attempted, transient replacement, final not adopted. 단순 API 이름 변화/리팩터링은 방법 변경과 별개. 링크로 인해 변경됐다는 표현은 시간선과 자기보고가 합치한다는 강도로만 쓰고 개인 인과 확정 금지.

## 5. 분석과 누락
주 estimand t12−에서 (E-L) 차이: 모든 1기 배정 중 독립적으로 채점 가능한 same-author 기능 교체·후보 일치 및 novelty-consistent 표시 각각, 품질 통과도 별도. 지연군 자력 발견은 같은 판정 규칙으로 원인이 카드가 아닌 자력으로 코딩. source-specific 사슬과 generic discovery 분리; E에 제공했으나 미열람도 E. 상태마다 confirmed/contradicted/unknown, binary point estimate는 complete-case 별도 또는 bounds; all-assigned 하한 성공/N, 상한 (성공+미확인)/N, 두 조건 차이 범위 [LE−UL, UE−LL]. 미제출은 독립 인수에서 실패(정의된 cutoff), 산출물 교체는 미확인이지 0 아님. observed no는 실제 기록된 부재. 정상 공석 = 아직 할당되지 않은 자리, NA = 구조상 비적용. 모든 사건×후보를 사람 수처럼 합산 금지. 기록 끊김·포기·링크 미열람·이미 알던 사람·오답·오염 모두 배정 분모에 유지. 24분 이후에는 모두 제공되므로 timing history 비교, 무노출 대조 아님. 2기 within-subject 탐색 및 period×timing/순서별 결과, 군집 단위 사람. carryover 유의성 검정 결과에 따라 1기/2기를 사후 선택하지 않는다.
labor: 작성자 탐색·설계·구현·테스트·수정, 독립 검수·인수의 person-min, 중복 시간은 같은 사람만 합집합. 대기/elapsed separately; 동시 두 사람은 사람시간 더함. 시각 경계와 실제 작업량을 구별, idle/회고 시간 분리. 검수 미실시=구조적 0(정의 명시), 로그 손실=U, 포기 전 비용 포함. 성공자 조건부 비용 별도 보고하며 선택 편향 표시. 전체 총비용/독립 수락 수(0이면 NA), accepted/N, 성공자 중앙값, 총·평균 비용, 리뷰별 표. M03 Lee bounds는 monotone selection 가정 사전 근거 없으므로 적용하지 않는다.
독립 코더 2명은 prior/교체 인과 문구를 별도 채점; 배정 숨기기 불가능한 추적 판독과 품질 판독 분리. 사전 봉인된 코드북, 불일치 원인/3자 조정, 원 레이블 보존. 일치율·교차표와 missing; 실제 4 합성 사례는 한 작업자 손 판독, 독립성 없음.

## 6. 실행 승인 전 체크
설계만, 모집·실험·실행·개인자료 수집 없음. 별도 승인 시 자료 동의, 배정 seed/hash, 고정 CPython version, URL content hash, 검수자 독립성, blind alias, freeze/append-only integrity, 시험 sandbox를 확인. 최초 dry-run은 합성 4개+누락/오염/rollback이며 결과는 empirical로 합산 금지. 실행 명령·벡터는 stimuli.md와 verify_vectors.py.
