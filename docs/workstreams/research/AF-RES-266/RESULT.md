83/83개를 `filename+SHA-256`으로 양방향 조인했다. 공동 필드의 URL·바이트·요구 버전·`core-metadata`·`yanked`·업로드 UTC 불일치는 0이다. `core-metadata`는 80개 wheel에 해시 객체, 3개 sdist에 boolean `false`다. Simple의 실제 `data-dist-info-metadata`도 같은 값이고, 버전 JSON에는 그 키가 없다. 두 API 모두 yanked `false`이며 버전 JSON의 `yanked_reason`은 `null`, Simple에는 독립 이유 키가 없다. Simple `provenance`는 `null`, 버전 JSON에는 해당 키가 없다. CSV의 `<absent>`는 원필드 부재, `null`은 실제 JSON 값이다. 네 공석은 정상 응답 두 모집단의 현재 조회 범위를 뜻한다. [공동 및 편측 필드](files.csv), [Simple 사양의 필드 정의](https://packaging.python.org/en/latest/specifications/simple-repository-api/#project-detail).

## Q6 · 태그와 제약의 반례

표 2의 sdist와 macOS arm64는 파일을 직접 열어 내장 메타데이터를 확인했다. 1.15.0의 실제 `cp313-cp313t-manylinux` 파일은 GIL 0, 자유 스레딩 1이다. 1.14.1 GIL M9는 wheel 목록, 본문, 공식 지원 진술, 현재 실행이 양성이다. 같은 판의 `info.classifiers`, 고정 `pyproject.toml`, M9 ZIP에는 3.13 분류자가 빠져 있어 분류자 단독 탈락 규칙이 틀린다. 1.14.0의 개발 이슈에는 3.13 지원 예상과 nightly가 있었으므로 현재 stable wheel 공석에서 당시 소스 지원 여부는 미확인이다. Nikon은 두 모델에서 게시 채널의 호스트·다운로드 OS와 실제 카메라 및 C 버전 문턱을 각각 기록해야 하는 사례다. [1.14.1 태그 pyproject](https://github.com/scipy/scipy/blob/92d2a8592782ee19a1161d0bf3fc2241ba78bb63/pyproject.toml#L55), [3.13 논의](https://github.com/scipy/scipy/issues/20992), [두 Nikon 원행](COUNTEREXAMPLES.md#nikon-정규화한-두-행).

## Q7 · 당시 CI 판정과 현재 실행

세 release tag의 peeled commit, 태그별 `wheels.yml`, `pyproject.toml`의 test-command 및 1.14.1의 `scipy.test()` 스크립트를 열었다. 1.14.1의 GitHub 설정은 cp313×manylinux x86_64 빌드, 테스트 준비, wheelhouse 업로드를 정의한다. 공개 exact-commit Checks와 tag 검색에서는 job 자료를 찾지 못했고, PyPI 다섯 파일의 Integrity API는 현재 provenance가 없다는 404였다. 개발 실패가 적힌 PR #21409는 aarch64·다른 checkout이며 Cirrus task 원로그는 502였다. 발행자 README 체크섬은 79/80 wheel이 일치했고, M9는 현재 GitHub Release와 PyPI에서 받은 전체 바이트의 지문도 같았다. 당시 job·artifact digest가 이 파일과 일치하는지는 5/5 미확인이다. [태그 확인](receipts/ci/scipy-tags.stdout.txt), [1.14.1 workflow](https://github.com/scipy/scipy/blob/92d2a8592782ee19a1161d0bf3fc2241ba78bb63/.github/workflows/wheels.yml#L77), [동판 시험 스크립트](https://github.com/scipy/scipy/blob/92d2a8592782ee19a1161d0bf3fc2241ba78bb63/tools/wheels/cibw_test_command.sh), [CI 산출물 반대 사례](https://github.com/scipy/scipy/pull/21409).

로컬 M9는 별도 빈 환경에서 CPython 3.13.5 GIL, Linux x86_64 glibc 2.41, NumPy 2.1.3으로 실행했다. `uv`는 두 wheel의 SHA-256을 강제하고 인덱스 없이 설치했다. `scipy.linalg.solve([[3,1],[1,2]], [9,8])`의 결과는 `[2.0,3.0]`, 최대 절대 오차 0.0, 종료 0이었다. 적재한 네이티브 `_fblas`의 SHA-256이 그 wheel ZIP member와 일치했다. 별도 빈 폴더의 오프라인 계산은 원응답 지문, 두 파서 결과, 83개 파일 및 9셀 조인을 다시 확인한다. ## 적용과 철회 조건

- **바이너리만 필요한 사용자**는 양성 5셀에 버전·태그·직링크·SHA-256 조합을 적용할 수 있다. 현 인터프리터/ABI/OS/architecture/libc가 다르거나 바이트·요구 버전·철회 상태가 달라지면 해당 조합을 다시 고른다. 공석 4셀의 표본 외 지원판은 별도 조사 대상이다.
- **과거 설치 안내의 편집자**는 버전 고정 인용과 현재 파일 링크를 함께 사용하고, 과거 진술에는 게시 채널·정밀도·원 파일의 기록 범위를 붙일 수 있다. 당시 인덱스 스냅샷이나 당사자 로그에서 정확한 파일/삭제가 확인되면 역사적 문장을 갱신한다. 현재 링크와 과거 인용의 유지 비용은 해시 및 조회 시각 한 쌍이다.
- **릴리스 관리자**는 SHA-256 및 별도 UTC와 함께 전달하고, “이 배포물을 시험했다”는 문구에는 job의 사용 wheel digest와 공개 대상 digest의 일치를 요구할 수 있다. 이 방법은 job이나 provenance 보존 비용이 든다. 현재 시험 영수증은 독립 실행의 의미로 제공한다.
