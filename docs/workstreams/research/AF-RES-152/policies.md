# 비교할 운영 정책

두 예산과 두 요청열은 모두 [config.json](config.json)에 있다. 넘기려는 작업은 요청·바이트·판독 모델초 중 하나라도 부족하면 시작하지 않는다. 한도는 6월 1일 기점의 연속 168시간마다 다시 채운다. 실제 수신 바이트나 사람의 작업시간은 이 장의 가정과 구별한다.

| 정책 | 동일한 입력으로 하는 일 | 운영 비용과 빠지는 상황 |
| --- | --- | --- |
| O 요청 때만 | 현재 요청의 공급원 목록이나 알려진 원문을 한 번 읽는다. 각 요청을 원격 조회하며 평시 추천 재고가 없다. 발견 이력은 평가에만 쓴다. | 수요 없는 대상을 읽지 않는다. 같은 요청이 겹치면 반복 비용을 내고, 원격 조회가 막히면 즉시 대답하지 못한다. |
| P 정기 목록과 원문 | 03 UTC에 공급원 목록을 순환하고 15 UTC에 기존 원문을 순환한다. 시작은 공급자 ID 순서, 유보 창부터 학습에서 정한 순서. 목록은 표시일 기준 최근 30일. | 빈 목록과 안정 원문의 판독을 운영자가 부담한다. 종료 표시가 된 원문을 다시 열어 확인할 수 있다. 기간 사이의 짧은 장애는 놓칠 수 있다. |
| S 통지 수확과 후속 확인 | 같은 배경 슬롯에 공급원별 72시간 뒤 신호를 다음 순서로 확인한다. 변동 공지는 원문 조회 대기에 넣고 예정 기한만 먼저 읽혔으면 해당 시점까지 보존한다. 직전 성공 시각에서 48시간 겹쳐 읽는다. 보존 창은 14일이다. | 통지를 제공하고 분류하는 공급자 비용, 누락 구간과 중복을 처리하는 운영자 비용이 생긴다. 밀린 원문 확인이 새 자료 확인을 밀 수 있다. |
| F 희소층 확인 기회 | S를 바탕으로 매 7일의 첫 배경 슬롯을 curl에 주고, 다른 슬롯의 통지는 가장 오래 읽지 않은 공급원부터 처리한다. | 희소한 출처가 통지 확인을 받을 시간을 보장한다. 이 슬롯이 후속 원문이나 주류 수요에 쓰일 수도 있었다. |

P/S/F에서 요청할 때 이미 알아낸 목록의 72시간, 이미 판독한 대상의 168시간 안이면 그 근거로 먼저 답한다. 기간이 지났으면 같은 예산으로 다시 읽으며, 예산이 없을 때는 지난 근거의 상태를 표시해 채점한다. 명시된 운영 종료 기한을 지나면 캐시에서 제외한다. 새 판의 정보가 실제로 들어와야 기한 변경을 알게 된다. 본문 관측에서 일시 실패를 확인한 상태는 불가로 표시하고, S/F는 24시간 뒤 원문 재확인을 대기에 넣는다. 상태 공지에서 사후 사건을 알게 되는 것과 장애 당시 사용 가능한 답을 주는 것은 별도 성적이다.

curl의 메일과 GitHub Release에 각각 공개된 시각, Firefox의 버전 문서와 도움말 판 이력, Cloudflare의 production 변경과 공개 날짜를 두 관측 API에 대응한다. 이 API는 오프라인 입력의 제한된 관측 함수다. Cloudflare 목록과 Mozilla 편집 이력에 이 재생의 14일 cursor API가 실제로 있다는 뜻으로 사용하지 않는다. 표시일이 오래된 항목은 최근 표시일 목록에서 빠질 수 있다. 수확 쪽의 시간은 기록이 새로 공급된 시점이다. 사이트의 라이브 전환 시각이 없는 경우 증거표의 하한 또는 일자 끝을 적용한다.

## 판정

- 신규의 발견은 처음 관측한 발행 항목 ID다. 최신판 질의 답은 같은 공급자에서 지금까지의 항목 중 표시일이 가장 최근인 것으로 판정한다. 기존 대상은 판별에 필요한 이유·가용성·기한을 저장한다. 신규 원문 기능의 지역별 도달은 채점 밖이다.
- 기존 대상마다 매시 추천 가능·부적합·일시 실패·보류를 비교한다. 기대 이유가 바뀐 공지 셀 또는 영향권에서 실패한 때 추천이 나가면 낡은 추천에 넣는다. 아직 맞는 이유를 기한 만료나 과거 장애 때문에 숨기면 잘못된 제외다. 특히 복구 뒤 이전 장애 표시는 오경보 시간이다. O의 재고 없는 시간은 별도 분모로 보인다.
- 역사적 시각이 여러 개인 경우 발생·당시 관측 후보·직접 현재 열람을 따로 둔다. 한 시간보다 짧은 장애는 잠재적으로 한 틱 이하로 나타난다. 각 사건이 다음 정정에 덮인 뒤에는 당시 뜻을 확인했다는 점수를 주지 않는다. 사후 장애 공지를 본 것은 사건 인지로 기록하고 직접 판독은 별도 열에 기록한다.
- 요청 결과는 올바름, 보류, 잘못된 제외, 낡음, 당시 원문 근거 미확인으로 센다. 지연은 확인된 검열 전 값과 끝까지의 하한을 모두 남긴다. 시드의 지식은 시작 시점의 고정판이나 종료 예고다. 오늘의 연속 가용성으로 바꾸지 않는다.

연합 수확자는 삭제·롤백·쪽 토큰을 고를 수 있고, 공급자가 무보존이면 다시 전체를 열어야 한다. 출판사는 정정 표현과 판 연결을 제공하고, 인용·추천 운영자는 같은 DOI에서 근거로 삼은 요소를 다시 판독해야 한다. 긴급 이용자는 상태가 회복돼도 접근 지연을 바로 부담한다. 소규모 공급자는 새 게시가 적어도 피드 유지 및 재시도 부하를 겪는다. 별도 현장 대안인 접수 순번의 확인 기회는 위 비용을 같은 기간에 비교할 수 있게 한다.
