# 통계·표준 정정과 귀속 반증

[정정 원장](../corrections.csv)은 7행, 6사건이다. C3은 동일 정정 사건의 현금 VAT 입력과 발생 기준 차입 집계를 분리했다. 이 자료는 코드 PR 분모 밖이다.

- **C1**. ONS G7G6의 v28 표는 Civil Service FTE SA, 단위 천명, 2022 Q2 480. 2022-09-13 버전 목록에는 일정 갱신과 정정이 각각 있고 정정 설명은 479다. 2026-09-15 동일 series의 2022 Q2 셀은 실제로 479다. 이전 표제 GB, 현재 UK를 보존했다. 이전판의 수정 통지와 훗날의 실제 셀을 함께 볼 수 있다. 같은 날 대체됐을 시점의 CSV 행은 열지 못했다. [v28 원표](https://www.ons.gov.uk/employmentandlabourmarket/peopleinwork/publicsectorpersonnel/timeseries/g7g6/pse/previous/v28) · [발행 이력 L96–99](https://www.ons.gov.uk/employmentandlabourmarket/peopleinwork/publicsectorpersonnel/timeseries/g7g6/pse/previous) · [후판 L225–235](https://www.ons.gov.uk/employmentandlabourmarket/peopleinwork/publicsectorpersonnel/timeseries/g7g6/pse).
- **C2**. 사망 인증 Table 1 row 1의 라벨은 R68.8→R68로 정정됐고 2023–25 건수 11,835/13,528/14,933과 표내 비율 23.1/26.6/30.4%가 같다. 버전 쌍과 값은 확정할 수 있고 발행 기관 외 초기 개인 제보자는 미확인. [원표 L356–360](https://www.ons.gov.uk/peoplepopulationandcommunity/birthsdeathsandmarriages/deaths/articles/deathcertificationreformenglandandwales/2025/previous/v1) · [정정판 L61–68, Table 1 L340–344](https://www.ons.gov.uk/peoplepopulationandcommunity/birthsdeathsandmarriages/deaths/articles/deathcertificationreformenglandandwales/2025).
- **C3**. HMRC의 2025-10-08 예외 발행은 4–8월 VAT 현금 수입 오류를 신고하고 합계 £2.4bn 상향을 밝혔다. ONS의 9-19·10-21 발표된 HTML 원표에서 동일 -J5II, 동일 UK FY to August 2025, 같은 £bn 열은 83.8→79.6이다. 10-21 설명은 발생기준 VAT 부분을 약 £2.0bn으로 지목하며 전체 £4.2bn에는 다른 변경이 섞인다. 명시된 제보자와 수정된 해당 지표를 둘 다 확인해도 전체 변경을 한 제보로 귀속할 수 없다. 10-08 즉시 현금 VAT 월별 원표의 절대 수준은 미확인이다. [HMRC 공지](https://www.gov.uk/government/statistics/schedule-of-updates-and-announcements-for-hmrcs-statistics/2025-hmrc-statistics-announcements#8-october-2025-hmrc-hm-revenue-and-customs-tax-receipts-and-national-insurance-contributions-for-the-uk) · [ONS 10-08 설명](https://blog.ons.gov.uk/2025/10/08/an-update-and-explanation-on-the-public-sector-finance-statistics/) · [9-19 Table 2](https://www.ons.gov.uk/economy/governmentpublicsectorandtaxes/publicsectorfinance/bulletins/publicsectorfinances/august2025#borrowing-in-the-financial-year-to-august-2025) · [10-21 Table 4·§7](https://www.ons.gov.uk/economy/governmentpublicsectorandtaxes/publicsectorfinance/bulletins/publicsectorfinances/september2025#revisions).
- **C4**. ONS 별도 2026-08-21 공지에는 HMRC, 3/4/5월, 월별 약 £235m 과대 VAT 및 해당 차입 과소가 있다. 공지에서 동일 셀의 표준 ID와 두 원자료 수준을 얻을 수 없었다. **제보자 식별 가능, 해당 원표 셀 미확인** 사례다. [재발행 상단](https://www.ons.gov.uk/economy/governmentpublicsectorandtaxes/publicsectorfinance/bulletins/publicsectorfinances/july2026).
- **E7138**. Yousouf Taghzouti가 Table 5의 `text/html;level=3` q값을 제보하고 Francesca Palombini가 Verified 처리했다. 원 정적 HTML의 q=0.7과 inline 정오표 화면의 수정 블록 q=0.3을 각각 직접 읽었다. 같은 예시의 media range와 일치하고, 수정은 원판을 그대로 보존하는 별도 표시에서 관찰된다. [공개 erratum](https://errata.rfc-editor.org/eid7138/) · [원표](https://www.rfc-editor.org/rfc/rfc9110.html#table-5) · [표시판 L3226–3268](https://www.rfc-editor.org/rfc/inline-errata/rfc9110.html).
- **E7107**. James Synge가 숫자 절을 신고했고 RFC Editor가 Julian Reschke 판단을 받아 Rejected로 처리했다. 지목된 RFC 9112 §7.1.2와 원 RFC 9110 §6.5.1 연결이 실제 존재한다. 보고·판정·문서 변경이 각각 별도다. [공개 erratum](https://errata.rfc-editor.org/eid7107/) · [원문](https://www.rfc-editor.org/rfc/rfc9110.html#section-6.5.1) · [대상 절](https://www.rfc-editor.org/rfc/rfc9112.html#section-7.1.2).

원표 제보자가 있어도 수치 정정 범위가 식별되지 않는 C4와 정정은 확실하지만 개인 제보자가 알려지지 않은 C2를 의도적으로 같이 읽었다. RFC의 명시 심사·판 표시는 PR의 열린 스레드와 달리 결론을 분명히 표시하기도 한다. 반대로 조직 공급자로부터 전달된 통계 사건에서는 개인 최초 인지와 Git과 같은 개별 편집 시계가 보이지 않는다. PR 작성자, 피드백 제공자, 실제 hunk 작성자, 릴리스 편집자를 별도 칸에 둬야 한다.

## 먼저 의심한 판단과 근거를 뒤집으려는 검사

- 링크의 효과를 전부 0으로 볼 가설은 #9618 후반의 [구체 타입 제안](https://github.com/pydata/xarray/pull/9618#discussion_r1911138165)과 [응답 및 자체 수정](https://github.com/pydata/xarray/pull/9618#discussion_r1912819641)으로 약해졌다. 제거한 NumPy 타입을 직접 확인했고, 실제 날짜 경계 검사 줄은 유지되었다. 별개로 같은 저자의 [pandas 논의에 대한 최초 인지](https://github.com/pydata/xarray/pull/9618#issuecomment-2426782047) 문구를 찾았으나 유사한 기존 구현과 연결해 보존했다. 런타임 링크 주장에 필요한 이 두 종류의 증거는 다른 사건에 있다.
- #7576의 공개 문서 경고 이후 원작성자가 코드를 바꿨다는 가설을 [원 리뷰](https://github.com/scikit-image/scikit-image/pull/7576#discussion_r1834941659), [기여 의사](https://github.com/scikit-image/scikit-image/pull/7576#issuecomment-2465641126), 새 [old hunk](https://github.com/scikit-image/scikit-image/commit/d012dc088b20c63291b61bb76ce078ed8c399740)에서 검증했다. lagru 패치가 확인되었고, 11-19 재배치된 committer 시각 대신 11-08 당시 객체를 읽었다. 원저자의 먼저 도입한 `@`는 안내 링크보다 앞선다.
- #7575에서 상대가 “이미 해결했다”고 한 말의 신뢰도를 PR 생성보다 더 깊게 시험했다. 실제 #7699의 [첫 Git hunk](https://github.com/scikit-image/scikit-image/commit/7417342f6c00501125698f29dd1e4a2ff0f879a5)와 [첫 공개 PR](https://github.com/scikit-image/scikit-image/pull/7699)이 두 시계 모두 링크보다 앞섰다. 뒤에 플랫폼을 되돌린 것은 뒤의 별도 패치다. 공개 기본 빌드 로그 소실 상태는 그대로 기록한다.
- 유사한 출력의 가설을 실제론 더 취약한 조건에서 시험했다. SciPy 1.11.2 `diags_array` 부재와 비주대각 값 순서 차이, 동일 adjacency에서 `*` 차이, normalize=True에서도 clip=False이면 1 초과를 재현했다. 값 수준과 dtype/shape/예외 각각을 기록했다. [두 실험 원장](../compatibility.csv).
- E7138의 status와 표준 본문이 모두 바뀌었을 가설을 정적 HTML과 주석을 연속 열어 시험했다. HMRC의 통보가 합계 수정의 전부였을 가설을 전후 동일 코드의 두 표와 ONS 분해 설명으로 시험했다.

## 접근 시도와 재개 입력

웹 원문은 접근했으나 ONS generator CSV는 MIME `application/octet-stream`, Appendix XLSX는 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`를 웹 조회기가 읽지 못했다. ONS 호스트에 대한 셸은 CONNECT 403, 클라우드 데스크톱의 browser requirements 조회 실패 뒤 공식 archive에 들어간 Chromium은 `ERR_TUNNEL_CONNECTION_FAILED`였다. 클라우드 데스크톱 스킬에 따라 범위와 환경 설정을 유지했다. 명확한 실행 환경에서 [sources.jsonl](../sources.jsonl)의 ONS-G7-27-FAIL/ONS-G7-29-FAIL, ONS-VAT-M29/M30/D109/D110-FAIL URL을 내려받아 다음을 비교한다.

- CSV에서 header의 series G7G6, title, unit과 `2022 Q2` 행을 함께 출력한다. v28의 오류 시점, v29 스냅샷이 반영한 발행 날짜 및 배열 방향, 13 December 2022 regular revision을 같은 시계로 둔다.
- XLSX에서 Appendix M Table 4–6과 Appendix D의 VAT 행을 2025년 9월·10월 edition에서 비교한다. 월별 현금 VAT는 별도 HMRC 19 September / 8 October edition으로 식별한다. 매 셀의 sheet, 주소, 통화·회계기준, 관측 UTC와 SHA-256을 기록한다. 영수증 검산은 기존 코드와 별개다.
