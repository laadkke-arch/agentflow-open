# 공개 문서 배포 사건: 사후 반례 조사

- 작성 범위: 선택된 소비 프로젝트 여섯 자리의 밖에서 생성·게시 도구 이슈를 읽었다. 사전 A/B 예산 봉인 커밋은 부모가 알려 준 `c16ae96`이며, 이 파일의 모든 자료는 그 이후 사실 검증이다. 사전 링크 선택 또는 추천 점수를 수정하는 자료로 소급하지 않는다.
- 읽은 원문 행은 7개, 보수적 계보는 6개다. 그중 실제 실패·변경 사건은 독립 이슈 4개이며, 배경 설명 2계보는 사건 수에 더하지 않는다. 같은 이슈의 댓글·복구 보고와 현재 산출물 재조회는 같은 계보다.
- 공개 접근 실패는 근거가 아니다. GitHub REST 댓글 403, web DisabledError를 attempts.jsonl에 남겼다. 공유 비인증 API 잔여량이 0이라는 통보 이후 API를 다시 요청하지 않았다.

## 추가로 읽은 경계: 사건 수에서 제외

**INC06 — [mike discussion #206](https://github.com/jimporter/mike/discussions/206).** 2024-02-10/11 소유자는 독립 mkdocs.yml 프로젝트와 deploy_prefix를 연결했다. 2024-06-03 후속 질문의 `/page` → `/0.1/page/` 자동 리다이렉트에는 지원하지 않는다고 답하고 수동 작성이 필요하다고 했다. 이는 ‘판별 디렉터리를 만드는 기능이 예전 루트 딥링크를 자동 보존한다’는 일반화를 반박한다. 실제 사이트의 이행·실패를 관측한 사건으로는 세지 않는다.

**INC07 — [pkgdown PR #2001](https://github.com/r-lib/pkgdown/pull/2001).** 2022-01-07 기능 변경 본문은 deploy_to_branch의 subdir를 worktree 경로와 공개 URL에 함께 연결한다. 한 도구 안에 생성과 게시 지원이 들어 있을 수 있다는 배경 근거다. diff·검토·실제 소비자의 배포는 확인하지 않았으므로 보존 성공 사례로 쓰지 않는다.

## Q별로 옮길 수 있는 판단

- **Q2:** 생성 산출물의 위치와 호스팅이 실제 해석하는 prefix/alias는 교환 조건이다. 명령어 안에 deploy가 있다고 공급자·호스팅 책임이 하나가 되는 것은 아니다.
- **Q4:** 사건의 공개 대화, 현재 산출물, 당시 런은 증거 수준이 다르다. 네 사건의 성공 대화가 두 단계 런 ID를 대신하지 못한다.
- **Q5:** 루트/하위 경로, alias의 symlink/redirect 표현, 브랜치/태그 권한, 루트/하위 프로젝트 활성 판이라는 네 종류의 경계를 찾았다. 옛 판 자체가 삭제됐다는 주장은 하지 않는다.
- **Q6:** 확인해야 할 설정 필드는 해당 사건의 문구에서 셀 수 있다. prefix·alias_type·환경 규칙·활성 판은 각각 관측된 필드이며, 작업시간이나 사업자 과금의 추정으로 변환하지 않는다.
- **Q8:** 한 필드를 되묻는 값이 행동을 바꿀 수 있다는 배경 근거다. 예컨대 ‘이 게시처가 Git symlink를 웹 별칭으로 처리하나요?’의 확인된 가능/불가능 값은 기본 alias 유지와 redirect/copy 지정으로 갈린다. 원래 소비 여섯 자리에서 이 필드가 실제 필수인지 확인한 후에만 카드에 쓴다.

## 읽기·재요청 원장 한계

attempts.jsonl은 확인 가능한 시도 21행이다. 검색 2행은 도구 배치 단위이며 개별 네트워크 요청 수와 같지 않다. web 원문 8회(접근 실패 3회 포함), 확인된 REST 본문/댓글 10회(댓글403 3회 포함), 현재 파일 GET 1회가 기록돼 있다. 검색 스니펫이나 실패를 원문 수에 넣지 않았다. 도중 API 검색의 정확한 입력·횟수는 보존되지 않았으므로 전체 네트워크 요청 수는 산출 불가다. 이미 읽은 페이지에 대한 외부 재요청과 메모리 내 재독을 구분하며, 알려진 외부 재요청에는 표시했다. 모든 조회가 사전 A/B 판독 뒤에 수행되어 그 두 번의 예산에 산입하지 않는다.

web 배치 시각은 직전 UTC 시계이고 각 응답의 정확한 완료 시각은 없다. REST 본문 시각은 작업자 시작 시각이며 댓글 개별 시각은 해당 배치 구간으로만 남았다. 이슈는 수정 가능한 자료이므로 날짜·댓글 ID·읽은 절을 남겼고, 원문 장문 복사 대신 요약을 기록했다.

## 남은 공석과 최소 확인

1. **양쪽 성공인데 옛 URL 실패:** mike188 원 저장소가 비공개다. 공개 사례를 추가로 찾을 때 입력은 고정 generator 버전·태그·원 URL과 두 런 ID, 관측은 빌드 산출물·게시 성공·같은 시점 옛 URL의 실제 응답이어야 한다. 이 네 사건만으로 강한 반례 충족을 선언하지 않는다.
2. **역사 복구의 정확한 경로:** RTD12181의 수정 커밋·배포 런을 찾으면 루트 활성 판 설정과 robots.txt가 같은 배포에서 연결됐는지 판정을 높일 수 있다. 현재 HTTP200만으로는 그 경로를 선택할 수 없다.
3. **현재 태그 게시 안내:** deploy-pages76은 역사 사건이다. 여섯 사례에서 태그 배포를 추천해야 할 때에는 해당 판의 공식 환경 규칙·권한 문서와 실제 workflow를 함께 읽어 현재 허용 조건을 판정한다.
