## 판을 구별할 때 주소와 DOI만으로 부족했던 이유

### 정정 전후 파일의 DOI·최초 날짜가 같다

PLOS의 두 보존 PDF는 각각 원판·정정판으로 표시되어 있다. 두 파일 본문은 같은 원논문 DOI 0301852와 2024-04-16 최초 발행일을 유지한다. 그러나 PDF SHA-256과 추출문 SHA-256은 모두 다르다. 정정 공지는 어떤 파일이 원판인지, 어떤 파일이 재발행판인지 명시한다. 이 관측은 **판 식별을 DOI 문자열과 최초 날짜만으로 끝낼 수 없다**는 직접 반례다. `pdf-receipts.jsonl`, PUB07–10.

기계적 텍스트 비교에서는 66개의 변경 구간이 있었다. 줄바꿈과 추출 순서도 포함되므로 이를 66개 수식 오류나 66개 실질 정정으로 세지 않는다. 판을 구별할 증거가 필요하다는 판단에는 PDF·텍스트가 다르다는 관측과 출판사의 원판/정정판 라벨이면 충분하다.

### 영구 식별자는 남아도 원문을 공개하지 않을 수 있다

[Zenodo 22705920](https://doi.org/10.5281/zenodo.22705920)는 DOI를 실제로 열어도 HTTP 410과 철회 tombstone을 반환한다. 인용과 식별자, 2026-09-19 철회일은 남아 있으나 원파일은 제공되지 않는다. API와 DOI 경로는 같은 사건의 두 표현이다. 이는 식별자의 지속성과 옛 내용의 공개 열람이 다른 조건이라는 반례이며, 의도된 철회를 서비스 장애로 바꾸어 해석하지 않는다. PUB17/19.

[17295496 원기록](https://zenodo.org/api/records/17295496)은 별도로 저장소 범위 밖 사유의 2026-07-15 제거를 표시했다. 이 역시 파일을 제공하지 않지만, 일반 철회와 다른 정책 사유이므로 동일한 서비스 동작이라고 합치지 않는다. PUB18.

### 주소가 달라도 같은 판일 수 있다

`https://doi.org/10.5281/zenodo.2893252`와 `https://zenodo.org/record/2893252`를 실제 요청하니 모두 `https://zenodo.org/records/2893252`로 갔고 v3.1.0 HTML의 SHA-256도 `e141b79c067b8607f8c12a51dce4478cff930b3907d75fcda4b766a180a98272`로 같았다. 두 주소를 두 판이나 두 출판 계보로 세면 안 된다. 이는 한 시각의 동일 응답 관측이며 계속 동일할 것이라는 보증은 아니다. PUB15/16.

## 공식 계약과 실제 사건을 함께 읽은 결과

| 공식 정책 | 실제 사건의 대조 | 웹 문서 사이트로 옮길 수 있는 질문 | 옮기면 안 되는 결론 |
| --- | --- | --- | --- |
| Zenodo version/concept DOI 분리 | matplotlib 두 역사판은 각자 DOI·파일 지문이 있고 concept는 현재 최신판으로 감 | 이 링크는 특정 판인가, 판이 바뀌는 진입점인가? | DOI를 쓰면 웹 딥링크·라우팅·HTML 콘텐츠도 보존된다고 단정 |
| Zenodo 철회와 tombstone | 22705920은 식별자를 남기고 파일 공개를 철회 | 남아야 하는 것은 식별·인용인가, 실제 내용인가? | 응답 URL이나 ID가 살아 있으면 원문 열람 성공이라고 판정 |
| PLOS 정정·드문 원 온라인판 교체 | 0301852/0316774에서는 실제 구판과 정정판 PDF를 모두 열 수 있음 | 수정 후에도 무엇을 어떤 별도 위치에서 다시 읽을 수 있는가? | 모든 PLOS 정정이나 모든 웹 호스트가 구판 전체를 남긴다고 단정 |
| Crossmark 수정 정책 공개 | 정책은 원판을 교체하는지·남기는지 밝히도록 권함 | 누가 수정·철회·보존 결정을 맡는가? | 변경 상태 알림을 아카이빙 또는 파일 전송 성공으로 대체 |

Zenodo의 현재 [파일 수정 정책](https://help.zenodo.org/docs/deposit/manage-files/)은 한 가지 더 제한한다. 발행 후 30일 안의 경미한 수정과 최초 발행 후 45일 안의 재게시를 허용하면서 DOI는 바뀌지 않는다고 설명한다. 이는 일반적인 version DOI 설명의 범위를 좁히는 명시적 예외다. 조사한 matplotlib 판에 이 수정이 일어났다는 증거는 없으며, 그 사건을 꾸며내지 않았다. PUB01/03/04.

같은 출판사의 사건도 보존 근거가 같지 않았다. [PLOS 정정 0315776](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0315776)은 2024-11-22 이해상충 문구 수정 재발행을 알리지만 그 공지에서 원판·정정판 PDF 한 쌍을 제공하지 않는다. 이것은 공지 내 링크 부재의 관측이며, 구판이 어디에도 없다는 증거는 아니다. PUB20.

## Q7에서 전달할 최소 정보

웹 배포 판단에 옮길 수 있는 것은 특정 제품의 승인이 아니라 판독 순서다. 독자가 보존할 내용을 먼저 정한 뒤, **판 식별자 → 최종으로 해석된 URL → 그 판의 실제 산출물 → 수정/철회 관계 → 현재 공개 접근**을 각기 확인한다. 고정판 요구가 있으면 태그만 보지 말고 source SHA와 산출물 지문·게시 사건을 연결한다. latest가 목적이라면 갱신 진입점 자체가 올바를 수 있다. 별도 요구가 관측되지 않은 프로젝트에 구판 보존을 임의로 추가하지 않는다.

이 자료만으로 Read the Docs, GitHub Pages, pkgdown 등 여섯 모집 사례의 A/B를 승인하지 않는다. 실제 소비 프로젝트의 경로·권한·출력 디렉터리·게시 이력이 그 판단의 근거여야 한다.

## 열람·지문·접근 한계

- `sources.jsonl`: 원문 내용, 절·판, UTC, 주장, 반증/지지, 한계와 계보. PUB11의 첫 성공 시각만 두 도구 시계 사이 구간으로 기록했다.
- `attempts.jsonl`: 검색과 실패, 이미 열린 페이지, 외부 재요청을 구분한 58행. 웹 도구의 PDF 리다이렉트 접근 실패 후 공개 publisher URL을 HTTP로 읽었다. 임시 서명 URL은 보존하지 않았다.
- `receipts.jsonl`: 현재 HTTP 응답 지문·상태, 공식 API의 필요한 메타데이터만 보존했다. 장문 본문 복제는 하지 않았다.
- `pdf-receipts.jsonl`과 `pdf-comparison.json`: 실제 구판·정정판 PDF, 텍스트 추출 종료값과 지문. PDF 전체 파일은 저장하지 않았다.
- `events.jsonl`: 6개의 실제 사건을 정책과 분리했다. 부모의 `deployments.jsonl`에 필요한 경우 이 행을 연결하면 된다.

eLife 원논문 25157의 challenge와 PLOS 원논문의 HTTP 502는 이 환경의 접근 결과다. 내용 소실·역사판 폐기·출판 실패로 세지 않았다. 현재 공식 정책은 당시 계약을 자동 증명하지 않으므로 출판 날짜와 열람 날짜를 분리했다.

## 남은 확인

1. **역사적 바이트 보존**: matplotlib v3.1.0/v3.2.0 ZIP을 실제 다운로드하고, 당시 릴리스 자산·서명 또는 독립 시점별 지문과 비교한다. 입력은 두 레코드의 파일 URL과 당시 태그 SHA, 관측은 ZIP 지문과 파일 트리다. 지금은 현재 원장 메타데이터 수준이다.
2. **현재 접근과 전체 구판**: eLife 25157의 공식 아카이브·버전 기록과 84187의 그림 파일을 합법적인 공개 경로에서 다시 연다. 입력은 두 DOI이며 관측은 원문 전체와 원그림의 실제 가용성이다. challenge만으로는 판단을 바꾸지 않는다.
3. **같은 DOI 수정의 실제 이력**: Zenodo의 30일 수정 규칙을 적용한 공개 사건에서 전후 지문과 발행 기록을 구한다. 입력은 동일 DOI의 날짜별 파일 지문, 관측은 수정 권한·게시 사건·내용 변화다. 정책상 가능성과 실제 조사한 matplotlib 사건을 분리한다.
