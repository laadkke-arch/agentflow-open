## 질문과 범위

관리형 서비스의 시작 링크 하나(A), 또는 생성기와 게시처 두 링크 및 교환 산출물(B)이 실제 유지관리자의 공개 문서 요구를 얼마나 뒷받침하는가를 판독한다. 원 프로젝트 채택, 연구자가 제안한 대안, 독자에게 같은 판을 제공한 공개 관측을 별도로 센다. 현재 HTML은 과거 배포 증명이 아니고, CI YAML은 실행 성공이 아니다. 설치·배포·유료 API·계정/중앙 원장 변경은 하지 않는다.

## 모집틀 동결 — 결과를 보기 전

1. GitHub orgs/pypa/repos 및 orgs/r-lib/repos의 공개 전체 목록을 pagination 끝까지 취득한다. public/non-fork를 남기고 `casefold(name), name`의 사전순으로 정렬해 원순번을 붙인다. API 원순서는 정렬 기준으로 쓰지 않는다. 전체 목록·언어·archived·생성/수정시각과 취득 지문을 evidence/*-frame.json에, 모든 행을 FRAME.csv에 보존한다.
2. 이 현재 조직 소속을 2024–2025년 조직 소속으로 소급하지 않는다. 기간은 UTC `[2024-01-01, 2026-01-01)`. 정식 배포는 GitHub release의 draft=false/prerelease=false와 published_at, 또는 GitHub 정식 릴리스가 없으면 유지관리자의 NEWS/배포 기록에 날짜가 명시된 정식 tag로 확인한다. prerelease 이름(a/b/rc/dev/pre 등)은 배제한다. 태그 이름만 있고 정식 배포 날짜 근거가 없으면 미확인이다.
3. 사전순으로 기간 내 정식 배포가 있는 후보를 최대 15개까지 검사한다. 기간 내 정식 배포가 없는 행은 모집틀에는 유지하되 15개 적격 후보 한도에는 넣지 않는다. 적격 후보 중 기간 마지막 정식 tag에 (a) 독자용 문서 원본(README만이 아니라 docs, vignette, man 등)과 (b) 외부 독자를 위한 게시 안내 또는 문서 사이트 링크가 함께 있는 첫 3개를 선정한다. README의 일반 저장소 링크/버그트래커만으로 (b)를 만족시키지 않는다.
4. 세 자리가 선정되면 뒤 후보는 `not_screened_after_third`로 남긴다. 15개를 채우기 위한 불필요한 후순위 열람을 하지 않는다. 모든 원순번·제외·접근 실패를 유지하며, 요구가 둘 미만이거나 배포 근거가 빈 자리도 교체하지 않는다.
5. 선정은 docs 경로와 사이트 링크 존재 확인까지만 한다. 서비스를 기준으로 선택하거나 배포 성공/요구 자료량을 보고 선정하지 않는다. tag README와 tree에 노출된 CI 배지 등은 사전 노출로 기록한다.

## 비교안과 동일 읽기 예산

- 공통 요청: 선정 tag의 해당 문서 사이트를 외부 독자에게 게시하고 유지관리자가 명시한 결과를 보존한다. 두 번째 독립 조건은 실제 발화에서만 추가한다. URL 하나를 임의로 콘텐츠/URL 두 조건으로 분할하지 않는다.
- A: Python 문서는 Read the Docs의 기존 프로젝트 시작 안내 한 링크; R 문서는 GitHub Pages의 게시 원본 설정 안내 한 링크. 이 선택은 현재 프로젝트 채택을 확인하기 전에 생태계별 대안으로 고정한다. 서비스 하나가 내부 generator를 실행할 수 있다.
- B: Python은 Sphinx 생성기 + GitHub Pages 게시 문서; R은 pkgdown 생성/배포 API + GitHub Pages 게시 문서. 생성물 HTML 트리 및 게시 루트/branch/artifact의 교환 조건을 전달한다. 선정 문서 원본이 generator와 맞지 않으면 부적합 또는 별도 대안으로 표시하고 사전 B를 바꾸지 않는다.
- A/B의 정확한 첫 링크, 선택된 tag, 실제 조건, 초기 권고는 묶음 2에서 동결한다. 그 뒤 안내 원문을 읽는다. A는 시작 문서와 거기서 다음으로 선택한 공식 문서/절까지 2회, B는 두 링크의 관련 공식 절 각 1회, 총 2회 이하다. 읽은 페이지/절과 해당 요건의 지지·반증·누락을 paths.csv에 남긴다.
- 논리 열람(exposure), 고유 URL, 외부 HTTP 요청, 캐시/이미 열린 페이지 재사용을 따로 센다. 동일 URL의 두 다른 절을 읽으면 exposure 2이지만 HTTP 1일 수 있다. 다른 자리에서 이미 읽은 원문은 reuse=true이며 새 외부 요청 0이다. 검색 스니펫·접근 실패는 성공 열람에 넣지 않는다.
- 동일 조사자의 판독이다. 무작위·눈가림·실사용자 성능시험으로 주장하지 않는다. A를 읽고 B를 읽는 순서 고정과 선행 노출의 영향을 한계로 남긴다. 사후 확인에서 알게 된 원 프로젝트 채택을 사전 예측 점수로 소급하지 않는다.
- 2회 예산 판독을 모두 저장한 뒤 태그 CI/설정, 공식 역사판, 공개 빌드/배포 로그, 현재 HTML/아카이브, 독립 사건과 정책을 제한 없이 검증한다. 이 단계는 사후 사실검증이며 A/B 열람 예산에 섞지 않는다.

## 증거와 분모

소비자 6자리(계보 목표 6), 직접 연 원저작/독립 사건 최소 22, 실패 또는 변경 없이 보존된 독립 사건 4 이상, 다른 분야 공개 원기록 4 이상이 기준이다. 같은 이슈와 PR·회귀시험·번역·미러·반복 열람은 한 계보로 센다. 접근 실패와 검색 스니펫은 attempts에만 남긴다. 관측 사실, 코드/설정 의도, 공급자 계약, 연구자 추론을 표시한다.

필수 분모: ① 선정/6 및 조건 2개 확인/6, ② 실제 소유자 선택 관측/6, ③ A/B 각각 기술적 가능성·부적합·미확인/6, ④ 같은 역사적 배포에서 두 조건을 함께 관측/조건2개 확인 자리, ⑤ 현재 독자가 요청한 판을 열 수 있음/6. 0/0은 산출 불가다. A/B 승률을 원 프로젝트 선택과 합치지 않는다. 2024–2025 당시 공급자 계약과 현재 문서의 차이는 미확인으로 남긴다.

단계 수는 사용자 설정 블록(저장소/연결, 빌드환경, generator 명령/입출력, 게시 target/권한, URL/판 routing, 승인 등)으로 정의하고 항목을 열거한다. 실제 공급자는 SaaS/호스팅 조직, OSS generator는 별도 구현 수로 기록한다. 시간·요금·권한이 관측되지 않으면 추정하지 않는다.
