# AF-RES-192 판단

**자체 PARTIAL** (정확판 DOI/개념 DOI 실물 미확인). 네 판, 지정 인용 저작, 개별 배포 파일 레코드는 모두 확인. 핵심 역할 분리 사례와 단일 링크 대조는 성립한다. 36개 고유 직접 자료(내용이 다른 판 파일 포함), 32개 work_id, 50개 원장 행; 판별 자료 수와 저작 수를 혼동하지 않는다. 정확한 외부 UTC 조회 시각/전체 태그 SHA/역사적 archive metadata는 일부 미확인이다. 출처 원장에는 실패도 남겼다.

## Q1. 저자 지정
CFF에서 preferred-citation은 소프트웨어 본체와 다른 인용 저작일 수 있다(R01/R02). seaborn 네 파일 관측 중 CFF 2/2와 README 2/2 동일 blob(각각 하나로 셈). 최상위 author/title/type/version/DOI 미기재; schema에서 type 기본 software와 title 필수라는 규칙은 관측 원값을 채우는 허가가 아니다. 메시지는 과학 논문에 핵심적으로 쓰였을 때의 권고. preferred type article, title, DOI와 발행연도 일치; issue 6/volume 60은 JOSS 실제 volume 6/issue 60 및 T09와 충돌. 출판사 값을 우선하되 수정 이력 보존. MAPIE top title/version 명시, type/doi 없음, date-released 2019-04-30 두 판 동일; preferred conference-paper 제목·6인 저자·year2023·pp549–581, DOI 없음. old-citation은 preferred가 아니다. README는 Taquet 2022 workshop도 소개한다. 인용 형식 자동 변환이나 과거 GitHub Cite 버튼의 렌더링은 관측하지 않았다.

## Q2. 실제 도착 객체
JOSS DOI는 논문, archive DOI는 software, PyPI record는 판별 distribution 목록. A01(software 10.5281/zenodo.4645478)은 논문과 같은 표제이나 Notes v0.11.1·별개 zip 1.8MB·MD5 명시; A02 v0.13.0 zip 2.0MB·별개 DOI. A01/A02 relation label은 Is supplement to, 방향 archive→GitHub branch/tag; 이를 article DOI로 바꿔서는 안 된다. A01 JOSS→archive 링크 자체를 논문과 archive의 연결 근거로 별도 기록. MAPIE DOI 10.48550/arXiv.2207.12274의 실제 redirect는 2022-07-25 arXiv v1, preferred PMLR 2023과 별개. PMLR 논문의 제목/저자/페이지 조인으로 식별(논문 DOI 자체는 미확인). P02 PDF 내부 1–33 vs proceedings 549–581은 서로 다른 pagination.
D01–D04 네 판 sdist/wheel 8개 이름·SHA256(64자)을 읽었으며 실제 파일 다운로드·해시 계산은 하지 않았다. M1 PyPI provenance가 release commit d4020d46d60a34ad17148cf3c8e20d34e277153e를 표시하나 independent signature check 아님. R04는 concept DOI가 최신 판으로 이동한다는 정책; 2026-11-24 UTC 조회에서 actual conceptrecid/relatedIdentifiers와 이동 대상 미확인(F02–F06); 정확판 DOI 0/4 확인(실제 0개 존재라는 주장 아님). 따라서 A01/A02를 S1/S2에 대체 연결 금지. 논문 DOI의 리졸버와 같은 랜딩은 한 저작으로 집계.

## Q3. 기능과 방법
Seaborn의 JOSS Figure1(p2)은 relplot 및 hue/style/col 의미를 설명하고, 예제 버전은 0.11.1. T14/T15 두 태그 relplot의 실제 x,y,hue,style,col 인자 확인. 이것은 시각화 라이브러리 설계·사용 원리이지 KDE 수학 최초 발표라는 뜻이 아니다. T11 KDE class 및 EstimateAggregator, T12 barplot weights 확인. 후속 v0.13.1 weighted estimation은 2021 논문이 해당 판 기능을 보증하지 않는 반례.
MAPIE는 P02 library paper가 CP 통합 및 p-normalized residual contribution을 설명; P03 2022 workshop은 이전 소개, P04 Romano/Sesia/Candès 2020은 별도 adaptive classification method. P04 Algorithm2 ↔ T10/T13 CrossConformalClassifier.predict_set lines477–522, 특히 508–514의 crossval 조건이 정확한 연결. 기본 mean을 Algorithm2로 설명하면 오답. P04 가정/coverage bound를 분리; 정확한 조건부 coverage 보장이나 라이브러리 결과의 수학적 동등성을 주장하지 않음. API 코드 관측이며 실행이 아님.

## Q4. 판 변화
S1/S2 CFF·README 동일 blob(권호 불일치도 그대로), G01 release notes 및 D01/D02 다른 파일 기록은 실제 판 변화. M1/M2 CFF version 변경, date-released 및 선호/old 동일, README banner 1.0.0→1; 기능판은 G02 binary risk→multiple risk/parameters 및 기타 fixes로 별도. README를 모두 동일 텍스트로 간주하지 않는다. G01/G02 release display 시각과 PyPI 날짜는 일치, timezone/초는 미확인. A01 archive modification date는 publication event와 별개, 현재 레코드를 과거 당시 metadata로 소급하지 않는다. Zenodo version/metadata 규칙을 적용하되 과거 snapshot 및 개념 DOI 실제 이동은 미확인.

## Q5. 반환 목적·클릭
routes.csv에 4판×4목적=16행. 탐색기에서 primary URL까지 1 사용자 클릭, PyPI 목록에서 선택 파일 +1; DOI redirect는 사용자 추가 클릭이 아니다. P01/P02 landing에서 PDF +1, P04 직접 PDF는 1. 실제 사용자 동선·로그가 아니라 페이지의 관측 링크로 계산. 파일 요청이면 PyPI 판 페이지 또는 source tree; 원리 요청이면 그 원전과 적용 함수/조건; 저자의 선호대로 인용이면 논문(PMLR에 DOI가 없다고 arXiv를 승격하지 않음); 재사용이면 고정 package record. 사용자의 질문이 단일이면 두 링크가 항상 필요한 것은 아님. 개발자/저자/연구자/편집자는 각기 목적을 다르게 명시할 수 있다. 두 목적을 동시에 묻거나 하나로 모호하면 역할 표시 두 링크와 보류 이유를 반환. 일반판 개념 DOI가 충분하다는 것은 규칙 차원의 가능성으로만 기록.

## Q7. 보류·병합 규칙
1. 최소 식별자는 객체 역할(논문/방법/소프트웨어/판/파일), 원문 ID, 판, 발행자, 관계 방향, 확인 시점, 증거 출처. 같은 DOI 리졸버/랜딩·동일 CFF blob은 중복 자료로 유지하지 않되 판별 관측은 보존. 동일 저장소/제목/저자/논문 DOI만으로 software release 병합 금지.
2. 우선순위는 목적에 조건부. 정확판 필요 시 DOI 없으면 판 PyPI·태그를 반환하고 archive 미확인 표시. preferred 없는 판은 이번 표본에 없음: 규칙 후보로만, 공식 권고 확인 시에만 preferred 라벨; 자체 추론은 별도 제안. 논문과 software DOI 모두 있는 실례는 A01 및 P01 링크(같은 CFF 안에 두 DOI는 본 표본에서 관측 안 됨, R02 규칙 예만 있음). DOI-only search에서 preferred 없는 DOI 필드를 실패로 처리하면 MAPIE 오답. 
3. 관계를 검증하지 못하면 같은 카드에 별도 링크를 역할명으로 묶을 수 있으나 sameAs를 생성하지 않는다. exact판 파일의 SHA256 표시를 실행 성공으로 바꾸지 않는다. concept DOI가 실제 같은 판에 도달하더라도 미래 고정 링크와 동일한 강도의 약속이 아니다.
 
## 경쟁 설명·재사용 비용
- 경쟁 A: 프로젝트 이름 하나에 모든 링크를 단순 dedup. 저장·검색은 저렴하나 네 판의 서로 다른 file/hash 및 MAPIE old/preferred와 논문 원전 관계를 소실. 같은 이름도 객체가 다른 명확한 반례가 있다.
- 경쟁 B: 모든 URL마다 별도 객체. 실패: 같은 CFF blob 두 번, DOI redirect/landing 두 번, 카탈로그 집계/개별 중복으로 불필요한 개수 증가. ID 역할 구분과 자료/관측 분리로 완화.
- 경쟁 C: 모든 요구에 두 링크 이상. 혼합 목적에는 유용하나 인용만 필요한 경우 paper 하나, exact 파일 선택만 필요한 경우 PyPI 하나로 충분. 링크/설명 길이와 사용자 추가 선택 비용 증가; 목적 미확인 시 역할별 후보 제시.
- 관계 정교화는 수동 근거 탐색·버전 갱신 비용을 추가한다. 요구 단일/가벼운 경우 소프트웨어 패키지 URL과 설명 우선, 방법 provenance 요구 시 CFF→출판 record 및 code anchor까지 확인. 비용은 관측 건수(네 판, 16 route, 배포 파일 8개), 추정 시간·비용 없음. 모든 프로젝트의 관행, 영향력 순위, 서비스 순위·DB/API 확정 금지. 
- 더 강한 판 결론에는 공개 Zenodo/DataCite 원 JSON의 concept DOI/relatedIdentifiers, 실제 redirect/date 및 file hash와 tag 연결 확인이 필요. 접근 제한을 우회하지 말고 응답 없으면 보류. 추가 설치·빌드·render·재현 실험 없이 이번 문헌판정을 닫는다.
