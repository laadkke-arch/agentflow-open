# 공개 이슈 모집과 요청 봉인

GitHub 검색에서 프로젝트별 `repo:owner/name is:issue created:2023-01-01..2025-12-31`를 생성 오름차순으로 40개씩 반환받았다. 각 공개 이슈 페이지의 `issueViewerRoute.data.repository.issue`에서 번호·생성 UTC·작성자 게시 본문을 읽었다. [issue-frame.csv](../issue-frame.csv)에는 정렬한 30개 본문과 경계 확인을 위한 뒤 10개 행이 프로젝트별로 있다. 30/31위 동시각은 0개였다. 검색 결과 자체의 생성 시각 필드는 비어 있었고 해당 페이지의 실제 시간으로 대사했다. 30행을 넘는 본문은 판정과 요청 제작에서 제외했다.

판정 규칙의 두 번째 조건은 남겨야 하는 동작이나 요청이 명시한 별도 적용 환경·데이터 상태도 포함한다. 후보를 만든 과정을 재현할 수 있도록 본문의 필수 구절과 브랜드를 제거한 두 표현을 [queries.jsonl](../queries.jsonl)에 남겼다. 대체 예시였던 환경이나 단순 실행 로그만으로 필수조건을 추가하지 않았다. 카드와 목적/판 재정렬 코드의 Git 봉인은 `9a628ee32a20f5e399bc3414804455d4c84b3f8e`이며 공개 이슈 검색 전에 원격에서 확인했다.

현재 서비스의 본문은 답글과 분리된 작성자 게시물이다. 공개 HTML의 `bodyVersion`은 버전 식별값이다. 그 값으로 최초 제출본의 본문인지 판정할 수 없다. REST/GraphQL 및 공개 GH Archive 시간 파일은 이 환경의 네트워크에서 차단됐고 시도한 편집 경로는 404였다. 따라서 여섯 자리 모두 `published_starter_snapshot`이며 생성 순간의 원문과 일치 여부는 미확인이다. GitHub 게시물 자체, 생성 순서, 두 조건의 출처 위치는 확인했다. 앞자리가 사후 편집됐는지에 따라 최초 통과 번호가 달라질 수 있다.

MkDocs #3083의 화면 폭 조건은 제목에 있고 작성자 본문에는 가로 스크롤과 대안 두 개가 있다. #3084의 본문은 실행 파일을 찾지 못한 증상과 작성자가 추가한 자체 해답을 포함한다. #3085의 본문은 생성한 사이트에서 복사 등을 제한하는 두 요소를 직접 기술한다. 공개 페이지 보조 재열람에서 #3085의 후속 댓글 중 해법의 편집 비용에 관한 한 줄이 노출됐다. 구현 방법은 요청이나 판독에 사용하지 않았다. GDAL #7010 재열람은 이후 댓글에 편집 표시가 있다는 메타데이터를 제공했다. 전체 HTML을 전송한 출처에서는 프로그램이 이슈 객체의 본문만 판독 파일에 추출했다.

검색문에는 현재 제품 버전을 임의로 삽입하지 않았다. 이슈 생성 당시 제품 버전은 관측된 사건 배경이고 조회의 평가 범위는 두 고정판이다. SP의 Python 3.8 및 GD의 Windows는 원문에 남은 요청의 기술 조건이다. 동일 원문의 영어·한국어 쌍은 요청 한 건으로 계산한다. 카드 언어는 원문 영어 48, 공개 번역 검색 카드 0이다.
