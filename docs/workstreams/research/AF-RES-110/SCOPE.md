## 카드, 요청, 판독

카드 작성 단계는 이슈 본문 및 순위를 열기 전에 끝낸다. 기능마다 고정 old/current 출처 URL·제목·영어 용도 한 문장·입출력/적용 객체·검증된 제한·판과 정확 위치를 저장한다. 일반 목적과 판 제한은 별도 열이다. 출처 코드나 발행 노트가 별도 파일인 경우 근거 위치에만 둔다. 사이트의 여러 절이나 번역은 자동으로 독립 저작이 되지 않는다. 원본 영어 필드만 A/B/C에 공통 사용하며 공개 번역은 검색 색인에 투입하지 않는다. 검색용 한국어는 동일 영어 요구에서 작성하며 독립 요청으로 합산하지 않는다.

이슈는 `is:issue created:2023-01-01..2025-12-31`의 전체 공개 상태에서 생성 UTC 오름차순, 동시각 번호 오름차순으로 앞 30건을 읽는다. 뒤의 요청을 보더라도 앞의 통과를 바꾸지 않는다. 최초 제출자 본문에서 (1) 구체 동작 (2) 그 동작과 분리해 함께 요구한 유지·출력·환경 조건이 확인될 때만 통과다. 오류 문구나 제목으로 추론한 기대만으로 채우지 않는다. 조건 해석이 필요하면 근거 절과 함께 기록한다. 편집 기록이 있는 경우 최초 본문을 대조하고 못 읽으면 미확인 상태를 유지한다. 댓글은 요청 작성에 사용하지 않는다. 리포트·계정 식별자나 예제의 비필수 경로는 검색문에서 제거하고 대조 가능한 짧은 키워드와 원 게시 위치를 남긴다. 버전과 표준 형식 같은 요청의 기술 조건은 보존한다.

판독 입력은 요청의 동작·조건 두 개, 원 절·판·입출력이다. 각 요청에 여섯 프로젝트의 전체 24자리를 판독한다. 서로 다른 자료의 유사 단어 또는 계보만으로 등치시키지 않는다. 다음 범주와 old/current의 동작·조건 근거를 남긴다.

- direct는 두 조건 모두 해당 판에서 직접 지지한다.
- partial은 하나 또는 구체 조건의 일부만 직접 지지한다.
- old_only는 옛판에서 두 조건을 지지하고 최신판 변경 근거가 있다.
- conflict는 요구 동작·객체·필수 조건의 불일치가 확인됐다.
- unknown은 판·해당 근거·호환을 판정할 수 없다. vacancy는 모집 자리의 결손이다.

한 작업자가 단계를 진행한다. 원장 파일 및 Git 커밋으로 카드·요구·판독을 날짜순 분리하고 판독 때는 검색 출력을 생성하거나 열지 않는다. 독립된 사람/세션의 재판독 여부는 인계에 별도로 남긴다. 동일 작업자의 순위 맹검과 독립 채점자를 구별한다.

## 고정 조회

A는 원형 Catalog.add와 discover에 같은 48판 카드, 원형의 세 operation key에 해당하고 원절이 있는 관계, 검색문을 넣는다. 관계 키의 추출은 원형 `infer_mechanisms`를 그대로 사용한다. 카드를 보기 전에 관계 세 키는 원 경로 원본 보존, 뒷 실패 뒤 성공 항목 유지, 중복 유입 방지로 제한한다. B는 같은 DB 정의·함수에 `words(note)`를 `catalog_term` 집합으로 합친다. 공통 `op_count DESC, word_count DESC, item_id`와 유니온 중복제거를 유지한다. 설명은 원형 함수의 근거 문자열에 의존하지 않고 주소·제목과 메모의 실제 교집합을 각각 계산한다.

C는 B의 12후보에만 적용한다. 카드 목적에는 문서가 지지하는 대상군과 명시적 제한만 기록한다. 원문 언어와 한국어 검색문에서 고정 정규식으로 명시 기술 필드(파일 형식, 외부 실행조건, 정확 버전)를 읽는다. 문서가 특정 대상으로만 동작한다고 밝히고 그와 상호 배타적인 요청 대상이 있을 때, 또는 요청의 명시적 버전과 문서가 명시한 호환 제한이 충돌할 때만 안정적으로 뒤로 보낸다. 무표식·다른 제품의 버전은 `unknown` 표시, 양립 가능성은 `unchecked`다. 문서 무언급은 충돌로 취급하지 않는다. 필드 목록과 코드 지문은 요구 봉인 전에 확정한다. 정답·이슈 답변·수작업 요청별 채점은 C의 입력에 없다.

모든 A/B/C 실행에서 12 조사 슬롯과 3 표시 슬롯을 유지한다. 세 방식의 표시 36×3과 빈 배열을 원장에 둔다. 고유 기능은 버전 없는 slot ID, 페이지는 실제 반환하는 핀된 절 URL이다. 페이지별 적격은 판별된 두 조건을 양립해서 직접 지지하는 정확 판이다. 적격 0인 요청의 recall 분모는 0으로 기록하고 비율은 비운다. 단어 수 동점이라는 사실과 정확한 ID 정렬을 기록하고, 경계에서 역순 ID를 쓰는 민감도도 비교한다. 후보 밖의 적격과 확인되지 않은 반환을 구분한다.

준비 비용은 고유 원문 전송 바이트, 메모 문자/바이트, 편집·근거·관계 건수, SQLite DB/색인 페이지를 기록한다. 반복은 고정 cache/page/journal로 새 DB에서 A→B→C 및 영어→한국어 같은 순서를 쓴다. 별도 보조층에 원형 예산 묶임, 메모 토큰, 자연 표본에 없는 역사 수정과 오추천 반례가 들어갈 수 있다. 기능마다 실제 출시 차이와, 같은 입력에 대한 과거 DB·현재 DB·핀된 인용을 따로 저장한다.
