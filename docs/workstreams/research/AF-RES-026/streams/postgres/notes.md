# P 계열 T0 봉인 대기

## 실제 모집과 읽기

사전 규칙 커밋 `cecbfb981b9a7ccfd59f7bc40a23445a19d020fa` 뒤, 공식 pgsql-general 2022년1월 원장 앞에서부터 첫 8개 root 지원 요청을 읽었다. 2022-01-01부터 01-05 12:10까지 39개 메시지 헤더 중 root 8개를 포함했고 답장 헤더 31개는 제외했다. 본문 적격성으로 탈락한 root는 0개다. VACUUM 오류와 PostGIS 판 차이는 구체 기능의 진단 요청을 허용한다는 사전 규칙에 따라 포함했다. 이것은 전체1월 전수조사가 아니다. 목록에 이후 날짜도 보였으나 첫8개 상한 뒤 본문을 열지 않았다.

`read_roots.py`는 개별 Message-ID URL의 message-content만 출력했다. Whole Thread 링크는 사용하지 않았다. 스크립트는 reply-navigation을 포함하는 HTML을 받을 수 있으나 답장 본문은 그 페이지에 없고, 모델은 답장 제목/발신자/시간 메타데이터만 봤다. 24건 전체 봉인 후 root가 허용하기 전에는 후속을 열지 않는다.

모델은 첫 요청의 전문을 읽었다. 저장은 짧은 한국어 코딩·원문 위치·해시뿐이며 전문을 복제하지 않았다. P02의 최초 글에 이미 연결된 WordPress 경험담 본문도 읽었다. 서명 홈페이지·전화·공개키·LinkedIn 링크는 문제 자료가 아니므로 열지 않았다. P03에 별도 이미지/첨부 링크는 없고 원문 본문에 실행계획이 있었다.

## 판·시간·보존의 한계

원판은 수정 가능한 게시물이 아니라 공식 아카이브의 고유 Message-ID별 전문이다. 후속이 있는 7개는 navigation의 첫 답 시각이 root Date보다 뒤다. P03은 현재 navigation에서 답장이 보이지 않는다. transport Received 헤더는 회수하지 못했다. 공식 raw GET은 같은 HTML로 리다이렉트됐고 인증이나 계정 변경을 하지 않았다. Date는 아카이브 표시 메일시각이며 당시 서버 수신 영수증이라고 쓰지 않는다. 재확인을 더 엄격히 요구하는 판단자는 8개를 RFC822 원문 미확인 하위집합으로 분리할 수 있다.

`input_sha256`는 root normalized body SHA-256과 같은 당시 공급자 파일의 blob SHA/고정 커밋/URL을 정렬 JSON으로 합친 해시다. body 정규화 절차와 HTML SHA는 capture-index에 있다. 응답 URL에는 당시 release tag를 사용하고 sources에는 40자리 커밋을 함께 고정했다. 무버전 root는 OP판을 추정하지 않고 14.1 비교판이라고 표시했다. P02는 실제명시11.11, P04는 dump/target14.1, P06은 명시된 PostGIS3.2의3.2.0을 썼다.

## 사전 반례와 범위

- P01의 Q는 이미 p4와p9–11에 적힌 부모 저장을 다시 묻는다. 원 요청만으로 조회 방향 설명은 충분하다.
- P02의 작성자 진술(select 정상)과 첨부 증거(EXPLAIN 계획)는 같은 것이 아니다. Q를 알아도 복구원인 전체는 판정되지 않는다.
- P03은 첫 진단 명령을 제시하는 데 원격/로컬 ID 원천 질문이 필요하지 않다. 원격 join 설계는 그 변수에 영향을 받는다.
- P04는 원본 재접속 가능 여부가 경로를 바꾸지만 C로 두 조건을 먼저 전달할 수 있다. 실제 사용 효과는 아직 미열람이다.
- P05의 do not want를 금지로 승격하지 않았다. 구문 가능 여부는 조건 질문 없이 설명할 수 있다.
- P06은 동일 입력이라는 답 하나가 와도 실제 값·호출/PROJ판이 없어 두 버전의 차이를 해결하지 못한다.
- P07은 SQL함수 존재 여부와 특정 Oracle 스크립트 이식 가능 여부가 다르다.
- P08은 NUMBER 예시가 있어 숫자를 보존하는 후보는 이미 제시할 수 있다. text변환 허용은 다른 후보를 열지만 최고효율은 사용패턴 없이는 미확인이다.

위 내용은 후속을 보지 않은 자기 코딩이다. 실제 응답/시행/오승인 수가 아니다. 24개 메시지는 모두 가상이고 발송하지 않았다. 최대길이는 259자로300자 상한 이하다. 8 대화+12 공급자 원파일=20개를 최소수 후보로 기록했고 모집원장/비공식 연결경험담은 제외했다. 공급자 문서는 구현 실행증거가 아니다.

## 접근 실패·대체와 재개

web open의 두 월별 원장 URL과 since URL은 DisabledError였다. 같은 공식 HTTPS 주소를 Python urllib로 읽어200을 받았다. search는 원장 위치를 찾는 데만 썼고 검색 노출순을 표집순으로 쓰지 않았다. 그 과정의 out-of-sample 2021말·2023/2024글 일부가 노출됐지만 선정 P01–P08의 후속은 노출되지 않았다. 실제 root 표집에는 공식 월별 원장의 순서만 사용했다.

다음 첫 행동: root가 이 T0 묶음과 전체24건을 원격 봉인하고 SHA를 돌려준 뒤, navigation-metadata의 연결을 이용해 30일 후속을 연다. `initial.jsonl`과`frozen-responses.jsonl`은 이후 수정하지 않고 보정은 별도 파일로 남긴다. 후보/원문을 다시 생성하는 `build_t0.py`를 이후 실행하지 않는다.
