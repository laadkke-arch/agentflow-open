# P03 사후 표적 교차검토

## 1차: 최초 원문만 읽은 결론

실제 운영 쿼리에서 IN/ID 집합을 만드는 테이블이 로컬인지 동일 외부서버인지 첫 글만으로 확정할 수 없다. 예제는 literal SELECT UNION이며 어느 테이블에서도 ID를 읽지 않는다. 실제 select는 따로 있다고 명시되어 있다.

- 최초 열람 UTC: 2026-11-22T05:27:07Z
- 1차 결론 저장 UTC: 2026-11-22T05:28:01.986806+00:00
- 원문: https://www.postgresql.org/message-id/DB9PR07MB7180EDC1ACD3222532399E1CCB499%40DB9PR07MB7180.eurprd07.prod.outlook.com
- 1차 내용 SHA256: `37b9344911f41d5d831a9263d743355753f7f18a49b9c182534fa62460e9f274`
- 이 저장 전 postgres T1 파일과 후속 메시지는 읽지 않았다.

**L19** — tbl_link가 postgres_fdw table이라는 사실은 명시. 필터 대상의 원격성은 확인되지만 ID 생성 테이블의 위치를 말하지 않음.

**L20** — SELECT UNION은 예제이고 실제 select는 다르다고 명시. 실제 select의 FROM/서버/테이블은 생략.

**L26–29, L36–39** — IN 집합은 상수 또는 SELECT 상수 UNION이다. INTO local_1은 결과 저장대상이며 ID 생성 원천의 위치 증거가 아니다.

**L40–51** — 예제 plan에 Foreign Scan과 local Hash/Result/Append가 보이지만 이것만으로 생략된 실제 ID select의 저장위치를 확정할 수 없다.

이 검토는 다른 계열 담당자의 사후 표적검토다. 통합자가 양성 사례라고 알려 준 상태라 결과 존재까지 가린 독립 재현은 아니다. 새 가상 I/C/Q를 쓰거나 후보·변수를 고르지 않는다. 1차 결론을 저장한 뒤 기존 판정과 후속 원문을 열 계획이다.

## 2차: 기존 판정과 후속 원문 대조

첫 postgres 판정 파일 열람은 **2026-11-22 05:28:08 UTC**, 후속 원문 열람은 **05:28:13 UTC**다. 위 1차 메모를 저장한 뒤 열었고 1차 JSON의 SHA256은 그대로다. 읽은 판정은 `streams/postgres/case-analysis.jsonl`의 P03 행이며, 전략을 다시 작성하거나 재채점하지 않았다.

후속 원문: https://www.postgresql.org/message-id/DB9PR07MB718015C40BC021957A7165F5CB4C9%40DB9PR07MB7180.eurprd07.prod.outlook.com

**L23–26**에서 원 작성자는 IN절의 결과를 local table이라고 부르고 자기 사례의 local 쪽이 remote보다 작다고 설명한다. 따라서 “작성자가 추가 대화에서 local이라고 말했다”는 관측에는 동의한다. 제3자의 말만 있는 것이 아니고, 나중에 생긴 DELETE 요구를 이 값 대신 사용한 것도 아니다.

다만 **L28–31**에서 여전히 상수 UNION 예제를 반복한다. 실제 업무용 ID-producing SELECT의 FROM이나 원천 relation/server는 제시하지 않는다. 바로 아래 **L113–114**에 인용된 응답자는 그 예제의 inner subquery가 foreign scan이 아니라 로컬 join이라고 설명했다. 작성자가 이에 동의하며 파생 결과집합을 local이라고 부르는 것인지, 실제 base table의 저장위치를 새로 명시하는 것인지는 완전히 풀리지 않는다.

### 판정 강도에 대한 이견

- **예제의 ID 집합이 평가되는 위치**가 변수라면 첫 글의 Result/Append/Hash 계획이 이미 local 평가를 보여 주므로 새 사실의 양성으로 세기 어렵다.
- **실제 업무용 ID 원천 테이블의 위치**가 변수라면 첫 글에는 미상이다. 후속의 local 설명을 그 원천의 확인으로 읽을 수는 있으나, 파생 결과집합이라는 다른 해석이 남는다.

따라서 **조건부 동의**다. 작성자의 local 추가 설명은 보존하되, 실제 원천 위치가 확정되어 remote-join 후보가 탈락했다는 유일 양성은 해석 전제를 함께 밝혀야 한다. 넓은 자연어 해석에서 1건, 엄격한 실제 원천 위치 확정에서는 0건이라는 민감도를 권고한다. 어떤 성능 개선이나 가상 Q의 인과효과도 확인한 것이 아니다.

판정을 확정하는 최소 추가 자료는 **같은 최초 SELECT INTO의 실제 ID-producing SELECT 및 그 FROM relation/server를 밝힌 작성자의 공개 기록**이다. 다른 연산인 새 DELETE의 로컬 테이블을 옮겨 증명하면 안 된다.

### 검토의 한계

이것은 전역 봉인 이후 다른 계열 담당자가 먼저 원판만 읽은 사후 표적검토다. 통합자가 전체의 유일 양성 사례라고 알려 주었으므로 선정 이유까지 가린 독립 검토는 아니다. 한 사례를 겨냥한 지시 대상의 강도 검토이며 독립 일치율을 산출할 수 없다. 최초판/후속 읽기 순서·UTC·첫 메모 해시는 JSON에 보존했다.
