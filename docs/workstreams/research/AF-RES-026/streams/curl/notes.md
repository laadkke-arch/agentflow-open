# curl T0 판독·봉인 메모

- 프로토콜: `cecbfb981b9a7ccfd59f7bc40a23445a19d020fa`. 최초판8개와 I/C/Q24개를 후속 본문 열람 전에 작성했다. root가 원격 커밋하고 전체24건 봉인을 알릴 때까지 후속 본문은 열지 않는다.
- 실제 모델은 부모와 같은 상속 세션 표기(GPT-6 Astra Pro). 별도 사람 코더·독립 중복 판독이 아니다.
- 원장은2022-01 전체68개메일. root가 아닌 답장56개,릴리스공지/전체roadmap3개를 제외하고8개를 채웠다.8건상한 뒤1월30일 공지1개는 제목만 본 상한후행이다. 각심사는 frame.csv에 보존했다. 날짜목록의68개가68개사건은 아니다.
- 포함8건은1월1일~25일 최초 제출순. Daniel의 JSON/URL문법 제안2개도 단순공지/패치제출이 아니라 구체부분설계 질문이므로 포함했다. 동일 작성자가 유지관리자와 질문자 역할을 함께 가진다는 사실을 기록했다. 부모가 후속 미열람 단계에서 이 범위해석을 확인했다.
- January thread/date 목록과 root 하단에는 답존재·답제목·발신자가 노출된다. 본문이나 수락/결과를 선택에 쓰지 않았다. January 표본해석 확정 전에 February 목록도 열었으나 본문은 안 읽었고 표본을 늘리지 않았다. 후속 제목 노출과 후속 본문 노출은 다르다.
- 각 root HTML에 Message-ID, `sent`, `isosent`, `received`, `isoreceived`가 있다. `isoreceived`는 초단위 UTC와 부합하는 서버 아카이브 값이며 발송Date와 별도 보존했다. 예:C02 Date는05:31:37Z이고 서버아카이브는09:57:02Z라 같은시각으로 쓰지 않았다. Message-ID는 공개아카이브의 `_at_` 표기를 그대로 보존했다.
- 원판 전문은 root body 경계를 직접 읽고 SHA256을 남겼다. 원문메일·본문 전체는 연구파일에 복제하지 않았다. 현재 HTML페이지 전체해시는 메뉴재생성으로 달라질 수 있어 body section해시도 별도 기록했다. 메일원판 보존근거는 공식 개별메일ID·서버시각이며 signed raw MIME까지 확보한 것은 아니다. `.eml`/`.txt`는404,옛월별gz는HTML반환,공식curl-wwwGit경로는404였다.
- C06은 연결wiki가 후속에 바뀔 수 있으므로 현재판을 읽지 않았다. GitHub wiki history에서 revision시각만 추출해13:38:54Z 최초메일보다 앞선13:23:09Z `68fed966...`을 선택한 뒤 그판 전문을 읽었다. 이후수정본문/commitmessage는 보지 않았다. 그판은 `--json` shortcut과 `--jp`구성을 나누며 미출시 브레인스토밍이다. 따라서현재curl `--json`의사양을소급하지 않는다.
- C03만 curl7.55.1이명시됐다. 나머지curl판은미상이며7.80.0/7.81.0은연구자의동시대비교판이다. 메시지의release tag는provider-metadata의정확한commit/blob으로묶었다. OP실제판으로승격하지 않는다.
- `initial_sufficient`는그질문의조건/대상범위를판독할정보가있는지를뜻한다. 모든후보가구현되어있거나문제를해결했다고뜻하지않는다. 예C02는local_ip의범위를분명히말할수있어도실제IP반사서비스검증은없다. 최종전략별승인/보류분모는T1의case-analysis에서별도로분리한다.
- 최초판에서곧바로볼수있는반례:C03은이미바이트전송구간을원한다고적었으므로Q가중복이다.C07도새문법제안이라는점이명시돼Q가중복이다.C04의CR/LF조건은옵션선택을바꿔도추가문자의원인전체를확정하지못한다.C08은후보없음과진단입력부족을그대로보존한다.

## 파일과재생

`build_t0.py`는기록된공개metadata와연구자코딩만읽고네트워크/후속파일을읽지않는다. 원판코딩·메시지는원격봉인후재생성하지않는다. 본메모는사전판독의한계이며독립검증보고가아니다.

```sh
PYTHONDONTWRITEBYTECODE=1 python docs/workstreams/research/AF-RES-026/streams/curl/build_t0.py
```

최종T0파일해시는`t0-receipt.json`. 첫답의정확한시각/응답관계와30일/90일은전체봉인후에만읽어별도기록한다.
