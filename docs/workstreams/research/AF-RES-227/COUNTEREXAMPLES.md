## 추가 통제와 적용 경계

- C1–C4에서 context만 변경한 대조 56개 중 54개가 의미 hunk를 바꿨다. 두 예외는 C1 Breezy의 정·역방향 전체 교체였다. indent만 변경한 Git 대조 48개에서는 차이 0이었다. upstream t4061의 `spaces.txt` 및 `functions.c`는 indent에 따라 실제 다른 기대와 대조하며 suite가 통과했다. C4 결과를 전체 입력 공간에 적용할 수 없다. [표시 원영수증](receipts/controls.jsonl) · [t4061 실행](receipts/public.jsonl#L4)
- W1의 유일 변화 `b `→`b`는 각 Git 정책의 옵션 off에서 exit 1, on에서 exit 0과 빈 stdout이었다. Breezy 정확 비교는 교체를 표시한다. 고정 R1은 공백 변화가 없고 실제로 `b`→`bX`가 남는다. R1의 별도 -U0 구간은 210과 일치하는 A2/B2이며 Git의 section label `a`도 원영수증에 남겼다. [W1](receipts/challenges.jsonl#L1) · [R1 -U0](receipts/challenges.jsonl#L19)
- CE3는 matcher를 생략하면 CPython 기본, 명시하면 Breezy patience다. 동일 렌더러에서도 삽입 구간이 B4–8에서 B7–11로 이동했다. CPython 실행의 `difflib.py` SHA-256은 고정 소스와 동일한 `3eb2d371b4a171b063921de6bbf115108bc39de8bf72866315868ce2599213b7`이었다. C1의 CPython은 A1–3/B2–4를 남겨 Git의 같은 길이와 다른 증인을 선택했다. [C1 CPython](receipts/challenges.jsonl#L8) · [CE3](receipts/challenges.jsonl#L10)
- CE4에서 -U0 두 hunk가 `--inter-hunk-context=1`로 하나가 되었고 보존 (2,2)는 같았다. CE6 `--anchored=A`는 순정 patience의 B,C 보존을 A 보존으로 바꿨다. CE7에서 유일 앵커 patience의 6 indel과 `minimal`의 2 indel을 관측했다. 대조의 단위는 patch 및 줄 편집이다. [CE4](receipts/challenges.jsonl#L13) · [CE6](receipts/challenges.jsonl#L15) · [CE7](receipts/challenges.jsonl#L17)
- Breezy 0.2.13의 -U0 빈 range 헤더는 항상 시작 오프셋+1을 출력한다. Git·CPython 형식은 빈 쪽에 직전 줄 번호를 쓴다. 예를 들어 C2 Breezy의 파일 맨 앞 삽입은 `-1,0`, 그 위치의 Git 빈 range 규칙은 `-0,0`이다. normalize에서 엔진별 빈 쪽 규칙을 반영하고 원본 헤더는 보존했다. 다른 patch 적용기의 수용 여부는 미확인이다. [Breezy -U0](receipts/controls.jsonl#L53) · [Breezy 렌더러](https://github.com/breezy-team/patiencediff/blob/834fad2d280fa0634d00d658c61c15d82031f519/patiencediff/__init__.py#L81-L98) · [CPython range test](https://github.com/python/cpython/blob/2abcf904b8dac8c999d2b3aac76681abb333798a/Lib/test/test_difflib.py#L297-L312)
- 카드 [2,1,3]에서 greedy [1,3]과 고정 DP [2,3]을 직접 확인했다. 논문의 10장 예에서도 첫 증인 1/2가 다르고 길이 5는 같다. Sage fixture의 세 증인은 완전 열거와 일치했다. 외부 DP는 6개 doctest를 통과했고 반복값 [1,1,1]은 nondecreasing 길이 3이라 strict 길이 1과 갈린다.
