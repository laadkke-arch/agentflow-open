# JSON-LD 공식 적합성 입력과 반례

**판정 범위:** 공식 fixture의 입력과 기대 결과를 읽었다. 특정 구현판에서 실제 실행해 통과한 기록은 아니다. 이 자료는 후보 목록/상위 세 자리의 사용자 2동작 창에 역으로 넣지 않는다.

고정 suite SHA: `fd4f7eb41f679fb73a54923143c473c3a1d06093`. manifest 두 개, README, fixture 열 개를 직접 읽었다. 13열람 행이며 **고유 저작 1개**로 집계한다. `sources.jsonl`에 URL·blob·위치·한계를 남겼다.

| 반증 묶음 | 공식 입력과 기대 | 의미 및 한계 |
| --- | --- | --- |
| LD-T01/T02 | expansion n006의 유효한 @nest 객체/배열은 속성을 합친다. en01의 문자열 @nest는 `invalid @nest value` 오류 대상이다. | 같은 기능어라도 자료형/구조 조건을 보존해야 한다. 두 공식 fixture를 읽은 것이 어느 구현의 통과를 뜻하지 않는다. |
| LD-T03 | n007의 @nest 아래 두 객체가 부모 속성 배열로 합쳐지고 결과 blob은 n006과 동일하다. | LD-3에서 @nest로 원래 객체의 a,b,c 조합을 보존한다고 가정하면 안 된다. 사용자 전체 context 및 프레임은 아직 실행하지 않았다. |
| LD-T04/T05 | expand 0002는 term→IRI 정규화, compact 0002는 IRI→context term 축약. compact 기대 결과와 expand 입력은 동일 blob이다. | 두 연산의 방향을 바꾸거나 동의어로 합치는 번역을 거절한다. 전 입력에 대한 byte 역함수 증명은 아니다. |

## 재개 입력

`test-cases.csv`의 정확 URL이 재개 입력이다. 공급자 구현판을 선택한 뒤, 해당 판의 공식 runner에 이 suite SHA의 expansion n006/en01/n007/0002 및 compaction 0002의 input/context/expect를 넣어야 한다. 구현판과 runner가 아직 지정되지 않았으므로 실행명령을 임의로 만들지 않는다. 이 단계는 공식 자료를 읽는 사전 반례 작업이며 구현 실행은 **미실시**다. 이후 구현판/runner를 확인한 담당자가 별도 실행 계획을 고정할 수 있다.

README는 @list를 제외한 배열의 일반 비교 순서를 구분한다. 따라서 n006/n007의 단순 JSON 문자열 순서만 보고 합격/불합격을 정하지 않는다. 이 비교 규칙도 특정 구현의 동작 증거와 구별한다.
