# JSON-LD 모집 및 사전 용어표

## 고정 모집과 표본

2026-11-23 UTC에 Stack Exchange 공개 API의 `json-ld` 현재 태그를 `creation asc`, `pagesize=40`, `fromdate=1609459200`, `todate=1735689599`로 조회했다. 날짜 동률은 question_id 오름차순이다. 응답 40건, `has_more=true`; 기간 전체를 전수 조사했다는 뜻은 아니다. 해당 40건의 개정 이력 87행을 조회하여 모두 revision_number=1 본문을 복원했고 생성 시각도 질문 생성 시각과 일치했다. 답/댓글은 가져오거나 읽지 않았다.

최초 진단 출력의 첫 질문 응답 일부에 score/answer_count가 보였지만 선정에는 사용하지 않았다. 이후에는 이 필드를 제거한 질문/개정 자료만 읽었다. 후속 답/댓글 내용 노출은 없다. 제품/언어 이름은 원 질문에서 보인 그대로 기록했고 목록과 목적지·시험 결과를 읽어 표본을 고르지 않았다.

현재 태그 모집은 과거 태그 전체 모집과 같지 않다. 최초 원 태그와 이후 태그 수정 시각을 `revision-audit.json`에 남겼다. LD-1은 json-ld가 2021-01-05T20:00:15Z에 추가됐고 LD-2는 2021-01-21T20:22:49Z에 추가됐다. LD-2 최초판에는 jsonschema가 있었고 이후 제거됐다. 이 사실을 태그 동의어라고 해석하지 않았다. 사용한 별칭은 없으며 삭제/재태깅으로 현재 목록 밖으로 나간 질문의 과거 모집단 완전성은 미확인이다. 따라서 현재 재탐색 모집에 최초 본문 조건을 적용한 연구다.

선정은 최초 본문에서 입력 데이터를 JSON-LD 내용으로 생성하거나 JSON-LD 내용을 변환/추출하는 목적과 독립 조건 둘을 확인한 첫 네 건이다. 순서는 1,3,5,7이다. 내용 도출을 동반한 HTML/JSP→JSON-LD 생성도 포함한다. 단지 JSON-LD 태그를 DOM에 붙이는 위치/시점이나 검색엔진 노출만을 묻는 질문은 제외한다. r1/r3를 전형적인 JSON-LD API 연산이 아니라는 이유로 제외하지 않았다. r1 C2의 head 목적지는 원문 코드에 있고 끝 문장의 대상 tag 이름은 누락되어 있다. 이 판독 경계는 요구 원장에 명시했다.

다음에 나오는 form 생성(r12), 좌표 변환(r14), URI 축약(r36), 노드 필터(r39)는 더 깔끔한 표준 매핑이 가능해 보여도 네 자리를 대체하지 않았다. 후반 적격성은 별도 상세 판정 실험이 아니라 추가 후보/반례 기록이다.

## 사전 용어 관계

`vocabulary.csv`의 L은 원문 기능구의 case/공백/hyphen만 정규화한다. V는 L을 유지하고 LD-3의 JSON-LD frame에 정의상 연결되는 `framing` 한 용어만 추가한다. 해당 표준 URI는 JSON-LD 1.1 Framing §2.1, §2.1.1이다. 이름 관계의 허용은 그 구현/판에서 조건 둘이 충족된다는 뜻이 아니다.

LD-1의 데이터 생성/DOM 삽입을 expansion/compaction/fromRDF로, LD-2의 AEM 조건부 반복을 framing으로, LD-4의 PHP 추출/출력을 framing/flattening으로 바꾸는 매핑은 보류했다. 표준 변환은 이 동작 전체의 동의어가 아니다. LD-3의 선택 기능을 flattening이나 compaction으로 바꾸는 것도 보류했다. 방향/언어/1.1 문맥과 부정 조건을 유지한다.

이 문서는 목적지/후보 순위 열람 전에 작성했다. 본 하위 작업자는 공식 구현 목록, 구현 README, 유지보수자 문서, 구현 시험 결과를 아직 읽지 않았다. 원 질문의 digitalbazaar/jsonld.js 링크는 제품 노출로만 기록했다. `framing` 제거 및 상위 네 자리 감도는 후속 계산에서 주표와 분리한다.

## 자료 보존과 검토

전체 공개 원문은 열람 뒤 제출용으로 복제하지 않는다. 각 최초 본문 SHA-256, revision GUID, 정확 API 입력, 문서 URL/판, 짧은 발췌/해석과 한계를 보존한다. 프레임/개정판/요구 조건 작성 주체는 같은 연구의 JSON-LD 하위 작업자다. 별도 독립 외부 검토로 표시하지 않는다.
