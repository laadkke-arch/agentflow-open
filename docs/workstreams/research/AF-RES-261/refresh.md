## 4. Refresh and withdrawal rules (product design alternatives)

- Keep provenance tuple: artifact/package identity, exact release/source SHA, target triple/platform, document URL and build ID/flags, public export expression, direct manifest feature request, effective feature graph witness or unknown, runtime/driver and input requirements, last observation date, evidence kind. Never equate docs build and consumer graph. Distinguish display, gate, compile, runtime (4 separate statuses).
- Reopen only affected layers: docs host re-render/build/toolchain→page visibility/badges and build receipt; package release/gating diff→exact export predicate and target; Cargo.toml, Cargo.lock, workspace member/resolver/target/dev/build flags→effective graph; runtime Builder/config/environment/input change→runtime prerequisite. GDAL release/format list/build/plugin change→actual driver inventory. Keep immutable old URLs/history and invalidate the dependent claim, not all links.
- Low-cost design A: pinned docs/source and conditional badge; ask for exact manifest/target only when gate relevant. Fast, but cannot claim local availability. B: consumer-specific graph witness with cargo metadata/tree and optional Codex check receipts, more expensive and strongest for exact build; don't use graph output as runtime proof. C: exact execution receipt only when required; safe fixture/driver test, never operate production service. If receipt absent, retain A/B as condition rather than fabricated certainty.
- Withdraw a positive gate result if exact tag/target expression differs or resolved package is not identical. Withdraw positive runtime promise when driver disabled, file unreadable, non-yielding future, no event, or different OS. For both examples never treat absence of a retrieved response as proof of absence of API.
- Corrections made during investigation: (i) before: docs root/full looked sufficient; after: actual log all-features + unstable flags is broader than full, not evidence of default; (ii) before: minimal feature looked like usable function; after: blocking.rs no-rt stub and builder defaults off show runtime gate; (iii) before: ctrl_c calls looked Linux examples; after: exact target cfg shows both sampled signal calls non-Unix; Linux timeout calls separately confirmed. (iv) before: WASI fix sounded full cross-target support; after: lib.rs global compile_error retained. (v) before: lock might indicate active feature; after: Cargo resolver doc and PR evidence show lock is identity only. Prior scope hypotheses remain; no retrospective rewriting.
