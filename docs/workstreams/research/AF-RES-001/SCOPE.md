# AF-RES-001 — 입력의 원뜻 보존 연구 범위

시작 시점 범위 기록 · 시도 1 · 기준 커밋 `11137686f238b7a7f66e7fdeb72f5f6c49565486`. 시작 상태는 IN_PROGRESS였으며 현재 연구 결과와 상태는 [RESEARCH.md](RESEARCH.md), 최종 저장·검증 범위는 [HANDOFF.md](HANDOFF.md)에서 확인한다.

## 질문과 완료 조건

전체 설계가 있는 입력, 선택한 부분과 목적만 있는 입력, 주변 제약이 부족하거나 상충하는 입력에서 무엇을 받아야 원뜻을 지키며 탐색할 수 있는가? 같은 원래 사례를 **원문 유지 / 가벼운 구조화 / AI 분해 제안**으로 각각 표현하고, 빠진 조건·추가된 추측·잘못 좁힌 목적을 대조한다. 필수 정보와 선택 정보, 추가 질문 조건, 답 없이 탐색할 범위, 추측을 멈출 조건을 근거와 함께 남긴다.

이것은 입력 대안 연구다. 검색 성능·후보 순위·카탈로그 식별 체계·최종 DB/API·AgentFlow 연동 계약은 정하지 않는다. AI 분해안은 연구자가 수작업으로 작성한 비교용 후보이며 새 모델/API 실행 결과로 표현하지 않는다.

## 고정 입력과 권한

- 저장소: [laadkke-arch/agentflow-open](https://github.com/laadkke-arch/agentflow-open).
- 통합 기준: [11137686f238b7a7f66e7fdeb72f5f6c49565486](https://github.com/laadkke-arch/agentflow-open/commit/11137686f238b7a7f66e7fdeb72f5f6c49565486). 작업 브랜치가 없음을 조회한 뒤 최신 `chore/workspace-foundation`에서 생성하고 같은 SHA를 확인했다.
- 출력: `docs/workstreams/research/AF-RES-001/`만. `dot-control.json`·공통 색인·공통 계약·제품 코드·기존 AgentFlow Studio는 편집하지 않는다.
- `depends_on=[]`. 다른 작업 결과를 선행조건으로 사용하지 않는다.
- 필수 문서의 고정 SHA·blob SHA·URL 및 배정 항목은 [INPUT_LOCK.json](INPUT_LOCK.json)에 있다. 브랜치로 먼저 읽은 필수 7개 문서와 고정 SHA의 blob이 모두 같음을 재조회했다.
- 기준 문서의 “미래 연구 미배정” 문구는 배정 전 상태다. 이번 사용자 지시와 AF-RES-001 항목이 이 입력 연구를 명시적으로 허용한다.

## 조사와 검토 방식

1. 외부 실제 자료 최소 20개를 직접 열어 읽는다. 검색 결과·목차·열람 실패는 본문 열람 수에 넣지 않는다. 같은 페이지의 여러 절을 자료 수로 부풀리지 않는다.
2. 구조/인터페이스 문서와 질문/요구공학/타 분야 자료를 독립 조사하고, 주 작성자는 공개 소프트웨어 사례와 같은 입력의 세 표현을 작성한다.
3. 문서 설명(D1), 코드 관찰(D2), 자체 실행(D3), 프로젝트 적용(D4)을 구분한다. 이 연구가 자료의 동작·검색 효과를 실행 검증한 것으로 쓰지 않는다.
4. 원문 URL·버전 또는 확인시점/절·확인한 내용·한계·입력 판단에 주는 함의를 자료별 기록한다. 출처 원문 전체는 복제하지 않는다.
5. 반례를 먼저 정리한 뒤 독립 검토자에게 고정 사례와 핵심 결론을 주어 오류·이견을 남긴다. 내부 별도 에이전트 검토를 독립된 사용자 시험이나 모델 간 블라인드 평가로 부르지 않는다.
6. 완성된 묶음마다 원격 커밋을 만들고 마지막에 HANDOFF.md를 커밋한다. 원격 파일을 다시 읽어 저장 성공을 확인한다.

## 첫 가설과 반증 계획

첫 가설은 “원문을 보존하고 목적·대상 부분·제약만 가볍게 표시하면 충분한 경우가 많다”이다. 이를 확정하지 않는다. 인터페이스 단위 호환성 검토처럼 상세 구조가 꼭 필요한 경우, 목적 자체가 아직 모호해서 구조화가 조기 고정이 되는 경우, 누락 문맥을 계속 요구하면 부분 질문이 불가능해지는 경우를 찾아 대조한다. 원문 보존만으로 해석의 정확성이 보장된다는 가정도 검토 대상이다.
