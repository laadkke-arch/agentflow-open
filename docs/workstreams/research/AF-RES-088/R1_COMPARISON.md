# R1 공개판 비교 봉인

R0 결과를 원격 `42e46d5788278efa8d5b8ab0272ace48830fb477`에서 다시 읽은 뒤 R1을 판독했다. root가 PE2부터 JN1까지 역순으로 본문을 읽고 같은 HTML 표현의 diff를 검사했다. 답·채택·댓글은 아직 열지 않았다. 같은 작업자가 앞판을 기억하므로 순서 변경은 독립 판독이 아니다. 플랫폼 보조자의 별도 검산은 GUID·본문 사슬·모집순서의 메타데이터 감사이며 후보 의미 판독이 아니다.

## 사전 가능성과 실제 관측

계약은 요구 수정·해법명 삽입·조건 삭제로 판정이 달라질 수 있다는 가설을 열어 두었으며 변경 수를 미리 예측하지 않았다. 실제8자리에서는 명시 C1/C2 변화0, 입력 상세 보완1(JN1), 본문 바이트 변화5, 동일본문3이었다. 네 편집층은 모두 요구 문구를 유지한 서식/표현/이미지 표시 수정이었다. 이를 수정의 일반 효과0으로 확대하지 않는다.

32쌍 모두 공개판과 고정 후보를 연결했다. 문서 적합 상태가 확정된 쌍26에서는 상태 변경0/26이다. 6쌍은 필요한 Pandoc 코드/환경을 아직 모르는 조건부 경로이므로 정오 변화율 분모에서 제외한다. 조건부 안내의 라벨은 그대로6/6이며 성공 확인이 된 것은 아니다. 각후보 반환정보를 비교하면 JN1/map 한 쌍에서 추가 요청할 입력이 달라졌다(1/32; 확정 비교군 안1/26). 링크·정오와 다음 질문의 변화를 같은 변수로 합치지 않는다.

JN1 R1의 FULL json은 유효 JSON으로 파싱되고 DailyForecasts가5개다. 원문의 두 경로를 Python으로 투영한 값은 rain `[2,1,7,6,9]`, grass `[12,12,13,29,69]`다. 이 값은 공개 입력의 내용 확인이며 jq 실행 결과나 작성자의 성공 출력이 아니다. 최초판에 없던 전체 입력을 있었다고 소급하지 않는다.

PE1은 A0Wtm.png→yQDJv.jpg→avk9k.png URL변경 뒤 링크→본문 img 표시로 바뀌었다. 텍스트 조건은 같다. 옛 이미지의 셸 GET403과 웹 inaccessible을 기록했다. R1 웹 endpoint는 이미지 항목으로 발견했지만 실제 pixel 대조를 하지 않았으므로 `visual_equivalence=unknown`이다. 텍스트 조건 불변0/8과 모든 시각 정보 불변0/8은 다른 주장이다.

## 반례와 별도 탐색

- JE1은 HTML heading→문단, code fence/들여쓰기가 달라도 Document의 두 속성 요구는 같다. Python에 공백이 중요하므로 일반 공백 무시 검증기는 만들지 않았다. 예제는 실제 실행가능한 전체 프로그램으로 판정하지 않는다.
- JE2는 `_rid`의 따옴표→인라인코드와 문구 정리, jquery 태그 제거다. 안쪽 `_rid` 보존 조건은 양판에 있다.
- PE2는 잘못 렌더링된 code fence가 pre/code로 바뀐다. `code-fold`는 R0부터 등장했으므로 후속 답에 의해 본문에 유입됐다고 세면 틀린다.
- JN2·PN1의 후속 태그 편집을 본문 수정으로 세지 않았고, PN2는 전체 이력1행으로 별도 본문 수정이 없다.

선정 이외60목록에서 작성자 수정에 solution/answer/함수명이 새로 들어온 경로를 기계 검색했다. jq78337654와78366187의 원판·diff, Pandoc78552455·78624199의 추가행을 열었다. 이들은 탐색 대조일 뿐8자리/32쌍을 늘리지 않는다. jq78337654의 select는 이미 R0에 있었고 뒤에 입력·괄호가 바뀌었다. jq78366187은 고정 child ID 조건을 input type 조건으로 일반화하고 원 jq1.5 제약을 유지한다. 이 사례들의 답 시각은 사후 단계에서만 조회한다. 탐색으로 유리한 의미변경 질문을 고정 편집층에 교체하지 않는다.

현재 판정은 텍스트와 고정 문서의 비교다. 엄격 최초게시 바이트, 원 질문자의 성공 실행판, PE1의 옛 이미지, 특정 Pandoc 구현 코드가 관측되지 않은 자리는 계속 미확인이다. 전체 상태는 사후자료·최소량·자가검산 뒤 결정한다.
