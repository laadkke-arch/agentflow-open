## 1. PE1: 산문은 구별하지만 기계 기록은 아직 과도하게 닫혀 있다

R1_COMPARISON.md는 옛 이미지 접근 실패, R1 이미지의 pixel 미검사, visual_equivalence=unknown을 분명히 적었다. PE1의 요구 문장 ‘줄번호를 여백 안으로’와 ‘Pandoc Markdown→PDF’가 그대로라는 진술은 텍스트에 한정하면 타당한 보고다. 이 부분은 적절하다.

그러나 revisions.jsonl의 PE1 semantic_comparison에는 requirement_change=false와 input_information_change=false가 들어 있고, pairs.csv의 PE1 네 행은 counterexample을 raw HTML changed with same requirement라고 쓴다. 이 필드만 재집계하면 변경된 이미지의 의미까지 변하지 않았다고 읽힌다. 수정해야 할 것은 보존된 사전 판정이 아니라 **관측 범위의 기계 표현**이다.

권고 필드:

- text_requirement_change=false
- text_input_information_change=false
- visual_equivalence=unknown
- full_input_information_change=unknown
- comparison_scope=HTML text and referenced-document constraints; changed image assets unavailable
- missing에 A0Wtm.png / yQDJv.jpg / avk9k.png의 비교 결손을 포함
- counterexample은 ‘읽은 텍스트 조건은 유지; 이미지 의미는 미확인’으로 한정

PE1의 --standalone 음성 한 쌍은 읽은 텍스트 목적만으로도 근거를 세울 수 있다. 그림을 못 봤다는 이유로 이미 관측된 모든 텍스트 음성을 무조건 삭제할 필요는 없다. 대신 그 1쌍을 0/26에 포함하는 이유를 ‘번호 배치라는 명시 목적에 대한 standalone 기능 범위 판정’으로 표시하고, 그림까지 포함한 네 후보의 설명·다음 질문이 동일하다는 주장으로 확대하지 않는다.

옛 그림이 다른 번호 자릿수·여백·문서 폭·별도 해결책을 보여 주었다면 반환할 조건 또는 다음 질문은 달라질 수 있다. 따라서 이 정보가 없는데 PE1 네 쌍의 condition_or_next_question_changed=false를 완전한 반환 내용 동등성으로 읽을 수 없다. 좁은 텍스트 코드에 한정했음을 필드에 기록하거나, 전체 반환 비교 필드를 unknown으로 둬야 한다.

PN1/PN2도 이미지 pixel을 검사하지 않았다고 적혀 있다. 같은 HTML/같은 이미지 URL은 같은 시각적 바이트의 독립 증거가 아니다. 다만 이 두 질문은 별도 본문 리비전이 없고 텍스트에 목적·입력이 있으므로, PE1처럼 관측된 URL 교체와는 구별한다. 전체 이미지 동등성 7/8 같은 새 수치를 만들어서는 안 된다.

## 2. ‘미확인’과 ‘조건부’ 반환의 의미를 더 좁혀야 한다

여섯 Pandoc쌍은 assessment=미확인인데 return_status=조건부이다. 현재 이유는 실제 handler·template·writer/engine·출력 대조가 없다는 것이다. 이 ‘조건부’는 **시도할 수 있는 문서상 연결 경로**이며 ‘조건을 충족하면 이 질문이 해결된다는 것이 입증된 조건부 정답’이 아니다. RESULT 표2와 지표에 두 의미를 섞지 않는 정의가 필요하다.

현재 여섯 쌍:

| 쌍 | 아직 없는 최소 근거 |
| --- | --- |
| PN1/lua-filter | 고정 3.1.11 AST, 선 위치·굵기·색을 다루는 handler, 실제 PDF 출력 |
| PN2/lua-filter | HTML reader가 보존한 AST, Math 생성 handler, AsciiDoc stem 출력 |
| PE1/metadata | 실제 highlighting 환경, header-includes 내용, LaTeX/PDF 출력 |
| PE1/template | template 내용, highlighting style·engine, 줄번호/여백 대조 |
| PE1/lua-filter | CodeBlock/RawBlock 처리 내용, 코드·번호 보존, PDF 출력 |
| PE2/lua-filter | 실제 writer, Quarto output Div/AST, handler, 펼침/접힘 출력 |

이 여섯 쌍에서 미확인→미확인 라벨이 유지된 것은 6/6이고, 성공의 정오가 불변이라고 확인된 것은 0건이다. 0/32 정답 변화나 32/32 일치라는 요약은 금지하고 26확정+6미확인을 그대로 보여 주는 현재 방향을 유지해야 한다.

## 3. 후보 하나의 기능과 사용자 코드 허용 범위: 경계 민감도

SCOPE는 후보 하나를 평가하고, 추가 named helper·다른 후보·핵심 외부 변환을 배제했다. 따라서 JE1의 JSONLoader, JE2의 JSONL 순회처럼 풀 밖 해법을 후보 성공으로 채우지 않은 선택은 일관된 연구 질문이다. 이것을 도구 전체가 해결하지 못한다는 주장으로 쓰면 안 된다.

다음 두 경계는 추가 설명이 필요하다.

첫째, JN1/map의 configuration은 .DailyForecasts | map(...)이다. SCOPE의 jq 설명은 인수 안의 필드 접근을 허용한다고 썼지만, 후보 앞에서 대상 배열을 고르는 이 배선의 허용은 명시하지 않았다. 이 접근이 핵심 배열화와 무관한 입력 선택이라고 판단한 이유를 후속 메모에 남겨야 한다. R0 커밋을 소급 수정하거나 새 허용 범위를 처음부터 고정돼 있었다고 쓰지는 말아야 한다.

둘째, Pandoc에서는 PE1의 metadata/header-includes 및 template를 LaTeX 코드를 전달할 경로로 인정하면서, PN1/template와 PE2/template는 wrapper가 내부 행이나 chunk를 식별하지 않는다는 이유로 범위 밖이다. 옵션 자체 기능만 보면 설명 가능하지만 **사용자 템플릿/삽입 코드가 허용되는 정도**에 따라 이 음성은 경계에 민감하다. 서식 재정의·삽입 script 같은 코드를 후보의 일부로 허용할 때도 범위 밖인지, 아니면 임의 후처리이므로 계약 밖인지 명시해야 한다. 이 검토에서는 그러한 코드가 실제로 작동한다고 주장하지 않는다. 원문 매뉴얼 재열람이 실패했으므로 기술적 반증으로 세지도 않는다. 다만 ‘문서에 완성 코드가 없다’와 ‘이 경로로는 원천적으로 할 수 없다’는 서로 다른 판단이다.

추가 실행/문서 확인으로 일부 범위 밖이 미확인으로 이동하면 확정 분모는 26보다 작아질 수 있다. 양판의 동시 재분류로 변화 0이 유지되더라도 **분모와 음성 구성은 달라지므로** 최초 분모를 조용히 덮어쓰지 말고 사후 민감도 분석으로 표기해야 한다.

JN1/map 유일한 긍정도 문서상 배열화 기능의 적합 판정이다. R0 next_minimum_input은 전체 field 존재를 다시 확인하라고 적고 있다. 원문에서 이미 맞는 값을 추출한다고 보고했으므로 전체 JSON이 없어도 map의 관련성을 판정할 수 있다는 논리와, R0의 실제 전체 입력에서 실행 성공까지 확인했다는 주장을 명확히 나눈다. 후자는 없다. Python 투영은 이 간극을 jq 실행 증거로 메우지 않는다.

## 4. 반환 내용 변화의 단위를 고정해야 한다

pairs.csv는 JN1/map 한 쌍에서만 condition_or_next_question_changed=true이고, judgments.csv의 next_minimum_input 실제 차이도 그 한 쌍이다. 이 집계는 재현된다.

반면 judgments.csv의 reason은 모든 R1행에 ‘R1 재판독’ 설명이 덧붙어 문자열로는 32쌍 모두 달라진다. 이는 연구 주석이며 추천의 의미가 32쌍 바뀌었다는 뜻이 아니다. reproduce.md에서 적합 상태·반환 라벨·실제 반환 조건/다음 질문·연구 주석을 구별해야 한다. 현재의 1/32는 ‘원문 변화가 있었던 질문 비율’이나 ‘조건이 바뀐 독립 사용자 비율’이 아니라 **명시적으로 코딩한 next_minimum_input의 후보쌍 비율**이다.

JN1은 하나의 질문이다. 질문 단위로는 자연층 1/4가 입력을 보완했고, 그 영향이 map 다음 질문에 반영됐다. 네 후보쌍을 질문 네 개로 늘리면 안 된다. PE1 전체 이미지 반환 비교가 unknown이라면 1/32는 계획분모상 관측 건수로 남기고 완전 관측 빈도처럼 사용하지 않는다.

## 5. 모집·가림·범위에 관한 감사 의견

현재 태그로 모집한 첫 30건과 그중 자연층 첫 적격 2개는 무작위 표본이 아니다. 자연층 발생률은 ‘선정된 현재 태그·기간·순서의 4질문’에서만 계산한다. 편집층 4/4 수정은 모집상 선택 조건이며 자연 발생률이 아니다. PE2는 후속에 pandoc 태그가 추가됐다는 기록도 있어, 모집 당시 태그와 개설 당시 태그가 같다는 전제를 붙일 수 없다.

R0 봉인 뒤 R1을 역순으로 읽었다는 것은 순서 오염을 줄이려는 절차이지 기억효과를 제거한 것은 아니다. 이 점을 이미 명시한 것은 적절하다. 단, SCOPE의 ‘보조 조사자는 매뉴얼·플랫폼·타 분야만 읽는다’와 R0_SEAL의 ‘문서 담당 보조자가 jq R0 30건과 16후보를 검토했다’는 문장이 다르다. R0만 읽은 추가 검토는 R1 노출을 뜻하지 않지만, **사전 역할 계약에서의 절차 차이**로 남기는 편이 정확하다. 독립 원문 판독자 수를 늘리는 근거로 사용하지 않는다.

검색기 실행·검색 결과 순위·실제 사용자가 링크를 발견한 시간이 이 파일들에는 없다. 따라서 이 연구가 직접 측정하는 것은 고정 질문 공개판에 대한 고정 기능 절의 문서 적합성이다. ‘처음 정보로 링크를 검색해 찾을 수 있었다’는 검색 행동의 반사실은 직접 측정하지 않았다. 도움·시간 절감 인과효과 역시 미측정이다.
