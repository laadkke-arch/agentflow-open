# AF-RES-088 재개 사후 응답 감사

## 판정

원격 API를 새로 열어 질문8·답11·답리비전13·댓글17을 재확인했다. 같은 필터로 비교한 본문·GUID·작성주체·생성시각·현재채택의 중요한 값은 기존 수집물과 일치했다. 재집계 검사는 **PASS**, 종료값0이다. 사후 원문 해석 두 곳은 아래와 같이 정정해야 한다. 이 재개 검산은 독립 맹검 판독·전체 연구 재현이 아니며 새 원자료 최소량을 늘리지 않는다.

원격 재조회 시각은 `2026-11-23T15:35:02Z–15:37:21Z`; 각 URL·HTTP200·응답 SHA256·페이지 끝은 [remote_attempts.jsonl](remote_attempts.jsonl)에 있다. 모두 has_more=false였다. 첫 반복에서 withbody 필터가 last_body를 생략한 두 행은 원래 필터로 다시 조회하여 일치를 확인했다. 필드 생략을 본문 변경으로 세지 않았다.

## 두 필수 정정

### 1. JE1: 출력은 첫 프로그램과 일치하고 두 대안이 서로 다르다

원문 [답78299501 최초판](https://stackoverflow.com/revisions/78299501/1), GUID `1A2183FA-65F2-4D46-953C-DF98E9A237D4`의 첫째 pre/code와 둘째 pre/code를 별도 읽었다. 첫째의 metadata 표현은 `.value | {…} + {seq_num:(.key+1)}`이므로 key를 원 entry가 아니라 value 객체에서 읽는다. 둘째는 value 변환이 끝난 후 원 entry 문맥에서 `.key+1`을 평가한다.

보존 R0 JSON을 두 원문 식에 넣은 **보조 실행**은 다음과 같다. 실행파일은 기존 `/usr/bin/jq`, 표시판은 `jq-1.7`이며 고정 참조판 `jq-1.7.1` 실행이 아니다. 원 질문자 실행도 아니다. [영수증](JE1_answer_variant_run.json)에 입력 SHA256·argv·UTC·stdout SHA256·종료값을 보존했다.

| 대상 | seq_num 출력 | 종료값 | 게시 출력과의 관계 |
| --- | --- | --- | --- |
| 답의 첫 프로그램 | `[1,1]` | 0 | 게시 출력 `[1,1]`과 일치 |
| 답의 둘째 프로그램 | `[1,2]` | 0 | 게시 출력과 둘째 값이 다름 |

권고 대체문: **“답은 JSON 객체 모양을 시연하지만 실제 Document 속성 주입을 증명하지 않는다. source를 가정했다고 명시한다. 두 제시 프로그램은 seq_num을 서로 다르게 계산하며, 게시된 [1,1]은 첫 프로그램과 일치한다. jq1.7 보조 실행에서 첫 식 [1,1], 둘째 식 [1,2]를 확인했으며, 원 질문자의 JSONLoader 실행은 미확인이다.”**

수정 대상: `author_outcomes.py`의 JE1 agreement → `outcomes.jsonl` → `support/sources_outcomes.jsonl` → `sources.jsonl`, `RESULT.md` 표3의 JE1 세 행·Q6 및 같은 주장이 있는 검산/인계. 고정 R0/R1 64행은 이 정정의 대상이 아니다. 사전 판정 봉인 이후의 응답 해석 정정으로 기록한다.

### 2. PN1: 출력값 문자열과 작동 보고를 나눈다

[답78261053 최초판](https://stackoverflow.com/revisions/78261053/1), GUID `7986F26B-4B07-44F8-B575-C42E578E25B7`, 첫 문단은 “It works, but the results aren't as pleasant”라고 하고 수평선이 행 사이에서 수직 중앙에 오지 않는다고 설명한다. 이 답을 `no textual execution/output report`라고 부르는 것은 과도하다. 그림을 직접 보지 않았어도 **답변자의 서술상 작동·한계 보고**는 있다.

권고 필드/집계:

| 개념 | 대상 답ID | 수 | 증명하지 않는 것 |
| --- | --- | ---: | --- |
| 본문에 구체 출력값 문자열을 제시 | 78266070, 78299501, 78269109 | 3/11 | 작성자의 실제 실행환경, 질문자의 성공 |
| 작동·결과를 서술한 보고(앞의 출력값 보고 포함) | 위3개 + 78261053 | 4/11 | 실행 로그·사용판 검증 |
| 질문자 완전 성공 보고 | 현재 증거 없음 | 0/8 | 실제 실패0 또는 도움이 없다는 의미가 아님 |
| 질문자 성공+정확판 확인 | 현재 증거 없음 | 0/8 | 채택3건을 성공판으로 전환하지 않음 |

`answerer_textual_result_evidence`라는 기존 bool은 두 의미를 섞으므로 `answerer_output_values_in_text`(3개)와 `answerer_reported_result_evidence`(4개)로 분리하거나 기존 필드의 좁은 정의를 명시하고 별도 필드를 추가한다. `answerer_demo_kind`의 PN1 둘째 답은 `verbal operation and layout limitation report; image not inspected`로 고친다. 기존3/11은 **“본문의 구체 출력값 문자열3/11”**로 한정하면 유지할 수 있다. 실제 데모 실행을 했다는 수로 바꾸지 않는다.

## 두 대조사건

- **SC1 60148441:** 재취득 rev5는 rev6의 정확 접두부다. 같은 질문자667049가 rev6에서 while/reverse/join/tostring/-r와 답 귀속문을 덧붙였다. 대응 답60178790 최초판이 삽입보다100,013초 앞선다. rev6의 감사문은 답 사용의 자가보고를 지지하나 정확 URL은2026년 제3자 rev7에서 붙은 것이므로2020년 hyperlink로 소급하지 않는다. 원8자리/32쌍과 분리한다.
- **NR1 78566705:** 재조회에서 답API0·댓글API0, 각 has_more=false이고 전체 보존 질문리비전1개다. 현재 공개 무응답/무편집 대조라는 제한된 주장은 지지된다. 삭제된 응답·외부 해결·편집유예까지 부정하지 않는다. 6대조후보 탐색의첫 후보에 댓글8개가 있었던 반례 기록도 타당하다.

SC1 보고서에는 내용 원자료3행이라고 되어 있으나 통합 집계는 댓글을 중복보조로 제외해2로 세는 것으로 보인다. 집계 담당자에게 확인을 요청했다. 이 차이는 표본/결과효과 분모와 무관하지만 문구·출처원장은 일치시켜야 한다.
