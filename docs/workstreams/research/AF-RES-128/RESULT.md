## Q6. 음성 대조·구간 민감도
- P3 NEG-WRITE: 동일 CSV/동일 문서에 가까운 DictWriter 구간은 출력 필드 순서이지 중복 key 입력 처리와 반대 방향. F+O 3,000자이지만 새 핵심 지지 없음. P3 SENS-HEADER-ONLY는 동일 3.9.12 Lib/csv.py L93–112, 574자; N L93–127 1,070자에서 L119 dict(zip)와 길이 비교가 들어와 중복 축소의 설명이 가능해진다. 앞 574자만 고르면 그 설명은 다시 미확인. 실제 동료가 아닌 동일 작업자의 다른 경계 선택.
- J2 NEG-JSON: JSON roundtrip (1,500자)와 YAML parser는 입력 형식 불일치. fq N은 입력·출력은 일치하지만 도구 조건이 어긋나므로 jq의 내장 지원이라고 반환하면 오확정. 원 작성자가 일반 도구만 유지하려 한다고 응답. yq는 원리 대안이지 jq 교체 보장 아님.
- J1 NEG-DUPLICATE: jq1.6 src/builtin.jq L297–303 reduce 같은 id에 재할당. 서로 다른 두 id 예 성공은 중복 id까지 모든 레코드 보존하는 보장이 아님.
- J3 새 면은 단일 sub의 성공 보고와 global 실패를 동시에 포함. 여러 cd 제거 필요를 명시하여 최초 두 줄에 맞는 처방을 전체 요구 해결로 오인하지 않도록 한다. 124의 jq1.7 기존 실행은 해당 판에서 성공했다는 사후 자료일 뿐 1.6 증거 아님.
- P1 RFC4180 §2 마지막 CRLF 생략 가능; Go NoEOLTest는 reader가 EOL 없는 CSV를 읽을 수 있음을 예로 보이나 CPython writer append가 기존 EOF를 수리하는지 증명하지 않는다. 이미 CRLF 있는 파일에 무조건 prefix newline을 추가하는 것도 반례 조건이다.
- P2 작성자의 SEP 처리 함수에서 firstline.upper().startswith("SEP=")이면 메타데이터로 소비; 정상 첫 필드가 SEP= 형태인 데이터에서는 행 손실 위험, strip은 공백 delimiter 의미를 바꿀 수 있다. Rust has_headers(false), Ruby explicit header 예는 첫 행 보존을 제어하는 비교 설계로만 채택.

## 작은 판단 단위 (편집 대안)
1. 채택 후보: F만으로 지지하는 주장 명시 → 비는 조건 하나를 선택 → 조건과 판·입력·보존·방향이 일치하는 둘째 면. 필수 예외가 없으면 “핵심 보류” 보존.
2. 조건부 조합: 동판 구현+동일 입력의 작성자 보고. 구현은 메커니즘, 보고는 사례, 시험은 예상/실측을 구별. J1/P3 같이 둘 모두 필요한 경우 하나의 둘째 면으로 완전 판정이 불가능하면 더 읽을 자료 요청.
3. 보류: 제목 유사도만으로 시험 추가. J2 JSON/YAML, P3 writer/reader, J3 원판/새판과 예외 차이에서 정확한 조건보다 제목이 가까워도 오확정 유발.
4. 미검증: 자동 N 선택 효과, 원판 실행, 독자 의사결정 변화, 실제 편집 비용. 원문·선택 이유·반대 조건·후속 확인을 함께 반환하는 탐색기 UI를 후보로 남김.
