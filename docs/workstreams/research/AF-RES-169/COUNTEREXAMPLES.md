# 반례 및 수정된 판단 (④)

## 반증 실험: 실행 아님
- H1 “첫 후계/CLDR alias가 옛 지시 대상 전체와 같다”: B05 S008에는 spn이 먼저, S016/IANA S042에는 aqt, spn, S062에는 aqt만. B08 S008에는 ntd가 먼저, S037에는 itd, ntd, S062에는 itd만. 나열 순서가 규격마다 다르다. 후계집합 크기가 2인데 한 값만 같다고 볼 수 없다. 실제 원장 S072: 요청서 발췌는 두 언어가 서로 다르고 한쪽을 대표 언어로 볼 근거가 없다고 주장한다. 공식 전문 미확보이므로 강도는 발췌/하류 근거.
- H2 “지역/likelySubtags면 분할도 자동 선택 가능”: S100에서 aqt·spn 및 enl·enx는 각각 동일 Latn/PY, dwu·dwy는 동일 Latn/AU. 지역만으로는 둘 중 하나를 가르지 못한다. itd/ntd의 default ID/MY는 다르지만 개별 언어의 실제 지역 또는 기록이 주어져야 하며 default는 증명이 아니다. 37/38에는 이 키들의 해당 exact from 없음 (S098, S099).
- H3 “항상 옛 코드로만 검색”: B02, B03 duplicate, PV와 CLDR 일치(S017,S019,S059), Glottolog 발췌(S074,S075)는 같은 언어/중복을 지지. B03에서 최신 표준화 키 하나는 유용하다. 옛 레코드의 날짜와 원래 값은 보존. B01 M은 merge이므로 ‘같은 옛 범위’라고 단정하지 않는다.
- H4 “모든 하류가 같은 규칙”: WALS lng 레코드는 Enxet/enx (S076), CLDR leg→enl(S062). WALS의 과거 leg 값은 미관측이므로 실제 치환을 입증한 것은 아니다. 이름·자료 목적을 비교하면 단일 default만 추천할 때 Enxet을 놓칠 수 있다는 반례. WALS code leg는 다른 이름공간의 Lega/lea(S077)여서 같은 문자열도 같은 지시 대상이 아니다. OpenJDK webrev는 두 Comments 유지(S097); 등록표 복사이지 runtime 관측 아님.
- H5 “deprecated면 개별 자료도 모두 바뀐다”: PHOIBLE 2.0 실제 목록 duj와 DICE PDF DUJ(S078,S080)가 남아 있다. 시점/레코드별 변경 전후를 보지 못했으므로 실제 변경률은 계산하지 않는다. PHOIBLE의 좌표나 DICE의 넓은 지역만으로 분할 후 한 언어로 확정하지 않는다.
