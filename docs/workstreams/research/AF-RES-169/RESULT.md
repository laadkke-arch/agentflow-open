## 조건부 대안과 추가 분석
- 등록기관 관점: 원 지시 범위와 최종 결정의 날짜·후계 집합을 먼저 보존. D는 단일 후계를 우선 검색하되 옛 인용은 바꾸지 않음. M은 범위 확대 가능성을 표시. S는 역참조 및 모든 후보. N은 옛 기록 보존, 후계가 없다는 등록 사실과 도구 부재를 분리. 비폐기 이름 변경은 같은 ID를 사용하되 범위 같음은 별도 확인.
- 하류 라이브러리 관점: API 호환성만 목적이면 특정 버전의 단일 alias를 쓰는 것이 타당할 수 있다. 정규화 결과는 사용자 의도의 추론값이 아니며, 버전·namespace·default 여부를 밝힌다. 옛 태그를 별도 보존하고 기술 표준용 정규화와 언어 선택을 구별한다. 릴리스 자료·공개 테스트 기대값과 실행 확인은 단계가 다르다.
- 자료 독자 관점: 문헌의 옛 원판은 바뀐 URL/후계 표로 덮어쓰지 않는다. 1) 원래 값·판·출전 2) 관계 및 모든 후보와 근거 3) 특정 소비자 매핑 4) 좁힐 추가 맥락을 필요할 때 조합. 후계 이름이 같은 sap도 자동 동일성이 아니다. 같은 문자열 leg도 namespace가 다르면 대상이 다르다.
- 경쟁 설명: “default 한 값이 실용적으로 충분하다”는 좁은 canonicalization 목표·단일 D에는 지지(S019,S059,S120); “모든 자료에 충분하다”는 S072/S076/S078/S100에 의해 약해짐. 동일한 후보 집합은 의미 선택을 정당화하지 못한다. 지역·script가 구분될 때 실제 기록 문맥과 함께 좁힐 가능성은 남긴다. 판정이 반대로 바뀌는 최소 관측은 마지막 표.
- 수치: 127행 열람·실패 원장 중 opened 98, blocked 29, 보수적 산입 31 고유 work IDs(결정 0, IANA 12, CLDR/소비자 13, 옛 태그 2, 전거 2, 지명 2). 7 관측 계보 표기, ICU를 CLDR 파생으로 묶으면 6, IANA/CLDR의 ISO 공유 계보까지 고려하면 ISO 원결정의 독립 증거는 0. 동일 registry·XML·ICU metadata의 여러 판을 각각 하나의 연속 저작으로 더 엄격히 묶으면 22(31−4−4−1); 같은 PR·diff·배포는 동일 관측을 공유한다. 다만 8개 formal decision 하위 하한 0/8로 전체 완료 아님. 자연층의 대표 비율이나 실제 치환률 계산하지 않음. 확인 UTC 일자만 기록.
- 161 중앙 DONE vs 자기 PARTIAL 구별, P910 등은 재조사하지 않음. 이번 자기판정 PARTIAL. 실제 제품 DB·검색엔진·Studio 연동 결정을 하지 않았고 실행/빌드/외부 쓰기 없음. 자기 점검은 독립 검토 아님.
