AC02의 추정형까지 포함하면 이름 조인 0/3과 3/3이다. 자연 AN01의 제안은 공식적인 넓은 양성 근거와 만났으며, 공개 저자 실행의 증거는 없다. [짝 변화와 답 범위](matches.csv) · [전체 계산](evidence/metrics.json) · [공개 보고](gold.jsonl)

별칭을 펼치면 attrs 넓음은 323개 정규 기능에서 381개 표기로, Click 8.0.3은 851에서 889, Click 8.5.1은 877에서 918로 늘어난다. 동일 기능 위치를 각각 세면 3,240, 3,068, 4,426이다. 위치나 동판의 명시 이름을 늘리는 방식은 같은 단위의 존재를 바꾸지 않는다. 다만 문자열 그대로 맞추는 별도 방식에서는 `attr.define.slots`와 `attrs.define.slots`의 표기 선택이 영향을 줄 수 있다. 교정의 실제 소비판에는 두 namespace의 대체 효과가 미확인이다. ## Q7. 설계자가 선택할 확인

- **목록을 넓힐 때.** AN01처럼 상위 필드 링크만 있고 `init=False`와 `default`를 함께 쓴 공식 예가 필요한 경우다. 현재판에서 예제와 생성 선언을 연결해 API 위치를 반환하고 정확한 환경의 채택은 별도 확인한다. [attrs 기능 조합](https://github.com/python-attrs/attrs/blob/7bfc49e9b22d5ba25b6e429524c3d49fee27cb36/docs/examples.md#L76-L87)
- **정확판을 되물을 때.** AC01처럼 보고의 조작이 참조판에 있지만 결과가 갈린 경우다. 사용자가 가진 공개 성공 출력에서 `python -VV`, `importlib.metadata.version("attrs")`, 두 키의 실제 조회 결과가 묶여야 같은 구현을 비교할 수 있다. 이번 참조판으로 성공판을 채우지 않았다. [작성자 보고](https://github.com/python-attrs/attrs/issues/971#issuecomment-1159394251) · [참조판 실행](runs.jsonl)
- **추가 확인을 기다릴 때.** CN02처럼 명시한 소비판에서 완성 콜백은 확인되지만 사용 앱과 실제 zsh의 경고 발신자가 미확인인 경우다. 전체 등록 코드가 포함된 원 zsh 호출에서 표준 오류와 완성 값이 관찰되기 전에는 조용한 실행을 보장하는 링크를 반환하기 어렵다. [원 질문](https://github.com/pallets/click/issues/2176) · [구조 변경 뒤 보고](https://github.com/pallets/click/issues/2176#issuecomment-1030792664)
