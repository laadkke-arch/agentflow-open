## 판, 목록, 기능 단위

- 참조판은 PyPI 공식 Click/attrs 파일 메타데이터에서 stable(PEP 440 사전·개발판 제외), 명시적 yank가 없는 배포 중 파일의 최초 공개시각이 `2026-11-22T00:00:00Z`보다 앞선 버전으로 고른다. 버전별 첫 적격 업로드시각을 비교하고 동률은 PEP 440 버전 내림차순으로 해소한다. 인덱스가 제공하는 현재 yank 표지와 과거 cutoff의 yank 상태 증명 여부를 분리한다. 정식 패키지 버전과 대응 태그 및 peeled commit을 실물로 대조한다.
- 자연 정확판은 작성자가 질문의 자기 실행과 직접 연결한 Click/attrs 단일 정식 배포판이다. 교정 정확판은 작성자가 성공 사용과 직접 연결한 단일 배포판이다. 자연 후속 성공판은 별도 필드에 둔다. 의존 버전, 라이브러리 호환 범위, 브랜치, Python 버전, 작성일과 최신판 추정은 정확판으로 대입하지 않는다. 동일 태그 두 판은 셀을 유지하고 중복 표지를 붙인다.
- 네 셀 순서는 좁음/참조 `NR`, 넓음/참조 `BR`, 좁음/정확 `NE`, 넓음/정확 `BE`다. 태그 루트 `README.{rst,md}`와 `docs/index.{rst,md}`의 발행자 명시 기능 이름 또는 기능으로 해소되는 직행 문서 링크의 목록 문법과 명시 인라인 API 표기를 좁은 범위로 쓴다. 일반 프로젝트 홍보, 설치, 버전 이력, 포괄 목차, 섹션 이름만으로 함수, 옵션의 동작을 추론하지 않는다. 목차가 지칭하는 부모 기능과 다른 하위 기능에 같은 등재를 상속하지 않는다.
- 넓은 범위는 좁은 목록의 합집합이다. Click의 직접 사용/API 문서 경로군은 `docs/{api,options,option-decorators,arguments,parameters,parameter-types,commands,commands-and-groups,advanced,complex,testing,click-concepts,extending-click,quickstart}.{rst,md}`다. attrs는 `docs/api*.{rst,md}`와 `docs/{examples,init,types,extending,glossary,names,overview,how-does-it-work}.{rst,md}`를 포함한다. 두 확장자는 구판과 신판에 동일하게 적용한다. 공식 태그 경로 이름을 확인한 뒤 최초 원 글·답 및 기능 판독 전에 이 고정 경로군에 문서 분할 경로를 명시했다. 배포 모듈은 Click `src/click/**/*.py` 또는 옛 판 루트 `click/**/*.py`, attrs `src/{attr,attrs}/**/*.py` 또는 옛 판 루트 `{attr,attrs}/**/*.py`다. 문서에 명시되거나 공개 namespace가 내보내는 공개 선언·매개변수와 같은 판 `tests/**/*.py` 상류 시험의 사용·기대를 포함한다. changelog, 이슈, PR, 커뮤니티 예시, 비공개 구현 심벌 자체, 생성 HTML, 문서 설정, 테스트 헬퍼 그 자체, 시험 전용 라이브러리 호출은 제외한다.
- Git 트리 UTF-8 경로순으로 지정 경로군 파일을 전수 열고 태그, peeled commit, 파일 경로·해시·바이트, 파서 실패, 부재한 경로, 읽은 선언·심벌 수를 남긴다. 정적 전수 인벤토리와 조건 의미 판독을 구분한다. 파일 파싱이나 기능군 열거가 완전하다는 보장이 없는 셀은 음성 증거에 사용하기 전에 실제로 남은 범위와 해당 결손을 밝히고 `unknown`으로 둔다. 경로 패턴에 파일이 없으면 그 경로의 부재를 표시하고, 태그에서 다른 경로를 읽었다면 따로 표시한다.
- 단위는 `패키지.공개기능` 또는 기능의 독립 동작을 선택하는 명시 매개변수 단위다. 예를 들어 API `click.option`과 그 기본값 선택 `click.option.default`는 다른 기능 단위다. 문서·구현·시험 위치는 단위의 원위치다. 같은 판의 명시 재수출·별칭 선언으로만 합치고, 공개 동작이 같다는 사전 가정 없이 키를 유지한다. 조합은 공식 글의 한 예제나 한 상류 시험의 공동 사용에서 두 개가 짝으로 확인되는 경우만 저장한다. 동일 파일·시험에 같이 나타나는 독립 기능을 자동으로 조합하지 않는다. 셋 이상이 필요한 해결은 별도 범위 밖으로 기록한다.
- 판정은 단순 등재와 공동 지지를 구분한다. `positive`는 목록의 동일 기능/조합이 동일 입력→결과·C1·C2·금지 동작·환경을 뒷받침하는 근거가 있을 때다. `refuted`는 같은 목록에서 관련 후보를 확인했고 요구 중 하나를 깨는 직접 근거가 있으며 공동 양성이 없을 때다. `absent-in-scope`는 완전히 조사한 고정 범위에서 관련 단위의 등재 위치를 찾지 못했을 때다. `unknown`은 결측 판·원판·원자료·관련 범위의 미소진 또는 공동 근거 부족이다. 관련 단위가 등재되어도 적용 환경이 불명확하면 공동 판정은 unknown일 수 있다. 대안과 저자 확인 기능의 사후 조인은 별도 열에 둔다. 등록만으로 공동 분자를 늘리지 않는다.

## 분석과 재실행

- 기본 비교는 `NR`에서 같은 판의 `BR`, 같은 범위의 `NE`, 두 축의 `BE`를 각각 비교한다. 완전관측 분모는 네 셀 모두 unknown 외일 때다. 회복기회 분모는 완전관측이면서 NR이 양성이 아닌 경우다. NR 양성 후 손실, 단일 축 양성인데 BE가 양성이 아닌 경우 등 비단조 패턴을 원래 4값과 함께 유지한다. 기본 유형은 범위만, 판만, 둘 다, 각각으로 회복, 네 셀 동일 양성, 네 셀 비양성 및 그 안 상태 차이, 미판정이다. 범위·판 방향 짝별 분자/비교 가능 분모도 층별로 낸다.
- 실험 셀은 CC01, CC02, AC01, AC02다. 공석과 미확정 소비판을 교체하지 않는다. 정답 공개 뒤 fixture, 양성·경계 기대와 명령을 먼저 커밋한다. 같은 짧은 Python fixture로 각 패키지의 공식 정확 배포와 참조 배포를 격리 설치하고 Click 출력·반환 코드, attrs 결과·예외·원 객체를 비교한다. 저자 보고, 문서, 상류 시험, 연구 재실행을 구분한다. 네 자리의 실행 불능도 보존한다.
- 민감도는 동일/다른/정확 미확인, 저자 성공/제안/미확인, 별칭과 URL 결합/분리 기준을 층별로 기록한다. 원저작 산입은 직접 열어 읽은 공식 원자료/공개 작성 사건 단위로 제한한다. 같은 글의 mirror, 판이 같은 원자료, 같은 사건의 답, 검색 미리보기, 차단 응답을 별도 독립저작으로 세지 않는다. 타 분야 원기록은 별도 표본이다. 비용의 고유 바이트는 조사 파일의 SHA-256으로 합친 원 바이트이며 전송 바이트 및 실행 횟수와 구별한다.
- 작업 순서는 ① 모집·가림·범위 계약 ② 최초 요구·목록·공동 판정과 근거를 원격 커밋 ③ 보고 공개 및 실행 기대 커밋 ④ 실행·빈 폴더 검산·결과 ⑤ 원격 결과/수용 원장 및 실제 세션 체크 후 인계 단독 커밋이다. `fixtures/scoring-cases.json`은 실험 사례를 읽기 전에 고정한 판정 분기 시험 입력이다.
