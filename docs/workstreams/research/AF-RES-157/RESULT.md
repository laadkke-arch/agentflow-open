## Q1 · 원자료의 접근과 판독

Sketchy CSV의 공식 Git 체크아웃과 고정 raw 다운로드에서 전체 바이트를 얻었다. 두 사본 SHA-256은 `aec34f174ac350448b62a2223a859303ae496f99ba526775e027e914a4a1afbc`이며 선행 Git blob과도 일치한다. 저자 README의 Drive는 뷰·다운로드 모두 실패했다. 수집 DB 스키마에는 사용자명과 설문도 있어, 접근이 열리면 받은 자료가 공개 비식별 export인지 먼저 확인해야 한다. [취득 영수증](evidence/ACQUISITION.md)

Apollo는 발행 색인의 ZIP 설명을 확인했다. DOI, item, REST bundle, handle, 레거시 후보에서 ZIP의 실제 바이트를 얻지 못했다. TU Delft의 대체 공개 기록은 ASME 논문 DOI를 연결했고 파일 링크는 표시하지 않았다. VIS는 저자 OSF Wiki 안내, root·node·provider·파일 및 ZIP 요청을 확인했다. 파일 목록 응답은 열리지 않았다. 저자 PDF·슬라이드와 DRUM 학위논문 메타데이터는 연구 절차를 확인하는 대체 경로다. [archive.csv](archive.csv)

두 연구 4쌍씩의 기준을 못 채워 B04→B06→B09를 순서대로 확장했다. B04에서 완료 시각을 수기로 적는 절차를 확인했고, B06의 피츠버그 기관 PDF 경로는 404였다. B09에서는 원문의 중간안과 최종 작성 절차, 자료 손상 수를 확인했다. 원 패킷·봉투·D1/D2 개인 키는 확인된 공개 범위에서 미발견이다. [A21–A23, S34–S38](archive.csv)

## Q2 · 배정, 표시, 열기, 편집 저장

Sketchy의 고정 코드에서 방 유형은 Peek 버튼의 사용 가능 여부를 전한다. 사용자가 요청하면 서버가 `peek`와 상대의 당시 스냅샷을 기록한 뒤 성공 응답을 보낸다. 최초 화면은 클라이언트 콜백에서 그려지며, 수신한 실시간 변화와 창 크기 조절도 다시 그리기를 일으킨다. `peekReview`는 보기를 끝낸 투표, 원 요청 시각 및 그때 상대 그림을 기록한다. 화면의 실제 그리기 완료는 서버 기록과 구별해야 한다. `stats`도 현재 스케치를 DB에 저장하므로 영속 row가 생겼다는 사실만으로 새 편집을 주장할 수 없다. Stroke 끝, undo, redo, clear는 편집의 근거가 되는 별도 경로다. [S07–S13](sources.jsonl)

수집 코드 Date는 JavaScript epoch ms 계열이다. 파일럿의 13자리 숫자를 Unix ms로 읽으면 파일명과 양립하는 2018-12-06·13 UTC가 된다. 실제 export가 개봉 시작, 투표, 별도 변환 중 무엇을 기록하는지와 서버 시간대 교차표는 미확인이다. 같은 repo의 변환 스크립트는 다른 이름과 열의 CSV를 만든다. 파일럿에는 예시 배열과 완료 배열이 있고 `room`·편집 저장 이력·별도 시계가 없다. [구조 진단](evidence/OBSERVATION.md)

VIS의 썸네일·hover, 확대 링크, 북마크, 별도 Jamboard 저장은 서로 다른 원시 사건이 필요하다. Delft에서 실험자가 종이를 배포한 시각은 개인의 실제 확인 시각을 주지 않는다. 최소 보완은 이벤트 사전과 수집기, 원본의 실제 열기/저장 행에 공통 시계나 공개 보정 규칙이 있는 자료다. [VIS 방법](https://www.zcliu.cs.umd.edu/papers/ExamplesDesign_VIS24.pdf#page=4), [Delft 논문](https://doi.org/10.1115/1.4035540)

VIS에서는 사후 참가자 스케치와 연구자 재구현을 분리해, 사전판이 없는 인코딩 변화 판정을 보류했다. ## Q6 · 대조, 역방향, 민감도

Sketchy Study 1은 자원한 분반의 디지털 Peek 가용성 차이다. 비활성 분반도 이웃 화면을 볼 수 있다. Study 2 참가자는 전원 디지털 Peek를 사용할 수 있다. 파일럿 export에 개별 조건과 탈락자 원표는 없다. Delft는 네 조건에 무작위 배정했고 혼합군에서 구체 예시를 먼저 주고 15분 뒤 원리를 제시했다. 처음 숙고 3분에 그림을 기록하지 않는 절차였고, 혼합군 중간의 사전 작품부터 노출까지는 원파일이 열리면 따로 확인할 수 있다. VIS 무작위 지연 15분은 소프트웨어에 접속하지 않는 시간대다. 해당 시간의 기저 작품, 실제 열린 자료와 참가자별 탈락은 미확인이다. [대조 원장](contrasts.csv)

질문은 원래 선택이 노출 전에 있었는지까지 포함한다. B09에서 중간 작품이 검색 자극을 골랐고, VIS §6.1 참가자도 이미 그렸던 안과 유사해 예시에 주목했다고 말했다. B03 대조군에는 제공되지 않은 예의 가스 구동 프레스와 같은 선택이 나타났다. A01은 셋이 같은 원페이지를 각각 고른 경우, A05는 직전 선택에 이미 있는 특징을 제거한 저자 코딩과 거의 같은 복사 사례를 보여 준다. 이러한 사례를 비교하면 모양 일치를 원인으로 재코딩할 수 없다. [B03 §5.3](https://www.designsociety.org/download-publication/32459/physical_examples_in_engineering_idea_generation_an_experimental_investigation), [A05 pp. 88–89](https://www.eecs.harvard.edu/~kgajos/papers/2015/siangliulue15providing.pdf#page=6)

동률 제외, 다른 자극 제외, 5·30초 간격의 사람 결과는 모두 시계와 키 부재로 미확인이다. 인공 검산에서 기준 2쌍, 다중 자극 허용만 바꾸면 3쌍, 최소 간격 2tick과 다중 허용을 함께 적용하면 2쌍이었다. 마지막 경우에 합계가 같아도 최초 배제 사유는 달라졌다. 사람의 효과 방향에 쓸 분모는 0이다. [민감도와 비용](evidence/COMPARISONS.md)

## Q7 · 전후 증거를 갖춘 링크와 보류할 링크

참가자의 당시 발언은 어떤 특징을 보았는지 설명할 수 있다. 연구자는 사례 선택과 코딩, 때로 별도의 재구현을 맡는다. 원작 제작자는 실제 버전과 제작 제약을 설명한다. 이후 설계자는 자신의 입력·보존 조건·회귀 시험에서 작동을 재판정한다. 같은 사람이 같은 자료를 실제 열었음을 보여 주는 연결과, 두 판에서 무엇이 달라졌는지를 서술하는 연결은 독립적으로 확인할 수 있다.

Darwin 1859/1860 p.490에서 최초 생명의 주체를 명시하는 문구와 진화 명제의 보존을 확인했다. Frankenstein 1818/1831 Chapter I의 Elizabeth는 친조카로 수용되는 사람에서 다른 집안에서 태어나 농가를 거쳐 가정에 들어오는 인물로 바뀐다. 다른 대목 C29_app146에서 Thomas의 자필 정정과 1831 읽기는 수렴한다. 편집 기관은 1823년 이후 해당 책에 직접 접근할 수 없었다고 설명하며 더 이른 MS에도 유사한 읽기가 있다. 같은 선택의 발생 경로는 여전히 기억·공통 선행판·다른 중간판의 검사가 필요하다. [Darwin p.490](https://darwin-online.org.uk/Variorum/1859/1859-490-c-1860.html), [Frankenstein C29](https://github.com/FrankensteinVariorum/fv-data/blob/2debfb706fbe0c1cc2c90b5a75d41b5591aef9c4/2023-standoff_Spine/spine_C29.xml#L2446)

애니메이션 두 건은 공개 초안 안내와 영어 VSE 제작 원본의 고정 전후 판이다. 3화는 011을 17프레임 늘리고 012를 17프레임 줄였다. 4화에서는 두 컷 경계의 겹침 2프레임과 CROSS가 확인됐다. 같은 4화의 gap 수정 커밋에선 바이너리가 바뀌었지만 읽은 편집 필드는 전부 같았다. 2화 보드는 변경된 animatic을 나중에 반영할 수 있다는 제작자 설명도 확인했다. 이 두 제작 자료를 스토리보드 분야의 제작 변경 기록으로 집계했다. 그림 보드 개정판 자체나 최종 렌더를 판독한 사례의 수는 이 집계와 다르다. [제작판 실측](evidence/COMPARISONS.md)

- **변경을 확인한 링크 문장.** “장면을 컷 전환으로 연결할 때 두 입력을 2프레임 겹치고 CROSS 처리를 추가한 24fps 편집 설정을 확인할 수 있습니다. 두 판의 씬 시간 범위는 같습니다.” 반대 판이나 렌더에서 같은 영어 장면·활성 컷·효과의 입력이 성립하지 않으면 작동 설명을 철회한다. [부모 파일](https://gitlab.com/OpenSourceAnimation/pepper-and-carrot-ep04/-/blob/4fd74aaa3f9e3fad6b19bc97a51a10562ee3ca81/project-en.blend), [변경 커밋](https://gitlab.com/OpenSourceAnimation/pepper-and-carrot-ep04/-/commit/8bf0f22e2a1196e0d33248b48252c7828a27324a)
- **판단을 보류할 링크 문장.** “백분율 주석이 있는 예시와 참가자의 그다음 스케치를 비교할 수 있습니다. 참가자는 기존에 비슷한 안을 그렸다고 말했고, 그 안의 주석과 분모는 미확인입니다.” 실제 개봉 직전·직후 버전으로 새 선택임이 확인되면 개정한다. 직전판에 같은 계산이 있었거나 연구자 구현에만 있으면 변경 문장은 철회한다. [VIS Fig. 7 및 §6.1](https://www.zcliu.cs.umd.edu/papers/ExamplesDesign_VIS24.pdf#page=8)

## 조건부 대안과 비용

같은 막대 형태를 보여 줘도 절대값과 비율의 목적을 분리한다. Vega 예제는 범주 내 분모를 정규화하고, OWID는 산림 순변화와 벌채량의 단위를 나눈다. Sankey 예제는 실측 `source, target, value`를 필요로 한다. 원자료에 없는 작물×원인 링크를 화면 도형으로 채우면 작동의 검증 조건을 잃는다. [Vega 예제](https://github.com/vega/vega-lite/blob/v6.4.2/examples/specs/stacked_bar_normalize.vl.json), [OWID 원면](https://ourworldindata.org/deforestation), [Sankey 원구현](https://github.com/d3/d3-sankey/blob/v0.12.3/src/sankey.js#L126)

가벼운 전달은 출처의 정확한 위치와 확인된 범위를 붙인다. 단계별 검증이 필요한 요청에는 버전 그래프와 로그 유형을 함께 보존한다. Git·MediaWiki는 작품 부모와 판을 비교할 수 있고, OpenTelemetry·xAPI는 발생·관측·저장 시각과 도메인 행위의 의미를 별도로 정한다. 실제 링크를 본 사람에 대한 설명에는 이벤트 이름·대상 버전·시계와 보존 조건의 시험이 더 필요하다. 파일럿 고정 다운로드 1회 15,062,721바이트와 1.187초가 이번 취득 샘플이다. 사용자가 검색하고 설치하거나 렌더링하는 총비용·품질 변화는 미측정이다.
