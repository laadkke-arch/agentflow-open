## 판정과 범위

**PARTIAL.** 네 논문을 직접 읽고 저자 판·소비 코드·그림 연결의 판별은 실질적으로 성립했다. 그러나 R v1 alias 전수의 재확인과 음악 실제 녹음 원기록 직접 열람은 완료되지 않았다. E4 동일 출력 실행 증명은 네 건 모두 없음. 출처 65행 중 보수적으로 산입 43개(논문4, 코드24, 발행/방법8, seaborn3, 공연 원자료4). 4개 논문 사건은 확률표본이 아니며, seaborn 사용률 또는 추천 순위 추정 금지. 문장 단위 원문은 저작권상 긴 인용 대신 정확 위치·짧은 식별자·한국어 의미로 남겼다. mentions.csv 26행은 25개의 언급/alias 자리와 R의 Waskom/감사 미언급 상태 1행; 특히 R 일부 쪽/그림 위치는 미확인. 표1 문장 역할은 추론, 원문 속 명시 주장은 저자 진술, 파일 위치와 literal은 관측이다. 표2의 E3 자산 조인은 실행 결과 관측이 아니며 E3-caption/asset-only/conditional은 동일 경로 완전성에서 구별한다.

## Q1. 문장이 지칭한 객체와 역할

- C는 하나의 소비자에게 비교, 상호운용, 실제 예제 호출, 산출물에 대한 저자 주장, 참고문헌이 동시에 있다. [P01](https://joss.theoj.org/papers/10.21105/joss.07120.pdf#page=1) p1에서 Waskom은 팔레트 선택 대안, p5에서는 density workflow이다. p6 DOI는 설치판이 아니다. 다른 패키지에서 영감받은 HCL 경로와 특정 API를 분리. p2 named palettes에서 영감이 언급되나 seaborn 특정 palette 계승은 증명하지 못함. 
- K [P02](https://joss.theoj.org/papers/10.21105/joss.08661.pdf#page=1) p1, V [P03](https://joss.theoj.org/papers/10.21105/joss.09037.pdf#page=1) p1 비교 인용을 E0로 유지한다. K에는 별개 E1과 lazy 등록이 있으므로 소비자 전체를 비교 전용으로 납작하게 분류하지 않는다.
- R [P04](https://www.research.unipd.it/retrieve/51d20577-f084-42f5-b411-281063d883e6/2019_Raincloud_plots_a_multi_platform.pdf#page=14) p14-20은 상류 라이브러리 이름과 직접 호출을 제시. Waskom 2021 DOI가 없는 것이 사용 없음은 아님. v1 p34 코드 보관본을 우선. 출판문은 직접 열었으나 F13 재조회 실패로 모든 alias의 위치를 다시 세지 못함; mentions.csv에서 유보.

## 경쟁 설명과 비용·조합 조건

- 논문 저자는 공헌을 대비하고 설명 가능한 example을 제공한다. 라이브러리 저자는 권장 citation과 API 계약, 소비자 파일·실제 호출은 서로 다른 책임이다. 재현 개발자는 release/lock/data/entrypoint/output artifact의 연결을 필요로 하고, 편집자는 크레디트와 계획 목록의 시간 차이를 관리하며 연주자는 실제 performance edition을 확정한다. 각자의 주장 대상과 증명 책임을 분리.
- 대안 A: 인용 그래프 기반(낮은 조사 비용, 문맥 탐색에 충분, 비교 인용 false-positive). B: tag+manifest+정적 호출(중간 비용, 함수 수준 안내, lazy import/도구 scope 및 비실행 경로 false-positive). C: figure ID + script + output path + 실제 log/artifact(높은 비용, 정확한 그림 목적에 유용; 원 로그가 없으면 재현 결과도 역사적 실행과 다름). 금액/시간 실측 없음. 단계별 fetch 수/실패를 기록할 수 있으나 실제 비용은 미확인.
- 조합 후보: A에서 passage role을 복수 허용 → B에서 소비 scope와 호출 경계 확인 → C는 exact-artifact 목적에서만. 주장을 독립 유지하는 가벼운 contract 후보 (consumer DOI+version/date, passage locator, role, cited object, software ref+blob, use scope, call signature, output ID/path, execution evidence ref, alternative explanation, status). 동일 관계 하나로 합치면 K 비교→사용, V 동명→reuse, R 후대→당시 오류 발생.
- 불확실성 표현: 비교했다 / 요구 파일에 적혀 있다 / 함수 호출 텍스트가 있다 / 해당 자산 생성 스크립트가 있다 / 동일 출력 실행 로그 확인 — 각기 다른 문장. UI/DB 선택 및 최종 순위는 후속 설계자가 결정. 검증을 실행할 Codex 절차는 HANDOFF.
