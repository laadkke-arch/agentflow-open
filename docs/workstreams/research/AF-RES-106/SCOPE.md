## 2. Q1 모집 단위와 완전성

옛 고정 발행 트리의 ggplot2 `reference/*.html` 및 Matplotlib `gallery/**/*.html` 전 목록을 확보한다. 한 번 받은 배포 archive 또는 동일 고정 Git tree를 기계 판독할 수 있다. 전체 경로·blob·수신 지문·누락을 남기고, 새판 본문은 이때 열지 않는다. `frame.csv`는 제외 행도 포함한다. 자동 스캔 페이지 수와 사람이 아닌 AI가 원문을 직접 판독한 고유 자료 수를 구분한다.

단위는 **한 페이지의 첫 적격 논리 예제 하나**다. 정확한 절 안에 설명, 실행 가능한 예제 코드, 그 설명에 연결된 그림·SVG·애니메이션·다운로드·내장 자원이 있어야 한다. 로고·배지·탐색용 썸네일은 제외한다. 앞선 예제의 실패 때문에 두 번째 예제로 교체하지 않는다. 대표 자원은 첫 설명용 그림/내장 표현이 있으면 그것을 택하고, 없으면 그 첫 예제에 실제 연결된 실행 source download를 택한다. 설명·실행코드·download가 있는 Matplotlib sgskip 예제도 `asset_kind=download-python`으로 적격이며, 그림 없는 예제 수·GUI 실행 미실시를 별도로 밝힌다. 단순 문서 저자 소스 링크나 code-only는 다운로드 실행 예제의 대체물이 아니다. resource와 source가 같은 파일이면 최소 자료수에 중복 산입하지 않는다. 인라인만 있는 예제는 따로 세며 외부 경로가 없다는 이유로 삭제 사례로 만들지 않는다. 자동 파서가 자격을 확인하지 못한 것은 접근 실패 또는 판독 미확인으로 보존한다. 선택 후보의 원 HTML을 직접 다시 읽어 파서 경계·코드·자원이 맞는지 검토한다.

옛판에서 먼저 페이지·실제 DOM id·절 경계·대표 자원 경로·연결 코드 및 소스·독자 목적 두 칸을 고정한다. 시각적 목적은 결과 그림/상호작용이 전달하는 역할, 구체적 방법은 그 결과를 만든 API/호출 방법이다. 같은 시각 결과를 다른 API로 만든 경우 두 축의 결과가 다를 수 있다. 102의 `frame.csv`에서 eligible=YES인40개씩과 교정 예제·명백한 별칭은 제거하되 전체 경로 목록에서는 제외 이유를 남긴다. 잔여 범위 내부에서도 원 HTML의 첫 출력 목적·데이터·구체 API 방법이 같은 논리예제는 한 개로 합친다. canonical은 옛 `page_path`의 사전순 최소이며 해시나 새판 결과로 고르지 않는다. 동일 payload의 그룹은 검토 후보일 뿐 자동 동일성 판정이 아니다. `stat_identity`나 `qplot`처럼 구체 방법이 다르면 같은 그림이어도 별도 유지한다. 이 규칙은 원격①·새 트리 열람 전에 별도 검토에서 발견한 내부 반복을 처리하려고 명시했다.

## 3. Q2 경로 신호·서로 배타적인 층

묶음①을 원격에서 확인한 다음, 새 **트리 경로와 Git 변경 종류만** 읽는다. 새 본문·그림·변경 설명/diff 내용은 예측을 봉인할 때까지 읽지 않는다. 버전 루트와 상대 `..`를 URI 의미대로 해소하되 대소문자·확장자·fragment·1x/2x를 합치거나 소문자로 바꾸지 않는다. HTML fragment는 경로 존재 여부와 별도 보존한다. 파일 수록은 트리에서 fragment를 분리한 해당 파일로 검사하지만 도착 가능성을 미리 확정하지 않는다.

| 순서·층 | 후보 조건 | 자리 |
|---|---|---|
| A · 옛 외부 자원 부재 | 완전한 새 발행 트리에 옛 대표 외부 자원 경로가 없음 | GG-A1/A2, MP-A1/A2 |
| M · 자원 잔류·본문/소스 경로 소멸 | A가 아니며 옛 외부 자원이 남고, 옛 본문 파일 또는 대응 예제 소스 경로가 없어지거나 Git에서 이동으로 확인됨 | GG-M1/M2, MP-M1/M2 |
| G · 일반 대조 | A와 M에 들지 않는 적격 예제; 내장 전용/외부 확인불명은 별도 표시 | GG-G1/G2, MP-G1/G2 |

단순 source blob 변경은 M의 충분조건이 아니다. **source-set는 옛 예제와 연결을 확인한 렌더 입력 및 저자 예제 소스의 집합**이다. ggplot2의 렌더 입력 `man/<page>.Rd`와 더불어, 옛 HTML의 Source 링크 및 옛 R `@examples`/첫 코드 또는 Rd의 생성 관계로 연결한 R 저자 소스도 포함한다. 단순 구현파일 링크만 있고 예제 연결이 확인되지 않으면 자동 포함하지 않으며 `source_mapping=미확인`을 남긴다. 집합 중 옛판에서 실재한 어느 경로든 새판에서 사라지거나 이동하면 자원 잔류 조건 아래 M이다. `.r`→`.R`도 정확 경로 변화이며 대소문자를 합쳐 생존으로 처리하지 않는다. Matplotlib은 실제 발행 `_downloads/<hash>/<example>.py`와 확인한 저자 예제 경로를 함께 보존한다. 이 **공개 다운로드 경로의 소멸도 M 신호에 포함**하되, 저자 경로(옛 고정판 실제 루트 `examples/...`)의 삭제·이동과 따로 기록한다. download 자체가 대표 자원인 예제에서 그 경로가 없어지면 우선순위에 따라 A다. content-hash 다운로드 주소 변화나 대소문자 이동만으로 논리 예제의 삭제를 판정하지 않는다. 소스의 의미적 변경 판단은 사후 단계다.

이 source-set 해석은 첫 원격 커밋 `ccbc56bb0891a5721e4f53438e431df81fc8b2a3`의 man 중심 규칙을 **새 경로 목록 노출 뒤·새 본문 및 정답 판독 전**에 교정한 것이다. [METHOD_AMENDMENT.md](METHOD_AMENDMENT.md)에 이유·이미 본 신호·수정 순서를 보존하고 별도 원격 커밋을 확인한 뒤 재계산한다. 첫 규칙을 소급 수정하거나 전체 규칙이 새 경로 노출 전부터 고정됐다고 주장하지 않는다. 좁은 man-only 계산은 민감도 부록으로 보존하며 최종 예측은 새 본문 개봉 전에 별도 봉인한다.

모든 후보를 A→M→G 순서로 한 층에만 배정한다. 각 프로젝트·층에서 아래 hash의 오름차순 앞2개를 택하고, 동률은 옛 절 경로순이다. `old_section_path`는 버전 루트 기준 `reference/...html#id` 또는 `gallery/...html#id`다. hash 문자열은 `AF-RES-106`이 아니라 배정문의 고정 문자열 **`AF106`**이다.

```text
SHA256(UTF8('AF106|' + project + '|' + old_section_path))
```

층에2개 미만이면 남은 자리는 결원이다. 후보가 없다는 결원과 후보는 있으나 예측/판독이 불명이라는 유보를 구분한다. 미완전 트리는 부재 신호나 부재 결원을 입증할 수 없다. 그 경우 부족한 모집 범위를 PARTIAL로 표시한다. 선택12자리, 전체 분모, 결원, 예측, 노출 시각을 묶음②로 원격 봉인한 후에만 새 본문을 연다.

## 4. Q3 봉인할 예측

옛 대표 외부 자원 경로가 새 완전 트리에 있으면 `prediction_U=YES`, 없으면 `NO`, 완전성이나 기존 외부 대상이 불명/내장 전용이면 `미확인`으로 예측 유보한다. 실제 빈 자리는 `vacant=YES`와 `prediction_U=미확인`으로 기록하지만 예측 유보 분모에 넣지 않는다. 사전 임시 URL은 새판 루트에 옛 페이지/fragment와 옛 대표 자원을 그대로 연결한 값이다. 이 주소는 **검증된 반환 링크가 아니다**.

반대 관측의 사전 조건: 파일이 남지만 선택 절/후계가 사용하지 않으면 YES 오경보가 가능하고, 파일이 없어도 새 이름/내장/다른 API가 원 목적을 이어가면 NO 놓침이 가능하다. fragment 변경, 같은 파일 다른 caption, 같아 보이는 그림의 다른 목적도 오판 조건이다. 운영자의 확인 비용·오경보, 역사 저자의 당시 근거 보존, 다음판 독자의 정확 예제 접근을 별개로 평가한다. 예측을 사후 판독에 맞춰 고치지 않는다.

## 5. Q4–Q5 사후 판독과 NO의 경계

12쌍·24판 자리를 유지하고 결원도 이유와 재개 입력을 남긴다. 각 실제 예제의 old/new 정확 fragment, 동급 제목까지의 경계, `base/src/srcset/picture`, data URI·SVG·다운로드/스크립트를 읽는다. 실제 참조한 자원과 저자 소스의 URL, Git blob/SHA-256, 역할을 연결한다. 1x와2x를 각각 보존하고 둘을 서로 다른 독립 자료로 중복 계산하지 않는다. 고정 raw HTML의 정적 id 확인을 브라우저 실제 스크롤/표시 실행으로 부르지 않는다.

| 축 | YES 근거 | NO를 부여할 최소 범위 | 미확인으로 남기는 경우 |
|---|---|---|---|
| P · 새판 수록 | 완전 발행 tree와 실제 참조 payload의 경로·지문 | 완전 tree/내장 범위에서 그 자원이 없음 | 접근 실패·불완전 tree |
| 옛 주소 도착 | 새판의 옛 페이지와 옛 fragment가 실제 DOM에 존재, 그 경계의 목표 확인 | 완전한 해당 HTML에 id 없음 또는 완전 tree에 페이지 없음 | 동적 redirect/실표시 확인 불가 |
| U · 옛 시각 목적 | 실제 새 절/대체 표현·코드와 저자 변경의 연결로 목적 계승 확인 | 관련 전체 새 gallery/reference 경로와 코드의 basename·caption·특징 호출 검색, 후보 전부 판독, 공식 삭제/이동 기록을 대조해 명시한 범위에서 후계가 없음을 확인 | 첫 URL 실패만 확인, 후보 누락·의미 모호 |
| API 방법 계승 | 원 방법의 호출/사용이 정확 새 예제에서 확인 | 목적 후보 및 공식 변경에서 해당 방법의 제거/대체가 확인 | 호출 불명·간접 실행 |
| G · 당시 생성 | 보존된 실제 build run·입력/환경·출력 manifest/digest→발행 연결 | 그 실제 run이 복사/재사용만 했다는 직접 실행 근거 | 실행 연결 미보존; source와 tree만 확인 |

P는 실제 따라간 자원의 수록이며 `legacy_path_P`는 옛 경로 생존이다. 새 이름의 후계이면 legacy_path_P=NO와 P/U=YES가 함께 가능하다. 옛 경로가 남아도 그 파일의 새 절 참조와 원 목적 계승은 따로 본다. 같은 hash·파일명·겉모습만으로 후계를 확정하지 않는다. 정적 목적 판독과 R/Python 실행, 브라우저 표시, 역사적 생성은 각각 다른 증거다. 빌드 증거가 우연히 확보되면 G를 기록하되 이전 빈 실행검색을 반복하지 않는다.

## 6. Q6 보조 경로와 집계

주 층에서 양방향 오류가 없으면, 결과를 보기 전에 정한 보조 경로를 사용한다. 동일 두 source revision 사이 예제 소스 이동/삭제가 포함된 commit 목록을 **committer UTC 오름차순, SHA 오름차순**으로 정렬하여 프로젝트당 최대10건을 추적한다. Git 파일변경 종류/경로만으로 목록을 먼저 고정하고 commit 설명·patch·새 후보 본문은 묶음② 이후 연다. merge의 중복 변화는 동일 사건 계보로 표시하고 독립 사례수로 합치지 않는다. source change event가 없는 프로젝트는 그 결원을 보고한다. 주 표본과102 사례는 제외/계승으로 표시한다. 필요한 자료 하한을 채울 별도 대조는 주 예제 제외 후 같은 hash순으로 정하며 주 오류율에 넣지 않는다.

각 프로젝트·층에 TP/FP/FN/TN, 예측 유보, 실측 미확인, 결원, 실제 U양성/음성 분모를 따로 계산한다. 두 목적 축이 다르게 판정되면 시각U의 주 혼동표와 방법의 보조 혼동표를 구분한다. 실제 음성0이면 FPR와 특이도는 `산출 불가`다. 세 층의 비율이나 보조 표본·102 표본을 합친 전체 성능을 만들지 않는다. 전수 경로 탐색과 제한한 상세 판독 범위를 명시한다.
