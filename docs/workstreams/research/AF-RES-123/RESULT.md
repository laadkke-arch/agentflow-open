## Q1 · 보고된 현상과 실행 범위

2023-01-06 현재 API의 opening과 119의 사양 SHA가 일치한다. 본문은 ordinal과 색이 함께 있는 경우 mark와 empty canvas의 결과를 구분한다. 사용자가 원래 새 brush를 그리려 했는지 기존 brush를 옮기려 했는지, 유지하려던 투영 집합과 색을 명시하지 않았다. 고정판은 `mousedown`과 `window:mouseup` 사이의 `window:mousemove!`에서 컴파일된 signal을 움직인다. unbound translate가 켜지면 foreground brush는 신규 시작에서 제외되고 이동 anchor에 연결된다. 배경 fill과 투명 앞쪽 stroke mark는 별개다. shared는 anchor/delta 두 신호와 시작 filter를 없애므로 앞 brush 아래에서도 새 범위를 만들 수 있다. 원형의 x 투영은 월 변환 필드와 band의 `E` 열거로 관측됐다. 문서의 binned 또는 timeUnit 투영 한계는 별도 연속 예도 보여주므로 스케일 유형과 컴파일 필드를 같이 확인하는 편이 안전하다. ## Q6 · 추천에 필요한 증거와 비용

정지 화면은 범위 상태 및 실제 target을 결정하지 못한다. 저장 diff와 compile은 사용 가능한 세 절을 낮은 비용으로 좁힌다. `translate`는 폭 보존 정책, 조건 색은 출력 범주의 표현, projection은 필드와 열거 집합의 해석에 연결한다. 같은 x 첫 이벤트와 저장 신호를 실제로 대조하면, 조건 색과 translate를 단독 좌표 교정으로 추천할 수 없는 행을 찾는다. 저장 설정만 볼 때의 순위와 after-event 조건, 추가 사용자 정보 하나, 틀릴 조건은 각 본행에 기록했다. 저장판별 사전 규칙의 우선 절은 32/48에서 after-event의 조작 목표별 절로 바뀌었다. 이는 같은 작업자의 규칙 비교다. 독립 가림 판독이나 사람의 도구 채택 관측으로 해석하지 않는다. [48개 전후 결정](decisions.csv) · [사전 규칙](SCOPE.md#실행-전-기대와-반환-메뉴)

간단한 반환은 공식 기능 절과 예상 보존 상태를 제공하고 필요할 때 한 번만 시작 상태·hit 단서를 더 받는 방식이다. 실제 동작의 원인이 결정에 중요하면 두 단계의 포인터 이벤트, unit 원점, 첫 frame의 pixel extent와 투영만 먼저 받아 좁힐 수 있다. 빌드·해상도와 전체 input/scenegraph를 보존하는 방법은 판·렌더러 불일치를 확인하기 쉽지만, 이번에는 본행과 대조에서 9,330 callbacks 및 84개 원파일을 남겼다. 더 작은 반환으로 시작해도 seed·hit가 달라진 경우에는 같은 실험 분모에 섞지 않는다.
