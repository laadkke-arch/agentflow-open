## 3. 두 부분 요구 — 결과 전에 고정

### P1: 기존 읽기/계산 호출을 유지할 수 있는가

기존 프로그램의 public 이름·호출과 기본값을 바꾸지 않고, 이전 판에서 사용한 정상 입력을 다음 판에 넣었을 때 필수 값·자료형·차원/순서·메타데이터를 보존해야 한다. 새 이름으로 코드를 바꾸면 P1 충족이라고 하지 않는다. 단지 경고가 새로 생긴 경우 출력과 경고 정책을 분리한다.

- GIS 역할: 오래 보관한 파일을 기존 GDAL/OGR reader가 읽는다. raster fixture는 2×2 정수 표본 `[1,2;3,-9999]`, nodata -9999, EPSG:4326 및 geotransform `(0,1,0,2,0,-1)`; vector fixture는 순서 있는 두 Point feature, 정수 `id=[1,2]`, UTF-8 `label=['가','b']`, 좌표 `(0,0),(1,1)`이다. 해당 format으로 표현할 수 없으면 원 공급자 최소 fixture를 쓰되 지원 불가 속성과 이유를 명시한다. driver 이름을 지정한 호출과 자동 감지는 별도다.
- OSS 역할: 과거 수치 계산 코드의 import/호출 유지. sampled data fixture `y=[1.,3.,2.]`, `x=[0.,1.,2.]`, 역순 x, 길이 0/1, 2-D 두 행, float32 및 복소 입력을 미리 후보 입력으로 둔다. 선정 기능과 무관한 입력은 적용 외. 해당 public function의 공급자 최소 test fixture를 전후 똑같이 사용하고, 선택한 test ID·구체 입력을 결과 전에 관측 원장에 명시한다. SciPy 전체의 호환성을 이 한 기능 결과로 말하지 않는다.

### P2: 새 환경에서 교체 부품으로 출력 기능과 오류 계약을 계속 제공하는가

명시적 이관 지침에 따른 새 import/driver 이름은 허용한다. 출력 소비자의 지정 판과 입력/출력/오류 계약은 유지해야 한다. 쓰기·생성 기능이나 필요한 자료형/경계 동작이 없으면 거절/보류한다. 이름을 바꿔 정상 입력 하나가 맞는 것만으로 충분하지 않다.

- GIS 역할: 위 decoded object를 새 driver의 Create/CreateCopy 또는 vector CreateDataSource로 써서 이전 소비자가 다시 읽는다. field 값/순서/형, CRS, nodata를 보존하며, 지원 불가 geometry 또는 손상된 header를 성공으로 삼키지 않아야 한다. 새 default file-format 판과 이전 소비자 허용 판의 충돌을 명시한다. read-only driver이면 P1의 read 가능성과 P2의 write 불가를 분리한다.
- OSS 역할: 새 import/함수로 위 numeric task를 수행한다. 정상·역순·빈/길이 1·2-D 축·dtype와 잘못된 axis(`axis=9`) 또는 불일치 shape의 예외를 전후 비교한다. 함수의 역할상 axis가 없으면 다른 공급자 invalid-input test를 명시하고 적용 외 이유를 남긴다. 연결/포크 판정과 API 대체 적합성은 독립이다.

적용 입력의 세부 serialization은 선정 format/API에 맞추는 작업이며 요구 변경이 아니다. 실제 실행, 공급자 시험의 정적 판독, 명세상 기대, 미관측/예측을 구별한다. 최소 각 분야 1사건은 같은 전후 쌍에 P1·P2를 모두 적용한다. 적용 불가를 성공 분자로 세지 않는다.

## 4. 사전 고정 수선 규칙과 독립 기준

**URL-only U:** old URL GET의 301/308 chain이 한 목적지로 끝나면 목적 주소로 수선하고 같은 레코드를 유지한다. 같은 주소가 2xx이면 유지한다. 다중 도착, 302/307만의 이동, 다른 응답, 접근 실패는 보류. 페이지 내용/이름/지문은 U의 판독 입력이 아니다. fragment는 HTTP 요청에 실리지 않음을 별도로 기록한다. U는 분리를 표현하지 못하며 이를 별도로 센다.

**Target-aware T:** old/new namespace·대상 종류·판·공식 계보·원 기능 절을 읽고 ①동일 ID 유지 ②범위 있는 별칭 ③혼합 record의 대상 분리 ④별도 ID 간 방향 있는 후속/포크/기능 이동 관계 ⑤보류를 부여한다. 필요하면 ③+④. 계보와 행동 호환성은 별도 열이다. 200·같은 이름·해시·중개자 설명만으로 병합하지 않는다.

독립 기준은 저자의 결론이 아니라 (a) 발행자의 명시적인 namespace/기능 선언과 수신자의 역확인, (b) 판이 고정된 구현/공급자 시험 또는 실제 동일 입력 실행이다. 동일성의 단위를 먼저 정한다. 이 기준이 없는 사건은 판정 비교의 비율 분모에서 분리한다. U의 보류를 오류로 바꾸지 않으며 U에 존재하지 않는 분리 행동을 가정해 false-split을 만들지 않는다. 별칭을 무조건 별개로 만드는 가상 정책의 중복 작업은 주 U 비교와 별도 가설이다.
