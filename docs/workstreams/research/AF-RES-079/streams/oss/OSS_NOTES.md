# AF-RES-079 OSS 조사 인계

> 후속 확인: 이 문서는 원판 조사 체크포인트의 미실행 상태를 보존한다. 이후 OSS4개 사건의 역사판 실행200호출/49대응은 historical/HISTORICAL_RESULTS.md와 historical/paired-check.receipt.json에 있으며, 재개 시 streams/resume-oss/audit.json에서 핵심18호출을 별도로 재실행했다. 현재 판정은 RESULT.md·observations.csv의 H-행을 읽는다.

## 범위와 분모

이 스트림의 자연 모집은 **4 / 4 사건**이다. 양쪽 판의 공식 문서와 고정 구현을 확보한 쌍도 **4 / 4**다. 반면 같은 입력을 양쪽 역사판의 설치 환경에서 실행한 쌍은 **0 / 4**다. 소스 판독·공급자 시험의 기대값과 실제 실행을 서로 대체하지 않았다.

모집 기준은 상위 `SCOPE.md`의 SciPy 1.5.0–1.14.0 minor release notes, 2020-01-01–2024-12-31, 최대 10개 공지, 날짜 다음 원문 순서, 첫 적격 네 사건이다. 부모가 알려 준 봉인 원격 SHA는 `dfdfe1b82ee1921f2f90c723dbd9fe8d22138ead`다. 이 스트림은 모집틀을 확대하지 않았다. 공개 API의 이름·메서드·기능 이동만 취하고, 인자 이름만 바뀐 경우·private 구현 정리·과거 이관의 경고 승격은 제외했다.

`release-screen.json`은 10개 공지의 실제 취득 주소·해시·UTC와 선별 위치를 보존한다. 1.5/1.6의 모집 관련 원절을 상세 판독했고, 1.7/1.8의 다음 후보와 1.14의 제거 절을 추가로 직접 읽었다. 1.9–1.13은 기계적 키워드 선별만 했으므로 직접 읽은 독립 원저작으로 세지 않는다. `recruitment.csv`는 채택 4건과 중복·배제·정원 이후 후보를 원문 순서로 보존한다. 해당 CSV 행의 `source_line`은 고정 release RST의 행이고 웹 렌더의 행 번호와 다를 수 있다.

### 결과를 읽으며 발생한 선별 해석의 교정

초기 후보 단계에서 integrate와 stats의 rename을 나누고 `wminkowski`를 네 번째 후보로 보았으나, 이는 최종 모집이 아니다. 같은 명명 결정의 별칭들을 하나의 사건으로 세라는 봉인 기준에 따라 integrate와 stats의 이관을 **O02 한 사건**으로 묶었다. 이 사건 안의 네 기능 ID는 서로 합치지 않았다. PR12374는 `wminkowski` 이관이 이미 SciPy 1.0에서 시작됐음을 명시하므로 1.6의 경고 승격은 기간 밖 사건의 반복으로 제외했다. 그다음 원순위의 `ndimage.sum` 이름 변경이 O04가 됐다. 채택 이후 자료를 구하지 못한 사건을 다른 사건으로 바꾼 일은 없다.

1.5.0에서 O01, 1.6.0에서 O02→O03→O04가 확정 순서다. O04의 첫 이름 언급은 release RST L490의 issue10593이고, 명확한 새 이름은 같은 문서 L637의 PR12242에서 확인했다. 같은 사건의 재언급이므로 한 자리다. 1.7의 `pinv2`는 정원 이후 후보로 남겼다.

## 네 사건의 관계와 두 요구

P1은 옛 호출·기본값으로 요구된 값·형상·순서를 유지하는지, P2는 새 이름을 허용하면서 지정된 결과와 오류 조건을 유지하는지다. 아래는 **역사판 실행의 결과가 아니라 원문·구현·공급자 시험 판독**이다. 각 원근거와 구별 입력은 `observations.jsonl`의 행 ID로 연결한다.

## 원문과 선언이 어긋나거나 설명이 부족한 곳

### 1. 공식 rename이어도 기본 동작은 다를 수 있다

O01의 구 구현은 raw MAD에 scale을 곱하고, 신 구현은 scale로 나눈다. 구 기본값은 1.4826이고 신 기본값은 1.0이다. 제공자의 새 이름은 의미 정리를 포함한다. 같은 발행자·같은 제품·비슷한 이름만으로 행동 동일성을 선언할 수 없다. 구 `median_absolute_deviation` wrapper가 실제로 역수 변환을 넣었다는 점이 어댑터 필요성의 독립 구현 근거다. 빈 `(3,0)`, `axis=1` 입력에서는 구판 scalar NaN과 신판 길이 3 NaN 배열이 갈라져 정상값 어댑터만으로 전체 계약을 복구할 수 없다.

근거: `OS-PR-11431`, `OS-ISSUE-11090`, `OS-CODE-01/02`, `O01-BOUNDARY-EMPTY`.

### 2. 같은 짧은 이름이 같은 기능이라는 뜻은 아니다

O02의 `integrate.trapezoid(y,x)`와 `stats.trapezoid(c,d)`는 다른 namespace와 역할이다. 전자는 수치 적분이고 후자는 확률분포 생성자다. 실제 설치된 1.17.0에서 적분 입력 두 배열을 후자에 넣었을 때 수치 4.5가 아니라 `rv_continuous_frozen` 객체가 만들어졌다. 이 음성 시험은 연구자가 구성한 구별 입력이며 추가 자연 사건으로 세지 않는다. 한편 동일 기능의 `ndimage.sum`과 `sum_labels`를 별개 구현으로 쪼개면 같은 label 합계를 중복 계산한다. 이름이 다르다는 이유만으로 분리할 수 없다.

근거: `OS-PR-12934`, `O02-NAMESPACE-COUNTER`, `current-native.jsonl#O02-RUN-wrong_namespace-stats.trapezoid`, `OS-PR-12242`.

### 3. 이관 공지는 반환 계약 전체를 보장하지 않는다

O03 원 PR12382는 `k=None`을 undocumented로 표현했지만, 직접 읽은 1.5.4 query 문서의 Returns는 그 모드의 거리 목록을 설명한다. 원문 작성자의 표현도 구판 문서와 대조해야 한다. 새 메서드의 인덱스 정렬과 옛 메서드의 거리 정렬은 서로 다르며, 거리 자체가 새 반환값에 없다. 구 구현은 `distance < bound`를 사용한다. 반경과 정확히 같은 거리를 가진 점의 신판 포함 여부는 과거판 native 실행으로 확인하지 않았으므로 **반례 후보/보류**로 남겼다.

원1.6.0 공지의 제거 예정판은 1.8.0이고, 2026-11-23 현재 query 설명서는 실제 제거를 1.9.0 변경으로 명시한다. 계획과 실제 제거판을 같은 필드로 덮어쓰지 않는다. 현재 manual banner는 1.18.0이었다. 로컬 실제 실행판 1.17.0과도 구분한다.

근거: `OS-PR-12382`, `OS-DOC-O03-old/new/live_old`, `O03-P2-RETURNS`, `O03-BOUNDARY-RADIUS`.

## 현재 HTTP 관측과 URL 단독 수선

`http-observations.jsonl`의 12건 중 구/신 **버전 고정 설명서 8개는 모두 200**이었다. 실제 관측한 redirect chain은 각 행에 남겼다. URL fragment는 서버로 전송되지 않으므로 상태 관측과 문서 절 판독을 별도로 다룬다. 현재 응답으로 과거 redirect 이력을 추정하지 않았다.

현재 구 이름의 unversioned URL 네 개 중 MAD·integrate.trapz·ndimage.sum은 404이고 KDTree.query는 200이었다. 봉인한 URL 단독 규칙으로 404는 **보류**다. 이를 거짓 분리라고 세지 않는다. query의 200은 같은 레코드를 유지하지만 옛 mode의 유무를 표현하지 못한다. 버전 고정 구 주소의 200은 과거 인용을 그대로 보존할 근거이며, 그것만으로 신판 동작을 승인하는 근거가 되지 않는다.

현재 runtime의 `ndimage.sum` 호출 성공은 문서 404가 함수 제거와 같지 않음을 보이고, `query(k=None)`의 ValueError는 문서 200이 옛 mode 보존과 같지 않음을 보인다. 문서와 runtime 판이 다르므로 “현재 배포 전체”의 동질성으로 확장하지 않는다. URL 규칙이 표현하지 못하는 동작·ID 분리의 한계와, 독립 정답 없이 수치화할 수 없는 거짓 병합 건수를 구분했다.

## 모집 밖 반례: wminkowski

PR12374는 구 이관을 경고로 강화한 사건이므로 자연 사건 수에는 포함하지 않는다. 그러나 잘못된 이름 교체의 구별 입력으로는 유용하다. 구식은 가중치를 p승 안에, 신식은 p승 밖에 두므로 `u=[0,0], v=[1,1], w=[2,1], p=2`에서 수식상 구값은 √5, 신값은 √3으로 예측된다. 구 wrapper가 신 함수에 `w**p`를 전달하는 것이 이 차이를 보상한다. 이것은 공식 수식·코드의 예측이며 두 역사판에서 실행한 수치 결과는 아니다.

근거: `OS-PR-12374`, `OS-DOC-SUP-WMINKOWSKI`, `OS-DOC-SUP-MINKOWSKI`. 이 두 설명서 절도 기존 API manual 계보이므로 추가 산입하지 않았다.

## 실행과 검사

`current-native.receipt.json`은 실제 명령·작업 위치·시점·환경·해시·종료값을 기록한다. 최종 실행은 Python 3.12.14 / NumPy 2.3.5 / SciPy 1.17.0에서 **50 호출 기록, 프로세스 종료 0**이다. 예상된 API 오류도 각 호출 결과로 수집하므로 종료 0을 “50 기능 모두 성공”으로 해석하면 안 된다. 모든 현재 행은 `historical_pair_claim=false`다. 이후 하나의 역사판을 실행하더라도 자동으로 pair 성공이 되지 않도록 `selected_historical_release`와 `historical_pair_claim`을 분리했다.

`static-comparison.receipt.json`은 O04의 두 helper 함수 원문이 양판에서 같은지 비교한 검사다. `_stats`, `_safely_castable_to_int` 모두 같은 본문 해시를 얻었고 종료 0이다. 정적 동일성은 컴파일된 두 환경의 동작 검증을 대체하지 않는다. 잘못 추정한 `scipy/integrate/quadrature.py` 경로는 404 접근 실패로 보존했고, 실제 `_quadrature.py` 취득 성공과 구분했다. 실패 최초 시각은 기록하지 못했으므로 재관측한 404의 정확한 UTC를 추가했고 최초 시각을 꾸며 넣지 않았다.

## 가장 작은 재개 행동과 입력

먼저 Python 3.8의 별도 환경에서 다음 네 판에 **같은 NumPy 1.19.5**를 고정해 `probe.py`를 실행한다. 아래 설치·과거판 실행 명령은 **아직 실행하지 않았다**. 당시 Linux x86_64 wheel을 확보할 수 없는 경우 해당 판을 결손으로 남기고 현재판 결과로 채우지 않는다. 설치물은 연구 산출물로 커밋하지 않는다.

```bash
AF_OSS=docs/workstreams/research/AF-RES-079/streams/oss
mkdir -p "$AF_OSS/replay"
for AF_VER in 1.4.1 1.5.0 1.5.4 1.6.0; do
  python3.8 -m venv "$AF_OSS/.venvs/scipy-$AF_VER"
  "$AF_OSS/.venvs/scipy-$AF_VER/bin/python" -m pip install --only-binary=:all: "numpy==1.19.5" "scipy==$AF_VER"
  "$AF_OSS/.venvs/scipy-$AF_VER/bin/python" -B "$AF_OSS/probe.py" --output "$AF_OSS/replay/scipy-$AF_VER.jsonl"
done
```

프로브 안에 정상값, 역순 적분, 빈 배열, float32/complex, 잘못된 axis, NaN 오류, KDTree 반경 1.1/정확 경계 1.0, ndimage label 순서/없는 label/shape 오류의 정확한 입력이 들어 있다. O01은 1.4.1↔1.5.0을, O02/O03/O04는 1.5.4↔1.6.0을 같은 `event_id/case/api/input`로 결합해 비교해야 한다. 새 이름이 옛판에서 없는 것 자체와 신판의 대체 호출이 구 기대값을 지키는지는 별개 검사다. 이 교차판 비교 전까지 native pair 분자는 0을 유지한다.

최우선은 O03의 정확 반경 1.0 입력을 양판 실행하는 일이다. 그 한 입력은 보류한 경계 차이를 결정한다. 다음은 O01 빈 `(3,0)`/`axis=1`의 실제 반환 형상과 reciprocal-scale 어댑터의 dtype/NaN 예외다. O02는 같은 NumPy 의존판이 입력값뿐 아니라 dtype·예외를 보존하는지 확인해야 한다.

## 인계 상태

네 자연쌍·양판 원문·P1/P2 판독·반례·현재 HTTP·현재 실행은 제공했다. **역사판 native 교차 검증은 미완료**이고, 독립 판독자의 판단은 부모의 별도 검토에 달려 있다. 원래 ID·판·주소·기대값을 남긴 상태에서 별칭 또는 관계를 추가하는 가역 수선을 제안한다. 이 스트림의 제한을 전체 완료 주장으로 바꾸지 않는다.
