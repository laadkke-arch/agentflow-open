# AF-RES-036 사전 방법 검토

작성 주체: 내부 scope_review 에이전트. 023/032를 교정용으로 읽었으므로 이 문서를 만든 주체는 새 보기의 엄격 미노출 판독자가 아니다. 새 외부 목적지는 열지 않았다. 이 검토는 루트가 범위와 카드를 봉인하기 전에 적용할 제안이며, 실제 시행 여부는 봉인된 SCOPE와 영수증으로 판단한다.

## 1. 제외목록의 단위

`exclusions.json`은 AF-RES-032 고정 SHA `b4dcf0a1ca3f2066629869ac1a9347ad2f5717df`의 원 references 18행(A12+B6), 보조 분야 원문 14행, AF-RES-023 고정 SHA `a9178ca95979564fd8801559d90d15db4ddac91b`의 소비자 인용13행과 사건21행(본표본18+보충3)을 연결한다. 각 읽은 입력의 SHA256·바이트·고정 커밋을 적는다. 새 source 최소수에 넣지 않는다. 이 파일은 이전 정답과 관측을 포함하므로 새 미노출 판독자에게 전달할 입력이 아니다.

032의 소비자 프로젝트는 CPython, PostgreSQL, SQLite, knitr, rmarkdown, dplyr, Ruby on Rails, httr, PycURL, Sphinx Sitemap, StarlingX다. B05는 A-D04와 동일한 PostgreSQL psql→RFC4180 소비자·목적이며 독립 사례로 세지 않는다. 다른 릴리스나 다른 URL wrapper로 이 목적을 다시 뽑아 새 표본으로 만들면 안 된다. 같은 목적지라도 소비자·목적이 실질적으로 다르면 새 참조의 가능성은 있지만, 기존 판정 노출 위험을 별도 표시해야 한다. 가장 보수적인 표집은 이 프로젝트와 기존 사건을 후보 목록에서 먼저 제외하는 것이다.

기존 보조 분야는 ONS Blue Book 2022/2023 GDP 개정·BoE 2023년 11월 보고서와 MoMA의 Barr 1936 카탈로그·Malevich 작품79269·Lowry 2012 해석 사슬이다. 이들은 새 지리·서지 사례를 대신하지 않는다. 과거 SQLite 미열람 46판과 엄격 전파 시각을 다시 채우는 것은 이번 연구 범위가 아니다.

## 2. 표집을 결과와 분리

두 유통 경로에서 각각 6개의 서로 다른 출판 문서를 선택하고 전체 최소 6프로젝트·프로젝트당 최대 2문서를 지킨다. 하나의 거대한 HTML의 다른 절을 서로 다른 출판 문서로 세지 않는다. 배포 archive에 소스 `.texi`/`.Rmd`만 있고 실제 빌드 HTML이 없으면 빌드 실행으로 과거 배포물을 만들어 내지 않는다. 사전 목록의 다음 공식 배포 목록으로 넘어가며 부재한 member와 전체 HTML 목록을 기록한다.

기간, 날짜 정렬 방향, 동일 날짜 tie-break, 프로젝트 순서, 각 문서의 후보 링크 순서, 제외 사유 우선순위, fallback을 첫 현재 URL 조회 전에 고정한다. 최종판을 알고 링크를 고르는 방식은 금한다. `frame.csv`에는 선택된 12행만이 아니라 도달한 후보와 탈락을 남겨 왜 다음 것으로 갔는지 재현하게 한다. 원 href·link text·주변 원문·배포판·멤버 hash·목적을 원문에서 봉인한다. 오래된 문서라는 사실만으로 특정 판 재현 목적을 만들어 내지 않는다.

## 3. B/N/H의 판독 계약

| 조각 | 들어갈 것 | 들어가면 누출 또는 겹침인 것 |
| --- | --- | --- |
| B | 원 배포·실제 href·링크 텍스트·원문 문맥·노출판·원문에 근거한 최소 목적 | 현재 도착 요약, 후속 편집자가 바꾼 href, 수집자의 현재 권고 |
| N | 같은 확인창의 실제 요청·redirect chain·도착 URL·요구 절·판 식별에 필요한 현재 원문 | 별도 옛 판을 수집자가 의도적으로 보충한 요약, 미래 정답 |
| H | 현재 확인창보다 앞선 발행자 원판·정정/이전 공지·배포 멤버의 날짜 있는 원문 | 오늘 상태, 유지/교체 권고, 평가용 답안, 수집자의 성공/실패 해석 |

N의 상태와 현재 절이 본래 과거 이력을 설명하면 삭제로 자연 문서를 왜곡하지 말고 `current_contains_history=true`와 겹친 위치를 기록한다. 기본 분석과 그 사례 제외 분석을 모두 낸다. H는 오늘 내려받더라도 사건 날짜가 과거일 수 있다. 조회 UTC를 H의 사건 시각과 혼동하지 않는다. 발행일을 모르면 모른다고 둔다.

절단은 각 조각의 동일 규칙으로 정한다. 예: DOM의 명시한 element/제목 다음 문단, 원본 위치·정규화 규칙·최대 UTF-8 바이트·절단점·excerpt hash를 기록한다. 길이 한도를 초과하면 후속 결과를 본 뒤 핵심 문구만 골라 바꾸지 말고 버전이 다른 카드로 남긴다. 원문 없이 모델이 만든 설명을 발행자 발췌로 부르지 않는다.

각 view는 저장된 B/N/H 바이트를 단순 조합한다. B+N과 B+N+H에서 N의 byte sequence·순서·길이·hash가 같고 B+H와 B+N+H에서 H가 같아야 한다. 누락 H는 빈 문자열로 보존하며 '없다'라는 사실을 '불필요하다'로 해석하지 않는다. 보기 사이 설명 문구의 차이로 정답을 알려 주지 않는다.

## 4. 사전 행동 규칙

`유지`: 제공된 근거가 원 href의 현재 도착에서 원 목적·대상·요구 판을 충족함을 보인다. `교체`: 같은 목적의 대체 목적지가 필요함을 보여 준다. 교체 필요와 구체 대체 URI 검증은 별도 열이다. `보류`: 목적이 애매하거나 현재 도착·해당 절·판 적합성이 결정 불가하다. HTTP 200만으로 유지를 정하지 않는다. 404만으로 특정 새 URI가 맞다고 정하지 않는다. 오래된 판이라는 이유만으로 최신판 교체를 정하지 않는다. 역사 원문을 재현하는 목적에서 새 판에 더 나은 설명이 있어도 원판을 없애지 않는다.

행마다 view에 있는 정확한 evidence component와 위치를 인용하고, 행동·이유·대체 URI(있으면)·남은 불확실성을 저장한다. 모델의 배경지식이 이유를 채웠으면 `provider_background=true` 또는 해석 플래그로 표시한다. 48칸이 모두 필요하며 정보가 없는 칸을 삭제하지 않는다.

## 5. 판독자·순서·노출

가능하면 네 개의 새 문맥을 만들고 각 사례의 네 보기를 네 문맥에 한 번씩 배정한다. 권장 배치는 Latin square로, 각 문맥은 사례12개를 한 번씩만 읽고 네 보기 각3개를 받는다. 이렇게 하면 같은 문맥의 동일 사례 재노출을 피하면서 '판독자 하나=보기 하나'의 완전한 교락을 줄인다. 사례 순서·배정 seed 또는 균형 순서는 첫 카드 공개 전에 고정한다. 한 문맥당 한 보기만12개를 읽는 더 단순한 배치도 가능하지만, 판독자와 보기가 완전히 묶인 한계를 적는다.

새 문맥에는 상위 연구대화·결론·같은 사례의 다른 보기·adjudication을 전달하지 않는다. 각 문맥의 packet 파일은 배정된 사례별 보기 하나만 포함하고 원 manuscript 접근이나 웹 재검색은 허용하지 않는다. 네 문맥은 같은 모델의 내부 반복이며 사람 실험으로 부르지 않는다. 실제 입력 hash와 응답 hash를 보존한다. 다른 사례가 같은 프로젝트/목적지에 속해 간접 단서를 줄 수 있으므로 그 중복 노출도 표시한다.

이미 상위 대화·원문·다른 보기 또는 정답을 받은 agent는 새 프로세스여도 엄격 미노출이 아니다. full-history fork는 특히 이 조건을 충족하지 않는다. 한 작업자만 가능하면 사전 규칙에 따른 자체 재판독 48행을 유지하고 엄격 미노출 분모는 0으로 표시한다. 순서를 섞는 것만으로 기억이나 카드 작성자의 해석을 제거했다고 주장하지 않는다. strict0이면 효과가 없다는 증명이 아니라 독립 시험을 하지 못했다는 뜻이다.

## 6. 기준판정과 출처 수

48결정을 원격 봉인한 뒤 기준판정을 작성한다. 발행자 원문의 날짜·배포물·실제 대체 목적지의 정확한 절을 대조한다. 현재 N과 동일한 발췌를 그대로 기준으로 쓰면 `dependent_same_excerpt=true`다. 다른 절·판을 추가 검토했어도 같은 연구자의 자기 판정이라는 점은 유지한다. 다수결은 독립 정답이 아니다. 원 href의 전달 상태와 새 href의 목적 적합성을 분리한다. 기준 보류는 정확도 분자에 넣지 않고, 보류/기준미확정 분모를 따로 낸다.

최소 30고유 외부 원문은 범주별 조건을 각각 확인한다: 소비자 실제 배포 문서12, 현재 적격 본문8, 독립 과거 배포/정정/보존 원자료6, 새 지리·서지의 발행자/소비자 각 한 쌍4. 행 수가 곧 고유 수가 아니다. 같은 manuscript의 byte 동일판·mirror·별도 serialization은 한 중복군이다. 한 자료를 소비자와 H로 재사용해도 고유 총수는 한 번만 센다. H6이 원 소비자12의 재사용뿐이면 '독립적인 과거 원자료6'을 충족했다고 하지 않는다. 검색 요약, archive index, 접근 실패 body, 작업자가 만든 표는 적격 내용이 확인된 외부 원문 수를 늘리지 않는다.

## 7. 비교와 비용 검산

주 비교는 같은 참조의 B+N→B+N+H다. 각 목적 층에서 옳은 유지·옳은 교체·오교체·잘못 유지·보류를 따로 센다. 맞음→틀림, 보류→옳음, 보류→틀림과 변화 없음도 보존한다. 기준 미확정은 따로 분리한다. 제공자 배경·카드 해석·사전 노출 제외, N에 이미 역사 서술이 있는 사례 제외를 각각 재집계한다. H가 바꾼 양성 사건이 0이어도 표본을 갈아 끼우지 않는다.

요청별 ledger에는 시작/끝 UTC·wall elapsed·status·redirect·성공/실패·retry·received byte·stored byte·shared acquisition ID·logical use가 필요하다. decompressed member bytes와 네트워크 응답 bytes를 혼동하지 않는다. 웹 도구가 네트워크 바이트를 주지 않으면 미측정이다. 동일 archive 한 번에서 두 참조를 얻으면 실제 취득1/논리사용2로 나눈다. 카드 길이, 재열람 횟수, 읽기 시간·판정 시간의 측정 여부를 별도 표시한다.

두 번째 요청은 동일 예산·동일 목적을 먼저 고정한다. C1은 다시 취득해야 하는 N 및 필요시 잃어버린 H 경로를, C2는 이미 저장된 판·근거 재사용과 현재 N 재검을 비교한다. 실제 재생과 모의 원가합산을 행별로 구분한다. C0 최초 발견 비용, 인간 노동, 모델 토큰 요금, 실제 서비스 운영 원가는 관측 없으면 미측정이다. 저장 byte 차이가 시간 절감이나 총비용 절감의 관측을 대신하지 않는다.

## 8. 주요 실패 조건

1. 표집의 목적이 '현재 작업'과 '특정 판 재현' 중 어느 것도 명시하지 않으면 목적층을 채우려고 억지 분류하지 않는다. 애매한 층의 크기가 크면 일반화 범위를 줄인다.
2. H가 답을 개선해도 더 긴 읽기량·카드 작성자의 단서·기준판정과 같은 발췌 때문이면 역사 정보만의 인과효과라고 할 수 없다.
3. 정확한 판을 보존해도 원판이 원래 틀렸거나 새 URI의 anchor가 없으면 둘 다 있어도 판단 불가할 수 있다. 이 결과는 실패로 지우지 않는다.

결과에 가장 먼저 붙일 한계는 '자료 수와 입력 일치의 기계 검산은 사람이 링크를 누른 결과·인간 노동·서비스 비용·독립적인 사용자 정확도를 검증하지 않는다'다.
