# AF-RES-036 원장·비용·입력 연결 내부 감사

**확인한 snapshot에서 실질적인 산술 오류나 입력 연결 불일치는 발견하지 못했다.** 원문 산입48개, 측정 GET153회, 네 보기48개와 실제 판독 입력48개의 연결을 다시 계산했다. 다만 이 수치를 전체 연구 완료·독립 정답·미노출 효과·최소 운영비로 확대할 수는 없다. 적용 범위와 미확인 조건을 아래에 적었다.

검토자는 이전 연구와 카드 구성 배경을 알고 있는 동일 작성팀 `/root/scope_review`다. 독립 기준판정이나 새로운 미노출 판독이 아니다. 새 기준판정 agent 폴더는 열지 않았고 외부 조회·커밋을 하지 않았다. canonical 원장, 기존 네 판독자의 입력/출력/영수증, 봉인 packet, 모의 재조회 입력만 검토했다. 정확한 입력 SHA와 검산 행은 `ledger-audit.json`에 있다.

R01의 workflow404는 적격 본문에 포함되지 않는다. CX-B05의200 JavaScript shell과 CX-B14의202·0 byte도 본문을 읽은 원문 수에 들어가지 않는다. 오래된 판을 현재 URL에서 전달하는 것과 오늘의 최신판인 것은 구분되어 있다.

## 4. 두 번째 조회 모의의 해석

48개 모의행의 unit attempt ID·요청수·exchange·본문 bytes·2회 예산 여부를 실제 첫 조회 원장과 다시 계산했으며 일치했다. 모든 모의행은 두 번째 조회 미실행, 새 상태·bytes·time 미측정, 원 packet hash 복원 false로 표시한다. 이 구분은 적절하다.

다음 네 가지 범위를 유지해야 한다.

1. **과업 최소비용이 아니다.** `current_decision_N`은 고정 N 구성을 다시 얻는 경로다. G03의2018판 확인 목적에 Shell 절까지 반드시 필요하다는 것은 입증하지 않았다. 따라서 G03의3operations는 고정 N 재구성의 예산 실패이며, 그 최소 목적 자체를2회 안에 해결할 수 없다는 증거가 아니다. 루트에 통보했고 모의행의 설명을 보완한다고 확인받았다.
2. **과거 배포물 전체를 복원하지 않는다.** C2가 로컬에서 읽는 H는 원문 발췌와 source metadata를 합한 exact H text다. 총10,448 logical bytes를 보관해서 수 MB의 tarball/PDF 전체 바이트를 되살린다는 비교가 아니다. 적절한 과업 명칭은 N/H에 사용한 원문 발췌의 재구성이다.
3. **사전 C1은 순수 문맥+href보다 강하다.** B에는 판·배포 URL·member도 들어 있다. 따라서 `C1=B`는 C1*로 명시해야 한다. 순수 문맥+href 조건의 경로 재발견 비용과 판독 효과는 여기서 관측하지 않았다. 루트가 RESULT의 구별과 별도 미계측 시나리오를 추가할 예정이라고 통보했다.
4. **논리 payload는 실제 보관원가가 아니다.** B는10,354B, H 추가는10,448B, 합은20,802B다. 공유파일·JSON·locator·해시·인덱스·실제 저장 구조의 바이트는 별도다. 루트가 구체 보관 레코드 직렬화 계측을 추가하고 있으며, 이 감사는 그 아직 미확인 산출물의 통과를 선언하지 않는다.

같은 자료가 유지되고 정확한 주소·추출 위치를 이미 안다는 oracle 가정은 C1*에 낙관적이다. 실패 경로를 두 번째 조회에 강제로 반복시키지 않은 것은 타당하지만, 주소 재발견 비용이 사라졌다는 실측으로 읽어서는 안 된다. C0 최초 발견·사람 판독·모델 요금·서비스 운영비도 이 비교 밖이다.

## 5.48결정의 입력 연결과 노출

각 packet의 입력 문자열·UTF-8 길이·B/N/H 해시를 재계산했다.12개 사례 모두 BN과BNH의 N이 정확히 같고, BH와BNH의 H가 같으며, 네 보기의 B도 같다.50개의 N/H source alias 연결은 canonical 원장으로 모두 해소된다.

각 판독에 대해서는 `packet.input_text → assignment의 case JSON → case 파일 SHA → reader output.input_sha256 → decisions.csv.input_sha256`를 직접 대조했다. **48/48 일치**하며 네 output 파일 해시도 영수증과 일치한다. `input_sha256`은 packet 문자열이 아니라 실제 배정된 case JSON 파일 바이트의 해시이므로 이 두 해시를 혼동하면 안 된다.

반면 same-case-other-view·배경사용의 보고가0이라는 사실이 간접 노출0을 뜻하지 않는다. **40/48행**에 `prior_related_case_ids`가 있다. 그중 일부는 같은 GNU/Bioconductor 발행 계열이라는 넓은 관계여서 모두 실제 오염이라고 세는 것도 과도하다. 그러나 G01 판독자는 앞선 G03에서 같은 G-N01 조각을 봤고, R05 판독자는 앞선 R06에서 반복되는 intro 본문을 봤다고 명시한다. 같은 프로젝트·공통 목적지·실제 반복 조각을 구분한 민감도가 필요하다.

모든 보고 관계를 제외하는 매우 보수적인 집합은 R06/G05 두 사례다. 이는 넓은 발행자 단서까지 제외한 민감도이며 실제 미노출 효과의 유일한 정답 분모가 아니다. B의 수집자 최소 목적까지 전부 해석으로 제외하는 사전 계약의 분모0도 별도로 보존해야 한다. 필터별·주요 결합별 분모를 실제 `case-overlap`과 `sensitivity` 산출물에서 확인해야 한다.

현재 행동만 보면 BN→BNH의 변경은0/12이고 B와BH는 각각12/12 보류다. **이는 아직 채점하지 않은 행동 동일성이다.** 현재 접근을 확인해야 한다는 고정 규칙, 실제 N 안의 이력 설명, 과거판 층1개/R경로0, 같은 내용의 N/H 중복을 함께 읽어야 한다. 이것을 독립 정확도나 이력 일반의 무효로 부르지 않는다. 새 기준판정은 이 감사에서 보지 않았다.

## 6. Q7의 명시적 정정과 레코드 변경 시각

감사 snapshot의 보조 자료는 Census→BLS 실제 href 쌍, ONS 소급 반례, NLI1953판과 SEP의1953 p.222·번역 지목, Nagoya와 Grub Street의 같은 ESTC 판에 대한 경쟁 보정값을 제공한다. 일반 LOC 규칙·정책은 특정 책의 정정 전후 기록을 대신하지 않는다.2021 논문의 실패 응답은 산입하지 않았다.

**실제 판별 정정 사례가 있다는 것과 동일 catalog 레코드의 날짜 있는 전후 snapshot·갱신 UTC를 확보했다는 것은 다른 조건이다.** 후자는 이 snapshot에서 미확인이다. 보조 분야 각2원문이라는 최소수 충족과 이 한계를 별개로 표시해야 한다.

감사 말미에 루트는 추가 원문2개를 직접 읽었다고 통보했다. [NULDL000040](https://da.adm.thers.ac.jp/en/item/n003-20230901-00040)의 Norton→Warren 명시 정정 및 [Takano2016 논문](https://nagoya.repo.nii.ac.jp/record/21891/files/01_TAKANOAkira.pdf)과 그 [발행·공개일 metadata](https://nagoya.repo.nii.ac.jp/records/21891)다. 이는 실제 정정과 날짜 있는 근거를 보강할 수 있다. **본 감사자는 다시 열지 않았고 현재48개 원문 수에 더하지 않았다.** 따라서 향후 산출물을 "실제 정정 사례가 전혀 없다"고 요약하지 않으며, 레코드 변경 전 바이트·변경 시각의 미확인만 정밀하게 유지한다.

## 7. 수용 판단

산술·범주 합·입력 바이트·판독 연결은 이 snapshot에서 통과한다. 완전한 연구 수용 여부는 아직 판정하지 않았다. 최종 단계에서는 추가 기준판정의 요청·자료 증분, 보관 레코드의 실제 직렬화 바이트, 교차 노출/원문 이력 포함/수집자 해석의 민감도, 서지 정정의 관측 한계를 별도 조건으로 닫아야 한다. 동일 작성팀 내부 감사라는 사실은 추가 원문이나 해시 검산으로 독립 정답으로 바뀌지 않는다.
