## Q4 · dtype과 값, 오류 뒤 상태

- 두 정상 setter의 `4`와 `3.0`이 각각 실제 index 0과 1을 바꿨다. `2.0`만 보면 이미 같은 값이라 no-op도 같은 결과를 낼 수 있다. source와 raw output을 대조해 두 비호환 probe 뒤 [1,2,3] 유지, native guard 원인 및 nullable 검증 위치를 확인했다. 기본 시리즈는 `float64`·`object`로 승격했다. NumPy와 int 변환은 fractional 값을 1로 잘랐고 potage는 둘 다 명시 오류로 거부했다. dtype 일치나 한 종류 오류 하나만 관측해서는 전체 판정이 달라진다. [판독 CSV L20–44](probe-results.csv#L20-L44) · [cast L1931–1966](https://github.com/pandas-dev/pandas/blob/8dab54d6573f7186ff0c3b6364d5e4dd635ff3e7/pandas/core/dtypes/cast.py#L1931-L1966) · [masked L198–237](https://github.com/pandas-dev/pandas/blob/8dab54d6573f7186ff0c3b6364d5e4dd635ff3e7/pandas/core/arrays/masked.py#L198-L237) · [1.5 및 문자열의 당시 pytest L9–55](https://github.com/pandas-dev/pandas/blob/8dab54d6573f7186ff0c3b6364d5e4dd635ff3e7/pandas/tests/arrays/masked/test_indexing.py#L9-L55) · [NumPy 배열 대입](https://numpy.org/doc/1.23/user/basics.indexing.html#assigning-values-to-indexed-arrays)
- numpy can_cast는 별개의 casting 정책이며 일반 setter의 값 보존을 직접 규정하지 않는다. 038의 t0 원 동작은 4 이후 2.0의 연속 대입이고 이번 관측은 2.0을 별도로 reset했다. `Int64`는 생성 스키마의 대안이다. 기존 native 자료의 교체 허용 여부, bool, NA, overflow, 묶음 쓰기는 미확인이다. 입력 정책이 이들을 포함하면 현재의 정수 scalar 결과로 범위를 넓히지 않는다. [NumPy can_cast](https://numpy.org/doc/1.23/reference/generated/numpy.can_cast.html) · [원 드라이버 순서 L273–312](upstream/replay_api_contracts.py#L273-L312)

## Q5 · expectedFailure가 다른 이유로 통과하는 반례
