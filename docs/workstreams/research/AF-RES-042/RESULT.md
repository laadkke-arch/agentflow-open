## 날짜와 정수의 판정

**실측.** 두 공개판에서 초기 두 가지 구현의 정답 계열과 지정 오답을 구별했다. P04는 형식을 결정하는 시점과 실패 위치가 판정에 필요하다. DMY에서 `12-01`과 `13-01`은 1월 12일과 13일이다. 고정 MDY의 두 번째 입력은 월 13이어서 실패해야 한다. 반대로 `12-01/01-13`은 MDY에서 성공하고 DMY에서 두 번째가 실패한다. stdlib에서 `list[datetime]`, 벡터에서 `DatetimeIndex[Timestamp]`가 관측됐다. 오류 뒤 반환 batch는 없었고 원래 리스트는 유지됐다. 벡터 `ValueError`의 정확한 위치는 **같은 format을 개별 요소에 재적용**해 index 1에 좁혔다. B0/B2의 구형 infer 값은 MDY와 우연히 일치하고, B1의 Dec 1/Jan 13이 결함을 구별한다. 엄격 경로의 DMY·MDY는 각각 `%d-%m-%Y %H:%M:%S`, `%m-%d-%Y %H:%M:%S`다. [P04 대응 행 L2–19](probe-results.csv#L2-L19) · [B1-xfail 원로그](evidence/logs/F-P04.driver.json#L89)

**저자와 유지보수자 기록.** PDEP-4 최초판은 같은 B1에서 혼합을 보고했고, 1.4.4 당시 테스트는 추정 형식이 일치하지 않을 때 일반 파서로 되돌아가는 동작을 승인했다. 이슈에는 시각 없는 슬래시 입력에서 경고가 나오며 단일값에서도 나올 수 있다는 기록이 있다. 이번 고정 43행은 각각 경고 0이었다. 선례의 경고 정책을 근거로 이번 입력의 성공이나 실패를 추정하면 오판할 수 있다. [PDEP-4 L24–51](https://github.com/pandas-dev/pandas/blob/e59b6ffd4881ecebb1d3739080d16e162660ae83/web/pandas/pdeps/0004-consistent-to-datetime-parsing.md#L24-L51) · [당시 테스트 L2033–2068](https://github.com/pandas-dev/pandas/blob/ca60aab7340d9989d9428e11a51467658190bb6b/pandas/tests/tools/test_to_datetime.py#L2033-L2068) · [경고 보고 #12585](https://github.com/pandas-dev/pandas/issues/12585)

**실측.** P06은 `int64`의 앞단 guard와 생성 때 정한 `Int64` 모두 int `4`와 float `2.0`, `3.0`을 받았다. `2.0`은 대상이 이미 2라서 단독으로 대입 여부를 판별하기 어렵다. 독립 `3.0`은 실제 index 1을 바꿨고 두 정답 경로에서는 뒤의 `1.5`와 `'potage'` 오류 후 각각 `[1,2,3]`과 선언 dtype이 유지됐다. native guard의 외부 `TypeError`에는 `LossySetitemError` 원인이 있고 nullable 경로의 오류는 `_validate_setitem_value`에서 발생했다. guard를 직접 두지 않은 1.5.2 기본 Series 대입은 `float64`·`object`로 승격했다. NumPy 배정과 E3에 대응한 명시 `int()` 강제 변환은 둘 다 `1.5`를 `1`로 저장하고 `int64`를 유지했다. 두 절삭 경로 모두 동일 초기 상태의 `potage`는 거부했다. 초기 상태·최종 상태·접근 시의 스칼라 타입·값/타입이 변경된 위치를 CSV에 남겼다. **해석.** 날짜 생산자가 DMY 또는 MDY를 선언할 수 있으면 한 번 선언한 형식은 설명하기 쉽다. 생산자 표기가 불명확하면 일회 추론이 입력을 바로 읽어주지만, 첫 값이 모호할 때도 뒤의 비호환 값을 거부한다. 모호성을 줄여야 하면 원 생산자가 형식을 붙이거나 별도의 혼합 허용 계약이 필요하다. 정수 생산자에게 작은 정수 계약이 고정돼 있으면 native guard로 스키마를 유지할 수 있고, 생성 시 nullable 스키마를 고를 수 있으면 그 setter가 이 범위를 충족한다. 값과 dtype이 각각 중요한 분석 소비자에게는 호환 값의 실제 변경과 비호환 오류 후 상태가 모두 필요하다. pandas 후대 구현과 승격 경고 정책은 별도로 문서화됐다.
