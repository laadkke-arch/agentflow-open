## 표집

전체 64이유×16분기 1,024셀. T0는 표집에서 제외하고 기준 실행으로 쓴다. 유지 897셀을 계열별 16개, 무효 95셀에서 각 계열 4개씩 뽑는다. 무효 한쪽의 모집틀이 4개 미만이면 부족분만 상대 계열로 옮긴다. 최초 오류 16셀 및 과거 보류 16셀에서 계열 통합 각 1개를 뽑는다. 최초 상태 그룹에서 같은 이유의 분기 셀을 독립 이유로 세지 않는다.

`draw.py`의 고정 시드와 단계명이 들어간 SHA-256 순위로 층 안에서 단순무작위 비복원 추출을 구현한다. 정렬 충돌은 중단한다. 각 층에서 오름차순 처음 n개를 쓰고, 별도 단계로 전체 42개를 섞어 연속 익명 ID를 붙인다. 균등 순열 모형에서 한 셀의 포함확률은 해당 층의 n/N이다. 고정 시드는 재생을 위한 의사난수다. 이유·판·분기 중복을 보존하고 같은 주장은 하나의 검사를 재사용한다. 이유 군, 목표판 군, 기존 변경 표식, S 신호, 절 존재 분모는 공개 후 계산한다.

큐 필드는 익명 ID, 계열, 원 주장 문장, 원 환경, 분기, T0와 목표판의 공개 태그·커밋·컷오프·배포일이다. 표집 프로그램만 `timeline.jsonl`의 층·행 메타데이터를 읽고 `cohort.csv`·`claims.json`·`releases.csv`·`snapshots/*.jsonl`와 대조한다. 답은 임시 경로에 저장하고 해시만 공개한다. 프로그램이 선택층·개별 근거 URL·종료 사유를 판독 표면으로 보내지 않는다. 계약/관측 봉인 뒤 024의 판정·D/S 원장으로 조인한다. 반복 실행은 빈 임시 작업 디렉터리와 동일한 획득 캐시 및 고정 코드를 사용한다.

## 판정 계획

1. 양·경계 입력, 호출, 예상 반환·예외·부작용을 T0 공식 원문과 연결해 표집 후 실행 전에 커밋한다. 이름 존재와 원 용도 달성은 다르다. 예제의 좁은 의미와 다른 플랫폼·입력에 대한 보장은 구별한다.
2. Linux x86-64의 Node 공식 바이너리와 CPython 공식 태그 소스 빌드를 우선한다. 원 바이너리가 필요하고 못 구하면 같은 태그의 빌드 또는 공식 당시 테스트 영수증, 그 뒤 정적 판독을 찾는다. 동일 태그의 직접 실행도 별도 빌드·OS 조건을 기록한다. 배포일·태그·해시·버전·아키텍처·기준 옵션을 기록한다.
3. 양·경계 테스트의 실제 관측과 환경을 따로 보존한다. T0 양성 조건 자체가 불성립하면 최초 오류 후보, 준비 불충분 또는 해석이 모호하면 보류다. T0 양성과 경계가 성립하고 목표판 원 주장 조건이 깨지면 무효다. 경고만 추가되면 별도 관측이다. 경계에서만 차이가 나면 해당 입력이 원 주장에 포함되는지를 판정한다. 주장 의미를 벗어난 추가 가정이 발견되면 원 계약·결과를 보존하고 변경을 새 판으로 남긴다.
4. 직접 쌍, 공식 과거 실행, 정적 판독, 환경 부재는 증거 등급을 분리한다. 정책 혼동표는 20회 한도의 D/S 예측 상태를 그대로 둔다. 표본의 옛 분모와 신참값 채점 가능 분모의 차이를 보이고, 보류·최초 오류는 이진 혼동표에서 검열한다. 유지 32셀의 미확인 양끝을 계산한다. 대조 10셀의 오류율을 모집단 추정에 합치지 않는다.
5. 024의 전체 방문·시점·비용 재생, 새 경보/크롤러, 타 생태계 발생률 추정은 범위 밖이다. 실행 실패와 조건부 성립을 포함한 42행이 우선이며 주 표본의 각 계열 직접 실행 쌍 목표는 8셀 이상이다.
