## Q1 · 최초 가용 본문과 조작

M03이 말한 가운데는 색 막대의 내부 중심이다. B는 그 예제의 `cb.ax.text(.5,.5)` 기본 좌표를 그대로 둔다. A는 작성자가 수락한 `cb.ax.transAxes` 인자만 추가한다. M02에는 30개가 넘칠 때 고정 글꼴로 두 데이터 축을 유지하려는 요구가 있다. ## Q3 · 중앙은 축 비율로 보존된다

3.0.2에서 이 imshow/Normalize 경로는 `norm.inverse`를 수직 막대의 x와 y 양쪽에 적용한다. 실제 limits와 선형·정방향 전제를 세 시점에 각각 확인했다. 그 조건에서 B의 .01은 양축 50/99, .001은 500/99였다. .01 B는 글자가 화면 안에서 보이고 A보다 저장 anchor가 y 방향으로 1.6302px 높았다. 독립 잉크 bbox의 시작 행은 2px 높았다. .001 B는 layout 시도 직후 y=1599.5556px로 400px 캔버스 바깥이며, TypeError 이전의 layout 경고와 이후 미시도 저장을 나눠 기록했다. A의 .01/.001 x 픽셀은 각각 420.9653/416.5903이지만 세 시점의 두 축 비율은 .5다. ## Q7 · 설계자에게 돌려줄 판단

인쇄에서 CSS 페이지 위 가운데 box는 페이지 border의 수평 가운데를 보존한다. XSL-FO에서는 같은 이름의 페이지 영역에 정적 내용을 되풀이해 본문 흐름과 영역을 분리한다. Adobe의 현행 Custom 옵션은 x와 y의 페이지·프레임·baseline 기준을 각각 선택할 수 있다. Writer의 문단·문자 anchor는 인쇄 도구에서도 대상 내용을 따라가는 반례다. 지도에서 Maplex는 라벨과 지물의 대응을 우선하고 배치·서체·밀도·충돌 정책을 바꾼다. QGIS의 가시 polygon과 전체 polygon centroid 선택은 지도에서도 보이는 프레임과 전체 대상의 목표가 갈릴 수 있음을 보인다. Ordnance Survey의 강 양쪽 사례와 Mapbox의 충돌 시 아이콘만 남기는 옵션은 지물 대응과 화면 표기가 별개의 조건임을 드러낸다. [인쇄 원장 P01–P04](sources.jsonl) · [지도 원장 M01–M04](sources.jsonl)

사용자는 M03에서 보이는 중앙과 M02에서 데이터 축을 원했다. 차트를 해석하는 독자에게는 정확한 값과 범례 완전성이 달라지는 비용이다. 유지보수자는 독립적인 None 예외 회귀와 배치 거부 상태를 확인할 필요가 있으며 해당 결과를 좌표 보장으로 확대할 수 없다. 3.0.2의 `Axes.text` 예제와 Tight Layout Guide만으로 실제 조작 A와 B에 도달할 수 있다.
