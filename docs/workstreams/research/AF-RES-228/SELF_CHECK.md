## 실패, 정정, 남은 범위

- 먼저 읽은 선행 인계에 가설이 적혀 있었다. SCOPE의 첫 커밋에 이 노출을 표시했다. 고정판 원문을 열어 중립 파일명 예상과 GUID/링크 분기를 수정한 뒤 두 번째 커밋으로 고정했다. 원형 수신은 그 뒤 실행했다.
- 첫 컨테이너는 모든 capability를 빼면서 작업용 bind mount의 읽기 권한 오류로 PHP 전 단계에서 중단됐다. 기본 컨테이너 권한과 no-new-privileges로 해결했다. 외부 통신 차단과 읽기 전용 입력은 계속 적용했다. 첫 검산의 앱 로그 수집이 `*.log`만 찾던 문제를 `log.txt`로 수정하고 네 시작점을 다시 만들었다. 첫 검산 8회는 비교용으로 보고했다. [실패 및 사전검산 영수증](receipts/preflight-main/), [최종 주실험 영수증](receipts/container-main.json).
- 주실험/통제/재생의 원본 Git archive SHA-256과 이미지 ID는 각각 같다. 스냅샷의 새 행 ID와 시간이 새 컨테이너에서 달라진다. 재생은 그 두 필드를 제외한 피드와 조인된 항목·관계 값을 비교했다. 새 환경에서 양성 3행과 음성 2행이 재현됐다. [실행 로그](receipts/container-replay.json).
- 실제 사용자의 계정 전체, 원 RSS GUID, 운영 플러그인·동시 실행·다른 DB 엔진, 구독 갱신·purge, 웹 UI 검사는 미실시다. 숫자 `0`이 있는 행과 실제로 조인되는 행이 없는 통제, 과제에서 관측하지 않은 값을 구분했다. [남은 약점](RESULT.md).
