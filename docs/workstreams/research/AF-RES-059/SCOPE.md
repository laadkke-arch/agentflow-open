## 모집

- 대상은 이름을 정규화한 PyPI `tzdata`와 npm의 정확한 비스코프 이름 `moment-timezone`이다. UTC `[2023-03-20T00:00:00Z, 2023-04-11T00:00:00Z)`에서 공식 목록에 보이는 모든 정식판과 바로 앞·뒤 각 하나를 모집한다. PyPI는 PEP 440의 pre/dev를 제외하고 정식 post가 있으면 별도 판으로 남긴다. npm은 정식 SemVer만 포함한다. dist-tag나 현재 latest는 기준에서 쓰지 않는다.
- PyPI 판 시각은 현재 기록에서 가장 이른 파일 업로드 UTC다. 같은 판의 wheel과 sdist를 모두 기록하고 wheel 전체를 본 실행 대상으로 삼는다. 파일마다 업로드 시각, yanked 상태와 이유, 해시, 크기, 원 주소와 최종 주소를 보존한다. 선택판의 sdist는 내장 생성 입력과 데이터 귀속을 대조한다. 버전 게시 후 wheel 추가가 있다면 파일별 공개시각이 우선이다. 명시적 철회 파일도 게시판 모집에서 제거하지 않고 당시/현재 이용 가능성을 별도로 적는다. 파일 목록이 빈 판과 404·403·해시 불일치·철회·중간 상류판을 안 담은 배포에는 서로 다른 상태를 쓴다.
- npm은 packument의 `time[version]`으로 판을 정렬한다. `versions[version].dist`의 tarball 하나와 SHA-512 integrity, 배포 크기를 기록한다. time만 남은 행, dist의 deprecation 표시, 현재 조회 불가를 따로 기록한다. 정식판의 전후 동시각은 버전 정렬로 타이를 정하고 창 내 동시각은 전부 포함한다. 파일은 게시시각, 파일명, digest 순으로 정렬한다. 같은 라벨의 바이트 변경을 확인하려면 두 시점의 파일 영수증이 필요하다. 현재 목록에 없는 완전 삭제 이력, npm 재게시 유무, 당시 CDN 가용성은 확인 단계가 별도다.
- 소비 후보는 `pandas-dev/pandas`, `grafana/grafana`다. 공개 GitHub release의 `published_at`을 우선해 같은 창과 앞뒤 정식판을 조사한다. 태그·프로젝트의 공개 다운로드 기록이 release API에서 빠지거나 서로 시간을 달리하면 별도로 기록한다. RC/nightly는 정식 모집 분모에서 제외하고 관측하면 원장에 남긴다. 동일 날짜에 복수 유지보수 계열이 있으면 모두 조사한다. 릴리스 날짜와 고정 트리 경로 순으로 배포 의존 선언·잠금·빌드·로그·artifact를 연다. 잠금은 해결된 판의 후보이고, 실제 설치에는 설치 영수증 또는 배포 이미지·파일의 축출 근거가, 해당 변환 실행에는 그 멤버와 입력·출력 결합 기록이 더 필요하다.

## 출력 봉인과 반증

- 판 선택은 공개 시각으로 먼저 정한다. 배포물의 변환값을 보기 전에 이름, URL, 배포 해시, 대응 후보 상류판과 입력별 예상을 추가 봉인한다. 상류 출처 예약 ID는 `IANA-A/B/C/US/TZIF`, 실행 키는 `B21/B23/N21/N23`이다. 예상은 레이블 검증의 독립 증거가 아니다. 레이블·생성물/원규칙·전환 지문이 충돌하면 귀속을 보류한다. 같은 값인 a와 c는 그 값만으로 구별하지 못한다. 이 단계에서 읽은 값은 055에서 물려받은 상류 기준뿐이다.
- UTC에서 현지로 계산한다. 순서는 베이루트 21Z, 23Z, 뉴욕 21Z, 23Z이고 관측 단위는 UTC 동쪽이 양인 정수 초, ISO 현지 달력 시각(초 포함), 로더의 약칭이다. 날짜 경계와 독립 판별값은 오프셋만 같아도 함께 검사한다. ZoneInfo는 wheel TZif를 명시 경로로 연다. Moment는 고정 의존과 npm tarball에서 나온 기본 전체 자료를 로드한다. npm `moment`는 창 종료 직전 공개 정식판 가운데 모든 본판의 선언 범위를 만족하는 최신판 하나를 고정한다. 로드 경로와 해시, 배포 멤버의 원본 해시 연결을 남긴다.
- 각 배포 파일을 새 디렉터리에 풀고 별도 프로세스로 실행한다. 두 번째는 또 다른 디렉터리에서 배포 순서만 반대로 하며 네 입력 순서는 유지한다. 실패도 입력별 자리를 유지한다. 전환 전후 검사는 본 네 입력과 별도다. npm 축소 bundle, 기본 Python OS/패키지 fallback, Node 호스트 런타임, 오래된 파일에 새 라벨, 현지시각을 UTC 입력으로 오인한 경우도 본 분모에서 분리한다. 설치 대신 사용한 실제 해제 방법과 검증 선을 남긴다.
- B21의 중간판 대비가 주 반증이다. B23과 뉴욕은 같은 값만으로 판을 맞힐 수 없음을 시험한다. 문서/태그 발견 시각, 공개 배포 시각, 실사용 시각을 분리한다. 앞뒤 관측만으로 설치 지연을 숫자 하나로 쓰지 않는다. 상류 변경 시작/끝을 재는 시계(태그·공지·tar 디렉터리)마다 지연을 따로 계산한다.
- 타 분야는 BLS JOLTS 비농업 전체 계절조정 일자리 공석 계열 `JTS000000000000000JOL`과 ALFRED `JTSJOL`의 2024년 1월 관측을 우선한다. 2024-03-06 첫 발표와 2024-04-02 다음 발표/빈티지를 조회한다. 어느 쪽 수치도 이 봉인에 선입력하지 않는다. 동등한 월·단위·조정 조건과 발표 빈티지의 실측 여부를 개별 판단한다. 055의 2024년 3월 CES는 제외한다.
