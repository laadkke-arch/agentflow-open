## Q2. 라벨·생성·실제 데이터

wheel에서는 `METADATA`, IANA 라벨, `tzdata.zi`, 두 TZif를 읽었다. 같은 버전의 wheel·sdist·공개 태그에서 네 비교 멤버가 각각 일치했다. 압축 아카이브의 크기와 해시는 두 파일이 달랐다. ## Q3. 실제 로드와 수작업 검산

Cloud의 Python 3.12.14와 Node 24.22.1에서 archive digest를 확인하고 각 파일을 따로 해제했다. Python은 절대 경로 파일을 열어 TZif 바이트를 `ZoneInfo.from_file`에 넘겼다. Node는 Moment 2.29.4와 대상 tar의 기본 진입점 및 모듈의 packed JSON을 로드했다. 프로세스의 stdout·stderr·입력·종료, 모듈 경로·해시와 `openat`을 기록했다. 앞뒤 두 차례 18개 독립 프로세스에서 네 본 입력을 읽은 72/72가 일치했다. 전환 두 경계의 전후 72/72 지문도 맞았다. 최초 스크립트는 내장 `_zoneinfo`의 파일 속성을 가정해 실패했고, 런타임 위치를 내장 여부에 따라 기록한 새 폴더에서 재실행했다. [실행 영수증](evidence/run-receipts.json) · [경계 원장](evidence/fingerprints.jsonl)

Beirut 표준시의 +02에 DST +01을 더하면 +10,800초다. b에서는 4월 21일 현지 표준시 00:00이 4월 20일 22:00Z다. 21:00Z에는 아직 표준시 +7,200초이며 23:00Z에는 +10,800초다. 3월 규칙을 쓰는 판은 3월 25일 22:00Z에 이미 바뀐다. 뉴욕은 3월 두 번째 일요일부터 DST가 적용되어 4월의 표준 -05 +01이 -14,400초다. ## Q5. 소비자가 실제로 어느 판을 썼는가

공개 GitHub Release의 `published_at`으로 pandas 3개와 Grafana 6개를 골랐다. 공개 npm `@grafana/data`의 끝 이후 첫판은 9.5.0이라 GitHub 기준 첫판 9.2.17과 달랐다. 9.5.0은 감도로 보존했다. Grafana 9.4.0 Release는 관측 API에서 prerelease로 찍혀 정식 창 분모에서 제외했다. 샘플 패키지 수와 GitHub Release의 날짜순이 맞아도 소스 커밋·패키지 원본·공지의 시계는 여전히 각각이다. [소비 릴리스 프레임](evidence/consumer-releases.json) · [PyPI/npm 대조](evidence/consumer-index-crosscheck.json)

- pandas v2.0.0과 v2.0.1의 CPython 3.11 manylinux x86-64 wheel 세트에서 각각 `tzdata>=2022.1`을 읽었다. v1.5.3 wheel에는 해당 의존이 없었다. 태그의 트리와 이름이 정해진 잠금 후보를 살폈고 해당 런타임 판을 못 박는 배포 잠금을 찾지 못했다. v2.0.0 코드에서 일반 문자열이 pytz 경로로 가는 분기, dateutil 경로, ZoneInfo 객체를 인정하는 경로를 확인했다. 같은 `tzdata`를 환경에 설치한 경우에도 일반 문자열의 변환 공급자를 다르게 고를 수 있다. [의존 및 코드](evidence/consumer-code.json) · [wheel 검사](evidence/consumer-artifacts.json)
- Grafana GitHub 창 안의 네 정식판에서 잠금과 공식 `@grafana/data` 라이브러리의 선언은 모두 0.5.34–0.5.38이었다. 라이브러리 등록 자료는 별도 모듈을 선언하고, 읽은 관련 번들에서 확인 가능한 ESM import를 가리킨다. 정의된 `yarn install`과 `yarn build`, 해당 버전의 Syft 첨부물이 이를 뒷받침한다. 그 첨부물의 `sourceInfo`는 `yarn.lock`이며 `filesAnalyzed=false`라 잠금 수준에서 센다. ## Q6. 반례와 기록별 비용

오래된 파일을 b 설치 사본의 새 라벨 아래에 두자 양쪽 모두 B21에 +10,800 EEST를 냈다. Python은 Beirut TZif만 바꿨고 Node는 예전 packed 파일을 바꾸면서 현재 판 표기까지 넣었다. 의도한 멤버 해시에서 두 경우 2/2를 거절했으며, 두 런타임 모두 오래된 archive 자체를 새 판 해시로 바꿔 제시한 경우도 거절했다. 이 값들은 고의로 주입했다. 공식 tar와 wheel에서 대응 결함을 관측한 수는 0이다. [통제 출력](evidence/controls.jsonl) · [바이트 거절 시험](evidence/cost-receipts.json)

같은 b wheel이 설치된 상태에서 Python 일반 조회의 첫 파일은 호스트 `/usr/share/zoneinfo/Asia/Beirut`였고 +10,800초였다. 빈 `PYTHONTZPATH`에서 패키지 fallback을 써서 +7,200초가 나왔다. Node의 이 호스트 ICU 78.3, tz 2026e는 +10,800초와 로캘 단축 표시 GMT+3을 반환했다. 입력의 `Z`를 떼고 같은 숫자를 베이루트 현지로 읽으면 두 런타임 모두 실제로 19:00Z라는 다른 순간을 계산한다. 오프셋 +7,200이 같아도 현지 출력은 21:00이다. [호스트와 입력 경계](evidence/controls.jsonl) · [열린 파일 trace](evidence/run-receipts.json)

## Q7. 통계 개정과 사용 조건

BLS JOLTS 원표의 2024년 1월 미국 비농업 전체 계절조정 공석은 2024-03-06 공표에서 8,863천 건, 04-02 공표에서 8,748천 건으로 115천 건 하향됐다. 두 표의 1월 공석률은 반올림 5.3%로 같다. 3월 6일 공표는 연례 기초 고용값·계절조정 업데이트를 설명하고, 4월 2일의 월간 개정은 추가 보고와 계절요인 재계산을 적는다. ALFRED의 JTSJOL은 원 발행자, 월, 천 건, 계절조정이 같고 다운로드 설명은 관측월과 빈티지 날짜가 두 축임을 확인해 준다. 2024-03-06 및 04-02 두 열의 2024-01 행은 현 도구에서 미확인이다. BLS 두 숫자를 ALFRED 셀로 기입하려면 보관처에서 직접 받은 판별 열이 필요하다. 통계 사용자의 과거 분석 증명에도 계열·통계일·빈티지·GET/파일 해시·실행 키가 각각 필요하다.
