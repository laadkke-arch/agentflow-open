# 공식 생성·호스팅·상대 경로 근거

- **M01** [Getting permanent links / Press Y](https://docs.github.com/en/repositories/working-with-files/using-files/getting-permanent-links-to-files): Commit ID binds the selected file version; a branch-head file can change. This fixes the file content, not external links embedded inside it. 한계: File-link policy; no guarantee that external linked resources are pinned or the repository remains accessible. Publication UTC unspecified.
- **M02** [Viewing HTML elements / Rendering differences](https://docs.github.com/en/repositories/working-with-files/using-files/working-with-non-code-files): GitHub distinguishes source and rendered views and documents that HTML commit rich views are not directly supported. The R1/R2 live browser observations independently establish source display for these exact blob URLs. 한계: The cited policy section concerns commit/diff rendering. Do not generalize it alone into a comprehensive MIME policy for all raw URLs. Publication UTC unspecified.
- **M03** [2.4.3 Document base URLs](https://html.spec.whatwg.org/multipage/urls-and-fetching.html): HTML URL resolution uses the first base element with href, otherwise the document fallback URL (subject to override/about-document cases). Identical HTML at a different base can resolve relative resources differently. 한계: Normative resolution rule, not proof of any target payload availability. GitHub code is text, so source href is not automatically a live anchor. Publication UTC unspecified.
- **M04** [External files; Output formats](https://pkgdown.r-lib.org/reference/build_articles.html): pkgdown copies linked images via external-resource detection; resource_files can explicitly list files when detection fails. Independently hosted Shiny iframes are described separately. A page file and a complete resource set are different preservation units. 한계: Current documentation does not prove how archive/asciicast historical files were built. No build was executed. Publication UTC unspecified.
- **M05** [URL schemes; How to change](https://docs.readthedocs.com/platform/stable/versioning-schemes.html): RTD permits multi-version paths with language/version prefixes and single-version roots. Changing a versioning scheme can break existing links unless redirects are provided. URL structure is configuration, not a content-version attestation. 한계: General current policy; no inference that this configuration change caused P1 named404. Publication UTC unspecified.
- **M06** [Linking to pages; file layout](https://www.mkdocs.org/user-guide/writing-your-docs/): MkDocs rewrites links to source Markdown into HTML output paths, adjusts relative paths, and leaves absolute paths unchanged. Source URI and generated URI are not interchangeable. Header fragments are preserved while the path is transformed. 한계: Current help; does not prove historical generator behavior or make an external destination same-version. Publication UTC unspecified.
- **M07** [Referencing downloadable files / download role](https://www.sphinx-doc.org/en/master/usage/referencing.html): Sphinx download role copies referenced downloadable files into a hashed _downloads directory and emits a link for HTML output. This is a concrete way to preserve a document plus next file rather than only its source URI. 한계: General documented mechanism; the existence of a role in source does not itself prove the output resource exists in a given project build. Publication UTC unspecified.
