## 직접 실행하지 못한 검사·명령과 입력

현재 환경에서 `python3.10`과 `docker` 실행파일은 둘 다 찾지 못했다. 관측한 interpreter는3.12.14다. 역사 버전의 import/API/전체 build를 수행하지 않았고 실행 성공을 추정하지 않았다. 후속 실행은 `streams/pandas/execution-next.md`의 Docker image 실제digest·wheel SHA·freeze·stderr·종료코드 절차를 먼저 따른다. 이 파일의 NumPy1.23.5 등은 API 재현용 선택 lock이며 당시 환경에서 복구한 lock이 아니다.

그 파일의 **별도 Python3.10.6 환경**에서 실행할 driver 명령은 다음과 같다. P04 환경은 pandas1.4.4, P06 환경은 pandas1.5.2이며 각 환경에 명시된 의존판을 둔다.


입력은 P04 t0 `['01-01-2000 00:00:00','02-01-2000 00:00:00']`, t1의 `12-01/13-01` 및 `12-01/01-13` 두 독립batch다. explicit 배열/행 파싱과 infer-once strict를 대조하며 MDY의 정당한 오류도 허용한다. P06는 매번 선언 dtype의 `[1,2,3]`에서 int4, float2.0/3.0/1.5, text'potage'를 검사한다. 값/타입 literal과 오류 후 값·dtype을 기록한다. 드라이버의 잘못된 관행 대조 expectedFailure(P04 1개/P06 3개)는 성공 대안 수에 합치지 않는다. 실제 테스트 결과는 아직 없다.

P02의 다음 실행은 전체 build가 아니라 고정 POC source와 CI 기록의 당시 resolved 의존 SHA 확인이다. 정확한 clone/fetch/show·check-runs/PR 댓글 조회 명령은 `execution-next.md` P02절에 있고 입력은 CMake POC `d62f894c3ec08b721de0499cabe2c58a6e322496`, Meson POC `7e401dc31ca155fcc7b3128ee7a7b43989c71da3`다. closure가 확인되지 않으면 복원 미확인으로 종료한다. N08의 NumPy1.4.0 commit `4b42c8f6b81d87f35ed8dcf4430224992cf2d296` 실제 실행도 미실시이며 현재 관측은 주어진6행의 산술/의사코드에 한정된다.

원자료 구조 검사를 다시 할 명령과 입력은 다음과 같다. assembler나 seal_examples를 재실행해 과거 봉인·기대/실제 판독을 덮지 말고, 변경은 새 판과 커밋으로 남긴다.
