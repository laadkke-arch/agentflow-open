# P06 · 정수 편집기의 dtype 계약 · t0

공개 인터넷 검색, 실행 도구, 도움 요청 규칙, 교육과 작업 예산은 모든 보기에서 같습니다. 진행자가 사전에 공통 공지한 예산·재검 간격·도구 정책을 적용하세요. 첫 채택을 선언할 때 결정 ID와 제출판을 고정하세요. 찾은 자료와 사전 인지를 기록하고, 실행하지 않은 결과는 미확인으로 적으세요. 후대 자료를 발견했다면 URL·판·첫 노출을 기록하세요. 이 과제는 문서·의사코드의 요구 합치성을 판독하며, 실행하지 않은 성공을 요구하지 않습니다.

## 상황과 최초 요구

새로 만드는 작은 정수 편집 컴포넌트의 대입 방식을 선택합니다. 계획 기준은 2022-12-23의 formal proposal입니다. 생성 때 native int64 또는 nullable Int64 schema를 명시할 수 있으며, 생성 뒤에는 그 dtype 자체가 계약입니다. 이미 존재하는 native 컨테이너를 다른 dtype으로 바꾸는 작업이 아닙니다.

- P06-R1: setitem 뒤에도 생성 때 정한 dtype을 보존하세요.
- P06-R2: 호환되는 정수와 정수값 float는 손실 없이 저장하세요.
- P06-R3: 비호환 fractional/text 값은 조용히 자르거나 dtype을 승격하지 말고 오류를 내세요. 오류 뒤에는 원래 값과 dtype이 유지되어야 합니다.

초깃값은 [1,2,3]입니다. t0에서 index0=4와 index1=2.0을 처리하는 경로를 설명하세요. 검사 범위는 작은 수의 scalar 정수·정수값 float·fractional float와 부적합 text입니다. NA/NaN, overflow, bool, vector/slice 대입과 전체 API는 별도 범위입니다.

## 제출

생성 schema, 호환성 판단 위치, 검증과 실제 쓰기의 순서, 실패 시 동작, 대안 하나와 근거 절을 적으세요. 독자적으로 조합한 guard라면 공식 완성 recipe와 구별하고 실제 실행 여부를 적으세요. 결정 ID D-P06-SCHEMA와 D-P06-COMPATIBILITY, 첫 채택 선언과 제출판을 고정하세요.
