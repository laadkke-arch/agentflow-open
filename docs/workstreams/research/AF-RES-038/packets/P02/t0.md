# P02 · 빌드 구조 선택 · t0

공개 인터넷 검색, 실행 도구, 도움 요청 규칙, 교육과 작업 예산은 모든 보기에서 같습니다. 진행자가 사전에 공통 공지한 예산·재검 간격·도구 정책을 적용하세요. 첫 채택을 선언할 때 결정 ID와 제출판을 고정하세요. 찾은 자료와 사전 인지를 기록하고, 실행하지 않은 결과는 미확인으로 적으세요. 후대 자료를 발견했다면 URL·판·첫 노출을 기록하세요. 이 과제는 문서·의사코드의 요구 합치성을 판독하며, 실행하지 않은 성공을 요구하지 않습니다.

## 상황과 최초 요구

native extension을 포함한 Python 패키지의 빌드 구조를 선택합니다. 현재 컴파일 대상·의존·생성 로직이 하나의 setup 스크립트에 모여 있으며 개발 중의 병렬화가 source-distribution 설치에는 제대로 이어지지 않습니다. 계획 기준 시점은 2022-08-06입니다. 새로운 공개 자료를 발견했다면 노출 기록에 남기세요.

- P02-R1: 컴파일 대상·의존·생성 규칙을 명시적인 빌드 graph 또는 동등한 구조로 분리하고, Python metadata/배포 산출 책임과의 경계를 제안하세요. 파일 이름이나 파일 개수 자체는 평가 기준이 아닙니다.
- P02-R2: 개발 build와 source-distribution을 푼 뒤 설치하는 build 양쪽에 병렬 가능한 컴파일 경로가 있어야 합니다.
- P02-R3: 표준 Python frontend/backend 경계에서 native artifact와 wheel/sdist 입력·출력을 연결하세요.

packaging과 metadata를 기존 라이브러리에 위임하는 구조도 가능합니다. 특정 도구 이름, 문법 선호, 이후 널리 채택되었는지는 합격 조건이 아닙니다.

## 제출

채택할 구조와 대안 하나, 컴파일 graph/개발 명령/표준 backend/wheel·sdist의 연결, worker 설정 전달, 필요한 source archive 입력, 근거 절과 적용 한계를 적으세요. 실제 빌드를 하지 않았다면 검증 계획과 미확인을 구별하세요. 완성 pandas 전체를 구현하는 과제가 아닙니다.
