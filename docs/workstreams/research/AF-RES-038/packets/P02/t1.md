# P02 · 동일 요구 재검 · t1

새 요구를 추가하지 않고 t0 제출의 P02-R1~R3을 다시 확인합니다. 첫 제출판을 보존하고 수정이 있으면 새 판을 만드세요.

1. t0 구조에서 native target과 dependency를 표현하는 책임 영역을 추적하세요. target 하나를 더 선언한다고 가정해 그 경계를 설명하되 실제 새 기능을 구현할 필요는 없습니다. 컴파일 graph의 관리와 packaging 책임이 분리되는지 확인하세요. 파일 이름이나 파일 수는 합격 기준이 아닙니다.
2. source-distribution을 clean directory에 푼 뒤 표준 frontend가 backend를 호출할 때, 개발 때 쓰던 native graph에 도달하고 병렬 worker 설정을 사용할 수 있나요? 두 호출 경로를 적으세요.
3. source archive에 필요한 graph·source·backend 입력이 포함되며 wheel/sdist의 산출 계약을 지키나요? 성공 실행이 없으면 통과한 실행으로 쓰지 말고 확인할 명령과 입력을 적으세요.

각 요구에 유지 / 수정 필요 / 미확인과 근거를 적으세요. 수정한다면 되돌린 결정 ID, 원래 요구 ID, 변경판, 수정 활동을 연결하세요. 기존 metadata/packaging 위임은 그 자체로 위반이 아닙니다. import 때 자동 재빌드 같은 새로운 편의는 별도 제안란에 남기며 이번 재작업으로 가산하지 마세요.
