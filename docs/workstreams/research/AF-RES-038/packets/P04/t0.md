# P04 · 일관된 날짜 파싱 · t0

공개 인터넷 검색, 실행 도구, 도움 요청 규칙, 교육과 작업 예산은 모든 보기에서 같습니다. 진행자가 사전에 공통 공지한 예산·재검 간격·도구 정책을 적용하세요. 첫 채택을 선언할 때 결정 ID와 제출판을 고정하세요. 찾은 자료와 사전 인지를 기록하고, 실행하지 않은 결과는 미확인으로 적으세요. 후대 자료를 발견했다면 URL·판·첫 노출을 기록하세요. 이 과제는 문서·의사코드의 요구 합치성을 판독하며, 실행하지 않은 성공을 요구하지 않습니다.

## 상황과 최초 요구

날짜 문자열 batch를 처리하는 파싱 방식을 선택합니다. 계획 기준 시점은 2022-09-18입니다. 공개된 입력 해석 문제가 동기이며 특정 반환 컨테이너나 가장 빠른 구현을 요구하지 않습니다.

- P04-R1: format을 명시하거나 첫 non-NaN 입력에서 정한 뒤, batch 안의 모든 행에 같은 format을 사용하세요.
- P04-R2: 불일치를 만나면 미리 선언한 errors 정책을 적용하고 다른 날짜 순서로 조용히 전환하지 마세요. 이번 과제의 공통 errors 정책은 raise입니다.
- P04-R3: 선언된 형식에서 불가능한 문자열을 다른 형식으로 바꿔 정상 날짜로 반환하지 마세요.

첫 입력은 ['01-01-2000 00:00:00', '02-01-2000 00:00:00']입니다. DMY와 MDY 중 하나를 암묵적인 정답으로 강요하지 않습니다. 선택한 모드와 format에 맞는 출력 또는 정당한 오류를 평가합니다. 고정된 literal 범위는 year2000의 naive datetime이며 timezone·locale·NA 표현·광범위한 추론 알고리즘은 별도입니다.

## 제출

선택한 방식과 대안 하나, declared_mode(explicit 또는 first-non-NaN inference), declared_format 또는 inference rule, format_used, errors='raise', 첫 입력의 결과와 이유를 적으세요. output 문자열은 ISO 형식으로 정상화해도 됩니다. 근거 절과 실행 여부를 구분하고 결정 ID D-P04-FORMAT을 고정하세요.
