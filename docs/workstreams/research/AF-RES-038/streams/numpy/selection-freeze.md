## 선정 사례 N08: 구매기록 집계 흐름

- 최초 복구판: https://github.com/numpy/numpy/blob/bceb9c20700514db5667831ce2878f1660fb071f/doc/neps/groupby_additions.rst . 문서 작성일 2010-04-27, 최초 추가 commit 작성시각 2010-04-29T23:57:39Z. 더 이른 공개 메일의 동일성은 조사 중이며 최초 공개 절대시점은 미확인이다.
- 당시 구현 근거: NumPy 1.4.0 release commit `4b42c8f6b81d87f35ed8dcf4430224992cf2d296`, commit 작성시각 2009-12-28T01:25:08Z. 1.4.x 렌더 문서는 2010-07-21 빌드여서 당시 공개판으로 사용하지 않는다. 같은 API의 사전 존재는 고정 소스로 확인했다.
- 원 사용례: 1차원 구조화 구매기록 `year/month/day/time/store/SKU/number`에서 제품·월·점포별 수량 max/min/mean/sum을 계산한다.
- 과제 범위: 세 가지 그룹 정의(SKU, 연월, 점포) 각각에 대해 그룹 정체성→행 소속→네 집계→키가 붙은 결과를 설계한다. 이를 작은 전체 집계 흐름으로 분류하되, NumPy 전체 API에 `reduceby/reducein/segment/edges`를 새로 도입하는 정책은 평가하지 않는다. 장기 시스템 설계 대표성은 제한된다.

| 요구 ID | 원판 위치 | 보존할 조건 |
| --- | --- | --- |
| N08-R1 | Example Use Case, 구조화 dtype 및 by product/month/store 문단 | 원래 필드·키 의미를 보존하고 SKU·연월·점포 세 grouping을 각각 지원한다. |
| N08-R2 | Example Use Case, max/min/mean/sum 문장 | 그룹 안의 모든 `number` 값에 대해 네 집계를 제공한다. 행 수를 수량 합계로 바꾸지 않는다. |
| N08-R3 | Example Use Case의 structured-array group-by 목적; reduceby의 unique index 정의 | 같은 키의 모든 행을 같은 집계에 배정하고, 서로 다른 키 결과를 합치지 않으며 결과에 원 키를 붙인다. 원문에 정렬된 입력이라는 전제는 없다. |

합격 대안 1: 키의 정렬 순열을 구하고 값에 같은 순열을 적용한 후 그룹 경계에서 합/최소/최대/개수를 구하고 합÷개수로 평균을 만든다. `sort/argsort`, `reduceat`, `sum/min/max/mean`의 1.4.0 공식 문서가 각 단계를 지지한다.

합격 대안 2: 고유키와 역색인으로 행 소속을 보존하고, 각 그룹의 값들을 골라 네 집계를 구한다. 합·개수에 `bincount`를 사용할 수 있으나 그것만으로 최소·최대가 생긴다고 주장하면 실패다. `unique(return_inverse)`와 각 감소 연산의 1.4.0 공식 문서를 근거로 삼는다.

고정 오류 예시: 고유키를 정렬해 결과 라벨로 쓰되 원 데이터의 연속 구간 또는 원 순서 수량을 라벨 배열과 직접 짝지어 집계한다. 분리돼 나타난 동일 키가 다른 그룹에 섞여 R3를 위반한다. 또는 수량 합을 `bincount` 무가중 빈도로 바꾸면 R2를 위반한다. 채점 예시는 정확히 하나의 주 오류를 고정한다.

## t0/t1 경계

t0에 같은 세 grouping과 네 집계를 모두 명시한다. t1은 동일 필드·같은 허용값 범위에서 행의 순서와 반복 키를 바꿔 같은 계약을 재검한다. 신규 요구인 빈 그룹의 최소/최대, 결측값 처리, 부동소수 정밀도 임계값, 성능 상한, 분산 실행, 새 API 도입은 t1에 넣지 않는다. 관측된 정답 대안이 바뀌지 않으면 `수정 불필요`다.

## 선정 전 탈락 요약

NEP1은 NPY 전체 MUST를 보존할 때 pickle/tofile/HDF5의 추가 라이브러리·메타데이터·mmap·역공학 요건 문제가 있어 두 적격 대안 미확인이다. NEP2는 경고 제거 제안에서 두 정당한 전체 해법/독립 기준이 미확인이다. NEP3는 모든 플랫폼 보존과 설정시간 증가 한계를 수반하며 두 대안의 만족을 원문만으로 확인하지 못했다. NEP4/7은 정해진 datetime 타입/호환 요구에 대한 둘째 전체 해법이 미확인이다. NEP5는 최초 작성일과 두 전체 해법이 미확인이다. NEP6은 운영 bug-tracker 절차라 사전 제외다. NEP8은 원문에 실제 소비자 과업과 기존 해법 경로가 둘 이상 있어서 처음 적격으로 선정했다. NEP9~20은 원장 머리말을 기록하되 선택 슬롯이 채워진 이후의 후보이며 추가 선택하지 않는다.

## 정정 주석 · 2026-11-22

위의 원래 봉인 문구에서 '연월'은 원문 by month의 가능한 해석 하나였으며 최초판은 연도 경계를 명시하지 않는다. 이를 새 필수조건으로 추가하지 않는다. 실제 t0/t1은 year=2010인 같은 6행만 쓰고 month와 (year,month)를 모두 허용한다. 최초 의도 추론의 과잉을 줄이기 위한 정정이며 원 문구를 보존했다. 후보 20·선정 1·예시 3·요구 3의 분모는 바뀌지 않는다. N08 전체는 작은 집계 흐름이라는 범위만 유지한다.
