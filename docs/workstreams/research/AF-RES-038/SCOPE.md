## 3. 두 시점과 세 보기

`t0`는 첫 채택 선언 + 제출판 고정이다. `t1`은 동일 요구의 재검이다. 달력 간격·90/60분·7일·품질 비열등 경계·최소 사업차이는 미합의이며 이번 과제지에 확정값으로 넣지 않는다. 한 실행의 예산/간격은 모집 전에 운영자가 공통 run-config에 고정해야 한다.

| 보기 | 제공 내용 | 공통 조건 |
| --- | --- | --- |
| A | 보통 자유 검색; 선별 링크 없음 | 같은 과제·요구·공개 인터넷·검색·도구·교육·예산·지원 정책 |
| B | A + 중립 제목의 선별 원문 링크 최대 3개 | 제목에 추천 순위/완성 답을 넣지 않음 |
| C | B와 URL·판·순위 동일 + 요구 ID→근거 절 + 적용 한계 한 줄 | 새로운 요구·완성 코드/답·별도 검색권한 없음 |

B/C 실제 파일의 URL 배열, 개수, 순서, 버전과 Unicode 본문 문자수를 검사한다. 제목·공통 머리말을 동일하게 둔다. C의 길이 증가는 처치 일부이며 가짜 filler로 맞추지 않는다. A↔B는 선별·제공 묶음, B↔C는 설명 추가 및 읽기 부담, A↔C는 전체 제공의 비교다. 링크 선정 효과만, 설명 의미만 또는 길이만의 순수 효과는 분리하지 못한다.

각 요구에는 ID·원판 영구 URL·절·원문 작성 시점·필수/보조 구분을 붙인다. t1에서 최초판에 없던 조건을 발견하면 `new_requirement_excluded`로 분리한다. 후대의 테스트는 동일 행동의 판정 근거에만 쓰며 참가자에게 미래 자료를 차등 공급하지 않는다. 현재 자유 웹에서 미래 자료를 찾는 것은 막을 수 없으므로 노출을 기록한다. 엄격한 역사적 정보집합 실험으로 보고하지 않는다.

참가자에는 `packets/<case>/t0.md`, 배정된 arm 1개, 시점이 오면 `t1.md`만 준다. rubric·examples·sources·RESULT·후속 공개 결정 URL은 배포 목록에서 제외한다. 공개 저장소 전체를 참가자에게 주는 행위는 가림을 깨뜨리므로 운영자가 개별 파일만 전달한다.

## 4. 사전 합격 기준

- 4과제 각각 최초판 요구에 맞는 대안 2개 + 그럴듯하나 필수조건 1개를 어기는 대안 1개를 봉인한다. 두 적격 해법을 입증할 수 없으면 부적격이며 파일만 있다고 준비 완료로 세지 않는다.
- 요구별 `pass / partial / fail / unverified`와 중대 위반을 별도로 코딩한다. 표현·유명도·도구 이름은 정답 기준이 아니다. 대안 이름을 지운 제출물에도 행위/출력/경계 조건 증거는 남긴다.
- 최소 12개 작성 예시를 실제 판독한다. 저자 자기점검과 별도 AI 문맥 판독은 구별하며 사람 간 합의로 부르지 않는다. 별도 판독자에게 expected·arm·도구명·저자 결론을 주지 않는다. 판독 전 입력 해시/범위를 고정한다.
- 허용 대안 오탈락, 잘못된 유명 대안 오통과, 설명 카드의 오연결, 전부 무수정 결과를 확인한다. 불일치는 삭제하거나 새 답을 과거 판정으로 덮지 않는다.
- 채택 전 포기, t1 결측, 품질 실패, 변화 없음, 새 요구만 추가를 예시 사건으로 만든다. 사람의 가상 초/분은 생성하지 않는다. 예시의 모든 시간은 null/미확인이다.
- 전체 배정자 최종 품질과 소비 노동을 우선한다. 채택자 재작업과 완료자 시간은 조건부 분모를 명시한다. t0 미채택자의 재작업은 해당 없음, 결측은 미확인, 관측된 무수정은 별도 0사건이다.
- 제공자 준비·검수·유지와 소비자 노동을 분리하고 합산 범위를 명시한다. 소비자 수가 없으면 비용 분산을 계산하지 않는다.

## 5. 출처·예산·반례 탐색

적격 고유 외부 원문 최소 24: 최초 제안 4, 동시대 대안별 명세/공식 근거 8, 상세 기준/시험 4, 후속 결정/재검 4, 디자인·교육 방법 원문 4. 역할 중복 문서는 한 번만 산입하고 각 역할의 충족은 별도 집계한다. 원문 부록을 별도 논문으로 늘리지 않는다. 검색 snippet·접근 실패·미러·재인용은 산입하지 않는다. `sources.jsonl`에 필수 13키와 직접 열람 위치·한계·고유 그룹을 남긴다.

사례별 탐색은 원판→당시 대안→자격 봉인→시험/후속 순서다. 후속을 먼저 본 경우 실제 노출 순서를 보존하고 순수 전향 선정이라고 부르지 않는다. 한 주소 실패 후 공식 HTML→공식 저장소 고정판→저자/기관 원본 순으로 찾는다. 유료/로그인/비공개 우회는 하지 않는다. 24개를 채우지 못하면 부족한 역할과 첫 재개 URL을 기록한다.

예상 반례: 링크가 쉬운 정답을 강하게 암시한다; C가 새 조건을 추가한다; 최초판이 후속 편집으로 바뀐다; 두 해법이 사실상 같은 API 명칭만 다르다; 빠른 제출은 포기 또는 오류다; 채택자 선택이 수정노동 차이를 만든다; 잘못 연결한 카드가 고착을 유발한다; 전문가에게 설명이 순비용이다; 작성자 비용이 독자 이득보다 크다; 단기 API 문제의 성공이 장기 설계로 전이되지 않는다; 유효한 대안은 t1에서 전부 무수정이어서 재작업 차이를 식별하지 못한다.
