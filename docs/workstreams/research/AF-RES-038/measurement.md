# AF-RES-038 · 향후 사람 시험의 원자료와 판정 규칙

**미실시 프로토콜이다.** 이번 기록은 작성한 과제·보기·예시 답안의 탁상 점검이다. 사람 참가자·실제 노동·제품 효과는 관측하지 않았다. AF-RES-034의 [future-study](https://github.com/laadkke-arch/agentflow-open/blob/f6dc9b8873b049f1eb4f8977ce3408ed057df1f7/docs/workstreams/research/AF-RES-034/future-study.md) §§1–5와 [measures](https://github.com/laadkke-arch/agentflow-open/blob/f6dc9b8873b049f1eb4f8977ce3408ed057df1f7/docs/workstreams/research/AF-RES-034/measures.md) §§1–3의 경계·분모를 재사용한다. 기존 효과값이나 표본 수는 재계산하지 않는다.

## 1. 배정과 제공 절차

한 사람에게 한 과제와 한 보기만 배정한다. 과제 4종 × 보기 A/B/C의 병렬 비교이며 동일인이 같은 요구의 다른 보기를 다시 풀지 않는다. 사용 가능한 인원이 작으면 각 과제의 세 군을 유지하고 과제 수를 줄인 별도 파일럿으로 등록해야 한다. 과제 수를 사람 수로 세지 않는다. 실제 업무에서 팀원끼리 자료를 공유하면 팀 단위로 배정·분석하고 팀원 노동을 합산한다.

운영자는 과제별 경험·간단한 기초 문제·특정 해법 이전 사용/문서 인지를 처치 전에 기록한다. 사전 검사는 정답·선례를 노출하지 않는 별도 평행문항을 쓴다. 경력과 특정 해법 인지는 별도 변수다. 사전 인지자를 사후 제외하지 않고 예정된 층과 별도 기술 결과에 남긴다. 과제별·인지층 내 균형 무작위 배정을 사용하며 난수 시드 해시와 할당 파일 접근권한을 봉인한다. 실제 배정은 이번에 하지 않았다.

진행 순서는 (1) 공통 환경 안내와 사전 인지, (2) 배정 및 t0 과제·해당 arm 파일의 동시 제공, (3) 첫 채택 선언과 제출 해시 고정 또는 포기/상한 종료, (4) 동일 창에서 t1 재검 제공, (5) 변경 또는 유지 사유와 최종 제출 고정, (6) 조건 가림 채점·불일치 조정이다. 최초 정답 테스트 통과 시각과 첫 채택 선언은 서로 다른 필드다.

모든 군은 같은 검색엔진·브라우저·IDE·코드 실행 권한·생성 도구 정책·튜토리얼·지원·휴식 정책을 사용한다. 검색어와 자료 찾는 순서는 자유다. B/C만 최대 3개 링크를 처음부터 받는다. C의 추가 설명을 읽는 시간은 소비 노동에 포함한다. 참가자는 보기 차이를 볼 수 있으므로 참가자 맹검이라 부르지 않는다. 진행자·제공자도 보기를 알 수 있고, 품질 채점자는 모른다.

시간상한·재검 간격·보상·모집/제외 기준·최소 사업차이·허용 품질열화·중대오류 허용 여부·표본수·중단 규칙은 `forms/run-config.json`에서 모집 전에 확정해야 한다. 034의 7일·90/60분·임계값을 자동 채택하지 않는다. 이번 파일은 빈 프로토콜 변수의 위치를 제공하고 효과/판별력을 약속하지 않는다. run-config가 확정되지 않으면 **내용 검토 가능, 사람 시험 개시 불가**다.

공개 저장소 전체를 참가자에게 공유하지 않는다. 배포자는 `distribution.json`의 t0+배정된 arm만 전달하고 나중에 t1을 전달한다. 채점표·예시 정답·sources·후속 결정은 전달하지 않는다. URL 본문은 원래 허용된 근거다. A 역시 동일 인터넷에서 접근할 수 있어야 한다. 현재 웹 검색으로 후대 결론을 찾는 오염은 모든 군에 가능하므로 원 URL·판·첫 노출시각·사전인지와 군 간 공유를 별도 기록한다. 이 설계는 역사적 웹 재현이 아니다.

## 2. 기록표와 자료형

빈 CSV 양식은 `forms/`에 있다. UTF-8, UTC ISO-8601 시각, `null`은 JSON null/CSV 빈 셀로 저장한다. UI 표시는 `미확인`과 `해당 없음`을 분리한다. 외부 사람의 개인정보는 공개 저장소에 넣지 않고 가명 ID와 동의 범위 안의 공개 가능한 집계만 관리한다.

| 원자료 | 기본키·연결키 | 반드시 남길 값 | 잘못 해석하면 안 되는 값 |
| --- | --- | --- | --- |
| assignment | run_id + unit_id; person/team 구분 | case_id, arm, 배정 시각/해시, 배정 전 제외, 경험층, 해법 인지 | 배정 후 포기를 제외하거나 시행 수를 사람 수로 세지 않음 |
| exposure | unit_id + exposure_id | card/source ID·판·shown/opened/cited/adopted 시각, 최초인지, 공유 경로 | 화면에 표시됨·클릭·이해·채택을 동일시하지 않음 |
| activity | person_id + interval_id | phase, 시작/종료, read/search/design/code/test-inspect/discuss/active-wait/idle, active_seconds, 관측법·누락 | elapsed/CPU/build/commit 간격을 사람 노동으로 대체하지 않음 |
| submission | unit_id + phase + submission_id | first_declaration_utc, immutable hash, decision IDs, acceptance/withdrawal/timeout, final_available | t0가 품질통과를 뜻하지 않음. 정답확인 시각은 별도 |
| quality | submission_id + requirement_id + rater_id | pass/partial/fail/unverified, 중대오류, 근거 위치, 독립 원판, 합의 전후 | 부분/미확인 항목을 임의 pass로 올리지 않음 |
| rework | unit_id + event_id | old/new decision/submission, original requirement, trigger, changed/retained, discarded work, repair intervals | t0 전 탐색과 새 요구 기능추가를 예방 가능 재작업에 합치지 않음 |
| provider_cost | bundle_id + cost_id | 준비·판확인·검수·정정·유지 담당자/구간·실제초, 재사용 수 | 소비자 수가 없는데 공짜 또는 임의 상각하지 않음 |
| deviation | run_id + event_id | 오연결/판변경/문구정정/도구장애/정보공유, 영향군, UTC, 대응 | 문제가 생긴 C 참가자를 사후 지우지 않음 |

품질의 1차 원점수는 요구별 순서형 범주와 중대 오류다. 임의 가중 총점 하나로 중대 오류를 상쇄하지 않는다. 과제 통과는 모든 필수 요구 pass이고 중대 오류가 없는 경우다. partial 또는 근거 불충분은 통과가 아니다. 채점자는 등록되지 않은 대안도 원래 요구·독립 증거를 만족하면 받아들이며, 대안 이름의 일치 여부를 점수로 쓰지 않는다.

## 3. t0 이후 사건 분류

분류는 효과 가설을 모르는 채점자가 원 요구·판·제출 변화·실제 활동 증거로 한다. 예시의 t0 해시는 실제 참가자 제출 해시가 아니라 작성 fixture ID다.

| 코드 | 필요한 증거 | 재작업 사건/노동 처리 |
| --- | --- | --- |
| original_requirement_repair | t0에 채택된 결정 + t0부터 있던 요구 위반 + 첫 t0 채택 선언 이후(재검 제공 전 사이 작업 포함) 그 결정을 변경한 증거 | 예방 가능 재작업 후보. 인과적으로 예방됐다는 판단은 군 비교가 있어야 함 |
| retained_correct | t0/t1 동일 요구 통과 + 변경 없음 | 수정 불필요 0사건. 재검/검증 노동은 총노동에 포함하며 0분이라 하지 않음 |
| retained_incorrect | t1 원 요구 실패 + 변경 없음 | 무수정이지만 품질 실패. 재작업 감소 성공으로 판정하지 않음 |
| new_requirement_excluded | t0에 없던 조건과 생성시점 + 그 조건 때문에 한 변경 | 예방 가능 재작업에서 제외; 전체 소비 노동 및 별도 확장 노동에는 보존 |
| pre_adoption_abandonment | t0 채택 선언 없음 + 포기 | 채택 뒤 재작업은 해당 없음. 전원 품질·소비 노동 분모에는 포함 |
| followup_missing | t0 채택 증거는 있으나 t1/최종 품질/활동 누락 | 수정 여부·최종 품질·누락 노동 미확인. 0으로 채우지 않음 |
| verification_only | 원 요구 재검 활동, 결정/구현 변화 없음 | 검증 노동, 결정 되돌림 0사건 |
| card_error_repair | 제공 카드 오류 근거 + 원 요구 위반/변경 | 처치 오류로 기록. 원 요구 수정이면 repair에도 태그, 원인과 총량을 이중 합산하지 않음 |

하나의 변경에 원 요구 수정과 새 요구 추가가 섞이면 활동을 분리할 근거를 기록한다. 분리가 안 되면 `mixed_unseparable`이고 예방 가능 수정 노동만 계산하지 않는다. 최초에 버린 구현 노동은 이미 t0 소비 노동에 포함되므로 t1 repair_seconds에 다시 더하지 않는다.

## 4. 분모와 계산 가능성

군 g의 배정 단위 수를 N_g, t0 채택수를 A_g, t1 최종 제출수를 F_g, 모든 필수 요구 통과수를 P_g, 최종 품질 결측수를 M_g로 둔다. 이 기호는 데이터가 생긴 뒤 채울 양이며 이번의 12개 작성 예시와 같지 않다.

| 결과 | 분모·필요 원자료 | 현재 계산 여부 |
| --- | --- | --- |
| 전체 배정자 최종 품질 | P_g/N_g, 중대 오류/N_g, 미확인 M_g/N_g 별도; 결측 시 통과율 경계 P_g/N_g~(P_g+M_g)/N_g | 사람 배정 N_g=0, 해당 없음 |
| 총 소비 노동 | 배정 단위별 공통 훈련+초기+사이 작업+t1 검증/수정의 실제 active_seconds; 팀은 모든 구성원 합 | 사람 활동 없음, 미확인. 누락을 0으로 대체 불가 |
| 시간·품질 공동 판정 | 사전 품질 허용 경계, 노동 최소 차이, 군별 추정 불확실성·결측 민감도 | 경계·사람 입력 없음, 계산 불가 |
| 채택 뒤 수정 노동 | A_g를 먼저 제시하고 원 요구 repair 활동만 합산; t1 결측 분리 | 조건부 이차 기술통계. A_g=0이면 해당 없음 |
| 완료자 시간 | F_g 또는 명시된 성공자 분모와 그 사람들의 노동 | 처치 뒤 선택분모, 전원 효과로 주장 불가 |
| 성공까지 시간 | 성공사건 시각, 상한, 경쟁사건(포기/확정 실패/철회), 원 활동 | 상한 도달만 행정적 검열; 조기 포기를 자동 비정보성 검열로 취급하지 않음 |
| 전체 제공비용 | 준비+검수+정정+유지 노동 + 소비자 노동 합; 공통 연구 채점비용은 별도 | 관측 소비자수·제공자 노동 없으므로 미확인 |

계산 가능한 원자료가 생겨도 클릭·테스트·요구 행은 독립 표본 수가 아니다. 개인 또는 배정된 팀을 기준으로 과제와 사전 인지 층을 반영한다. 같은 과제의 세 군 두 주대비(A–B, B–C)를 우선하고 A–C는 전체 묶음 보조대비로 등록한다. 다중 비교·분산/분포·중단/결측 처리·표본수 근거는 자료를 본 뒤 유리하게 바꾸지 않는다.

## 5. 어떤 결과가 가설을 지지하는가

| 가설/대비 | 지지할 관측 | 기각/제한할 관측 | 자료만으로 분리 못 하는 요소 |
| --- | --- | --- | --- |
| H_link: B–A | 같은 사전 품질 기준을 만족하면서 전원 소비 노동의 감소가 사전 실질 차이를 지지 | 링크 탐색만 짧고 총노동 같음/증가, 품질 악화, 불확실성이 경계를 넘음 | 선별 정확도·권위/순서·초기 제공시점·제목 효과의 분리 |
| H_explain: C–B | 같은 URL/판/순위에서 설명 추가의 총 결과가 품질·노동 기준 만족 | 읽기 부담으로 총노동↑, 오연결로 유명 오답 고착, 비주류 대안 오탈락 | 의미·본문길이·주의 유도·읽기 부담의 개별 기여 |
| H_rework | 전원 최종품질과 총노동 기준을 지키고 원 요구 되돌림·repair가 줄어드는 패턴 | 결함을 유지해 수정0, t0 채택자만 남겨 차이가 생김, 새 요구 노동만 차이 | 채택자 조건부 평균의 인과효과; 장기 운영으로의 외삽 |
| H_total: C–A | 전체 제공의 품질·소비/제공 노동을 합친 사전 기준 만족 | 독자는 이득이어도 작성·검수·유지 노동 포함 시 비용 증가 | 링크 제공과 설명의 상호작용/매개효과; 길이만의 효과 |

한 비유의 검정만으로 같은 품질·효과 없음·동등성을 선언하지 않는다. 효과가 작다는 좁은 구간과 판별 불충분한 넓은 구간을 구분한다. 사전 품질 경계 또는 노동 최소 차이가 정해지지 않았으면 방향/불확실성만 기술하고 성공 판정을 보류한다. 전부 처음부터 맞아 t1에서 어느 대안도 바뀌지 않았다면 재작업 발생이 없는 범위에서 0사건을 보고한다. 링크가 재작업을 예방했다고 인과적으로 주장할 수 없으며 난도를 사후 높여 인위적 실패를 만들지 않는다.

## 6. 가림·불일치와 비용 전가

자료 담당자는 군명·카드 ID·추천 시스템·도구/정책 이름을 제거하고 익명 제출 ID를 난수 순으로 제공한다. 코드/API 이름 자체가 본질이면 기능을 보존한 중립 표현을 사용하되 변환 전후 diff와 정보손실을 따로 점검한다. 채점자는 원 요구와 독립 판정 근거를 받으며 어떤 군이 유리해야 한다는 설명을 받지 않는다. 채점 후 어떤 군/정책으로 추측했는지도 남겨 가림 실패를 확인한다.

사람 시험에서는 두 채점자가 먼저 독립 판독하고 requirement별 근거를 봉인한 후 제3 조정자가 이견을 처리한다. 다수결만으로 원문 모순을 덮지 않는다. 최초 두 판정과 수정 이유를 모두 보존한다. 이번 작업의 별도 AI 문맥 판독은 이러한 외부 사람 합의를 대신하지 않는다.

초보자는 설명을 정답으로 읽을 수 있고, 숙련자는 추가 읽기만 늘 수 있으며, 이미 해법을 안 사람은 발견 효과가 없다. 제공자는 판 고정·기준검수·오연결 수리에 시간을 쓴다. 조건을 모르는 채점자는 유효한 다른 대안을 익숙하지 않다는 이유로 탈락시킬 수 있다. 장기 설계는 운영/이행/조직 의존이 있어 작은 파싱·자료 저장 문제의 결과를 그대로 옮길 수 없다. 구체 원문과 사례별 오류 관측은 methods 갈래와 RESULT에서 연결한다.

## 7. 이번 탁상 점검

`evidence/measurement-fixtures.jsonl`은 사람 관측이 아니라 분류 규칙 검사용으로 직접 만든 예시다. duration·실제 시각은 모두 null이며 합계·평균·절감 초/분을 만들지 않는다. `evidence/measurement-check.json`은 각 예시의 입력→기대 코드→규칙 판정의 일치만 기록한다. 12개 답안 예시는 별도 `examples.jsonl`과 가림 판독에 있으며 사람 12명이나 실험 시행 12건이 아니다.


## 8. 별도 문맥 검토 뒤 고정한 시간축·분모 보완

`evidence/protocol-review.json`의 PR-02 지적으로 **수정 관측 시작을 첫 t0 채택 선언 직후**로 통일했다. t1은 재검을 제공하는 시점이며 그 이전의 원요구 수정도 누락하지 않는다. 검토 전 파일과 설정은 `evidence/protocol-input-v1.md`, `evidence/run-config-v1.json`에 보존한다.

시간 원점은 참가자에게 t0 과제가 처음 실제로 표시된 시각이다. 예산의 단위는 초이며 경과시간 상한과 실제 활동초를 구별한다. t1 제공은 모든 배정자에게 같은 규칙으로 **t0 과제 표시부터의 사전 고정 간격**을 적용한다. 간격 수치는 미합의이며 초기 상한보다 길거나 같아야 한다. 첫 채택이 빠른 사람에게 자동으로 더 짧은 관측창을 주지 않는다. t0 종료·첫 채택·각 제출·첫 기록된 통과 제출·평가시각·t1 표시·최종 종료·경쟁사건을 별도 필드로 저장한다.

첫 기록된 성공은 보존된 제출 중 공통 루브릭의 필수조건을 모두 통과한 가장 이른 제출이며, 그 제출 시각과 실제 채점시각을 구별한다. 이는 머릿속에서 해법을 처음 얻은 시간이나 관측되지 않은 더 이른 성공이 아니다. t0/최종 두 스냅샷만 있으면 사이의 정확한 최초 성공은 미확인이다. 기록 간격으로 성공이 위치한 범위만 말하고 정확 시각을 만들어내지 않는다.

초기에 채택하지 못했거나 상한에 도달한 사람에게도 같은 t1 재검을 제공한다. 동의를 철회한 사람을 추적하지 않으며 철회 사유와 데이터 범위를 기록한다. 초기 비채택자가 t1에 완성하면 최종 품질과 총노동에는 포함하지만 t0 채택자 재작업으로 분류하지 않는다. t0 전원 상태는 initial_adopted / no_initial_adoption, 후속은 repaired_original / retained_correct / retained_incorrect / new_only / mixed / missing을 교차 집계한다. 이 공동 상태표도 채택자 선택의 인과 문제를 없애지는 않는다.

일차 소비 노동 요약량은 **배정 단위당 총 실제 활동초의 평균**이며 분포·중앙값·구간별 값도 기술한다. 팀 배정이면 구성원 실제 노동을 합친 팀 값을 사용한다. 비교 차이의 단위는 초/배정단위이고 제공자 노동 포함 결과는 별도다. 노동의 일부 구간이 누락된 경우 전체 평균은 미확인이다. 관측 합계를 하한으로, 사전에 허용한 활동창과 팀 규모로 정할 수 있는 유한 최대를 상한으로 둔 민감도 범위를 사용할 수 있다. 유한 상한을 정할 수 없거나 가능한 범위에 따라 결론이 바뀌면 노동 감소 성공 판정은 보류한다. 알려진 사람만의 평균을 전원 평균으로 바꾸지 않는다.

PR-01/03/05의 수치가 필요한 항목은 run-config의 명시적 null로 유지한다. 모집·동의/보상·중단·표본수·품질 비열등 경계·노동 최소 차이·군 차이의 추정법은 후속 사람이 참여하기 전에 결정할 값이다. 개인 과제 통과는 필수조건 모두 pass/중대오류 없음으로 이미 정의했으며, 군 전체의 중대오류 허용 경계는 별도 미합의다. 실제 사람 연구를 시작하지 않은 상태를 준비 완료로 바꾸지 않는다.
