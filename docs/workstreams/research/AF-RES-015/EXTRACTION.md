# 답 위치 대조와 수집 경계

AF-RES-011에 있는 61스레드와 635개 위치를 [커버리지 원장](results/answer-coverage.csv)에 유지했다. 초기 판별 뒤 스레드 원문을 직접 열고, 상세한 본문을 읽을 수 있었던 Stack Exchange 30개에서는 본문 행 위치로 원자화했다. HN·Reddit·GitHub·Lobsters·OKKY·GeekNews의 나머지 31개도 공개 스레드를 열었고, 보이는 대상 문장이 일치하면 원문 행을 썼다. 후속 댓글의 표시·순서가 달라지거나 문장 귀속을 정확히 재현하기 어려운 경우 011의 고정 답별 요약에서 확인 가능한 범위만 재코딩하고 근거 종류를 표시했다. 답 위치가 있더라도 스레드 내에서 정확한 날짜 없는 댓글은 null이다. Stack Exchange가 답 시각에서 연도를 생략한 경우 같은 페이지의 현재 연도 표기와 관측 창을 함께 적용했다.

후보 이름만 있는 비교도 제품 식별이 가능한 경우 추출표에 있다. 같은 답에 이유 없는 후보와 구체 이유가 있는 후보가 함께 있을 수 있다. 원문 URL, 원문에 나온 근거 링크·예시, 011의 후보 링크를 보존했고 별도의 현행 공식 URL은 현재 판정 단계에서 붙인다. 이 셋은 후보로 직접 이어지는 실제 링크인지 분석할 때 구분한다. 고정 데이터의 답별 요약과 이번 작업자 판정은 별도 열로 읽어야 한다. 원문 문장·이름·프로필은 산출물에 복제하지 않았다.

T011의 Visualping은 ChangeDetection 답의 후속 발언이다. T014 OpenShot도 댓글 위치를 사용했다. T002 Veusz의 Python 사용은 2017 원 답보다 나중에 추가된 문장이다. 이 행의 답 게시일은 원문 주소 찾기에만 쓰고 당시 상태 복원에는 별도로 확인할 진술 시점이 필요하다. T001 비교 주장과 T024 유지 상태처럼 음성·조건부 진술도 해당 적용 대상·조건을 따로 적었다.

실행 도구는 [고정 추출 스크립트](src/extract.py)이며 입력은 data/extract-stack.txt, data/extract-social.txt와 고정 CASES.json이다. 접근 시험은 [access.json](results/access.json)에 실제 UTC와 elapsed seconds를 기록했다.
