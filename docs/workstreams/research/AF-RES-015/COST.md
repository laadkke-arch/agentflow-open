# 확인 비용과 재생 실험

12개 동일 이유는 신호 결과 커밋에 [입력](data/cost-bench.txt)으로 고정했다. 표본은 성공, 폐기, 과거부터 틀린 진술, 원래 링크에서 신호를 붙이기 어려운 후보를 포함한 의도 표본이다. 모집단 평균이나 사람 채용 비용으로 일반화할 수 없다.

| 방식 | 절차 | 관측 기록 |
| --- | --- | --- |
| A 원문 대조 | 공개 답과 공식 자료를 각각 열어 같은 이유의 범위와 판정을 대조 | 한 명의 Codex 작업자가 실제 문서를 읽었다. 사람이 참여하는 인건 시간 계측은 미실시다. 웹 도구 연산·열람 페이지·벽시계는 [cost-review.jsonl](results/cost-review.jsonl) |
| B 자동 신호 | 공식 GitHub 홈페이지의 archived, 기본 커밋 시각, 011의 기존 404 중 하나라도 양성이면 경보 | 허용 호스트에 실제 GET. 요청 수·리다이렉트·대기·상태는 [cost-network.jsonl](results/cost-network.jsonl) |
| C 자동 뒤 선별 대조 | B를 새로 실행하고 경보를 받은 항목의 공개 답과 공식 자료를 다시 검토 | B와 별도로 실행한 네트워크 비용과 선별 웹 열람을 동시 기록 |

A의 최초 도구 호출은 메타데이터 줄을 본문처럼 선택하는 파서 결함이 있어 pilot로 보존했다. 본문 위치로 수정한 두 번째 A의 12건만 집계했다. C의 TanStack 위치를 원 답까지 좁혔다. A의 같은 행은 질문과 공식 문서를 열어 봤고 답 연결에는 기존 원장을 사용했다. 읽은 페이지 수는 관련 원문 영역이 보이는 페이지의 수다. 해석 전용 시간과 웹 도구 안쪽의 실제 HTTP 요청 수는 별도로 계측하지 못했다. A와 C의 웹 연산 건수를 HTTP GET 수로 합치지 않았다. 본 벤치의 자동과 선별은 익명으로 정해진 1.06초 간격을 사용했다. 재조회는 데이터 캐시의 영향을 받으므로 최초 사용자 체감과 동일하다고 볼 수 없다.

A와 C의 판정 기준은 [REASONS.jsonl](REASONS.jsonl)의 공식 근거와 같다. Gifcurry, Markor, nfnt/resize, Soft Serve, Rhasspy, Buttercup 설치 표면, TanStack, Papers We Love는 확인한 범위에서 기능·권리 근거가 남는다. Directus의 소스 공개 조건과 Dcoder의 서비스는 뒤에 바뀌었다. Mattermost와 공식 Roo Code 확장의 두 진술은 답 시점 이전 자료에서 반박된다. 표본이 작아 B·C 정확도는 혼동표 전체 추정으로 사용하지 않았다.

## 월·분기·연과 요청 시

[재생 입력과 집계](results/cadence.json)는 확인한 이유 변화 사건의 구간을 사용한다. 같은 Almond 통합 변화에 대한 두 답은 하나의 사건으로 합쳤다. 날짜가 있는 답만 사용한 분석과 질문 날짜를 대용한 민감도 분석을 각각 낸다. Q5는 마지막 성립 이후부터 최초 반박까지의 정확한 복원 불가능성 때문에 양 끝 시나리오를 사용한다. 구간 안의 변화가 계속 유지되고, 한 번의 요청으로 현재 근거를 읽을 수 있다고 가정한다. 두 끝점의 지연 중앙값은 실제 분포의 추정치나 수학적 상하한이 아니다. 과거 공개 증거의 첫 날짜 전까지 경보를 확인할 수 없다고 가정한 재생도 같은 원장에 있다.

요청 14·90·365일은 현재 요청 로그가 없는 경우의 가정이다. 재요청이 없으면 수동 발견은 관측 창 끝에서 검열된다. 각 행의 검사 횟수는 답 기준일에서 2026-11-20까지의 가상 검사 횟수다. 이 실험은 일회 실행이며 예약 작업을 만들 이유가 없다.
