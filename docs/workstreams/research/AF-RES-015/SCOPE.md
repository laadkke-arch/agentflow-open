# AF-RES-015 — 사전 조사 규칙

기준 브랜치 `chore/workspace-foundation`의 시작 SHA는 `55313b44af48ba85e967a96e885bf9b7a7d8c8ba`다. AF-RES-011 `478c301b693896e2c6d777f46ac441f071bfdfe8`의 CASES·aging-observations·sources를 고정 입력으로 사용한다. AF-RES-009 `7f627a81199f06da7f7b15f979e7fef25dd17602`의 HANDOFF 및 지정 세 파일은 유지 방식과 실패 사례의 기존 해석을 인용하는 데 사용한다. 011의 HANDOFF도 해당 결과 SHA에서 확인했다. 공용 문서와 진행표는 읽기 전용이다. 이 문서는 최초 호스트 접근 시험 후, 이유 추출과 현재·과거 상태 판정 전에 동결한다.

## 표본과 이유 추출

- 61개 스레드의 고정 답 위치 `Tnnn.Annn`을 시작점으로 전수 대조한다. 답의 추천 대상은 고정 CASES의 후보명·URL·역할·요약에서 찾고, 답 본문의 추천과 합치할 때 이유를 붙인다. 순수 비판·질문·잡담·이름 없이 일반 절차만 설명한 답은 제외 사유를 남긴다. 동일 답의 여러 대상과 한 대상의 여러 독립 이유는 별도 행으로 남긴다. 고정 위치가 다른 독립 답의 반복 추천은 합치지 않는다.
- 추천 이유는 답이 실제로 진술·비교하거나 구체적 사용을 근거로 제시한 대상의 속성이다. 질문자가 원한 조건, 외부 제품 문구, 추천 사실 자체로 이유를 추정하지 않는다. 원문 또는 고정 입력에서 답 발화에 귀속되는 구체적 요약과 위치를 확보하고 출처 경로를 구분한다. 아직 귀속할 수 없으면 `추출 미확인`, 확인한 답에 이유가 없으면 `이유 없음`으로 코딩한다. 이름과 링크만 적힌 답과 개인적 선호만 서술한 답은 따로 센다.
- 가능한 한 이유를 원자화한다. 분류는 가격, 라이선스, 기능 지원, 플랫폼, 호스팅 방식, 관리 상태, 성능, 기타 검증 가능, 이유 없음, 추출 미확인이다. 가격은 통화·범위·기한·무료 플랜과 평가판, 라이선스는 서버/클라이언트·버전·에디션, 기능은 기능을 수행하는 구성 요소와 옵션, 플랫폼은 OS/제품/도구 이름, 호스팅은 운영 주체와 인터넷 의존을 구분한다. 긍정과 부정을 함께 주장하면 속성마다 방향을 보존한다. 일회성 사례와 사용자 평가를 일반 기능 보장으로 확대하지 않는다.
- `answer_ref`는 고정 답 위치다. `evidence_locator`에 원문 답 ID·답 내 문단/소제목 또는 고정 입력 JSON 위치와 독립 요약을 둔다. 본문·사용자 이름·프로필을 저장하지 않는다. `answer_date`는 확인한 답 날짜만 쓴다. 현행 편집본만 보이면 편집 전 상태를 보증하지 않으며 날짜가 없으면 null과 사유를 기록한다. 질문 날짜를 답 날짜로 치환하지 않는다. 후보 URL은 답의 링크 우선이며 정규 주소는 별도 보존한다. 링크만 있는 답과 추출 미확인은 200개 답 추출 게이트의 유효한 이유 분자에서 분리해 보고한다.
- 표 1의 단위는 유형 내 고유 답이다. 같은 답의 동일 유형에 여러 판정이 섞이면 `무너짐 > 약화 > 판단 불가 > 성립`으로 집계한다. 공존 이유를 숨기지 않도록 원자 이유 기준 표도 추가한다. 유형별 분모는 합산하지 않는다. 경과 연수는 답 날짜가 확인된 행만 사용하고 그 수를 함께 표시한다.

## 현재 판정과 답 시점 판정

| 현재 코드 | 경계 |
| --- | --- |
| 성립 | 공식 문서·패키지·코드에서 동일한 조건/범위의 속성을 긍정적으로 확인 |
| 약화 | 핵심은 일부 남지만 판·요금제·플랫폼·유지 조건이 좁아짐. 별도 유지 항목이 없으면 archive를 기능 약화로 자동 코딩하지 않음 |

- 항목마다 실제로 읽은 현재 1차 URL, UTC, 위치, 관측 수준, 한계를 적는다. 문서가 직접 지지하는 사실과 직접 실행을 구분한다. Git README의 나이와 npm 메타데이터는 기능 판정의 단독 기준으로 삼지 않는다. 신호를 보고 판정이 바뀌어야 한다면 교차 근거가 있는지 확인하고 표에 순환 가능성을 표시한다.
- `then_verdict`는 `성립 / 처음부터 틀림 / 판단 불가`다. 답 시점과 일치하는 1차 원본 스냅샷, 날짜가 있는 태그·커밋·릴리스 코드/문서, 또는 공식 이행 기록이 직접 지지해야 한다. v1이 답보다 오래됐다는 사실만으로 최신판의 당시 판정에 사용하지 않는다. 1차 상태 변화가 공표됐으면 답 시간과 어떤 판에 영향을 미쳤는지 검토한다. 현재 페이지에서 과거를 역투사하지 않는다. 처음부터 틀린 추천은 변화율에서 제외한다.
- `break_interval`은 마지막 성립 관측과 첫 무너짐 관측의 열린-닫힌 구간 `(L,U]`다. 공지의 발행·시행일을 구별한다. 경계가 없으면 좌/우 검열로 두고 지연 계산의 확정 분자에서 제외한다. 방재 저장은 추천 작성일·캡처일·현재 확인일을 별도 표시한다.

혼동표는 이유별 신호 노출 중 현재 성립·약화·무너짐이 독립적으로 판정되고 신호를 읽은 분모를 쓴다. 주분석 양성은 확인된 `무너짐`이며 `약화`를 더한 민감도와 답 시점 성립이 확인된 행만의 민감도를 낸다. 처음부터 틀림은 노후화 해석 시 제외한다. 중복 후보를 제거한 후보별 진단도 함께 낸다. 비용 및 확인 시각이 다른 상속 신호의 순서는 사전 예측 시점을 보장하지 않으므로 동시적 식별 성능으로 보고한다. 과거 신호가 실제로 먼저 찍힌 사례만 예상 선행 기간을 말할 수 있다. 분모 0 및 정밀도/재현율 정의 불가는 미확인으로 표시한다.

## 비용과 시뮬레이션

- 닫힌 벤치 입력 목록을 비용 실행 전에 보존한다. (a) 연구자가 답과 1차 문서를 읽어 표에 판정하는 흐름, (b) 신호만 한 번 확인하는 흐름, (c) 신호로 경보를 내고 경보 항목만 (a)를 적용하는 흐름을 같은 항목군에서 비교한다. 벽시계는 monotonic stopwatch, 요청은 성공·실패와 HTTP 리다이렉트 포함, 읽은 페이지는 실질 본문을 읽은 수다. 도구가 내부 HTTP 요청을 노출하지 않으면 관측된 호출과 HTTP 요청을 분리한다. 자동과 수동의 중복 후보 캐시, 실패·요청 간격·환경을 표에 명시한다. 작업자 측정과 실제 사람 참여 계측의 범위를 구별한다.
- 과거 시점 재생은 확인된 구간별로 월/분기/연 점검일을 답 날짜에 고정한다. 달력 말일은 해당 월의 마지막 날로 내린다. 관측 종료일까지 계산한다. 각 경계에서 추정 발견일을 구하고 끝점 시나리오의 지연 범위·중앙값·미발견을 각각 보고한다. 임의 보간을 실측으로 세지 않는다. 요청 시 관측은 실제 재요청 로그가 없으면 공개 후 14·90·365일 간격의 고정 예시로 재생하고, 재요청 없음 시나리오의 우측 검열을 따로 보고한다. 표본이 충분하면 신호 큐·이유별 만료도 동일 판정 능력 가정과 함께 비교한다.

## 접근·재개와 반례

첫 단계에 네 지정 호스트의 익명 접근과 한도 헤더를 각 1회 확인하고, 차단 호스트를 우회하지 않는다. 허용되는 공식 저장소 Git 이력과 공개 레지스트리 중 해당 이유의 직접 1차 증거를 찾는다. 단일 호스트에는 보수적으로 1초 이상 간격을 두며 429·Retry-After·서비스가 문서화한 한도에 맞춰 감속 또는 중단한다. 계정/토큰 생성, 비공개·유료 수집, 예약 실행은 범위 밖이다. 공식 종료 공지와 살아 있는 상단 페이지, 관리 중단과 버전 고정 사용, 이름 변경과 이동, 답 시점 반박, 보존본 경고 유무를 반증 방향으로 확인한다. 웹·API 원문을 재배포하지 않는다. 표본을 바꾸거나 정보원을 추가한 경우 시점과 이유를 결과에 적는다.
