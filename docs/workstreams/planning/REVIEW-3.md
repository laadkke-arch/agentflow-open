## 4. 진행 기록상의 문제 (PLAN#2 §4 이후 미해결)

1. **DONE 10건 모두 `acceptance_evidence`가 빈 배열이다.** 009~012의 brief는 "완료 수용 때 SELF_CHECK와 '끝내도 되는 조건'의 대조 결과를 acceptance_evidence에 기록"하라고 했다. 하지만 기록되지 않았다. 각 HANDOFF의 상태는 `REVIEW_READY`다. 작업자 완료와 진행 담당 수용이 여전히 구별되지 않는다.
2. **`source_commit`, `actual_model`이 모두 null이다.** 실제 시작 SHA는 HANDOFF에만 있다(009 `50ebddb…`, 010 `1eca580…`, 011 `020c8d0…`, 012 `04441f9…`). 네 작업의 시작 SHA가 서로 다르다.
3. **`worker_kind`와 실제 실행 위치가 다르다.** 009·011은 `web-pro`인데 HANDOFF에는 Codex Cloud 작업공간에서 실행했다고 적혀 있다. "웹 Pro 연구 경로"의 성격을 판단할 때 혼동된다.
4. **네트워크 제약이 실행을 막았다.** 012는 huggingface.co 403으로 의미 검색을 못 했다. 010은 Google Patents 503과 Semantic Scholar 429를 겪었다. 다음 codex-cloud 작업은 첫 단계에서 필요한 호스트에 접근할 수 있는지 확인하고, 막히면 대체 경로와 재개 명령을 남기도록 brief에 적었다.
5. **공통 전체 검사 `scripts/check.py`를 실행한 작업이 없다.** 010·011 모두 이 검사가 owned_path 밖의 `.workbench/`에 쓰므로 실행하지 않았다고 기록했다. 통합 담당이 실행해야 한다.
6. **결과가 통합되지 않았다.** foundation 트리에는 여전히 연구 결과가 없다. RESEARCH_BRIEF의 "현재 상태: 미배정·미실행" 문구도 그대로다.

## 6. 색인 반영 제안 (적용하지 않음)

- D3를 `D3-search`(검색 결과 화면 관측), `D3-fetch`(페이지·API 응답 관측), `D3-run`(코드 실행 결과)으로 나눈다.
