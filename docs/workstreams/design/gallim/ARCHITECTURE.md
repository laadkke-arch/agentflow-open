# 구조, 자료집, 답을 한 요청으로 잇는 설계

설계 단위는 **“이 요청의 이 부분에, 이 자료의 어느 작동 방식을, 어떤 조건으로 쓸 수 있는가”**다. 프로젝트에 붙은 이름으로 사이트를 찾는 것만으로는 같은 단어가 반대 동작을 뜻하는 사례를 가려낼 수 없다. 반대로 모든 링크의 내용을 미리 요소로 분해하면 한 번도 쓰이지 않을 자료에 수집·갱신 비용을 지불한다. 여기서는 먼저 값싸게 찾고, 판단의 근거가 된 부분에만 비용을 더 쓴다.

## 1. 입력 계약을 결정하는 쪽

프로젝트 지도를 가진 도구, 설계 문서를 다듬는 AI, 사람이 직접 만든 요청 모두 입력 제공자가 될 수 있다. 제공자가 자신의 원본 형식을 아래 계약에 투영한다. 형식의 호환성과 전송 권한은 별도 문제다. 프로젝트 전체 백업을 요구할 필요가 없다. 첨부한 실행 표본은 특정 도구의 개체를 그대로 직렬화하지 않는다.

| 제공자가 정하는 값 | 저장할 최소 단위 | 실제로 달라지는 동작 |
| --- | --- | --- |
| 전체를 고른 것인지, 어느 부분만 고른 것인지 | 요청 ID·판, 선택 방식, 명시적으로 선택한 부분 ID, 범위에서 제외한 ID | 전체라도 제공된 부분 집합의 전체만 뜻한다. 선택하지 않은 이웃의 요구를 검색 목표로 올리지 않는다. |
| 무엇을 이루려는지와 지켜야 할 조건 | 원문, 조건별 원문 시작·끝, 필수/선호, 해당 부분 ID | “중복 등록을 막는다”와 “최초 경로의 원본을 건드리지 않는다”를 각각 검토한다. 원문 범위가 어긋나면 저장 전에 거절한다. |
| 선택 부분의 접점 | 부품 ID·이름, 누구에게서 무엇을 받아 누구에게 주는지, 자료/제어/참조의 방향 | 저장된 도면에서 이웃의 역할을 복원할 수 있다. 전체 프로젝트의 이름이나 긴 대화 없이도 어떤 위치의 대안을 구하는지 남는다. |
| 사람이 정하지 않은 사항 | 입력 누락, 판·설정 미상, 선택에서 제외한 내용 | 현 설치 버전을 모르면 고정판에서 읽힌 동작만 답한다. 명시적 제외를 ‘지원하지 않는 기능’으로 저장하지 않는다. |

입력 제공자의 **작성 중인 화면 선택**, **요청자가 맡긴 범위**, **검토를 돕는 이웃**, **외부 자료에서 찾은 후보**에 서로 다른 의미를 준다. 초안이 바뀌면 새 판을 만들고 이전 판에 자동으로 목적이나 선택을 덮어쓰지 않는다. 실험의 `scope_snapshot`은 원형 복원이 쉬운 불변 JSON, `request_revision`과 `requirement`는 실제로 조회·결합할 행이다. 장차 여러 프로젝트의 구조적 경로까지 자주 검색하게 되면 경계 간선만 관계 테이블로 승격할 수 있다. 지금도 원본 스냅숏에서 재구축할 수 있다.

## 2. 무엇을 저장할 것인가

| 자료의 수명 | 식별·저장 | 언제 더 자세히 읽나 |
| --- | --- | --- |
| 여러 요청이 공유하는 링크 | 원 URL. 같은 제품 안에서 설명하는 단위가 다르면 기능·문서 절·원리를 별도 엔트리로 둘 수 있다. 리다이렉트와 유사한 제목은 동일성 단서다. URL fragment·판·서로 다른 배포본을 한 사실로 접지 않는다. | 처음에는 주소만 받아도 된다. 역할이나 근거가 붙지 않은 주소는 책갈피 수준으로 반환한다. |
| 다시 찾기 위한 단서 | 짧은 이름·어떤 대상인지, 선택적으로 ‘어떤 동작이 어떤 성질을 보존/위반하는지’, 그 설명의 출처와 적용 한계 | 여러 요청에서 반복해 찾거나, URL 철자로는 알 수 없는 원리일 때 붙인다. 검색용 설명은 아직 검증되지 않은 가설일 수 있다. |
| 개별 요청의 판단 | 해당 요청 판, 후보 자원의 판과 설정, 조건별 근거의 방향, 문서판·인용 구간과 해시, 판정기 버전 | 후보를 보여주는 것과 ‘이 조건을 충족한다’고 말하는 데 필요한 비용이 다르다. 상세 확인은 사용자나 다음 모델이 링크를 열어 할 수도 있다. |
| 과거에 돌려준 답 | 요청·선택 부분·조건별 결과·원 링크 및 당시 판정 참조 | 외부 자료가 바뀌어도 “지난번 무슨 근거로 답했나”에 답할 수 있다. 그 당시에 저장하지 않은 외부 페이지 전문·실행 환경은 복원할 수 없다. |

실무에서 선택해야 할 세 비용이 있다. ① 주소뿐이면 저장량이 작고 최신 상세는 클릭 때 읽는다. ② 주소에 짧은 설명·관계가 있으면 분야명이 달라도 후보로 찾을 수 있다. 대신 잘못 요약한 문장이 오답을 올릴 수 있다. ③ 조건별 근거까지 모두 저장하면 재판독과 정정이 쉬워지지만 비용이 크다. 제안한 기본값은 **주소 등록 → 발견에 필요한 단서만 선택적으로 추가 → 실제 판단에 쓴 절만 판에 연결**하는 방식이다. 등록·발견·검증은 서로 독립적으로 진행할 수 있다. 이 선택을 뒤집을 근거는 [크기·회수 실험](LINK_STUDY.md)과 [유지비 평가](EVALUATION.md)에 적었다.

## 3. 소프트웨어 밖에서도 찾는 방법

‘원본 폴더의 PDF 보존’을 한 덩어리로 찾으면 PDF 관리 서비스에 검색이 몰린다. 같은 문장에서 **보존돼야 하는 것, 변해도 되는 것, 어떤 사건 뒤에도 유지돼야 하는지**를 추출하면 다른 자료집도 검색할 수 있다. 예를 들어 ‘보존 원본 → 이용용 사본 → 처리’는 기록보존 분야에도 있다. 이때 맞아야 하는 것은 분야명이 아니라 역할 간 관계다.

| 비교 지점 | 직접 쓸 후보 | 다른 분야에서 빌릴 원리 |
| --- | --- | --- |
| 무엇이 검색되는가 | 같은 목적의 완성 서비스, 특정 기능, 교체 가능한 부품 | 다른 대상에서 같은 관계를 보존하거나 같은 실패를 막는 절차 |
| 원문에서 확인할 것 | 특정 버전·설정에서 실제 입력, 동작, 출력 또는 명시 계약 | 공여 분야의 작동 방식과 한계, 우리 프로젝트의 대응 위치 |
| 잘못된 결론의 예 | 검색 순위가 높으니 모든 필수조건을 만족한다고 판단 | 아카이브에서 보존용 사본을 둔다는 자료를 근거로 소프트웨어가 정확히 한 번 등록한다고 판단 |
| 다음 확인 | 현재 설치판의 소비 폴더 동작과 중복 처리 설정 | 복사 완료 직후 중단하는 시험. 재시작 후 경로와 문서 수를 확인해야 수신 측 구현에 관한 주장을 추가할 수 있다. |

공유 자료집에 관계가 없거나 최초 후보조차 없는 경우도 양산 단계에서 중요하다. 제안하는 확장 경로는 (a) 프로젝트명과 분야명을 제거한 관계 질의를 여러 용어로 만들고, (b) 공개 목록·표준·전문 사이트에서 서로 다른 출처를 탐색하며, (c) 원 역할→대응 역할, 유지돼야 할 성질, 깨지는 입력을 함께 적을 수 있을 때 원리 후보로 받아들이는 것이다. 근거가 없으면 ‘확인할 만한 링크’로만 돌려준다. 실험 코드는 고정 어휘와 저장된 관계에서 이 경로의 뒷부분을 재현한다. 무제한 웹 발견, 자유문에서 신뢰할 수 있는 자동 원리 추출은 미구현이다.

‘새로움’도 대상에 따라 달라진다. 다음 버전에서는 사용자가 이미 고려한 대안을 선택적으로 받는다. 같은 도구가 다른 구성을 제안하거나, 직접 만들 단계를 없애거나, 다른 실패 경계를 만들 때에만 새 선택으로 센다. 이름이 생소하다는 이유만으로 점수를 주지 않는다. 다중 후보는 서로 보완할 수도 있다. 구성 A와 B의 출력·입력, 상태 변경 주체 및 실패 뒤 남는 것을 비교하고 **조합 자체에 대한 증거**를 확인하기 전에는 새 설계안으로 보관한다. 두 부품이 따로 동작하는 사실만으로 조합의 결과를 단정하지 않는다.

## 4. 원래 요청에서 답까지의 실행 경계

1. **요청 고정.** 제공자가 공유한 원문·선택·접점·조건을 한 트랜잭션에 쓴다. 각 조건의 인용 범위를 검증한다. 이미 저장한 판의 내용을 바꾸는 재전송은 거절한다.
2. **발견.** 요청에 포함된 목적·부분을 사용해 전역 카탈로그를 검색한다. 구현 후보와 원리 후보를 모두 찾되 존재하지 않는 유형의 결과를 억지로 채우지 않는다. 출처·검색 이유를 보존한다. 연결된 이웃은 가능한 접점을 설명하며, 이웃 자체를 바꾸라는 지시로 확대하지 않는다.
3. **후보 맥락 고정.** 짧은 목록에 든 자원만 요청과 연결한다. 같은 자원도 직접 소비와 사본 소비를 다른 구성으로 다룬다. 어휘·관계 검색 결과와 증거 판정은 서로 다른 행이다. 색인은 다시 만들 수 있다.
4. **조건 판정.** 후보의 대상·판·범위·설정이 맞고 직접 근거에 위치가 있는지 확인한다. 조건별 값은 지지, 반증, 미확인, 양측 근거 상충이다. 분명히 반증된 필수조건은 후보를 배제한다. 일부만 맞거나 상충하면 보류한다. 같은 맥락의 모든 필수조건에 근거가 있어도, 여러 조건을 동시에 시험했다는 뜻은 아니다. 공동 동작이 필요한 주장은 결합 시험을 별도 근거로 요구한다.
5. **답 고정.** 짧은 답과 상세 열람용 URL을 요청 판과 연결한다. 선택 부분과 필수조건마다 사용한 근거/남은 질문을 되짚을 수 있다. 검색에서 나온 원리와 실제 사용이 확인된 부품의 표현을 구별한다. 답이 여럿이면 어느 선택을 뒤집을지 판별할 확인 하나를 제시한다.
6. **변경 처리.** 새 출처판을 받으면 이전 판을 사용한 판단과 이를 입력으로 쓰던 후속 판단에 재검토 작업을 만든다. 지난 답 재생과 현재 상태 조회를 분리한다. 일부 관련 근거가 빠졌다면 자동으로 정반대 판정을 내리지 않는다.

## 5. 성장·장애·운영 비용

| 상황 | 대응과 남은 검증 |
| --- | --- |
| 출처가 바뀌거나 링크가 사라짐 | HTTP 상태와 ‘이유가 아직 맞는가’를 분리한다. 표본은 문서 판을 갈면 관련 판단을 보수적으로 재검토한다. 제품 단계에서 판 사이의 절 지문이 같은 경우 재검토를 줄이려면 단락 이동·분리·의미 변화 대조가 필요하다. |
| 여러 프로젝트나 분석기가 동시에 읽고 씀 | 실험은 동일 키의 재전송, SQLite 단일 작성자와 트랜잭션, 출처판 경쟁을 검사한다. 서비스 단계의 계정 분리, 권한 검사, 삭제 정책, 분산 작업자의 임대 만료·재할당은 별도다. 공용 링크와 개인 요청·근거는 별도 접근 범위로 둬야 한다. |
| 연결 대상이 스스로 의미를 바꿈 | 프로젝트가 쓰는 개체와 외부 자료의 동일성은 각각 버전·출처를 갖는다. 병합 별칭을 바로 사실로 쓰지 않는다. 기존 판을 다시 열 수 없으면 ‘당시판 미확인’으로 남긴다. |
| 수백만 링크와 수집 비용 | SQLite 표본은 동작을 점검하기 위한 크기다. 장차 전역 자료를 언어·출처·버전으로 좁힌 뒤 상위 일부만 판독하고, 외부 요청·바이트·편집 시간을 별도 집계한다. 링크 변경 알림은 프로젝트 원장 전체를 다시 판정하는 신호로 쓰지 않는다. 실제 카탈로그 크기의 지연·메모리·단위 비용은 미측정이다. |
| 사람이 문서 전체를 보지 않고도 쓸지 결정하고 싶음 | 출처 URL, 특정 절이나 대상, 추천 이유 한 줄, 깨지는 조건과 현재 미확인을 우선 전달한다. 원문을 더 읽을 역할은 사용자·후속 모델·선택적 검증기에 맡길 수 있다. 새 온라인 취득을 켤 경우 크기 제한·허용 공개 URL·타임아웃·취소·출처 권한을 구현해야 한다. |

지금 설계에서 가장 위험한 가정은 **작동 관계를 색인하는 비용보다, 다른 분야에서 정말 유용한 선택을 찾는 이득이 큰가**이다. 이득은 후보 수로 입증할 수 없다. 분야 이름이 주어지지 않은 새 설계와 사전에 봉인한 기존 후보로 비교하고, 알려진 이름을 가린 뒤에도 같은 결과가 나오는지, 사람이 실제 채택하거나 시험할 수 있는 새로운 행동이 생기는지를 본다. 효과가 작으면 주소와 짧은 설명만 유지하고 관계 편집은 반복해서 쓰이는 일부에 한정하는 구조로 되돌릴 수 있다.
