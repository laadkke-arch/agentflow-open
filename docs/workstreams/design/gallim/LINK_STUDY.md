# URL 한 개에 설명을 몇 바이트 더하면 무엇을 찾을 수 있나

설명 저장의 실익을 확인하기 위해 AF-RES-012의 고정 자료 156개와 전체·부분 설계 질문 36개를 다시 검색했다. **한국어 검색에서는 후보마다 기존 목적·메커니즘 설명을 덧붙이는 데 평균 104.9바이트가 더 들었고, 원리 후보 상위 10개 재현율이 0.066에서 0.125로 올랐다.** 영어에서 같은 변화는 101.2바이트와 0.219→0.226이었다. 이로써 모든 링크의 설명을 미리 작성할 이유가 충분한지는 알 수 없다. 이 실험에는 설명을 읽고 작성·교정하는 노동과 사람의 실제 설계 채택 비용이 들어 있지 않다.

## 비교 조건

- 같은 안정 ID, 같은 156개 URL, 같은 언어의 질문을 세 번 썼다. URL의 도메인·경로·문서명은 검색에 포함했다. 비교한 저장 내용은 ① 주소 ② 주소와 기존 이름·공식 요약 한 줄(없으면 고정 원장 제목) ③ 여기에 기존 작성자가 남긴 역할·목적·작동 방식을 설명하는 짧은 문구 하나다. ③에서는 앞에 반복되는 이름과 구분자만 제거했다. ①–③은 모두 로컬 색인 방식이고 이번에 새로 작성한 주석은 없다. 긍정·부정 조건을 검증하는 동작은 시험 범위 밖이다. [원 자료집·표현 규칙](https://github.com/laadkke-arch/agentflow-open/blob/cb602858378db90adb1f085953016267f9afbd6d/docs/workstreams/research/AF-RES-012/corpus/RULES.md)
- 12개 문제 각각의 전체 질의 1개·부분 질의 2개를 한국어와 원 연구의 영어 번역으로 따로 실행했다. 언어별로 NFKC와 소문자 정규화 후 영숫자 어절 기반 BM25를 적용했다. k1=1.5, b=0.75, 양수 IDF, 질의 단어 빈도 반영, 동점은 ID의 고정 해시로 풀었다. 어간 추출·번역·불용어 제거가 없다. 점수 0인 항목은 반환하지 않아 의미 없는 동점으로 상위 10개를 채우지 않는다. 한국어의 조사·활용 차이와 영어 정보가 많은 URL이 언어별 결과에 영향을 준다. 원 연구는 주소를 색인하지 않고 D-a·D-b를 서로 교체했다. 아래 비교는 주소에 각 필드를 **누적**하고 저장량을 계산한 별도 실험이다. [원 질문과 번역](https://github.com/laadkke-arch/agentflow-open/blob/cb602858378db90adb1f085953016267f9afbd6d/docs/workstreams/research/AF-RES-012/queries/TRANSLATION.md) · [원 연구 결과](https://github.com/laadkke-arch/agentflow-open/blob/cb602858378db90adb1f085953016267f9afbd6d/docs/workstreams/research/AF-RES-012/RESULTS.md)
- ‘저장 필드 B’는 해당 언어의 156개 값 자체의 UTF-8 바이트다. JSONL은 중복 없는 ID와 값을 배열로 기록한 실제 비압축 UTF-8 크기다. 따옴표·구분자·줄바꿈 1바이트를 포함하고 파생 색인·본문·DB 행 오버헤드·로그는 제외한다. 주소만 담은 원시 값은 총 8,159B(52.3B/건)이며 주소와 안정 ID를 함께 읽고 쓸 수 있는 JSONL은 11,224B(71.9B/건)다. URL, 양 언어 D-a와 D-b 본문의 빈 값은 각각 0/156이다. ko/en은 각각 하나의 단일 언어 프로필이며 URL을 두 번 지불한 이중언어 저장비로 더하면 안 된다.
- R@10은 원 판정 등급 1·2인 대상 중 상위 열 자리에 든 비율의 질의별 평균이다. 점수 불일치로 빈 반환이 된 질의에도 재현율 0을 준다. 역할 ‘원리’는 기존 자료집의 패턴·명세·알고리즘 분류다. 등급 1은 조건부 부품·전이·실패 경계 등 여러 종류를 포함한다. 둘 다 실제 타 분야 전이 성공을 전담하는 라벨이 아니다. ‘부분 질의’는 사용자가 전체 설계 중 한 부분을 물은 24개로, 근거의 부분적 성립과 구분한다. N은 유사하나 조건이 어긋난다고 이미 판정된 후보 수다. 미판정은 독립 열에 남겼다. [원 판정 기준](https://github.com/laadkke-arch/agentflow-open/blob/cb602858378db90adb1f085953016267f9afbd6d/docs/workstreams/research/AF-RES-012/qrels/NOTES.md)
- 순위를 만든 뒤에만 원 qrels와 원 연구의 상위 결과에서 모은 추가 판정을 읽는다. 새로운 주소 전용 순위를 위해 사람이나 모델이 추가 채점하지 않았다. 영어 URL에서 반환 256쌍 중 115쌍이 판정 밖이라, 해당 조건의 재현율·오답 개수는 알려진 판정에 한정된다. ‘최초 판정만’ 열은 채점 범위를 사전 동결판으로 좁혔을 때의 민감도다. 표의 숫자는 효과의 통계적 추정이나 모집단에 대한 하한이 아니다.

## 어떤 검색 근거가 실제로 작동했는가

- 제조의 인출·보충 원리를 느린 저장 장치의 투입 제어에서 참고할 수 있다는 Toyota 사례는 영어 URL만으로 4위였지만, URL과 질의에 함께 있던 단어는 **and 하나**였다. 공동기록 질문에서 TreeDB 논문이 영어 URL만으로 9위에 든 것도 공통 어휘가 **can 하나**였으며, 설명을 추가한 두 회차에서는 각각 84위와 17위였다. URL에 우연히 든 단어만으로 얻은 적중을 시스템이 다른 분야의 관계를 이해한 증거로 해석하면 잘못된다.
- 한국어에서는 Toyota·Bazel·TreeDB 세 사례가 목적·메커니즘 한 줄을 더한 뒤에도 점수 0이었다. 평균 원리 재현율의 상승과 이 실패는 함께 남는다. 설계자의 관계를 다른 표현으로 바꾸는 비용, 동종 분야에서 구할 수 없는 아이디어가 추가된 횟수, 전이의 성립 전제와 깨지는 조건은 이 실험에서 검증하지 않았다.
- 다른 분야 탐색의 귀결은 ‘링크당 몇 바이트’로 다 정할 수 없다. 주소만 보관한 뒤 요청 때 그 원문을 가져와 본문을 분석하는 방식, 외부 검색이나 새 자료 발견으로 링크를 더하는 방식은 별도 후보로 열려 있다. 이 비교에서는 외부 바이트를 가져오지 않았으며 그러한 방식의 속도·접근 실패·호출비·판 변동·다른 분야 발굴률을 추정할 수 없다. 이를 확인할 때에는 같은 사용자 목적, 같은 시간·원문 열람 수, 검색원이 다른 조건을 고정하고 ‘쓸 수 있는 원리 후보’와 ‘대상 적용까지 입증’한 수를 분리해 기록할 수 있다.

## 재현

Python 3.10 이상 표준 라이브러리와 Git만 사용한다. 아래 명령을 이 문서와 스크립트가 있는 디렉터리에서 실행한다. 첫 인자는 `cb602858378db90adb1f085953016267f9afbd6d` 객체가 들어 있는 agentflow-open 로컬 저장소의 경로다. 스크립트는 체크아웃·네트워크 접속·원본 수정 없이 고정판의 네 파일만 읽고 위의 두 표를 표준출력으로 내보낸다.

```sh
python3 link_study.py /absolute/path/to/agentflow-open
```

이미 그 커밋을 체크아웃했다면 같은 인자로 `/absolute/path/to/agentflow-open/docs/workstreams/research/AF-RES-012`도 쓸 수 있다. 디렉터리 모드는 제공한 파일을 그대로 읽으므로 판 고정이 필요할 때는 첫 번째 명령을 쓴다. 입력 파일은 과제 폴더의 `corpus/entries.jsonl`, `queries/queries.jsonl`, `qrels/qrels.tsv`, `results/pooled_judgments.tsv`다. 실험은 순위와 집계만 생성하고 입력 내용을 저장하지 않는다.
