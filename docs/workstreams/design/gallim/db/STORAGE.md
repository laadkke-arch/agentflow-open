# 원문에서 판정까지 보존하는 SQLite 기록

한 후보를 다시 평가할 때 지난 답변을 재현하려면 **그때의 요청, 실행 조건, 읽은 자료의 판본**을 함께 찾아야 한다. 이 예제는 세 요소를 별도 키로 저장한다. Python 표준 라이브러리와 로컬 SQLite 파일을 사용한다.

| 기록 | 무엇을 가리키는가 | 변경할 때의 동작 |
| --- | --- | --- |
| `request_revision` → `requirement` | 사용자가 쓴 전체 문장과 조건별 원문 범위·필수 여부. 범위는 유니코드 문자 기준 반열림 구간이다. | 요청을 수정하면 이전 판본에 연결한 새 판본을 만든다. 두 판본에서 같은 조건 이름을 사용해도 근거는 섞이지 않는다. |
| `resource` → `edition` → `candidate_context` | 자원 ID, 버전, 요청 판본, 적용 범위와 설정. 화면에서 같은 이름을 쓰는 프로젝트도 구분한다. | 원본을 직접 투입하는 경우와 사본을 준비하는 경우는 각각 한 문맥이다. |
| `source_document` → `source_revision` → `source_fragment` | 문서와 판본별 수록 범위, 수록 본문, 인용한 위치·URL. 전체 수록 텍스트와 인용 구간의 SHA-256을 따로 보존한다. | 같은 문서의 새 판본은 기존 끝 판본에서 이어진다. 독립적인 출처는 별도 문서로 등록한다. |
| `claim` | 한 조건에 관한 주장 한 개와 그 인용 구간. 후보의 대상 문맥과 근거가 실제로 관측된 문맥을 각각 지정한다. | 다른 판본의 설명, 복사 절차 제안, 유추도 보존할 수 있다. 평가기에 종류·문맥을 함께 전달한다. |
| `decision_run` → `decision_item`, `run_claim` | 한 후보의 판정 시점에 제공한 입력, 평가기 버전, 출력, 조건별 상태·근거 목록, 이미 대체된 근거의 식별자. | 새 답변은 별도 실행 번호를 얻는다. 지난 답변은 그때의 입력으로 계속 열 수 있다. |
| `decision_parent`, `recheck_job`, `recheck_resolution` | 참조한 선행 판정, 재검토 사유가 된 문서 판본, 재검토 결과를 대체하는 실행 번호. | 같은 자료에 의존하는 후속 판단까지 재검토 대상으로 삼는다. |

## 판본 갱신의 사례

1. 요청에서 “처음 넣은 폴더에 원본이 그대로 있어야 한다”를 필수조건으로 고정한다. 문서 처리기의 대상 버전과 소비 폴더 설정을 등록한다.
2. 고정된 문서 판본에서 소비 후 입력 파일을 제거한다는 구간을 읽고, 그 문맥·조건에 대한 반증 주장 한 개를 기록한다. 게시하면 클릭 당시의 판정과 입력 원문 범위, 근거 구간, 당시 사용된 평가기 버전이 연결된다.
3. 새 매뉴얼을 수록하면 저장소는 기존 근거를 읽은 판정과 그 판정을 참조하는 후속 판정에 재검토 작업을 만든다. 기존 답변의 상태는 당시 기록으로 남는다. 새 판정에 전달할 근거는 각 문서의 최신 수록 판본에서 가져온다.
4. 새 구간을 검토해 등록한 주장이 아직 없다면 평가기는 해당 조건을 직접 지지하거나 반증할 자료가 없는 상태로 판단한다. 이를 해소하려면 새 구간·주장을 명시적으로 등록하고 새 판정을 게시한다. 사람이 새 문장을 읽고 입력한 근거까지 저장소가 자동으로 검증해 주는 것은 아니다.

재검토는 읽은 모든 활성 주장에 대해 보수적으로 예약한다. 직접 반영되지 않았던 제안이나 범위가 다른 주장도 당시 읽었던 자료다. 기록된 선행 판단만 연결 그래프를 따라가므로 선언하지 않은 의존 관계는 추적할 수 없다. 새 문서 최초 등록이나 별개 주장 추가만으로 과거 답변이 자동으로 재생성되지는 않는다.

## 쓰기와 재시도

- `Ledger.transaction()`으로 입력 묶음을 원자적으로 저장한다. 개별 호출을 묶음 중간에서 사용해도 저장점과 바깥 트랜잭션이 함께 작동한다. 잘못된 인용 범위·외래 키·판정 결과로 실패하면 중간 행을 남기지 않는다.
- 같은 작업 키로 판정을 재요청하면 원래 실행 번호를 받는다. 같은 키에 다른 문맥·평가기 버전·부모·재검토 작업을 지정하면 오류다. 새 자료를 읽어 다시 판단할 때는 새 키를 사용한다.
- 같은 문서 끝 판본을 두 작성자가 동시에 변경하면 한 판본만 이어진다. 다른 작성자는 새 끝 판본과 자신이 받은 자료를 대조한 다음 명시적으로 재시도할 수 있다.
- 새 판정에 이미 재검토 대상이 된 부모를 입력하면 거절한다. 후속 판정의 재검토를 끝낼 때는 모든 기존 부모에 대해 유효한 원래 부모 또는 재검토한 대체 부모를 연결해야 한다.

아래 명령은 `store.py`가 있는 디렉터리에서 실행한다. `decision`의 숫자는 실제 게시로 반환된 실행 번호를 넣는다.

```sh

```

코드는 출처 본문·판본·인용 위치를 호출자가 제공하는 방식이다. 해시가 일치하면 수록 텍스트의 동일성을 다시 확인할 수 있다. 외부 사이트가 그 내용을 실제로 게시했다는 인증, 사용자별 접근 권한, 여러 서버 간 동시성, 원문 자동 수집은 이 단계의 검증 범위 밖이다.
