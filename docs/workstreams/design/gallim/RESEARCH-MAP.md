# 연구 60건을 제품 판단과 수용시험에 연결한 표

사용자는 소프트웨어 전체 또는 **선택한 부분과 그 목적**을 주고, 쓸 수 있는 제품·부품·참고 원리를 링크로 받아 설계 결정을 내린다. 이 문서의 시험은 그 목적에 맞춰 제안한 제품 수용시험이다. 오른쪽의 인계와 수용 기록은 각 연구자가 실제로 보고한 범위와 결손을 확인하는 곳이다. 아래의 제안만으로 원 연구의 미충족 항목을 통과 처리할 수 없다. [제품 의도](https://github.com/laadkke-arch/agentflow-open/blob/028d16fee1121f5862efd410b78ec1d79d7080f2/docs/product/RESEARCH_BRIEF.md)

## 생성·검색·판정 과정에서 보존할 정보

| 사용자의 결정 | 내부 데이터와 판정 기준 |
| --- | --- |
| 어떤 요청을 풀고 있는가 | 원문과 선택 범위, 목적, 필수·선호·금지, 대상과 시점을 보존한다. 해석이나 검색용 재표현에는 원문 위치를 단다. 빠진 정보가 실제 선택을 바꾸면 다음 확인 하나를 제시한다. |
| 이 후보를 어느 부분에 쓸 수 있는가 | 평가 한 건은 특정 요구와 구현·판·설정·제안 용도를 연결한다. 각 필수조건에 지지·반례·미확인, 원문 절과 관측 범위를 둔다. 두 조건 과제에서 서로 다른 판의 지지 한 건씩을 합쳐 완결 처리하면 실패다. 조건 개수는 실제 요청이 정한다. |
| 이미 쓰인 것인가, 옮겨 볼 원리인가 | 직접 사용 근거, 과거 채택 보고, 참고할 수 있는 메커니즘을 구별한다. 타 분야는 원 관계·대상과의 대응·전제·깨지는 입력을 기록한다. 사용자 본인의 채택 이력은 별도 결정으로 남긴다. |
| 보류 중 무엇을 한 번 더 확인할까 | 예를 들어 원본 보존이 필수이고 문서 한 곳만 더 열 수 있다면, 해당 배포판의 원본 삭제 설정과 기본값이 나온 절을 연다. 유지·삭제·자료 부족일 때 각각 후보가 어떻게 달라지는지를 먼저 적는다. |
| 재방문하면 무엇이 바뀌었는가 | 근거 주소·절·발행판·확인 시각·이전 판단을 보존한다. 저장 발췌의 복원, 현재 문서의 지지, 배포판의 재현, 특정 과거 프로세스에서 실제 사용은 각각 다른 증거를 요구한다. |
| 사람이 더 나은 선택을 하는가 | 같은 질문·자료·열람 예산에서 자유 검색, 링크만, 조건별 근거와 반례가 있는 링크를 비교한다. 조건 배정, 총 노동시간·품질·오권고 수락·완료 후 재작업을 같은 사람·과제에 연결한다. |

두 번 열어 두 조건을 확인하는 시험은 판정에 필요한 근거를 정해진 예산으로 얻을 수 있는지 확인한다. 제품이 보편적으로 두 조건 또는 두 링크로 제한되어야 한다는 근거는 없다. 실험에서 관측한 0, 해당 비교 분모가 0인 경우, 필요한 자료를 구하지 못한 경우를 따로 읽어야 한다.

## 내부 설계에 반영할 여섯 가지 규칙

| 단계 | 기록과 연산 | 재실행·변경 때 지킬 조건 |
| --- | --- | --- |
| 요청을 받는다 | 원문 판과 발췌 위치를 먼저 저장한다. 파생 조건에는 주어·행동·대상·긍정/부정·필수 여부·시점·해석 출처를 붙인다. 사용자가 명시한 목적과 분석자가 추측한 값을 구별한다. | 한 조건의 해석이 바뀌면 새 판을 만들고 그 조건에 의존한 질의와 판정을 다시 검사한다. 원어와 원래 제출한 검색 질의를 찾을 수 있어야 한다. |
| 후보를 찾는다 | 실행마다 요청판·파생 질의·검색원·목록판·반환 순서·열람 예산·실패를 기록한다. 후보 정체성, 실제 제안 용도, 문서와 절의 위치를 서로 다른 관계로 둔다. | 묶기·별칭 확장 전후의 후보와 원순위를 복원한다. 검색 결과가 비었는지, 요청 실패인지, 원문이 있었으나 해당 조건 근거가 없었는지 나눈다. |
| 근거 범위를 저장한다 | 출처의 발행판·대상 구현판·확인 시각·절과 짧은 발췌를 분리한다. 실행 근거가 있으면 환경·설정·입력·관측 출력·경계·재현 기록을 잇는다. | 서로 다른 판이나 설정에서 입증한 조건을 한 사용 사례로 자동 합치지 않는다. 공급자가 발행한 판, 소비자가 설치한 판, 과거 프로세스가 실제 읽은 자료판에 각각 고유한 증거를 요구한다. |
| 추천 결론을 계산한다 | 각 조건에 지지·반례·미확인과 판단원·규칙판을 저장한다. 필수조건 공동 지지는 같은 구현·판·사용 조건에서 모두 성립할 때만 파생한다. 참고 원리는 원래 관계·목표 대응·필요한 전제·깨지는 입력으로 표현한다. | 반례와 누락을 함께 보존한다. 근거 하나가 철회되면 그 근거만 의존하던 판정을 재검토하고 독립 근거는 남긴다. 사용자 채택은 제안이나 문헌 속 다른 작성자의 채택에서 추론하지 않는다. |
| 새 판을 반영한다 | 변경 사건에는 앞판·뒷판·관계·효력일·관측일을 기록한다. 자동 신호는 해당 이유를 재검토할 후보를 만든다. 새 결과는 이력에 덧붙인다. | 기존 주소가 살아도 이유의 조건은 바뀔 수 있다. 신호가 없더라도 필요한 원문을 재검증한다. 확인 가능한 과거 인용의 복원과 현재 사용의 유효성은 각각 검사한다. |
| 다음 확인의 비용을 정한다 | 각 미확인에 후보의 배제·보류·부분 사용이 실제로 달라지는 관측 하나와 대략의 확인 비용을 연결한다. 검색·원문 판독·재사용·재검사 횟수와 제약을 기록한다. | 확인을 추가했을 때 어떤 결정이 바뀌었는지 비교한다. 시스템 요청 수와 사람의 전체 노동시간은 별도 분모로 계측한다. 사람 시험에서는 조건 배정·품질·오선택·재작업을 같은 과제에 연결한다. |

가령 ‘원본 폴더의 **파일 유지**’와 ‘중복이면 **두 번째 등록 거부**’가 모두 필수라는 입력에서는 ‘내부 보관소 복사’ 근거를 첫 번째 조건에, ‘중복 감지’ 근거를 두 번째 조건에 자동 귀속하면 두 가지 오승인이 생긴다. 탐색기는 원문상 주어와 행동이 맞는 절을 찾고, 같은 구현판·설정의 지지나 반례를 각 조건에 연결한다. 해당 판의 중복 처리 설정만 확인하면 채택 여부가 달라지는 상황이면 그것을 다음 한 건으로 기록한다. 이 예시는 동작을 검사할 **합성 수용 사례**이며 특정 제품의 실제 판정은 고정판 원문에 따른다.

## 연구별 근거와 설계 대응

고정판의 인계·진행 기록과 세부 점검을 각 행에서 연다. 가운데 열은 대표 관측 및 적용 한계, 다음 열은 이번 제품안에서의 대응과 확인 방법이다. 모든 원 수용 기준의 문구·판정·미충족 사유는 맨 오른쪽 원장 또는 개별 검토에 따른다. 표 안의 자료만으로 같은 모델의 재판독을 사람 검증으로 승격하지 않는다.
