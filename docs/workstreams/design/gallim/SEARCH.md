# 조건을 잃지 않고 부품과 타 분야의 원리를 찾는 검색 설계

이 문서는 사용자의 부분 설계에서 후보를 찾고, 그 후보가 어떤 조건을 지키는지 판단하기까지의 내부 동작을 제안한다. 예시는 처음부터 끝까지 AF-RES-012의 K02.w 한 건이다. 스캔 문서를 가져오는 기능에서 **같은 파일을 다시 넣어도 문서가 중복 등록되지 않아야 하며, 최초 폴더의 파일은 삭제하거나 옮기면 안 된다**. 설치판과 중복 설정은 미상이고, 사용자는 이 단계에 쓰는 부품이나 원리를 선호한다. OCR 품질과 화면은 변경 범위 밖이다. 연구자가 만든 고정 질의이며 실제 고객 수요량이나 성공률을 측정한 값은 없다. [한국어·영어 입력 원문](https://github.com/laadkke-arch/agentflow-open/blob/cb602858378db90adb1f085953016267f9afbd6d/docs/workstreams/research/AF-RES-012/queries/queries.jsonl)

**이미 관측한 현상.** 자료집에 제약 설명을 더하자 한국어 BM25에서 Paperless-ngx가 20위 밖에서 1위로 올라왔다. 그 근거 문장은 실제로 소비가 끝난 파일을 최초 위치에서 제거하는 동작을 다루고 있었다. 검색은 중요한 문장을 잘 찾았고, 그 문장을 읽은 뒤의 판정은 ‘이 구성에서 위반’이어야 했다. 별도 영어 검색에서는 이름이 비슷한 Dataproc 노트북 도구도 2위까지 올라왔다. 고정판 사용 문서의 소비 동작과 개발판의 중복 처리 분기는 각각 해당 판과 경로에 귀속한다. [순위·동명이름·부정 반례 E07·E09](https://github.com/laadkke-arch/agentflow-open/blob/cb602858378db90adb1f085953016267f9afbd6d/docs/workstreams/research/AF-RES-012/ERRORS.md#L13-L16) · [근거와 설정 차이 C03·C05·C10](https://github.com/laadkke-arch/agentflow-open/blob/4d6208c08f6f2657865ba000d6768f6537e832b6/docs/workstreams/research/AF-RES-001/evidence/software.md)

**구현 범위.** 연구 브랜치에는 고정 자료집·질의·판정·검색 순위가 있다. 이 문서의 표는 제품 검색 설계다. SQLite에서 참조할 논리 레코드와 파생 색인 이름은 실제 테이블 DDL과 구분한다. 실행 표본의 합성 레코드나 고정 입력 검사는 열린 웹 탐색, 한국어 질의 자동 해석, 사용자의 환경 확인, 분야 단서 없는 발견의 품질을 입증하지 않는다. 제품의 입력·검색·저장 방식은 브리프에서 열려 있다. [연구 등급과 프로토콜](https://github.com/laadkke-arch/agentflow-open/blob/881bf8af6fe8b7044e828c1a999893d37ff25acf/docs/product/RESEARCH_PROTOCOL.md) · [제품 브리프](https://github.com/laadkke-arch/agentflow-open/blob/881bf8af6fe8b7044e828c1a999893d37ff25acf/docs/product/RESEARCH_BRIEF.md)

### 이 브랜치에서 실행할 수 있는 부분

동봉된 [검색 표본](db/retrieval.py)은 SQLite FTS5의 BM25와 선언된 원리 관계의 검색을 실행한다. 고정 어휘로 한국어·영어 요청에서 관계를 추출하거나 명시적인 관계 키를 받는다. 원본 요청·파생 검색어·관계 추출 방식·후보 구성 ID·근거 절 ID가 결과에 남는다. 검색 전용 테이블은 `retrieval_text`와 `retrieval_edge`다. [판단 저장소](db/schema.sql)의 `candidate_context` 및 `source_fragment` ID로 연결하고 재색인 실패 시 이전 색인을 보존한다. `--budget`은 표시할 구성 수다. 심층 취득량을 제한해 주는 옵션은 아래의 설계 제안에 속한다.

`python db/retrieval.py --demo --budget 2`의 스캔 고정 예시를 확인하면 R2의 `preserve-source-at-original-path`와 R1의 `prevent-duplicate-entry`가 추출된다. 어휘 후보 2개와 원리 후보 2개가 겹쳐 서로 다른 구성은 3개다. 표시한 두 개는 직접 소비 사례 `box`와 이용 사본 아이디어 `museum`이다. 전자는 최초 경로 조건을 위반하는 선언을, 후자는 타 분야 가설 선언과 그 절 ID를 갖고 있다. 둘 다 `unverified`로 반환된다. 이 고정 표본의 박물관 사례는 작성한 합성 데이터다. 실재 문헌에 의한 차용이나 제품 적합성 증거로 인용할 수 없다.

아래 세 경로 분리, 교차언어 사전 확장, 순위 결합식, 근거별 재판정, 원격 취득 예산, 사용자에게 새로운 조작을 측정하는 방법은 후속 설계다. 현재 검색 표본은 어휘 후보와 원리 후보를 결합한 뒤 직접 후보와 타 분야 후보를 우선 한 개씩 표시하고 서로 다른 자원을 선호한다. 별도 저장소의 판단 기능과 연결할 때도 검색 순위 자체를 지지 근거로 승격하지 않는다.

## 1. 무엇에 ID를 주고 무엇을 다시 만들 수 있는가

아래 이름은 구현 예시다. 판정의 작은 단위는 한 **요구 조건 × 후보 구성 × 적용 환경 × 시점**이다. 검색 결과 한 칸에는 이 단위 여러 개가 들어갈 수 있다.

| 논리 레코드 | 최소 필드와 식별 범위 | K02에서 필요한 이유 |
| --- | --- | --- |
| 요청과 조건 | 요청 ID와 수정판, 원문 문자열, 조건 ID, 글자 구간, 대상·동작·극성·필수성·발생 시점. 해석과 원문을 따로 보관 | R1은 재투입→새 문서 등록 금지, R2는 성공·재투입 상황에서 최초 경로 파일 삭제·이동 금지. OCR·화면을 범위 밖으로 유지 |
| 대상과 구성 | 제품·부품·원리 ID, 공급자·패키지 이름공간, 구성 ID, 판/설정/환경. 별칭에는 출처와 언어. 배포판·미러·후속 제품의 관계에 타입 | 동명 PyPI 도구를 분리. 같은 Paperless라도 원본 폴더 직접 소비와 별도 사본 소비는 두 구성 |
| 출처와 절 | 작품·문서 ID, URL, 판 또는 고정 커밋, 파일/절/심볼, 발췌 지문, 확인 시각. 동일 출처의 여러 URL과 변동판을 연결 | 내부 보관, 소비 후 최초 경로 삭제, 특정 중복 설정을 어느 문서판·코드 분기에서 읽었는지 추적 |
| 관측과 판단 | 주어·동작·대상·조건·근거 절 또는 시험 영수증, 관측 종류, 적용판, 판단 시각. 한 판단에 사용한 모든 근거 ID와 미확인 전제 | ‘보관한다’가 내부 파일인지 최초 경로 파일인지 확인. 직접 소비의 반례를 새 구성에도 자동 적용하지 않음 |
| 원리 대응 | 공여 분야·원리 ID, 출처, 입력/변환/유지할 상태/예외, 수신 측 역할 대응, 필요한 전제, 깨지는 입력, 관계를 제안한 주체 | 분야가 다른 유사 사례에서 옮길 수 있는 조작과 읽기 전용 경계·중복 조건의 빈칸을 보존 |
| 검색 실행과 선택안 | 실행 ID, 요청 수정판, 자료집·색인·어휘·규칙 판, 후보 ID와 발견 경로·순위, 열람한 바이트/절, 중단 사유. 선택안에 구성 ID와 미확인 조건 | 원문을 못 읽은 후보가 어디서 탈락했는지 복구. 사본 전달을 사용자의 요구와 별도 설계 제안으로 유지 |

SQLite 실험을 확장할 때 원본 레코드와 판단 이력을 먼저 영속화한다. 별칭의 정확 일치에는 `(namespace, alias, language)`, 근거 결합에는 `(configuration_id, revision, predicate, object_role)`, 무효화에는 `(source_revision_id, passage_id)`에서 판단 ID로 가는 역색인을 둔다. 대상 ID는 임의의 안정 키를 부여하고 URL 정규화는 중복 후보만 제시한다. 개별 경로의 순위, 전문 검색 문서, 원리·역할별 역색인은 위 자료로 다시 만드는 파생물이다. 어휘 정의를 고쳐도 원문·과거 순위·과거 판정은 원래 판 번호로 조회한다.

## 2. 한 요청의 세 검색 경로

원문을 먼저 그대로 고정하고 R1·R2의 범위와 부정 표현을 나란히 저장한다. 한국어 정규화·번역·동의어는 검색에만 추가한다. 예컨대 ‘삭제하지 않고’를 `delete`의 부정 필터로 구현하면 ‘소비 후 삭제한다’는 중요한 반례까지 빠진다. 긍정과 부정 표현 모두 찾아오고 판정 계층에서 읽는다. R2의 ‘그 폴더’를 ‘어딘가의 원본 사본’으로 바꾸는 확장은 금지한다. 문서에 나온 동사만으로 자동 극성을 확정하기 어려우면 해당 절을 보류한다.

| 경로 | 질의와 찾을 단위 | 이 요청에서 회수할 것 |
| --- | --- | --- |
| 원문·식별자 경로 | 제품·패키지의 정확 ID와 원문의 ‘중복’, ‘삭제하거나 옮기지’, ‘처음 넣은 그 폴더’. 제목·공식 별칭·본문을 각각 검색. 토큰 분할기와 자료 언어 기록 | Paperless 소비 문서와 동일 이름을 쓰는 다른 패키지가 각각 어느 대상인지 확인 |
| 동작·주장 경로 | 역할을 보존한 표현으로 확장. ‘재투입→또 등록’, ‘소비 성공→입력 제거’, ‘원래 경로→유지’. 코드 심볼·구현 절·시험과 부정 근거 포함 | 정상 소비와 중복 감지의 분기를 별도 회수. 재시도 시 문서 개수와 최초 경로가 동시에 보존되는지 검토 |
| 분야 이름 없는 원리 경로 | 제품 이름을 뺀 ‘원본을 그대로 두고 처리용 표현을 만든다’ 및 ‘같은 항목을 다시 받아도 한 번만 등록한다’로 원리의 관계 색인 검색 | 보존용 원본과 이용 사본을 구분하는 타 분야 사례를 찾을 질의가 생긴다. 이 예의 공여 문헌은 아직 확보하지 않았으므로 원리는 탐색 가설로 출력 |

한국어 전문 검색은 엔진 지원에 맞게 분절한다. SQLite의 기본 토크나이저만 사용할 때 ‘처음 넣은 그 폴더’의 조사와 띄어쓰기 차이를 놓칠 수 있다. 원문 전문 검색과 버전이 붙은 한영 어휘·기호 색인을 독립 경로로 유지하며, 평가 자료집에서 교차언어 회수와 잘못 승격한 후보를 함께 잰다. 벡터 검색을 더하는 경우에도 발견 경로 하나로 기록하고 기존 경로와 같은 적합성 판정을 거친다.

**합치기 순서.** 작은 비교 실험의 기본값으로 각 경로 상위 10건을 취해 동일한 대상·구성·판만 중복 제거한다. 경로별 원순위를 보존하고 `sum(1 / (60 + 경로별 순위))`로 읽을 순서를 정한다. 경로에 없으면 그 항의 기여는 0이며 동점은 안정 ID로 푼다. 동일 상류 문헌을 세 링크로 찾은 것은 독립 증거 한 건이다. 후보를 읽을 순서는 다시 계산할 수 있지만 사용자가 정한 필수조건은 이 식에 들어가지 않는다. 후보에 모순이 많아도 중요한 반례라면 조사 우선순위가 높을 수 있다.

## 3. 증거 판정과 다양성

두 조건에 대해 ‘지지’, ‘위반’, ‘미확인’을 따로 기록한다. 같은 구성·판에서 서로 상충하면 ‘충돌’을 두고 양쪽 근거를 노출한다. 구성 차이로 설명되면 행을 나눈다. 근거가 없는 상태, 열람 예산 소진, 후보 자체가 없는 상태를 별도로 보존한다. **직접 채택 가능한 후보에는 모든 필수조건과 그 조합의 환경 전제가 확인돼야 한다.** 한 조건이라도 위반한 구성은 반례, 미확인 조건이 남으면 확인할 후보, 다른 구성과 독립적으로 결합할 착상은 조합 제안으로 돌려준다.

| 검색 이후의 판단 단위 | R1 중복 등록 방지 | R2 최초 경로 보존 | 돕는 결정 |
| --- | --- | --- | --- |
| 원본 폴더를 Paperless의 소비 폴더로 사용 | 사용자 판·중복 설정 미상. 확인 필요 | 인용한 문서판의 성공 소비 경로는 위반. 사용자 설치판의 정확한 동작은 미확인 | 해당 문서판의 직접 구성은 제외하고, 원래 경로와 소비 경로를 분리할지 판단 |
| 원본 폴더를 읽기 전용으로 열고 별도 작업 폴더의 복사본만 소비 | 재시도·동시 투입에서 중복 방지 미확인 | 경로·권한·복사 완료 전 전달 방지 가정. 실측 전 미확인 | 조합 제안. 원본·대상 경로와 재입력 결과를 구분하는 시험이 필요 |
| 타 분야의 보존 원본·이용 사본 분리 원리 | 다른 분야에서 재등록 방지까지 제공하는지 미확인 | 역할 대응을 제안한 단계. 공여 원문과 수신측 실증 미확인 | 전용 제품을 상정하지 않고 사본 경계를 도입하는 설계 질문을 반환 |
| 같은 이름의 Dataproc 노트북 도구 | 대상 불일치 | 대상 불일치 | 동명이름으로 어느 경로에서 발견됐는지만 기록하고 제품 대안 수에서 제외 |

표에 채택으로 표시할 검증된 구성이 없으므로 이 예에서는 그 수를 **0**으로 반환한다. 숫자는 이 문서가 작성한 네 예시 행의 판정이며 데이터베이스 전체의 검색 결과가 아니다. 원문 근거에는 최초 경로 위반이 있다. 조합안에 대해서는 실제 입력과 같은 내용을 가진 두 파일, 동시 재전송, 복사 중 중단을 비교할 소형 시험을 제안한다. 처리 전후에 최초 경로·내용 해시와 등록 문서 수를 같이 기록한다. 원본이 남아도 문서 두 개가 등록되면 R1은 실패한다. 반대로 문서 한 개여도 원본이 사라지면 R2는 실패한다. 소유 경로가 다른 곳을 가리키거나 링크·마운트로 실제 입력에 접근한다면 보존에 관한 전제를 다시 확인한다. 시험 결과가 들어오기 전에는 두 조건을 통과한 것으로 저장하지 않는다.

**반환할 순서.** 먼저 필수조건을 모두 확인한 구성을 나열하고, 그다음 권고를 바꿀 정보 하나가 남은 조건부 구성, 다른 조작을 제시하는 원리와 반례를 따로 제시한다. 각 집합 안에서는 이미 반환한 결과가 다루지 않은 필수조건·구성 차이·새 확인 방법을 추가로 설명하는 행을 선호한다. 동률은 근거 절을 읽는 비용과 안정 ID로 정한다. 미러 문서가 새 필수 절을 담고 있다면 기존 구성의 추가 근거로 표시한다. 구성 ID, 바뀌는 조작, 구별 입력이 모두 같은 두 후보는 별도 설계 대안 수를 올리지 않는다. 예상 밖 원리를 위한 자리는 실제로 다른 동작과 검증 방법이 있을 때만 채운다.

## 4. 타 분야 원리를 찾아도 무엇이 새로워졌는가

원리 검색용 보조 색인에는 `preserve-source-at-original-path` 같은 관계 키와 공여 사례의 대상·입력·변환·불변조건·실패 조건을 둔다. 넓은 ‘보존’과 좁은 ‘최초 경로 보존’을 다른 관계로 저장한다. 계산된 유사도는 원리를 제안할 수 있고, 실제 차용 이력에는 수신 구현이 공여 원문을 지목한 별도 근거가 필요하다. 사용자가 이미 알고 있던 구성을 입력에 남길 수 있으면 ‘사용자가 명시한 대안’과 ‘이 제출에서 처음 제시된 대안’을 비교한다. 사용자가 안다고 말하지 않은 방식에는 사용자 기준 새로움이 미확인이라고 쓴다. 놀라움은 분야 간 거리보다 새로 선택 가능한 조작과 그 조작이 다른 결과를 내는 입력으로 설명한다. [분야 단서 없이 8요구×18후보를 조사한 결과](https://github.com/laadkke-arch/agentflow-open/blob/03ff2eb1264b85016266de1f36ddebe45f5fface/docs/workstreams/research/AF-RES-033/RESULT.md) · [역사적 차용과 구현 경계의 구분](https://github.com/laadkke-arch/agentflow-open/blob/e4c6a79f4fd1f4e3028b4407cf1c7433fe2eacd9/docs/workstreams/planning/REVIEW-16.md)

이 사례에서 공여 후보를 실제 대응으로 승격하려면 원본 보존 주체, 작업용 사본을 만드는 시점, 최초 위치·원본을 바꿀 권한, 실패 뒤 남는 상태를 원문의 절에서 채운다. 수신 측에는 최초 폴더, 별도 작업 폴더, 소비 프로세스, 문서 등록을 대응시킨다. 원본은 보존하지만 매번 새 등록번호를 내는 관행이면 R2의 착상으로만 쓴다. 원본의 위치가 바뀌어도 검색할 수 있는 관행은 R2에 대한 반례다. 공여측 원리 하나가 수신측에서 실제로 작동한다는 주장은 수신 구성 자체의 시험을 요구한다.

| 평가 대조 | 고정하는 것 | 달라야 할 출력 |
| --- | --- | --- |
| 양성 대조 | 시험용 자료에 ‘별도 작업 사본만 제거, 최초 경로·내용 유지’를 명시한 근거를 넣고 공급 분야 이름을 감춤 | 관계 키로 회수하고 R2 근거 절을 지정. R1은 그 문서에 없으면 미확인 |
| 가까운 음성 대조 | 같은 ‘원본 보존’ 문구를 쓰되 보관소로 이동한 뒤 최초 경로에서 제거한 자료를 같은 예산에 포함 | 어휘 검색에서는 회수할 수 있으나 R2는 위반. 채택 수에 포함되면 실패 |
| 반사실 대조 | K02 요청의 R2 한 조건을 ‘보관소 사본만 남으면 최초 폴더 삭제 허용’으로 바꾸고 나머지를 고정 | R2의 직접 소비 위반 사유가 사라져야 함. R1 미상은 유지. 이 입력은 별도 시험용 요청 수정판 |
| 새 대안 대조 | 동종 경로만 쓴 결과를 먼저 동결하고 타 분야 경로 한 개를 추가. 대상·공여 문헌·조작·시험 입력을 기록 | 수신 측 설계 조작과 경계 시험이 양쪽에서 같으면 새 대안 수 증가 0. 문헌의 설명 가치는 별도로 남김 |

고정된 자료집에서 시험용 대조를 통과한 결과와 공개 자료를 처음 찾아낸 결과는 원장을 분리한다. 실제 탐색 평가는 분야 힌트·공여자 이름을 미리 본 질의, 보지 않은 질의, 이미 선별한 원리를 찾아보게 한 질의를 구분한다. 동종 근거와 타 분야 근거가 다른 예측을 한 경우에만 어느 쪽의 예측이 맞았는지 계산할 수 있다. 그런 사례가 없으면 분모를 0으로 명시한다.

## 5. 어느 때 추가 원문을 열고 멈추는가

실험 하나의 예산을 먼저 고정한다. 예를 들어 로컬 경로별 상위 10건, 추가 취득은 URL 6개·문서당 500단어·총 전송 1 MiB 중 먼저 닿는 한도, 후보당 후속 절 2개다. 운영 권장값은 아니다. R1 설정과 R2 직접 소비의 모순처럼 추가 근거가 판단을 바꾸는 빈칸부터 읽는다. 공여 문헌을 찾는 경로에는 동일 총량 안에서 최대 2개 URL을 배정해 다른 후보 조사량이 줄어드는 비용도 측정한다. 검색·원문 취득·리다이렉트·재시도를 합친 외부 시도는 최대 10회로 둔다. 응답 크기가 남은 전송 예산을 넘으면 스트림 읽기를 멈추고 불완전으로 기록한다. 오류와 캐시 적중은 별도 계수한다. 같은 판·절을 두 경로에서 읽으면 전송 1회와 논리 열람 2회를 각각 기록한다. 네트워크가 없는 실험은 고정 자료집만 사용하고 원격 증거는 미확인으로 둔다.

본문이 잘리거나 판이 다르거나 모순이 풀리지 않으면 반환에 필요한 빈칸, 확인할 한 가지, 열어 본 범위와 멈춘 이유를 적는다. 커서나 예산 경계 뒤의 결과에는 부재 판정을 내리지 않는다. 변경 사실이 중요한 경우 동일 URL의 새 판을 별도로 보존하고 이전 판단을 그때의 근거로 다시 열 수 있게 둔다. 추가 획득 전후의 결과는 후보 수, 두 조건을 함께 입증한 구성 수, 근접 오답의 채택 수, 새 행동의 수, 논리 열람·실제 요청·바이트로 비교한다. 사람이 절약한 시간은 사람의 전 과제 수행을 별도 측정해야 한다. [고정 후보에서 절 도착점의 시간 대리값과 조건 완결 비교](https://github.com/laadkke-arch/agentflow-open/blob/6341dce67a4dd4e38f68c2f16c9ae9f499b18f6f/docs/workstreams/research/AF-RES-064/RESULT.md)

| 변경 | 다시 검사할 것 | 과거 조회에 남길 것 |
| --- | --- | --- |
| 사용자가 중복 정의나 보존 위치를 수정 | 새 요청 수정판의 조건과 그 조건이 등장한 후보 판정·순위 | 이전 원문·극성·분모·실행 ID |
| 같은 URL에서 문서판 또는 근거 절이 바뀜 | 지문이 달라진 절을 참조한 주장과 대응만 재판독. 절 이동·내용 변경·주소 실패를 분리 | 옛 판·지문·그 판의 인용. 지문 불변이어도 구성/버전 적용 범위는 별도 확인 |
| 사용자 설치판/설정 확인 또는 변경 | 즉시 채택을 보류했던 해당 구성과 설치판 전제. 다른 판에서 발견한 위반은 별도 보존 | 확인 전의 미상 상태와 실제 설치판에서 읽은 근거 |
| 어휘 사전·색인·순위 규칙 변경 | 파생 색인을 새 세대로 작성한 뒤 원자적으로 교체하고 고정 질의를 재생 | 이전 설정, 후보 합집합과 각 경로의 원순위, 실패했던 반례 |
| 타 분야 원전의 역할 대응이 철회됨 | 그 대응만으로 제안한 설계 원리와 검증 방법. 제품 직접 관측은 따로 보존 | 이전 대응과 철회 사유·시점 |

이 요청에서 답을 바꿀 첫 정보는 실제 설치판과 중복 설정이다. 그 정보가 있어도 원본 보존과 중복 방지의 결합은 확인할 조건으로 남는다. 검색이 성공했다는 가장 작은 주장은 **사용자가 지켜야 할 조건, 위반을 보여 주는 고정 절, 별도의 조작을 시도할 이유와 그 조작을 기각할 입력을 각각 찾았다**는 것이다.
