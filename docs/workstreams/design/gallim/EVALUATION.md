# 저장·조회 방식의 검증 기준

첫 검증 대상은 **질문에 답으로 쓸 수 있는 단위가 저장 뒤에도 보존되는가**다. 같은 프로젝트 안의 서로 다른 구현, 같은 기능의 서로 다른 쓰임, 과거에는 맞았지만 지금은 성립하지 않는 설명을 분간해야 한다. 검사 결과에는 입력판·실행한 구현판·기대값·실제값·실패 원인을 함께 적는다. 아래 시험은 구현 후보의 인수 기준이다. 이번 문서 작성에서 직접 확인한 범위는 마지막 절에 구분했다.

## 1. 저장 계약과 실패 복구

작은 고정 자료를 먼저 만든다. 예를 들어 문서 V1에는 ‘내보내기 지원’이 있고, V2에는 ‘읽기 전용’이 있다. 같은 사이트의 별도 도구에는 내보내기 기능이 여전히 있다. 이 세 사실에 다른 식별자를 주고, 서로 무관한 두 사용 목적을 붙인다. 기대 답은 색인 구현을 보기 전에 사람이 고정한다.

| 상황 | 넣을 입력과 관찰할 결과 |
| --- | --- |
| 중복과 재시도 | 같은 수집 요청을 두 번, 판이 다른 같은 URL을 한 번, 같은 바이트가 다른 출처에서 온 경우를 한 번 넣는다. 논리상 같은 요청은 한 효과만 내고, 서로 다른 판·출처의 관측은 각각 남아야 한다. 콘텐츠 해시가 같아도 출처별 방문 기록을 유지한다. |
| 동시 수집과 중간 중단 | 두 작업자가 같은 입력을 받는 경우, 서로 다른 두 판을 역순으로 쓰는 경우, 내용 저장 뒤·관계 기록 뒤·색인 반영 전 프로세스가 끝나는 경우를 만든다. 재시도 뒤 확정 기록·유효한 관계·조회 결과를 중단 없는 실행과 비교한다. 비동기 색인이 뒤처진 동안의 응답에 검색 가능 시점과 누락 범위가 드러나는지도 확인한다. |
| 버전 교체·철회 | V2 공개 전후 및 수집 전후의 질의를 따로 실행한다. ‘그날 실제로 알 수 있던 것’과 ‘나중에 얻은 자료로 그날의 사실을 복원한 것’의 답을 구분한다. 옛 철회 근거는 당시 조회에서 복원되고 현재 추천에서는 제외돼야 한다. 발행 시점을 모르면 불명으로 반환한다. |
| 출처와 유도된 주장 | 한 추천의 조건마다 원 자료의 고정판·위치까지 역추적한다. 독립 구현 두 개, 상호 보완 문서 두 개, 단순 거울 페이지 두 개의 관계를 다르게 복원한다. 같은 대상 이름만으로 발견·적합·실제 사용을 서로 대신하지 않게 한다. |
| 신뢰되지 않은 입력 | 문서 안의 지시문 모양 평문, 미지원 형식, 끊어진 본문, 접근할 수 없는 출처를 통과시킨다. 문서 내용은 인용 가능한 데이터로만 저장하고 작업 권한·조회 범위·검증 상태를 바꾸지 않아야 한다. 읽지 못한 자료에는 실패 이유와 시도를 남기고 원문 확인 성공 건수에서 제외한다. |
| 재구축과 복원 | 빈 검색 색인을 원 기록에서 다시 만들고 정답 집합·동순위 처리·근거 연결을 비교한다. 백업에서 복구한 뒤 같은 입력을 재전송해 중복 효과가 없는지 확인한다. 재구축 후 재현에 필요한 모델·분할·색인 설정의 판도 기록한다. |

시점 뒤섞임, 출처 유실, 읽지 않은 원문의 확인 처리, 재시도로 인한 중복 확정은 **발견 건수와 무관한 중단 조건**이다. 원인과 재현 입력을 고치고 같은 시험을 다시 통과한 뒤 검색 품질을 비교한다. 구현이 해당 동작을 아직 지원하지 않으면 그 칸은 미검증으로 남긴다.

## 2. 같은 원문에서 어떤 질문을 더 잘 푸는가

**A**는 문서 단위 전문 검색에 제목·기능명·버전 필터를 적용하는 기준선이다. **G**는 제안된 저장 단위·관계·원문 절 연결을 쓰는 조회다. 두 조건 모두 같은 원자료·시점·권한·검색 가능 범위, 결과 세 자리와 근거를 열 수 있는 횟수, 동일 요약 모델을 쓴다. A도 원문 위치·검색어 확장·보류를 쓸 수 있다. 각 조건의 전처리와 사람 손질을 비용 장부에 올린다. 외부 탐색까지 포함한 ‘평소의 상위 모델+웹 검색’ 비교는 별도로 실시한다. 고정 자료 안에서 찾는 능력과 아직 수집하지 않은 선례를 발견하는 능력은 다른 분모다.

| 봉인할 질문 사례 | 성공 기준 |
| --- | --- |
| 같은 요구·다른 구현 / 같은 구현·다른 용도 | 독립적으로 쓸 수 있는 대안을 살리고, 서로 대체할 수 없는 두 근거가 결과 세 자리에서 함께 보인다. |
| 전체안의 일부만 충족 / 같은 말·다른 기능 | 후보가 실제로 만족하는 조건과 남은 접합을 반환한다. 확인되지 않은 부분까지 전체 해결이라고 표시하면 오승인이다. |
| 현재 사용·과거 결정 / 동의어·부분 이름 | 지정한 시점과 용도에 맞는 후보 및 근거의 정확한 위치가 나온다. 날짜·이름만 일치하는 오답을 별도로 센다. |
| 답이 없는 질문 / 자료 접근 실패 | 보류 사유와 다음 확인에 필요한 입력을 반환한다. 답이 없다는 결론과 현재 확보한 근거가 부족한 상태를 구분한다. |

후보 수·링크 수 대신 **신규 질문 사건**을 한 건으로 센다. 과제 발견 전에 봉인한 적격 집합이 있는 경우에만 상위 세 자리 회수율을 계산한다. 정답이 여럿인 경우에는 ‘한 개 이상 회수’, ‘서로 독립인 대안 중 회수 비율’, ‘필수 조건의 근거까지 회수’를 나눈다. 적격 집합이 비거나 원문이 불명인 사건은 별도 분모로 두고, 잘못 확정한 사건과 올바르게 보류한 사건을 센다. 표본마다 A만 성공·G만 성공·둘 다 성공·둘 다 실패·미확인과 실제 반환 근거를 공개한다. 검색 밖에서 정답을 찾은 사건은 발견 당시와 소급 판정을 함께 보존한다.

진단할 때는 하나씩 바꾼다. 같은 후보·같은 순위에서 첫 목적지만 문서 첫머리와 해당 절로 바꿔 검증 도달을 비교한다. 그다음 같은 표현에서 관계 기반 묶음만 켜 보고, 숨겨진 독립 대안과 복원된 보완 근거를 센다. 같은 질의에서 추가 기능명만 켜 보면 이름 확장이 불러온 적격 후보와 오탐을 함께 셀 수 있다. 이 내부 비교로 인한 순위 향상을 사람의 발견·채택으로 환산하지 않는다.

## 3. 유지할 가치가 있는지 판단

비교당 읽은 원문·모델 호출·저장 및 전송량·실패와 재시도·질의 지연을 기록한다. 데이터 크기와 동시 사용자 수를 명시하며, 작은 고정 자료의 지연은 그 조건에서만 보고한다. 구축, 잘못 묶인 항목 분리, 출처 갱신, 철회 확인에 들어간 **사람의 분**은 별도다. 7일·30일에 실제 재사용과 관리 노동을 기록하고, 같은 품질로 끝난 질의에서 추가 구축·운영비를 회수할 수 있는 재사용 횟수를 구한다. 관측하지 않은 미래 이용량은 가정으로 표시한다.

다음 단계로 넘어갈 판단은 자료를 보기 전에 정한다. 무결성 시험을 통과하고, 미사용 과제에서 독립 대안·근거 도달이 기준선보다 개선되며, 치명적인 오승인과 허용 비용을 넘지 않아야 제한된 사용 시험을 연다. 동률이거나 자료가 적으면 이득이 자주 난 질의 종류만 남겨 새 과제로 재검한다. 절 연결만 도움이 됐다면 더 단순한 문서 검색에 절 연결만 추가한 구현을 다시 비교한다.

후속 예비시험은 공개 과제와 별도로 결과를 보지 않은 실제 설계 문제 8건(전체안·부품 각 4건)을 제안한다. 당사자가 알던 대상과 용도를 먼저 적고, 같은 도구·예산을 받은 평소 모델+검색과 갈림을 더한 조건을 비교한다. 과제마다 서로 다른 사람이 두 조건을 맡으며, 같은 사람이 다음 과제를 할 때에는 조건과 순서를 교차 배정한다. 독립 채점자 두 명이 출처·조건을 확인하고 도구명과 작성자를 가린 채 판정한다. 주 결과는 **당사자가 뜻밖이라고 확인하고, 적합 근거가 있으며, 실제 다음 결정에 반영할 수 있는 대안을 하나 이상 얻은 신규 과제 수**다. 7일 뒤 최초안의 품질·수정 노동, 포기·미완·추적 결손을 함께 남긴다. 최종 작성자가 AI일 때는 별도 세션에서 같은 최종 모델의 설계 변화만 본다. 이 작은 표본은 다음 시험을 설계할 관측치이며 일반적인 제품 효과나 검정력의 추정치는 아니다.
