# AgentFlow Studio 연결 경계 — 미래 통합 제안

상태: **참고 계약 초안, 연결 코드는 없음**. 2026-11-19.

최신 사용자 의도는 [연구 브리프](RESEARCH_BRIEF.md)를 따른다. 전체 구조 또는 선택한 부분과 그 목적을 받을 수 있으며, 탐색기에 필요한 입력을 연구한 뒤 AgentFlow에 그 형식으로 요청하는 방향이다. 아래 기능 중심 예시와 JSON은 이를 제한하는 확정 API가 아니다. 다른 종류의 제품에서 부분 원리·아이디어를 찾는 질문도 연구 대상이다.

## 왜 연결하나?

기존 AgentFlow Studio에서 프로젝트의 기능 지도·작업 기록·근거를 보다가 '이 부분을 직접 만들지 않고 해결할 수 있는 기존 도구가 있나?'라고 질문할 수 있다. 탐색기는 선택된 기능/문제에 대해 대체 서비스·재사용 부품·참고 구현을 비교해 답한다.

기존 Studio는 AI 작업/프로젝트 맥락과 이력을 다루며, 탐색기는 외부 자원의 사실·제약·채택 이유를 다룬다. **두 프로젝트의 저장소·운영 데이터·권한 범위는 지금 분리**한다.

## 초기 독립 동작과 추후 연결

1. 탐색기는 우선 사용자가 기능/문제 설명을 직접 입력해 검색·비교하도록 한다. AgentFlow 연동 없이도 단독으로 이용 가능해야 한다.
2. 다음 단계에서는 Studio에서 선택한 **명시적으로 허용된 지도 부분/문제 설명**을 일회성 입력으로 보내는 경로를 검토한다.
3. 탐색기에는 프로젝트의 전체 대화 원문, API 키, 개인 작업공간 전체를 자동 전송하지 않는다.
4. 원본 코드의 지도 출력/저장 계약을 직접 검토한 뒤 명세를 확정한다. 과거 채팅 설명을 최신 API 계약으로 취급하지 않는다.
5. 연결 결과는 어떤 후보가 기능과 맞는지, 왜 맞는지, 반례, 재확인 시점을 포함하는 **근거 링크**로 반환한다.

## 데이터 교환 개념 예시 (실제 API가 아님)

~~~json
{
  "request": {
    "selected_capability": "session_history_reuse",
    "problem": "프로젝트의 AI 작업 이력을 나중에 다시 활용",
    "constraints": ["self-hosted preferred", "evidence required"],
    "shared_context": "사용자가 공개 가능하다고 선택한 최소 설명"
  },
  "response": {
    "candidates": [
      {
        "resource_id": "example-id-only",
        "relationship": "component",
        "fit_reason": "검증할 이유와 요구사항 연결",
        "evidence_urls": [],
        "evidence_level": "D0",
        "unknowns": ["실제 연동 검증 전"]
      }
    ]
  }
}
~~~

**예시 레코드는 가공된 형식 예제이며 실재 후보 추천 또는 검증이 아니다.**

## 검증 전 금지할 가정

- GitHub OAuth 연결이 AI 웹 대화 원문까지 자동으로 제공한다는 가정.
- MCP/외부 도구 호출과 사용자의 모든 메시지 저장을 동일하게 보는 가정.
- 현재 Studio 지도 파일/브라우저 저장 구조가 외부 서비스에서 바로 접근 가능하다는 가정.
- 한 대화에서 보이는 정보를 다른 대화가 자동으로 알고 있다는 가정.
- 이 탐색기의 초안 DB를 Studio의 운영 이력 저장소로 사용하는 가정.

실제 통합은 **사용자 승인·데이터 범위·정확한 지도 인터페이스·보안·성능 테스트**가 완료된 후 별도 PR로 진행한다. Studio 저장소는 이 작업환경에서 수정하지 않는다.
