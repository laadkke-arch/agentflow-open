# 제품 요구사항·실행 로드맵

상태: **기획 단계**. 작성 2026-11-19. 제안/확정/미검증을 분리한다.

## A. 이미 정해진 목표

- 독립된 오픈소스·웹사이트·유용한 서비스 탐색기 시작. 기존 AgentFlow Studio는 그대로 두고 나중에 연동.
- 기획보다 먼저 기존의 적절한 도구/서비스/사례와 수요의 이유를 조사한다.
- 무료 서비스, 공개 소스, 상업 서비스, 재사용 컴포넌트를 구별한다.
- 문제/기능과 연결한 이유·제약·확인 근거가 있어야 한다.
- GitHub에 프로젝트 결정과 조사·실험 결과를 누적하며, 여러 AI 대화가 재사용할 수 있어야 한다.
- 추후 데이터베이스 기반 검색·조회·등록·수정·삭제 웹앱을 만들고 공개 접근 가능하게 한다.

## B. 수업 과제와 제품 목표의 구분

앞서 검토한 데이터베이스 과제는 *관련된 2~5개 테이블, PK/FK 관계(1:N 포함), CRUD·검색 및 공개 접속*을 요구하는 것으로 이해했다. 제공된 수업 예시에는 **Flask + TiDB Cloud + GitHub + Render** 배포가 등장하며, 예시의 QR 코드는 구현 사례이다.

- **수업 충족 요건**: 과제 지침의 최신 원문을 제출 전에 다시 대조해야 한다. 특히 QR과 Antigravity는 예시인지 필수인지 분리 확인한다.
- **제품 차별점**: 출처·근거·문제 적합성·채택 결정. 수업 통과만으로 제품의 추천 정확도를 증명하지 않는다.
- **개발 편의 제안**: 데이터 모델은 5테이블 초안을 두고, 실제 DB 선택과 Render 배포는 별도 승인 단계에서 확정한다.
- 로그인/권한이 없다면 공개 사이트에서 데이터를 아무나 수정하게 두지 않는다. 시연을 위한 쓰기는 별도 데모 데이터와 접근 제어를 사용한다.

## C. 순서와 완료 기준

| 단계 | 산출물 | 완료 판정 |
| --- | --- | --- |
| P0 공통 협업 규칙 | 이 문서, 역할 3개, 브랜치·인수인계 | 새 대화가 지정 문서·브랜치를 읽고 같은 범위로 시작 가능(직접 새 대화 검증은 별개) |
| P1 조사 증거 | 최소 10–20개 실재 후보의 근거·미확인·비교 | 타인이 원본 URL·확인일로 근거를 따라갈 수 있음 |
| P2 데이터 계약 | 2–5 테이블 SQL 초안 및 제약/테스트 | 실제 DB 또는 호환 시험환경에서 FK·JOIN·CRUD·중복·삭제 실패 재현 |
| P3 제품 MVP | 열람·검색·필터·자원 관리·프로젝트 관계 입력 | 사용자 경로와 권한·입력 검사가 통과 |
| P4 배포 | 배포 환경·DB·비밀키 분리·백업·접속 확인 | 내 PC가 꺼져도 공개 URL이 동작하고 관리자 쓰기 제한을 확인 |
| P5 품질·연동 | 실제 프로젝트 맞춤 비교, 선택한 지도 부분 연결 | 독립 탐색기와 선택한 AgentFlow 문맥이 근거 포함해 왕복됨 |

P1의 후보 숫자는 **초기 실험 제안**이며 확정된 납품 기준이 아니다. 각 단계가 끝나지 않았는데 다음 단계 완료로 보고하지 않는다.

## D. MVP 범위를 좁히는 기준

- 처음에는 수작업으로 사실을 검증하고, 반복 수집 대상만 API/자동화한다.
- 데이터는 Git에 작은 비식별 검증용 예시, 실제 웹앱 데이터는 DB에 둔다. 인증정보·대화 원문은 공개 저장소에 넣지 않는다.
- 외부 API 속도/가격, 커뮤니티 크롤링 제한, 데이터 재배포 라이선스를 확인한다.
- 대규모 추천 모델·의미 검색·AI 자동 판정은 P1/P2 기초 품질이 확보된 후 검토한다.
- GitHub Actions 무료량/결제 정책이 개발 계속 가능성을 좌우하지 않도록 로컬/직접 실행 경로를 유지한다. 차단 시 Windows/Linux 원격 검증이 성공했다고 주장하지 않는다.

## E. 현재 미완료

제품 개발 브랜치·실제 자원 카탈로그 데이터·테이블 마이그레이션·검색 화면·관리 권한·Render 배포·AgentFlow 지도 연동은 아직 없다. `docs/collaboration/`의 3세션은 **P1·P2·P3 설계·조사**를 병렬 검토하기 위한 것이며, 서로 구현 완료를 가정하지 않는다.
