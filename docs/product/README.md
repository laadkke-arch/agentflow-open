# Open-source & Service Discovery — 제품 기준문서

상태: **초기 제품 브리프, 아직 구현/검증 전**. 최종 명칭 미정(가칭: 오픈소스·웹서비스 탐색기 / Resource Discovery Lab). 기준일: 2026-11-19. 이 문서는 사용자와 앞선 대화에서 확인된 방향을 별도 프로젝트가 재개할 수 있도록 정리한 것이다.

**최신 범위:** 사용자가 추가로 설명한 목적·부분 구조·다른 분야의 메커니즘 참고·링크 중심 저장 가설은 [향후 연구 브리프](RESEARCH_BRIEF.md)를 우선 읽는다. 지금은 환경 설정 단계이며 제품 연구는 미래 작업자의 과제다. 아래 MVP·5테이블·분류는 초안이고, 여러 대안의 조사와 조합을 막는 확정 조건이 아니다.

> 핵심: **오픈소스를 많이 모으는 서비스가 아니라, 특정 개발 문제를 기존 도구로 해결할 수 있는지 근거를 들어 찾고 비교하는 서비스.**

## 1. 배경과 목적

- 새 기능을 구현하기 전에 이미 존재하는 저장소, 무료/유료 웹서비스, 재사용 가능한 라이브러리, 공개 구현 사례를 찾는다.
- 저장소의 Star 수나 키워드 일치보다 **왜 필요하고, 프로젝트의 어떤 부분에 적용할 수 있으며, 무엇이 맞지 않는지**를 설명한다.
- 단순 리스트, 검색 결과 나열, 자동 생성된 홍보 문구로 끝내지 않는다. 출처, 확인 시점, 제약, 적용 관계, 미확인 사항과 실험 결과가 함께 남아야 한다.
- 발견과 비교에서 생긴 지식을 GitHub에 버전 관리하고, 다음 조사·개발·검증 작업에서 재사용한다.
- 기존 `tlsee0813-cmd/agentflow-studio`와 **독립적으로 개발**한다. 향후 AgentFlow 프로젝트 지도에서 선택한 기능/문제에 맞는 자원을 추천하는 연결을 검토한다. 기존 제품 코드나 운영 환경을 자동으로 건드리지 않는다.

## 2. 구분해야 하는 두 축

1. **발견할 대상**: 공개 GitHub 저장소, 공개 문서·예제, 유용한 웹사이트, 개발 도구, SaaS/서비스, 무료 도구 및 공개 소스 부품. 유료 서비스도 비교 대상일 수 있지만 '무료' 및 '오픈소스'로 표시하지 않는다.
2. **프로젝트와의 관계**:
   - **대체 서비스 (alternative)**: 직접 구현하지 않고 외부 서비스를 사용하는 선택.
   - **재사용 부품 (component)**: 라이브러리, CLI, API, MCP 서버 등을 프로젝트의 일부로 통합하는 선택.
   - **참고 구현 (reference)**: 설계/코드/운영 패턴을 배우되 그대로 의존하지 않을 선택.

하나의 대상이 프로젝트에 따라 다른 관계를 가질 수 있다. '발견한 종류'와 '활용 관계'를 한 필드로 합치지 않는다.

## 3. 핵심 사용자 여정

1. **문제 정의** — 예: 'AI 도구의 작업 기록을 나중에 이어 쓰기 위해 무엇을 재사용할 수 있나?' 기능, 환경, 예산, 필수 조건을 기록한다.
2. **후보 발굴** — GitHub 검색·topics·awesome 목록, 오픈소스 문서·릴리스·이슈, 커뮤니티 사용 사례, 웹서비스 자료에서 후보를 얻는다.
3. **중복 정리** — 저장소 루트, 문서·이슈 URL, 공식 서비스 홈페이지를 구분해 같은 대상을 재등록하지 않는다.
4. **근거 확인** — README 주장과 직접 코드 관찰, 실제 실행 결과를 구분한다. 기능, 라이선스, 비용, 유지보수, OS·API 호환성, 제한 사항을 기록한다.
5. **프로젝트에 연결** — '어떤 기능을 대체/재사용/참고할지'와 채택·보류·제외 이유를 남긴다.
6. **비교·추천** — 적합성 설명과 근거 링크, 확인하지 못한 점, 직접 구현 시 필요한 작업을 함께 제시한다.
7. **갱신** — 시간이 지난 주장과 실험 결과를 다시 확인한다. 과거 결정은 이력으로 남기고 현재 판단을 갱신한다.

## 4. MVP 사용자에게 보여 줄 것 (제안 — 구현 아님)

- 자원 목록·상세 정보, 유형/기능 필터, 검색.
- 자원 등록/수정/삭제(관리자 한정), 출처·확인일·검증 수준 표시.
- 기능(capability)별 연결 및 3가지 활용 관계 선택.
- 사용자의 프로젝트/관심 기능에 자원을 연결하고 비교 이유 작성.
- 후보의 **미확인 정보는 미확인으로 표시**. Star/최종 갱신일만으로 적합성을 확정하지 않는다.
- 공개 페이지는 기본 열람 전용. 변경 권한·인증·악성 링크·입력값 처리 등은 배포 전에 설계·검증.

## 5. 지금 하지 않는 것

- 수천 개 저장소 자동 수집이나 서비스 약관을 무시한 크롤링.
- GitHub Star 기반의 무근거 '최고의 툴' 순위, LLM이 만든 검증되지 않은 사실의 자동 등록.
- 현재 AgentFlow Studio 저장소 수정, 사용자 AI 대화 원문 수집 또는 새로운 OAuth 범위 승인.
- Render·클라우드 DB 구축·공개 배포를 이 문서가 완료한 것으로 간주.
- 다중 ChatGPT 세션이 서로 기억을 자동 공유하거나 무기한 돌아간다고 가정.

## 6. 성공의 증거

- 하나의 개발 질문에서 **서로 다른 유형의 후보를 실제 출처로 확보**할 수 있다.
- 후보의 중복, 특징, 적용 관계, 불확실성, 탈락 이유를 추적할 수 있다.
- 2개 이상의 실제 기능·환경 제약을 넣었을 때, 추천 이유가 단순 검색 일치와 구별된다.
- CRUD와 관계형 JOIN이 실제 DB에서 작동하고, 권한 없는 쓰기는 거부된다.
- 다른 세션이 저장소 기준문서, 작업별 기록, 검증 커밋을 읽어 같은 결정을 재구성할 수 있다.
