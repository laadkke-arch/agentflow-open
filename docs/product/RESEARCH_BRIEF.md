# 향후 작업자에게 전달할 제품 연구 브리프

2026-11-19 사용자 설명을 기록했다. **미래 연구 과제의 목적과 질문이며, 현재 환경 설정 담당에게 제품 조사를 시작시키는 지시가 아니다.** 이 문서를 저장한 시점에 아래 질문의 조사·DB 설계·수집기 구현은 시작하지 않았다.

## 원하는 가치

사용자가 만들고 있거나 만들 예정인 소프트웨어의 전체 구조 또는 일부 구조와 목적을 받아, 도움이 될 기존 오픈소스·사이트·서비스·기능·부품·참고 원리를 찾고 그 링크를 제공한다.

비슷한 완성품만 찾는 데 그치지 않는다. 다른 종류의 제품이라도 일부 구조, 해결 방식, 반복·관리 원리, 상호작용 아이디어를 가져올 수 있으면 발견할 수 있어야 한다. 이미 더 나은 해결책이 있는데 모르고 다시 만들거나, 뒤늦게 유용한 원리를 발견해 설계를 크게 고치는 비용을 줄이는 것이 목적이다.

상세 코드와 긴 설명은 연결한 원문에서 읽을 수 있다. 제품의 반환 결과는 왜 도움이 되는지와 어느 부분에 해당하는지 이해할 수 있는 링크 중심으로 생각하되, 정확한 정보량과 형식은 연구 대상이다.

## 나중의 설계자가 받을 결과

앞선 연구자는 근거가 붙은 작고 재조합 가능한 연구 묶음을 만든다. 여러 창의적인 대안·서로 다른 원리·반례·조합 조건을 남긴다. 사용자는 이후 최상위 모델로 필요 없는 묶음을 버리고 다른 묶음을 재조합해 최종 설계를 맡기려 한다. 연구자가 일찍 한 가지 방식만 확정하는 것은 기본 목표가 아니다.

운영 방식은 [연구·정리 규칙](../RESEARCH_WORKFLOW.md)을 따른다. 이 문서에 나온 주제를 세 세션에 그대로 고정 분배할 필요는 없다.

## 입력과 연동에 관한 의도

- 향후 AgentFlow에서 작업 중·예정인 설계의 전체 또는 선택한 부분, 그 부분으로 이루려는 목적을 제공할 수 있다.
- 탐색기에 적합한 입력을 먼저 연구한 뒤 AgentFlow에 그 자료 형식으로 요청할 수 있다. 기존 예시 JSON을 현재 API 계약으로 고정하지 않는다.
- 전체 프로젝트가 없어도 부분 질문에 답할 수 있는지, 필요한 주변 문맥을 얼마나 요청할지 연구한다.
- 현재 AgentFlow Studio의 코드·데이터·운영환경을 이 설정 작업에서 변경하거나 연결하지 않는다.

## 예시·가설과 확정 요구의 구분

| 사용자에게서 나온 생각 | 현재 취급 |
| --- | --- |
| 링크 주소와 가벼운 설명을 저장하면 작고 찾기·관리하기 좋을 수 있음 | 우선 비교할 가설. 최소 필드와 정확도는 미결정 |
| 링크에 들어가 확인하는 크롤링 구조가 필요할 수 있음 | 필요 여부 자체가 연구 질문. 상시 크롤러는 확정 아님 |
| AI/API로 구조·목적을 먼저 분리·정리하면 질의가 나아질 수 있음 | 전처리 후보. 필수 단계·모델·호출 수는 미결정 |
| 원문 링크를 열어 코드·상세 설명 확인 | 링크 중심 반환 의도. 본문·스냅샷 저장 여부는 미결정 |
| 세 세션에 역할을 나눔 | 운영 선택지. 고정 조사·DB·UX 세 부서가 아님 |
| 기존 5테이블·특정 스택·초기 후보 수 | 앞선 예시/초안. 최신 사용자 요구를 대신하는 제약이 아님 |

## 앞으로 배정할 수 있는 연구 질문

아래 목록은 작업 대기 질문이다. 답이나 채택된 기술이 아니다. 실제 배정 시 관련 질문을 적절한 크기로 묶는다.

| ID | 연구 질문 | 설계자에게 남길 결과 |
| --- | --- | --- |
| scope | OSS·사이트·기능 외에 어떤 자료가 같은 목적에 도움이 되나? 저장소·문서·논문·표준·예제·실패 사례 등의 가치와 관리 비용은? | 수집 대상의 여러 범위와 포함·제외 조건 |
| identity | 제품, 그 안의 기능·메커니즘, 여러 출처 링크를 어떻게 구별하면 중복과 과도한 세분화를 줄이나? | 여러 식별·연결 방식, 최소 표현과 반례 |
| storage | 링크+짧은 설명만으로 어디까지 찾을 수 있나? 추가 구조가 필요하다면 어떤 질문 때문에 필요한가? | 가벼운 안부터 확장된 안까지 비교, 필요한 최소 근거 |
| retrieval | 동일 목적의 제품과 다른 분야의 유용한 부분·원리를 어떻게 함께 찾나? | 서로 다른 질의·검색 방식, 설명 가능성·누락·오탐 조건 |
| input | 전체/부분 설계와 목적에서 무엇을 받아야 하나? AI 분해가 도움이 되는 경우와 원뜻을 바꾸는 경우는? | 입력 계약 후보, 원문과 해석의 연결, 추가 질문 조건 |
| maintenance | 주소 생존, 리다이렉트, 내용 변경, 서비스·저장소 관계를 어떤 비용으로 확인하나? 수동·요청 시·주기 갱신 중 무엇이 필요한가? | 상시 수집이 없는 안을 포함한 운영 대안 |
| evaluation | 이름이 비슷한 것과 실제 도움이 되는 것, 다른 분야에서 옮겨온 좋은 원리를 어떻게 판정하나? | 비교할 과제·정답 근거·반례·평가 방법의 후보 |
| assembly | 위 대안 중 무엇을 함께 쓸 수 있고 무엇이 충돌하나? 처음 작게 시작한 뒤 무엇을 보존하며 바꿀 수 있나? | 조합·대체·이행 조건과 남은 결정 |

각 연구는 실제 사례·구현·사용자 경험과 필요한 검증으로 뒷받침한다. 이 목록에 기술 이름을 채운 것만으로 조사 완료라고 하지 않는다. 기존 자료를 재사용할 때는 확인일·범위·미확인을 함께 읽는다.

## 현재 상태

이 브리프의 연구 질문은 **미배정·미실행**이다. 저장소에 이미 있는 조사 표본은 이전 환경 작업의 자료이며, 위 질문 전체를 해결한 결과로 취급하지 않는다. 미래 제품 DB, 검색 방법, 수집 구조, API 호출, UI, AgentFlow 연동 계약은 미확정이다.
