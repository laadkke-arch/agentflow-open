# 03. 경쟁하는 완결 개념

일곱 개념을 같은 세 질문으로 비교했다. 기술 이름 없이 답한다. 세 질문은 "무엇을 미리 알아 두었나", "요청이 온 뒤 무엇을 새로 했나", "무엇을 기억했기에 다음 요청이 달라지나"다. 공통 사례는 셋이다. R1(저장이 느려도 대기와 동시 작업을 늘리지 않기), R2(우리 도구를 설치하지 않은 외부 감리자에게 작업 기록 넘기기), EVAL-X1(저장 목록을 외부 서비스에 맡기되 서비스가 사라져도 남게 하기).

## 1. 일곱 개념

| 개념 | 미리 알아 둔 것 | 요청 뒤 새로 한 것 | 기억했기에 다음이 달라지는 것 |
| --- | --- | --- | --- |
| **G** 모델과 웹 검색만 | 없음 | 일반 검색으로 상위 원문을 읽고 답한다 | 없음. 같은 요청도 매번 처음부터 |
| **S** 확인 기록만 남기는 단순안 | 이전 요청에서 연 원문의 주소·판·절 위치와 설명 한 줄 | 전문 검색과 일반 검색, 같은 절·판의 실행 | 같은 주소·판·절을 다시 쓴다. 이름이 맞을 때만 |
| **gallim** 기존 설계 | 시드 링크와 정규식 관계 셋 | 요청판 고정, 관계 추론, 어휘 순위, 고정 URL 둘의 판독 | 빈 답이라도 그대로 재생. 판단은 요청판에 묶임 |

| **현장(PR #8 B)** 요청 순간만 | 없음(전역 목록 없음) | Studio 맥락을 받아 가장 그럴듯한 해석으로 바로 찾고, 해석을 첫 줄에 복창한다. 네 갈래 탐색 | 사례(칸 패턴, 요건 사실, 판정)를 재사용하거나 구별한다 |
| **v1 확인 장부** | 표본관의 관측과 꼬리표, 수집 흐름이 이미 읽은 줄의 청구 없는 관측, 변경 채널과 감시 키 | 현장의 맥락 수집과 복창, 묻기 순서, 네 갈래 탐색, 사용자 판 확인, 원리 관문, 1~3자리 | 같은 판·위치는 다시 읽지 않는다. 판이 바뀌면 그 위치만. 채널 항목이 감시 키에 닿으면 인용한 자리에만 알린다. 판단은 프로젝트에 남는다 |

## 3. 어떻게 섞었고 왜

**뼈대는 현장(B)이다.** 요청은 Studio 맥락을 받고, 해석을 첫 줄에 복창하고, 네 갈래로 찾는다. PR #8의 비교에서 선택 객체·이웃·판이 첫 원문을 가르는 경우(107의 발생 위치 6/6 대 공유 정의 0/6)와 해석이 갈리는 경우가 모두 B 쪽이었다. 이런 요청이 가장 흔하다.

**기억의 단위는 표본관이다.** 관측(표본)과 판정 쪽지를 나누고, 쪽지는 덧붙이기만 한다. 사용 쪽지로 영향받은 답만 다시 연다. PR #8 A의 수장 기록과 B의 열람 관측은 키가 같아서, 이 둘을 하나의 관측 표로 합쳤다.

**수장고(A)는 그림자로만 둔다.** 일반 검색이 약한 입구(지역 언어 다이제스트, 배포 저장소 신규 목록)에서 수집 흐름이 이미 읽은 줄만 청구 없는 관측으로 남긴다. 추가 열람은 0회다. 입구를 따로 순회하며 미리 읽지는 않는다. 이 그림자는 "서랍만 찾은 적격 후보" 비율로 계속 정당화돼야 한다.

**S로 줄어드는 장치를 안에 둔다.** 표본관의 "병" 안처럼, 서랍만 찾은 적격 후보가 두 분기 연속 0이면 꼬리표·대비 작성을 멈추고 S의 표현으로 줄인다([04-architecture.md 7절](04-architecture.md#7-운영-지표와-줄이는-규칙)).

**gallim에서는 뼈대를 가져왔다.** 요청판 고정, 판단의 요청판 묶기, 보수적 판정기, 지난 답 재생이다([02-landscape.md 4절](02-landscape.md#4-무엇을-가져오고-무엇을-버렸나)).

## 4. 전제 뒤집기

전제 하나씩을 뒤집고, 각 세계에서 영구히 기억할 것을 정했다. v1은 두 세계에 공통으로 남는 것만 필수로 둔다.

| | 세계 1: 자료는 넘치고 읽기는 싸며 같은 문제가 드물다 | 세계 2: 읽기가 비싸고 같은 문제가 반복된다 |
| --- | --- | --- |
| 영구히 기억할 것 | 판정 쪽지(무엇이 왜 맞거나 틀렸나, 거절과 갈린 조건 포함), 후보를 처음 가른 해석, 서랍만 찾음 / 새 검색만 찾음 기록 | 관측(고정판 위치, 짧은 인용, 실행 영수증), 뒤집을 위치, 사용 쪽지 |
| 사라지는 것 | 꼬리표와 대비, 관측 재사용. 매번 다시 읽는 편이 싸다 | 매 요청의 넓은 탐색 |
| 이기는 개념 | S나 G에 가깝다. 복창과 맥락 수집만 남는다 | 표본관, 수장고 |

**우리 세계는 섞여 있다.** 주류 원문은 세계 1처럼 다시 닿기 싸다. 작은 외국어 자료와 다른 분야 원리는 세계 2처럼 한 번 놓치면 다시 닿을 길이 없다.

**두 세계에 공통으로 남는 것은 판정 쪽지와 탐색 경로 기록이다.** 그래서 v1에서 이 둘은 끌 수 없다. 관측 재사용, 꼬리표, 대비, 감시는 운영 지표로 켜고 끈다.

뒤집은 전제 하나를 더 시험했다. **"사용자는 질문하지 않고 가리키기만 한다."** 가리킨 부분과 목적만 있고 지킬 조건이 비어 있으면, 1번 자리의 하한(모든 필수 조건 L2 이상)을 적용할 대상이 없다. 이때 v1은 조건을 추론해 `provenance = inferred`로 적고 해석 줄에 밝힌다. R1의 S1(입력 끝을 일꾼에게 알린다)이 그렇게 들어간 조건이다. 추론한 조건은 1번 자리의 하한을 만족시키는 데 쓰지 않는다. 자리 문장의 "함께 필요한 것"에만 쓴다.

## 5. 낯선 분야의 운영 원리 셋

각 원리를 검토하고, 도입하면 사라지는 일과 새로 생기는 실패를 적었다. 일반 지식으로 쓴 원리는 그렇게 표시했다.

### 5.1 식물 표본관의 재동정 쪽지 (PR #6 2.6절)

**원리.** 표본관은 채집 꼬리표에 손대지 않고 새 재동정 쪽지를 덧붙인다. 쪽지에는 새 이름, 재동정한 사람, 날짜가 있다. 표본을 연구에 썼다는 사실도 쪽지로 남는다([PR #6][pr6]).

**v1 대응과 채택.** 표본은 관측이다. 채집 꼬리표는 칸 꼬리표다. 재동정 쪽지는 판정 쪽지다(`slip`, 덧붙이기만 하고 트리거로 수정을 막는다). 연구 사용 쪽지는 `usage`다. 모두 채택했다.

**사라지는 일.**
- 저장할 때 완벽하게 설명하는 일
- 같은 문제가 오면 원문 전체를 다시 읽는 일
- 마지막 판정을 덮어써서 생기는 잘못된 승인. 147에서 A-url이 40/96이었다

**새 실패와 대응.**

| 새 실패 | v1의 대응 |
| --- | --- |
| 미처리 표본 더미. 청구 없는 관측이 쌓이면 검색 잡음이 는다 | 서랍 후보 자격(두 칸, 내용어 둘)과 S로 줄이는 규칙 |
| 맨 위 쪽지에 끌려감 | 쪽지는 요청판·조건·요건 사실에만 묶인다. 다른 프로젝트는 쪽지를 보지 않는다 |
| 표본 소실. 원 위치에서 지워진 원문 | 관측의 `outcome`에 실패 종류를 적고, 현재 원문 없음을 따로 표시한다 |

### 5.2 항공 관제의 복창 (PR #8 B)

**원리 [일반 지식].** 관제 지시를 받은 조종사는 지시를 다시 읽어 확인한다. 관제사는 틀린 복창만 고친다. 지시가 모호하다고 매번 되묻지 않는다.

**v1 대응과 채택.** 답의 0번 자리가 해석 줄이다. 해석이 갈리면 묻기 전에 0단계(요청판의 다른 명시 칸이 정하는지 다시 읽기)와 1단계(두 뜻을 함께 채우는 공통 행동)를 둔다. 둘 다 아닐 때만 회수, 실행, 한 번 묻기, 조건부 두 링크로 간다(`Ledger.decide`).

**사라지는 일.** 해석이 갈릴 때마다 사용자를 기다리는 일. EVAL-X1 T0은 R2·R3·선호 칸이 "읽기 API로 가져오기"를 정해서 묻지 않았다(reread). R2는 "읽기 전용 + 지문 목록"이 두 뜻을 함께 채워서 묻지 않았다(common).

**새 실패와 대응.** 사용자가 복창을 읽지 않으면 틀린 해석이 그대로 간다. 그래서 해석 줄에 다른 뜻이면 어디를 먼저 보라는 길을 함께 적는다. 예를 들면 "서비스 화면에서 내보내는 뜻이면 1번의 두 번째 확인을 먼저 보세요"다. 복창을 읽는 비율은 측정되지 않았다(c).

### 5.3 항공 감항성 개선 지시의 적용 대상 관리 (sections/discovery_ops.md 7절)

**원리 [일반 지식].** 감항성 개선 지시는 형식·일련번호 범위·장착 상태로 적용 대상을 정하고, 이행 방법과 기한을 정한다. 운영자는 기체마다 모든 지시의 상태를 표로 유지한다. 상태는 이행, 반복 점검 중, 해당 없음과 그 이유, 종결이다.

**v1 대응과 채택.**
- 지시는 채널 항목이다.
- 적용 대상은 감시 키다(같은 주소 / 공급자 두 층).
- 이행 기한은 공지 기한이다.
- 대체 지시는 대체(supersession) 행이다.
- 반복 점검은 감사 표본이다.

모두 채택했다.

**사라지는 일.**
- 새 판마다 모든 활성 판단을 재검토하는 일
- 이 변경이 우리와 관계있는지 매번 따지는 일

EVAL-X1에서 다섯 사건 모두 Pocket 자리에만 알림이 갔고, 원리 자리에는 0건이었다(b).

**새 실패와 대응.**

| 새 실패 | v1의 대응 |
| --- | --- |
| 잘못된 "해당 없음"이 조용한 실패가 된다 | 감사에서 "감시 없음" 관측을 두 배로 뽑는다 |
| 상태 행이 항목 수와 프로젝트 수의 곱으로 불어난다 | 감시 키가 맞을 때만 작업을 만들고, 같은 관측의 새 원인은 열린 작업에 합친다(`_enqueue`) |

## 6. 섞을 때 깨질 수 있는 전제

| 전제 | 왜 필요한가 | 확인한 것 | 깨지면 |
| --- | --- | --- | --- |
| 수집 흐름의 관측과 요청 때의 관측이 같은 키를 쓴다 | 장면 2가 장면 1의 장부에 들어가야 한다 | 코드에서 같은 `observe`를 `via = collection / request`로만 구별한다(b) | 두 장부가 갈라져 장면 2가 서랍에 없다 |
| 칸 여섯이 소프트웨어 밖 원문도 서술한다 | 원리 후보가 칸으로 맞아야 한다 | OAI-PMH와 RFC 8493은 같은 칸으로 썼다(b, 고정 자료). 다른 분야는 미확인(c) | 원리는 새 검색의 분야 추정 갈래로만 들어온다 |
| 꼬리표 작성 비용이 작다 | 그림자 수장고가 요청 노동보다 싸야 한다 | 수집 흐름의 줄만 쓰므로 추가 열람 0회. 작성 노동은 미측정(c) | S로 줄이는 규칙이 먼저 걸린다 |
| 접수가 칸별 필요 문장을 쓴다 | 서랍이 칸끼리 맞춘다 | 세 사례의 필요 문장은 손으로 쓴 고정 자료다(c) | 서랍 적중이 줄고 새 검색에 기댄다. 첫 구현에서 잰다 |
| 판단 분리가 공유를 막지 않는다 | 다른 프로젝트도 관측은 재사용해야 한다 | 사례 A 프로젝트 C에서 전체 원문 열람 0회, 쪽지 0건(b) | 없음 |

PR #8이 짚은 전제 하나는 단순하게 정리했다. 일곱 칸을 여섯 칸으로 줄였다(input, output, user_without, keeps, breaks_when, summary). "다시 움직이는 근거"는 keeps 칸에, "막는 실패"는 breaks_when 칸에 들어갔다. 세 사례의 필요 문장이 이 여섯 칸 밖을 쓰지 않았다.
