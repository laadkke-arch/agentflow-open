## 1. 수정점

### I1. 설계 시험 33개를 단언 그대로 옮겼다

- **설계가 말한 것.** [06 3.2](06-assumptions-handoff.md#32-완료-기준) 1: `StorageContract` 13, `Rules` 2, `OperationalFixes` 14, `Decisions` 중 D1·D6·D7·D9 넷이 제품 코드에서 그대로 통과한다.
- **구현에서 본 것.** 33개 모두 단언을 바꾸지 않고 통과했다. 바꾼 것은 import 경로와 `cases.KB`를 같은 값의 상수 `KB`로 둔 것뿐이다. `test_port_guard.test_33_tests_are_ported_verbatim`이 함수 본문이 설계 시험과 바이트 단위로 같은지(`cases.KB`→`KB` 치환 뒤) 지킨다. 설계 예제는 고치지 않았고 기준선(`test_ledger.py` 50개, `cases.py --json | cmp`)은 그대로다.
- **정한 것.** `StorageContract`에 채널·감시·임차·기한 시험이 들어 있어, 그 저장 함수(`channel`, `watch`, `poll`, `lease`, `finish`, `due`)는 엔진에 함께 옮겼다. 단위 2의 시계·작업자·채널 어댑터는 만들지 않았다(I14).
- **영향.** 06 3.2.

### I2. 상수와 규칙 판을 한 곳에 모았다

- **구현에서 본 것.** 설계 예제는 상수를 `Ledger` 클래스 속성에 흩어 두었다.
- **정한 것.** [`ledger/afledger/config.py`](../../../ledger/afledger/config.py)에 예산·시계 상수와 규칙 판 일곱(`RULE_VERSION=unit1-r1`, `NORM_RULES=n1`, `MAP_RULES=m1`, `BUDGET_RULES=b1`, `PRIVACY_RULES=p2`, `SEARCH_RULES=s1`, `INTAKE_RULES=i1`)을 둔다. 결과 행에 판을 남긴다: `locator.norm_rules`, `observation.map_rules`, `budget_json.rules`, `answer_run.rule_version`, `r1_live.json.rules`. 값을 바꾸면 판을 올린다.
- **영향.** 07 8절 4.

### I3. 주소 정규화(R-1 임시안): opensource n1을 그대로 쓰고 재사용 키를 (page, 판, 위치)로

- **설계가 말한 것.** [07 R-1](07-review.md#p0-실제-사용-전에-반드시): 재사용·전파·경로 지표가 주소 문자열을 키로 쓴다. 정규형 규칙을 만들고 스키마에 정규 주소 열이 생겨야 끝난다. [04 4절](04-architecture.md#4-저장과-조회-예)의 재사용 조회는 `l.url = …/blob/main/…`이었다.
- **구현에서 본 것.** laadkke-arch/opensource `tools/rcore/normalize.py`(규칙 판 n1)를 [커밋 `7c8f9860`](https://github.com/laadkke-arch/opensource/blob/7c8f9860a6f1f39951ef6c2f2a4cfc4d8a5881bf/tools/rcore/normalize.py)에서 바이트 그대로 가져왔다(blob `1132b022`, 같은 blob이 `dot-a`·`dot-b`·`dot-c`·기본 브랜치 머리 `9c091fc1`에 모두 있다). `test_p0.NormalizeN1.test_vendored_file_is_byte_identical`이 blob 해시를 확인한다. link-index 세 브랜치의 주소 전체로 회귀를 돌렸다([measure_normalize.json](../../../ledger/out/measure_normalize.json)): 행 4,390, 서로 다른 원래 주소 2,438 → url_norm 2,437 → page 2,429 → target(없으면 page) 2,297. 실패 0, `normalize(url_norm)`의 page가 같은 비율 2,438/2,438. 과제 문서의 "약 4,150행"과 다른 것은 세 브랜치의 `W1.tsv`를 모두 센 차이로 보인다(같은 행 완전 중복은 0).
- **정한 것(임시).** 원래 주소 문자열은 `locator.url`에 그대로 두고 `url_norm`, `page`, `target`, `norm_rules` 열을 더했다(관측은 locator를 거쳐 이 열을 본다, `Ledger.obs`). 재사용 조회(`Ledger.reusable`)는 (page, 판, 위치)다. `…/blob/main/…`, `…/blob/v3.13.18/…`, `raw.githubusercontent.com/…`가 같은 관측을 찾고, 같은 target의 다른 파일이나 다른 판은 찾지 않는다(`test_reuse_meets_across_url_forms_but_not_across_target`). target은 재사용 키로 쓰지 않는다(전역 병합 금지 유지). 정규화가 실패하면(예시·로컬 주소) page = 원래 문자열이라 재사용이 넓어지지 않는다.
- **알려진 빈칸(고치지 않음).** `docs.python.org/3.13/...`의 판을 n1은 뽑지 않는다(edition 없음, page에 3.13이 남는다). 판이 page 안에 남으므로 다른 판끼리 잘못 묶이지는 않고, 단위 1은 첫 링크를 고정판 소스 줄로 낸다(D10). 문서 주소를 판으로 묶을 일이 생기면 출처 저장소에서 n2로 올린다(이 저장소의 vendor는 고치지 않는다).
- **위치 표기.** 장부의 줄 위치를 `L36-L38`(GitHub 조각과 같은 꼴)로 바꿨다. 설계 예제는 `L36–38`(엔대시)이었다. 재사용 키의 위치가 문자열이라 한 꼴로 고정해야 한다.
- **바꿀 자리.** `afledger/normalize.py`, `config.NORM_RULES`.
- **영향.** 04 4절(재사용 조회 SQL), 07 R-1.

### I4. 판 사이 위치 대응(R-1 임시안 m1): 정확한 인용 → 같은 기호 → 대응 없음

- **설계가 말한 것.** [04 3.8](04-architecture.md#38-재확인-작업자) 2: "판이 바뀌어 위치가 옮겨졌으면 뒤집을 위치로 찾는다 **[빈칸: 판 사이 위치 대응 규칙, 07 R-1]**". 05 2.7은 판마다 바뀌는 줄 번호를 손으로 맞췄다.
- **구현에서 본 것.** [`afledger/locate.py`](../../../ledger/afledger/locate.py). 관측에 앵커 열(`anchor_symbol`, `anchor_in_doc`; 인용 앵커는 기존 `quote_fp`)과 대응 열(`map_method`, `map_from`, `map_rules`), 고정판 바이트 범위(`byte_span`)를 더했다. R1의 3.13.18 → 3.12.3에서 지난 답이 인용한 줄 위치 셋을 cases.py 손 대응과 비교했다(`r1_live.json` `rev2.hand_map_comparison`): 새 판 위치 어긋남 **0/3**(L36-L38→L24-L26 정확한 인용, L355-L358→L333-L336 정확한 인용, `Queue.shutdown`→대응 없음). 첫 판에서 고른 줄 범위가 하나 다르다: shutdown을 손 대응은 `def` 줄을 넣어 L252–258로, 판독 어댑터는 docstring 구절로 L253-L258로 잡았다(대응 규칙과 무관). 넓혀서 queues.py·locks.py의 모든 class·def docstring 46개를 대응하면 46/46이 ast 정답과 맞았다(정확한 인용 27, 같은 기호 17, 대응 없음 2, [measure_r1_map.json](../../../ledger/out/measure_r1_map.json)).

### I5. D6c: 요청 수치는 프로젝트 장부로, 공용에는 열쇠 지문만

- **설계가 말한 것.** [07 6.2 D6](07-review.md#62-규칙으로-정한-결정) (c): 요청 수치가 든 영수증 입력·실행 관측·대비 행은 프로젝트 장부에 두고 공용에는 지문만 둔다. 예시 엔진에 없었다(M7c).
- **구현에서 본 것.** 그냥 sha256 지문을 두면 R1 입력(`{"items":40,"maxsize":8,"workers":4,…}`)처럼 작은 값은 사전 대입으로 되찾는다. 설계 예제의 영수증 프로그램은 요청 수치를 상수로 박아 프로그램 지문도 요청을 드러냈다.
- **정한 것.** 공용 `receipt`는 런타임·프로그램 sha256·입력 지문·출력 지문·실행 날짜만 든다. 지문은 프로젝트마다 다른 비밀 열쇠(`{p}.secret`)로 만든 HMAC-SHA256이다. 입력·출력 본문은 `{p}.receipt_body`, 실행 관측의 값 문장은 `{p}.exec_note`, 대비 본문은 `{p}.contrast`에 두고 공용 `contrast`에는 두 관측과 본문 지문만 둔다. 공용의 실행 관측 문장은 "실행 영수증: 프로그램 39a3555b5e95을 CPython 3.13.18에서 실행했다(입력·출력·값은 요청 프로젝트 장부)"다. `p` 없이 `receipt`·`contrast`를 부르면 `PrivacyError`다. 영수증 프로그램은 요청 수치를 표준 입력 JSON으로 받게 바꿨고(`ledger/programs/r1_queue.py`), 같은 입력에서 출력이 설계 영수증과 같다.

### I7. 새 검색 직접 갈래는 GitHub 코드 검색, 서랍 후보는 기호로 사용자 판의 소스를 찾는다

(2) 낱말: 칸별 필요 문장의 영어 내용어를 "몇 칸에 나오나" 내림차순, 칸 순서(input, output, keeps, breaks_when, summary)로 처음 나온 순서. 앞에서 `MAX_TERMS = 외부 시도 10 − 가져오기 4 = 6`개(예산에서 정했다). (3) 낱말마다 검색 1회. (4) 파일 점수는 맞은 낱말의 log(N/df) 합. (5) **서랍 기호 풀기(설계에 없던 단계):** 적격 서랍 적중의 자료집 이름이 `<패키지>.<클래스>`이면 `"class <클래스>"`로 한 번 더 찾아 사용자 판의 소스 파일을 정한다. 이 결과도 새 검색 탐색 기록에 서랍 출처와 함께 남는다. R1에서 `asyncio.Queue`→`queues.py`, `asyncio.Semaphore`→`locks.py`. (6) 사용자 판은 실행 러너가 실제로 돈 판의 태그다(맥락 "CPython 3.13" → 러너가 3.13.18을 돌림 → `v3.13.18`). 검색 결과 주소의 커밋은 사용자 판이 아니므로 page를 사용자 태그로 다시 연다.

- **원문(데이터, 모두 L1).** opensource `catalog/claims/F30.tsv` @ [`286d9d5`](https://github.com/laadkke-arch/opensource/blob/286d9d558739dbc67803bb9de52697ef7c95988d/catalog/claims/F30.tsv)의 기록:

### I29. 한 문장 요청에 한 번 되묻기: 적격 0은 줄지만 순위가 나빠져 권하지 않는다

- **배경(사용자 정보).** e1로 되돌린 것은 맞다(I24). (b)는 두 칸이 서로 다른 내용일 때만 뜻이 있으니, 같은 문장을 복사하는 대신 접수가 요청자에게 한 번 되묻는 길(무엇을 받나, 무엇이 깨지면 안 되나)을 (c) 새 검색 맡기기와 견준다. p5 기록이 한 원문을 원리·적용 장면·쓸모 세 문장으로 나누는 방식이 칸 나누기의 예다.
- **만든 것.** `intake.reask_questions`는 필요 문장이 칸 하나뿐이면 비어 있는 칸(받는 것 = input, 깨지면 안 되는 것 = breaks_when)마다 질문 하나를 낸다. 한 번만 묻는다. `intake.apply_reask`는 답을 칸으로 넣는다. "깨지면 안 되는 것" 답은 상한 단서만 있으면 keeps, 금지 단서가 있으면 breaks_when이고, 이미 있는 문장은 넣지 않는다(복사 금지). 시험 `test_unit1.ReaskI29`.
- **잰 것(규칙은 돌리기 전, `measure.i29`).**
  - 대상: A4 20건 중 부분 질의 16건, 한국어·영어판.
  - 대리 답: 같은 문제의 전체 질의(.w)를 접수 규칙으로 나눈 칸에서 input은 "받는 것" 답, keeps·breaks_when은 "깨지면 안 되는 것" 답이다. 부분 질의와 같은 문장은 뺐다. 전체 질의 그대로를 위쪽 한계로 같이 쟀다.
  - 권하는 규칙: 두 언어 모두 적격 0이 줄고, 자료집만 회수율·등급 2 수가 줄지 않고, 실제 행 2만 개의 판정 잡음이 늘지 않으면 권한다.
