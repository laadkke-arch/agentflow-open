## 구현과 재사용

프로젝트별 context 검색, manifest 기반 작업 실행, 입력·로그 해시를 가진 결과 기록, 오래된 결과 거부, 단일 프로젝트 내보내기를 구현했다. Python unittest와 urllib.parse, Git bundle, GitHub Actions를 재사용했고 w3lib·yarl·Nox·uv와 urllib3의 실제 설정을 비교한 선택 이유는 docs/research/tool-decisions.md에 남겼다.

주소 정리 실습은 8개 입력을 3개 저장소 식별자로 묶고 3개 모호하거나 범위 밖인 입력을 별도 보고했다. 출처 연결 실습은 같은 공통 주소 함수를 사용해 중복 저장소 참조와 문서의 출처 연결을 검사했다. 두 실습의 현재 상태와 결정 문서는 서로 섞이지 않는다.

## 완료하지 않은 범위

새 프로세스 재실행은 확인했지만 새 AI 대화의 인수인계를 시험한 것은 아니다. 비공개 공통 저장소 분리와 main 병합은 별도 승인 전 실행하지 않았다. 탐색기 제품·Render·DB·PC 연결은 의도적으로 보류했다. 이 실행기는 검토된 Python 작업용이고 보안 샌드박스가 아니다.

현재 연결된 브랜치에서 이어가는 데 추가 인증이나 설치를 사용자에게 요청할 필요는 없다. 원본 CI 아티팩트는 7일 보존되므로 영구 백업으로 간주하지 않는다. 현재 코드와 커밋된 판단·요약은 저장소에서 관리한다.

## 재현

저장소 루트에서 `python scripts/check.py --require-git`를 실행한다. 새 작업은 AGENTS.md, STATE.md, docs/START_HERE.md와 해당 프로젝트의 context에서 시작한다. 이 문서는 검사 이후 작성한 결과 기록이며 실행 코드를 추가로 변경하지 않는다.
