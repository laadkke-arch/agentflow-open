# 프로젝트를 축적하는 작업환경

2026-11-19 갱신: 이 문서의 GitHub 왕복 원칙은 유지한다. 최신 실행 명령·경로·검사 범위는 [START_HERE.md](START_HERE.md)와 [CLOUD_WORKFLOW.md](CLOUD_WORKFLOW.md)를 따른다. 아래 초기 Ubuntu 5분 설정은 과거 설명이며 현재는 Ubuntu/Windows 10분 검사와 문서 계약 검사를 사용한다. 원문 글도 2026-11-19에 본문을 직접 읽었으며 댓글 내용은 확인하지 못했다.

목표는 링크나 대화 요약만 보관하는 것이 아니라, 조사와 판단을 파일로 남기고 실제 실행 결과를 회수한 뒤 다음 작업으로 연결하는 것이다. 사용자가 참고한 커뮤니티 글은 여러 방법 중 하나다. 일시적인 요금 혜택을 환경의 필수 조건으로 삼지 않는다.

이 문서는 최초 실행 경로를 설명한다. 원문과 다른 도구를 비교한 전체 적용안은 [참고 방법을 조합하는 공통 작업환경](WORKFLOW_ADAPTATION.md)에 있다. 현재 경로가 최종 개발 방식이거나 가장 효율적인 방식으로 확정된 것은 아니다.

## 첫 구성

```text
사용자와 이 대화
  -> GitHub 연결로 자료와 코드 읽기/변경 저장
  -> 작업 브랜치의 변경으로 GitHub Actions 시작
  -> GitHub 제공 러너에서 제한된 검증 명령 실행
  -> 실행한 커밋, 성공/실패, 로그 회수
  -> STATE.md에 결과와 다음 행동 저장
  -> 다음 세션이 같은 브랜치의 상태와 필요한 근거를 읽고 이어감
```

GitHub가 코드와 기록을 보관하고, Actions가 실행을 연결하며, 러너가 명령을 수행한다. Render는 나중에 사용자에게 서비스할 앱을 배포하는 곳이다. 지금의 실행 왕복을 확인하기 위해 Render 서버나 사용자 PC를 먼저 켤 필요는 없다.

## 완료 판정

첫 시험은 `workbench/probe.json`의 식별자를 읽고 자료 목록을 검사한다. 로그에는 입력 식별자, 실제 체크아웃한 커밋 SHA, 실행 ID, 자료 목록 해시와 검사 범위가 나온다. 이 대화에서 그 값을 다시 읽어 원래 요청과 연결해야 왕복 시험이 완료된다.

파일 저장, 워크플로 작성, 워크플로 실행 성공, 결과 읽기, 상태 갱신은 각각 다른 단계다. 완전히 새로운 대화에서 이어받는 시험도 별도로 남긴다. 이 파일을 저장한다고 모델의 자동 기억이나 무인 상시 작업이 생기지는 않는다. 실행 왕복 성공은 자료 검색, 판단의 정확성, 경험 재사용의 완성을 뜻하지 않는다.

## 여러 프로젝트로 확장

지금은 별도 환경 저장소를 추가하지 않고 이 브랜치에서 공통 규칙과 템플릿을 검증한다. 장기 제안은 공통 환경을 비공개 별도 저장소에 두고 프로젝트별 코드는 각 저장소에 두는 방식이다. 현재 공개 브랜치를 비공개 자료 보관 공간으로 사용하지 않는다. 새 저장소는 아직 만들지 않았다.

프로젝트별 코드, 현재 상태, 비밀값은 섞지 않는다. 오래된 결정은 이력으로 보관하고 현재 결정은 짧게 유지한다. 공통 규칙은 검증 후 필요한 부분만 재사용한다.

## 도구 선택

현재 채택: 이미 연결된 GitHub, 공식 GitHub Actions, Python 표준 라이브러리. 패키지 추가 설치 없이 첫 실행 경로를 검증했다.

검토 후보: 짧은 반복 작업을 직접 수행하는 개발 환경, DevSpace 같은 로컬 연결, 기획·검증 절차와 단계적 자료 읽기를 돕는 기존 도구. 비교 내용은 WORKFLOW_ADAPTATION.md를 따른다. 필요할 때만 실제 연결과 동일 작업 평가를 진행한다.

현재 미실시: 사용자 PC 연결, 자체 러너 설치, 여러 코딩 에이전트의 병렬 실행. 로컬 파일, 특수 장비, 빠른 반복 편집이 실제로 필요해지면 별도 격리와 인증을 검토한다.

## 보안과 사용량

- 지금 저장소는 공개이므로 공개 가능한 프로젝트 요약만 저장한다. 원문 대화를 통째로 넣지 않는다.
- 초기 워크플로는 GitHub 제공 Ubuntu 러너, 읽기 권한, 5분 제한, 동시 실행 제어를 사용한다.
- 공식 checkout action은 확인한 전체 커밋 SHA로 고정하고 인증정보를 작업 디렉터리에 남기지 않는다.
- 사용자 비밀값, 배포 키, 사용자 PC 연결은 사용하지 않는다. 임의 셸 명령을 외부 입력으로 받지 않는다.
- 정기 실행이나 무한 재시도는 없다. `workbench/` 또는 워크플로 파일의 브랜치 변경에만 실행된다.
- 인수인계 기록은 코드 실행 결과와 구분한다. 이 대화가 종료된 뒤 자동으로 계속 작업하는 구조는 설정하지 않았다.

## 근거와 한계

초기 출처와 판단은 `workbench/sources.json`에 보관한다. 해당 파일의 `partial_search_only`는 당시 디시 원문 직접 접속에 실패한 상태를 기록한 것이다. 이후 사용자가 대화에 본문을 제공하여 그 텍스트를 읽었으며, 후속 적용 판단과 추가 공식 출처는 WORKFLOW_ADAPTATION.md에 보관했다. 최신 댓글과 현재 사이트 본문을 재열람한 것으로 표현하지 않는다.

공식 문서에서 확인한 기능, 커뮤니티의 개인 사용 경험, 우리 설계 제안, 직접 실행한 검증을 구분한다. 현재 검증기는 문서 내용의 진실성이나 코드 전체의 안전성을 인증하지 않는다.
